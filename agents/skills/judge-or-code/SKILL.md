# `judge-or-code`：写死、交给判断题小模型，还是这次不固化

## 什么时候读

**由正在写代码的模型自己触发**（创始人 2026-09-21 拍板）：「这里要不要写一道机械判断」本身是模糊题，最适合当场的模型判；不另造扫描器去猜——那等于用一道 if/else 去判「要不要用 if/else」。手正要落到下面任何一处时读：

- 写 **if/else 链、阈值、映射表、新闸、新检查**去判一件事：先过五问，多数在第 1 问就答完（结构化输入 → 写代码，接着干）；
- 写**关键词表、正则**去判一段**人写的文字**（报错原文、issue 正文、群消息、PR 描述）：这是最该停一下的；
- 为**一次性的批量分类**（几十张单归类、一批旧数据打标）写脚本；
- 为一道**是/否、几选一**的小判断去调大模型；
- 用户问「这个能不能用判断题小模型」「为什么写死」。

多数时候答案仍是写代码，读它是为了不漏掉少数该交给小模型的地方。要新造整个机制的，先读 `best-practice-first`；本页只回答「这一处判断用什么做」。

**判断题小模型**：专门答选择题、同时给出把握度的模型服务。fleet-dao 里叫 Jev：代码在 fleet-dao 仓 `packages/jev`（入口 `packages/jev/src/index.ts`），设计见 `docs/design.md`「十一、Jev 判断题服务」，旧系统的实测数字见 `docs/reference/data-jev.md`「三、Jev」。当前环境没有这种服务可调的，五问照样过，「交给小模型」的那几种落法换成写代码或人判。

## 五问（按顺序，前面答了就不用往下）

1. **输入是人写的自由文字吗？** 不是（数字、退出码、标签名、字段、文件路径）→ **代码**，到此为止。小模型比数字不可靠：贴线的算术题把握度只有 0.45，查表类的活交给它是花钱买不确定。
2. **判错了会怎样？** 会放行、合并、停整个账号池、删东西、花钱 → 小模型**不许单独触发**：只能当否决票或兜底，真正的扳机是规则、数字证据或人。这叫「能拦不能放」（fleet-dao 的 Jev 在类型上就表达不出放行，见 `packages/jev/src/effects.ts`）。
3. **要不要每次结果一样、说得出是哪条规则判的？**（闸、检查项、钩子、测试）→ **代码**。钩子在每次工具调用、每条消息上都要等它，崩了往往就等于放行；测试不许出网——这些地方接不了。
4. **这是一次性的，还是会反复跑？** 一次性的见下节，**多半什么都不用固化**。
5. **算账**：调用量 × 单价，对比「维护那张关键词表的人工」。旧系统按量计费的后端实测每百万输入 token 0.042 美元、单次 0.25–0.8 秒；走订阅会话的后端不算花钱但占额度，起一次要几秒到几十秒。一天几百次以内钱不是问题，**延迟和「没判出来时怎么办」才是**。反过来，每秒都在跑的路径（轮询、每条日志）先用规则筛掉明显的，只把剩下的交给它。

## 四种落法

| 场景 | 落法 |
|---|---|
| 结构化输入 / 要可复现 / 错了代价大 | 写代码。别因为「小模型便宜」就换 |
| 反复跑 + 自由文字 + 已有规则 | **规则在前，小模型兜规则没认出来的那部分**。原逻辑是主，小模型是补 |
| 自由文字要变成能判的字段 | **小模型抽特征，规则做决定**：问几道具体的题，再由一张显式规则表出结果。别让它直接打总分——「难度分」试过，没有可靠的对照答案，弃了 |
| 原来调大模型做小判断 | 换小模型，先影子跑（新旧并行、只记不用），对得上再切 |

## 一次性场景：先问「要不要留下东西」

一次性 = 跑完这次，下次再用到至少隔几个月，或者根本不会再用。

- **≤ 50 条**：主会话直接读、直接判，把结果写进 issue 或 PR。不写脚本，不写正则，也不调小模型。
- **几十到几千条**：在临时目录写个一次性小脚本调小模型，结果落报告，人抽查后再动手。**不进仓、不配测试。**
- **绝不**为一次性的分类写一张关键词表——它跑完就是死代码，而且下一个人会以为它还在管事。
- 一次性的活里**确定的部分照样查表**：一对一的改名用迁移表；只有表里标了「拿不准」的那几条，才用小模型的建议。

## 接的时候必须做到

- **每一处接线都在一个地方看得见**：接在哪、问什么、答案最多能引起什么、没判出来走什么、把握线。fleet-dao 里就是题库 `packages/jev/src/bank.ts`（每道题写明选项的效果和拿不准时的走向）加考题目录 `packages/jev/exams/`。
- **没判出来 = 照原来的行为走**，不当「否」也不当「是」。连不上、超时、被限流、答了题面以外的选项，都算没判出来。
- **喂全文，别裁剪**：追加 5 万字无关内容，答案只偏 ≤0.08；裁掉「看着无关」的正文，「有没有只有用户能拍的决定」从 0.76 掉到 0.30。缺信息比多信息伤得重。
- **把握低算弃权**，把握线用服务里配好的，调用方不另起一套。
- **问具体的事**（「正文里有没有写清怎么验收」），不问笼统的（「这单难不难」）。
- 上线前用**自己的真数据**测，样本里要有反例；没有反例样本，只证明了它会说「是」。
- **先只记不拦，攒够样本、准了再真拦**（fleet-dao 的门槛见 `packages/jev/src/policy.ts`）；要让它开始自动写 GitHub 或自动派单，属于改规矩，问人。
- 小模型反复认出同一类新情况 → 把那一类固化成规则（便宜、可复现），它继续只管没见过的。

## 不许碰

数字比较；放行、合并、停池、删除、花钱的扳机；任何钩子；测试和闸里的任何一步。
