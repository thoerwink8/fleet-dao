# `commander-handoff`：指挥官自己换棒

会话长了由指挥官自己开新会话交接，不叫创始人换（创始人 2026-11-14 定，#3988）。atom 都经 `mcp__mirasim__mirasim` 的 `call` 调；派活和回报规矩见 `mirasim-sessions`。

## 什么时候换

压缩过一次、过了一个里程碑或一关、自己觉得上下文太长，三条有一条就换。

## 换会话前先收子代理

换会话前，老会话先停掉或等完在跑的 Agent 子代理。做不到的，把 agentId、会话 id、进程号、工作树写进下面交接的「在跑」。新会话要停用 `pnpm agents:stop`，参数是工作树或 agentId：按本机归属记录找到老会话，把停止发给它。不按启动时间猜进程，不杀整个进程。不在本会话定时巡子代理（换会话后管不到）。

## 一、写快照

项目 docs 目录下的 `交接.md`，每次整份覆盖，固定这几节：现在在哪、在跑（每条写单、做什么、会话 id、agentId、进程号、工作树、状态）、排队、本棒合并、决定和出处、已知坑、下一步（只写一个）、停下的条件。写完把同样内容贴一条到总单评论。

## 二、写开场提示

一份短文件（放 `_tmp/`），写：上一棒的会话 key；先读 `交接.md`；对着真实状态核（`git worktree list`、`gh pr list`、`listSessions`），快照和现实不符以现实为准；哪些步已经过了不重做；本棒新增的规矩；第一条回复的格式。还在跑、没停掉的子代理以交接里的 agentId、会话 id、进程号、工作树为准，要停就 `pnpm agents:stop`。

## 三、开新会话

`prompt`：`sessionKey: null`，`agent: "claude"`，`route: "local"`，`workdir` 填项目根，内容只写「读 <开场提示路径>，照着做」。开出来 `renameSession` 成 `[#总单号] 指挥官 第 N 棒`。

## 四、子代理收口之后，再转在跑子会话的回报

Agent 子代理不留在老会话里接着跑。已经停掉或等完的不用再转。没停掉的只记在交接「在跑」里，由新会话用 `pnpm agents:stop` 发给老会话去停。新会话里的 TaskStop、SendMessage 只管本会话的代理，不要用来停上一棒的。

在跑的 mirasim 子会话，交代里写死的回报地址还是旧会话，所以：

1. 旧会话收到回报，原样 `prompt` 转给新会话，开头加 `[转自上一棒]`。
2. 新会话收到后，派活模板里的指挥官 key 改成自己的，往后的交代写新 key。

## 五、旧会话收尾

子代理已停、已等完，或归属已写进交接；在跑子会话的回报已转完。不再派活、不合并。最后一条回复告诉创始人新会话是哪条（标题和 key）。
