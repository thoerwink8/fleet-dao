# `discuss`：讨论和第二意见

两件事共用一套本机工具：**讨论**定方案（拍板前让别家挑错），**审 PR** 看代码（改到先审后合的路径时合并前要第二家审过）。规矩本身在 `docs/design.md` 第五节「讨论」「合并闸」，这里只写本机怎么做。盲设计题就是讨论的第 0 轮。

## 何时用

- 重大方案要请人拍之前：碰人闸（对外发布、花钱、删数据、改标准）、和已拍的规矩冲突、新加外部服务、改架构或改阶段划分（和引擎同一条判据，design 第五节「重大方案人拍」）。
- 用户说「出设计题」「先出盲设计题」「讨论一下」「让别家看看」。

小方案 AI 直接定，不用讨论；小选择题（已经收敛成 A 还是 B）也不用。

## 先和创始人把前提聊清楚

方案里有他没说清、没认同的前提（比如一对一还是一对多），先用大白话问他一两句，讨论到方向一致，再找别家挑错。前提没对齐，别家讨论得再细也是在错的前提上打磨（2026-09-26 创始人：「你有问题可以先和我讨论……我们讨论完你再和其他模型出方案；别连多个了，和 gpt 讨论就够了」）。

## 做法：每轮一问一答，没收敛能接着聊

每轮都是一问一答：不读仓、不跑命令、限 400 字、中等思考强度，每家 30 秒内。

1. **第 0 轮，各自独立答**（要盲设计时才做）：只写题面（背景、诉求、要回答的），**不带自己的方案**。题面一字不提示期望的方案形态。
2. **挑错**：自己的方案（有第 0 轮就连同它的答案）发给 GPT，要它说框架对不对、漏了什么、选项怎么改。
3. **接着聊**：它的意见你不认、或者冒出新分歧，把你的回应和新证据发回去接着聊。停在三种时候：意见一致；分歧说清（双方主张没变、证据没新增，写清各方理由和你推荐哪个）；到上限（本机先按 5 轮）。停了以后要重新拉起，得写明能改变结论的新证据。

材料里附上相关规则原文、数据和出处（对方看不到仓，漏写的事实它就不知道）。挑错轮的题面要带【推演】段：从创始人的角度把方案走一遍，按阶段列边界和最坏情况（缺了 `ask.mjs` 不发、退出码 2）。

## 交给人

只写三样：各家一致的、还剩的分歧、推荐哪个。对方的每条意见写明收没收、为什么。讨论是 AI 之间的事，人只拍板。

## 本机工具（引擎接活之前）

脚本在本技能的 `scripts/` 目录，下面写成 `$S`（Claude Code 是 `~/.claude/skills/discuss/scripts`，别家是 `~/.agents/skills/discuss/scripts`）；要这台机器上登录好的 Cursor 命令行（`cursor-agent login`）。

`node $S/ask.mjs --text 题面.md --round <0|1|2…> [--models gpt] [--limit 45]`

- `--round 0` 是各自独立答，1 起是挑错。默认只问 GPT；要盲设计、或者 GPT 答不上时才加别家（`--models gpt,kimi,glm`，最多 3 家：本机同时有工人在跑，五家齐跑加工人顶满进程数，宿主崩过）。界面类的题不找 GPT，换 Kimi 或 GLM。
- 每家一个 `cursor-agent --mode ask` 只读会话（空目录、不读仓），硬上限 30 秒（GPT 偶尔要 `--limit 45`）；超时、退出码非 0、没输出都照实记成「没答上」。退出码 2 = 没讨论成（一家都没答上，或这台没装、没登录 Cursor 命令行），别拿自己的方案冒充结论。
- 接着聊：把上一轮的原话、你的回应和新证据写进新题面再问一次（`ask.mjs` 每次都是新会话，所以上一轮要贴全）。
- `node $S/second-opinion.mjs --text 材料.md --name 短名 --author-family <族[,族…]> --effort medium [--blind] [--agent <profile>]`
  - `--author-family` 必须显式给出当前作者模型族，可重复传或用逗号分隔：`gpt`、`claude`、`deepseek`、`grok`、`kimi`。缺失或写了未知族直接退出，不从环境变量、会话名或模型字符串猜。
  - 候选族固定按 `GPT → Grok → Claude → DeepSeek → Kimi` 排序（创始人 2026-10-05：「第二意见太慢了，我建议优先gpt6luna，不行就grok」）；作者是 GPT 就跳过 GPT，作者是多族就全部跳过。显式 `--agent` 也要经过同族排除，不能手动绕过。
  - `--text` 和 `--pr` 同一套等法：一家起了会话后连续 4 分钟（`--stall-min`）没有任何新输出就停掉换下一家，几家加起来整轮上限 15 分钟（`--timeout-min`）；端点不可用也换下一家。结论已经收到后由本机解析，不因不喜欢结论换家。`--text` 想要更短的总预算用 `--budget-sec`。
  - 已接入的真实端点：GPT=`Mirasim/codex/gpt-6-luna`、DeepSeek=`Mirasim/dsh/deepseek-flash`、Kimi=`Mirasim/kimi/kimi-code/k3`、Claude=`reclaude -p --output-format json --effort medium --max-turns 1`。Grok 只在本机/Mirasim 真有执行体和登录态时尝试；端点缺失、未登录或 roster 不含该模型都照实记录并换下一家，不假定按量 API 可用。

## 审 PR（第二意见）

先审后合只剩两种改动：迁移里有删改语句；碰安全（密钥与登录鉴权、CI 工作流和卫生检查、法国防火墙、sudoers、香港 nginx），清单在 `packages/conventions/high-risk-paths.json`。清单里标了 `review: after-merge` 的（CI 判法那几份）先合后审：合并闸不等第二意见，合并后由本脚本补审（下面「合并后补审」）。其余 CI 绿就合，不补审。

- `node $S/second-opinion.mjs --pr <号> --high-risk --author-family <族[,族…]> [--ui]`：起一个全新的不同厂商会话审这个 PR，通过就在 PR 当前的头上写上合并闸认的「第二意见」提交状态；头变了要重审。已经合并的 PR 也能审（合并后补审，状态照样写在它的头上）。改到页面代码的加 `--ui`，不找 GPT。先审后合的 PR 若所有候选都不可用，退出码 2、合并闸不通过，不能自己写状态冒充通过；普通 PR 仍按 CI 绿就合的规则走。
- **挡不挡由脚本判，不信审的人最后那句结论**（创始人 2026-10-03「1+2+3」第 2 条，决定记录 0016；判法钉在 `agents/test/rules/second-opinion-verdict.rules.test.ts`）：审的人每条必须改要标【现实】/【构造】和【碰安全】/【改数据库】/【其他】。【构造】（要人故意写出特殊写法才出现）的一律不挡，算小毛病；第 1、2 轮【现实】的都挡（没带标签的按【现实】【其他】算）；第 3 轮起只挡【现实】且碰安全或改数据库的，其余写通过、评论里列「转合并后处理」（合并后开小单修）。第几轮 = 这个 PR 上脚本已经贴过的结论评论数 + 1，不管头变没变（`--round` 不算数）；读不到评论按第 1 轮算，宁可多挡。
- 退出码：0 通过；1 必须改（改完推上去再审）；2 没查成（连不上、没起来、超时、结果格式认不出——没有「必须改」那一段、最后一行不是结论），不当通过；3 没带 `--high-risk`。
- 同一个 PR 同时只跑一轮（按 PR 号锁，后来的退出 2）；不同 PR 可以并行，各拿一棵审查树（最多 4 棵，`--slot` 指定）。
- 主审连不上换下一家；几家都用不了照实报，别自己写状态冒充审过。
- **会话是一次性的，跑完就删**（创始人 2026-10-03：「你现在每次都会在 mirasim 起一个会话，我根本不想看见它，并且我希望随时能清理掉」）。Mirasim 上跑 GPT 那几家必然在会话列表里建一个会话（协议没有「藏起来不问」的起法，`open=false` 只是不弹窗），所以脚本跑完——成了、必须改、超时都算——用 `deleteSession` 把会话连它的目录和账本一起删掉，不留在列表里等人清。排查要留着看的那次加 `--keep-session`。
- `node $S/second-opinion.mjs --sessions`：列本机 Mirasim 上现有的会话（键、状态、是不是我们留下的）。`--stop-stale`：把已停的第二意见/反方会话一次清掉（正在跑的不动）。跑完自动删之后这两个只剩排查用——早先留下的旧会话拿它清。

## 合并后补审（先合后审的那一半）

- `node $S/second-opinion.mjs --after-merge-pending`：列主线上 14 天内合并、改到了清单里标 `review: after-merge` 的路径、PR 头上还没有通过的「第二意见」提交状态的 PR。读的是主线上那份清单，从这个标记第一次出现在主线上起算；读不到、认不出报没查成、退出码 2，不当成「没有」。`--json` 给机器读，`--no-fetch` 不取远端。
- `node $S/second-opinion.mjs --after-merge-sweep --author-family <族[,族…]>`：把上面还没补审的逐个审一遍，结论和状态照常贴到各自的 PR 上。补审没过的不重跑（重跑只会撞出一次随机的「通过」）：开修复 PR，或 `git revert <合并提交>`；修复合了跑 `--after-merge-resolve <原 PR 号> --by <修复 PR 号>` 记成已处理（只认原 PR 头上是补审没过、修复 PR 已合并的）。
- 开会话钩子（`agents/hooks/session-start.mjs`）在 fleet-dao 的检出里开会话时查一次（硬超时 8 秒）：有待补审的、或没查成才说一行；超时、网络不通算没查成，不当成「没有」。

## 判例

- 2026-08-14 第一次三臂盲设计：两个守住盲的臂独立得出同一个答案，证明「各自独立答」能给出收敛信号。当时每臂起完整会话、读仓外中性目录，一轮要几十分钟。
- 2026-09-25：创始人把总指挥的分析手贴给网页 GPT，20 秒拿回把框架推进一步的反驳（bootstrap 与生产运营混了）。挑错要的是对方看到具体方案，快比完整重要；于是改成一问一答。同日实测 medium、限 400 字：12–20 秒一轮。
- 2026-09-26：把「项目为顶层」方案连同多家挑错结果一起交创始人拍，里面有他没提、也不理解的前提（一个项目挂多个平台）。改成先和他聊清前提、只找 GPT 挑错。
