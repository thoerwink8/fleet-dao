# `discuss`：讨论

规矩本身在 `docs/design.md` 第五节「讨论」（什么时候触发、拍板怎么走、没人拍怎么办），这里只写本机怎么做。和审查是两回事：审查看代码，讨论定方案。盲设计题就是讨论的第 0 轮，是同一种东西。

## 何时用

- 重大方案要请人拍之前：碰人闸（对外发布、花钱、删数据、改标准）、和已拍的规矩冲突、新加外部服务、改架构或改阶段划分（和引擎同一条判据，design 第五节「重大方案人拍」）。
- 用户说「出设计题」「先出盲设计题」「讨论一下」「让别家看看」。

小方案 AI 直接定，不用讨论；小选择题（已经收敛成 A 还是 B）也不用。

## 做法：一问一答，不起完整会话

每轮都是一问一答：不读仓、不跑命令、限 400 字、中等思考强度，每家 30 秒内。

1. **第 0 轮，各自独立答**：只写题面（背景、诉求、要回答的），**不带自己的方案**，并行发两家。题面一字不提示期望的方案形态。
2. **第 1 轮，挑错**：自己的方案 + 第 0 轮的答案一起发一家，要它说框架对不对、漏了什么、选项怎么改。
3. 有新分歧再来一轮：自己自动挑错最多 2 轮；创始人回了新材料再跑的最多 3 轮；到数就停下等人拍，先做别的。

材料里附上相关规则原文、数据和出处（对方看不到仓，漏写的事实它就不知道）。

## 交给人

只写三样：各家一致的、还剩的分歧、推荐哪个。对方的每条意见写明收没收、为什么。讨论是 AI 之间的事，人只拍板。

## 本机工具（引擎接活之前）

`node ~/.local/share/second-opinion/ask.mjs --text 题面.md [--models gpt,kimi,glm,grok] [--limit 30]`

- 同一段题面并行问几家，每家一个 `cursor-agent --mode ask` 只读会话（空目录、不读仓），硬上限 30 秒；超时、退出码非 0、没输出都照实记成「没答上」。退出码 2 = 一家都没答上，算没讨论成，别拿自己的方案冒充结论。
- 第 0 轮和挑错轮用同一个命令，区别只在题面：第 0 轮只写问题，挑错轮带上自己的方案和第 0 轮的答案。
- 默认四家（GPT、Kimi、GLM、Grok）；2026-09-26 实测 GLM 21 秒、Kimi 25 秒、GPT 27 秒，Grok 常超时。本机同时有工人在跑时用 `--models` 只挑 3 家（五家齐跑加工人顶满进程数，宿主崩过）。界面类的题不带 gpt。
- 结论落在脚本旁边的 runs 目录（本机，不进仓）。Mirasim 云端这条路还用 `second-opinion.mjs --text 材料.md --name 短名 --effort medium [--blind] [--agent code|kimi]`，要几十秒到几分钟，Cursor 那几家答不上时再用。

## 判例

- 2026-08-14 第一次三臂盲设计：两个守住盲的臂独立得出同一个答案，证明「各自独立答」能给出收敛信号。当时每臂起完整会话、读仓外中性目录，一轮要几十分钟。
- 2026-09-25：创始人把总指挥的分析手贴给网页 GPT，20 秒拿回把框架推进一步的反驳（bootstrap 与生产运营混了）。挑错要的是对方看到具体方案，快比完整重要；于是改成一问一答。同日实测 medium、限 400 字：12–20 秒一轮；第 0 轮两家独立答 + 第 1 轮挑错，全程约一分钟（#69 的讨论稿就是这样出的）。
