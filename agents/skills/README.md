# 方法类 skill

## 这里放什么

各仓都用得上的思考方法和角色（比如指挥官 `commander`），每个一个目录，里面一份 `SKILL.md`：frontmatter 的 `description` 一句话写什么时候读，正文写怎么做。只对某一个仓有用的流程、脚本、钩子不放这里。

个别 skill 带脚本，放在它自己目录的 `scripts/` 下（比如 `commander` 的法国引擎页、本机工人启动器），同步时连子目录整个拷过去。脚本的数据写到家目录里，不写进 skill 目录：同步见 skill 目录里多了文件，会把整个目录换回仓里的样子。

**只放自研的。** 网上公开的基础 skill（先写测试、系统排错、完成前验证这一类）不放这里，放 `agents/skills-vendor/`：原样拷入、旁边有锁文件记来源和审查，规矩见那边的 `README.md`（创始人 2026-09-30 拍：自研和公开的分目录）。这里的测试（`agents/test/skills.test.ts`：描述不超过 120 字、指针都指得到）只管这里；第三方的描述可以长到 1024 字、指向它自己的脚本，放进这里会让测试红。

## 怎么分发

由规矩同步脚本 `packages/agents-sync` 分发，见 `docs/design.md`「三、已定（共识）」第 16 条：这里有几个目录就分发几个，拷进各家 AI 的 skill 目录；从这里删掉的，下次同步会从各家那里撤掉。`agents/skills-vendor/` 里核过锁文件的第三方 skill 同一趟一起装、一起撤；两边有同名的，同步脚本直接报错、一个都不发。

## 加新 skill 的门槛

至少两个仓用得上，才从别的仓提回这里；只有一个仓用得上的，留在那个仓里。
