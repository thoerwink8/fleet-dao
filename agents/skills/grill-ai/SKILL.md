# `grill-ai`：从零拷问我自己的做法

## 和 `grill-me` 的分界

| | 拷问对象 | 典型开场 |
| --- | --- | --- |
| `grill-me` | **用户脑子里的方案**：该不该做、长什么样 | 「拷问我」「grill me」「帮我压一压」 |
| `grill-ai` | **我手上正在走的路**：这条路是不是从一开始就走歪了 | 「不对劲」「从零拷问」「你这做法有问题」，或我自查触发 |

一句话分界：**要动的是用户的想法 ⇒ `grill-me`；要动的是我自己的做法 ⇒ `grill-ai`。**
两个都像 ⇒ 先 `grill-ai`：自己的路没证明是对的之前，拷问用户的想法只是在替一条歪路找理由。

## 何时触发

**用户触发**：上表里的任一说法，或直接点名本 skill。

**自触发（硬闸，不等用户发现）**：动手前先过这三问，任一命中即停。「动手」含开单——写代码算动手，新开一张 issue 同样算。

1. **补丁层数**：这次改动的起因，是不是「我上一次改动带来的副作用、或它没覆盖到的情况」？
   - 是 ⇒ 这是补丁第 1 层，记下，先不算命中。再问一次：**上一次**改动的起因，是不是又是它前一次改动的副作用？
   - 也是 ⇒ 我正在动手的是**第 2 层**，本问命中：同一种办法连错了两次。
   - 计数只认「同一目标、同一方向」，**不看时间跨度、不看改的是不是同一个文件、不看每层看起来多小**。补丁在局部看都小而顺手，正是这样骗过计数的。
   - 层号从记账里读，不靠回忆（见「补丁链记账」）：补丁链常跨会话形成，回忆一定漏。
   - **横向分裂也算一层**：同一个空缺在 N 个地方冒头，会裂成 N 张各自成立、各有证据的单——**正因为每张单看都合理，计数不会响**。自查一句：这几天开的单里，有没有两张的**起因能写成同一句话**？能，就是同一层，合成一张从零重推，不许并行派 N 个人去修。
2. **措辞报警**：我的方案里出现「兼容一下现状」「先这样绕过」「加个开关避免冲突」「再加一层就能圆上」——出现即视同第 1 问命中。
3. **同处二修**：同一处问题我已经修过两次还没修好。

自触发时不许「顺手先修完再说」：**当场停手，本轮不落盘**，先把下面的清单走完，再决定要不要动手。

## 加层还是返工

分界线：**上一层按设计工作了、是它的设计带来新后果 ⇒ 加层；上一层没做到自己的设计、把它改对 ⇒ 返工，不加层。** 返工次数多不触发本 skill（那是实现质量问题），补丁层数才触发。

- **算加层**：目标是「定时任务别重复跑」。第 0 层加一把文件锁；第 1 层，进程崩了锁没释放，于是加「锁超过 10 分钟算过期」；第 2 层，任务偶尔真跑过 10 分钟、两份又撞上，于是准备加「续约心跳」。目标没变，每层都留着上一层的机制、只绕开它的后果 ⇒ 第 2 层命中，停手。从零看的选项：换用调度器自带的「同一任务不并发」，或者让任务跑两遍也没事——整层锁都不要。
- **算返工**：上一轮说好「比对文件内容」，实际只比了文件名，这轮改成比内容。上一层没做到自己的设计，改对就是返工。

换方向的判准：**上一层的机制被整段删掉了，才算换方向、层号归零；它还留着、只是在旁边加东西，就仍是同一条链。**

## 补丁链记账

层号要记在跨会话找得回的地方，不然换一轮上下文就归零。最省事的记法：判出第 1 层时给这条链起个短名（如 `job-lock`），此后每层的 commit 标题末尾带 `[chain:<短名>#<层号>]`，动手前 `git log --all --grep="chain:<短名>" --oneline` 查一次。0 命中不等于没有链——浅克隆、squash 合并丢了分支上的提交信息都会查不到，查不成就按「有链」处理。不进 git 的改动（本机配置之类），把链记在 issue 正文。

## 五条清单（逐条回答，不许跳）

1. **第一性原理**：剥掉全部现状与已有实现，这件事的本质需求是什么？从零推，最好的做法长什么样？
2. **补丁链检查**：现在的方案是不是在给现状做兼容、打补丁？画出补丁链，每一层在修谁的副作用。补丁已到第 2 层，必须停手从零重推，不许在原方向打第 3 层。
3. **五步法按序过一遍，顺序不可换**：
   - 质疑需求：谁提的、为什么、今天还成立吗？说不出提出人和理由的，默认不成立。
   - 删除：删掉它（或它的哪一层）会坏什么？多久坏一次、谁会叫？
   - 简化：删无可删之后，剩下的能不能更简单——合并同类、去掉分支、用现成机制代替新造。
   - 加速：只给确定要留的环节提速。
   - 自动化：最后才谈；把一个错的流程自动化，只会更快地出错。

   本 skill 的加严：**删除**这一步必须摆出「删掉整层」的选项——不是「删掉某个参数」，是「这一层机制根本不要，回到没有它的世界」。摆不出来，这一步就算没过。
4. **摆差异与代价表**：把「从零方案」和「现状方案」的差异与代价摆出来交用户拍板，**禁止替用户默认取舍**。
5. **判制度**：这次偏差是制度缺失，还是执行失守？
   - 执行失守（规矩本来就有，是我没认出来）⇒ 把这次记成判例（能写成测试就写成测试），不改规矩。
   - 确属制度缺失 ⇒ 才提议改规矩。

## 收尾

清单走完，必须让用户拍板：用当前环境的提问工具出选择题；没有提问工具，就列编号选项请用户回编号。选项里至少包含**删掉整层的从零方案**和**继续现状方向**，各带代价。

不许自己选完再通知用户，也不许「两个都做」——那是第 3 层补丁换了个名字。
