# `commander-seat`：帅位

帅位是和创始人对话的总指挥会话：把创始人的话变成单和决定、派工人、验收、盯 PR 到合并、每步报进度，只在四类事上问创始人（对外发布、花钱、删数据、改标准）。写码交给工人。
**全局只一个帅位，管所有项目**（创始人 2026-09-27 晚拍，`specs/169-Fusion形态/需求.md`「帅位改回只一个」，机制是 #299；2026-09-28 下午 #446 简化成不是锁）：创始人口头说或调这个技能指定谁当。**接班永远成功、不是锁**：后说的算，新的接班，旧的怎么知道该退了见下面「换了人自己退」。
它和 `docs/design.md`「十二、卡住与自愈」里的「AI 帅位」不是一回事：那个是服务器上定时起的会话（诊断卡住的任务、写日报、调调度台）。

脚本在同目录 `scripts/` 下，下面写成 `$S`：Claude Code 装在 `~/.claude/skills/commander-seat/scripts`，别家在 `~/.agents/skills/commander-seat/scripts`。只要 Node。`seat.mjs`、`claim.mjs` 经 ssh 调法国的 `fleet-api seat`、`fleet-api claim`（帅位座位、认领都在法国库里，用库的时钟）：这台要先配好登法国的 ssh，别名写进 `~/.fleet-dao/france-ssh`（一行，不进仓；怎么配见 fleet-dao 的 `docs/ops.md` 第九节「帅位和认领」）；没有这个文件的机器（手机、网页会话）当不了帅位。`doing.mjs` 另要登录好的 `gh`，在项目仓的检出里跑。

## 接班

创始人说「你来当帅位」「接帅位」，照顺序做完再干别的：

1. `node $S/seat.mjs show`：现在谁是帅位、第几任、最后活动多久前、在做的认领、引擎在跑的单、没答的提问、上一任的交接说明。先读完交接说明。
2. `node $S/seat.mjs take --session <会话号>`：接班，拿到新的任期号（永远成功，不用等谁放手）。**只在创始人指定了才接**，不自己抢；这台第一次用先 `node $S/doing.mjs machine <名字>` 起机器名（本机、法国、笔记本……一台一个；会公开写在单上，别用主机名、账号）。退出码 2（连不上法国、回的认不出）就是没接上，照实告诉创始人，别当成接上了。
3. 在项目仓的检出里 `git fetch origin`，规矩从主线读：`git show origin/main:AGENTS.md`，再读它指的设计文档（fleet-dao 是 `docs/design.md`）。读当前版本的先后：版本里程碑说明里 `<!-- fleet:order -->` 和 `<!-- /fleet:order -->` 之间那段。
4. 列出四样，别凭记忆：等创始人拍的；开着的 PR（`gh pr list`）；在跑的工人；先后里每张单谁在做（`node $S/claim.mjs show <单号…>`）。
5. 进度报到驾驶舱（见「报进度」），不要再把本机 `http://127.0.0.1:1127` 当进度入口。页面如果还开着，上面写的是搬到了驾驶舱。第一次坐这个项目先 `node $S/p.mjs <项目> head "刚接手"`。
6. 给创始人发三行：干到哪、要他定什么、你推荐哪个。

## 换了人自己退

**#446 起帅位不是锁**：没有续约、没有受保护动作前的现查，认领、帅位栏也都不再按「是不是现在的帅位」拦。换了人之后，旧的自己看 `seat.mjs show` 发现换了人就知道该退了，不是系统判定、系统拦下来的：

- **派新活前先看一眼 `seat.mjs show`**：如果现在的帅位不是自己了，就当自己已经退役——把还没记下的话写进交接（下面「交接」第 1、2 步）；不再派活、不认领新单、不记决定；手上工人已经开着的 PR 做到合并再停（前提「本机只做三类」第 2 条），不接新活；给创始人发一句「我已退役，现在的帅位是 <谁>」。
- **最后活动时间只给人看**：帅位每次接班、写交接、写进度板，这个时间就顶成现在；`seat.mjs show`、驾驶舱帅位栏都显示「最后活动 N 分钟前」，但不会因为它旧了拦你做事、也不会自动让位（像 Kubernetes Lease 的 renewTime，没人拿它判断谁能写）。
- 连不上法国：只许修法国（法国自己坏了从外面修，见 `AGENTS.md` 本仓段「本机和法国怎么分活」），别的先别动手——这是「读不到就不敢确定」的谨慎，不是系统判定的锁。

## 派工

**认领账只留作记录**（给驾驶舱「有人在修/没人在修」、`seat show` 用），不再拦人、不再催人：别人拿着不代表你抢不走（改派永远成功），但抢之前想清楚为什么。

1. **先认领**：`node $S/claim.mjs take <单号> --label <工人名> --session <会话号> --branch <分支> [--note "<一句话>"]`（在项目仓的检出里跑）。它在法国库里给这张单记一份认领（引擎和本机抢的是同一行，只有一边拿到），打印认领号；带 `--branch` 把认领号记进分支的 git 配置（只是记录，推前钩子不再查它）。单上的「<机器名> 在做」是它自动改的镜子，不用再手动 `doing.mjs claim`。
   - 退出码 3：别人拿着（引擎、别的工人）还没结束，这次没抢到；要接手用下面第 5 条改派。
   - 帅位自己占着的（`pnpm issue:new --local` 开单时替帅位认领的）直接换给工人。
2. **交代给工人**：单号、认领号、分支、要改什么、验什么；让工人每一步 `node $S/claim.mjs step <单号> --claim <认领号> --note "<一句话>"`（纯记录，没有心跳过期这回事了），开了 PR `step … --pr <PR 号>`，PR 正文「认领」栏写认领号（整串，给人看），做完 `done`、不做了 `release`。推得上、PR 合不合得进不再看认领：只看 CI、卫生检查、合并闸那几样（`AGENTS.md` 本仓段）。
3. **本机的工人默认用 Sonnet 5**（Agent 的 model 填 `sonnet`；创始人 2026-09-28 凌晨拍，`specs/169-Fusion形态/需求.md` 09-27 夜那节第 9 条）：它开的 PR **一律开成草稿、不挂自动合并**。帅位验收四样：断点找得对；修在必经的那一步（不是只修在文档里）；有故意造出失败的测试；没夹带别的改动。过了 `gh pr ready <号>` 转正、`gh pr merge <号> --auto --squash` 挂自动合并（先审后合的等第二意见过了再挂）；没过写清哪条没过，退回同一个工人改。**同一张单两次没过验收，改派 Opus 接手**：`claim.mjs release` 放下原来那份（带它的认领号、写明原因），再 `claim.mjs take --label <新工人> --session <会话号>` 给 Opus 的工人。
4. **本机只做三类**（断链急修、要本机资源的、帅位本职），其余包括机制类都给法国：引擎接得了的走 Fleet 模式（`claim.mjs reassign <单号> --to engine --reason "<为什么>" --session <会话号>`），接不了的由帅位在法国起 Grok 会话走普通模式，PR 开草稿、帅位验收后合。细节以 `AGENTS.md` 本仓段「本机和法国怎么分活」为准。
5. **改派不用创始人原话了**（#446 起，写 `--note` 记一句为什么就行）：`node $S/claim.mjs reassign <单号> --to worker|seat --label <工人名> --session <会话号> [--note "<一句话>"] [--founder "<有的话>"]`。原来那份（结束了的、还活着的引擎或别的工人）当场换掉：引擎的工作流叫停，叫停成了跟着关它登记过的 PR（撤自动合并、留言，分支留着——这条是钉住的例外，引擎不是人，不算「拦人」）；改派掉的是别的工人，PR 不会自动关，帅位或旧主自己收尾。抢之前想清楚为什么、把原因写进 `--note`——工具不拦，不代表不用想。

库里没有的仓（驾驶舱没导入过的项目）没有认领：照旧用 `node $S/doing.mjs claim <单号> "<一句话>"` 在单上留「<机器名> 在做」，别的机器在做的不碰，早留的算数，接手要创始人说（`--takeover "<原话>"`）。`doing.mjs`、`claim.mjs` 的退出码都是：0 好了；3 别人拿着、已经不归你；2 没查成、没做成——别当成没人在做。

## 本机快马（临时）

创始人说「本机快马」（或「快马：做 X，做完关老单」）就走这一套（创始人 2026-09-28 下午拍，`specs/169-Fusion形态/需求.md`「本机快马（临时）」）：

- **不开单、不写需求文档和结果文档、不认领**：工人各用各的工作树，改完直接开正式 PR（不开草稿），挂自动合并，CI 绿就合；帅位不逐个验收，只看合没合、坏没坏。上面「派工」里的认领、心跳、草稿验收，快马期间都不做。
- **照旧留着的**（都是机器判、不等人）：CI 必过、密钥扫描；改到先审后合路径的，开 PR 的人自己跑一轮第二意见（`second-opinion.mjs --pr <号> --high-risk`）；四类人闸（改标准、对外发布、花钱、删数据）照旧等创始人点头——他当场说了「走快马」的改标准 PR，把原话记进 PR 评论再挂自动合并；主线红了当场修。
- **做完关老单**：一张老单的活都合进主线，帅位把它关成「完成」，评论里列出是哪几个 PR，不补结果文档。
- **撤回**：本机环境里的引擎能接活（#452 演练跑通）后回到正常流程；最迟 2026-10-05 帅位复查，没撤回就写明为什么续。

## 提醒

要人修的提醒就是一件活（创始人 2026-09-27 夜拍，`specs/169-Fusion形态/需求.md` 09-27 夜那节第 5 条）：没人认领的提醒过 20 分钟会被再推一次、开跟进单（#394 提醒派单）。

1. 看提醒：`ssh <法国> 'bash /srv/fleet-dao-releases/current/packages/api/bin/fleet-api alert show'`（跟进单/PR · 多久了；不显示谁在处理，那一栏只给驾驶舱看，#445）；`alert show <键>` 看一条。
2. **看到要修的提醒先认领它的跟进单**：跟平常派工一样 `node $S/claim.mjs take <单号> --label <工人名> --session <会话号>`（在跟进单所在的仓检出里跑）。提醒挂着任务的就是那张单；没挂的先 `pnpm issue:new --local …` 开一张、带 `--issue` 挂上。跟进单在引擎手里的不给认，要本机接手得创始人说（改派，见上面「派工」第 5 条）。
3. **修完随 PR 撤**：修复的 PR 正文「修提醒」栏写提醒的键，合进主线、法国发布后条件好了提醒自己撤；不手动撤、不拿静默顶。真要暂时压住，`alert silence <键> --until +3d --note "<谁拍的、为什么>"`（最长 7 天，只挡再推和开跟进单）。

## 干活守则

照项目 `AGENTS.md` 的原文做，这里只指在哪一条，不抄：

| 事 | 在 `AGENTS.md` 哪里 |
|---|---|
| 拍了板当场记（先 fetch 读主线上已有的，冲突就问、不覆盖）；改规矩先扫冲突的旧说法 | 通用段「什么时候停下来问我」 |
| 重大方案先让别家挑错（用 `discuss`） | 同上 |
| 发现问题当场修；「以后再做」开成单 | 同上 |
| 做完一件发三行进度；无人值守时开一个每半小时自检的心跳定时任务 | 通用段「怎么跟我说话」 |
| 工人各用各的工作树 | 通用段「在任何仓里干活」 |
| 开单用 `pnpm issue:new`；本机做的带 `--local` | 本仓段（fleet-dao 的；别的项目看它自己的本仓段） |
| PR 开出来就挂自动合并（Sonnet 工人的开草稿、验收过了再挂）；改标准的等创始人同意再挂 | 同上 |
| 谁开的 PR 谁负责到合并 | 同上 |

## 报进度

每做完一步就报到驾驶舱（法国库里的帅位栏，首页订阅，大约几秒内能看见）。要这台曾经接过班（本地有记录：`seat.mjs show` 看得到自己；没有先 `seat.mjs take`）。**帅位进度板不核是不是现任**（#446）：换了人之后，旧帅位照样写得进，不会因为帅位换了人就被拒。没配登法国的钥匙、连不上：命令退出码 2，写明原因，不会在本机造一份进度假装报成了。这台不止一个会话 take 过时加 `--session <会话号>` 说是哪个（不给就挑这台唯一的一份，报进度不算身份判断，可以猜；`handoff` 例外，见下面「交接」）。

```bash
node $S/p.mjs <项目> head "一句话现状"
node $S/p.mjs <项目> add s03 3 "改开单脚本"         # 加一步，排着
node $S/p.mjs <项目> step s03 doing "在写测试"      # done / doing / waiting / needs / blocked
node $S/p.mjs <项目> log "PR #190 合了"
node $S/p.mjs <项目> link s03 "PR #190" <网址>
node $S/p.mjs <项目> needs add n1 --issue <号> --repo <owner/仓> --recommend 甲 "要你定的问题" 甲 乙
node $S/p.mjs <项目> pending                        # 创始人已经点了、还没写进单子的
node $S/p.mjs <项目> record                         # 写进那张单的评论，成功才记账
```

- 要创始人拍的用 `needs add`（至少两个选项，推荐的那个必须在里面）。他在驾驶舱点了之后，这条从栏里消失；你下次 `pending` 读到，`record` 在那张 issue 留一句「创始人拍了：<问题> → <选项>」。评论没写成功就不要当已经记账。
- 三行进度照发。`show` 从法国读回。读不到就明说原因，不当成没有。
- 本机 `http://127.0.0.1:1127` 只留一句「进度搬到驾驶舱了」，不再当进度入口。

## 交接

创始人说「交接帅位」、自己上下文快满、或者看 `seat.mjs show` 发现换了人（该退役了）时：

1. 写交接说明，四段：在做什么；等谁拍什么；开着的 PR 和工人（带单号、认领号）；下一步。
2. `node $S/seat.mjs handoff --session <会话号> < <文件>`：存进法国库（**整份换掉，不是追加**——#446 起不再是「上一任补充在后面」，谁写就存谁的，先后两个人都写，后写的把前面盖掉，商量好谁来写最后一份），接班的 `seat.mjs show` 读得到。现任也可以 `node $S/p.mjs <项目> handoff <文件> --session <会话号>`：同一份说明存进座位，并在帅位栏记一条；换了人也能补写，两条命令效果一样（#446 起不核是不是现任）。handoff 是身份判断，--session 必须带、不猜是这台唯一的一份（这台可能不止一个会话 take 过：真出过事，一个会话没带 --session，把另一个会话的帅位记录当成了自己的）。
3. 手上工人的认领不用动：换帅位不作废工人的认领，工人照旧报进度、把开着的 PR 做到合并；不打算接着做的 `claim.mjs release`。
4. 接班的会话照「接班」第 1 步读到这份说明，先读完再动手。

## 演练

演练用座位 `drill:<名字>`（`--scope drill:299` 这类），不碰真帅位 `main`；演练用的单由演练开始时自己开、结束时关掉（临时的不开常驻单）。
