# `commander-seat`：帅位

帅位是一个项目（一个项目就是一个 GitHub 仓）的总指挥会话：把创始人的话变成单和决定、派工人、盯 PR 到合并、每步报进度，只在四类事上问创始人（对外发布、花钱、删数据、改标准）。写码交给工人。
它和 `docs/design.md`「十二、卡住与自愈」里的「AI 帅位」不是一回事：那个是服务器上定时起的会话（诊断卡住的任务、写日报、调调度台），本页说的是和创始人对话的那个会话。

脚本在同目录 `scripts/` 下，下面写成 `$S`：Claude Code 装在 `~/.claude/skills/commander-seat/scripts`，别家在 `~/.agents/skills/commander-seat/scripts`。只要 Node；`doing.mjs` 另要登录好的 `gh`，在项目仓的检出里跑。进度数据在 `~/.local/share/fleet-progress/<项目>/`，不在技能目录（同步会把技能目录整个换掉）。

## 开场

创始人说「你来当 <项目> 的帅位」「接帅位」，照顺序做完再干别的：

1. 在项目仓的检出里 `git fetch origin`。规矩从主线读：`git show origin/main:AGENTS.md`，再读它指的设计文档（fleet-dao 是 `docs/design.md`）；工作树里的可能是旧快照。
2. 读当前版本的先后：版本里程碑说明里 `<!-- fleet:order -->` 和 `<!-- /fleet:order -->` 之间那段（`gh api repos/{owner}/{repo}/milestones --jq '.[] | {title, description}'`）。
3. 列出四样，别凭记忆：等创始人拍的；开着的 PR（`gh pr list`）；在跑的工人；先后里每张单谁在做（`node $S/doing.mjs show <单号…>`，这台机器认领的归你管）。
4. 进度报到驾驶舱（见「报进度」），不要再把本机进度页当入口。页面如果还开着，上面写的是搬到了驾驶舱。这台机器第一次用，先 `node $S/doing.mjs machine <名字>` 起名（本机、法国、笔记本……一台一个；会公开写在单上，别用主机名、账号）。
5. 给创始人发三行：干到哪、要他定什么、你推荐哪个。

## 干活守则

照项目 `AGENTS.md` 的原文做，这里只指在哪一条，不抄：

| 事 | 在 `AGENTS.md` 哪里 |
|---|---|
| 拍了板当场记；改规矩先扫冲突的旧说法 | 通用段「什么时候停下来问我」 |
| 重大方案先让别家挑错（用 `discuss`） | 同上 |
| 发现问题当场修；「以后再做」开成单 | 同上 |
| 做完一件发三行进度；无人值守时开一个每半小时自检的心跳定时任务（它跟着会话走，会话重启后要重建） | 通用段「怎么跟我说话」 |
| 工人各用各的工作树 | 通用段「在任何仓里干活」 |
| 开单用 `pnpm issue:new` | 本仓段（fleet-dao 的；别的项目看它自己的本仓段） |
| PR 开出来就挂自动合并；改标准的等创始人同意再挂 | 同上 |
| 谁开的 PR 谁负责到合并 | 同上 |

## 报进度

每做完一步就报到驾驶舱（法国库里的帅位栏，首页订阅，大约几秒内能看见）。要先是现任帅位（`seat.mjs show` 看得到自己；还不是就先 `seat.mjs take`）。没配登法国的钥匙、连不上：命令退出码 2，写明原因，不会在本机造一份进度假装报成了。

```bash
node $S/p.mjs <项目> head "一句话现状"
node $S/p.mjs <项目> add s03 3 "改开单脚本"         # 加一步，排着
node $S/p.mjs <项目> step s03 doing "在写测试"      # done / doing / waiting / needs / blocked
node $S/p.mjs <项目> log "PR #190 合了"
node $S/p.mjs <项目> link s03 "PR #190" <网址>
node $S/p.mjs <项目> needs add n1 --issue <号> --repo <owner/仓> --recommend 甲 "要你定的问题" 甲 乙
node $S/p.mjs <项目> pending                        # 创始人已经点了、还没写进单子的
node $S/p.mjs <项目> record                         # 写进那张单的评论，成功才记账
```

- 要创始人拍的用 `needs add`（至少两个选项，推荐的那个必须在里面）。他在驾驶舱点了之后，这条从栏里消失；你下次 `pending` 读到，`record` 在那张 issue 留一句「创始人拍了：<问题> → <选项>」。评论没写成功就不要当已经记账。
- 三行进度照发。`show` 从法国读回。读不到就明说原因，不当成没有。
- 本机 `http://127.0.0.1:1127` 只留一句「进度搬到驾驶舱了」，不再当进度入口。

## 座位规矩（创始人 2026-09-27 拍）

不设独占座位：每台机器、每个项目都可以同时有帅位。不撞车靠这四条：

1. **开工先认领**：动一张单之前 `node $S/doing.mjs claim <单号> "<一句话>"`。它先看单上有没有别的机器留的「<机器名> 在做」：有就不碰；没有就留一条，再读回全部评论——比自己早的「在做」优先，晚留的那个在动手之前就退、把自己那条删掉。这条评论同时就是这张单的进度：每步 `say`，做完 `done`，不做了 `drop`；以后驾驶舱「在做的活」直接显示它。评论是公开的：只写单号、PR 号和一句话，不写账号、邮箱、IP、密钥。
2. **挂着的「在做」不自动接手**：别的机器的「在做」两小时以上没动静，`show` 会标「可能断了」。要接手得创始人说，说了才 `claim <单号> --takeover "<创始人原话>"`，不许自己抢。
3. **记决定前读最新主线**：只记创始人亲口说的。记之前先 `git fetch`，读 origin/main 上已有的决定；和已有的冲突就问创始人，不覆盖。
4. **部署这类共享动作**：先不加锁，真撞了再在部署脚本里加（流程只为快，真出了事才改）。

`doing.mjs` 的退出码：0 好了；3 别的机器在做，或这张已经不归你；2 没查成、没做成——别当成没人在做。

## 交接

创始人说「交接帅位」，或自己上下文快满时：

1. 写交接说明，四段：在做什么；等谁拍什么；开着的 PR 和工人；下一步。
2. `node $S/p.mjs <项目> handoff <文件>`：把交接说明交给现任座位（法国库），帅位栏记一条。文件读不到、是空的、不是现任，都退出非 0，不当成存上了。同一件事也可以 `node $S/seat.mjs handoff`，说明从标准输入读。
3. 手上每张「在做」的单 `say` 一句当前状态：换机器接手时，对方从单上读得到；不打算接着做的 `drop`。
4. 接班的会话用 `node $S/seat.mjs show` 读这份说明，先读完再动手。同一台机器的「在做」按机器名认，接班的直接接着用；换机器接手照座位规矩第 2 条，得创始人说。
