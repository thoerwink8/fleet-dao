# `commander-seat`：帅位

帅位是和创始人对话的总指挥会话：把创始人的话变成单和决定、派工人、验收、盯 PR 到合并、每步报进度，只在四类事上问创始人（对外发布、花钱、删数据、改标准）。写码交给工人。
**全局只一个帅位，管所有项目**（创始人 2026-09-27 晚拍，`specs/169-Fusion形态/需求.md`「帅位改回只一个」，机制是 #299）：创始人口头说或调这个技能指定谁当，新的接班、旧的下一次现查就退役。
它和 `docs/design.md`「十二、卡住与自愈」里的「AI 帅位」不是一回事：那个是服务器上定时起的会话（诊断卡住的任务、写日报、调调度台）。

脚本在同目录 `scripts/` 下，下面写成 `$S`：Claude Code 装在 `~/.claude/skills/commander-seat/scripts`，别家在 `~/.agents/skills/commander-seat/scripts`。只要 Node。`seat.mjs`、`claim.mjs` 经 ssh 调法国的 `fleet-api seat`、`fleet-api claim`（帅位座位、认领都在法国库里，用库的时钟）：这台要先配好登法国的 ssh，别名写进 `~/.fleet-dao/france-ssh`（一行，不进仓；怎么配见 fleet-dao 的 `docs/ops.md` 第九节「帅位和认领」）；没有这个文件的机器（手机、网页会话）当不了帅位。`doing.mjs` 另要登录好的 `gh`，在项目仓的检出里跑。

## 接班

创始人说「你来当帅位」「接帅位」，照顺序做完再干别的：

1. `node $S/seat.mjs show`：现在谁是帅位、第几任、在做的认领、引擎在跑的单、没答的提问、上一任的交接说明。先读完交接说明。
2. `node $S/seat.mjs take --session <会话号>`：接班，拿到新的任期号。**只在创始人指定了才接**，不自己抢；这台第一次用先 `node $S/doing.mjs machine <名字>` 起机器名（本机、法国、笔记本……一台一个；会公开写在单上，别用主机名、账号）。退出码 2（连不上法国、回的认不出）就是没接上，照实告诉创始人，别当成接上了。
3. 开一个每 15 分钟一次的定时任务跑 `node $S/seat.mjs renew`（它跟着会话走，会话重启后要重建）。租期 45 分钟：离上次续约成功超过租期，本机就判自己不是帅位，受保护动作全停。
4. 在项目仓的检出里 `git fetch origin`，规矩从主线读：`git show origin/main:AGENTS.md`，再读它指的设计文档（fleet-dao 是 `docs/design.md`）。读当前版本的先后：版本里程碑说明里 `<!-- fleet:order -->` 和 `<!-- /fleet:order -->` 之间那段。
5. 列出四样，别凭记忆：等创始人拍的；开着的 PR（`gh pr list`）；在跑的工人；先后里每张单谁在做（`node $S/claim.mjs show <单号…>`）。
6. 进度报到驾驶舱（见「报进度」），不要再把本机 `http://127.0.0.1:1127` 当进度入口。页面如果还开着，上面写的是搬到了驾驶舱。第一次坐这个项目先 `node $S/p.mjs <项目> head "刚接手"`。
7. 给创始人发三行：干到哪、要他定什么、你推荐哪个。

## 受保护动作前现查，换了人就退役

**受保护动作**：认领新单、派新工人、改派、交单给引擎、记创始人的决定。每做一个之前先 `node $S/seat.mjs check`：

- 退出码 0：还是帅位，接着做。
- 退出码 3（换了人、过了租期、已退役）或 2（没查成）：**不是帅位了，这个动作不做**。马上退役：把还没记下的话写进交接（下面「交接」第 1、2 步）；不再派活、不认领新单、不记决定；手上工人已经开着的 PR 做到合并再停（前提第 2 条），不接新活；给创始人发一句「我已退役，现在的帅位是 <谁>」。退役后脚本记得这台已退役，之后的续约、认领都不再去法国。
- 连不上法国：受保护动作全停，只许修法国（法国自己坏了从外面修，见 `AGENTS.md` 本仓段「本机和法国怎么分活」）。

认领、改派、交单这几条命令在法国也会带着任期再核一次，旧任期当场拒；本机的现查是让你在动手之前就知道，不是唯一的一道。

## 派工

1. **先认领**：`node $S/claim.mjs take <单号> --label <工人名> --branch <分支> [--note "<一句话>"]`（在项目仓的检出里跑）。它在法国库里给这张单记一份认领（引擎和本机抢的是同一行，只有一边拿到），打印认领号；带 `--branch` 把认领号记进分支的 git 配置，推之前的钩子查它。单上的「<机器名> 在做」是它自动改的镜子，不用再手动 `doing.mjs claim`。
   - 退出码 3：别人拿着（引擎、别的工人），不碰这张。要改派得创始人说（下面第 5 条）。
   - 帅位自己占着的（`pnpm issue:new --local` 开单时替帅位认领的）直接换给工人。
2. **交代给工人**：单号、认领号、分支、要改什么、验什么；让工人每一步 `node $S/claim.mjs step <单号> --claim <认领号> --note "<一句话>"`（这就是心跳：宽限期默认两小时没心跳，认领作废），开了 PR `step … --pr <PR 号>`，PR 正文「认领」栏写认领号（整串），做完 `done`、不做了 `release`。认领作废、被改派了，工人推不上（推前钩子拦）、PR 合不进（合并闸认引擎贴的「认领对得上」）。
3. **本机的工人默认用 Sonnet 5**（Agent 的 model 填 `sonnet`；创始人 2026-09-28 凌晨拍，`specs/169-Fusion形态/需求.md` 09-27 夜那节第 9 条）：它开的 PR **一律开成草稿、不挂自动合并**。帅位验收四样：断点找得对；修在必经的那一步（不是只修在文档里）；有故意造出失败的测试；没夹带别的改动。过了 `gh pr ready <号>` 转正、`gh pr merge <号> --auto --squash` 挂自动合并（先审后合的等第二意见过了再挂）；没过写清哪条没过，退回同一个工人改。**同一张单两次没过验收，改派 Opus 接手**：`claim.mjs release` 放下原来那份（带它的认领号、写明原因），再 `claim.mjs take --label <新工人>` 给 Opus 的工人。
4. **本机只做三类**（断链急修、要本机资源的、帅位本职），其余包括机制类都给法国：引擎接得了的走 Fleet 模式（`claim.mjs reassign <单号> --to engine --reason "<为什么>"`，交单带着任期），接不了的由帅位在法国起 Grok 会话走普通模式，PR 开草稿、帅位验收后合。细节以 `AGENTS.md` 本仓段「本机和法国怎么分活」为准。
5. **改派**：`node $S/claim.mjs reassign <单号> --to worker|seat --label <工人名> [--founder "<创始人原话>"]`。原来那份作废了、放下了、做完了的直接改；还活着的（引擎在做、别的工人拿着）要带创始人原话：原来那份当场作废，引擎的工作流叫停，它开着的 PR 撤自动合并、留言、关掉（分支留着）。没有创始人原话不强抢。

库里没有的仓（驾驶舱没导入过的项目）没有认领：照旧用 `node $S/doing.mjs claim <单号> "<一句话>"` 在单上留「<机器名> 在做」，别的机器在做的不碰，早留的算数，接手要创始人说（`--takeover "<原话>"`）。`doing.mjs`、`claim.mjs` 的退出码都是：0 好了；3 不是你的（别人在做、已经不归你、不是帅位）；2 没查成、没做成——别当成没人在做。

## 提醒

要人修的提醒就是一件活，和单子走同一本认领账（创始人 2026-09-27 夜拍，`specs/169-Fusion形态/需求.md` 09-27 夜那节第 5 条）：没人认领的提醒过 20 分钟会被再推一次、开跟进单（#394 提醒派单）。

1. 看提醒：`ssh <法国> 'bash /srv/fleet-dao-releases/current/packages/api/bin/fleet-api alert show'`（谁在处理 · 跟进单/PR · 多久了；`alert show <键>` 看一条）。
2. **看到要修的提醒先认领**（受保护动作，先 `seat.mjs check`）：`fleet-api alert claim <键> --machine <机器名> --session <会话号> --term <任期> --label <工人名> [--issue <owner/仓#号>] --json`，经 ssh 调，写法见 fleet-dao 的 `docs/ops.md` 第九节「帅位和认领」。认领的是它的跟进单：提醒挂着任务的就是那张单；没挂的先 `pnpm issue:new --local …` 开一张、带 `--issue` 挂上。跟进单在引擎手里的不给认，要本机接手得创始人说。
3. **修完随 PR 撤**：修复的 PR 正文「修提醒」栏写提醒的键，合进主线、法国发布后条件好了提醒自己撤；不手动撤、不拿静默顶。真要暂时压住，`alert silence <键> --until +3d --note "<谁拍的、为什么>"`（最长 7 天，只挡再推和开跟进单）。

## 干活守则

照项目 `AGENTS.md` 的原文做，这里只指在哪一条，不抄：

| 事 | 在 `AGENTS.md` 哪里 |
|---|---|
| 拍了板当场记（记之前 `seat.mjs check`，再 fetch 读主线上已有的，冲突就问、不覆盖）；改规矩先扫冲突的旧说法 | 通用段「什么时候停下来问我」 |
| 重大方案先让别家挑错（用 `discuss`） | 同上 |
| 发现问题当场修；「以后再做」开成单 | 同上 |
| 做完一件发三行进度；无人值守时开一个每半小时自检的心跳定时任务 | 通用段「怎么跟我说话」 |
| 工人各用各的工作树 | 通用段「在任何仓里干活」 |
| 开单用 `pnpm issue:new`；本机做的带 `--local` | 本仓段（fleet-dao 的；别的项目看它自己的本仓段） |
| PR 开出来就挂自动合并（Sonnet 工人的开草稿、验收过了再挂）；改标准的等创始人同意再挂 | 同上 |
| 谁开的 PR 谁负责到合并 | 同上 |

## 报进度

每做完一步就报到驾驶舱（法国库里的帅位栏，首页订阅，大约几秒内能看见）。要先是现任帅位（`seat.mjs show` 看得到自己；还不是就先 `seat.mjs take`）。没配登法国的钥匙、连不上：命令退出码 2，写明原因，不会在本机造一份进度假装报成了。

```bash
node $S/p.mjs <项目> head "一句话现状"
node $S/p.mjs <项目> add s03 3 "改开单脚本"         # 加一步，排着
node $S/p.mjs <项目> step s03 doing "在写测试"      # done / doing / waiting / needs / blocked
node $S/p.mjs <项目> log "PR #190 合了"
node $S/p.mjs <项目> link s03 "PR #190" <网址>
node $S/p.mjs <项目> needs add n1 --issue <号> --repo <owner/仓> --recommend 甲 "要你定的问题" 甲 乙
node $S/p.mjs <项目> pending                        # 创始人已经点了、还没写进单子的
node $S/p.mjs <项目> record                         # 写进那张单的评论，成功才记账
```

- 要创始人拍的用 `needs add`（至少两个选项，推荐的那个必须在里面）。他在驾驶舱点了之后，这条从栏里消失；你下次 `pending` 读到，`record` 在那张 issue 留一句「创始人拍了：<问题> → <选项>」。评论没写成功就不要当已经记账。
- 三行进度照发。`show` 从法国读回。读不到就明说原因，不当成没有。
- 本机 `http://127.0.0.1:1127` 只留一句「进度搬到驾驶舱了」，不再当进度入口。

## 交接

创始人说「交接帅位」、自己上下文快满、或者现查发现换了人（退役）时：

1. 写交接说明，四段：在做什么；等谁拍什么；开着的 PR 和工人（带单号、认领号）；下一步。
2. `node $S/seat.mjs handoff < <文件>`：存进法国库，接班的 `seat.mjs show` 读得到；退役后刚被换下的上一任也能补写（接在现任那份后面）。现任也可以 `node $S/p.mjs <项目> handoff <文件>`：同一份说明存进座位，并在帅位栏记一条；不是现任这条会退出，补写仍用 `seat.mjs`。
3. 手上工人的认领不用动：换帅位不作废工人的认领，工人照旧报进度、把开着的 PR 做到合并；不打算接着做的 `claim.mjs release`。
4. 接班的会话照「接班」第 1 步读到这份说明，先读完再动手。

## 演练

演练用座位 `drill:<名字>`（`--scope drill:299` 这类），不碰真帅位 `main`；演练用的单由演练开始时自己开、结束时关掉（临时的不开常驻单）。
