# `chain-first`：现状不对，先查断链

## 什么时候读

**任一「现状和预期对不上」的时刻**，不等用户提醒：

- 检查红了、读回的结果不是刚改的样子、数字对不上；
- 「应该有的东西没有」：该更新的文件很旧、该跑的东西没跑、该报警的没报；
- 用户说「不对」「怎么又这样」「这机制像个玩具」。

**不归本页管**：没有什么东西坏了，只是要做新功能、提新方案——读 `best-practice-first`。两页的先后是**本页在前**：查到要新造或换机制，才转过去（见第 5 步的表）。

**一句话**：症状是链上某一环断了的**结果**。只修症状，断的那一环还在，下次换个面目再来。

## 怎么做（六步，顺序不可换）

### 1. 止血（最多一步）

生产在坏就先恢复或回滚。**止血不算修完**，止完接着往下走，不许在这里收工。

### 2. 画链：这个事实从哪来、到哪去

写出四个角色，每个都答「现在是谁、还活着吗、上次动是什么时候」：

| 角色 | 要答的 |
|---|---|
| **写方** | 谁产生这份数据或状态？它挂在什么上面跑（定时任务、巡检、请求路径）？那个东西还在吗？这个值是**算出来的**还是**写死的**？ |
| **存放处** | 落在哪？最后一次被写是什么时候？ |
| **读方** | 谁拿它做决定？读的时候查不查新旧？读不到或过期时当成什么？ |
| **报警方** | 写方死了、数据旧了，谁会知道？ |

**去机器上读，不凭记忆**：文件修改时间、定时任务上次跑的时间、进程在不在、数据里的更新时间。「应该是 X 在写」不算答案。

### 3. 找断点，三问

1. 哪一环断了？
2. 断了多久？
3. **为什么这么久没人知道？**（报警方不存在 / 挂在没人跑的地方 / 红被当成常态 / 读方把「没查成」当成「没事」）

第 3 问的答案才是机制病；前两问只是定位。

### 4. 判这一层还要不要

- 删掉这一层，谁受影响？有没有第二份记录在说同一件事？（同一件事两本账，早晚对不上）
- **状态能不能不存、改成读的时候现算？** 不存就不会过期。
- 写方是不是挂错了地方？状态应该由**产生事实的那条路**自己写（发请求的路记成败），不是由旁边一个巡检代写——巡检一换，写方就静默消失。

### 5. 问题和机制，同一轮一起修

修法按这个优先级选，能用上面的就不用下面的：

1. **删层**：这份状态、这道检查不要了；
2. **读时现算**：不存状态，从已有的真实记录里现算；
3. **读方查新旧**：过期当「没查成」，不拦也不信，写明原因；
4. **加报警**：最后手段。报警自己也是一环，也会断。

要不要转去 `best-practice-first`，看修法，不看问题大小：

| 修法 | 要不要转 |
|---|---|
| 第 1、3 级：删层、给现有读方加新旧判断 | **不转**，没有提新设计，当场修 |
| 第 2 级：换掉原机制的做法（存状态 → 读时现算） | **转**，这是换设计，先查业界怎么做 |
| 第 4 级，或任何新造的东西：新报警、新状态文件、新常驻进程、新规矩 | **转** |

转过去**不重查现状**：把第 2–4 步的链图和断点带过去，从那边第 1 步接着走，走完回到本页第 6 步。

缺的机制可以先用临时垫片（一行检查、一个手动步骤）当场生效，正式版走 PR；垫片在 PR 正文写明「合并时退役」，免得它变成没人管的影子机制。

### 6. 扫同类，写清楚

- 同一个写方还喂着谁？同形的读方还有谁？列出来，属于本次的一起修，不属于的写明为什么不动。
- PR 正文写清四样：**链图（四个角色）、断点、为什么没人发现、问题和机制各怎么修**，几行就够；转过 `best-practice-first` 的，再附上那边要的来源链接和对照。真没有链可查的（错别字、依赖升级），写一行「断链：不适用——<理由>」。
- 值得留的教训，能写成测试就写成测试。

## 硬规矩

- **只改症状那一行，视为未完成。** 可以分两个 PR，但机制那个必须同一轮开出来，不许留成「以后再说」。
- **不许给读方加一个 `if` 绕过去就收工**——那是把断链藏起来，不是修。
- 准备给同一处打第二层补丁时停手，读 `grill-ai`。
- 「没查成」和「查了没事」必须分得开；分不开本身就是断点。

## 和相关 skill 的分工

| skill | 管什么 |
| --- | --- |
| **`chain-first`（本页）** | **机制断了**：一份状态、一道检查、一个定时任务该在而没在、过期了没人知道，查写方、存放处、读方、报警方 |
| `systematic-debugging` | **代码错了**：一个函数、一条路径给出错结果，按复现、缩小范围、找根因走 |
| `best-practice-first` | 查到要新造或换机制时转过去，从业务重推 |
| `grill-ai` | 准备给同一处打第二层补丁时先停下自查 |

分不清是机制还是代码：先画链（第 2 步）。四个角色都活着、数据也新，错在读方自己的逻辑里，就是代码错了。
