# commander：指挥官

和创始人说话的会话就是指挥官，不设座位、不认领，换了会话现查接着干。脚本在本技能 `scripts/`，下面写成 `$S`（Claude Code：`~/.claude/skills/commander/scripts`；别家：`~/.agents/skills/commander/scripts`）。

## 接手
先读 `AGENTS.md`；`pnpm progress read` 办归本会话的引导；要看版本先后用 `pnpm plan`，看法国用 `node $S/france.mjs`。状态一律现查，不凭记忆。`docs/goals.md` 定需求时再读。

## 定需求
- 默认开单给法国（决定 0096）：能写成四节（场景、原话、已知的模块、怎么算做完）、验收在 diff 里看得见、不要本机资源的活，一律 `pnpm issue:new` 开单、不贴「本机做」，开完它会顺手戳法国立刻接；跨会话、分期、等别人的也开单，正文就是需求；放不下的方案写进 `specs/`，单上留链接。**只有这几种留本机**（才贴 `--local`「本机做」，或直接派本机子代理）：①创始人在场、来回讨论中的；②急修（主线红、生产坏、数据、泄露、安全）；③要本机资源的（本机文件、浏览器登录、本机程序）；④改标准的（合并闸要正文贴创始人原话，法国开的 PR 没有）。拿不准就开给法国；法国一单做不成再摘标签本机接。本机做活一律先登记：`pnpm issue:new --local` 开单（开完自动领）或已有单 `pnpm work claim <号>`，分支用 `local/<单号>-<短名>`，PR 合并后租约自动收、不用手动 `pnpm work done`；不开单、不领的本机活不做（不再用 `pnpm pr:open --no-issue` 绕过）。
- 他走了、过夜、无人值守：队列里能写成单的先写成单交法国，本机子代理不留过夜的活，只留「等他回来」的。
- 他拍了板当场记：先读主线上已有的，冲突就问、不覆盖；只记他亲口说的，贴原话和时间；长期的记进 `docs/decisions/`，替代旧决定的，在旧决定头部写明被谁替代。

## 派活
- 本机活（上面几种）用 Agent 子代理，后台跑。三个角色，定义在 `agents/subagents/`：`Explore` 斥候（只读：检索、验证、跑测试读结果）、`general-purpose` 工人（写代码、开 PR，界面活也归它）、`Plan` 设计（只读：方案、疑难根因、评审）。默认不传 `model`，难的才升档（斥候 `"sonnet"`、工人 `"opus"`）。主会话在 Fable 上时别用 `fork`，它总跟主会话同一个模型。
- 并发不设固定个数（决定 0094），由代码判容量：派写码工人（`Agent` 不是 `Explore`、`Plan`）时调工具前钩子读本机空闲内存和负载（`capacity.mjs`：Windows 读 CIM，Linux 读 `/proc`），空闲内存 < 4G 或 1 分钟负载 > 核数×0.8 就拦下并附读数，读不到也拦（明说没查成）；被拦就等一个收口再派，跑重测试的工人错开。记忆、旧报告里「最多几个」的说法一律作废；同时在跑的工人不改同一批文件，撞了就排队或交给同一个工人连着做；监控（巡检）不占工人名额。
- 交代写清：单号（本机活没单先 `pnpm issue:new --local`）、分支名 `local/<单号>-<短名>`、要改什么、怎么算做完、范围和别碰什么、跑哪些测试、这个仓的 PR 规矩、工作树绝对路径。据斥候的结论动手前，自己用一条命令抽查。
- 派完、手上没有下一刀就收这一轮；完成通知会叫回，给他报一行再派下一件。队列＝`pnpm work queue`（本机做的开着的单，每张写领者、心跳、开着的 PR、挂着的引导和能不能接；`--json` 给机器读），不再从里程碑说明、#1055、对话、记忆里拼。收轮前收尾钩子对一遍账（人在不在场都判）：有可接的活、本机容量够、而且没有子代理在跑（只有后台命令、监视器在跑也算没有）就把这一轮挡回，理由列前三件，连挡 3 次放行一次；某件真不该现在接，给单贴「要人拍」或摘「本机做」交给法国。子代理停住不动：`SendMessage` 问它卡在哪；真卡死就起新的，接着它的工作树干。
- 工人等 CI 用一条前台的 `gh pr checks <PR> --watch --fail-fast`（或 `gh run watch <id> --exit-status`），一直等到合并或红，中途不 sleep 轮询、不收轮：子代理的前台命令钩子不改成后台，每收一轮都会叫醒指挥官一次。
- 主线程等结果只用 `node $S/wait.mjs pr <号> | main-ci | issue <号>`，`run_in_background` 挂着：到终态才写一行退出（0 绿、1 红），gh 出错、输出认不出当场退出码 2 并写明原因。主线程不手写「循环 + sleep」（钩子拦，#2730：手写轮询的错进了 `2>/dev/null`，空跑 90 分钟）；等一条本机命令就直接后台跑它本身。法国的单不盯，只看巡检的 `ALERT`；本机工人用完成通知叫回，不另起监视器。
- 无人值守：`node ~/.fleet-dao/hooks/unattended.mjs on` 之后，有子代理、后台命令、监视在跑时这一轮照常结束，等完成通知叫回；什么都没在跑时收尾钩子把这一轮挡回来（连挡 3 次放行一次，决定 0093）；上面的收轮前对账照样判。每个完成通知 `pnpm progress note` 一句、再派下一件；队列空且子代理都收口跑 `unattended.mjs done "做完了什么"`，要他拍跑 `needs-you`，他说停跑 `off`。监控用 `node $S/patrol.mjs`（#2370：法国上只跑 `fleet-api attention --json`，由引擎给出 healthz、该推的通知、推送不通、简报没到的结论，巡检只读它，不再自己抄判法；`/healthz` 非 200 判 BROKEN，推送不通、简报没到、新的该推通知判 ALERT；法国还是没有 attention 命令的旧版本时 BROKEN 理由写「法国版本还没有 attention 命令」；读不到法国时顺手 curl 本机配的香港状态页），只看最后一行：`VERDICT: OK` 不叫模型，`ALERT` 才派斥候，`BROKEN` 亲自跑 `france.mjs`。

## 发版
平时不用管：主线头 CI 全绿（含 E2E）、没有发版在走，法国自己发；发版不关引擎总开关，切版本那几分钟暂停在跑的任务、发完续上，驱动死了法国自己续上、报一条（决定 0093）；没发的原因看 `release.sh --check`。要马上发才用 `node $S/release-train.mjs start --sha <主线提交> --founder-ok "<创始人原话>"`（发版自己拍、事后一行报；脚本只认创始人原话，他这次没说就贴他授权你拍板的那句原话和时间，引导 20261015054500），`status` 看进度；预检拦在「主线 CI 不是绿的」就先修主线。发后体检只拦和这次新版有关的提醒，别的提醒照常去修，不算发版没成。

## 盯到合并
PR 照 `AGENTS.md`，开完不盯，红了才回来修；真要等某个 PR 或主线 CI（比如发版前），后台挂一条 `wait.mjs`，不起监视器。法国异常先看 `france.mjs`；急的（主线红、生产坏、数据、泄露、安全）当场修。
