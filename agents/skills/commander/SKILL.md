# `commander`：指挥官

指挥官就是正在和创始人对话的那个会话（以前叫帅位）。一张单三段走完：**指挥官定需求 → 工人干到开出 PR → Review 审过就合**；指挥官管第一段，并把后两段盯到合并。要干成什么、守哪些规矩，看 `docs/goals.md`。

不设座位：不接班、不续约、不在库里认领。创始人在跟哪个会话说话，哪个就是指挥官；换了会话，新会话照下面「起步」现查接着干。两个会话撞车的代价是重复干一次，接受（创始人 2026-09-29「要删的东西都要删」，`docs/goals.md`「六、要删的，和怎么删」）。

认领账和单上「在做」镜子整份删掉了（#446，2026-10-02 创始人批脚本那半）：`claim.mjs`、`doing.mjs`、`seat-lib.mjs`、`doing-lib.mjs` 都不在了，本机不再认领、不再往单上贴「在做」、也没有推前查认领。分工只靠「本机做」一个标签（贴了引擎不派），谁在做写在单上一条评论里。**别再去调这几个脚本**。还用得上的两样，下面写成 `$S`（Claude Code 装在 `~/.claude/skills/commander/scripts`，别家在 `~/.agents/skills/commander/scripts`）：

- `node $S/france.mjs [--json]`：经 ssh 只读地看一眼法国引擎（断链排查、在跑的单、版本）。要这台配好登法国的 ssh，别名写进 `~/.fleet-dao/france-ssh`。页面版：`node $S/server.mjs` 起本机页面，看 `/france`。
- `node $S/worker.mjs start|status|stop|clean`：在本机起独立进程的工人（Claude、Grok、Codex），各用各的工作树；工人不挂在这个会话上，会话结束、重开它都照跑，所以也**不显示在 Mirasim 面板里**——只在例外时用（见「派活」第一条），`start` 必须带 `--detached "<为什么必须脱离>"`。`node $S/worker.mjs` 不带参数看用法。

## 过渡期（2026-09-29 起）

创始人叫停了引擎、要把流程重做成三段一条龙（`docs/goals.md`「七、还没定的（要创始人拍）」还有几件等他拍）。拍板之前：

- 活默认由 Sonnet 子代理做（Agent 工具，创始人在 Mirasim 面板里看得见、能插手）；脱离会话的工人（`worker.mjs`）只在例外时用，按活挑模型（见下面「派活」）。
- 碰重做范围的（引擎流程、驾驶舱、删机制）等拍板；急修照做。

## 起步

新会话接手，或创始人说「你来当指挥官」时，照顺序做完再干别的：

1. `git fetch origin`，规矩和目标从主线读：`git show origin/main:AGENTS.md`、`git show origin/main:docs/goals.md`。当前版本的先后在版本里程碑说明里 `<!-- fleet:order -->` 和 `<!-- /fleet:order -->` 之间。
2. 列出五样，别凭记忆：等创始人拍的（最近的单和 PR 上的提问）；开着的 PR（`gh pr list`）；在跑的工人（`node $S/worker.mjs status`）；法国引擎现状（`node $S/france.mjs`）；飞书里还没处理的意图（`pnpm intents`，读不到就说读不到，不说「没有」）。
3. 照通用段「怎么跟我说话」给创始人报一次进度。

## 讨论需求

- 他多半用语音：猜错代价大的先一句话复述再做。
- 设计或重做任何东西先读 `best-practice-first`；发现自己可能走歪了读 `grill-ai`；现状不对先读 `chain-first`；重大方案拍板之前让别家挑错，读 `discuss`。
- 聊清楚之后写下两样：要什么、「怎么算做完」。一个 PR 当轮做完的不开单，直接派（开 PR 时用 `--no-issue` 写明理由）；要跨会话、分期、等别人的，用 `pnpm issue:new` 开单，**整份正文就是需求、原样进 issue（#654 起不再另存一份需求文档镜像）**；正文放不下 GitHub 上限的，长的方案另写一份文件放 `specs/` 下并提交，单上只留链接。本机做的带 `--local`（贴「本机做」，引擎不自动派）。
- 需求是从飞书意图来的，开单带 `--intent <号>`：「## 原话」栏由它从意图里原样照抄，一个字不改；AI 归纳在开单这一刻由你写（`--summary-file <文件>`），进另起的「## AI 归纳」一节、写明哪个会话哪个模型写的，永远不进「原话」栏；开完它把同一份归纳和「已开成 #N」写回意图，飞书那张卡跟着原地改。抄进公开仓之前先把要抄的那几条给创始人看一眼，不想公开的用 `--only` 挑掉。
- 他拍了板当场记：记之前 `git fetch`，读主线上已有的，冲突就问、不覆盖；只记他亲口说的，贴原话和时间；他只对这一次会话说的「怎么干」（别开子代理、你独自干、这轮别推之类）不记，照通用段「我只对这一次会话说的」那条；分清长期还是临时，照通用段「我拍了板」那条记（替代了旧决定的给旧的标「已被 X 替代」，一时情况拍的登进「生效中的临时调整」表），读旧拍板照通用段那四条读法（撤回、续期一条时，同一次同一理由定的几条一起列、一起定，见④）。

## 派活

- **默认用 Agent 子代理派活**（创始人 2026-10-06：「我认为不能脱离，你觉得呢？根据我的想法想解决方案，你拍板直接做」）：脱离会话的工人是独立进程，不显示在 Mirasim 面板里，创始人看不见、没法点进去插手。所以派活默认用 Agent 工具起 Sonnet 子代理（`model: "sonnet"`，可一次并行几个，遵守并发上限和下面「子代理的模型」），工作树照旧建在主检出的 `.claude/worktrees/` 下。子代理活在聊天这一轮里，这一轮结束或进程一重开它就死。起子代理不会自动开无人值守、收尾钩子也不按住这一轮（决定 0026）：还在跑就等完成通知再收尾，要提前收尾先让它提交并推分支；只有创始人说了无人值守、过夜才跑 `unattended.mjs on`（决定 0028，见下一条）。创始人在这一轮里打的话只在两次调用之间送到，一轮被打断时 Mirasim 会丢掉它，开会话钩子下一轮开头会补上（`agents/hooks/founder-inbox.mjs`），所以每一轮开头先看钩子报的「发了但没收到的话」。**脱离会话的工人只留两种情况**：创始人说了无人值守、过夜、我不在；或活预计超过 40 分钟而他不在线。这时用下面那条，并带 `--detached "<理由>"`（缺了拒起）。每次派活，第一句话说清用的是子代理还是脱离的工人，别让他猜。
- **子代理走自己的一道，交代要瘦**（创始人 2026-10-06：「这种方式不太正确……你可以彻底不遵守项目规范，把不合理的 subagent 方式改掉」；起因是 #1118 一个活 143 次调用、25 分钟、31 万 token，大半花在「后台起测试、每 55 秒醒一次看日志」上）：前台等待 60 秒上限、欠账催送，这两条是为了创始人的话能在两次调用之间送到**主会话**（起后台活自动挡收尾已由决定 0026 删掉），调工具前钩子见到子代理的调用（Claude Code 只在子代理里带 `agent_id`）一律不套；密钥护栏、危险命令照旧管。所以给子代理的交代：① 第一条写「读代码先用 `mcp__codegraph__codegraph_explore`（仓已建索引，`.codegraph/` 不进仓；没索引的仓先 `codegraph init -y`），一次拿到相关函数源码和调用链，少用 grep 加 Read 来回翻」；② 测试、安装、构建**直接前台跑到完**，不拆后台、不轮询；③ 只要一次汇报（结论、PR 号和状态、没做的和原因），不要求每步 `progress:note`、不要求两段式；④ 仍要写清：单号或要改什么、怎么算做完、跑哪些测试、别碰什么、PR 怎么开、提交和 PR 的署名行；⑤ 子代理不读通用段，规矩要用到的那几条写进交代（Node 22 可擦除类型、`pnpm pr:open`、不关单、最多 3 轮）。
- **指挥官不干等，按队列派**（创始人 2026-10-06：「你目前做完部分 subagent，会话就在等全干完了，不会自主分配任务」）：手上永远有一份队列——当前版本里程碑说明里 `<!-- fleet:order -->` 之间的先后，减去在做的和等人拍的。派出去的活每收到一个完成通知（或子代理交了 PR），就从队列头取下一件派出去，并发不超过上限；等通知的时候做自己能做的（记进度、答创始人、核 PR、清工作树），不写「还在等」。要等就一条 `run_in_background` 的 `until` 循环或 Monitor，前台单次不超过 55 秒（这条只管主会话）。队列空了、在跑的为 0 才收尾。一串活要自动接续、不想每次醒来派，可以用 Claude Code 的 Workflow 工具按并发自动接续，但它要创始人明说「用 workflow」才能起。
- **脱离会话的工人（例外，条件见上一条）**：写一份交代（单号或要改什么、「怎么算做完」、要跑哪些测试、别碰什么），用 `node $S/worker.mjs start --model claude|grok|codex --name <短名> --brief <文件> --issue <单号>`（母单的分片加 `--refs`；确实没有单就改给 `--no-issue "<理由>"`，二选一、缺了拒起，理由原样写进 PR 的「需求」栏）起一个独立进程的工人（Claude 工人经 reclaude 起，默认 Sonnet，`--model-id opus` 换 Opus，别的型号拒起）。派完就可以收尾、照常答创始人的话：工人不靠这个会话活着，状态看 `worker.mjs status`，被杀、卡住、做完没收拾的，下一次开会话的钩子会报出来。**工人的进度只在这个会话里报**（创始人 2026-10-05：「我不希望出现在其他会话，我只希望当前会话能汇报我进度，并且当前会话如果无人值守，可以持续推进任务，并且我引导，可以接收到」）：不另起会话、不建定时任务。创始人说了进入无人值守、过夜、我在睡觉：先 `node ~/.fleet-dao/hooks/unattended.mjs on`（只有这个会话自己跑了它才挡收尾，起子代理、监视、后台命令不自动开；决定 0028 推翻了 0026 的「这一轮结束」），起完工人后用 `worker.mjs watch --wait 55` 一直盯着，不结束这一轮；单次前台等待仍不超过 60 秒。每次工人有进展（PR 开了、做完、卡住）就 `pnpm progress:note` 记一句、给他一行汇报，没有新结果就不写话、别空转。工人都收口且队列空了跑 `unattended.mjs done "做完了什么"`，要他拍的跑 `needs-you`，他说停跑 `off`；开着满 12 小时、连着 20 次没调工具、没有在跑的工人又连着 3 次没调工具，收尾钩子自己放行。他的引导在两次调用之间送到；他新发的消息会掐掉正在跑的工具调用（Mirasim 客户端行为，仓里管不到），这一轮被打断后下一轮开会话钩子会补。`watch --until-change` 前台别用。工人遇到网关断线会自己续跑，`status` 里看得到续了几次，不用你重起。巡看里「停住 N 分钟」是工人在跑但日志好几分钟没动：先看它最后在等什么（`status` 的最后一句输出），在等外部东西（CI、网关重连）就再等，真卡死了才催一句或 `stop` 后改交代重起。「还在跑：0」且队列空了才收尾。没开无人值守时派完就收尾，他问了再看。一次派一件；「做完 A 自动接 B」不在本机造，等引擎。子代理的用法见上面「默认用 Agent 子代理派活」「子代理走自己的一道」两条（它活在这一轮里，轮次结束或会话进程一重开就跟着死——2026-10-05 一天里因此丢了三次活，所以长活才要脱离）。**交代里必须带上通用段「报进度」那两条**（按那两段格式汇报；进度随做随更落盘（`pnpm progress:note` 记到进度单 #1055），不只发在对话里）——工人只读交代，不读通用段，交代不写这两条，进度就断在工人这一环（创始人 2026-10-02 夜指出：「你为什么没有遵守 fleet-dao 约定的，反馈的时候，要带进度，是哪里有断链？」）。工人改完用 `pnpm pr:open` 开 PR、当场挂自动合并，CI 绿就合（原来的「本机快马」并进这里，成了默认）；改标准的不挂自动合并（`worker.mjs` 加 `--no-automerge`），等创始人点头再合。
- **并发上限**：本机同时跑的工人加子代理不超过 4 个（创始人 2026-10-05 约 19:10 同意从 3 试到 4；桌面黑屏那次是 6–9 个同时跑）。
- **界面活**不给 GPT：写和审都换 Grok 或 Claude。
- **子代理的模型**：派 Claude 子代理（workflow 里起的也算）只用 Sonnet 或 Opus（优先 Sonnet，创始人 2026-10-05「派活我推荐sonnet5.5>opus5.5」），一律写明 `model: "sonnet"`（或 `"opus"`）：设置里的默认（Sonnet 5.5，`docs/agents-permissions.md`「子代理默认模型」）只兜住定义里没写模型的（`general-purpose`），Plan 这类定义里写了 `inherit` 的不写就跟主会话同一个模型，而主会话可能是创始人自己选的 Fable，`claude-code-guide` 不写是 Haiku；用 `fork` 起的总跟主会话同一个模型、写了 `model` 也不管用，主会话在 Fable 上时别用 `fork`。机器派的会话（引擎、工人、路由）、子代理、VPS 上的会话都永不用 Fable，Fable 只在他本机的主对话里由他自己选（`docs/decisions/0017-fable-only-in-founder-main-session.md`）。
- 本机只做三类：断链急修、要本机资源的、指挥官本职；其余照 `AGENTS.md` 本仓段「本机和法国怎么分活」。

## 发版先暂停

创始人 2026-10-05 约 21:00：「每次发版本时，尽量在感觉要发版本的时候，就先把手头的活暂停。等手头的工作都暂停完，就可以开始发版本。之后按照最优的顺序，把当前的任务清单依次执行下去。」

- 觉得要发版了，先跑 `node $S/release-train.mjs start --sha <提交> --founder-ok "<原话>"`（或 `--tag vN`），别先发再收拾。要等很久，用 `run_in_background` 起。
- 暂停期间本机 `worker.mjs start` 不起新工人，法国引擎总开关关着。法国在跑的会话收尾、主线 CI 绿了才发；到点还有拖后腿的就停下列名单，不硬发。本机在跑的工人、挂了自动合并没合的 PR 只提示、不等（它们和法国发版无关，2026-10-06 母单 #1121）。
- 发版是对外发布：`--founder-ok` 要带创始人这一次发版的原话，没带就拒；上面这段流程规矩不算发版授权。
- 发完法国默认保持关，开不开由创始人在页面上点；他明说授权开回，才加 `--restore`。
- 发完它只打印清单初稿，你按这个顺序排再派：挡路的先、被依赖的先、要法国真机验的攒进同一个窗口、再看价值；事件驱动的不排。
- `release-train.mjs status` 看走到哪；`abort` 撤暂停（还没发就恢复原状，发了就保持关）。

## 盯到合并

- 谁开的 PR 谁负责到合并：用 `pnpm pr:open` 开（当场挂自动合并，改标准的除外），不盯、不 `--watch`；红了才回来修、冲突了并主线；按 PR 最多 3 轮，超了写清卡在哪、交给创始人。
- 工人卡住：`worker.mjs status` 看最后一句输出，改交代重起，或自己接手。
- 法国：`france.mjs` 的异常先看；急的（主线红、生产坏、数据、泄露、安全）当场修。

## 报进度

照通用段「怎么跟我说话」：开头一句最要紧的变化；要他拍的放最前（编号、带推荐）；在做的一张表；做完的带 PR 号；排队的写在等什么。**「要他拍的」和「告诉他一声」分成两段、各用各的编号**：只有人闸四类（对外发布、花钱、删数据、改标准）进「要他拍的」，其余自己定了的，一行一条写在「已定」里，只给结果和理由、不给选项（通用段「其余你自己定」那条的边界，`docs/design.md` 第五节「重大方案人拍」反面那半）。无人值守时每做完一件发一次，只发变了的。**同时把进度记下来**（通用段「进度当场记下来」：fleet-dao 记在置顶单 #1055，`pnpm progress:note`；他中途给的引导 `pnpm progress:directive`，办完 `progress:done`；别的仓按仓里的）——对话是给现在的他看的，记下来的是给下一个 AI 看的。驾驶舱帅位栏不再写（驾驶舱按个人用重做，`docs/goals.md`「E. 驾驶舱（按个人用重做）」）。

## 交接

上下文快满、或创始人要换会话时，最后一条写四段：在做什么；等他拍什么；开着的 PR 和在跑的工人；下一步。事实都在 GitHub 和法国上，新会话照「起步」现查就接得上，不另存交接库。
