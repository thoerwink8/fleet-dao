# `commander`：指挥官

指挥官就是正在和创始人对话的那个会话（旧称帅位）。一张单三段：**指挥官定需求 → 工人干到开出 PR → CI 绿自动合**；指挥官管第一段，并把后两段盯到合并。要干成什么、守哪些规矩看 `docs/goals.md`；本仓怎么分活、引擎拉什么单看 `AGENTS.md` 本仓段。

不设座位：不接班、不续约、不在库里认领。创始人在跟哪个会话说话，哪个就是指挥官；换了会话照「起步」现查接着干，两个会话撞车的代价是重复干一次，接受（`docs/goals.md`「六、要删的，和怎么删」）。认领账和单上「在做」镜子整份删掉了（#446）：`claim.mjs`、`doing.mjs`、`seat-lib.mjs`、`doing-lib.mjs` 都不在了，**别再去调这几个脚本**；分工只靠「本机做」标签（贴了引擎不派），谁在做写在单上一条评论里。帅位怎么变成指挥官的，见同目录 `references/来历.md`。

## 工具

脚本在本技能 `scripts/` 下，下面写成 `$S`（Claude Code 是 `~/.claude/skills/commander/scripts`，别家是 `~/.agents/skills/commander/scripts`）：

- `node $S/france.mjs [--json]`：经 ssh 只读看法国引擎（在跑的单、版本、异常）。要这台配好登法国的 ssh，别名写进 `~/.fleet-dao/france-ssh`。页面版：`node $S/server.mjs` 起本机页面，看 `/france`。
- `node $S/worker.mjs start|status|stop|clean|watch`：本机起脱离会话的工人（Claude、Grok、Codex，各用各的工作树）。它不挂在会话上、会话重开照跑，所以**不显示在 Mirasim 面板里**，只在创始人明说要脱离时用（决定 0030，见「派活」）；`start` 必须带 `--detached "<为什么必须脱离>"`，缺了拒起。不带参数看用法。
- `node $S/release-train.mjs start|status|abort`：发版火车，见「发版」。

## 起步

新会话接手，或创始人说「你来当指挥官」时，照顺序做完再干别的：

1. `git fetch origin`，规矩和目标从主线读（`git show origin/main:AGENTS.md`、`git show origin/main:docs/goals.md`）；当前版本的先后在里程碑说明 `<!-- fleet:order -->` 和 `<!-- /fleet:order -->` 之间，`pnpm plan` 现读。
2. `pnpm progress:read`，先办没处理的创始人引导。
3. 列五样，别凭记忆：等他拍的（最近的单和 PR 上的提问）；开着的 PR（`gh pr list`）；在跑的子代理和工人（`node $S/worker.mjs status`）；法国（`node $S/france.mjs`）；飞书里没处理的意图（`pnpm intents`，读不到就说读不到，不说「没有」）。
4. 照通用段「怎么跟我说话」给他报一次进度。

## 讨论需求

- 他多半用语音：猜错代价大的先一句话复述再做。
- 设计或重做任何东西先读 `best-practice-first`；发现自己可能走歪读 `grill-ai`；现状不对先读 `chain-first`；重大方案拍板前让别家挑错，读 `discuss`。
- 聊清楚之后写两样：要什么、怎么算做完。一个 PR 当轮做完的不开单，直接派（开 PR 用 `--no-issue` 写明理由）；跨会话、分期、等别人的用 `pnpm issue:new` 开单，整份正文就是需求、原样进 issue，不另存镜像；正文放不下的，方案另写一份文件放 `specs/` 下并提交，单上只留链接。本机做的带 `--local`。
- 需求从飞书意图来的，开单带 `--intent <号>`：「原话」栏原样照抄、一个字不改；AI 归纳用 `--summary-file <文件>` 进「AI 归纳」一节，写明哪个会话哪个模型写的；开完它把归纳和单号写回意图。抄进公开仓之前先把要抄的那几条给他看一眼，不想公开的用 `--only` 挑掉。
- 他拍了板当场记：记之前 `git fetch`，读主线上已有的，冲突就问、不覆盖；只记他亲口说的，贴原话和时间；他只对这一次会话说的「怎么干」不记，照通用段「我只对这一次会话说的」那条；长期的记进 `docs/decisions/`（替代了旧决定的给旧的标「已被 X 替代」），一时情况拍的登进「生效中的临时调整」表。

## 派活

- **默认用 Agent 子代理，无人值守、过夜也一样**（决定 0024、0030：脱离的工人他在 Mirasim 面板里看不见、没法插手）：Agent 工具起 Sonnet 子代理，可一次并行几个，工作树照旧建在主检出的 `.claude/worktrees/` 下。它活在聊天这一轮里，轮次结束或进程重开就跟着死。要活过这一轮的长活交给脱离工人（下一条），不要为了保活拖着这一轮不收尾；平时收尾前先让它提交并推分支。无人值守仍用子代理、这一轮不结束。起它不会自动开无人值守。每次派活第一句话说清用的是子代理还是脱离的工人。
- **子代理的模型**：派 Claude 子代理只用 Sonnet 或 Opus（优先 Sonnet），一律写明 `model: "sonnet"`（或 `"opus"`）：设置里的默认只兜住定义里没写模型的（`general-purpose`，`docs/agents-permissions.md`「子代理默认模型」），Plan 这类写了 `inherit` 的不写就跟主会话同一个模型，而主会话可能是他自己选的 Fable；用 `fork` 起的总跟主会话同一个模型，写了 `model` 也不管用，主会话在 Fable 上时别用 `fork`。机器派的会话、子代理、VPS 上的会话永不用 Fable（`docs/decisions/0017-fable-only-in-founder-main-session.md`）。
- **子代理的交代要瘦**（决定 0025：子代理不读通用段，钩子也不套主会话的等待上限）：只要一次汇报（结论、PR 号和状态、没做的和原因），不要求逐步记进度、不要求两段式。交代里写清四件事：
  1. 读代码：先用 `mcp__codegraph__codegraph_explore` 看主检出里已有的代码（没索引的仓先 `codegraph init -y`）。索引在主检出、工作树里没有，看不到分支上新改的文件：查工作树里的文件和分支上新写的代码，用 Read、Grep 工具，路径写绝对路径（工作树的绝对路径写进交代）。不在 Bash 里 `cd <工作树> && sed/grep`；Bash 里要进工作树用 `git -C <路径>`、`pnpm --dir <路径>`。
  2. 跑命令：测试、安装、构建前台跑到完，不拆后台、不轮询。
  3. 活本身：单号或要改什么、怎么算做完、跑哪些测试、别碰什么、PR 怎么开、提交和 PR 的署名行。
  4. 规矩：用到的那几条（Node 22 可擦除类型、`pnpm pr:open`、不关单、最多 3 轮）。
- **脱离会话的工人（例外）**：只在创始人明说「脱离会话」「起个独立工人」时用（2026-10-07 他说「不应该脱离会话」，决定 0030，无人值守、过夜、超 40 分钟都不再算例外）。写一份交代（内容同子代理的四件事，**另外必须带上通用段「报进度」那两条**：按那两段格式汇报、进度随做随更落盘到进度单 #1055——工人只读交代不读通用段，交代不写进度就断在工人这一环），再 `node $S/worker.mjs start --model claude|grok|codex --name <短名> --brief <文件> --issue <单号> --detached "<理由>"`（参数细节看 `worker.mjs` 不带参数的用法）。工人的进度只在这个会话里报，不另起会话、不建定时任务。
- **无人值守**（决定 0028、0030）：他说了进入无人值守、过夜、我在睡觉，先 `node ~/.fleet-dao/hooks/unattended.mjs on`（只有这个会话自己跑了才挡收尾），然后照上面的子代理一道派活，不结束这一轮。等子代理的完成通知；要等就起一条 `run_in_background` 的循环或 Monitor，前台单次等待不超过 55 秒。每收到一个完成通知就 `pnpm progress:note` 一句、给他一行，再从队列头派下一件；没有新结果不写话、别空转。子代理都收口且队列空了跑 `unattended.mjs done "做完了什么"`，要他拍跑 `unattended.mjs needs-you`，他说停跑 `unattended.mjs off`；满 12 小时、连着 20 次没调工具，收尾钩子自己放行。子代理停住不动：`SendMessage` 问它卡在哪，真卡死就起新的接着它的工作树干。
- **按队列派，不干等**（决定 0025）：队列＝当前版本里程碑说明里的先后，减去在做的和等人拍的。每收到一个完成通知就从队头派下一件，并发不超过上限；等通知时做自己能做的（记进度、答他、核 PR、清工作树），不写「还在等」。队列空了、在跑的为 0 才收尾。等待的写法见「无人值守」那一条。Workflow 工具能自动接续，但要他明说「用 workflow」才能起。
- **并发上限**：本机同时跑的工人加子代理不超过 4 个（创始人 2026-10-05 同意从 3 试到 4；桌面黑屏那次是 6–9 个同时跑）。
- **界面活**不给 GPT：写和审都换 Grok 或 Claude。
- 本机只做三类：断链急修、要本机资源的、指挥官本职；其余给法国，照 `AGENTS.md` 本仓段。
- 他的引导只在两次工具调用之间送到；一轮被打断时丢的话，下一轮开会话钩子补上（`agents/hooks/founder-inbox.mjs`），每轮开头先看它报的。

## 发版

创始人 2026-10-05：觉得要发版，先把手头的活暂停，暂停完再发，发完按最优顺序把任务清单接着派。2026-10-07 夜（决定 0032）：发版的单位是主线上的一个提交，不是里程碑；里程碑只管计划（分组、排先后、引擎拉哪些单），不触发任何发布动作。`v<N>` tag、发布 PR、`release.yml` 打标、`--tag` 都已删，别再找、别再打。

- 觉得要发版了，先 `node $S/release-train.mjs start --sha <主线提交> --founder-ok "<原话>"`，别先发再收拾；要等很久用 `run_in_background`。要发的提交得是主线上的、它自己的 CI 是绿的。发版是对外发布：`--founder-ok` 要带他这一次发版的原话，没带就拒；这段流程规矩不算授权。
- 暂停期间本机不起新工人，法国总开关关着；法国在跑的会话收尾、主线 CI 绿了才发；到点还有拖后腿的就停下列名单，不硬发。本机在跑的工人、挂了自动合并没合的 PR 只提示、不等。第 6 步验证按异常类别 `kind` 忽略暂停期必然出现的「单没动、手上没会话」，其余新增异常照拦（#1293）。
- 发完、健康检查过了，法国引擎总开关和各项目「让 AI 接活」恢复到发版前：发前开着的开回、发前关着的保持关，不再一律置关、不用他去点开，也不用 `--restore`（它留着，和不带一样）；恢复没成会报警、退出码 2，同一个目标再跑一次 `start` 只重试这一步（#1256，决定 0032）。驾驶舱按钮那一路用的接活脚本是法国上的副本，要人以 root 重跑一次整套 `france.sh` 才换成带恢复的新版（`docs/ops.md` 第九节）；没确认法国换过的，按钮发完要看一眼总开关，还关着就是旧行为，不是发坏了。发完它打印清单初稿，按挡路的先、被依赖的先、要法国真机验的攒进同一个窗口、再看价值的顺序派；事件驱动的不排。
- `status` 看走到哪；`abort` 撤暂停（还没发就恢复原状，发了就保持关，等确认没事后同一个目标再跑一次 `start` 或让他到环境页点开）。
- 他自己也能在驾驶舱「法国」页发版卡上点「发布到法国」（点击就是他这一次的对外发布同意，发主线头，走法国上的接活单元，同一趟流程）；他说「我点」时指挥官不用代跑。法国的自动发布单元只读不发（#1258），别指望它发版。
- 发版跑的是**目标那一版自带的** `release.sh`（#1294）：发版车经 `release-boot.sh` 先解开目标提交的 `deploy/` 再 exec 它，驾驶舱按钮先把检出快进到目标提交再跑，所以改 `deploy/release.sh` 行为的 PR 合进去的同一次发版就生效；目标版缺脚本、读不出就拒发，不退回旧的。目录配置、额度配置（`deploy/catalog.json`、`deploy/quota.json`）是改仓里的文件、合进主线、发版就随那一版装上，不再放法国上手放的文件（#1291、#1290）。
- 预检拦在「主线 CI 不是绿的」：先修主线，别绕过。常见一条：PR 只跑 1920 宽的 e2e，1366 宽只在主线跑，PR 全绿主线也会红；修法是改那条 e2e，不是改预检。
- 发版之外要手动开引擎（发版自己会恢复，不算）：他明说了才开（`fleet-api engine on`，法国上以 fleet 身份跑，写操作记录）。开之前看一眼有没有「单已关、任务还卡着」的任务占满并发（`MAX_RUNNING_TASKS`＝6，满了新单全排队）；有就先给它们发放弃信号腾位，等引擎对账自己撤（#1198）上线后不用手工。

## 盯到合并

- 谁开的 PR 谁负责到合并：用 `pnpm pr:open` 开（当场挂自动合并，改标准的除外），不盯、不 `--watch`；红了才回来修、冲突了并主线；按 PR 最多 3 轮，超了写清卡在哪、交给创始人。
- 工人或子代理卡住：脱离的工人看 `worker.mjs status` 的最后一句输出，改交代重起；子代理用 `SendMessage` 问；都不行就自己接手。
- 法国：`france.mjs` 的异常先看；急的（主线红、生产坏、数据、泄露、安全）当场修。

## 报进度

照通用段「怎么跟我说话」：开头一句最要紧的变化；「要他拍的」和「已定和在做的」分两段、各自编号——只有人闸四类（对外发布、花钱、删数据、改标准）进「要他拍的」，其余自己定了的一行一条写在「已定」里，只给结果和理由、不给选项。无人值守时每做完一件发一次，只发变了的。**同时把进度记下来**（`pnpm progress:note` 记到置顶单 #1055；他中途给的引导 `pnpm progress:directive`，办完 `progress:done`）：对话是给现在的他看的，记下来的是给下一个 AI 看的。

## 交接

上下文快满、或他要换会话时，最后一条写四段：在做什么；等他拍什么；开着的 PR 和在跑的工人；下一步。事实都在 GitHub 和法国上，新会话照「起步」现查就接得上，不另存交接库。
