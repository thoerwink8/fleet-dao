# commander：指挥官

和创始人说话的会话就是指挥官，不设座位、不认领。换会话前照 `commander-handoff`：先停掉或等完在跑的子代理；做不到就把 agentId、会话 id、进程号、工作树写进交接。要停用 `pnpm agents:stop`，按归属记录发给派出它的会话，不按启动时间猜进程，不杀整个进程。脚本在本技能 `scripts/`，下面写成 `$S`（Claude Code：`~/.claude/skills/commander/scripts`；别家：`~/.agents/skills/commander/scripts`）。

## 接手
先读 `AGENTS.md`；`pnpm progress read` 办归本会话的引导（引导办没办完看它挂的单：干活的 PR 写 `Closes #单号`，单关了就算办完，没有认领、标已处理这两步；记引导 `pnpm progress directive` 会挂单，不给 `--issue` 就顺手开一张）；要看版本先后用 `pnpm plan`，看法国用 `node $S/france.mjs`。状态一律现查，不凭记忆。`docs/goals.md` 定需求时再读。

## 定需求
- 默认开单给法国（决定 0096）：能写成四节（场景、原话、已知的模块、怎么算做完）、验收在 diff 里看得见、不要本机资源的活，一律 `pnpm issue:new` 开单、不贴「本机做」，开完它会顺手戳法国立刻接；跨会话、分期、等别人的也开单，正文就是需求；放不下的方案写进 `specs/`，单上留链接。**只有这几种留本机**（才贴 `--local`「本机做」，或直接派本机子代理）：①创始人在场、来回讨论中的；②急修（主线红、生产坏、数据、泄露、安全）；③要本机资源的（本机文件、浏览器登录、本机程序）；④改标准的（合并闸要正文有改标准凭据那一行，法国开的 PR 没有）。拿不准就开给法国；法国一单做不成再摘标签本机接。本机做活一律先登记：`pnpm issue:new --local` 开单（开完自动领）或已有单 `pnpm work claim <号>`，分支用 `local/<单号>-<短名>`，PR 合并后租约自动收、不用手动 `pnpm work done`；不开单、不领的本机活不做（不再用 `pnpm pr:open --no-issue` 绕过）。
- 他走了、过夜、无人值守：队列里能写成单的先写成单交法国，本机子代理不留过夜的活，只留「等他回来」的。
- 他拍了板当场记，先照通用段那条分拣、判法看 `pnpm progress directive` 的输出：先读主线上已有的，冲突就问、不覆盖；只记他亲口说的。产品拍板自用仓贴原话和时间，长期的记进 `docs/decisions/`（或那个产品的设计文档），替代旧决定的，在旧决定头部写明被谁替代；要做的活 `pnpm issue:new` 开单；以后都管的 AI 做法才 `pnpm progress directive --kind ai`。对外仓照通用段「对外仓和对外内容怎么写」写成结论、照那个仓自己的记法记，原话只进私有处，AI 怎么干活的那部分回 fleet-dao 记（只写意思，不带那个项目的业务、人名、地址）。

## 派活
- 干活方式由创始人在会话里指定（派子代理、开 mirasim 会话、自己干），指定后一直照着走，到他提出新方式为止；没指定时照下面（#3915）。他指定开 mirasim 会话的，照 `mirasim-sessions` 技能做。会话太长要换棒：照 `commander-handoff`。派中、大活前按 `discuss` 技能的档做讨论，结论写进单的「怎么算做完」和风险。
- 本机活（上面几种）用 Agent 子代理，后台跑。选哪个角色、给哪一档、`model` 怎么写、护栏和收货，一律照 `agents/subagents/README.md`，这里不重抄。派活步骤：
  1. 按活的类型在 README 里挑角色（`Explore`、`general-purpose`、`Plan`）；默认不传 `model`，降档升档只照 README 的条件和写法。
  2. 要降到 Haiku 的，派之前先把核对命令定好、规矩写全，写进交代。
  3. 交代里要它汇报首行写完整模型 id；收到后先对这个 id，再自己重跑一遍核对命令，不只看它贴的输出。
  4. 没过就照 README 的护栏换 Sonnet、留记录。
  5. 干活方式照 README「省额度的干活方式」：自己只调度，窄活分给互不重叠的子代理，子代理只跑自己那块单测，全部合进来后统一验一次，验出问题 `SendMessage` 派回原子代理修。
  主会话在 Fable 上时别用 `fork`。
- 并发不设固定个数（决定 0094）。一批任务里，主动派出所有彼此独立、文件范围不重叠且当前机器容量允许的活；不因省额度少派，也不以固定人数代替资源判断。Claude `Agent` 写码派发由调工具前钩子调用 `capacity.mjs` 判本机容量；Mirasim `dispatch.mjs` 没有容量拦截，每次派 `--route local` 的写码会话前都要现读并判：`node --input-type=module -e "import {readCapacityAsync,judgeCapacity} from './agents/hooks/capacity.mjs'; console.log(JSON.stringify(judgeCapacity(await readCapacityAsync())))"`，只有 `enough: true` 才派；`false` 或 `null`（没查成）就先不派，说明读数或失败原因、等容量恢复后再查。判法是空闲内存至少 4G、1 分钟负载不超过核数 × 0.8；只读会话和云端写码会话不占本机写码容量判断。容量随时会变，每次本机写码派发前都重新判断，不设并发人数上限。
- 能写成单的写码活优先 `pnpm work run <单号> [--brief <交代文件>]` 派（单 #2761）：工人脱离聊天进程（Windows 经 WMI 起看护进程，Mirasim 按停止、插队重启会话停不掉它），经 reclaude 起无头 `general-purpose` 工人，自己领单、建 `local/<单号>-` 工作树、续租约；网关断了等一会儿用同一个会话续，结束写结果文件，收尾钩子 `work-watch.mjs` 只在终态叫醒本会话。派前同样过容量判定；`pnpm work runs` 看全部；看护进程没了（关机、被杀）再跑一次 `pnpm work run <单号>` 接着续。要来回问答、要读本机图形界面的活仍用 Agent 子代理。
- 交代写清：单号、本次任务独有的具体文件/目录边界、共享接口或写入目标、分支名 `local/<单号>-<短名>`、要改什么、怎么算做完、范围和别碰什么、跑哪些测试、本仓 PR 规矩、工作树绝对路径。各个并行写码任务必须各用独立工作树；树只隔离检出，不代表文件或逻辑范围不冲突。派出前核对正在进行的任务边界，不能让并行工人改同一批文件或同时写同一个目标；有范围重叠或依赖就排队，或交同一个工人连续做。生产库和生产配置只读，未获明确许可不派生产写入。根据斥候的结论动手前，自己用一条命令抽查。
- 质量和路由观察沿用现有阶段回报、返工、完成通知及 `pnpm progress note`，按真实任务批次记录任务与工人会话的对应关系、实际 diff、该任务正常运行的测试、指挥会话实际验收结论及返工原因；不另出评测题，也不要求每回合额外测评。可查到 Magpie 用量时，按记录中的 `session` 和 `route_id` 对齐请求模型、实际服务模型（`served_model`）、是否回退（`swapped`）、请求状态和错误、时间及重试；注明时间窗、任务类型与难度、样本数、回退/重试和缺失项。对应不上或字段为空就记「未知」，不得用 HTTP 200、空的 `served_model` 或服务进程存活代替交付质量证据。样本量少、任务难度不同或记录缺失时，只报告观察和局限，不推断路由导致质量变化；不新增监控、例行评测或全量 Grok 复审。
- 派完、手上没有下一刀时：无人值守开着就用当前 CLI 的阻塞等待工具收结果、继续下一轮；未开时可以收轮。不能只凭后台任务存在就假定完成会叫回。结果实际送达后给他报一行再派下一件。队列＝`pnpm work queue`（本机做的开着的单，每张一个状态和为什么：母单、在做（开着的 PR、本机有 `local/<单号>-` 工作树、`pnpm work claim` 记下没到期的租约、30 分钟内的心跳）、等前置（正文一行「前置：#N …」里还有开着的）、等人拍、可接；`--json` 给机器读），不再从里程碑说明、#1055、对话、记忆里拼。收轮前收尾钩子对一遍账（只在无人值守开着时判；本会话显式 off 后不再拉起，重新 on 才恢复）：有可接的活、本机容量够、而且没有子代理在跑（只有后台命令、监视器在跑也算没有）就把这一轮挡回，理由列前三件，连挡 3 次放行一次；某件真不该现在接，给单贴「要人拍」或摘「本机做」交给法国。子代理停住：还在本会话里的，用 `SendMessage` 问它卡在哪。归属记在别的会话上的，用 `pnpm agents:stop` 把停止发给那个会话；问不到就停，不另起一个顶上，不按启动时间找进程。
- 工人等 CI 用一条前台的 `gh pr checks <PR> --watch --fail-fast`（或 `gh run watch <id> --exit-status`），一直等到合并或红，中途不 sleep 轮询、不收轮：子代理的前台命令钩子不改成后台，每收一轮都会叫醒指挥官一次。
- 主线程等结果只用 `node $S/wait.mjs pr <号> | pr-head <号> --after <完整40位head> | main-ci | issue <号>`，`run_in_background` 挂着：到结果才写一行退出（0 成功、1 失败），gh 出错、输出认不出当场退出码 2 并写明原因。复审等返工用 `wait.mjs pr-head`：同头继续等，变头返回旧、新完整 head 和 PR 链接；已合并返回 0 并说明，关闭未合返回 1，终态先于头变化。收到新头后重新审查，不表示批准、验收通过或已合并；不以旧头的 CI 或评审状态结束等待。`pr` 遇合并闸提交状态 failure 时从精确 head 的 REST 完整分页读理由并复读 PR 核身份，只豁免单一等验收；同名红 CheckRun 仍是真红，读失败或串头退出 2。主线程不手写「循环 + sleep」（钩子拦，#2730：手写轮询的错进了 `2>/dev/null`，空跑 90 分钟）；等一条本机命令就直接后台跑它本身。法国的单不盯，只看巡检的 `ALERT`；本机工人用完成通知叫回，不另起监视器。
- 无人值守：先看这个会话是不是 mirasim 托管的。是（环境里有 `MIRASIM_SESSION_KEY`，mirasim 起的会话都有：指挥官会话、它开的子会话都算）——`node ~/.fleet-dao/hooks/unattended.mjs on` 照样跑，它不挡收轮；接续不靠 Stop，靠两样：子会话用 `prompt` 把回报发进本会话，再加一个 30 分钟心跳（`mcp__mirasim__schedule_task`，`cron` 用 `*/30 * * * *`，`prompt` 写清「无人值守心跳：查子会话回报和队列，有活就接着派」，`once` 不设）。`on` 只记状态，不排心跳；心跳没排上就收轮，这个会话没人叫醒。队列空了、活都收口，`unattended.mjs done` 之后把这个心跳定时任务停掉。不是 mirasim 托管的会话照下面：`node ~/.fleet-dao/hooks/unattended.mjs on` 之后，未完成工作经同步 Stop 接到下一轮；后台任务先用本 CLI 的阻塞等待工具收结果，不能只凭任务条数结束。Claude/Codex 都登记成功 PostToolUse 的新写入、验证、提交、收工，连续三次无实质进展明确 paused 接续故障，不能仍标 on 却悄悄收轮；重复命令、sleep、PR 状态轮询不算进展。其他 CLI 未有实证支持时明确不支持，不照抄 Stop/asyncRewake。on 只记意图，安装、登记、信任、执行与完成通知须逐层验证（见 `docs/design/CLI无人值守接续.md`）。每个完成通知 `pnpm progress note` 一句、再派下一件；队列空且子代理都收口跑 `unattended.mjs done "做完了什么"`，要他拍跑 `needs-you`，他说停跑 `off`。监控用 `node $S/patrol.mjs`（#2370：法国上只跑 `fleet-api attention --json`，由引擎给出 healthz、该推的通知、推送不通、简报没到的结论，巡检只读它，不再自己抄判法；`/healthz` 非 200 判 BROKEN，推送不通、简报没到、新的该推通知判 ALERT；法国还是没有 attention 命令的旧版本时 BROKEN 理由写「法国版本还没有 attention 命令」；读不到法国时顺手 curl 本机配的香港状态页），只看最后一行：`VERDICT: OK` 不叫模型，`ALERT` 才派斥候，`BROKEN` 亲自跑 `france.mjs`。

## 发版
平时不用管：主线头 CI 全绿（含 E2E）、没有发版在走，法国自己发；发版不关引擎总开关，切版本那几分钟暂停在跑的任务、发完续上，驱动死了法国自己续上、报一条（决定 0093）；没发的原因看 `release.sh --check`。要马上发才用 `node $S/release-train.mjs start --sha <主线提交> --founder-ok "<创始人原话>"`（发版自己拍、事后一行报；脚本只认创始人原话，他这次没说就贴他授权你拍板的那句原话和时间，引导 20261015054500），`status` 看进度；预检拦在「主线 CI 不是绿的」就先修主线。发后体检只拦和这次新版有关的提醒，别的提醒照常去修，不算发版没成。

## 盯到合并
PR 照 `AGENTS.md`，开完不盯，红了才回来修；真要等某个 PR 或主线 CI（比如发版前），后台挂一条 `wait.mjs`，不起监视器。法国异常先看 `france.mjs`；急的（主线红、生产坏、数据、泄露、安全）当场修。
