# 子代理选模型（决定 0087：三个角色）

派 Claude 子代理之前读这一页。创始人 2026-10-12 定了「Sonnet 是工人、Haiku 是斥候、Opus 是设计」「你之前分了太多类了，不需要那么多类。你能删的删」「每一台机器都要沿用这种方式」（决定 0087）。原来的 16 个 `fleet-*` 和 `haiku55` 全删了；「子代理、工人永不用 Fable」不变。

## 三个角色

| 角色 | `subagent_type` | 钉的型号 | effort | 干什么 | 拿什么核对 |
|---|---|---|---|---|---|
| 斥候 | `Explore` | `claude-haiku-5-5` | medium | 只读：读码检索、谁调谁、日志和 CI 输出归纳、查资料、验证、跑测试读结果、分类和范围检查、评审初筛 | 产出要能一行抽查：`文件:行`、命令原始输出行；只回证据、不归因 |
| 工人 | `general-purpose` | `claude-sonnet-5-5` | medium | 写代码、改文件、改文档、修 bug、部署、开 PR；界面活也归它（照仓里的界面规范，用浏览器的官方命令行真点页面，PR 带截图） | CI 和点名跑的测试 |
| 设计 | `Plan` | `claude-opus-5-5` | high | 只读：计划、架构方案和取舍、方案合成、疑难根因、评审下结论 | 每个结论带证据；方案由派它的人落盘 |

- 三个名字就是 Claude Code 内置的，仓里 `agents/subagents/` 下同名的定义压住内置的（2026-10-12 本机 2.1.296 实测：`--agents` 和同名文件两条路，三个角色都用上了钉的型号）。
- 这三份是唯一的原件：`pnpm agents:sync` 把它们装到每台机器的 `~/.claude/agents/`（开会话钩子也跑；法国跟着自动发布给两个会话用户各装一份），引擎从发布目录的同一个目录转成 `--agents` 传给它起的 Claude Code 会话。仓里没有 `.claude/agents/` 了，别再建（`agents/test/rules/project-subagents.rules.test.ts` 钉着）。
- 改只改仓里，不在 Mirasim 智能体页面里编辑或开关这三份：页面「编辑」改的是同一个文件，下一次同步会备份后换回仓里的；「开关」是改名成 `.md.disabled`，同步会再装一份。
- 只有 Claude Code 读这些定义文件；Codex、Cursor、Grok、Devin 不读，它们靠通用段里的文字规矩。
- 会话里 `Explore` 还是内置那个（汇报首行的 id 不是 `claude-haiku-5-5`），就是这台还没同步上：跑 `pnpm agents:sync`、重开会话。

## 原则

1. **能用脚本判的不用模型**（`judge-or-code` 技能）：数文件、比对、巡检采集、判阈值用脚本；模型只管要理解的那一步。
2. **按「产出能不能被脚本或一条命令核对」选角色，不按活的名字**：能核对的只读活先给斥候；要写进仓里的给工人；错了会传到所有机器（改标准）、要下结论、两次失败的疑难，给设计出方案或根因，再由工人（升到 Opus）动手。
3. **不另造类型**：任务细节、仓的规矩、产出格式写进派活的话里。
4. **级联：先斥候、核对不过再升级，不在同档重试**：
   - 斥候：核对它的脚本或命令不过、产出里没有可核对的证据、它自己说拿不准，就改派工人重做。它的失败信号本身不可靠，同一个错不值得试第二次。
   - 工人：同档连着失败两次，同一个 `general-purpose` 传 `model: "opus"` 再派；还不行回到指挥官自己。
   - 汇报首行的模型 id 对不上（见下面「交代必写」），当这次没做、升一档重派。
5. **并发上限仍是 4**，斥候也占名额。无人值守时给监控留 1 个，干活的最多 3 个。

## 怎么派

- **Agent 工具**：写 `subagent_type`（`"Explore"`、`"general-purpose"`、`"Plan"`），不传 `model`（传了会盖过定义里的钉）。升档才传 `model`，只用这两种：斥候的只读活要更强的推理，`Explore` 传 `"sonnet"`；工人写不下来，`general-purpose` 传 `"opus"`。别名在经 Mirasim 起的会话里可能解析到旧版，所以派完照样核对汇报首行的 id。
- **Workflow**：`agent()` 的 `agentType` 填 `"Explore"`、`"general-purpose"`、`"Plan"`，不传 `model` 就用定义里的钉，升档才传 `model`。不写 `agentType` 的 `agent()` 跟主会话同一个模型（装了设置里默认的机器上是 Sonnet），所以每个 `agent()` 都写 `agentType`。`effort` 不用另传，定义里钉了。
- **命令行**：要某一版就写完整 id：`claude -p --model claude-haiku-5-5 …`。它返回的 `costUSD` 对 5.5 不准，不当账；账按官方价和实际 token 算。
- 主会话在 Fable 上时别用 `fork`：`fork` 起的总跟主会话同一个模型，写了 `model` 也不管用。
- 这几个环境变量不设：`CLAUDE_CODE_SUBAGENT_MODEL_FORCE`（压过定义里的 `model`）、`CLAUDE_CODE_EFFORT_LEVEL`（压过定义里的 `effort`）。设置里的 `CLAUDE_CODE_SUBAGENT_MODEL`（Sonnet）排在定义之后、压不住这三份，只兜住没写类型的。

Haiku 5.5 不做的：没有机器核对的开放式长链编码、改标准、架构方案、要下结论的评审、归因。官方基准里它的长链命令行编码只有 Sonnet 5.5 的一半多，我们的实测没覆盖这一类，不外推。它的提示超过 100K token 整单 5 倍计价，输入要控制在 100K 以内。

不派子代理的场景：
- 能用脚本判的：脚本，不叫模型（`judge-or-code`）。
- 讨论、让别家挑错：别家模型（`discuss`，默认 GPT；界面类不给 GPT），不派 Claude 子代理。
- 引擎自己接的单、法国上的会话：用的是驾驶舱配的路由，不归本页管。
- 一两条命令就查得清的：自己查，别起子代理（起手固定开销比活大）。

## 交代必写

每次派活的交代都写明这几样（另加 `SKILL.md`「子代理的交代要瘦」那四件事）：

1. **角色**：`subagent_type` 写三个名字之一；升档才写 `model`，写一句为什么。要它**汇报首行写自己的模型 id**（`claude-haiku-5-5`、`claude-sonnet-5-5`、`claude-opus-5-5`；它的系统提示里有），对不上就是这台的定义没同步上或别名指到了别的版本，当这次没做、升一档重派。
2. **做什么、范围**：只读，还是可写哪些路径；要独立工作树就在派的时候写 `isolation: "worktree"`（定义里不写）。
3. **产出格式和长度上限**：斥候一般 ≤15 行。
4. **停下条件**：做到哪一步就停、什么情况回来问。
5. **前台等待**：测试、安装前台跑到完，不拆后台、不轮询。
6. **拿什么核对**（派斥候必写）：派之前就定好核对它的脚本或命令，写进交代。
7. **这个仓的规矩**：三份定义是通用的，不带任何仓的命令和路径；怎么开 PR、跑哪些测试、临时文件放哪、署名行，都写进交代。

派斥候的交代另加：**用到的每条硬规矩都逐条写出来**（实测：只写了 8 条里的 4 条，它就把函数名、事件名也括进了「已知的模块」——没写明的细节它会漏）；输入控制在 100K token 以内；每条结论都附证据；拿不准就写「拿不准」，不猜。

## 先砍固定开销

每次子代理调用光起手的系统提示和工具说明就要写缓存约 2 万到 4.6 万 token，比模型差价更值得砍。

- 斥候的定义带 `omitClaudeMd: true`、限 `maxTurns`，不读全局说明。
- 交代里写回合上限和输出长度；一次能问完的不拆成几次派。
- 同一批相似的小活（几份单子的准入检查）合成一次派，不一份起一个。

## 斥候的结论怎么用

指挥官据斥候的结论动手之前，自己用一条命令抽查（跑那条核对脚本、读那一行、跑那一条命令）。抽查对不上：这次结论作废，改派工人重做。小模型的错答会不声不响地流进总管的结论，这一步不省；小模型评小模型偏松，斥候的产出不交给另一个斥候判。

## 无人值守的监控

监控的主体是脚本，不是模型。

- **采集和判定**：约每 10 分钟跑一次 `node ~/.claude/skills/commander/scripts/patrol.mjs`（在主检出根目录跑）。它一次 ssh 只读收齐法国的服务、资源、引擎总开关、没做完的单、定时任务、开着的通知，每项一行带计数和采集时间；和上一次的基线比出 `DELTA`；不变量（服务不 active、磁盘超 85%、可用内存少于 1G、单卡住或停下超过 30 分钟、定时任务最近一次不 ok、新开的通知、引擎总开关关着、在用版本读不到）由脚本判，命中就记进 `ALERT`。
- **基线只由脚本写**：放 `_tmp/patrol-baseline.json`。`OK`、`ALERT` 写新基线，`BROKEN` 不写。模型不碰基线。
- **沉默告警**：ssh 连不上、输出是空的、少了哪一块、库查询报错、采集时间和本机差超过 15 分钟，一律 `VERDICT: BROKEN`，不当 `OK`。
- **指挥官只读最后一行**：
  - `VERDICT: OK`：不叫任何模型，接着等。
  - `VERDICT: ALERT <n>` 且 `DELTA` 不为 0：派一个短命的斥候（`subagent_type: "Explore"`），输入只给那几行 `DELTA`、`ALERT` 和相关日志片段（远小于 100K），它只回证据行和哪几项变了，不归因、不给修法，≤10 行；核对：它回的证据行要在 `patrol.mjs` 的输出里原样找得到。归因和修由指挥官自己或派工人做；动手修之前先用一条命令抽查。
  - `VERDICT: ALERT <n>` 但 `DELTA` 是 0：同样的异常上一轮已经报过，不再叫模型；还没处理完就接着处理。
  - `VERDICT: BROKEN`：指挥官亲自巡一次（`node ~/.claude/skills/commander/scripts/france.mjs`）。
- **指挥官亲自巡的三个触发**：连续 3 个周期没读到 `VERDICT` 行；出现 `BROKEN`；据斥候的摘要要动手修之前。
- **自检**：无人值守跨天时，每天至少跑一次 `patrol.mjs --selftest`。它拿固定的假输出验 `ALERT`、`BROKEN` 的判法还灵；最后一行不是 `SELFTEST: OK` 就当监控失效，亲自巡，并修脚本。
- **不做**：不起一个无限循环盯盘的子代理（上下文会涨、会被截断、会话一断就没了）；不每个周期都叫模型。
