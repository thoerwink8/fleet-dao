# 子代理选模型（决定 0034）

派 Claude 子代理之前读这一页。创始人 2026-10-09 00:09 授权「改成最具有性价比的调整方案……全程你拍板」，指挥官据此定了下面这套，取代了「子代理只用 Sonnet 或 Opus」；「子代理、工人永不用 Fable」不变。

## 原则

1. **能用脚本判的不用模型**（`judge-or-code` 技能）：数文件、比对、巡检采集、判阈值用脚本；模型只管要理解的那一步。
2. **按「错了的代价 × 能不能抽查」选档，不按活的名字**：
   - 错了没代价或一眼看得出、产出带 `文件:行` 或命令输出这类可抽查的证据 → Haiku 5.5。
   - 要写进仓里、会合进主线、错了要回退 → Sonnet 5.5（默认档）。
   - 错了会传到所有机器（改标准）、要下结论的评审、架构方案、两次失败的疑难 → Opus 5.5。
3. **升级，不在同档重试**：
   - Haiku：一次产出里没有可抽查的证据、或它自己说拿不准，就升到 Sonnet 重做。它的失败信号本身不可靠，同一个错不值得试第二次。
   - Sonnet、Opus：同档连着失败两次，升一档；到 Opus 还不行回到指挥官自己。
   - 汇报首行的模型 id 对不上要的那一版（见下面「交代必写」），当这次没做、升一档重派。
4. **并发上限仍是 4**，Haiku 也占名额。无人值守时给监控留 1 个，干活的最多 3 个。
5. **有理由可以越档**：表里是默认值，不是死规矩；越档要在交代里写一句为什么。

## 档位表

| 活 | 默认模型 | effort | 为什么 |
|---|---|---|---|
| 读码检索（找文件、谁调谁，配合 codegraph） | Haiku 5.5 | low–medium | 机械、可抽查，要它回 `文件:行` |
| 跑指定测试、压缩日志和 CI 红灯输出 | Haiku 5.5 | low | 输出大、结论短；**只回证据行，不归因**，原因由 Sonnet 或指挥官下 |
| 只读巡查 VPS 的异常摘证据 | Haiku 5.5 | low | 采集和判定靠 `patrol.mjs`，Haiku 只摘 `DELTA` 里的证据；只准只读命令 |
| 评审初筛（范围越界、碰标准路径、疑似密钥、测试是否点名） | Haiku 5.5 | medium | 清单式；结论仍由 Sonnet 或 Opus 下 |
| 写代码、改文件、补测试、改文档、开 PR、调研、写给引擎的单子、给 CI 红灯归因 | Sonnet 5.5 | medium | 默认档，性价比最高的「手」 |
| 改标准（`agents/**`、通用段、技能说明、钉住规矩的测试）、架构方案、评审下结论、两次失败后的疑难调试 | Opus 5.5 | high | 错了代价大 |
| 讨论、让别家挑错 | 别家模型（`discuss` 技能，默认 GPT） | — | 换族才有价值，不派 Claude 子代理 |

Haiku 5.5 不做的：复杂多步编码、要改仓里文件的活、要下结论的评审、归因。它的提示超过 100K token 整单 5 倍计价，输入要控制在 100K 以内。

## 交代必写

每次派活的交代都写明这几样（另加 `SKILL.md`「子代理的交代要瘦」那四件事）：

1. **模型**：Agent 工具的 `model` 只收别名，写 `"haiku"`、`"sonnet"` 或 `"opus"`，不留空。要的版本是 `claude-haiku-5-5`、`claude-sonnet-5-5`、`claude-opus-5-5`：交代里要它**汇报首行写自己的模型 id**（它的系统提示里有），对不上就是这台的别名指到了别的版本，当这次没做、升一档重派。能写完整 id 的地方（工人的 `--model-id`、设置里的默认 `CLAUDE_CODE_SUBAGENT_MODEL`）一律写完整 id、不写别名。
2. **做什么、范围**：只读，还是可写哪些路径。
3. **产出格式和长度上限**：Haiku 一般 ≤10 行。
4. **停下条件**：做到哪一步就停、什么情况回来问。
5. **前台等待**：测试、安装前台跑到完，不拆后台、不轮询。

Haiku 子代理的交代另加三句：输入控制在 100K token 以内；每条结论都附证据（`文件:行`、命令和它的原始输出行）；拿不准就写「拿不准」，不猜。

## Haiku 的结论怎么用

指挥官据 Haiku 的结论动手之前，自己用一条命令抽查（读那一行、跑那一条命令）。抽查对不上：这次结论作废，升到 Sonnet 重做。小模型的错答会不声不响地流进总管的结论，这一步不省。

## 无人值守的监控

监控的主体是脚本，不是模型。

- **采集和判定**：约每 10 分钟跑一次 `node ~/.claude/skills/commander/scripts/patrol.mjs`（在主检出根目录跑）。它一次 ssh 只读收齐法国的服务、资源、引擎总开关、没做完的单、定时任务、开着的通知，每项一行带计数和采集时间；和上一次的基线比出 `DELTA`；不变量（服务不 active、磁盘超 85%、可用内存少于 1G、单卡住或停下超过 30 分钟、定时任务最近一次不 ok、新开的通知、引擎总开关关着、在用版本读不到）由脚本判，命中就记进 `ALERT`。
- **基线只由脚本写**：放 `_tmp/patrol-baseline.json`。`OK`、`ALERT` 写新基线，`BROKEN` 不写。模型不碰基线。
- **沉默告警**：ssh 连不上、输出是空的、少了哪一块、库查询报错、采集时间和本机差超过 15 分钟，一律 `VERDICT: BROKEN`，不当 `OK`。
- **指挥官只读最后一行**：
  - `VERDICT: OK`：不叫任何模型，接着等。
  - `VERDICT: ALERT <n>` 且 `DELTA` 不为 0：派一个短命的 Haiku 子代理（`model: "haiku"`），输入只给那几行 `DELTA`、`ALERT` 和相关日志片段（远小于 100K），它只回证据行和哪几项变了，不归因、不给修法，≤10 行。归因和修由指挥官自己或派 Sonnet 做；动手修之前先用一条命令抽查。
  - `VERDICT: ALERT <n>` 但 `DELTA` 是 0：同样的异常上一轮已经报过，不再叫模型；还没处理完就接着处理。
  - `VERDICT: BROKEN`：指挥官亲自巡一次（`node ~/.claude/skills/commander/scripts/france.mjs`）。
- **指挥官亲自巡的三个触发**：连续 3 个周期没读到 `VERDICT` 行；出现 `BROKEN`；据 Haiku 的摘要要动手修之前。
- **自检**：无人值守跨天时，每天至少跑一次 `patrol.mjs --selftest`。它拿固定的假输出验 `ALERT`、`BROKEN` 的判法还灵；最后一行不是 `SELFTEST: OK` 就当监控失效，亲自巡，并修脚本。
- **不做**：不起一个无限循环盯盘的子代理（上下文会涨、会被截断、会话一断就没了）；不每个周期都叫模型。
