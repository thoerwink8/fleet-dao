# core：纯判断层（业务说明）

> 一句话：把「一张单下一步该怎么走、这块活收不收、这个问题算不算合格提问」这类判断写成不碰网络和库的纯函数，让引擎、后端、网页、`fleet` 命令都调同一份，判得一样。
> 出处：`packages/core/package.json` 说明；`docs/decisions/0003-fusion-flow.md` 第 12 条；`packages/core/test/structure.test.ts`。

## 一、干什么、不干什么

- **干**：13 个文件，每个文件是一类判断——状态机（`flow.ts`）、Fusion 工作流要的判断（`fusion.ts`）、任务简报（`brief.ts`）、Lead 验收副手（`acceptance.ts`）、开 PR 前别家验证的结论（`verdict.ts`、`criteria.ts`）、问创始人（`ask.ts`）、派不派一张单（`dispatch.ts`）、流程配置和库里副本（`config.ts`、`replica.ts`）、帅位租约与认领（`seat.ts`）、提醒谁在处理（`alert-work.ts`）。
- **不干**：读库、读 GitHub、读文件、起工作流——那些是「外壳」（引擎、后端、网页、fleet 命令）的事，外壳把读到的东西交进来，这里只判。
- **硬约束**：只许依赖 `@fleet-dao/shared` 和 `zod`（`test/structure.test.ts` 盯着，含一条故意引入 `node:fs` 会被认出来的失败用例）。

## 二、业务规则（每条标出处）

**A. 派不派一张单（`dispatch.ts`，26 条测试）**

1. 自动派要过五道：接活开关开着；这张 issue 是开关打开以后开的；挂在**当前版本**上；不是母单也不是子单；没贴「本机做」。——`test/dispatch.test.ts`；0003 第 2、4、8 条；design 第九节。
2. 「当前版本」＝还开着的、名字以 `v<N>` 开头的里程碑里 N 最小的那个；旧的 P 阶段里程碑、`v1.5`、大写 `V`、没数字的一律认不出、不算版本。——同上。
3. 未排期、挂在别的版本、挂在已关的里程碑、里程碑认不出版本号：都不派；认不出说「没查成」，不当成当前版本。——同上（故意造出的失败行）。
4. 母单和子单都不自动派（一张单只走一块，母单子单各起一条会抢同一批文件）。——#252。
5. 贴了「本机做」的不自动派（认领进库之前的止血）；要交给引擎得先去掉标签再 `handover`。——#299。
6. 人明说交给引擎（`fleet-api handover`）：替人放行开关以前、别的版本、未排期那几道，但任务和 issue 的规矩照旧：在跑的不重复起；GitHub 上已关的一律拒（哪怕任务还在跑）；已结束的只有重开过才再起一轮；这个号其实是 PR 也拒。——同上。

**B. 一张单怎么走（`flow.ts`、`fusion.ts`，36 条测试）**

7. 状态机是一张表：「当前状态 + 刚发生的事 → 下一步、外壳要做的事」；认不出的组合明说「不该出现」，不猜着往下走。——`flow.ts` 头注释；`test/flow.test.ts`。
8. 发布前就在跑的工作流，旧状态里没有后加的字段（如 `mergeRounds`）：补缺的字段照样能判，已有的值不被起始值盖掉；错的值照样判「状态认不出」。——`flow.test.ts`。
9. 开工前先看流程配置能不能用、这张单用哪套、每一步派哪几个模型；单上指定的配置不存在、判的时刻认不出：不派，不拿默认那套顶。——`fusion.test.ts`（`setupFusion`）。
10. Lead 交回的方案和任务简报要齐全才收；Lead 的最终审查过了才关，要改的带一份能派的修复简报。——`checkLeadPlan`、`checkLeadReview`。
11. PR 正文和关单评论的写法：方案摘要打头、验证结论进「怎么验证的」、建议进「还欠什么」、按推荐先做了的进专门一栏；没验、Lead 单干、用的全组织默认，都明说；读不到的写「没读到」，不写成 0。——`fusionPrParts`、`closeComment`；#259、#246。

**C. 任务简报与副手验收（`brief.ts`、`acceptance.ts`，12 条测试）**

12. 简报缺目标、范围、只许改的文件、怎么算合格、交回格式的不收；几份同时派的不许改到同一个文件，最多 3 份。——`brief.ts`；0003 第 5 条。
13. Lead 验收：先看事实，空交付、测试没过或没跑成（没跑成≠没过≠过了）、碰到别的块简报里的文件，Lead 说收也不收；简报外、别的块也没认领的文件不算事实，Lead 看过就收下、结果里列出来；打回满 2 次再不行 Lead 自己接手。——`acceptance.ts`；#246（一块的单没有别人的文件，「简报外一律不收」注定白转两轮）。

**D. 开 PR 前别家验证（`verdict.ts`、`criteria.ts`，35 条测试）**

14. 对照「怎么算做完」**逐条**答：做到 / 没做到 / 看不出，带证据。只有三种能挡：没做到验收条、有证据弄坏原有功能、安全或丢数据；其余写进 PR 当建议。——`verdict.ts`；0003 第 5 条第 5 步。
15. 交回的认不出、审的不是送检的头、验证模型和写的同族：一律「作废」，不当成过了；Lead 驳回必须带证据，不带证据作废。——`verdict.test.ts`。
16. 「怎么算做完」按规范化后的文字对（只抹不改意思的格式差别，如反引号），对上了往下传的是**清单原文**；真不一样、撞成同一条、漏答，各有明确判法。——#246 验收撞上的。
17. 需求文档路径来自单子正文里那一行「文档：`specs/<号>-<短名>/需求.md`」；引擎自己开的单没有这行，正文写全了需求就照正文写、随 PR 进主线；「怎么算做完」被删或空了：**明确报错**，不拿空清单去验。——`criteria.ts`；#295。

**E. 问创始人不许卡住活（`ask.ts`，26 条测试）**

18. 提问一律带选项和推荐；这张单范围内的岔路**按推荐先做、不等**；超出这张单范围的另开一张未排期单等他拍，这张单绕开；碰人闸四类的也先按推荐做，只挡合并那一步。——#259。
19. 只有他本人才有的东西（账号、权限、登录）不算提问，走 `fleet blocked --needs access`。——同上。
20. 他晚到的回答：选的就是推荐的只记一笔；选了别的，单子没合就在下一个存档点交给主导改，已合就开后续单；后续单照抄原单类别、挂原单同一个版本，超出范围的一律未排期。——`ask.test.ts`。
21. 说是按推荐先做、却没记推荐的，不算按推荐先做（不拿空的冒充推荐）。——同上（故意造出的失败行）。

**F. 流程配置（`config.ts`、`replica.ts`，28 条测试）**

22. 全组织默认一份（`packages/core/flow.default.json`），各仓 `.fleet/flow.json` 只写不同的；禁令只能写在全组织默认里、项目改不掉。——0003 第 9 条。
23. 全组织默认读不到、认不出＝全部停派；项目的读不到、认不出＝这个项目停派、报红；**都不拿默认顶**。——`config.test.ts`。
24. 库里的配置副本只是副本：对账读完仓里的文件写副本；派活前看副本能不能用（认不出、从没同步过、超过 45 分钟都停派，同步时刻在将来不为此停派）；「这版没听说过的字段」和「真错了」分开（前者可能是配置比引擎新）。——`replica.test.ts`。

**G. 帅位租约与认领（`seat.ts`，32 条测试；`alert-work.ts` 的一部分）**

25. 时间一律用库的 `now()`，不拿各机器时钟判过期；任期号就是栅栏号，接班一次加一；读不到、认不出一律算「不是帅位」（fail closed）。——`seat.ts` 头注释；#299。
26. 认领过了宽限期没心跳＝作废；引擎的认领、已结束的认领不按心跳作废；「认领对得上」只放行正文写的是现在那份认领号的 PR。——`seat.test.ts`；#348。
27. 提醒的「谁在处理」读时现算（认领、PR 镜像、发布记录），引擎自己的认领不算有人在处理，单列 `engine_stuck`；静默必带到期（最长 7 天）、必写为什么。——`alert-work.test.ts`；#445（删掉了自动开跟进单、要认领这一层）。

## 三、现状（做了 / 没做 / 做坏了）

- **做了**：以上全部；每张判断表都带「故意造出的失败」行，且纯度有测试盯着。
- **做坏了**（按 `docs/goals.md`）：Fusion 0–7 步交接太多、断点太多——引擎到 09-29 只做完 12 张单、叫停 75 张；`seat.ts` 32KB 是 core 里最大的一块，服务的是「帅位全局只一个」，创始人 09-29 已拍删。
- **没做**：三段一条龙（指挥官→工人→Review）对应的状态机；副手的判断（问什么、答什么）。

1. core 只剩 4 类判断：接活（派不派）、三段状态机、问创始人、提醒静默与发布状态；文件数和行数明显少于现在，仍只依赖 `shared` 和 `zod`。
2. 每一类判断有边界表测试，**每条「读不到、认不出」的路径都有一条故意造出失败的用例**（通用段「底线」）。
3. 删掉 `seat.ts`、认领相关的同时，引擎、后端、网页、`fleet` 命令里对应的调用和库表一起删（第六节「新旧不并存」）。
