# engine（五）：会话与端口（怎么起 AI 会话、交代活、认交回、接 GitHub 和库）

> 本份是 `engine.md` 的子文档之一。「端口」（`ports.ts`，41KB）是引擎对外的每个动作：起会话、推分支、开 PR、等 CI、合并、写进度、问创始人、开人闸……每个都是一个 Temporal 活动，由别的包实现。`real/` 是真装配（库、GitHub、会话插头、工作树），`fakes.ts` 是假实现。生产只认 `FLEET_ENGINE_PORTS=real`，**缺了哪一项就不起、一次列全，不带着半套配置接活**。
> 出处：`packages/engine/src/{ports,fakes,worker,main}.ts`、`real/`（24 个文件，`sessions.ts` 104KB 是全仓最大的单文件）；测试 `real/*.test.ts`（约 700 条，全在 `packages/engine/test/real/`）。

## 一、端口与活动的约定（`ports.ts`）

1. 每个动作是一个活动：实现方**不用碰 Temporal**，拿到的 `ctx` 里有取消信号和心跳；抛 `PortError`（`code`、`retryable`、`details`）就把错误码原样带过 Temporal 边界；GitHub 包的 `GitHubError` 一律换成 `PortError`（码和「能不能重试」原样带过，失败分流按码判）。——`ports.ts` 头注释；`real/github-ports.test.ts`「GitHubError → PortError」。
2. 长活动（`awaitSession` / `waitCi` / `runTests`）**至少每 `heartbeatSeconds/3` 调一次心跳**，不调就在心跳超时后被判「工人丢了」并重试（工人重启后分钟级发现，不再干等整段限时）；会被重试的活动**必须幂等**：推分支、开 PR 按分支复用、合并带头约束（已合上的回 `merged` 和合并提交）、写 GitHub 带幂等键、删已经不在的对象正常返回；编号由工作流给（记在历史里）、实现按编号去重。建树等 GitHub 时也照常心跳（大仓第一次抓进镜像可能几分钟）。——`ports.ts`；`real/github-ports.test.ts`。

## 二、会话端口（`real/sessions.ts`，117 条测试）：起、看守、叫停、收孤儿

3. **起会话按 `runId` 幂等**（库里 `session_runs` 一行）：同一个 `runId` 起第二次回同一个、不起第二个进程；叫停过的 `runId` 不再起；建树取包半截失败后同一个 `runId` 重试照常取包、检出分支，不在空仓里起会话；路由的执行方式没接上（`HOST_NOT_WIRED`）、账号池没定会话用户、任务不在：**起之前明确拒**；资源上限不是非负整数（小数、负数）起之前明确拒、不悄悄取整；**项目没写测试命令（流程配置副本里没有）：写码会话起之前明确拒、库里不留这一行，不拿给人看的旧值顶**；交给插头的上限帮手认得（交换区上限 0 写「0」，写「0M」帮手会拒、会话起不来，法国 2026-09-26 实测）。——`sessions.test.ts`「写码会话」「失败」。
4. **会话号**：Claude 的由我们定（UUID，`--session-id`）；cursor、Mirasim 开新会话的号是它自己起的，开工先记一眼看得出不是 UUID 的临时号（`cursor-pending:<runId>`），真号到了记在看守上、结束时交给工作流写进库；grok 我们定号（`-s`）但真开了会话才算数（终帧回的就是它）。**起进程失败明确报 `SPAWN_FAILED`（不可重试）、进程迟迟起不来到点报 `SPAWN_TIMEOUT`（不可重试）、进程起来了库里却没这一行（`SESSION_RECORD_MISSING`）或开工写库时库报错（`SESSION_RECORD_FAILED`，可重试）：都停掉会话、收掉 scope，不留孤儿**。——`sessions.test.ts`。
5. **交活判据**：写码类用 `fleet done`（后端核实写进库），会话结束后引擎自己看工作树拿头和改动；**没用 `fleet done`、有没提交的已跟踪改动、没有新提交，都判没交付、不当成做完**；会话说卡住（`fleet blocked`）：结局 `blocked` 带原因。分诊、需求文档、方案、审查把结论写进检出副本里的 `.fleet-out/` 下文件，引擎读出来按形状核对——**没写、不是 JSON、说不清却没写要问的、审的不是送检的头、漏答、答了清单外的（字不一样，不只差格式）：都判「交错了」（`wrong_output`）并写明哪里不对，不猜、不补默认值**。续同一个会话时，以前同一步留下的结论文件起之前先删掉（这一轮没写就是没写）。——`sessions.test.ts`；`real/prompts.ts`。
6. **这一步自己改了什么：扣掉会话并进来的主线**（#293）：会话并了改过页面代码的主线、再改一个非界面文件，只算自己改的那一个；只并了主线自己没写东西＝判没交付（不当成交了主线上别人的活）；并主线有冲突、会话解了：解冲突改的文件算这一步的、主线另带进来的不算；树里没钉主线明确报 `MAINLINE_MISSING`，不拿「起会话前的头之后的全部」冒充；找含到的主线、算并上主线的样子没跑成或输出认不出：明确报 `GIT_FAILED`。**patch-id**：相对主线的改动指纹，只并了主线不变、PR 自己又改了一处就变；没钉主线、给的提交不在树里算不出来抛 `GIT_FAILED`（调用方按「没查成」处理，不许当成一样）。——`real/user-git.test.ts`。
7. **会话断了接着干**（`decideContinuation`，#212、#59，`real/continuation.test.ts` 14 条）：同池、同会话用户、同执行方式、同一个目录、真号 → `--resume` 续上；**续不上就开新会话并带「接力任务书」**（步骤、进度、已提交的不重做），`why` 写清为什么：上一轮的记录查不到、上一轮跑在别的（已停用的）会话用户下、上一轮的路由已不在、换了执行方式、续的号不是 UUID（cursor 报出真号之前就断了）、换了目录（会话记录按目录存）、cursor/grok/Mirasim 换了账号池（没有 fork）、Claude 换了账号池且上一轮上下文大了；**只有 Claude、只换了池、上一轮上下文还小才 `--fork-session` 续**（不改属主、不拷记录）。续会话等第一帧的时限按已有长度放宽（每 4 万 token 一分钟、最多 12 分钟；上下文不知道的按上一轮跑了多久每 10 分钟一分钟；多长都不知道给放宽的一半）；上一个会话没提交的改动写进提示词（前 20 个，先读 `git diff` 接着做，不从头重写）；这一轮的花费按上一轮的累计求差。——`sessions.test.ts`；`real/resume-startup.test.ts`。
8. **切号那一刻在跑的会话**（#59）：停下跑在这些池上、进程起来了的会话，交回 `org_switch`（可重试，不算路由的失败）；别的池上的不碰、已在停的不重复叫停；接着干时换了池 fork 续上、提示词写上一次为什么停、怎么续的进操作记录；不是切号停下的不记这一条。——`sessions.test.ts`。
9. **失败**：额度用满带上游给的清零时刻交失败分流并顺手记账；设备被撤销（`device_revoked`）、封号：整池暂停（写 `pool-hold:<池>` 要人拍，写清哪台机器、哪个会话用户，已暂停的不重复开），下一次跑通就撤；**按进展判停滞**：同一个动作反复做半天没推进（绕圈）停掉、结局 `stalled`；工人重启过接不上：按记下的 scope 收掉旧会话、回 `SESSION_LOST`、库里记结局；卫生检查：给别家（Cursor、Grok 上的副手和验证）的整份提示词**先过卫生检查**，查出名单上的值不发、不起会话（`MATERIAL_BLOCKED`，报错只有位置和规则、没有值），没配卫生检查发不出去（`HYGIENE_UNSCANNED`），名单没读到 `HYGIENE_LIST_MISSING`。——`sessions.test.ts`。
10. **Jev 只在看守活动里问**：规则认不出的失败问一次（带会话、任务、步骤），回答随结局交给工作流、只记不拦的不改路由的账；规则认得出的（设备被撤销）不问；Jev 卡住、抛错当没判出来、结局照常交回；停滞拿不准：问 Jev，只记不拦的「在绕圈」不停会话、同一个会话隔一阵才再问，真拦且有把握才停（规则 LJ）。——同上；`real/jev-port.test.ts`。
11. **临时目录**（每个会话自己的 `_tmp/<会话编号>`，会话的 `TMPDIR`，路径够短：会话里的工具在下面建 unix 套接字超过 107 字节建不了）：插头一收场就删（失败、被叫停、进程没起来都删）；工人重启后看守接不上时收掉旧会话并删它的临时目录；**删不掉：会话结局照常交回，日志里明说没删掉、是哪个目录，不当成删好了**；工人起来时清掉上一轮留下的（这个进程里在跑的不碰），删不掉、列不出来明说没清成、不挡工人接活。——`sessions.test.ts`；`real/worktrees.test.ts`。

## 三、执行方式驱动（`real/hosts.ts` 42KB，86 条测试）：一家一个驱动，收成同一个形状

13. 每种执行方式（Claude Code 经 reclaude、cursor-agent、grok、Mirasim；接上的就是 `WIRED_HOSTS`，别的会话端口明确报 `HOST_NOT_WIRED`、选路不派、探针记 `not_wired`）一个驱动，管三件事：**拼起会话的参数、跑插头、把插头的报告整理成同一个形状（`HostReport`）**；起会话、看守、结局判定、失败分流、记账和路由探针只认这个形状。——`hosts.ts` 头注释。
14. **会话用户怎么定**：池上定了且是现在的会话用户就照池；池上定的不是现在的（已停用的）报缺什么、不瞎挑；Claude 的池没定会话用户报没定（它绑着 reclaude 组织，猜不得）；cursor、grok 的池不绑，用法国唯一的会话用户（不止一个或一个都没有报缺什么）。——`hosts.test.ts`「会话用户怎么定」；design 第十节（法国只留一个会话用户，创始人 2026-09-26）。
15. **cursor-agent**：会话用户自己读家里的 API 密钥再起（不在、是空的、是个目录：不起、明确报，不去试浏览器登录、不空着跑；权限太松 644 不起）；`current` → 最新版本目录现找（CU-03：升级会删掉旧版本目录；不是版本号的名字如 UUID 临时包、`latest` 不认；最新的跑不了跳过用下一个；都不能跑退出 127 stderr 写清没装，失败分流认成执行方式配置不对）；干活的会话放开命令（`--force --trust`），探针不放；没有 fork；报告里 token 照终帧（含缓存读写）、没有花费、没有实际模型、没有上下文大小，读不到的不记成 0；装机脚本找 `cursor-agent` 和引擎起它挑的是同一个（两边对得上有测试）。——`hosts.test.ts`。
16. **grok**：会话用户家里的 `grok` 在不在、能不能跑，在就 `exec` 成它（不在、不能跑、是个目录：退出 127）；会话号我们定（开新会话带 `-s`，半路断了下次 `-r` 续得上；一帧都没有就不给）；干活放开命令（`--always-approve`），探针不放；没有 fork；实际模型取终帧 `modelUsage` 的键；**实际回话的是别的一代（点名 `grok-4.7` 回 `grok-4.6-build`）判模型不符**（带渠道后缀的同一代不算）；没登录（error 帧和 stderr 各一遍、退出 1、没有终帧）：原话进 `rawError` 且只一份。——同上；#266。
17. **Mirasim**（#345）：会话号不是我们起的（先回临时号，server 的 `accepted` 帧才给真号）；**只留「中继额度」这一种路由，`route` 永远是 `cloud`（design 第三节第 12 条、MS-28：不许反代）**；模型串 → 执行体的对应表 `MIRASIM_AGENT_BY_MODEL`：`opus-5.5→claude`、`gpt-5.6-luna→codex`、`kimi-k3→pi`、`deepseek-flash→dsh`，**认不出的明确报错、不落到某个默认执行体上**（新路由忘了改这张表当场炸，不会悄悄派错）；pi（kimi-k3）不带 `model` 只带 `expectModel` 核对回读的快照；服务端 `accepted` 就报 `onSpawn`（没有根进程 pid 记 0，不报的话引擎等满 120 秒判 `SPAWN_TIMEOUT`）；没接这一针不报；起没起来没查成（服务端明确拒）→ `facts.spawnError`（判失败、不算路由的账）；**prompt 发出去了没等到应答（可能已经在跑）→ `facts.launchUnknown`，不当成「没起来」重派（会烧两次额度）**；快照说 done 但没给账本目录：中转到底走没走上游没查成（DL3），不当成交了活也不当成执行体失败；账本读到了但起针之后没有一次 2xx：不算真交了活；账本读不了：不当成零次调用。——同上。
18. **思考档位**（创始人 2026-09-28 傍晚拍：默认 `high`，驾驶舱按模型配是 #470）：没配是 `high`；Claude、Grok、Mirasim 起会话的参数里带；配了不认识的档位报错、插头不起；Grok 不支持 `max`（Claude 认）；方括号模型串里已有档位原样传、没档位补默认；没方括号的 cursor 模型串保持原样、再单独配档位报错；方括号里档位不认识或和路由上另配的对不上：报错、不起。——`hosts.test.ts`「思考档位」。
19. **登录失效的修法各家不同**（写进整池暂停提醒）：Claude 去哪台机器以谁重跑 `reclaude login`；cursor 去后台重新生成密钥、照 ops 放进哪台机器谁家里（服务器上存不下浏览器登录）；grok 在哪台机器以会话用户跑 `grok login --device-code`；Mirasim 用桌面端 SSH 远程连那台机器那个会话用户登一次。——`hosts.test.ts`、`real/route-probe.test.ts`。

## 四、GitHub 端口（`real/github-ports.ts`，53 条测试）

20. **建树只定位置、记下主线的头**（树等起会话时由会话用户自己建）；同一位置留着的旧树先删（删的时候也心跳）；收树：没合并就收→没提交的改动**先存档成补丁**再删，本来就不在的正常返回。——`github-ports.test.ts`。
21. **推分支**：会话用户把新提交打成 bundle 交出来、`github` 包导入再推、临时文件用完删；树的头不是要推的、有没提交的改动、没有新提交、树不在：明确报错不推；**推之前把最新主线并进会话的树**（`--no-ff`，第一个父提交是会话交的头）再推并出来的头；并完推没成、活动重试：头是上一次并出来的就接着推它；并出冲突：**撤掉这次合并**（树回到会话交的头、没有并了一半的状态），报 `MERGE_CONFLICT` 带冲突文件；没跟踪的文件挡着并：撤掉、报 `MERGE_CONFLICT` 带文件名；并的时候 git 自己出错（`.git/index.lock` 被占）：报 `GIT_FAILED`（可重试，不当冲突）；并提交那一串里夹着一个普通提交：不认，`HEAD_MISMATCH`；`BEHIND_MAINLINE`：到引擎这层改成可重试。——同上。
22. **推被拒先认领远端新头再判是良性前进还是被改写**（#307/#389 那次真事）：`DIVERGED` 且远端含着起会话前的头（良性前进）→ 认领、并一次、改用新头重推；`REMOTE_AHEAD`（远端已含着我们要推的头还往前走了）→ 认领远端的新头、不用再推；**`DIVERGED` 且远端不含起会话前的头（历史被改写过）：不试着并，原样报出去、明确写「不含」**；远端分支已不在了（被人删了）：不当成改写、写清「不见了」。——同上。
23. **开 PR**：正文给结构（github 包按 PR 模板 `renderPrBody` 渲染，**不自己拼字**）；照抄需求 issue 的类别标签和里程碑；「按推荐先做了」（#259）照传给正文生成（漏传 PR 正文里那一栏永远是「无」）；**需求文档随这个 PR 才进主线**（#295）：「对应计划」照单子此刻挂的版本写、没挂写「未排期」、不去读主线；照单子版本写却读不到单子（502）、没给单号：不开 PR、明确报错、不当成未排期；需求文档没有「对应计划」那一行（`SPEC_PLAN_MISSING`，不重试）或那一行空着、需求文档还没进主线（读回 null）、读需求文档读不了（403）、`specs` 目录给空串：都明确报错；`specs` 目录末尾没带斜杠补上。——同上。
