# shared：共用的类型、约定和常量（业务说明）

> 一句话：所有包共用的「说法」——领域对象（`domain.ts`，数据库表以它为准）、三份接口约定（驾驶舱网页 ⇄ 后端 `web-api.ts`、fleet 命令 ⇄ 后端 `agent-api.ts`、飞书网关 ⇄ 后端 `feishu-api.ts`）、全局硬禁令（`bans.ts`）、额度窗扣不扣某条路由（`quota.ts`）、用量怎么汇总（`usage.ts`）、实时推送的表名单（`realtime.ts`）、工作流编号的拼法（`workflow-ids.ts`）；用 zod 校验，**两边各写各的会飘，所以只留一份**。
> 出处：`packages/shared/package.json` 说明；`src/` 各文件头注释（10 个文件，101 KB）；`test/usage.test.ts`（22 条）；引用它的包的契约测试。

## 一、干什么、不干什么

- **干**：类型与 zod 校验、常量、纯函数（用量折算、额度窗匹配）。
- **不干**：任何 I/O。工作流代码可以从 `@fleet-dao/shared/workflow-ids` 取编号（**这个文件不引任何东西**，打进工作流沙箱的只有那几行）。

## 二、业务规则（每条标出处）

1. **全局硬禁令写死在代码里、不靠数据库配置**（创始人定的）：GPT 不做界面类的活（包括审界面）、不用 Fable；库里的 `bans` 表清空了也照样生效；驾驶舱改路由顺序、换路由，引擎选路由，目录装载器收配置，都先过这里、再并上库里另加的禁令。——`bans.ts`；`api` 的 `views.test.ts`、`db` 的 `candidates.test.ts`；通用段「我的机器与模型」。
2. **`domain.ts` 是数据库表的准绳**：字段增删要同时改表和迁移；`db` 的 `domain-map.ts` 每个函数必须列出领域对象的每一个字段，少写编译不过；`enums.ts` 的值表和这里的联合类型逐一对齐。——`domain.ts` 头注释；`db.md` 第 1 条。
3. **接口约定三份，两边都按同一份实现**：`web-api.ts`（后端对每个返回都按它 `parse`，多余字段会被剥掉；前端也照它解析；写操作另带 `X-CSRF-Token`，fleet 令牌一律被拒）、`agent-api.ts`（错误码：401 令牌无效过期或会话已结束、重试没用；400 请求不合约定；409 暂时做不了过一会儿再试（`done` 带的 PR 还没同步进库）；422 核实不过要改了再交（原因在 `details.reasons`）；503 同一个幂等键的上一次还在处理、稍后用同一个键重试；出错返回体统一 `{ error: { code, message, details? } }`，`message` 是给 AI 看的白话）、`feishu-api.ts`（每条接口在 `FeishuRoutes` 里标了 `acting`：`required` 代表某位创始人、必须带 `X-Fleet-Acting-Feishu: <open_id>`，后端按 `open_id` 认创始人、不是就 403、操作记录写 `via=feishu`；`none` 只验通行证、带了这个头也不认人；后端按这张表逐条放行、表里没有的一律拒绝）。字段增删两边一起改。——各文件头注释；`api` 的 `cockpit.test.ts`「约定与实现对得上」、`feishu-routes.test.ts`「门」。
4. **额度窗扣不扣某条路由**只有一份判法：读额度的（adapters）、选路由的（db 的候选路由、引擎）都用它，免得两边判法不一样；账号级窗口卡所有模型、`7d_<组>` 只卡该组、有成员表的按成员表。——`quota.ts`；`adapters.md` 第 23 条、`db.md` 第 10 条。
5. **会话用量怎么汇总**（`usage.ts`，#216，22 条测试）：一张单按模型、按阶段、整张合计；**四样 token 折成输入当量：输入 1、缓存写 1.25、缓存读 0.1、输出 5**（design 第十节），四舍五入到整数不带浮点尾巴；**读不到的另记次数（`missing*`），不当成 0**：四样缺一样就折不成（回 `undefined`）、认不出的数（负数、小数、NaN、无穷）当成没读到；缓存只读到一半整次记没读到（读到的那一半也不加）；输入、输出只读到一样整次记没读到；终帧里一样用量都没有：四项都记没读到；花费按计费方式分开加（按量是真花的钱、套餐内是折合价，没读到的各记各的；按量的会话没报花费：那一栏记没读到、不当成花了 $0；渠道查不到、计费方式认不出：记进「分不清」、不猜成套餐内）；只报 token 不报花费的渠道（cursor）：token 和当量照加、花费每次记没读到；进程没起来就结束的会话记 `notStarted`；还在跑的只记 `running`（不进合计、也不算没读到）；时刻认不出或倒着的：时长记没读到；各组的花费分开记账互不串。后端的任务详情、网页的演示数据、会话时间线都调这一份（Fusion 关单评论的「各模型额度」以后也该用它）。——`usage.ts`；`usage.test.ts`。
6. **实时推送的表名单只增不改**：这些表一有写入，数据库就 `NOTIFY fleet_changes`（触发器在 `db` 的迁移里，测试逐表核对），后端 `LISTEN` 再经 SSE 推给页面；**删掉或改名一张表，正在监听它的页面会悄悄收不到变化**。——`realtime.ts`；`db` 的 `notify.test.ts`。
7. **工作流编号的拼法**引擎（起工作流）和驾驶舱后端（发信号）共用这一份：`req:<owner/name>#<issue>`、`sub:<subtaskId>` 等；**拼法进了在途任务的历史，改格式要在引擎里用 `patched()` 并同时改后端，不许两边各拼各的**。——`workflow-ids.ts`；`api` 的 `temporal.test.ts`、`engine` 的 `contract.test.ts`。

## 三、现状（做了 / 没做 / 做坏了）

- **做了**：三份接口约定、领域对象、硬禁令、用量汇总、额度窗匹配、推送名单、工作流编号。
- **做坏了**：`domain.ts`、`web-api.ts` 里含有 Fusion、认领、帅位、多人权限（成员与权限页、代理授权）的对象和接口形状；`feishu-api.ts` 整份看第七节第 4 条；随删除计划一起瘦（具体哪些类型待删除计划落成母单时逐个列，本份未逐个核对类型名）。
- **没做**：三段一条龙的对象（指挥官、工人、Review、副手档案）。
