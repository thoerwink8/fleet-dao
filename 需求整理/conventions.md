# conventions：把规矩写成检查（业务说明）

> 一句话：把「设计文档第七节」「流程只为快」那些规矩变成能自动跑的检查——CI 该跑哪些、合并闸放不放行、开单和关单要带什么、单子自动打标挂版本、欠账、文档指针、版本快照、本机只跑改动相关的测试。
> 出处：`packages/conventions/package.json` 说明；`src/` 各文件头注释；`test/`（21 个文件，约 480 条用例）；`docs/design.md` 第五、七节；#74、#87、#241、#444、#448。

## 一、干什么、不干什么

- **干**（33 个源文件，按用途分七组）：
  1. **CI 按改动跑**：`ci-plan.ts`、`bin/ci-plan.ts`、`bin/ci-verdict.ts`（必过检查 `check` 的汇总）；
  2. **合并闸**：`merge-gate.ts`、`merge-gates.ts`、`gh-api.ts`（在 PR 当前头上写 `merge-gate` 状态）；
  3. **PR 正文栏和补贴**：`pr-fields.ts`、`pr-columns.ts`、`pr-labels.ts`、`pr-links.ts`、`labels.ts`；
  4. **开单和关单**：`issue-new.ts`、`issue-close.ts`、`close-rule.ts`、`close-sweep.ts`；
  5. **单子自动打标挂版本、闲置清理**：`issue-groom.ts`（纯判断，引擎去读写）；
  6. **欠账、文档指针、版本快照**：`debt.ts`、`doc-pointers.ts`、`plan-snapshot.ts`、`plan.ts`、`markdown.ts`；
  7. **本机测试**：`test-changed.ts`（`pnpm test:changed`）、`test-run.ts`（开几个测试进程）。
- **不干**：写 GitHub 的动作除入口脚本外都不在纯判断里；**必过检查里不许读 GitHub**（#87：同一份代码什么时候跑结果都得一样，读单子开没开的放进定时任务、只留言）。
- 判法和高风险清单读的是**跑这段代码的那一份检出**（`merge-gate.yml` 检出主线：PR 改不了自己的门槛）。

## 二、业务规则（每条标出处）

**A. CI 按改动跑（`ci-plan.ts`，46 条测试）**

1. 三态纪律：认不出的路径、读不出的依赖图、空的改动列表、非 PR 事件一律**升成全跑**，不拿「没改什么」冒充可以少跑。——`ci-plan.ts` 头注释；`ci-plan.test.ts`。
2. 依赖图从 `packages/*/package.json` 读；读不出（缺文件、不是 JSON、没有 name、一个包都没有）要说为什么、升全跑。——同上。
3. 改哪里跑哪里：根配置、锁文件、CI 工作流、shared、测试夹具、`deploy/` → 全跑；纯文档 → 只跑每次都跑的 `hygiene`、`docs`；只改没人依赖的包 → 只测它；改 `db` → 它和依赖它的（engine、api、github、jev）都测，engine 单独一台带 Temporal；改 `web` → 打包演示版并跑 deploy；改 `feishu`、`agents-sync` → 要跑 deploy；只改 `docs/ops.md` → deploy 只跑读它的两块。——同上；#88（引擎偶发超时只挡改到引擎的 PR）。
4. 测试不只读自己包里的文件：`PATH_RULES`、`TEST_READS` 是「谁的测试读谁」的清单，`ci-plan.test.ts` 扫所有测试文件里指向包外的路径，**漏记一条就红**。——同上。
5. 汇总 job `check`：该跑的跑了且绿、不该跑的确实跳过；本该跑的被跳过/红了/取消、本该跳过的却跑了、`changes` 没算成、`hygiene` 红了、少了某个 job 的结果、plan 读不出、`needs` 不是对象、plan 说全跑却有 job 没开——**一律不过**。退出码：0 对得上、1 对不上、2 没拿到输入。——`ci-verdict`；测试「汇总」节。
6. `ci.yml` 和这里对得上（有测试盯着）：`check` 是汇总 job、`always()`、`needs` 全部 job；并发组 PR 按号分、推主线按分支分——合过的 PR 改标题正文那一轮不许挤掉主线的全量，主线推送不挤掉在跑的全量，否则一个全绿的提交都没有、自动发布无可发（#362）；不用工作流级 `paths` 过滤（必过检查要永远触发）；已知敏感值名单只给 `hygiene` job，PR 里的代码只当数据扫、不执行（#115）。——`ci-plan.test.ts`「ci.yml 和这里对得上」。
7. 「少跑」等于放行没测过的改动，所以 `ci-plan.ts` 和两个入口都在先审后合清单里；入口顺着相对导入走到的文件必须都在清单里，漏一个 PR 改它就能让测试少跑。——同上。

**B. 合并闸（`merge-gate.ts`、`merge-gates.ts`，36 + 15 + 7 条测试）**

8. 判红只有几样：草稿；和主线冲突；改到先审后合的路径而**当前头上**没有通过的 `second-opinion`；读不到、认不出写 `failure`（没查成）；GitHub 还在算冲突写 `pending`，一直算不出来也不当通过。必填栏（标签、里程碑、对应计划、specs、档位、这个 PR 做完就关单）**只提醒、不挡**（创始人 2026-09-26「流程只为快」）。——`merge-gate.ts` 头注释；#74、#444。
9. #444 起去掉两项：「认领对得上」「写了关单却没带 结果.md」不再挡合并（引擎机器人照样贴「认领对得上」状态，只是合并闸不再等它）。——`merge-gate.test.ts`【故意造出的失败】两条。
10. 合并闸能看的现状被钉死：只有 PR 本身（草稿、冲突、改了哪些文件）和当前头上的提交状态（第二意见）；不看时间（判法里没有 `Date.now`）、不看单子开没开、不看别的仓；多加一个读写口子或多认一个状态名，`merge-gate-inputs.test.ts` 就红——要加，得先改设计文档第五节的规矩再改清单。——创始人 2026-09-27 晚拍（#299），09-28 下午收窄成现在这样（#444）。
11. 第二意见状态被重算：`merge-gate.yml` 放行 `second-opinion` 状态事件，状态一贴上来就把开着的 PR 全重算；主线在这次运行里变了不写回（旧结果不盖新结果）；读不到主线头一条都不写。——`merge-gate.test.ts`；`merge-gate-inputs.test.ts`【故意造出的失败】。
12. 先审后合清单（`packages/conventions/high-risk-paths.json`）：每条有理由、指的路径都在；引擎代码和部署脚本**不在**里面，对公网开口子和提权的生产配置在；迁移里「新迁移只建表、加列、建索引」不算，改删已有迁移、新迁移里删改已有东西、看不到内容都算；清单坏了（不是 JSON、缺字段、路径往外跳……）说为什么、判没查成。——`merge-gates.test.ts`；通用规矩「先审后合只剩两种」。
13. 状态说明放第一条、多的写「另有几条」，不超过 GitHub 的 140 字符。——`merge-gates.test.ts`。

**C. PR 正文的栏和自动补贴（`pr-fields.ts`、`pr-labels.ts`、`pr-links.ts`、`pr-columns.ts`）**

14. PR 必填栏：恰好一个类别标签、挂一个里程碑（版本；旧的 P 阶段仍认）、「对应计划」（版本全名、`#<单号>`、未排期，或 plan.md 某条旧写法）、「specs」（路径或「不适用」）、「档位」（三档之一加理由）、「这个 PR 做完就关单」；每缺一样报一句「缺什么、怎么补」。全部只是提醒。栏名有加粗、不加粗、英文冒号、列表里等多种写法都认，不加粗时只认模板里的栏名。——`pr-fields.test.ts`（35 条）；design 第七节「标签和里程碑不靠人记得贴」。
15. 填了「是」（做完就关单）却没写关单词（#460）：提醒补 `Closes #<需求栏的号>`；「需求」栏取不到号就提醒写通用一句、不瞎编号；填「否」不要求写关单词。——`pr-fields.test.ts`。
16. PR 补贴（#448 替掉 #425「没有就只提醒」）：PR 缺类别标签或里程碑：有对应 issue（先看「需求」栏、再看标题 `(#号)`）就照抄；没有有效对应 issue 就按标题前缀猜类别（`fix`→缺陷、`feat`→需求、其余常见前缀→杂项）并挂当前版本；PR 已有的不动；猜不出类别、算不出当前版本才只提醒；读、写 GitHub 出错一律「没补成」（退出码 2），不当成没事。——`pr-labels.test.ts`（27 条）。
17. PR 挂的单 ＝「需求」栏（没有再看标题）的 #号 + GitHub 合并时会关的关单词，只算同仓的；代码块里举例的不算；「修提醒」栏写提醒的键或编号。驾驶舱据此现算「PR 开着 / 合进主线 / 法国已发布」。——`pr-links.test.ts`、`pr-columns.test.ts`。
18. 类别标签：每张 issue、每个 PR 恰好一个（名字在 `labels.ts`，颜色和说明以 GitHub 上为准）。——design 第七节。

**D. 开单、关单、对账**

19. 开单只走 `pnpm issue:new`：缺类别、缺里程碑、或正文里没有写了字的「## 怎么算做完」就不开；标签和里程碑在同一次 `gh issue create` 里带上（名字对不上就一张也不建）；里程碑＝版本：认全名、`v<N>`、旧 `P<N>` 简写或「未排期」（未排期不挂里程碑）。——`issue-new.test.ts`（43 条）；design 第三节第 35 条；创始人 2026-09-26 拍。
20. `--mother` 多贴「母单」标签；`--parent` 开子单：**先不带里程碑建单 → 挂到母单下面 → 再挂里程碑**（免得中间那一下是一张挂在当前版本上的独立单，被接活派走）；`--local` 多贴「本机做」并当场替帅位认领。任何一步失败都明说停在哪、怎么手动补，不说死「没开」（超时时可能已建）。——同上；#299。
21. `--specs`：完整需求写进 `specs/<号>-<短名>/需求.md`，issue 上只留原话、AI 理解和路径；目录已在不覆盖；`gh` 起不来、单号认不出照实报，不吞。——同上。
22. 关单只走 `pnpm issue:close <号>`：主线上有 `specs/<号>-<短名>/结果.md` 才关成「完成」、评论贴结果链接；没有结果、下面还有开着的子单、是 PR 都拒关（退出码 1）；读不到 GitHub 或主线不关（退出码 2）；关完回读确认。「这张单有没有结果」全仓只在 `close-rule.ts` 判一份。——`issue-close.test.ts`（20 条）；#241、#325。
23. 关单对账（每天）：四种要提醒——`due`（有结果、没有开着的 PR 还引用、下面没子单，却没关）、`mother`（母单的子单都关了）、`merged`（合了的 PR 填了「是」挂的单却还开着，#460）、`no-result`（30 天内关成「完成」却没有结果）；判不了的记没查成、不当成没事；留言不写别的单号（免得那张单多一条「被提到」）。——`close-sweep.test.ts`（20 条）。

**E. 单子自动打标、挂版本、清闲置（`issue-groom.ts`，41 条测试，#448）**

24. 类别只贴不摘：Jev 判出来且把握够才贴；Jev 连不上不贴、记没查成；把握不够不贴、进日报（不是没查成）；**人摘掉过类别标签就不再贴**（看标签时间线上最后一条摘除事件是谁做的）。——`issue-groom.test.ts`。
25. 版本：人（创始人）开的、进门时没归类的挂当前版本；机器人开的（引擎对账、提醒）进未排期、不挂；`issue:new` 开的「未排期」是有意的、不碰；当前版本读不到（没有还开着的 `v<N>` 里程碑）报没查成，不当成「未排期」。——同上。
26. 版本交接：里程碑关了、没做完的单挪到下一个版本（留言写清从哪到哪）；没有下一个版本就不挪、报出来。——同上。
27. 闲置清理（照 Kubernetes 两段）：闲置满 30 天贴「过时」；贴了满 14 天关成「不做了」；贴了「冻结」不动；母单不动；查不出「过时」是什么时候贴的就不硬关。——同上。

**F. 欠账、文档指针、版本快照**

28. 欠账检查（#67）：「以后再做」「先不建」这类推后的话，同一句里要带单号（`specs/<号>-<短名>/` 下的文档本单号也算）；`specs/*/需求.md` 的「怎么算做完」不能空。分两半：**只看文件的**（不读 GitHub，没网照跑；`debt.yml` 在 PR 和主线上跑、**只报告不挡 PR**，创始人 2026-09-26）；**看 GitHub 现状的**（挂的单号还开着吗、开着的 issue 主线上有没有需求文档，只在定时任务里跑、留言到单上、同一条只留一次，绝不接进必过检查，#87）。退出码 0 没欠账 / 1 有欠账 / 2 没查成（一份文档都没读到是 2，不是「0 个问题」）。——`debt.test.ts`（44 条）。
29. 文档指针：`docs/design.md`、`plan.md`、`ops.md`、`README.md`、`specs/` 下文档里指向仓内文件的路径、「第 X 节」、「「X」一节」、plan.md 的阶段和条目都得指得到，指不到报 `文件:行`；`需求.md`、`方案.md` 写在动手之前、指到还没有的不报，`结果.md` 和 design 照报；读不到、列不出目录明确报没查成；**有误报就收窄规则、不往文档里加豁免**。——`doc-pointers.test.ts`（24 条）。
30. 版本快照（#138 `pnpm plan:snapshot`）：从 GitHub 读版本、先后（里程碑说明里 `<!-- fleet:order -->` 标记之间）、母单和子单，重写 `docs/plan.md` 快照标记之间的三节；输出只由读到的数据和快照时间定（同一份数据跑两遍一字不差）；**读不到、先后标记缺了或认不出、两个里程碑同版本号、子单绕圈、plan.md 标记不成对、写不进——一律不写文件、退出码 2**，不拿空快照或旧快照冒充；每条都有故意造出失败的测试。——`plan-snapshot.test.ts`（31 条）；创始人 2026-09-26 晚拍（#169 第 5 件）。

**G. 本机测试**

31. `pnpm test:changed`（#164）：改动 ＝ 和 `origin/main` 分叉以来提交的 + 暂存 + 没暂存 + 没跟踪；选测试和 CI 按改动跑同一套判法，再加 `docs` job 那两份；git 每一步没成都报错、不当成没改动（原来的 `vitest --changed` 在基准读不到时静默只测没提交的，所以不用它）；改到引擎工作流代码跑引擎全部（vitest 顺着 import 找不到 Temporal 按路径打包的工作流）。——`test-changed.test.ts`（35 条）。
32. 要全跑（根配置、锁文件、shared、夹具、deploy）时**本机不跑、退出码 3**，写明原因和改到的包各自单跑的命令；只有 `--all` 才在本机全跑；CI 里（`CI=true`）和引擎起的会话里（有会话标记）照旧全跑；只收 `--all` 一个参数，别的退出 2；vitest 起不来 2、被信号杀掉 1，都不当成通过。——同上；通用规矩「本机推之前只跑改动影响到的测试」。
33. 测试开几个进程（`test-run.ts`，#160）：有内存上限就按上限算 `(上限 − 留给主进程和 Claude Code 的) ÷ 每进程`，至少 1 个；没有上限（本机、CI）照 vitest 默认；**读不到、认不出上限就报错、不猜成「没有上限」**；`VITEST_MAX_WORKERS` 不是正整数报错。——`test-run.test.ts`（19 条）。
34. 测试里起子进程一律走 `child.ts`：卡死的被杀掉、起不来的和被信号杀掉的都抛出说清，不冒充「命令失败」。——`child.test.ts`。

- **做了**：以上全部；每条「读不到、认不出」的路径基本都有故意造出失败的用例。
- **做坏了**（按 `docs/goals.md`）：两块是 AI 自己加的关卡——「关单必须带结果.md」（`close-rule.ts`、`close-sweep.ts`、`issue-close.ts` 的结果检查、每天关单对账，#241、#325、#460）；「认领」那一套在 PR 栏、`--local`、合并闸常量里留了尾巴（`ENGINE_BOT_LOGIN`、`CLAIM_MATCH_CONTEXT`、`prClaimId`）。
