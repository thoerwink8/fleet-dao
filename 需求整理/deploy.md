# deploy：两台机器的装机、发布、备份、隔离（业务说明）

> 一句话：法国（引擎、后端、库、Temporal、AI 会话都在它上面）和香港（对公网的入口 nginx、飞书网关、演示版静态文件、备份仓库）这两台机器**怎么装出来、怎么发新版本、怎么自动发版、怎么备份、AI 会话怎么被关进笼子、线上配置怎么对账**；全是 shell 和一点 node，**幂等**（跑第二遍什么都不变），每一步「先查再做、做完读回」；外加一份**本机档**（`FLEET_PROFILE=local`，同一份装机脚本装到本机的 WSL 里做演练）。
> 出处：`deploy/` 各文件头注释（51 个源文件 602 KB：`france.sh` 84 KB、`release.sh` 80 KB、`hk.sh` 31 KB、`lib/*.sh` 22 份、`france/`、`hk/`、`backup/`、`local/`、`web/health/`）；`deploy/test/` 与 `deploy/backup/test/`（33 个文件、约 1478 条用例）；`docs/ops.md`（运维手册 216 KB，第五节机器地基、第九节自动发布与配置对账）、`docs/reference/deploy.md`（部署与运维手册 P 编号）、`specs/323-*`、`specs/450-*`。
> **和创始人最终目标的关系**：他要「把法国 VPS 换成更好的配置」「本机 WSL 演练环境」「再部署到法国」——**这份目录就是换机的路径**：新机器 = 在新机器上跑 `france.sh`（装）→ 恢复备份（换机恢复）→ 切香港的隧道；本机演练 = `deploy/local/install.sh`（本机档）。

## 一、干什么、不干什么

- **干**：装机（`france.sh`、`hk.sh`、`backup/install.sh`、`local/install.sh`）、发布（`release.sh`：换版、健康检查、自动退回、一键退回）、自动发布（每 5 分钟一轮）、备份与恢复演练、配置对账、会话隔离（用户、scope、资源上限、端口隔离）、各家 AI 的执行方式怎么装怎么查（cursor-agent、grok、Mirasim、reclaude、ddgs）、健康页、飞书网关发到香港、演示版发到香港。
- **不干**：应用本身（`packages/*`）；旧系统的站点和服务（香港上别家的站点和服务**一概不动**，装机前后各拍一次「不归 fleet-dao 管的东西」快照，diff 必须为空）。
- **机器分工**：法国**不开任何入站端口**，主动经 WireGuard 连香港；香港对公网只开白名单端口，nginx 上只加 fleet-dao 这一个站点（`listen` 参数和旧站点一致：不加 `default_server`、不开 `http2`——`http2` 是整个 443 端口共用的开关，开了会连旧网关的握手一起改掉）；驾驶舱接口 `/api`、`/auth`、`/github/webhook`、`/healthz` 由香港经隧道转给法国的后端（`10.99.0.2:8787`），`fleet` 命令接口（`127.0.0.1:8788`）只给本机的 AI 会话。

## 二、业务规则（每条标出处和去留）

### A. 装机脚本的共同规矩（`lib/common.sh`、`lib/snapshot.sh`）

1. **每个动作先查再做，做了记一笔 `changed`；第二遍跑必须一笔都没有**；判红就 `return 1`，调用方开着 `set -e`，`ERR` 陷阱给出结论后停下，不带着坏状态往下装。装机结果分三态：**红**（做错了、读回不对）、**待配**（要人做一件事，如放密钥、登录）、**没查成**（工具缺、读不到）——三态各自有出口，**退出码 0 全绿、1 有红、2 有待配或没查成**；`--check` 只读回不改任何东西。
2. **装机前后各拍一次「不归 fleet-dao 管的单元与监听端口」快照，diff 应为空**（证明旧系统没被碰）；连跑两遍装机、两遍之间各拍一次「fleet-dao 管的东西」（文件指纹、包、单元、库、命名空间），diff 应为空。**快照的判据故意不复用装机脚本自己的比较逻辑：自己查自己查不出错。**——`lib/snapshot.sh`。
3. **`ERR` 陷阱下「没装」不许被当错误**：Mirasim 目录不在（会话用户从没碰过它，最常见的起始状态）曾经被错判成红（`ls` 找不到目录退出 2）——现在是「待配」，测试专门挂上 `ERR` 陷阱再跑一遍钉住。——`mirasim.test.sh`、`mirasim-session.test.sh`。
4. **值一律不进输出**：密钥、令牌、口令、组织编号、邮箱、IP 在装机的所有输出里搜不到（测试逐项造一把假密钥再全输出里搜）；只报路径、属主、权限、字节数、「一致/不一致」。——各 `*-key.sh`、`app-config.sh`、`config.mjs`。
5. **「以 root 执行的文件，文件本身和每一级父目录都必须属 root、且组和其他人不可写」**（审计 P02）：判据读 `systemctl show` 的有效配置（合并了 drop-in，只读单元正文会被 drop-in 里的 `User=root` 骗过）；有效身份是 root 的单元的全部 `Exec*` 命令、参数里的脚本（有执行位、脚本扩展名、或解释器后第一个操作数；还不存在的也算）、`EnvironmentFile`、`WorkingDirectory`；非 root 单元里带 `+`、`!` 前缀的命令照样以 root 跑、同样查。退出码 0 干净、1 有违规、2 没查成。——`lib/root-exec-check.sh`；`root-exec-check.test.sh`（故意造违规样本，同时造几个不该拦的看会不会误报）。

### B. 法国装机（`france.sh`）

6. **装什么**：引擎用户 `fleet`、**唯一的会话专用用户 `fleet-agent-carpool`**（reclaude 一个账户最多挂 4 台设备、一个家目录算一台，本机和另一台机器已占掉，法国只占 1 台；名字是历史沿用，改名得重新登录 reclaude；曾有的 `fleet-agent-dedicated` 已停用、机器上已删，装机脚本不建也不查，测试钉住「重新加回来会红」）、创始人的登录用户 `pilot`、目录、PostgreSQL 16（Ubuntu 自带的源，吃得到自动安全更新）、Temporal 服务端 1.32.0（Postgres 持久化，端口和旧系统错开）、nft 表、AI 会话资源池 `fleet-agents.slice` 与起会话的脚本、`fleet` 用户的 pnpm（corepack）、AI 会话用的 pnpm（归 root，钉版本、核 sha512）、WireGuard 客户端、应用的本机配置与随机密钥、往香港传静态文件的钥匙、把演示版可见范围推到香港的单元、会话用户和 `pilot` 家里各家 AI 的全局说明与方法类技能（`agents-sync`）、他们各自的 `ddgs`、会话用户的 `cursor-agent` / `grok`、`fleet-temporal` 运维命令行、备份（另一个脚本）。
7. **`pilot`（创始人经 Mirasim 桌面端的 ssh 远程模式登进来的用户）该是的样子**：非 root、没有任何 sudo（脚本从不给它写 sudoers）、只在自己的组和 `systemd-journal` 里（看日志）、家目录 750、`~/.local/bin/reclaude` 它自己执行得了并且登录 shell 里找得到（Mirasim 在远端按「登录 shell 跑一遍 env」取 PATH）；**家里不放任何凭据**：登录用的公钥、reclaude 登录都由创始人自己来；`pilot` 不登录 reclaude，读回不查它。`reclaude` 从本地造的「发布」装，sha256 照核，对不上不装、不留半截；登录脚本前台卡住时读回判红（退出码 124、几秒内返回）。——`lib/login-user.sh`；`login-user.test.sh`。
8. **会话用户该是的样子**（`lib/session-user.sh`，故意造错都判红）：没有 sudo、只在自己的组里、家目录的属主和权限对（755 让别人读得到登录态、归 root、读不到属主权限、不在 `/home/<用户>` 下，都判红）、没有 GitHub 凭据；**`~/.ssh` 只许放创始人登录 `pilot` 的钥匙**（`3b` 这一节，#502）：空的、只放那一把（前面带限制选项、有注释行照样认得）绿；多了一把 `pilot` 家里没有的、有一行认不出、会话用户自己有私钥、`authorized_keys` 是 644 或归 root 或是链接、`~/.ssh` 是 755 或是个文件、`pilot` 那份读不到或是空的：都红，不当成「只有认得的那几把」；`reclaude` 没装红（引擎起不了 Claude 会话）、装了没登录是待配、`device.json` 是空的算没登录。
9. **配置文件的读法和 systemd 完全一致**（`lib/app-config.sh`）：`engine.env`、`api.env` 和几个随机密钥文件是单元的 `EnvironmentFile`，「服务里生效的值」按 systemd 的读法算（缩进、`=` 两边空白、引号、转义、注释、CRLF、同一个键写几行取最后一行）；装机脚本补键、填值、读回都用这一种读法。**样例后来加的键：机器上的文件里一次都没出现过（生效的赋值、注释掉的赋值、光写了键都算出现过）才照样例补上，只补缺、已有的一概不动（这些文件之后归人改）；要人定的键（`APP_CONFIG_MUST_SET`，如 `FLEET_ENGINE_PORTS`）不补，缺了读回判红；同一个键写了两行判红并点名键**；`api.env` 的 `FLEET_GITHUB_WEBHOOK_SECRET` 要和 GitHub「引擎」App 设置里的 Webhook secret 一致（空着的那一行照填，带 `+ / = # ;` 的照填、按 systemd 读法读回和 json 里一字不差，权限 640）；**已知敏感值名单**（卫生检查要读的）：只有注释、空行记待配（卫生检查按没读到处理）、谁都能读（644）判红、在、640、有值才过。配置文件的路径不是普通文件（链接、断链、目录）：判红、什么都不改、坏路径背后的东西不动。
10. **会话隔离——`fleet-agent-scope`**（`france/fleet-agent-scope.sh`，`/usr/local/sbin/`，root 755；`/etc/sudoers.d/fleet-dao` 只放行 `fleet` 以 root 跑这一个文件）：引擎经 `sudo -n fleet-agent-scope run <编号> --user <会话用户> [--memory-high/--memory-max/--memory-swap-max/--tasks-max/--cpu-weight] [--cwd …] -- /绝对路径/命令`，把一个会话以会话用户的身份放进 `fleet-agents.slice` 下它自己的 scope（单元名写死 `fleet-agent-<编号>.scope`）；**它以 root 跑，所以只做这一件事**：身份只能是会话用户、slice 写死、参数逐个按白名单验，**环境变量不走命令行**（`sudo` 会把命令行记进日志、`/proc` 里谁都看得到），只收 sudoers `env_keep` 放过来的几类；**引擎重启后按 scope 名找回旧会话再收**（会话脱开引擎跑：#412，发布不打断在跑的会话，创始人 09-28 凌晨拍）；子命令 `adopt`（把工作树交给会话用户：不在就建、在就改属主，相对路径、不在工作树根下、只有一层、路径上有符号链接、`--user` 不是会话用户或是停用的 `fleet-agent-dedicated`、路径里有空格：都退出码 64；**`fs.protected_hardlinks` 读不到或为 0 时拒绝 `chown -R`（不许当成「开着」）**）、`remove`（符号链接不碰目标、本来就不在报 `gone`）、`org-use`（#157：切会话用户挂的 reclaude 组织；**每种没切成的路径都故意造一遍**：`org list` 读不了、认不出、带 `*` 的不是恰好一行、那一类的组织不是恰好一个、`org use` 退出码 1 却切了、退出码 0 却没切、切错了往回切、往回切也没成、切完回读核对不了；输出里搜不到组织编号和邮箱；每一步只给剩下的时间，调用方等 300 秒不会半道被掐）。真机验收 `agent-scope.e2e.sh`：会话在自己的 scope 里、身份对、只在自己的组、提不了权、读不到 `/etc/fleet-dao`、`sudo` 失败、**没有 GitHub 凭据（调用方塞的 `GH_TOKEN`、`GITHUB_TOKEN`、`GIT_CONFIG_*` 都带不进去）**、连得上 `fleet` 命令接口、连不上 Temporal 和库、PATH 是「引擎给的原样在前、会话用户自己写得动的 `~/.local/bin` 接在最后」、内存上限（连 swap 一起封）超了只杀它、进程数到顶 `fork` 失败、引擎被 `SIGKILL`：会话留在自己的 scope、新引擎按名字找回；引擎正常停（`SIGTERM`）：`sudo` 把信号转给会话、不留孤儿。**留。**
11. **端口隔离——`fleet-dao.nft`**（按套接字属主 `skuid` 拦；自己一张表、自己一个单元 `fleet-firewall.service`，**不启用 `nftables.service`**——它默认配置开头是 `flush ruleset`，会把 `ufw` 的规则一起冲掉；前两行让整张表先删后建、在一个事务里换掉、重载没有空窗；载入前 `nft -c` 验过、读回核对内核里的表就是这份文件）：①Temporal、库、驾驶舱后端的固定端口在本机只许 `root` 和 `fleet` 连（Temporal 没开认证、只靠绑本机回环：谁连得上谁就能给任意工作流发信号，会话就能绕过人闸）；②**会话用户在本机回环开的口（它的 `reclaude` 守护开 HTTP 代理，会话的 `HTTPS_PROXY` 指它，代理不认客户端是谁）只许它自己和 `root` 连**（#35，2026-09-27 法国实测 `pilot`、`fleet` 连上去发 `CONNECT` 回 502，即能借用会话用户的订阅额度）。测试在一次性网络命名空间里载入真模板、以三个临时用户（扮会话用户、`fleet`、`pilot`）真连一遍、内核真判：IPv4、IPv6 都挡、别人之间照常通、被挡的连接一个都没到会话用户那头；**强制 syncookie（SYN 洪水下内核就这么做）**下第 2 条认不出应答的是谁，此时靠第 4 条兜住，代价（写在规则注释里）是别人之间连临时口也被复位，固定端口不受影响，且**对照：拿掉第 4 条盲送数据的口子就开了**；规则载上之前就连着的连接规则管不到：装的时候 `ss -K` 断掉、读回判出来，断不掉记红。读回判「通」要读到对面发来的一行，光 `connect` 成功不算（SYN 洪水下握手能过、数据过不去）。**留。**（`lib/session-ports.sh`、`france/fleet-dao.nft`、`session-ports.test.sh` 46 条。）
12. **AI 会话用的 pnpm**（`lib/session-pnpm.sh`，#164 法国复测查出的断链）：会话交活要原样跑过仓的测试命令（`pnpm test:changed`，交活核对只认命令开头就是它，绕成 `corepack pnpm …` 不算），而引擎给会话的 PATH 里原来没有 pnpm；这里装仓根 `package.json` 的 `packageManager` 钉的那一版：从 npm 下 `pnpm-<版本>.tgz`、**核 `france.sh` 顶部钉的 sha512、核包名和版本**，解到目录，入口是一个小脚本（`/usr/local/bin/pnpm`），**都归 root、会话改不动**，入口关掉 node 的编译缓存、用钉的 node 跑包里的入口；不用 corepack 给会话装（它按调用者家目录缓存、第一次用才下，缓存落在会话自己家里、会话写得动）；**核不上就不装、判红返回 1、什么都不装**；第二遍不下载不改；包里的文件被改过、入口被删、钉的校验和换了都认得出来。`france.sh` 钉的 pnpm 版本必须等于仓根 `package.json` 的 `packageManager`（升 pnpm 漏改一处这里就红）。引擎给会话的 PATH 照在跑的引擎进程读（`FLEET_CLI_BIN` 在前、引擎自己的 PATH 接后面、别的环境变量不带出来；没配则按 `main.ts` 的真实路径算 `packages/cli/bin`）。
13. **node 的编译缓存目录由 root 先建好**（`lib/node-cache.sh`）：`/tmp/node-compile-cache` 谁都能写，会话用户（AI）赶在别人前面建出这个目录、替 `fleet`/`pilot`/`root` 的 uid 预先建好子目录、放进编译缓存，对方的 node 就照读——等于以对方的身份跑它放的代码；目录归 root、755 之后非 root 的 node 建不了自己的子目录（编译缓存就不用了：只慢一点不报错）；**用真 node 做对照**：目录归别人时他能把 root 的子目录换成自己的；归 root 时不能。开机时 `/tmp` 清空由 `systemd-tmpfiles` 照 `/etc/tmpfiles.d` 重建。归别人、权限松、里面有别人的东西、是符号链接、是文件都判红，装的时候删了重建。
14. **`ddgs`** （`lib/cli-tools.sh`）：给会话用户和 `pilot` 装、查（技能 `docs-lookup` 首选的搜索命令行）：以他自己的身份 `uv tool install`，装在他家里；`ddgs` 和它的依赖都**钉死版本**（`primp`、`lxml` 带编译好的二进制，不钉就是每次新装拿当时最新的；PyPI 上的包只钉版本、不核校验和）；装和查都按虚拟环境里实际装着的逐个核对（依赖漂了而 `ddgs` 自己版本号没变照样判红、重装整套；命令还在虚拟环境没了判红；两边照同一个写法比，名字大小写、`-` 和 `.` 不算不一样）；**读回不会被 `ddgs` 卡住**（他家里的 `ddgs` 他自己改得动）：后台进程占着输出也几秒返回、前台卡住 10 秒被叫停（124）、不理叫停再过 5 秒被强杀（137）、卡住的都收掉不留他的进程；`uv` 失败只记红、不中断装机；`--no-config`（不读他家里的 uv 配置）、只用系统的 Python；PATH 里他写得动的 `~/.local/bin` 排最后。
15. **别家执行方式的装与查**（各一份 `lib/*.sh` + 测试，每条失败路径都故意造出来）：

### D. 自动发布（`france/auto-release/`，每 5 分钟一轮）

24. **发什么**：主线上比在用的新、CI 全绿的最新一个提交（`fleet-auto-release.timer` 每 5 分钟经 `fleet-auto-release.service` 拉起，以 root 跑）——**主线头的 CI 还在跑或红了，就沿主线往回找最新的全绿提交**（只往前走：不越过在用的、人按住的、发过没成的）；CI 结论**只认这个提交在 `main` 上那次 push 的 `ci.yml`，取最新一次**；**CI 结论读不到（限流、回的不是 JSON、连不上、半小时还查不到这次 CI）：不发、记没查成、下一轮再问，不拿哪一个当绿**；刚合进来 CI 还没开跑：等。
25. **不打架、不死循环**：发布没成：记下、报警一次，同一个提交不再试（不往回挑它前面的再试一个），等主线出比它新的全绿提交；发过、判过不健康的提交（状态文件丢了也认得）不自动再发；**人手动退回过：退回之前合进来的提交（含退回掉的那个）再绿也不自动发，只发那之后合进来的**（不跟人打架）；`--unmerged` 手动发的（合并前在真机上验）：主线出新提交之前不动它；人手动切的才算「按住」（带 `auto` 的不算；主线头比那次新就不按住）；发布历史认不出：拿不准人动没动过手，不发、记没查成；**发之前状态文件写不进去：不发**（发到一半这一轮没了，下一轮连发过什么都不知道）；上一轮的发布没收到结果（那一轮被杀了）：锁还占着就等，空了按在用的是谁定成败。
26. **发之前先排空引擎**：有要发的就马上交给发布脚本、它先排空引擎（不起新会话，在跑的最多再做 10 分钟，到点停下、按编号续上）；不先看有没有会话在跑、不干等空闲；引擎不会排空（退出 76）：等空闲、记下从何时等，**等满 60 分钟照发（带 `--busy-ok`）**；切之前又看到会话在跑（76）、另一个发布在跑（75）：什么都没动、不算没成、不报警。
27. **发完同步规矩**：发完把各家 AI 的规矩同步给会话用户（`agents-sync`，给的人和 `france.sh` 的 `AGENT_RULES_USERS` 一样）；**规矩同步没成：记下、报警，不挡发布**；同一个提交不重跑；检出和在用的对不上就不同步。
28. **每一轮的读数写进状态文件**（`/srv/fleet-dao-releases/.auto/state.json`，后端 `packages/api/src/deploy-lag.ts` 按 `STATE_SCHEMA` 认，**改字段两边一起改**）：后端 `/healthz` 读它现算「跟不跟得上主线」；读数是一行人看的（主线头、落后几个、这一轮干了什么、规矩和装机层到哪）；主线头读不到：记没查成（原因留着、上一次的主线读数不丢）、不发、不同步规矩；库连不上：报警留到下一轮再发，不丢；**装的是副本**：主线上改了 `auto-release/` 要重跑 `france.sh` 才换，后端 `/healthz` 会标「装机脚本落后」（一个测试钉住：「装机层落后的路径」盖住了 `france.sh` 从仓里读的每个文件）。读回（`lib/auto-release-state.sh`）：用 `ranAt` 和 `last`、**不看 systemd 的 `ExecMainExitTimestamp`**（服务正在跑的那几分钟里它是空的，会误报「一轮都没跑过」）；状态文件不在：待配「还一轮都没跑过」不判红；读不了（是个目录）、不是 JSON、格式版本不对、`ranAt` 认不出、载不进来、`node` 起不来：判红写明原因、不当成没跑过。
