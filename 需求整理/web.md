# web：驾驶舱前端（业务说明）

> 一句话：创始人打开的那个网页——看板（仓 → 需求 → 子任务 → PR 的思维导图）、任务详情（时间线、用量、追问）、调度台（每个阶段用哪家 AI 的哪个模型）、渠道与账号、额度、定时任务、通知、操作记录、设置；外加一个**演示版**（同一套代码、假数据、按可见范围收起、可以发链接给别人看）。React Router 纯前端单页模式，读一律经 `FleetApi`（真后端 `http.ts` / 假后端 `mock/`）。
> 出处：`packages/web/package.json` 说明；`src/` 各文件头注释（107 个文件，705 KB；其中 `components/ui/` 26 个是通用小组件、`api/mock/` 三个文件 100KB 是假后端和假数据）；`test/` 与 `*.test.ts(x)`（31 个文件，约 330 条用例）；`docs/design.md` 第十四节、15.x；#29、#54、#129、#199、#216、#259。
> **这块 `docs/goals.md` 第四节 E 写的是「按个人用重做」**：现有页面按多人和 Fusion 设计（帅位栏「特别怪」）。

## 二、业务规则（每条标出处）

**A. 「读不到就照实说」（AGENTS.md 底线，`read-failures.test.tsx`、`review-fixes.test.tsx`、`not-built.test.tsx`）**

1. **读不到的时候必须说「没读成」，不许用空列表、0 冒充「查了没事」**：帅位栏接口失败写没读到；通知中心提醒没读成不说「没有待处理的提醒」；任务清单某个仓没读成点名缺了哪个、全没读到不说「没有符合条件的需求」；总览看板没读成数字写「—」；定时任务没读成不说「还没有定时任务」、失败数写「—」；操作记录、渠道与账号、任务详情的日志和步骤同理；顶栏的铃和侧栏角标没读成显示「!」不显示成 0 条；回答追问、换模型对话框里读不到也照实说；**仓列表没读成不冒充「没有仓」**（设置页、⌘K、顶栏仓切换）；看板重拉失败保留上次的画面并显示「看板刷新没成」；推送断了顶栏照实说「推送断了」、手机上也看得见。——同上。
2. **「待实现」和「没查成」「离线」是两回事**：还没做的功能整块显示「待实现」占位（写明排在哪个阶段、哪张单，和 `/healthz` 的「未接」同一个做法），不许说成「没查成」「离线」（那两个词只留给真去读了、读失败的）；反过来真去读了读失败的只许说「没查成」、不许被占位盖掉。——`components/not-built.tsx`；`not-built.test.tsx`。
3. **额度：用量没读到不当 0%**：只有清零时间或只有已用没上限：用量是「不知道」、不参与高亮和「快用完」；上游新出的窗口（`other`）长度不知道不喊「先用它」；**上游说已用满就是已用满（以上游为准）**；读数过期（后端判的 `stale`）不喊「先用它」（旧数不能当现值）；上游这次没报的窗（`staleSince`）照样显示、注明，不参与比较和报警；按单位写数（token 用万、美元带 `$`、超额照实写）；没读到用量的窗不排进「最满」、不算「快清零」，底下写明有几个没读到；一个池一句话、各页说法一致：有窗上游说已用满整个池说「已用满」、从没读成过的池写「额度没查成」；**只扣一组模型的窗用满了（如只有 fable 组）：同池别的路由不算满，写明是哪一组**（`routeQuotaHeadline`，判法同 `shared` 的 `windowAppliesTo`）；模型在目录里查不到整池一起算（宁可说紧）；每个数都写明来源（估算的标「估算」）；用了九成以上标「快用完」；快清零还剩不少高亮提示先用它、离清零还早不高亮。——`components/quota.tsx`、`lib/route-quota.ts`；`quota.test.tsx`、`route-quota.test.ts`、`review-fixes.test.tsx`。
4. **用量说给人听**（#216，`lib/usage.ts`，数一律出自 `shared` 的 `summarizeUsage`，算法只有一份）：每一项分四种说法——还没有数（没有结束了的会话，这不是没读到）、全读到、读到一部分（照数写、标「不全」、写明另有几次没读到）、全没读到（写「没读到」、**不写 0**）；花费分三种计费方式说：**按量是真花的钱、套餐内是按 API 价折合不另花钱、渠道查不到的「分不清」、不猜成套餐内**；cursor 走订阅不报花费写「套餐内 · 花费没读到」（原来会被说成「没有按量花费」）；时刻倒着（结束早于开工）写「时刻认不出，时长没读到」不写 0 秒；还在跑的只写时长、用量等它结束才有、不算没读到；结束了却没开工标「没起来」不标「排队中」；美元不到一分多写两位、再小写「<$0.0001」，不四舍五入成 $0.00。——`usage.test.ts`（17 条）、`usage-panel.test.tsx`（22 条）。
5. **路由在线状态**（#129，`components/route-health.tsx`、`lib/route-status.ts`）：照探针写进库的结论说：探通了在线（原因写回答和用时）；**探针还没看过写「还没探过」，不说成离线、也不当在线**；探了没通离线标红（原因照探针写的原话）；插头没接、这一轮没探也是离线（派不到）标灰；**结论是 `ok`、`alive` 却是假的：照 `alive` 说离线（派工只看 `alive`），不拿上一次的 `ok` 冒充在线**；离线却没写原因明说「没写原因」；结论超过 45 分钟没更新标过期（探针可能停了）、放慢的执行方式（cursor-agent 探通了隔 2 小时再探）按它自己的线（2 小时 30 分以内不标过期）；一条结论都没有 `lastAt` 是 `undefined`（不拿 0 或现在冒充探过）；渠道页每个渠道数在线几条、离线划掉悬停写原因；换路由对话框里选不了的原因照探针写的说。——同上；`route-status.test.ts`、`route-health.test.tsx`。
6. **定时任务：「查了 0 个问题」和「这次没查成」分开写**：跑成了查到 0 条、跑成了查到几条、只查了一部分（`partial`）写明没查成的原因、**跑了但一个都没扫到是「没查成」不是「没问题」**、失败写明原因、还在跑或从没跑过都不写成「没问题」；期望间隔说成人话。——`lib/schedule.ts`；`schedule.test.ts`。
7. **通知里「谁在处理 · 链接 · 多久了」**（design 15.3）：后端现算、这里照着显示；这一页算不出来（没接上、读不到）时照实写一句、提醒照常列出，**不给每条编一个「没人在修」**。——`alert-handling.test.tsx`。

**B. 看板与任务（`board/*`、`lib/status.ts`、`lib/phases.ts`）**

8. **看板的图**：仓 → 需求 → 子任务 → PR（开了 PR 的子任务外面挂一张 PR 卡）；做完的需求收成一张卡不展开子任务；「只看我提的」按用户编号过滤；状态变了（颜色、文字）排版指纹不变、节点增减才变；**用 ELK 排成思维导图**：仓在中间、右边一棵向右展开左边一棵向左展开、两个需求左右各一、只有一个需求时只排右半边；子任务在它的需求外侧、PR 在它的子任务外侧、卡片互不重叠；ELK 在 Web Worker 里跑（约 1.5 MB，用到时才加载）、没有 Worker 的环境退回同线程；**排不出来（脚本没加载成、Worker 出错、卡死）必须报错，画布据此说「排版没成」，不能一直空着**；失败的那次不进缓存。——`layout.ts`、`model.ts`；`layout.test.ts`。
9. **手机上的看板**是可折叠的树形列表，信息和操作一样不少：默认列出这个仓的全部需求（没做完的按优先级在前、做完的在后）；在跑的需求默认展开子任务；「只看卡住的」只留等人、停滞、失败的；每张卡一句白话（在写码的子任务写明谁在干哪一步）。——`board-tree.tsx`；`board-tree.test.tsx`。
10. **每张卡一句白话状态，颜色只表达状态（七种）**：在写码的子任务后端给「谁在干哪一步」前端补上干了多久；还在排队的会话写「已排」、不写成在干活；停滞的子任务写明卡在哪一步；等前置的写明等哪一个；等人回答的需求是「等你」色；**只有真在干活的需求才有动效**（排队、等人的没有）；「只看卡住的」挑出等人、停滞、失败，不含正常在跑的；「只看我提的」提出人填用户编号或名字都认。——`lib/status.ts`；`status.test.ts`。
11. **一个需求走过的五段**：分诊 → 需求 → 方案 → 执行 → 合并（看板的迷你时间线和任务详情的阶段条共用）。——`lib/phases.ts`。
12. **快捷操作只有一份定义**（悬停条、右键菜单、侧边详情、手机列表、任务详情都从这里取，行为一致）：能做的动作以 `shared/web-api.ts` 的 `TaskActionRequest` 为准——**暂停、继续、叫停、换路由（可指定子任务）、回答追问**。——`components/task-actions.tsx`。
13. **流程配置在看板上的两处**：卡片/详情的小标「全组织默认配置」（只有 `org_default` 渲染，`project` 和空的不渲染，点开是品牌上的那一句、不把外层点击一起触发）、顶栏（读自仓里 / 全组织默认 / 认不出就停派标红写原因，还有上次读成的就补上）；**停派与否只显示后端给的 `paused`/`why`，页面不自己算 45 分钟**。——`flow-source.tsx`；`flow-source.test.tsx`。
14. **AI 问创始人（#259）在驾驶舱里怎么说**（`lib/ask.ts`，和飞书卡片同一套说法）：还没回：写明已按推荐先做、改选会怎样、合进去以后改选开后续单；碰人闸、另开单各有说法；回了：按后端给的 `effect` 说怎么生效；单子结束后：按推荐先做了的合进去以后照样能改，叫停、失败的和老式的不能答。——`ask.test.ts`。
15. **调度台「最近改动」的白话**（`lib/policy.ts`）：挪顺序说清把哪条（模型 + 账号池）从第几挪到第几、两条对调说对调、加去钉住都写出来；**记录里没有前后对比：照实说、不给撤回的依据**；操作记录里认不出的动作原样显示、不猜。——`policy.test.ts`、`lib/audit.ts`。

**C. 与后端的通道（`api/`）**

16. **FleetApi 一个接口两个实现**：方法和 `shared/web-api.ts` 的 `WebRoutes` 一一对应；`http.ts`（真后端：请求体和返回都按 `shared` 校验、**不符合就报 `bad_response_shape` 不将就着用**；写操作带 `X-CSRF-Token`（值从 `/api/me` 来）、读不带；登录前的免登请求不带 CSRF、也不先问 `/api/me`；401 时调 `onUnauthorized` 跳登录页；CSRF 令牌失效后下一次写请求重新拿）和 `mock/`（假后端，开发和测试用）；在 `api/index.ts` 里选：默认连真后端（同源 `/api`、`/auth`，开发时 Vite 代理到 `127.0.0.1:8787`）、`dev:mock` 用假数据；**演示版只用假数据**，判断写成 `import.meta.env.MODE` 构建时就定死，连后端的那份整个打不进演示版的包。——`http.test.ts`（18 条）。
17. **实时推送（SSE）客户端**：连 `/api/events`，收到 `ready` 才算连上；`change` 事件按 `ChangeEventSchema` 解析成「哪张表哪一行」；**看不懂的 `change` 当成 `resync`（全部重拉），不当没发生**；网络断了浏览器自己重连（显示「连接中」、我们不另起连接）；后端回 502 把连接关死：显示「断了」、退避后先探 `/api/me` 再重连；后端一直没起来按 1、2、4 秒……拉长间隔；重连成功收到 `ready` 后退避清零；探 `/api/me` 回 401 跳登录页不再重连；取消订阅关掉连接。——`http.test.ts`。
18. **推送到缓存：按表名决定重拉什么**：需求表变了重拉看板、任务详情、时间线；阶段策略变了只重拉调度台；**认不出的表、断线重连：全部重拉——宁可多拉，不把漏收当没变化**；重拉不打断正在读的（读完再补拉一次）；推送攒一小会儿再作废（窗口内来的多条只作废一次，窗口一到就作废）。——`client.test.ts`。
19. **首屏的读取一轮发完**（`first-screen.test.tsx`）：经香港转到法国的每个请求都要一趟往返（约 0.2 秒），前一个回来才发下一个每多一轮就慢一趟；所以读取和确认登录一起发：看板（回访）登录、仓列表、看板、路由、提醒都在第 1 轮，推送等确认登录后再连，没用到的额度、路由对话框不读；总览（回访）各仓的看板、额度、操作记录也都在第 1 轮；头一回打开（本机没记过仓）看板要等仓列表、第 2 轮，读到的仓记下来下回就是第 1 轮；没登录：页面一直不露出来、推送不连、说要先登录。
20. **假后端**（`api/mock/server.ts` 45KB + `seed.ts` 55KB）：实现 `FleetApi`、数据在内存里、带模拟器让盘面「活」起来（连跑 300 拍不出错、返回照样过校验、盘面真的在往前走）；**每个返回都按 `shared/web-api.ts` 校验后才交出去，报错的 code 和白话也照真后端**（换到犯禁令的路由 422 `route_not_allowed`、结束了的任务 409 `task_finished`、没有在跑的会话 409 `no_active_run`、调度台保存别人先改了 409、设置版本对不上 409）；页面上的操作真的改状态并留操作记录、刷新就回到初始盘面；只推 `shared/realtime.ts` 名单里的表；假数据的用量照各家终帧实际报什么编（Claude Code 补缓存读写和花费；cursor、Grok、中转站只报 token 不报花费；专门有一张单演示「没读到」长什么样）；**名字、账号都是编的**（公开仓里不放真实账号）。——`mock/server.test.ts`（24 条）。

**D. 演示版与品牌（#29、#54，设计文档第十四节）**

21. **品牌**：正式驾驶舱页面上看得见的名字、标签页标题**只写「驾驶舱」，不带仓名、GitHub 账号名和地址**（登录页是公开的）；演示版换一套和正式版不沾边的名字和图标、内部叫法换成通用说法、不给任何外链；代码里统一 `import { brand } from '#brand'`（正式构建按 `package.json` 的 `imports` 解析到 `cockpit.tsx`，演示版构建由 `vite.config.ts` 把 `#brand` 换成 `demo.tsx`——**正式那套名字根本不进演示版的包**，打包后还有一道扫描兜底）；仓库里的 PR、issue：正式驾驶舱给外链、演示版只显示文字；词表用打包扫描那一份（`BUILTIN_TERMS`，`api` 的 `/healthz` 对外的话也拿它扫）。——`brand/*`；`brand/cockpit.test.tsx`、`brand/demo-flow.test.ts`。
22. **构建演示版**（`scripts/demo.ts build`）：构建完**先查第三方许可证声明在不在，再扫一遍产物（声明文件也扫）**：声明缺了、扫出真名、内部叫法、GitHub 地址、源码对照文件，都算失败；发布时额外要拦的词（真域名）经 `FLEET_DEMO_FORBID` 给（只写在服务器配置里不进仓）；演示版搬到别的路径、别的域名时改配置（`FLEET_DEMO_URL`）不改代码。——`scripts/demo.ts`、`src/build/scan.ts`、`src/build/licenses.ts`。

**E. 界面基本功**

27. **状态色当小字用时的对比度闸**（`contrast.test.ts`）：每套主题（8 套）× 深浅 × 七个状态，墨色（`app.css` 的 `--st-*-ink`）在页面上实际出现过的每种底上（卡片、页面底、浮层、侧栏、muted，以及叠在它们上的同色淡底：状态标签 12–14%、时间线「在跑」15%）都要 ≥ 4.5:1（WCAG AA，11px 小字）；扫到 0 套不算通过；故意造一套不够的主题闸要拦下来；颜色算法（oklab 混色、sRGB 叠色、相对亮度）独立写、不读页面算出来的值。
28. **主题** ＝ 主题色 × 深浅 × 动效，存在浏览器本地、切换即时生效；首屏主题脚本与主题解析逻辑一致（`theme.test.ts`）；深浅切换写到根节点上、所有主题色的小样都跟着换。——`lib/theme.ts`；`theme-switch.test.tsx`。
29. 数字与时间的中文说法（`lib/format.ts`，显示时外面套等宽字体 `class="num"`）；路由、模型、账号池、额度窗的白话名只从 `lib/catalog.ts` 拿、各页不各拼各的。
