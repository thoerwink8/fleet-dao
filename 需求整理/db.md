# db：库表、迁移、查询（业务说明）

> 一句话：整个系统的「事实账本」——Postgres 里 44 张表（Drizzle 定义）、23 份迁移（0000–0022）、和引擎、后端、网页共用的读写语句；账本自己用约束把「不许说谎」的规矩钉死（不知道就是空、不是 0；没跑成不许写成「没问题」；结束了必须有结局……）。
> 出处：`packages/db/package.json` 说明；`packages/db/src` 各文件头注释；`packages/db/test/`（28 个文件、约 400 条用例，`constraints.test.ts` 58 条「库自己挡住的错，每条对应一个旧系统踩过的坑」）。

## 一、干什么、不干什么

- **干**：
  1. 表结构（`src/schema/` 8 个文件）与迁移（drizzle-kit 生成 + 手写触发器；生产和测试跑同一批）；
  2. 领域对象转换（`domain-map.ts`：库里的行 → `@fleet-dao/shared` 的对象，少一个字段编译不过）；
  3. 查询与写入语句（`src/queries/` 22 个文件：会话生命周期、追问、报警、人闸、额度、候选路由、看板树、时间线、巡检、对账、定时任务、幂等键、帅位与认领、提醒一件活……）；
  4. 目录装载器（`catalog.ts`：把本机目录配置补进库）和种子（`seed.ts`）；
  5. 测试库（`testing.ts`：PGlite 内存里跑真迁移，生产代码不许引）。
- **不干**：判断。「能不能派、算不算满、要不要切号」的判法在 `@fleet-dao/core` 和引擎里，这里只存事实、把几条语句拼成一个事务、用约束兜底（`queries/canary.ts`、`queries/reconcile.ts` 头注释都写明「判断不在这里」）。
- **不放账号信息**：种子和示例配置里没有邮箱、IP、像密钥的长串（公开仓；`seed-and-domain.test.ts`、`catalog.test.ts` 各有一条盯着）。账号池、路由、成员、额度都在机器本地配置里。

## 二、业务规则（每条标出处）

**A. 表结构和迁移**

1. 表以 `@fleet-dao/shared` 的 `domain.ts` 为准：`domain-map.ts` 每个函数必须列出领域对象每个字段，`enums.ts` 的值表逐一对齐共享的联合类型，多写少写都是编译错误。——`domain-map.ts`、`enums.ts` 头注释。
2. 改了表结构必须带迁移：按当前表结构再生成一次迁移应当零条语句，否则当场红。迁移序号连续、时间戳严格递增、和 SQL 文件一一对应；触发器迁移可以单独重跑、不装出重复触发器。——`schema-drift.test.ts`、`migrations.test.ts`（30 条）。
3. 升级已有库不许悄悄改行为：已有的仓一律是「接活关着」（0005）、「流程配置还没同步过」（0011，派活前按停派算）、阶段路由的开关回填成开着（0003）、升级前的会话缓存读写是空不是 0（0013）。——`migrations.test.ts` 各节。
4. 连接串只读 `DATABASE_URL`，没有默认值；没设就报错，不回落到任何默认库。——`client.ts`、`migrations.test.ts`。

**B. 路由、账号池、额度（调度台的事实）**

5. 一条路由 ＝（渠道 + 账号池 + 模型 + 执行方式）；池必须属于路由写的渠道；同池同模型同执行方式不许重复；并发上限必须是正数（没有「不限」）。——`constraints.test.ts`「路由与账号池」。
6. 路由在线（`routes.alive`）只由探针和熔断写：只有探针结论 ok 才能在线，不是 ok 一律不在线并写原因；结论和时刻同空同有；新路由没探过就不在线；Claude 订阅池的结论连「那时挂的组织」（拼车、独享）一起写，认不出的值库里拒绝。——`probe.ts`、0010、0019、`route-probe.test.ts`；#129、#335。
7. 会话用户只有一个：法国只留 `fleet-agent-carpool`，池另存组织类型（拼车、独享）；写别的、写已停用的名字都报错并说清改成什么。——0007；创始人 2026-09-26；`catalog.test.ts`。
8. 额度窗：按上游原名一行（同类可有多个，原名重复不行）；`7d_model` 必须写组名；池的成员表每项是 `{in:[…]}` 或 `{notIn:[…]}`；写入唯一入口 `savePoolQuota`，一个池一次读数整批一个事务，写到一半被拒就整批回滚。——`quota.ts`、`constraints.test.ts`、`quota.test.ts`（36 条）。
9. 读数怎么当真：超过 30 分钟不当现值，是「没查成」不是「还够」；上游说满了就是满，哪怕数字才 99%；已知清零时刻的「满」在清零前一直算满、过了清零时刻旧读数作废；晚到的旧读数整批不生效；读失败什么都不动；没读全只写收到的、不标别的过期；上游这次没报的窗口标过期、满 24 小时才删；超额是真实情况（利用率可以大于 1，剩余按 0）；全程用传进来的时钟，不看墙钟；读数时刻比现在还晚的按现在算。——`quota.test.ts`；#76、#49。
10. 候选路由：某阶段没配顺序就候选为空并写明，不拿全部路由凑数；被挡的路由不删、带原因留着（渠道关了、订阅过期、禁令、模型组窗口满了、池成员表不含它、Cursor 两个桶）；代码里的硬禁令（GPT 不做界面、不用 Fable）库里没有也生效；额度没读成不挡、但排在读到了的后面并标 `unknown`；并发按账号池算，不属于任何需求的会话也占名额。——`candidates.ts`、`candidates.test.ts`（18 条）；通用段「我的机器与模型」。
11. 目录装载器只补缺、跑几遍一样：库里没有的行插进去，已有的只填空着的字段，驾驶舱或人改过的一概不动，不一样的列进 `kept` 给人看；阶段顺序每阶段只排一次（`stage_policies.catalog_applied_at`）；配置缺失、格式错、引用不存在都退出 1、库里一行不写；撞约束、撞硬禁令、写到一半失败整批回滚；发布脚本只认退出码。——`catalog.ts`、`catalog-cli.test.ts`、`catalog.test.ts`（28 条）；`docs/ops.md` 第九节「目录配置」。

**C. 干活记录**

12. 会话（`session_runs`）：排队时长和干活时长分开、由库算、不许手写；结束了必须有结局、有结局必须已结束；开工不早于排队；token 和花费不知道就是空，不记成 0；缓存读写不能是负数；「请求的模型」和「上游实际用的模型」分开记；子任务必须属于会话写的那个需求；帅位、考新模型的会话可以不属于任何需求。——`constraints.test.ts`「会话记录」。
13. 会话生命周期都幂等、不倒退：起会话按 id 幂等；叫停请求可以先于会话行插入、起会话后原样带出；开工不倒退 `started_at`；结束的不改（第二次回 `already_finished`）；`ended_at` 早于开工时拉齐；失败的原话读得回来（续会话时写进提示词）、超长截到 2000 字；「不知道的用量」是 null。——`engine.ts`、`engine-runs.test.ts`（33 条）。
14. 状态变化由库自己记（触发器）：新建记一行、改状态记一行、改别的不记；删需求时它的状态历史一起删。——0001、`constraints.test.ts`。
15. 追问（#259）：同一会话问一模一样的一句只有一条（`run_id + md5(question)`），一问最长 2000 字；带范围的提问必须带推荐、推荐必须在选项里；范围只认 `task / outside / hold`，`hold` 的原因只认 发布、花钱、删数据、改标准；回答、谁答、何时答要么都有要么都没有；「带了范围的提问」不算会话在等人——否则真停滞会被当成「在等人」放过。——0014、`asks.test.ts`、`engine-asks.test.ts`。
16. 人闸批准：开批准按 id 幂等并同时开一条待批的报警；已决定的不改；不存在回 `not_found`。——`engine-asks.test.ts`。
17. 进度事件：一批写进去；带输出序号时「事件进库」和「确认到哪一行」同事务、只往前推；事件写不进去确认也不推——接回会话时这些行照常重来，不会漏；plan 载荷必须是 `{steps:[…]}`。——0021、`engine-asks.test.ts`。
18. 子任务：只能依赖同一需求里的、不能依赖自己或不存在的；同需求里序号不重复；重拆方案时旧子任务标作废、新的可以复用同一序号。——`constraints.test.ts`、`engine-routing.test.ts`。
19. 执行计时（`step_timings`）：活动、等待各写一条；活动重试重写同一笔返回 `duplicate` 不报错。——0004；#216。
20. PR 镜像：每个仓每个编号一行，CI 汇总默认「没有」。——`constraints.test.ts`。
21. 时间线和看板全从 Postgres 读、不靠 Temporal 历史（只留 30 天）：31 天前做完的需求每一步也读得到；同一时刻按 `(at, id)` 排、顺序确定；「进入当前状态多久」从状态变化算、不从开单算。——`timeline.ts`、`board.ts`。
22. `fleet history`：按关键词（标题、摘要、结果）和改动位置（子任务改过的路径）翻做过的需求；`%`、`_` 按字面；条数限制 1–20；空查询不返回东西。——`history.ts`。

**D. 提醒、通知、定时任务、幂等（「不许说谎」的一层）**

23. 通知同一件事（去重键相同）只有一条；没拿到飞书 `message_id` 不许记成已送到。——`constraints.test.ts`。
24. 报警：同一件事一条，再报原地更新，已处理的重新打开；处理掉必须写为什么（正文开头「已撤：为什么」，同事务记操作记录）；处理人和做事的分开记；只改开着的、不替人把处理掉的又打开；前缀逐字比、空前缀明确拒（那等于全表）、`%` `_` 不当通配符；列不全照实回 `truncated`。——`alerts.ts`、`alerts.test.ts`、`engine-asks.test.ts`。
25. 提醒是一件活（`alert_work`）：只记「没挂任务」或「挂了别的单」的；「谁在处理」不另记、读时现算；静默（`alert_silences`）到期按库的 `now()` 定、最长 7 天由约束钉死、撤了记谁撤的、为什么。原来「提醒派单」和「帅位换单」两条写路 2026-09-28 已删（#445），表和历史行留着给驾驶舱读。——`alert-work.ts`、`alert-work.test.ts`。
26. 定时任务以**登记**为准、不以跑过的记录为准：从没跑过的也列出来标 `never`；`ok` 必须真扫到东西、一个都没扫到只能记 `unscanned`（健康度 `no-samples`）、不是 `ok` 的都写原因；上次成功太久是 `stale`；刚登记还没轮到第一次的算新鲜，超过期望间隔还没跑过的不新鲜；重复登记只更新计划、不丢运行记录；收尾不存在的记录要报错。——`schedule.ts`、`ops.test.ts`；#203。
27. 外部写操作（GitHub 评论、开 PR、关单……）防重复：写之前占键、写成了记回执、重放拿回执；确认没写成才放键；写成了的键放不掉、也不能完成两次。放在库里、不放本机文件：换机器、重启、恢复备份后都认得出。——`idempotency.ts`、`ops.test.ts`。
28. 操作记录：失败的操作必须写错误；「谁做的」统一记 `actor_kind + actor_id`；引擎做的事（切号、核对……）成不成都进记录，没成的必须写为什么。——`ops.ts`、`session-org.test.ts`。
29. 设置：第一次写入版本是 1、版本不能是 0 或负数。成员：飞书身份和 GitHub 数字编号各自唯一，机器人可以没有飞书身份。——`constraints.test.ts`。
30. Jev 记录：模型版本钉死、不许用 `latest`；单选题至少两个选项、是非题不带选项；新题默认只记不拦；没判出来（超时、连不上）要写原因且没有答案、不能当成「否」；准确率只从有真值的算，没判出来、把握不够、判了没真值、判对、判错分开数。——`jev.ts`、`jev.test.ts`；#40、#61。
31. 全流程巡检（`canary_runs`，#223）：一轮一行；有结论就不再改；断了、没跑成必须写为什么（库约束：不许「没通过也不知道为什么」）；健康页读最近一轮**有结论**的（没跑成也算一轮，不跳过它去拿上一次通过的）；没收尾的一轮补记成「没跑成」并写原因；读不到照抛，不拿空顶。——`canary.ts`、0016、`canary.test.ts`。
32. 每小时对账要的事实：没结束的单（含排队，终态不列）、这张 issue 最近一次接活处理过的投递、合了的 PR 和它对上的单的记账；受管的仓按 `repos` 表列，不另写一份。——`reconcile.ts`、`reconcile.test.ts`。
33. 接活入口（0005，#43）：收到的 GitHub 事件原文一次投递一行（去重、重放都靠它）、每次投递带的对象版本另记；事件表不收没原因的「不收」「出错」、处理中不许有收尾时刻；仓上的自动派活开关默认关。——`schema/ops.ts`。
34. 流程配置副本（`repos.flow_*`，0003 号决定第 9 条）：只由引擎对账写、接活和起会话读；配置、同步时刻、提交、来源四样要么都有要么都没有；来源只认 `project / org_default`；认不出只记原因（停派）、其余不动；没查成什么都不动只记这次的原因和时刻；仓不在回 `not_found`；测试命令只认副本里的（从没同步过就没有，不拿旧的 `test_command` 列顶）；会话行记下「起会话时被交代的测试命令」、已开工的不改。——`flow.ts`、0011、0015、`flow-replica.test.ts`。
35. 开 PR 前别家验证（`verify_rounds`，0012）：只统计这张单上真起过的、会写东西的会话用过哪几族（审查、验证、没起来的不算）；一个会话都没有回空数组、由调用方明确报错，不当成谁都能验；作废的一轮写原因、没有结论；验证交回后写一次、Lead 驳回后再写一次，同一行。——`verify.ts`、`verify.test.ts`。
36. 实时推送：触发器装在哪些表、报什么，都照 `@fleet-dao/shared` 的 `REALTIME_TABLES` 核对；载荷只有表名和 id；额度窗按池通知（池本身改了也报，上游一个窗口都没报时额度页也能刷新）；名单外的表写入不发；名单上每张表都真发过。——`notify.test.ts`。
37. 会话用户切号要的事实（#157、#59）：带组织类型的池各自的额度窗口（和选路同一判法，只算管得着在用路由的窗口）、这些池上还没结束的会话；读数旧了状态是 `stale`（选路算「不知道」）但「到顶了」照实给。——`session-org.ts`。
38. 帅位租约和认领（#299，0017、0022）：接班是一条语句、任期只增不减（任期号就是栅栏号）；带旧任期号续约不续；心跳、续约、过期一律用库的 `now()`；认领每张单一行、一条语句抢、只有一边拿到；结束的认领下一次整行换新号；引擎的认领跟着任务走（写快照的同一事务里）；约束：待起只有引擎有、引擎要工作流编号且不带机器、本机要机器和工人名、作废放下要写原因；`scope` 只认 `main` 和 `drill:*`。——`seat.ts`、`seat.test.ts`（20 条）。
39. 飞书四张表（0006）：随手记草稿、关注、推送的送达状态（outbox）、卡片登记；取值用文字加检查约束、不用 pg 枚举（卡片种类以后还会加）；收到的话和卡上「改一下」的幂等放 `idempotency_keys`。——`schema/feishu.ts`。
40. 账密登录（0008、0009）：用户名大小写不敏感唯一、有密码必须有用户名、失败次数不能负、有锁定到期；`session_version` 用来让旧登录失效。——#120。

## 四、现状（做了 / 没做 / 做坏了）

- **做了**：以上全部；每条「读不到、认不出」的路径基本都有【故意造出的失败】用例（`constraints.test.ts` 58 条、`seat.test.ts`、`catalog.test.ts` 等）；表结构和迁移不一致当场红；实时通知按表核对。
