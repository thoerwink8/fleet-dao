# api：驾驶舱后端（业务说明）

> 一句话：法国机器上的一个 Hono 后端，对外三件事——给驾驶舱网页读写（登录、看板、任务、调度台、额度、通知、设置、实时推送、发信号给工作流）、给 AI 会话里的 `fleet` 命令读写（进度、提问、交活、翻历史）、接 GitHub 的事件（验签、落库、白名单、变成任务）；外加一份 `/healthz`「哪一层断了」的体检，和运维用的 `fleet-api` 命令（设密码、开关接活、交给引擎、帅位与认领、提醒静默）。
> 出处：`packages/api/package.json` 说明；`src/` 各文件头注释（55 个文件，`pg-store.ts` 78KB、`memory-store.ts` 62KB、`ports.ts` 58KB 最大）；`test/`（56 个文件、约 1200 条用例；`store-contract*.ts` 是两个 Store 共用的契约）；`docs/design.md` 第十四节；`docs/ops.md` 第九节。

## 一、干什么、不干什么

- **两个监听、分开**（`app.ts`、`listen.ts`）：**cockpit**（驾驶舱接口 `/api`（含飞书网关的 `/api/feishu/*`）、登录 `/auth`、GitHub 事件 `/github/webhook`；生产上听 WireGuard 隧道地址，香港 nginx 经加密通道转进来）和 **agent**（`fleet` 命令接口 `/agent/v1`，只听本机回环、AI 会话在同一台机器上调，外面够不着）。两边各管各的：驾驶舱应用上没有 `/agent`、agent 应用上没有 `/api`。——`agent.test.ts`「令牌越权」。
- **读一律从库里读**（不直接查 GitHub）；**每个写操作都留操作记录**；判断在 `@fleet-dao/core`，库语句在 `@fleet-dao/db`，读写 GitHub 在 `@fleet-dao/github`，这里是外壳（`views.ts`、`cockpit.ts`、`agent.ts` 拼装和放行）。
- **Store 两份实现**（`pg-store.ts` 真库、`memory-store.ts` 内存参照实现），过**同一套契约测试**（`test/store-contract*.ts`）；语义改动两边一起改。
- 不干：跑 AI 会话、推分支、开 PR（那是引擎）；不存密钥值（配置只从环境变量来，缺了或不合规**拒绝启动并一次列出全部问题**，`config.test.ts`）。

## 二、业务规则（每条标出处）

**A. 登录与会话（`auth.ts`、`session.ts`、`credentials.ts`、`password.ts`、`login-throttle.ts`、`tokens.ts`）**

1. **只放行 `users` 表白名单里的人**（创始人）：不在白名单的飞书账号 403、不发 Cookie、操作记录留一条被拒；已登录的人被改成协作者，下一个请求就 403（**每个请求都回库查一次用户**）；协作者、机器人、停用的账号进不了驾驶舱，但协作者开的单、写的评论照样算 GitHub 白名单作者。——`auth.test.ts`；`whitelist.ts`。
2. 登录方式：飞书浏览器登录（授权码 + PKCE，v2 令牌端点 JSON 请求体，state 和暂存 Cookie 对不上拒绝且不去换令牌，暂存 Cookie 10 分钟过期、成功失败都删）、飞书客户端内免登（`requestAccess`，不带回调地址和 verifier）、**账密登录（#120）**、开发环境免登（`POST /auth/dev-login`，只许本机回环监听，生产环境拒绝启动，驾驶舱接口监听非回环地址也拒绝启动）。会话 = 自签 HttpOnly Cookie（带过期）+ 按会话派生的 CSRF 令牌，写操作必带；登录后跳回地址只许站内路径；**先记后做**——登录记录、退出记录写不进就不种 Cookie、不清 Cookie。——`auth.test.ts`、`password-login.test.ts`。
3. **账密登录**（#120）：`crypto.scrypt`，参数 N=2^15、r=8、p=3（OWASP 等强度组合之一，每次算 32 MiB、同时最多 4 个）、存 `scrypt$N$r$p$盐$哈希`（参数跟着哈希走，以后调参数旧哈希照样验）；新密码至少 10 位、不超 256 字节；**密码错、没这个人、没设过密码、不在白名单一律 401 `bad_credentials` 且答复一模一样**；连错 5 次锁 15 分钟（按用户名和按来源各计，库里没有的用户名也计数上锁，来源取香港 nginx 写的 `X-Real-IP`，键 HMAC 过、内存日志里不出现明文来源和没登成的用户名，键满了也不扔正锁着的）；登上一次清零；哈希格式认不出抛 `PasswordHashFormatError`（500 `password_hash_unreadable`，**不当成「密码错」**）；白名单里的人却读不到登录信息 500 `credentials_missing`、不记输错。——`password-login.test.ts`（39 条）。
4. **设置页**（`credentials.ts`）：看、设、改自己的账密；已设过的改用户名或密码都要带当前密码（输错计入同一个锁）；还没设过的必须是 **10 分钟内飞书登录**的会话才能设（偷到旧 Cookie 的人不能顺手配密码）；用户名大小写不敏感唯一（`username_taken`）；操作记录里没有密码和哈希；**会话作废**：改密码后别处的旧 Cookie 401 `session_revoked`、改密码的这一处换新 Cookie，退出后退出前的 Cookie 全作废，服务器上 `set-password` 重设也作废，只改用户名不作废；#120 之前发的会话（没带版本）在版本还是 0 时照常能用。——同上。
5. **fleet 令牌**（`agent-token.ts`）：引擎开会话时签发，**只对一个任务的一次会话有效、带过期**（寿命超上限、签发时间在未来、换密钥、改内容都不认）；驾驶舱接口一律不认它（哪怕同时带着有效登录 Cookie），登录 Cookie 也不能拿去调 fleet 接口；用登录密钥签的、别的会话的、会话结束后的都 401；所有签名走同一套 HMAC-SHA256，`purpose` 做域隔离（同一把密钥签出的不同用途的东西不能互相冒充）；两把密钥必须不同、够长。——`agent.test.ts`、`config.test.ts`。
6. **飞书网关通行证**：网关（香港）代创始人操作时认 `open_id`（不要 CSRF，操作记录 `via=feishu` 记在这位创始人名下）；**网关对需求只能叫停**（暂停、继续、换路由一律 403）；只放行约定里的接口（查任务、叫停、回答追问、以及 9 条飞书接口），别的一律 403；通行证不对、没配 401 且不退回去认 Cookie；通行证不进日志、响应、操作记录；不给连 SSE（推送走长轮询）。——`gateway.test.ts`。

**B. fleet 命令（`agent.ts`，`/agent/v1` 七个动作，`agent.test.ts` 42 条）**

7. 七个动作：`task`（看自己的需求、做完标准、要改哪里、当前步骤）、`plan`（整张替换进度清单；同时两步在进行 400）、`say`、`ask`、`done`、`blocked`、`history`（按关键词翻本仓做过的需求）。**每条命令先写库、再叫醒工作流**（库是准，信号只是叫醒）；**只有 `ask` / `done` / `blocked` 才发信号**，`say` / `plan` 不发；信号发给**会话所属的工作流**（子任务会话直接拼 `sub:<subtaskId>`，需求自己的会话查库拼 `req:owner/name#issueNumber`；查不到明确抛 `WorkflowTargetNotFoundError`、不瞎拼）；叫醒失败不挡命令但留日志。——`agent.ts` 头注释；`temporal.test.ts`。
8. **幂等键**（插头重试同一条命令用同一个键）：重试直接回第一次的结果（只记一条、`blocked`/`done` 只叫醒一次）；没带键照常执行（老插头）；被退回（422）不占键；同一个键的上一次还在处理 503 + `Retry-After`；占着没做完的键是本进程启动前占的（发版重启）或占了超过 60 秒：重试接过来执行并留日志（接管后旧请求的凭据放不掉、也记不上）；同一个键用在别的命令上 409（不回上一条命令的结果）；键太长 400。——`agent.test.ts`；`store-contract.ts`「命令的幂等键」。
9. **`fleet ask`：问他不挡路（#259）**：这张单范围内的岔路当场回「已按推荐先做」、不等回答（推荐的排第一个落库；同一句再问复用同一条、只叫醒一次）；超出这张单范围回 `outside`（另开单等他拍、这张单绕开，不给工作流加人闸）；**碰了人闸：先按推荐做、给这张单的工作流加人闸（合并前等批）**；碰了人闸而引擎连不上：问题记下了但明说人闸没加上（503），不回「合并前等批」装作拦住了，重试加上；没带选项、没带推荐、推荐不在选项里、选项太多、人闸认不出、既超范围又碰人闸：400 `ask_incomplete`、一条都不记；答过了的（驾驶舱、飞书、issue 回的都算）再问同一句直接回答案。——同上。
10. **`fleet done` 要核实，不是说了就算**（`done-check.ts`，12 条）：会话只在本地提交、推分支开 PR 由引擎在会话结束后做，所以交活能核实的证据是**会话自己跑的测试**（插头从过程记录读出来记进库）；**测试只认起会话时交代的那条命令**（`session_runs.test_command`，`fleet-dao` 是 `pnpm test:changed`），认开工时记下的、不认此刻仓里的；跑的是 `pnpm check`、vitest 单跑几个包这类插头都不记 → 退回并写明要原样跑哪一条；**以最后一次为准，认不出结果的（接了管道、放了后台）那一次也算最后一次**，前面的「通过」顶不上；自己报测试没过直接退回；写码会话开工时没记下测试命令（加这一列之前开的会话）退回、不拿仓此刻的命令顶；写需求文档、调研这类活不要求测试证据；带了 PR 编号：库里还没有 409（过会儿再交）、不是本会话分支或已关退回；**PR 上的 CI 是上一次推送的结果，不拿来判这次会话**；能判定的问题一次全列出来；退回落库（操作记录 + 时间线），不只打日志。——`done-check.test.ts`；`specs/164-会话内存与交活测试/`。

**C. 驾驶舱接口（`cockpit.ts`、`views.ts`，`cockpit.test.ts` 38 条 + `views.test.ts` 24 条）**

11. 约定与实现对得上：`WebRoutes`（`shared/web-api.ts`）里每个接口后端都有；每个读接口的返回符合 shared 的形状；**库里多出来的字段不会漏给前端**（仓的测试命令、用户的飞书编号）；库返回缺字段当场 500、不把坏数据交给前端；翻页游标看不懂 400 `invalid_cursor`（**不回空页**，空页会被当成「后面没有了」）。——`cockpit.test.ts`。
12. 看板与任务：卡片上一句白话状态、步骤进度、「此刻」面板；任务详情带全部会话（含已结束）、追问（#259：范围、推荐、人闸、后续单；「回答之后会怎样」）、**用量汇总（按模型、按阶段、整张合计；没读到的花费记次数、不当 0；按量计费与套餐内分清，渠道查不到、路由查不到时计费方式留空并记进「分不清」，不猜成套餐内）**；时间线倒序翻页不重不漏；看板顶栏的流程配置副本：刚同步的全组织默认不停派、认不出/超过 45 分钟没同步成/从没同步过：停派并写原因；任务卡片、详情、看板都带 `flowSource`（用了全组织默认的要标出来，#276）。——同上。
13. **发给工作流的信号**（暂停、继续、叫停、换路由、回答追问）：**先记后做**（发起那条在前，没做成再追加一条 `ok=false`）；操作记录写不进信号不发；换路由只许换到在线、不犯禁令的路由；任务已结束、工作流不在了 409；回答追问：写库、发 `answer` 信号、留记录，第二次回答 409，追问指向的任务不在库里回答照常成功但拼不出工作流编号、叫醒失败留日志（不瞎拼、不装成功）；回答追问的驾驶舱接口和飞书回复追问卡走同一条路（`answer-ask.ts`）。——`cockpit.test.ts`；`answer-ask.ts`。
14. **调度台**：每个阶段类型都有一行（没配过的是空列表）；改路由顺序**先比较后改**（改之前被别人改过 409、不悄悄盖掉），同一事务写操作记录（改前、改后、理由），操作记录写不进顺序也不改；拖动排序后关着的仍关着、新挂进来的开着；**硬禁令写死在代码里**（`shared/bans.ts`：GPT 按族认、不做 UI，Fable 哪个阶段都不用）——库里的 `bans` 表空了照样拦、判路由时连上游串和别名一起看（模型叫 `opus`、上游发的是 Fable 或 GPT 照样拦）；库里另配的禁令和硬禁令一起生效；已下架、目录里没有的模型、不存在或重复的路由、不存在的阶段都不许挂；下架渠道写操作记录、不存在的渠道 404。——`cockpit.test.ts`、`views.test.ts`。
15. **额度表、定时任务、通知、设置**：额度过期的读数标出来、一条都没读到的标「没查成」、上游数冻住没前进也算过期（看 `dataAt`）、超额原样给、还没做的读取器标「待实现」；路由表带探针结论（离线带原因、没探过的不说成离线）；定时任务按期成功 / 超期 / 从没成功分开（`expectEveryMinutes` 已含余量、不再加倍，partial 也算跑成）；通知没拿到消息编号算没送到、处理掉后不在「未处理」里；设置只收表里有的键、值合规、版本对不上 409、改了留记录。——同上。
16. **实时推送 SSE**（`sse.ts`、`changes.ts`）：整个进程只占**一条** `LISTEN fleet_changes` 连接分发给所有订阅者；先发 `ready`，库一变推 `change`（表名 + 主键），断过线推 `resync`；每条带 id（`本进程轮次.序号`），浏览器重连带 `Last-Event-ID` 补发断开期间的事件，**补不全（后端重启过、挤出缓冲、id 看不懂）先发一条 `resync` 让前端全量重拉**；没登录不给连；LISTEN 连接悄悄断了（查询照常）由自发 ping 收不回来发现并报红，重连后 `resync`，一轮恢复只发一个 `resync`；探活重发有上限；一个订阅者抛错不影响别人。——`sse.test.ts`、`changes.test.ts`（18 条）。

**D. 接活：GitHub 事件 → 任务 → 工作流（`github.ts`、`issue-intake.ts`、`whitelist.ts`、`reconcile.ts`）**

17. **验签**（`X-Hub-Signature-256`）：**按收到的原始字节算**（香港只转发不验签、原样透传请求体和头，被重新序列化过就验不过）；不对、缺签名、别的密钥签的：401 留日志、**不落库**（没认证的请求不许往库里写）、不交给引擎；没配密钥 503（不会无签名放行）；缺投递编号或事件名 400、签名对但请求体不是 JSON 400、认得的事件形状认不出：不收、原因记进库并告警。——`github.test.ts`。
18. **原文落库、去重、白名单**：放进来的、不收的都记一行（原文、事件、仓、结局和原因，处理完的带上做了什么）；同一个投递编号只处理一次；交给后面处理失败 500、这条记成出错（原因、原文都在），GitHub 重投时照样能进来、次数加一；**白名单是唯一的门**（design 删了「进门标签」，公开仓里陌生人也能开单评论，所以在代码里强制、不靠互动限制）：有数字编号的人只按编号认（同名不同号的冒充者不认）、只登记了登录名的按登录名（不分大小写）、**机器人只按编号认而且 `type` 必须是 `Bot`**；白名单作者的单被外人编辑：不收并告警；自家机器人的动作只同步镜像不叫醒；不是本系统管的仓、从 fork 来的 PR 和 CI 事件不收；重放（改了名单之后当初不收的现在收）。——同上。
19. **issue 变任务**（`issue-intake.ts`）：白名单作者开的单：建一行任务（原话去掉进度段、排在这个仓最后）、拉起需求工作流（**起的是 Fusion，#214 起不再起旧的**）、都记操作记录；**每一步都能重放**：任务行按（仓, issue 号）唯一、起工作流按工作流编号去重、叫停重发引擎回「已经在叫停」；**抛错 = 没处理成**：这条投递记成出错，对账重放时整条再来一遍（GitHub 自己不重投）；`/issues` 列表里混进来的 PR 不建任务；关了：给需求工作流发叫停（记下是谁关的），自家机器人关的（做完了引擎自己关单）不叫停，工作流不在、任务还在排队直接记成叫停；重开：已结束的任务重新拉起一次，补收看到「开着、任务已结束」不算重开；关了又马上重开而上一轮还没结束：记成「等着」（503，不当后端出错）、上一轮结束后重放再拉起；白名单的人改了标题正文任务行跟着改；**评论 → 回答追问**：白名单的人评论、这张任务正好一条没答的追问：当作回答（写库、发 `answer` 信号）；「按推荐先做了」的追问一直开着时随手的评论（问进度、「在做」）**不当改选，和某个选项一字不差的才算**；自家机器人的评论、改过的评论、空评论、PR 上的评论不当回答。——`issue-intake.test.ts`（66 条）。
20. **派不派**（判法都在 `core/dispatch.ts`，见 `core.md` 第 1–6 条）：开关开着、issue 是开关打开以后开的、挂在**当前版本**上（未排期、别的版本的不碰）、不是母单或子单（#252 之前一张单只走一块）、不贴「本机做」（#299 止血）；**挂在哪、当前版本是哪个、是不是母单子单、贴了哪些标签，拉起前在 GitHub 上现读**，操作记录写明按哪个版本派的；**读不到里程碑（GitHub 出错）或里程碑认不出版本号：不派、投递记成出错、写明「没查成」，不当成当前版本**；查父子关系失败不派、不当成独立的单；标签漏贴但下面挂着子单的结构上就是母单；后来挪进当前版本（`milestoned` 事件）照开关规矩再判一次；开关关着、开关以前开的不去读 GitHub；**流程配置副本不能用：这个项目停派**（建了任务行但不拉起，投递记成「等着」503 并写原因，改好、对账同步之后重放就拉起；也不退回去起旧的需求工作流）。——`issue-intake.test.ts`；0003 第 2、8、9 条。
