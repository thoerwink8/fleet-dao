# hygiene：公开仓卫生检查（业务说明）

> 一句话：这个仓是公开的，**推上去就公开了**——所以在推之前（本机 git 钩子）、CI（每个 PR，扫最终的文件树、逐个提交、PR 标题和正文）、引擎推分支（`packages/github` 的 `push.ts`）三处，把要公开的新内容过一遍：邮箱、公网 IP、私钥、令牌、账号和组织编号、密钥文件名；命中只报「文件、行、规则名」，**绝不打值**；没扫全就是失败，绝不冒充干净。
> 出处：`packages/hygiene/package.json` 说明；`src/` 各文件头注释（16 个文件，74 KB）；`test/`（14 个文件，约 120 条用例）；`AGENTS.md` 本仓段「这是公开仓…卫生检查」；`docs/reference/`（旧系统的坑）。

## 一、干什么、不干什么

- **干**：
  1. **规则**（`rules.ts`，26KB）：一段文本里有没有能认出人、账号、机器、凭据的东西——凭据看前缀或键名、编号只在 `org` / `account` / `组织` 这类上下文里算、明显编出来的值（顺序、重复、带 `fake`/`example` 字样、只有头没有正文的私钥）放行；
  2. **已知敏感值名单**（`values.ts`）：光看形状认不出的真实组织编号、账号，放在本机、服务器和 CI 密钥里，不进仓；
  3. **扫法**：全仓扫（`scan.ts`，接在 `pnpm check`）、只看新增行（`diff.ts`）、逐个提交扫（`history.ts`）、推送前钩子的判定（`prepush.ts`）、CI 按提交扫一段历史（`ci-history.ts`）、CI 扫 PR 标题正文（`ci-text.ts`）；
  4. **白名单**（`allowlist.ts`）：每条只放行一种规则在一类文件里的命中并写明为什么不算泄漏，只许越来越短；
  5. **命令行入口**：`bin/check.ts`、`bin/pre-push.ts`、`bin/install-hooks.ts`（`pnpm install` 的 `prepare` 把 `core.hooksPath` 设成 `.githooks`；已被设成别的目录不覆盖、只提示）、`bin/ci-history.ts`、`bin/ci-pr-text.ts`。
- **不干**：判断「这个密钥是不是真的」；保护私有仓（私有仓里可以写账号、编号、邮箱、IP）；拦 AI 读密钥文件（那是 `agents/hooks/pretool.mjs`，见 `agents.md`）。

## 二、业务规则（每条标出处）

**A. 退出码：没扫全 ≠ 查过没事**

1. 退出码三种：**0**＝扫了、名单也读到了、没查出东西；**1**＝查出了（或白名单有没写理由的条目）；**2**＝**没扫全**（列文件出错、一个文件都没扫到、清单里缺必有的文件、已知敏感值名单没读到、`base/head` 解析不出、git 出错、git 输出认不出）。2 和 1 分得开：**没读到名单时，不靠名单的规则（令牌、私钥）查出来的照样列出来，但退出码仍是 2（没扫全压过查出问题）**。——`check.ts`、`ci-history.ts`、`ci-text.ts`；`check.test.ts`、`ci-history.test.ts`、`ci-text.test.ts`。
2. **任何输出只报文件、行和规则名，不打命中的值**；文件名里带名单上的值（推上去名字一样公开）也报，记在打了码的路径上；网址里可能带令牌：钩子参数里的远端（可能是带令牌的网址）**不用、也不打印**。——`scan.ts`、`prepush.ts`、`values.ts`；`values.test.ts`、`prepush.test.ts`。
3. 白名单：一处都没用上的条目只提示、不判红（别的分支、以后的夹具可能还用得上）；**没写理由的判红**；`match` 里用 `(?:…)` 把原文拆开写，白名单文件自己才不会被扫出来；测试数据里的「像真的」串一律用固定种子的伪随机（运行时拼、源码里不出现整段，全仓检查不会扫到测试自己）。——`allowlist.ts`；`check.test.ts`、`helpers.ts`。

**B. 三处检查**

4. **推送前**（`prepush.ts`，主闸）：公开仓一推就公开了，CI 只在 PR 上跑太晚。**远端还没有的提交逐个过规则和名单**（推上去的是整段历史，先加后删的密钥、写进提交说明的组织编号、作者和提交者邮箱照样留在远端历史里）；「远端还没有」按本地记着的**所有远端分支**（`refs/remotes/*`）算（只认这次的远端名的话，推到网址、没 fetch 过的远端名会把早就公开的历史整段重扫、必被拒，还叫人去改写主线）；合并提交只看它自己改的（两边重新合一遍、和实际结果的差）；文本文件被 git 当二进制（`.gitattributes` 标 `-diff`、`core.bigFileThreshold` 调低）内容照样扫；带 NUL 的段是真二进制：不看内容、单独报，二进制的密钥文件照样按名字拦；删远端分支（本地提交全 0）没有新内容不扫；要推的提交远端早就有了（换个分支名再推）：没有新提交、放行；本地没记着任何远端分支：整段历史都扫并说清；**git 出错、输出认不出：退出码 2，也拒推**。——`prepush.test.ts`（19 条）、`history.test.ts`。
5. **本机没放名单不拒推**（创始人 2026-09-26 拍：新机器因为没名单推不上，名单又只是账号、编号、IP 这类标识）：这台机器压根没放名单（三处都没有、也没设环境变量 → `absent`）时，令牌、密钥文件这些不靠名单的规则照查，名单上的值**明说「没查名单、交给 CI」**；**放了却读不了、是空的、环境变量指错都不算 `absent`：退出码 2、拒推**；目录没权限（EACCES）不算没放（`existsSync` 在这种时候也回 false，会把放了读不了的名单当成没放，#184 第二意见）。CI、引擎推分支、写单子**必须**有名单，没读到就不算过。——`values.ts`、`prepush.ts`；`values.test.ts`、`prepush.test.ts`。
6. **CI 每个 PR 跑的 `hygiene` job**（不按改动裁剪）：除了扫 PR 最终的文件树，还**按提交扫这个 PR 的 `base..head`**（`ci-history.ts`）、**扫 PR 标题和正文**（`ci-text.ts`，改了标题正文会重跑）；`base/head` 收版本号（分支名、SHA 都行）、自己 `rev-parse` 成完整提交号，**像参数的（以 `-` 开头）不当版本号递给 git**、直接判没扫成；`head` 是 `base` 的祖先（没有新提交）：范围是空的、退出码 0，不判没扫成；`git log` 什么都没吐但范围里其实有提交：退出码 2；**跑的是主线上那份卫生检查代码（`trusted/`），PR 里的代码只当数据扫、不执行**；真的已知敏感值名单只给 `hygiene` job；`fetch-depth: 0`（浅克隆拿不到 `base..head`）。——`ci-history.ts`、`ci-text.ts`；`packages/conventions/test/ci-plan.test.ts`。
7. **PR 标题、正文从环境变量 `PR_TITLE` / `PR_BODY` 读**（工作流用 `env:` 传值），**绝不能把 `${{ github.event.pull_request.title/body }}` 直接拼进 `run` 脚本文本**（标题正文是 PR 作者能自由写的内容，直接拼进脚本文本等于把它们当命令跑＝脚本注入）；标题、正文当两段独立的文本、不查文件名规则、**也不过白名单**（白名单按文件路径配、管不到标题正文，误判要么改规则本身、要么改标题正文）；两个环境变量都没设当空文本（干净）。——`ci-text.ts`；`ci-text.test.ts`。
8. **推别的分支没开 PR 时**，另有 `hygiene-push` 工作流按提交扫这个分支上 `main` 还没有的部分（不是必过检查，查出来就让那次运行标红）；引擎推分支在 `packages/github` 的 `push.ts` 里自己扫（推带 `--no-verify`、git 钩子不跑，只能在那儿拦）。——`ci-history.ts` 头注释；`github.md` 第 12、17 条。

**C. 规则（`rules.ts`）**

9. 每一类违规都放样本、每条规则都有样本撑着，形状像但不算的逐个核对（`rules.test.ts`）：邮箱（示例域名放行）、公网 IPv4（内网段的边界两侧都核）、公网 IPv6（全球单播的完整或压缩写法；文档段、链路本地、只有前缀的、不合法的不算）、私钥（有头有正文；只有头的放行）、各家令牌（`tvly-`、`AKIA` 开头的 AWS 密钥、`sk-`、`rck_`、GitHub、JWT、Bearer……）、账号/组织编号（**只在上下文里算**：`org`、`account`、`组织`、`账号`、`独享`、`拼车`……）、占位 UUID 放行；「编出来的值」判法：顺序、重复、字符种类少、带假字样，**真随机串不算**；单调按字符种类比（随机的 16 位十六进制、12 位数字不算编的）；同一类规则的几种写法对上同一处只报一条；命中带着行号。——`rules.ts`；`rules.test.ts`（11 条）；`missed-by-review.test.ts`（PR #21 第一版审查时漏掉的 14 条真泄漏，先红后绿）。
10. **密钥文件按名字拦**（`SECRET_FILES`，`.gitignore` 标记段圈出来的 `.secrets/`、`*.pass`、`*.key`、`*.pem`…）：`.gitignore` 管「平常 `git add` 加不进来」，卫生检查管「`git add -f` 强行加进来的」；**规则表和 `.gitignore` 的标记段是同一张名单，两边对不上就红**（标记段被删掉下面两条就成了空测，所以要求标记段在且不空）；大小写、目录深浅都拦；源码、公钥、样例 env 不拦；被强行提交的密钥文件（二进制的、工作树里已删但还在 git 里的）也报（不带行号）。——`secret-files.test.ts`。
11. **已知敏感值名单**（`values.ts`）：格式：一行一个值、空行和 `#` 开头的不算、首尾空白去掉、重复的只留一个；找的顺序（第一个存在的算数）：环境变量 `FLEET_SENSITIVE_VALUES_FILE` > `~/.fleet-dao/sensitive-values.txt` > `/etc/fleet-dao/sensitive-values.txt`（CI 把 Actions 密钥 `FLEET_SENSITIVE_VALUES` 写成临时文件再用环境变量指过来）；**环境变量指的文件不在：算没读到，不悄悄退回家目录或 `/etc`**；一个都没有、存在但读不了、读出来是空的：都是没读到，不当成「没问题」；比：短值（少于 6 个字符）没上下文不报（行号、端口、计数里撞上的不算），带上下文就报，且要整词（更长的数字、小数、带点分段的编号的一截都不算）；键名里的 `org` 用下划线、连字符、驼峰连着也算上下文；长值（≥6 字符）整词出现就报、不要上下文、大小写不管。——`values.test.ts`（16 条）。
12. 全仓扫（`scan.ts`）：进 git 的每个文件（外加还没提交、也没被忽略的新文件）先按文件名判是不是密钥文件、名字里有没有名单上的值，再把内容过一遍规则和名单，最后按白名单放行；只读本地文件、跑一次 `git ls-files`、不出网；**一个文件都没给：扫了 0 个，和「扫了没事」分得开**；二进制和已删的单列；读文件出了别的错（不是文件不在）直接抛、不当成扫过；只看新增（`diff.ts`）：从 `git diff -U0` 取新增行（行号对得上新文件、按文件按连续的一段，跨行的规则如私钥正文照样认得出）加上新增、改动、改名的文件名；删掉的行不报；逐个提交扫（`history.ts`）：三次 `git log` 取新增的行、文件名、提交说明和作者提交者，**输出格式钉死、按从旧到新排；认不出、对不上就抛错，调用方按「没扫成」拒推**。——`scan.test.ts`、`diff.test.ts`、`history.test.ts`。

## 三、现状（做了 / 没做 / 做坏了）

- **做了**：三处检查全通；「没扫全 ≠ 干净」的退出码；先加后删、提交说明、作者邮箱、合并提交、二进制、文件名都覆盖；PR 标题正文防脚本注入。
- **做坏了**（`docs/goals.md` 第六节）：**已知敏感值名单**（`values.ts` 及所有「名单没读到就不算过」的判法）——它让新机器推不上（要放 `sensitive-values.txt`）、让 CI 和引擎写单子时因为「没读到名单」而失败（本次夜间我们自己就撞上：`second-opinion` 评论因为本机没有名单没贴上 PR），创始人 09-28 傍晚已拍删（名单：#481 在做）。
- **没做**：GitHub 自带密钥扫描的接入确认（goals 第四节 I：「推之前扫一遍 + GitHub 自带的密钥扫描」）。

## 六、怎么算做完（重做之后）

1. 名单相关的代码、CI 密钥、`AGENTS.md` 里的说法、`README「密钥和本机配置在哪」`、`docs/ops.md`、`packages/github` 和引擎里的 `HYGIENE_LIST_MISSING` 一起删；本机新机器不放任何名单也能推。

3. `.gitignore` 标记段和 `SECRET_FILES` 保持同一张名单；GitHub 自带密钥扫描（push protection）在仓设置里打开并有一条验证。
