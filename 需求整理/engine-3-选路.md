# engine（三）：选路（一次派活派给哪条路由）

> 本份是 `engine.md` 的子文档之一。选路 = 「这一步、这张单，用哪家 AI 的哪个账号池、哪个模型、哪种执行方式」。全部是纯函数（`packages/engine/src/routing/`，13 个文件），不取时钟、不随机、不碰网络和文件，只引本目录和 `@fleet-dao/shared`（`routing/structure.test.ts` 盯着）；输入由 `real/store-ports.ts` 的 `pickRoute` 从库里取齐。
> 出处：`docs/design.md` 第九节「选路」五条 + 第十二节；`docs/reference/quota.md`（坑 Q1–Q29、R1–R3、C1、D2）；测试 `routing/*`（约 280 条）、`route-probe.test.ts`（49 条）、`org-switch.test.ts`（27 条）、`org-drift.test.ts`。

## 一、结果只有三种

**派**（带路由的全部身份和「为什么派给它」一句话）、**等**（全是「等得来」：等空位 / 等额度清零 / 等熔断试探 / 等切号 / 等探针探一次，带最早几点能好）、**派不出**（要报警，附每条被挡的原因）。——`routing/types.ts`、`choose.test.ts`。

## 二、业务规则（每条标出处）

**A. 过滤：一条路由这次派不派得出去，挡在哪（`filter.ts`，64 条测试）**

1. 被挡的路由**不删**，带原因留给驾驶舱；每个原因一条、白话 + 「等不等得来」。等得来的原因带「最早几点能好」，**一定晚于现在**：那个时刻已过（读数、熔断状态慢了一步）就按「不知道」算、调用方按轮询间隔再选一次——给一个过去的时刻等待秒数成了负数，选路循环会空转。一条路由挡在几处：**有一条硬挡就是硬挡**（等来了也派不了），全是等得来的就取都解除的最晚时刻。——`filter.ts`、`group.ts`；`filter.test.ts`。
2. 硬挡：单条开关关着、渠道关了、模型下架、订阅过期、探针判不在线、禁令、「执行方式不会做这个阶段」；执行方式 × 阶段是数据（写码、UI 要能改文件，接口外壳挡；判断题、分诊接口外壳和命令行都行；**认不出的执行方式挡，不当它什么都会**）。——`filter.test.ts`「执行方式 × 阶段是数据」。
3. 禁令用 `@fleet-dao/shared` 的硬禁令，候选查询漏了也挡：Fable 一律挡（按显示名认，目录里写成 opus、上游串或别名却是 Fable 的照样挡）；GPT 在 UI 阶段挡、写码阶段不挡；**界面类的活（验证一个改了页面的改动）不管哪个阶段 GPT 都挡（GPT 不审界面）**；渠道自己挑模型的（上游串或别名是 `auto`）认不出是哪一家，只派别家时不派。——通用段「我的机器与模型」；`filter.test.ts`。
4. 额度：只挡「用满的窗口」和「剩余不够收尾的窗口」；**额度没读成的池不挡**，但排在读到了的后面并写明「额度未知」；读数过期不当现值（不当「还够」）；用满的窗口不知道清零时刻，最早能派也不知道（不编一个）；模型组窗口只卡对应模型（`7d_fable` 用满只挡带这个窗口的路由，`7d_claude` 用满只挡 Opus、Kimi 照常）；账号的失败不算到模型头上（Grok 在 A 池战绩差，同一模型在 B 池不受牵连，Q17）。——`filter.ts`；`pitfalls.test.ts`、`scenarios.test.ts`。
5. **额度够收尾**（design §九第 1 条）：独享号 5 小时窗只剩 1%，写码这种重活不派、等它清零（审查实测照派了）；周窗只剩 2% 也不派（一个活要 3%）；正好剩一成也算够（`1 − 0.9` 算出来是 0.0999…）；判不了扣不扣的窗口和读数过期算不出剩多少的窗口不在这里挡（那是额度未知）；池级读数过期但会话里顺手读到的窗口还新：读到了不够就等它清零，不拿活去撞。——`filter.test.ts`「额度够收尾」。
6. 并发按账号池算（C1）：独享号满了不影响别的池；已选定、还没开工的也占位子（一批任务同时选路：在跑 3 + 已选定 2 = 上限 5 就等空位）；`no-slot` 不算坏、等空位；已选定数没给、认不出**不当 0**（当 0 一批任务会各放一个拼车号试探）。——`filter.test.ts`、`scenarios.test.ts`。
7. **会话用户挂哪个组织**（design 第九节：一个会话用户，同一时刻只挂一个组织）：挂着的那个组织的池能派；没挂的组织的池硬挡并写明现在挂的是哪个；不知道挂的是哪个（读不到、认不出）→ 带组织类型的池**一律不派**、原话写进原因，别的池照派。不是挂着的那个组织的池：**引擎打算切过去的等切号（等得来），不打算切的硬挡**（#335，和切号同一个判法 `orgIntent`）；整池暂停着（`pool-hold`）就算打算切也硬挡。——`filter.test.ts`；`real/org-plan.ts`。
8. 探针在另一个组织挂着时没探的（`skipped`、`probeOrg` 是另一个组织，#335）：现在挂的正是它的组织就不当坏了、等下一轮探针探过；过了探针过期线还没探到按不在线硬挡、写明探针可能停了；别的不在线照老样子硬挡。——同上。
9. 熔断（`failure/breaker.ts` 的输出）：`none` 挡、等到试探时刻；`trial` 放一个（已有试探在途时熔断自己判 `none`）；`all`（候选全熔断）放最早到点的一条去试探并报警；半开且已有试探在跑：不给过去的时刻、等试探结果；**只有一条熔断、别的只差空位：不强放试探，等空位**。——`choose.ts`；`choose.test.ts`「熔断」。
10. 「等」取**最早好的那条，不按种类挑**（一条等额度 1 小时、一条等熔断 2 小时→等 1 小时）；有一条时刻不知道，不拿别的路由几天后的清零时刻去睡，按轮询间隔再看；额度 3 天后才清零又在等试探结果：最早 3 天后（不因为试探时刻不知道就每 30 秒轮询 3 天）。——`choose.test.ts`、`filter.test.ts`。

**B. 排序与微调（`rank.ts`，30 条测试；design §九第 3 条）**

11. 按**人排的顺序**取第一条能用的（驾驶舱「调度台」排的每个阶段的路由顺序）；阶段没配顺序时**派不出、提示人排**，不按 id 字典序乱挑（旧系统按 id 字典序选中了 Cursor，R3）；同模型不同执行方式是两条路由（Kimi 经 Mirasim 与经 Cursor 各算各的，避开一条不连累另一条，R4）。——`rank.ts`、`choose.ts`；`pitfalls.test.ts`。
12. 三条微调（钉住的行**原地不动**、不参与任何微调，没钉住的在其余位置里重排）：① 快清零还没用完的往前提（只看周窗和按月窗，5 小时窗快清零不提；周窗 20 小时后清零且剩 70% 提到最前，30 小时不提，剩 20% 不提；不会把 5 小时窗已用 90% 的池顶到最前；其余窗口有一个没读成也不提；两条都快清零清零早的在前；估算的照样提、理由写「估算」）；② 战绩明显差的往后放（10 次成 3 次往后放；样本少不动；只后置不淘汰，全员差照派）；③ 额度未知的排在读到了的后面（几条未知之间保持人排的顺序）。**每个窗口都看、不只看最紧的那个**（周窗用了 55.7% 但 20 小时后清零，快清零的信号不丢，Q7）。——`rank.test.ts`、`pitfalls.test.ts`。
13. 拼车号、独享号**不分主备**（#59 删掉了「备池排在主池后面」「备池只放一个试探」）：人把拼车排在前面就先用拼车；拼车按自己池的并发上限算、满了回到独享号；不分轻活重活。——`rank.ts` 头注释；`scenarios.test.ts`。
14. **选路自己不存任何状态**（R1）：上一次挡住的路由这一次事实变了就照常派（没有留在别处的冷却表）；快清零过了清零时刻就不再提前（按现在的时刻现算）。——`pitfalls.test.ts`。

**C. 任务指定路由、试探、开 PR 前验证留一家（`choose.ts`、`verifier.ts`）**

15. 任务指定了路由（续会话、人点名）：没被挡就用它、哪怕排在后面；**被硬禁令、下架、关闭挡：报「指定的路由用不了」，不偷偷换成别的**；只差空位就等它、不换；不在这个阶段的顺序里也能指定；额度未知照派、写明。——`choose.test.ts`「任务指定了路由」。
16. 试探（探索）：构建期默认关；开着时随机数落在 10% 里派给非首选（理由写「试探」，派工记录打标 `explore`，〇.4），只从能派的里挑、样本不够的优先；首选钉住时、任务指定路由时不试探；随机数由调用方给、引擎记进历史。——同上。
17. **开 PR 前验证只派别家**（0003 第 5 条第 5 步）：写这张单的族整族避开（族名不分大小写），有别家就派别家（哪怕人排在后面），只有同族就**派不出、不拿同族顶**，别家在等空位就等它、不回派不出。——`choose.test.ts`、`filter.test.ts`「避开」。
18. **给验证留一家**（`verifier.ts`，#293：界面单写的是 Claude Lead + Grok 副手，GPT 不验界面、Grok 和 Claude 同族，干完才挂起「没有别家可验」，干等 47 分钟）：选副手、Lead 换路由会给这张单加一个写手族，加之前先看验证那一步还有没有别家可派——界面单 Lead 是 Claude 时副手改派 Opus（同族、不多加一族）、验证派到 Grok；非界面单副手照旧先派 Grok；别家只是派不出（额度、连不上）就交派不出、让 Lead 自己干，不报警；验证那一步的别家只是在等额度清零不算派不出；写这张单的族已经让验证没人可派、选谁都救不回来时照常选并带上报警原因；Lead 换路由「非派不可」：照常派并带上「做完没人能验」原因让调用方当场报警；任务指定的路由不挡不换。——`verifier.test.ts`（18 条）。

**D. 探针结论与「为什么派给它」**

19. 探针结论过期：照上一次的结论派、**理由里写明**（不停工）；过期线和驾驶舱是同一条（整 45 分钟不算过期，多 1 分钟就算）；按一次的成本放慢的执行方式（cursor-agent、grok，探通了隔 2 小时再探）按自己的线（2 小时 30 分以内不算过期）；只说派出去的这条。——`choose.test.ts`；`routeProbeStaleMinutes`。
20. 「为什么派给它」人看得懂：快清零提到最前写几点清零、还剩多少；首选被战绩挤下去写明那条战绩差；钉住的写「钉住」；跳过很多条时只列前两条、其余写个数；每条路由的判定都留在结果里。——`names.ts`、`choose.test.ts`。
21. **输入先整体认一遍**（`validate.ts`，25 条测试，每条路径一条故意造坏的用例）：时刻、阶段类型、试探开关与随机数、重复的路由（在顺序里两次、同一位置两条、事实两份）、顺序里的路由没给事实（不当它不存在）、池的组织类型与会话用户挂的组织（既给了又说认不出：输入拼错了、不挑一边）、认不出的被挡原因（不当没被挡）、在线却没带探针时刻（不当刚探过）、额度状态和被挡原因对不上（用满的池会被照派）、上游模型串和别名没带（硬禁令认不出）、在途数并发上限、战绩、额度窗——**认不出就抛 `RoutingInputError`，不当成「没被挡」「额度没问题」往下走**。参数策略（`policy.ts`）给了但不对直接报错、不悄悄换默认。——`validate.test.ts`；`policy.ts`。
22. 候选查询的被挡原因两边各写一份（engine 不依赖 db）：`db` 那边加了取值、这边没跟上，端口一接上就全是「被挡原因认不出」（PR #17 加 `switched-off` 时漏过一次），所以 `blockers-sync.test.ts` 读 db 的源码现比，读不到、认不出就红。——`blockers-sync.test.ts`。

**E. 路由探针（`jobs/route-probe.ts`、`real/route-probe.ts`，#129，每 15 分钟一轮，49 + 50 条测试）**

23. 探什么：插头接上了、渠道开着、有阶段开着该路由、会话用户挂着这个组织，才探；插头没接记 `not_wired`（不写成探过、离线）；**按量计费不探**（探一次就是一笔账）；渠道或模型下架、没有阶段开着各写各的不探原因；会话用户挂拼车时独享池的路由不探（探了扣的是拼车的额度）；挂的组织认不出：带组织类型的池一律不探、记没探成（写明原因），不拿拼车顶。——`route-probe.test.ts`「探不探」。
24. 怎么探：以会话用户身份、经 `fleet-agent-scope` 在自己的 scope 里起一次极小的无头会话问一句「只回 OK」——**同一个插头、同一份执行体、同一个模型串（路由上写的）**，所以探通了就说明会话起得来、答得上；判法也是同一套（`judgeRun` + 失败分流规则表）；什么命令都不许跑（Claude 用 `dontAsk`，cursor 不带 `--force`）；Claude 不存会话记录；同时最多探两条，结论按路由的顺序写。——`real/route-probe.ts`。
25. 结论怎么写：**只有 `ok` 让路由在线，其余一律不在线并写明原因**；第一次没通隔一会儿再探一次（通了就在线，原因里记着第一次），连探两次没通写离线并写明两次的原因（不许拿上一次的在线冒充）；要人修的整池问题（登录失效、设备被撤销、封号、欠费）同一轮不再试，写 `pool-hold:<池>` 那条「要人拍」、选路整池避开、探通了就撤；**额度用满被拒算通**（在线）——额度那一套去挡，不当成离线（离线在选路里是硬挡，任务会挂起等人）；探针自己抛错按没探通记；原因太长截断、不塞整段报错原文；探的时候顺带读到的额度也记账；Claude 订阅池的结论连那时挂的组织一起写（选路靠它分清「那一轮挂着别的组织、没探它」和「探了没通」）。——`route-probe.test.ts`、`real/route-probe.ts`。
26. 按一次的成本放慢：cursor-agent、grok 探通了隔 2 小时再真探；结论照旧的不写库、不起会话，算看过、算在线；上一次没通、没探过、结论 ok 却不在线、时刻在未来都每轮探；结论照旧之外该写的一条没写进去照样记 `failed`。——`route-probe.test.ts`。
27. 一轮的记账（`schedule_runs`）：读不到路由表记 `failed` 并抛（**一条都不写，不许留着上一轮的在线当没事**）；一条路由都没有记 `unscanned`；有的写不进库记 `partial` 写明哪几条；一条都写不进记 `failed` 并抛；探的时候路由被删了不算写进去也不算出错；记不上开始原样抛出（不去探、不写，登记表上它会过期，看门狗看得见）；记结局失败原样抛。`scanned` = 看过的路由数（含结论照旧），`found` = 其中不在线的（和驾驶舱调度台在线数对得上）。——同上。

**F. 会话用户切号（`jobs/org-switch.ts`、`real/org-switch.ts`，#157、#59）**

28. 平时挂拼车；**拼车额度用满（和选路同一个判法）切独享，拼车用满的那几个窗口清零时刻都过了切回拼车**；手上有 Claude 会话在跑：能先停下、切完续上（#59）就照切，不能就等；独享也用满、独享池整池暂停着、库里两个池不全：切过去也派不了，不切；拼车池整池暂停：先不切回。——`org-switch.test.ts`（27 条）。
29. **判不了的不切**：挂的是哪个认不出不切；挂的是哪个这会儿定不下来（读数刚变、引擎没切过号，#335）这一轮不切、写明是定不下来不是认不出；**拼车用满却读不到几点恢复是 `stuck`，要人看，不当成到点了；读数旧了也不算恢复**（选路那边读数旧了算「不知道」，这里当成恢复就会切回去、被拒、再切走，来回折腾）。——同上。
30. 怎么切（`real/org-switch.ts`）：路由探针每一轮探之前现读会话用户挂的组织（`real/session-org.ts`：以会话用户身份跑 `reclaude org list`，带 `*` 的是现在挂的，`team` 是拼车、`personal` 是独享；**组织编号、名字、邮箱一概不往外带**；读不到、认不出——一个组织都没有、没有带 `*` 的行、带 `*` 的不止一行、类型认不出——一律明确失败，原因里不带编号、邮箱）；该切：先让选路停下（读组织回 pending，选路过 30 秒再选）、等一会儿、把跑在 Claude 池上的会话停下（交回 `org_switch`，切完续同一个会话、换池 fork 续上）、经 root 帮手的 `org-use` 切过去并回读核对，没切成、核对不了都切回原来的，切完记操作记录；这一轮探完切过去的池的路由探通了才算切成；没切成、切完探针读回不在线、拼车用满读不到恢复：写 `session-org:*` 的「要人看」提醒（驾驶舱健康检查 `session_org` 跟着红），条件没了自己撤；这一步出什么错都不抛，探针照探、下一轮再判。——`real/org-switch.ts`、`real/session-org.ts`。
