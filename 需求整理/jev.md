# jev：判断题小模型（业务说明）

> 一句话：把「一句话能判出来的小问题」（这张单该贴哪个类别？这次失败下一步怎么办？这个会话是在等还是在绕圈？）交给一个便宜的小模型去答——**只能让流程更谨慎（拦、退回、换路、提醒人），不能放行、批准合并、动账号、删东西**；答不上、不确定、连不上，一律当没判、照默认走，绝不当成「否」。
> 出处：`packages/jev/package.json` 说明；`src/` 各文件头注释（17 个文件，133 KB）；`test/`（15 个文件，约 240 条用例）；`docs/design.md` 第十一节（十个接入点）；`AGENTS.md` 本仓段「Jev：判断题小模型（TypeSafe 的 System One）」。

## 一、干什么、不干什么

- **干**：题库（`bank.ts`：设计第十一节的十个接入点）、提问接口（`jev.ts` 的 `ask(题, 证据) → 选项 + 把握度`）、可换的后端（`backends/typesafe.ts`：旧系统的 Jev 服务、按量计费；`backends/claude.ts`：经插头起一个 Claude 会话，套餐内，**目前接不了**——要等 `fleet-agent-scope`）、只记不拦 ↔ 真拦的转换（`mode.ts`、`store.ts`）、考题（`exam.ts`、`exams/*.json`）、机器配置（`config.ts`）、「接没接、调不调得通」（`wiring.ts`，引擎和 `/healthz` 的 `judge` 项共用）。
- **现在真接上的只有**：引擎的**错误分流、停滞预判**两处（`packages/engine/src/real/jev-port.ts`，先只记不拦）和 **issue 归类**一处（#448，`real/issue-kind-jev.ts`）；设计第十一节表里其余接入点没接。
- **不干**：选「哪条路由」（题库里没有哪道题是在一串路由里挑一条，`bank.test.ts` 钉死）；放行类的任何决定。

## 二、业务规则（每条标出处）

1. **能拦不能放**（设计第十一节）：Jev 的结论在**类型上就表达不出放行**——效果只有收紧的几种（让一件事停下、退回、换路、提醒人看）；题库里每个选项只能挂这几种之一，调用方拿到的 `act` 也只会是这几种之一；没有、也不许加「放行」「批准合并」「动账号」「删除」这类值。——`effects.ts`、`verdict.ts`；`effects.test.ts`。
2. **调用方只看 `verdict.act`**：**真拦**（题目在真拦、回话的就是钉死的模型、题面和库里一致、把握够）时是选项挂的效果；**只记不拦、把握不够、没判出来（连不上、超时、被限流、答了题面外的选项……）一律 `none`，当它不存在、照默认走，不当成「否」**；`ask` 不抛，任何出错都变成一个没判出来的 verdict。每道题每次都记一行 `jev_answers`（包括本地就拦下的：停用、次数用完、证据不全），记不上就当没判（`store_error`）。——`jev.ts`；`jev.test.ts`（60 条）。
3. **没判出来的各种原因各记各的**：后端抛异常 `backend_error`；答了题面以外的选项 `bad_option`；回话的模型不是钉死的那个 `model_mismatch`（**模型必须钉死到具体型号、别名不行**）；回包里没有这道题、形状认不出、把握度不在 0–1；库出错 `store_error`（也不问出去）；停用 `off`；必填证据没给或全是空白 `missing_evidence`；给了题目不认识的证据字段 `bad_evidence`；没给 `subject` 不问。——同上。
4. **本地就拦下的不问出去也记一行**；**「库里的题面和代码对不上」（改了题还没同步）、「只改了证据字段」都算换了一道题：这次只记不拦**；钉死的模型和这次后端的不一样：题目在真拦也只记不拦；把握度低于把握线＝没判出来（答了什么照记，统计里算「没把握」）。——同上；`questions.ts` 头注释：改题面、选项或证据字段＝换了一道题，`rev` 变，之前攒的准确率不再算数，真拦的题退回只记不拦。
5. **真拦中的题漂了：当场退回只记不拦**（答了题面外的选项、或回话的不是钉死的模型）：这一问就退回、留操作记录（指着这一问），下一问不再真拦；考试里漂了也当场退回（不等考完、也不怕下一次考试把它洗掉）；别的模型漂了不连累钉死的那个。——同上；`store.test.ts`。
6. **只记不拦 → 真拦**（`mode.ts`，纯函数）：攒满 `minSamples`（默认 50）条「有把握、有真值」的判定、准确率不低于线、且最近一次巡检考题及格、且攒样本期间没漂过：才转真拦（留操作记录）；**真拦 → 退回**：考题不及格、生产判定（人改判、结局回填）准确率掉到线下、答了题面外的选项或回话模型不对；**「考试没考成」不算掉线**（没考成 ≠ 考砸）；人停的（`off`）只有人能开、这里从不动；只记不拦挂了 14 天还没攒够样本：标「影子停滞」；漂过之后考及格也不马上转真拦：要在漂移之后重新攒够一批样本；线和天数从驾驶舱设置读、**设置认不出就报错，不拿默认线去判真拦**。——`mode.test.ts`（21 条）、`store.test.ts`。
7. **准确率只按「当前题版本 + 钉死的模型」算**：旧版本、别的模型、没把握的、考试的真值都不算；准确率 ＝ 把握够且答对的 ÷ 答在题面里的；真值必须是这道题的选项，补上之后才算进去。——`store.ts`；`store.test.ts`。
8. **考题**（`exams/<接入点>.json`）：每个接入点一份、从旧系统真实记录里挑出来并脱敏、每道题至少 N 道、答案里既有放过的也有拦的；公开仓不许带邮箱、IP、令牌、家目录用户名、飞书编号；「审查意见分级」的意见原文里不许留审官自己的定级（那等于把答案写进题里）；考一个接入点：逐题记分（答对、答错、把握不够、答了题面外的选项分开数），标准答案记成真值（来源 `canary`、从不真拦）；**考题写坏了或一道都没有：不考、报错（坏考题算出来的准确率会被当真）**；答出的不够八成、或少于最少道数：没考成、不当成考砸；巡检考试的每日次数默认够一天四轮满卷（每 6 小时一轮），**另算次数**（生产问满了不挡考试、考试也不占生产的）。——`exams.test.ts`（15 条）、`exam.ts`。
9. **证据：喂全文，库里只留脱敏摘要**：证据按题目声明的字段收、**原样喂给模型不裁剪**（缺信息比多信息伤得重，旧系统实测）；几道题一起问时字段按第一次出现的顺序去重；库里只有长度、哈希、开头 200 字（**私聊字段不留开头**）+ 调用方给的能复原原文的引用；开头**先脱敏再截**（先截再脱敏会让跨过截断处的令牌剩下认不出的半截漏进库）；上游报错原文进库、交回调用方之前也脱敏；写进库的字都要收得下（`jsonb` 不收落单的代理项和 NUL，换成 U+FFFD）；引用转不成 JSON（BigInt、循环引用）：引用不要了、原因记在这一行里、判断不丢。——`evidence.ts`、`scrub.ts`；`jev.test.ts`、`scrub.test.ts`。
10. **每天的上限**：次数到上限就不再问出去（本地拦下的不占次数；「今天」从 UTC 0 点算，和额度读取器里 Jev 池的窗口一致）；按量计费的后端花费按回包的 token 记进库，再问会超每日花费上限就停调、走默认、库里记「因上限没问」；**发出去就记账**：超时的调用按事前估算记（标明是估的）、出错的回包里上游报了 token 数按报的记、后端抛异常按估算记——这样上限才不会被出错的调用绕过去；判断没记进库但这一问已发给后端：花费另记一行（`unrecorded`）、占每日花费和次数、调用方拿到 `store_error`；订阅内的后端（没有单价）不受花费上限管；花费上限默认是旧系统的日帽、设置里配了以设置为准、**设置里的上限认不出：不问出去、明说设置坏了（不拿默认值顶）**；一次问几道算几道（剩的次数不够这一批就整批不问）。——同上。
11. **一次问几道题**：分诊要判的四件事各成一题（一道题只问一件事），四题**共用一份证据、一次调用问完**，token 按道分摊、同一批带同一个批号；类型上 `option` 收窄到这道题的选项、`act` 收窄到这道题的效果。——`bank.ts`；`bank.test.ts`。
12. **TypeSafe 后端**：`POST <地址>`、Bearer 密钥、请求体 `{state, model, questions}`；回包 `{model, answers:{题号:{type, choice, probabilities, confidence}}, usage}`；**地址和密钥只从机器配置读、没有默认值**；模型钉死（`jev-x.y.z`）、地址必须 https、没有密钥：当场拒绝创建；回包里的 `model` 是实际回话的版本号，和钉死的对不上就当没判（`model_mismatch`）、**但带上实际版本和上游报的 token 数照样要记账**；回包没带 token 数：按字符数保守估、标明是估的、不记 0；HTTP 状态码分到原因上、报错原文带回来但不带密钥、先脱敏再截；连不上 `network`、超时 `timeout`；回包不是 JSON、没有 `answers`、没带 `model`：`bad_answer`；某道题答案形状不对：这道题记成认不出、别的照常。——`backends/typesafe.ts`；`typesafe.test.ts`（14 条）。
13. **Claude 后端**（接不了）：经插头起一个 Claude Code 会话答判断题（构建期先用 Opus 5.5，套餐内）；会话在一次性空目录里跑、权限 `dontAsk`、不给任何仓库和凭据、答完收掉目录；提示词里证据包在标签里原样放进去、每道题带全部选项、末尾说清只回 JSON；答案夹在别的文字或代码块里也能取出来；回复里找不到 JSON：原文先脱敏再截；起会话抛异常不往外抛、当没判；测试里不会起真的 reclaude。起一次会话要几秒到几十秒，适合分诊、质检、交活核实这类不赶时间的题，飞书这种要秒回的题用 TypeSafe。**当前：配置齐了也一律拒（接上 `fleet-agent-scope` 之前不开）**，目录样例里关着的两条 Claude 就是因为这个（`catalog-judge.test.ts` 钉着，哪天接上会红）。——`backends/claude.ts`；`claude.test.ts`、`config.test.ts`。
14. **本机的判断题接没接（`wiring.ts`，引擎每次提问和 `/healthz` 的 `judge` 项共用一份）**：**「未接」只有一种：没写 `FLEET_JEV_CONFIG`、默认位置（`/etc/fleet-dao/jev.json`）上也没有配置文件**；别的一律算坏了、要报出来，不许当成没配悄悄不问：`FLEET_JEV_CONFIG` 明写的文件不在、文件在却读不到（权限不够——`existsSync` 会把它说成「不存在」，所以不用它）、是个目录、内容不是 JSON 或有不认识的键、调度台判断阶段没有开着的路由、库读不到、钥匙文件不在或是空的、钥匙读到了后端起不来（原因里没有钥匙的值）；**判断阶段挂的路由不看 `alive`**（`alive` 只由路由探针写，而 Jev 是按量计费渠道、探针按规矩不探、一直写「不在线」；在这里看 `alive` Jev 就永远问不到）；**用哪个后端、哪个模型不在配置里定，调度台「判断」阶段排第一的那条路由说了算**（`backendForRoute`：接口外壳 + `jev-*` → TypeSafe；`claude-code` → 一律不开），驾驶舱改了顺序、开关下一次就按新的走；`/healthz` 的 `judge` 项：配好没调过是好、最近一次真调用没成报坏（带原因和原文）、下一次调成了自动好；**把握不够也算调通了**（答了、只是不作数）；本地就拦下、没发出去的不算调用（盖不住前面那次没成的）；考试也是真调用；判断记录里记下用的是哪条路由。——`wiring.ts`、`config.ts`；`wiring.test.ts`（25 条）、`config.test.ts`。
15. **十个接入点**（设计第十一节那张表）都有题、每道题写得对（题面、选项带效果和真拦时怎么走、证据字段、拿不准时的默认走向）；写坏的题、同一次问的几道题里同一个证据字段名字不一样：都查得出来。——`bank.test.ts`。

## 三、现状（做了 / 没做 / 做坏了）

- **做了**：题库、提问接口、TypeSafe 后端、只记不拦/真拦、考题、机器配置、接没接的判法；引擎两处（错误分流、停滞预判）和 issue 归类接上（只记不拦，issue 归类由 `issue-groom` 按把握度决定贴不贴）。
- **做坏了**：**一开始想让 Jev 在多处「真拦」**（#196、#144 已按 NOT_PLANNED 关；#61 判断题按调度台路由选后端，goals 建议关），但 Jev 是按量计费渠道、每日花费上限、探针不探，接得很窄；「转真拦」需要攒 50 条有真值的样本，实际没有哪道题攒到。
- **没做**：Claude 后端（等 `fleet-agent-scope`）；#40 按用途分钥匙（一类一把 API key，一把额度用完不连累别的）；其余八个接入点。

## 六、怎么算做完（重做之后）

1. Jev 只剩「单子归类」一道题和提问、记账、每日上限、后端、`wiring`；「能拦不能放」类型约束保留。
2. 错误分流、停滞预判的接入和它们的题、考题、转真拦逻辑一起删，引擎里的默认「不问」实现也一起删。
3. `/healthz` 的 `judge` 项保持「未接只有一种、别的读不成都报坏」。
4. 每一条「读不到、认不出、模型对不上」的路径保留一条故意造出失败的用例，且不许记成「否」。
