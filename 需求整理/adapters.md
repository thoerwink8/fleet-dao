# adapters：渠道插头（业务说明）

> 一句话：把「一家 AI 的命令行或服务」包成同一个样子——**无头起一个会话、边跑边把过程记录转成进度事件、结束时交出一份报告、判这次算不算做完**；外加一套**额度读取器**（每个账号池每个时间窗还剩多少），和几个以 root 帮手身份做的小动作（进 scope、收树、切组织）。
> 出处：`packages/adapters/package.json` 说明；`src/` 各文件头注释（52 个文件，390 KB）；`test/`（41 个文件，约 660 条用例）；`docs/reference/adapters.md`（协议与坑：CC-05、CU-03/05/08、GK-03/04/08、MS-01…28、GEN-08、PI-02、DL3）；`docs/reference/quota.md`。

## 一、干什么、不干什么

- **干**：
  1. **五家插头**：Claude Code（经 reclaude）、cursor-agent、Grok 命令行、Mirasim（本机服务的回环 ws）、接口外壳（命令行够不到的模型，用最小的「读写文件 + 跑命令」循环直连 OpenAI 兼容或 Anthropic 接口）；codex 直起**已定不直起**（按量计费）——只经 Mirasim 中转走。
  2. 共用管道：`process.ts`（起进程、提示词走 stdin、超时/停滞/叫停整个会话一起杀）、`procs.ts`（找出并收掉一次会话留下的全部进程）、`detached.ts`（会话脱开引擎）、`stream-kit.ts`、`lines.ts`、`env.ts`、`effort.ts`、`judge.ts`（判一次会话的结果）、`delivery.ts`（交付判据）。
  3. **额度读取**：`quota/`（`readAllQuotas`、6 个读取器、估算、命令行表格）。
  4. **以 root 帮手身份做的事**：`adoptWorktree`、`removeWorktreeDir`、`listAgentScopes`、`stopScope`、`switchSessionOrg`（都只交参数给 `fleet-agent-scope` 帮手，边界在以 root 跑的帮手脚本里）。
- **不干**：选路、判失败下一步做什么、写库、推分支（那些是引擎的事）；插头**不碰 GitHub 凭据**。
- **进度事件的字段名**（`say.text`、`tool.name`、`file.path`、`test.passed/command`）被驾驶舱后端的时间线按名字读，**改字段名先对 `packages/api` 的 `describeTimeline`**。——`types.ts`。

## 二、业务规则（每条标出处）

**A. 会话怎么起、怎么读、怎么判（各家共同的）**

1. **提示词不进命令行参数，走 stdin**（超长会 `E2BIG`；Claude 的 `--allowedTools` 吃变长参数，放在它后面的提示词会被当成工具名，已实测）；喂完立即关；Grok 的 `--prompt-file /dev/stdin` 读不了 Node 给的 socketpair，前面垫一根 `cat` 真管道；codex 用 `-`。——`claude-code/args.ts`、`grok/args.ts`、`codex/args.ts`。
2. **环境每次现场显式构造，不继承宿主环境块**（旧系统守护进程带着一周前的 env 起会话，排查了两小时）：只从宿主抄一小撮白名单变量；**宿主的上游改写（`ANTHROPIC_*`、`CLAUDE_CODE_OAUTH_TOKEN`）、代理、GitHub 凭据、密钥一个都不带**（带了就绕开 reclaude）；`TMPDIR` 不从宿主抄（那是引擎自己的），会话的临时目录必须是绝对路径、每个会话一个、结束整个删掉；起之前就拒：单元测试里起真执行体、环境里带上游改写或推送凭据、工作目录不存在、提示词为空。——`env.ts`；`env.test.ts`、`claude-run.test.ts`。
3. **生产配置下不进 scope 就不起**：`FLEET_ENV` 不给、给空、`production`、认不出都算生产（`development`/`test`/单元测试放行）；接口外壳的三件工具生产配置下也必须给 scope；命令行上只放白名单里的执行体开关（`sudo` 记日志、`/proc` 别的用户读得到，名字不像凭据的也拒），白名单里的值带控制字符拒；命令没写绝对路径、环境里有白名单以外的变量：不起会话、交报告说没起来。**Grok 无人值守的几个开关都在白名单里**——少一个法国经帮手起 grok 当场被拒。——`scope.test.ts`（15 条）。
4. **交付判据：执行体说「做完了」不算数**（`delivery.ts`，windsurf-dao#1572 的假完成）：会话只在本地提交、推分支由引擎在会话外做，所以**交付 ＝ 引擎能推走的东西**：① 相对**此刻**的目标分支有自己的提交且有内容差异（必须先抓最新的目标分支再比：拿旧的比，被快进到新主线、自己一行没写的树也会显得「有新提交」）；② 这一轮会话自己有新提交（`since..HEAD`；续会话那一轮什么都没做不能靠上一轮的提交）；③ 已跟踪的文件没有没提交的改动（引擎只推提交、这部分会丢；没跟踪的构建产物不算）；提交了又撤回、净差异为零：没交付；抓不到目标分支、找不到起点提交：**没查成，不当成没交付**。——`delivery.test.ts`。
5. **判一次会话的结果的优先级**（`judge.ts`，判法只有这一份，各家插头把记录整理成 `RunFacts`）：进程没起来 → 起没起来没查成 → 被我们杀掉 → 跑完才看出的不一致（模型或会话号：点名的和实际的都写明）→ 额度用满 → 没有终帧 → 终帧报错 → 退出码 → 中转没查成 → 交付。叫停算 `stopped`、停滞算 `stalled`、其余被杀算 `failed`（被信号杀掉写明信号）；额度用满但终帧说成功以终帧为准；**中转没查成、起没起来没查成判失败但原因单列**（该重查 / 先对账），不混进执行体失败；不是进程的插头（Mirasim、接口外壳）没有退出码也能判。——`judge.test.ts`。
6. **过程记录解析：认不出的帧只计数、不报错；用量读不到就不给、不记成 0**；形状**以真跑夹具为准**（各家夹具在 `test/fixtures/`：Claude Code 2.1.281、cursor-agent 2026.09.23、Grok 1.0.41、codex 0.156.1 对假上游、Mirasim 0.0.355；夹具只脱敏家目录用户名和账号级 signature）。——各 `*-stream.test.ts`。
7. **测试结果只认可信的退出码**：工具报成功且命令可信才记通过；`pnpm check | tail` 这种（退出码是 `tail` 的）记「结果未知」；放到后台跑的记未知；`grep` 出测试命令不记成一次测试；仓的测试命令本身是几条串起来的按「含」认、不拆；测试命令是空的什么都不算。——`stream-kit.ts`；`claude-stream.test.ts`「测试结果只认可信的退出码」。这条直接决定 `fleet done` 核实（`api.md` 第 10 条）。
8. **起停纪律**：整个会话（执行体、子孙、各自的进程组、带会话标记 `FLEET_RUN_ID` 的进程；放进 scope 时以 cgroup 为准）**一起杀**，执行体退出后会话里还活着的（后台服务、`setsid` 脱离进程组的测试）一律收掉（谁起的谁回收，不留孤儿占树——Claude 的 Bash 工具每条命令都 `setsid` 自成一组，只杀进程组收不干净）；起动预算默认不少于 180 秒（只有 stderr 在打「Syncing config…」不判失败、不重发提示词）；迟迟没有第一帧按起动超时杀；总时长到顶连同子进程杀掉、判超时而不是 0；**没有工具在跑却长时间没动静判停滞，有工具在跑（如一轮长测试）不算**；进程一起来就交出进程号（引擎记下、重启后能收旧会话）；进度回调抛错不打断解析、记在 `hookError`（async 回调被拒也接住，交报告前等它落定）；命令不存在：交报告说没起来、不抛；进程退出却没有终帧：判没交代结果。——`process.ts`、`procs.ts`；`claude-run.test.ts`（27 条）。
9. **思考档位**（`effort.ts`，创始人 2026-09-28 拍默认 `high`）：引擎起会话总是显式传；这里只管「传了的值认不认、这家接不接」，**不认识、这家不支持（Grok 不支持 `max`）都抛错、调用方不起会话，不许当成 `high`**；档位不认识不传给命令行。——`claude-args.test.ts`、`hosts.test.ts`（见 `engine-5` 第 18 条）。
10. **fork**（换会话用户接着干：带着旧会话的记录开一个新编号）：`--resume <旧> --fork-session --session-id <新>`；`from`、`id` 都要是 UUID 且不能一样；**fork 没续上（init 帧回来的还是旧编号）按会话不一致停掉（花的是旧账号的额度）**；fork 出来的会话不给花费（累计值从 0 起算还是接着旧会话没实测过）；续会话回来一个别的会话号：停；不存会话记录（`persistSession:false`）又要续、fork：写错了、当场拒。——`claude-args.test.ts`、`claude-run.test.ts`。
11. **调工具前那条钩子经 `--settings` 带上**：只登记 `PreToolUse` 一组（挂在 Bash、PowerShell、Read、Grep 上，和 `agents-sync` 给 Claude 登记的那组一样），跑仓里的 `pretool.mjs`；**钩子脚本不在、是个目录：不起会话**（起了也没人拦，钩子出错 Claude 照样放行）；不用 `--bare`（经 reclaude 起会认证失败、回一条 `<synthetic>` 占位）。——`claude-args.test.ts`、`claude-run.test.ts`；e2e `claude-guard-e2e.ts`。（**这条随 goals 第六节「拦 AI 读密钥文件的钩子」删**。）
12. **会话脱开引擎进程**（`detached.ts`，创始人 09-28 凌晨拍）：执行体的输入输出错误都接文件、退出码由**会话那一侧的外壳**写进文件；引擎只是按序号读；收发目录归引擎（`fleet`，`0711`），里面 `prompt(0644)、out/err/exit/pid(0622)、started、helper.err`；引擎重启后新引擎照同一目录从头重读（接回）：**确认过的行只重放不再报**；会话在引擎不在时跑完了照样读得到结局；**退出码丢了（外壳被强杀、会话也不在了）照实判 `exit_lost`，退出码文件写的认不出照实报——都不当成 0**；叫停：外壳和执行体一起收到 TERM、外壳等执行体退了再写退出码；执行体起不来（命令不在）外壳写 127。——`detached.test.ts`。

**B. 各家插头的特性（跟着真跑记录来）**

13. **Claude Code**：会话号由我们定（UUID，`--session-id`）；实际模型看助手消息的 `message.model`（`init.model` 只是把请求原样回显，点一个不存在的模型也照回）；**模型不可用时 CLI 自己合成一条 `model=<synthetic>` 的助手消息，终帧 `is_error=true` 但 `subtype` 仍是 `success`**——合成的不算数、没有主会话回复就不给；**实际回话的模型不是点名的那个：读到第一条真实回复就停**；一条助手消息按内容块拆成多帧（同一个 `message.id`），**用量以终帧为准**；**花费是整个会话的累计值，续会话本轮要减掉上一轮，不给上一轮就不带花费**；`lastContextTokens` ＝ 最后一条助手消息的 input + 缓存读 + 缓存写，子代理（Task 工具）的助手消息不算；额度读数边跑边交出去（`rate_limit_event`，5 小时窗与 7 天窗）；用满那一刻只有 `{status:"rejected"}`、没有利用率时记 5h 已用满、刷新点按「约 N 分钟后重置」推；opus-5-5 的工具表里没有步骤清单工具，步骤只能靠 `fleet plan` 主动报；命令行版本低于要求：停。——`claude-stream.test.ts`（34 条）。
14. **cursor-agent**：参数固定带 `--trust`（探针也要：没信任过的目录里 `-p` 只打一段 Workspace Trust 提示就退出），干活的带 `--force`、探针不带；续会话 `--resume`；**开新会话的会话号是它自己在 init 帧里起的，报出来时调 `onSessionId`（只报一次，回调抛了记进 `hookError`）**；`init.model` 是界面名（`Auto`、`Grok 4.6 High Fast`），流里没有「实际用的哪个模型」；工具调用 `tool_call`、退出码在 `shellToolCall.result.success.exitCode`；待办清单 `updateTodosToolCall` 增量更新（`completed` 帧的 `result.success.todos` 才是整张）；终帧 usage 只算这一轮、**没有花费**（花费不在流里只认 Dashboard，CU-08）；stderr 报错退出：没有终帧、原因带上原文；「Cursor 拒了 API 密钥」（头一行自带终端颜色，去掉颜色、三行原话都留）不当成额度用满；stderr 说额度用完判额度用满；续会话回来的不是原来那个会话：当场停、不把对不上的号报出去。——`cursor.test.ts`。
15. **Grok**：会话号我们起（UUID，`-s`），续跑 `-r` 同一个号，终帧 `end.sessionId` 回的就是它；**会话号和实际模型只在最后一行 `end` 里**：跑的中途核对不了、跑完核对，不符照样判失败（`modelUsage` 的键就是实际模型；带渠道后缀算同一个、换代不算：点名 4.7 回 4.6 判模型不符）；旗标都在前面不用子命令（放子命令之后报 `unexpected argument` 退出 2，GK-03）；**免确认用 `--always-approve`**（`--permission-mode auto` 每条外部命令还要确认，GK-04）；**总带 `--no-plan`**（`--always-approve` 管不到计划模式，无人值守会卡着等人点头）；目录信任、反问选择题两张卡走环境变量；文字增量一字一帧、拼起来才是一句话（遇到别的帧再作为一条 `say` 发出去）；`grep` 没匹配 `exit_code=1` 不是失败；`end` 永远是最后一行；花费只算这一轮；没登录（error 帧和 stderr 各打一遍、退出 1、没有终帧）：同一句只留 stderr 那一份；额度用完（402/要订阅）判额度用满；半路断了没有终帧、攒着的最后一句话也交出去；关自动更新。——`grok.test.ts`。
16. **Mirasim**（#345，`mirasim/`，38 + 6 条测试）：**只留作「Mirasim 中转额度」这条路由的薄插头**（MS-28：中转不许反代，只能用它的客户端；主线定的是给会话用户单独起一份 Mirasim 服务、各自登录一次，配好之前 Mirasim 路由保持关闭）；引擎只收发帧：起会话、另开连接订阅状态、叫停、事后读账本核实走了哪条上游；**法国防火墙只放行会话用户和 root 连那个回环口**（`docs/ops.md` 第五节「会话用户的口只许它自己连」，#35），引擎自己（`fleet` 用户）连不上（2026-09-28 实测断链）→ 经 `fleet-agent-scope` 起一个短命**桥接进程**（`bridge.ts`，以会话用户身份，只用 node 自带模块，帧经 stdin/stdout 按行 JSON 转）；每次建连现读令牌（服务每次起停都换令牌）；起一个 codex 会话会把服务端单线程堵 40–58 秒，建连重试到 90 秒左右（MS-08）；状态合并：订阅回的 snapshot 整份替换、`session` 帧按 `seq` 打补丁，补丁跳号回 `gap` 让调用方重订阅，旧 `seq` 的快照丢掉；`done` 带死因、`incomplete` 都是失败（MS-10、11）；**「中继返回额度用完」判成账号池额度用满，不当成上游抖动**；快照里的模型不是声明的那个：停会话；`prompt` 发出去没等到应答标「没查成」、不当成确定没起来（MS-18）；不带本次 `clientRef` 的 error 帧不算被拒；一直排队起不来超时停掉；**流量账本**（`~/.mirasim/traffic/<会话 uuid>/index-*.ndjson`）：判「这次到底走的哪条上游」只认它（MS-27：`route=auto` 时服务端按额度窗自己选）；中转路由起针之后没有 2xx 行，`done` 不算数；账本的行在调用结束后才写、会话一结束就读是空的，等它追上来再判；账本读不了/没给目录/会话号认不出：「中转没查成」，不当成零次调用；账本里只挑路由相关的几个字段（行里还有账号、设备这类，一概不读出来）；令牌读不了、是空的：明说不连；法国上 Mirasim 服务不在：原样报出来判失败；测试里连真服务一律拒绝。
17. **codex**：**直起 codex exec 已定不直起**（按量计费 key，`docs/design.md` 第十四节）：调用方不显式给 `allowMetered: true` 就拒起、一个进程都不起，免得哪天被当成普通渠道接上、账单多出一笔；只用假上游验过事件格式；`turn.completed` 的 usage 是**整个会话的累计值**，续跑本轮要按上一轮求差、没给上一轮不带用量；`turn.completed` 不带 usage：用量没查成、不记 0；续会话回来的 thread 不是原来那个：当场停；上游 401 先重连 5 次再报 `turn.failed`；凭据在 `CODEX_HOME`（每个账号池一个）。——`codex.test.ts`。
18. **接口外壳**（`shell/`，20 条）：命令行够不到的模型，循环在引擎进程里：发对话 → 模型要调工具就在工作树里做（放进 scope 时以会话用户身份）→ 把结果接回去 → 直到它说完；三件工具（读文件、写文件、跑命令）**只许碰工作树**（路径出了工作树一律拒；符号链接也逃不出）；生产配置下命令、读、写都经 `fleet-agent-scope`（引擎用户自己不碰工作树里的文件，否则命令会以引擎的身份跑、读得到引擎的配置和凭据）；接口密钥只在发请求用，不进报告、不进子进程环境；没有服务端会话：续跑就是把上一轮的对话记录带回来；**花钱红线：按量计费的接口不许真跑，这一轮没有已确认在套餐内的接口，所以只有假接口的测试**（测试里不给假 `fetch` 就不许起）；认证失败不重试判执行体报错；额度用完判额度用满，限流先按 `retry-after` 重试，上游 5xx 重试几次不行判上游出错；**回话被截断、到了轮数上限都判失败，不当成说完了**；OpenAI 的 `prompt_tokens` 含命中缓存的部分（输入只记没命中的，缓存不算两遍）；引擎叫停：停在下一轮之前，信号传进正在跑的命令。——`shell.test.ts`。
19. **帮手的调用**（`adopt.test.ts` 27 条、`scope.test.ts`）：`adopt <工作树> --user <用户>`、`remove <工作树>`、`org-use <类型> --user <会话用户>`、`stop`、`list`；工作树要绝对路径且不许有控制字符；`--user` 只能是会话用户（别的、已停用的 `fleet-agent-dedicated` 都拒）；只认 `carpool`、`solo` 和会话用户；退出码 0 成功、64 是 `usage`（带帮手原话）、别的是 `failed`；帮手脚本本身起不来（`spawn` 失败）`exitCode` 是 `null`；退出码 0 却认不出最后一行（别的路径、空输出）：`failed`，**不当成删好了 / 切好了**；`switchSessionOrg`：帮手说没切成带上「现在挂的是哪一类」和原话，超时被停：不知道挂的是哪个，**等帮手的时限比帮手自己的总时限长**（不会切到一半被这里掐掉）；`listAgentScopes` 认不出的行、帮手报错、帮手起不来：明确失败，不当成一个都没有。
20. **「现在挂的是哪一类」有且只有一份口径**（`currentOrgOf`，引擎、额度读取器、切号帮手同一个）：`reclaude org list` 里带 `*` 的恰好一行、类型认得出（`team`＝拼车、`personal`＝独享）才算；**一行都认不出、没有带 `*`、带 `*` 的不止一行、类型认不出：一律认不出，不挑一个、不猜**；只留类型和是否当前，编号、名字、邮箱不往外带。——`quota/claude.test.ts`；`quota/readers/claude.ts`。

**C. 额度读取器（`quota/`，约 150 条测试）**

21. **一轮读完所有账号池，每个池一定有一条结果**（`read-all.ts`）：读成的、读到 0 个窗口的、没读成的分得清；各读取器并发、各自有超时（卡住的那个到点给 `timeout` 并收到叫停信号、别的池不受影响）；读取器自己崩了记成 `crashed`、错误信息先脱敏；读取器交回来的数再过一道（别的池的、重名的、不是有限数的丢掉并写明，不静默）；**交回来的窗口一个都不合格：`bad_response`，不许变成「读成了、0 个窗口」**；外部能力（进程、网络、文件）**必须显式注入**（`productionQuotaIo()`），库函数不自己去碰真进程、真网络、真文件，没注入当场抛错；配置里读取器类型不认识：这个池报 `config`、别的池照读；同一 key 的共用调用只跑一次。命令行退出码：0 全部读到、1 有池没读成（表里写原因）、2 配置或参数不对。——`read-all.test.ts`、`cli.test.ts`。
22. **读数的诚实**：「读到 0 个窗口」≠「没读成」（上游说 `ok` 而窗口为空：零个窗口正常返回）；`usage.ok` 不为真报 `upstream`、不填默认窗口；**上游改了字段名、一个窗口都认不出：`bad_response`——不能把 97%、99% 的池报成「没有窗口」让调度当成不限额**；个别窗口缺数：那一格不收并写明、其余照收，全坏才算失败；缺数字但带着 `limit_reached` 的窗口不丢（只留状态字，调度照样看得见它满了）；点数缺了、百分比还在：按「已用 + 剩余」认刻度，认不出刻度就不收；以**上游状态字为准**（`7d_fable` 用到 99.04% 上游就说 `limit_reached`，`7d` 到 85% 就 `warning`；Claude 的写法：`rejected`＝已满、`normal`＝正常、`critical` 只是很紧），认不出的状态字不归类不猜、只留原字；利用率按「已用 ÷ 上限」算、不看上游百分比的刻度（0–1 还是 0–100）；没给清零时刻按 `resetAfterSeconds` 从采样时刻推；上限每次都从这一帧重读（官方改档后按新上限算）。——各 `quota/*.test.ts`。
23. **窗口归类：集合不固定，认不出的也收下**（`windows.ts`）：`5h`/`7d` 是账号级窗口；`7d_<组>` 是只扣这一组模型的周窗口；没见过的时长或形状归 `other`（原名留在 `label` 不丢）；标了模型组却没有组名的整个标签当组名、不当账号级；**账号级窗口卡所有模型，`7d_fable` 只卡 id 里含 fable 的**；模型 id 去掉了厂商前缀时按模型族认组；**有成员表的组按成员表、不按名字猜**（Cursor 的 auto 与 api 桶）；分隔符写法不同也认得出。——`windows.test.ts`。
24. **各家读法**：
    - **Claude 订阅（经 reclaude，`claude.ts`）**：跑 Claude Code 自带的 `/usage`——无头模式下是**本地命令**、不调模型、不花额度（实测 `num_turns 0`、`cost 0`；**每次都核实没花钱**：花了 $0.41 报 `read_cost`、读数不采信；没有 result 行核实不了 `bad_response`）；`stream-json` 里带结构化 `usage_report`（服务端给几行就是几行，新出的窗口不用改代码就收：`kind` 原样当名字、按 `kind` 归类不按展示文字）；`rate_limits` 为空值＝Claude Code 没拿到、报错，`limits` 为 `[]`＝服务端明说没有额度行、零个窗口；额外用量开着：按月美元窗口，金额从美分换成美元并提醒会花钱；**只读「这台机器当前挂的组织」，读取器绝不切号**（当前是独享：独享池实读、拼车池报 `not_current`；读的过程中组织被切走：这次读数作废、不记到错的池上）；工作目录固定为同一个私有空目录（不加载别人的项目设置、不每读一次留一个项目目录；里面有东西就不用、抛错）；不带 `--bare`、只加载项目级设置；没登录、起不来、超时各给明确原因；没给 `orgKind` 时不跑 `org list`。被动读：真会话过程记录里的 `rate_limit_event` → 窗口读数（零成本，不另起探针；事件里一个能记的窗口都没有——API key 会话就不带窗口——返回 `undefined`＝没读到、不是 0%）。
    - **reclaude 拼车组织（`reclaude.ts`）**：reclaude 开放接口（网页「设置 → API Key」那把，Bearer，只读 GET），读的是**每个拼车成员另设的 5 小时美元上限**——`/usage` 看不见它（`/usage` 显示 16% 时真实请求已被拒过，design 第九节）；Key 是账号级的：不看这台机器挂哪个组织、不起 Claude Code；独享组织的用量这套接口不给、仍走 claude 读取器；上游明说没设上限：零个窗口并写明；开没开认不出、金额缺或不是数 `bad_response`；到期日取唯一的拼车组织（几个就不猜）；组织列表说拼车池用不了（没有拼车组织、没分到账号、已到期）抛 `upstream`；Key、编号、邮箱一个字都不往外带。
    - **Cursor（`cursor.ts`）**：Dashboard 只读接口（网页「用量」页用的同一套），已登录的 accessToken，不起对话；一个账号分两个桶：**Auto（含 Composer 等自家模型，成员表由接口给）**与 **API（点名的其它模型）**，各有百分比，另有账期美元；清零时刻＝账期结束；`totalPercentUsed` 是合成数不单独当窗口；以后多出来的桶（`xxxPercentUsed`）照收；只 POST 白名单里的只读方法；401 要重新登录（`auth`）、连不上 `unreachable`、没有登录文件 `no_credentials`；只剩账期美元、桶的百分比找不到：照收但写明按桶卡不住。
    - **Grok（`grok.ts`）**：读 `grok` CLI 里 `/usage` 弹窗用的账单接口 `billing?format=credits`，只读 GET，CLI 已登录的 OAuth 令牌；**令牌过期不自己续**（续期会轮换 `refresh_token`，CLI 手里那份就作废了），过期只报「要让 grok 自己续一下」（`auth`）；这一期的总用量收成一个周窗口；没见过的账期类型归 `other` 原样收并写明；缺总用量 `bad_response`、不填 0；订阅回包里的身份信息一个字都不往外带。
    - **Mirasim 中转（`mirasim.ts`）**：问本机 `mirasim-server` 一句 `getRelay`（桌面端显示额度用的就是它），零次上游调用、不花额度；一份账号额度被所有走中转的路由共扣（5h、7d），另有只扣某一族模型的窗口（`7d_claude`、`7d_fable`…，集合不固定：09-06 的帧没有 `7d_claude`、09-24 多出来的照收）；令牌只进 URL；令牌文件不在 `no_credentials`（写明是服务没跑还是没权限）；连不上回环端口 `unreachable`、令牌不进错误信息；服务端一直不回 relay 帧到点 `timeout`。
    - **估算（`estimate.ts`）**：官方接口和网页接口都读不到时，按我们自己的用量记录估「用了多少」，**一律标 `estimated`**；固定窗（从 `anchor` 起每 `periodHours` 一格，清零时刻可算）和滚动窗（往回看 `periodHours`，没有单一清零时刻）；缺金额的记录不硬算、写明是下限；模型组窗口只算本组；Jev 日账（旧系统 `~/.dao/judge-spend` 的形状，每个 UTC 日一条、金额＝tokens × 每百万单价）：**日账目录不在：`no_usage_source`——不许按「今天用了 $0」算，否则每日上限永远不触发**；日账文件坏了或缺 tokens：`bad_response`、不跳过；目录在、这段时间一条记录都没有：照算 0 但写明这只是下限。
25. **配置**（机器配置，不进 git）：从 `FLEET_QUOTA_CONFIG` 指的文件读（默认 `/etc/fleet-dao/quota.json`；仓里只有 `deploy/examples/quota.example.json`，六个池一个不少）；校验**一次列全、不撞到第一个就停**：拼错的键、重复的池、没有的读取器都报出来；Claude 的环境变量按前缀禁 `ANTHROPIC_*`，另禁 `CLAUDE_CODE_OAUTH_TOKEN`；估算窗口要写全（时长、单位、上限）；文件不在报错并指向样例、不是 JSON 报错；`_` 开头的键当注释放行、空的 `pools` 不行。——`quota/config.test.ts`。
26. **`redact`**：凭据和身份在进日志、进库、进驾驶舱之前先抹掉再截到末尾 max 个字：Bearer 令牌、邮箱、JWT、`sk-` 密钥、查询参数里的令牌、IP、40 位以上的长串、`tvly-`、`AKIA` 开头的 AWS 密钥、32 位十六进制、`rck_` 开头的 reclaude Key；几个邮箱连着写、邮箱和密钥之间没有分隔：都要抹干净（先抹密钥后抹邮箱；和旧写法对拍随机两万条结果一样）。——`quota/util.test.ts`。

## 六、怎么算做完（重做之后）

1. 新增一家 AI 只需要：一个 `args`、一个 `stream` 读取器（对着真跑夹具）、一个 `run`、在 `judge.ts` 里已有的优先级下判定；不许改 `judge` 的优先级。
2. 额度读取器补齐 Mirasim、Grok、Cursor 三家的定时读入库；每家的「读不到、认不出、改了字段名」都有故意失败用例，且**不许报成 0 个窗口**。
3. `pretool.mjs` 钩子登记随钩子一起删（代码、测试、`claude-guard-e2e`、文档）。
4. 会话脱开引擎、交付判据、测试结果只认可信退出码这三条保持，它们是「工人干完等 CI」的地基。
