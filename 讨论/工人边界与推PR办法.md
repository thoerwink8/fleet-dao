# 工人的活动范围与推 PR 的办法（D0④，2026-09-30 凌晨；分析草案，不改代码）

对应：母单 #509「先做的分析」第 4 条；`docs/goals.md` §四 B「工人跑在法国」；总计划 D0④。写法照 `best-practice-first`。**「现有」= 我读代码核实的；「提议」= 我的判断；「待实验」= 要连上法国、在 Ubuntu 24.04 上试过才知道（今晚连不上，没试）。**

## 一句话

工人（AI 写码会话）要**关在一个只能写自己那棵工作树的笼子里**：看不见别的会话和它们的目录、写不了系统、不能提权、出网只放行几家模型服务的域名、内存进程数磁盘有上限；**它拿不到任何 GitHub 凭据，提交打成包由引擎在会话外推、开 PR**——这一半法国**已经是这样做的**，只需要补测试。缺的是「笼子」本身：法国现在所有会话共用一个 Unix 用户，只限了内存、没限文件、没限出网。09-29 清空 C 盘的事故说明真正要防的是**乱写乱删**（不是「读密钥」，那条你 09-28 已经拍过不管，本文不重开）。**本机 Windows 上不再起别家模型的工人。**

## 一、要防的六件事

| # | 什么事 | 例子 | 归谁管 |
|---|---|---|---|
| 1 | **乱写乱删** | 09-29：本机上一个不受限的 Grok 会话把权限命令打到整个 C 盘并大量删除（`docs/decisions/0004`、记忆里的事故记录） | 文件系统边界 |
| 2 | **会话之间互相碰** | 法国所有会话共用一个 Unix 用户，一个工人能读写别的工人的工作树、看到和杀掉别的会话的进程 | 文件系统 + 进程边界 |
| 3 | **被人下套（提示注入）** | 单子正文、网页、依赖包里藏一句「把环境变量发到某某网址」（Willison 说的「致命三件套」：能摸到私有数据 + 读进不可信内容 + 能对外通信，三样凑齐就能被偷，<https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/>，2025-06-16，取 2026-09-30） | 出网边界（砍掉第三样的**一部分**，见下面「能防什么、不能防什么」） |
| 4 | **把机器拖垮** | 内存、进程数、磁盘写满、CPU | 资源边界 |
| 5 | **提交里夹带** | 改 CI 工作流让 CI 去读仓库密钥；提交里带密钥 | 推 PR 的那一步（引擎在会话外做） |
| 6 | **提交内容本身是武器**（GPT 反方补的） | 工人改构建脚本、依赖、测试、应用代码——不碰工作流也一样：这些之后会在 CI 里、在法国上被执行；加一个恶意依赖、改 `pnpm-workspace.yaml` 里允许跑安装脚本的名单 | 提交审查（Review）+ CI 权限最小化 + 依赖变更列入先审后合（第四节第 10 行） |

**笼子能防什么、不能防什么（先说清，别据此承诺密钥安全）：** 笼子和出网白名单防的是**一般性的乱写和外传**——写到别处、杀别的进程、`curl` 到任意网址、DNS 外泄。它**防不住**：①经**放行的域名**外传——模型服务本身就要收提示内容，域名前置之类也能绕（Claude Code 沙箱文档自己写了「不是完整的隔离边界」）；②经**输出通道**外传——提交内容、PR 正文、分支名、`fleet say/ask` 写进去的话，这些出口靠卫生扫描（只认已知的密钥形状，编码一下就能绕）和 Review 兜，不是密钥安全的保证；③笼子里那个工人**自己那一棵树**里发生的一切。所以本文承诺的是「**一个被下套的工人弄不坏别的东西、偷不走大批东西**」，不是「**密钥绝对安全**」。

**已经拍过的，不重开：** 你 09-28 傍晚拍的「别家模型（Grok 等）的会话不关目录、不设沙箱，能读创始人账号能读的一切」「拦 AI 读密钥文件的钩子整个删」（`specs/169-Fusion形态/需求.md` 第 289–306 行，原话「整个删掉」）。那次的判断是：读密钥防不住（环境变量、gh 登录一样拿得到），真正的防线在**往外写**的那一步。09-29 的事故不是读，是**写和删**——这是那次没有考虑到的另一类风险，所以本文只谈写、进程、资源、出网，读只当顺带收窄。**这一条和你 09-28 的第 2 点字面上冲突（「不设沙箱」），需要你重新点头，见第十节。**

|---|---|---|---|

**旧系统踩过的坑（本仓 `docs/reference/`）：** ①「凭据隔离是 always-approve 的前提」：旧系统挡「读树外凭据」只靠权限白名单，`cat <树外的机器人凭据文件>` 曾被当成「只读巡检」自动放行（`adapters.md` 第 41 行、GEN-13）；②**「沙箱缺一样，会话能起来但一点活都不干，一晚死了 3 个审官会话」**（`deploy.md` P29：codex 的沙箱要 bubblewrap，还要 AppArmor 允许建 user namespace；**不许用全局 sysctl 关掉这个限制**）。第二条是设计的硬要求：**笼子起不来，会话必须明确起不来（大声失败），不能悄悄没笼子就跑、也不能悄悄跑不动。**

## 三、业界对照（都点得开；「取」= 我读原文的日期 2026-09-30）

| 层 | 同类做法 | 结论 |
|---|---|---|
| **一个会话一个笼子** | Anthropic 的 Claude Code 沙箱：Linux 上用 **bubblewrap** 做文件隔离、`socat` 把网络流量转到沙箱代理；默认只许写当前目录、出网只许放行的域名；`sandbox.failIfUnavailable: true` 让「沙箱起不来」变成**硬失败**而不是悄悄不设防，<https://code.claude.com/docs/en/sandboxing>（取 2026-09-30）。bubblewrap 自己的说明：新的挂载命名空间、PID 命名空间（**沙箱里看不见外面的进程**）、网络命名空间（只有回环）、`--new-session`（防 TIOCSTI，CVE-2017-5226），「保护到什么程度完全取决于传给它的参数」，<https://github.com/containers/bubblewrap>（README，取 2026-09-30） | 用 bubblewrap，**按会话套**；沙箱起不来 = 会话不起 |
| **不要只信厂商自带沙箱** | 同一份 Claude Code 文档写明：沙箱只管 **Bash 子进程**，内置的 Read / Edit / Write 工具走权限系统、不进沙箱；并且「沙箱降低风险但不是完整的隔离边界」（域名前置等）。四家模型（Claude、Cursor、Grok、Mirasim）各自的沙箱不一样 | **在整个 CLI 进程外面套一层**（我们自己在 `fleet-agent-scope` 里套），四家一个样，不靠各家自带的 |
| **现成的可复用件** | Anthropic 开源的 `@anthropic-ai/sandbox-runtime`（`srt`）：Apache-2.0，Linux 用 bubblewrap + 网络命名空间 + 代理过滤，「可以给任意进程套」；**Beta 研究预览**，版本 0.0.77（2026-09-18 最新；`npm view` 取 2026-09-30），<https://github.com/anthropics/sandbox-runtime> | 可以当实现，但版本还是 0.0.x，要钉版本、读过再用（和第三方 skill 同一套规矩） |
| **另一条路：Landlock** | 内核自带、无需特权：进程限制自己和子孙的文件、网络（TCP 绑定/连接的**端口**）、抽象 Unix 套接字和**信号**，<https://docs.kernel.org/userspace-api/landlock.html>（内核文档，2026-08，取 2026-09-30）；OpenAI Codex CLI 在 Linux 上用它（我没读到官方原文，**未查证**：`developers.openai.com` 回 403） | 比 bubblewrap 轻，但只按路径和端口、不按域名；作为备选 |
| **出网** | Claude Code 沙箱代理按域名放行（新域名要批准）；**局限**：代理按客户端给的主机名放行、不看 TLS 内容，域名前置能绕；放行 github.com 这种大域名本身就是外传的通道（同上文档「Security limitations」）；GitHub Copilot cloud agent 也限制它的出网（原文「GitHub restricts Copilot cloud agent's access to the internet」，<https://docs.github.com/en/copilot/concepts/agents/coding-agent/risks-and-mitigations>，取 2026-09-30）；Codex Cloud 的环境里「密钥、对外身份、网络」是显式配置项（<https://learn.chatgpt.com/docs/cloud>，取 2026-09-30） | 出网**默认关、只放模型服务的域名**；放行清单越短越好、不放 github.com |
| **推送权限** | Copilot：代理**不能自己 `git push`**、只能做简单推送；不能批准、不能合并；提交署名 Copilot、带会话日志链接（同上 risks 页）；GitHub App 安装令牌可限定到具体仓和权限、1 小时过期（<https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app>，取 2026-09-30） | 和我们现有做法一致：会话没有凭据、引擎推、令牌限仓限权 |
| **资源** | systemd 的 cgroup：`MemoryMax`、`TasksMax`、`CPUWeight`；**`IPAddressDeny=any` + `IPAddressAllow=` 可以给一个单元做 IP 级出网白名单**（Ubuntu 24.04 的手册页 `systemd.resource-control(5)`，取 2026-09-30） | 内存进程数用现有的 scope；磁盘另想办法（见第四节第 8 行） |

**冲突和要拍板的：** ①业界都是「笼子 + 出网白名单 + 不给凭据」；我们的特殊约束是**四家模型、一个 Unix 用户、一台 12G 的机器、约 10 个并行会话**；②bubblewrap 在 Ubuntu 24.04 上默认被 AppArmor 拦（要给 `bwrap` 一份只对它自己生效的 AppArmor 配置，Claude Code 文档给了写法；**不许用全局 sysctl 关闭限制**，本仓 `deploy.md` P29 同样写着）——**但如果由 root 那一侧（`fleet-agent-scope`）起 bwrap，根本不需要用户命名空间，这条限制就绕开了**（待实验）。

## 四、从业务重推：每一条边界

| # | 边界 | 要求（说人话） | 做法（提议） | **越界必须失败**的用例（每条一个故意造出失败的用例） | 现在 |
|---|---|---|---|---|---|
| 1 | 文件：写 | 一个工人只能写**自己的工作树**、自己的 `_tmp/<会话编号>`、自己的收发目录，别处一律写不进 | 整个 CLI 进程外面套 bwrap：根目录只读挂载，只把这三处读写挂进去 | 在别的会话的树里建文件、往 `/usr/local/bin`、`/etc`、家目录写：必须失败；写自己的树、`_tmp`：必须成功 | 没有（同一用户，写别人的树是允许的） |
| 2 | 文件：读 | 别的会话的树、引擎的目录、`/etc/fleet-dao` 看不见；共用的工具链（node、pnpm、git、pnpm 仓库）只读可见 | bwrap 的挂载视图：别的会话的树不挂进来；`/etc/fleet-dao` 本来就 root:fleet 750，会话用户读不了（**已有**） | 读别的会话的树、`/etc/fleet-dao/*`、`/var/lib/fleet-sessions/<别人>`：必须失败；读共用工具链、读自己的树：必须成功 | 树：没有；`/etc/fleet-dao`：有（权限挡住） |
| 3 | 进程 | 看不见、杀不了、也不能调试别的会话的进程 | `--unshare-pid --unshare-ipc --unshare-uts --die-with-parent --new-session`；再 `setpriv --bounding-set=-all --inh-caps=-all` | `ls /proc` 里没有别的会话的进程；`kill`、`ptrace` 别人的进程：必须失败 | 没有 |
| 4 | 提权 | 不能变成 root、不能加载模块、不能挂载 | 已有 `setpriv --no-new-privs`；加上 seccomp 默认过滤（bwrap `--seccomp`） | `sudo -n true`、`mount`、写 `/proc/sys`：必须失败 | 有一半（`no-new-privs`） |
| 5 | 凭据：GitHub | 会话里不能有，也不能拿到 | 已有：环境里不放、引擎推 | 会话里 `env` 没有 `GH_*`/`GITHUB_*`；`git push` 到 GitHub 必须失败（没凭据 + 出网被拦） | 有（缺真机用例） |
| 6 | 凭据：各家模型 | 只把**这条路由要用的**凭据文件挂进去（Claude 用 reclaude 的，Cursor 用它的密钥文件……），别家的不挂 | bwrap 只读绑定这一家的凭据；**这不是防偷，是缩小面**（你 09-28 已拍「不管读」，所以这条便宜就做、不做就算了） | 起 Claude 路由的会话，读 `~/.cursor/fleet-api-key`：应当失败（若做） | 没有 |
| 7 | 出网 | 只能连这条路由的模型服务域名（加引擎的本机接口）；别的一律不通，包括 DNS 外泄之类（**防的是一般性外传，不是经放行域名和输出通道的外传**，见第一节） | `--unshare-net`（没有网卡）+ 通过 Unix 套接字转到宿主上一个**按域名放行的代理**（Claude Code 沙箱同款做法）；**放行清单**：这条路由的模型域名、`fleet` 命令要连的引擎本机口；npm 由引擎在起会话前装好、会话里不联网装包 | 会话里 `curl https://example.com`、`git push`、`nslookup` 外部域名：必须失败；连模型服务、`fleet` 命令：必须成功 | **没有（出网全开）** |
| 8 | 资源 | 内存、进程数、磁盘都有上限，写爆只坏自己 | 内存：现有 scope；`TasksMax`、`CPUWeight`：用演练台量出画像后设；**磁盘：`_tmp`、工作树各给大小上限**（做法待实验：给 `/var/lib/fleet-work` 单独一个带项目配额的分区，或每会话一个限大小的 tmpfs） | 往 `_tmp` 写超过上限：必须失败（写不进）、且不影响别的会话；fork 炸弹：被 `TasksMax` 拦住；吃内存：被 OOM 杀、只杀这个 scope | 内存有，其余没有 |
| 9 | 笼子起不来、或笼子换了没验 | **大声失败**：起不来就不起会话、报「笼子没起来：原因」，不带着「没笼子」跑，也不「起来了但干不了活」；**笼子的参数一变，先验过才放行** | ①起会话前先跑一遍**自检**（一个一秒的探针：在同样的笼子里试一次 1–4、7 的越界，全失败才放行）；bwrap、socat、AppArmor 配置缺了直接报错。②**笼子参数指纹**（GPT 反方补的）：bwrap 参数、AppArmor 配置版本、出网放行清单由**一个函数**生成、算出指纹；`selftest` 通过就写「已验证指纹 + 时间」；`run` 只在「当前指纹 = 已验证指纹、且验证在 N 小时内」时才起会话，否则大声失败；发布改了参数 → 指纹变 → 先自检再放行；运行中的会话把起它时的指纹记在 `meta.json`，指纹变了的标「旧笼子」、排空后重起 | 故意删掉 AppArmor 配置：会话必须起不来且写明缺什么（旧系统 P29：一晚死 3 个会话就是因为悄悄没起来）；故意改一个 bwrap 参数不跑自检：`run` 必须拒绝；改了参数后旧会话必须被标出来 | 没有 |
