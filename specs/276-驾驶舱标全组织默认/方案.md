# 驾驶舱标出「用的全组织默认」（#276）
> 本文档是历史原话，一字不改。按库里的 tasks.flow_source 和 repos.flow_* 标「全组织默认」已被后来的决定取代：这两处随 Fusion 一起删，驾驶舱按个人用重做。现行口径见 [#509](https://github.com/thoerwink8/fleet-dao/issues/509) 和 `docs/goals.md`。


对应需求：`specs/276-驾驶舱标全组织默认/需求.md`。库里已经记下了（#214）：每张单这一轮读自哪是 `tasks.flow_source`，每个项目此刻的副本是 `repos.flow_*`，能不能派由 `packages/core/src/replica.ts` 的 `replicaVerdict` 判。这张单只把这两样接到驾驶舱接口和页面上，不改判法、不加列。

一句话：卡片和详情只在「这一轮用的是全组织默认」时挂小标；看板顶上另写这个项目此刻的副本，停派与否只调 `replicaVerdict`，页面不自己算 45 分钟。

## 两套来源不要混

| 看哪里 | 数据 | 什么时候变 |
|---|---|---|
| 任务卡片、任务详情的小标 | `tasks.flow_source`（这一轮开工时写下的） | 仓里后来加了、删了 `.fleet/flow.json` 不回头改 |
| 看板顶上那一栏 | `repos.flow_source` / `flow_commit` / `flow_synced_at` / `flow_error` / `flow_unread`，停派与否用 `replicaVerdict` | 对账每 15 分钟重写副本 |

所以会出现：顶栏已经是「读自仓里」，旧单上还有「全组织默认配置」。这是对的，不要用项目此刻的副本去填单上的标，也不要反过来。

## 接口

`packages/shared/src/web-api.ts`：

- `FlowSourceSchema = z.enum(['project', 'org_default'])`。
- `TaskSchema`、`BoardTaskSchema` 各加可选 `flowSource`。库里是空的就不给这个字段，不给 `null`，也不拿 `project` 顶。
- `BoardResponse` 加必填 `flow`：

```ts
flow: {
  source?: 'project' | 'org_default'; // 从没同步成过就没有
  commit?: string;                    // 提交前 7 位，不足 7 位原样，不加省略号
  syncedAt?: string;                  // ISO，前端用现成的 formatAgo 显示「几分钟前」
  paused: boolean;                    // replicaVerdict 不通过
  why?: string;                       // 停派原因，就是 replicaVerdict 的 why，不改写
}
```

`paused` 和 `why` 同有同无（schema 用 `discriminatedUnion` 钉死）。判得过（`paused: false`）时 `source`、`commit`、`syncedAt` 必须都有；缺了就让 `reply` 走现成的 500 `bad_response_shape`，不许填 `project`。

领域对象 `packages/shared/src/domain.ts` 的 `Task` 加上可选 `flowSource`。`packages/db/src/domain-map.ts` 的 `toTask` 把列上的空映射成不填（`null` → 丢掉，和现有 `build` 一样）。任务详情现在是把 `getTask` 的对象整份交给 `TaskDetailResponse`，字段加上之后会自己带上。

看板那一栏不塞进 `RepoSchema`（仓列表不该带停派原因）。`BoardStore` 加 `getRepoFlow(repoId)`，没有这个仓回 `null`，有就回这五列的原值（提交是全长，截到 7 位在视图里做）：

- 内存版：`RepoRecord.flow` 在现有 `FlowReplica` 上多带可选的 `source`、`commit`。`repoOnly` 已经把 `flow` 剥掉，仓列表接口不会漏出去。
- Postgres 版：从 `flowReplicaOf` 读，时刻转成 ISO。
- `packages/api/test/pg-fixtures.ts` 的 `flowColumns` 优先用内存对象上的 `source` / `commit`；没写时维持今天的做法（同步过就写成 `project` 和 40 个 `f`），这样旧夹具两个 Store 仍然一致。`dev-fixtures` 的样例仓要显式写成 `project` 加一条 40 位提交，五分钟前同步、没有 error。

`packages/api/src/views.ts` 新增 `boardFlow(row, now)`：把行收成 core 的 `FlowReplica`（`testCommand` 填 `null`，判停派用不上它）交给 `replicaVerdict`。`buildBoard` 把每张单的 `flowSource` 抄上去（没有就省略键），并把 `boardFlow` 的结果放进 `flow`。`cockpit.ts` 的看板处理里先 `getRepoFlow`，仓不存在仍是现在的 404。

## 页面

新组件 `packages/web/src/board/flow-source.tsx`，两处共用：

1. **小标** `OrgDefaultMark`：只有 `flowSource === 'org_default'` 才渲染，文案固定「全组织默认配置」。悬停用现成的 Tooltip，点开用 Popover，同一句（手机没有悬停）。点的时候 `stopPropagation`，免得把卡片的选中、跳转一起触发。句子由品牌拼出来，正式版必须一字不差：

   > 这个项目没有 .fleet/flow.json，这一轮按 fleet-dao 的全组织默认流程配置派（每步模型顺序、验证几轮都用默认的）

   `project` 和空都不渲染。不要用失败红（红只留给停派）。

2. **顶栏** `FlowBanner`：放在 `routes/board.tsx`，桌面画布和手机树形列表的上面都有，不放进画布绝对定位的工具条（工具条会挡住，手机树又没有它）。区域 `aria-label="流程配置"`。
   - 没停派、`source === 'project'`：`流程配置读自仓里 · {commit} · {formatAgo(syncedAt)}`
   - 没停派、`source === 'org_default'`：`流程配置用的全组织默认 · {commit} · {formatAgo}`
   - `paused`：标红（沿用 `text-ink-fail` / `border-st-fail`），主文「这个项目停派」，下面整段 `why`。还有 `commit` 和 `syncedAt` 时，淡字补「上次读成：{commit} · {formatAgo}」。

挂小标的位置：

- 画布卡片 `nodes.tsx` 的中景、近景标题行（状态胶囊旁边）。远景只有色块和数字，不塞字。
- 手机列表 `board-tree.tsx` 的 `TaskRow`。
- 看板侧栏详情 `detail-panel.tsx` 的标题行。
- 任务详情页 `routes/task-detail.tsx` 的标题行，读 `detail.task.flowSource`。`boardTaskOf` 拼兜底卡片时把这个字段抄上，免得看板还没到、小标闪一下没有。

手机宽度用现成的 `useIsMobile`（`max-width: 767px`），375 会走树形列表，不要把桌面画布缩小来冒充。

## 定下的（这张单里自己定的）

1. **停派只在后端算。** 页面只显示 `paused` 和 `why`。网页不依赖 core，避免演示包扫出 `.fleet/flow.json`。假数据写死三种样子，不在假后端重算 45 分钟；太久没同步的失败测试放在 `boardFlow` 的单元测试里。
2. **远景卡片不挂小标。** 远景只剩色块和数字，字会挡；中景、近景、手机列表、两处详情都挂。点开详情仍看得到。
3. **任务清单页不挂。** 需求点的是卡片、详情、看板顶上。清单是表。
4. **顶栏放在画布外面。** 桌面、手机同一块，项目页 #131 做好之前就放这里。
5. **文案走品牌。** 正式版用需求里的原句；演示版换掉会让扫描失败的那两个词，意思不变。

## 怎么验证

- `boardFlow`：`org_default` 且刚同步过 → `paused: false`、提交是前 7 位；`error` 非空 → `paused: true`，`why` 含那段错误和「改好仓里的」；`syncedAt` 早于 45 分钟 → `paused: true`，`why` 含「分钟没同步成」；`syncedAt` 空 → `paused: true`，没有 `source`；判得过但 `source` 空 → 不返回 `paused: false`，也不填 `project`（交给 schema 变成 500，或函数直接拒绝，二选一，失败要看得见）。
- 接口（内存版驾驶舱，`cockpit.test.ts`）：把一张单的 `flowSource` 设成 `org_default`，任务详情和看板都带 `flowSource: 'org_default'`；【失败】另一张是空的，JSON 里没有 `flowSource` 这个键；把副本的 `error` 设上，看板 `flow.paused === true` 且 `why` 含这段错误。`store-contract` 两边都读得到样例仓的 `source: 'project'` 和全长提交；没有的仓是 `null`。
- 页面：`org_default` 渲染「全组织默认配置」，`project` 和空不渲染；顶栏三种文案各有一条组件测试。演示品牌的文件名、组织名过 `scanText`，不含 `fleet`。
- 截图：`pnpm --filter @fleet-dao/web dev:mock`，顶栏切三个仓。电脑 1280 宽、手机 375 宽（确认走的是树形列表）各一张，共六张，放进 `specs/276-驾驶舱标全组织默认/截图/`，`结果.md` 嵌上。orbit 那张上看不到小标，canary 那张上卡片有小标。没有浏览器就照实写没截成，不要造图。
- `pnpm exec tsc -b`，再跑上面点名的测试。`node packages/web/scripts/demo.ts build` 必须过。
