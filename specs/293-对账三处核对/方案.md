# 方案：每小时对账补上三处核对（#293）

需求见同目录 `需求.md`。三项都做成每小时对账（`packages/engine/src/jobs/hourly-reconcile.ts`）的新部分，和已有的「工作树」「提醒」两部分并列：各返回一个 `SweepPart`，由 `combineParts` 并成这一轮的结局；提醒自己报、自己撤（不进 `alert-sweep.ts` 的判法表，只在它开头「谁来撤」的清单里补一行）。

## 一、开着的单都有工作流

- 新查询 `activeTaskRefs(db)`（`packages/db/src/queries/reconcile.ts`，从 index 导出）：没结束（不在 `TERMINAL_TASK_STATES`）的任务，带仓的 owner/name、issue 号、state、`updatedAt`。
- 判法（`packages/engine/src/jobs/reconcile-checks.ts` 的 `checkWorkflows`）：
  - `queued`：跳过（没派是有意的：不在当前版本、母单子单、开关关着；派没派得出去由接活和投递重放管），计进 scanned。
  - 其余没结束的状态（triaging、asking、planning、running、merging、stalled）：问 `WorkflowReader.state(requirementWorkflowId(...))`；`running` 没事；`closed` / `missing` 且任务 10 分钟内没更新过（避开工作流刚收尾、状态还没写的那一下）→ 报 `reconcile:workflow:<taskId>`（alert 级、带 taskId 和 issue 链接，正文写库里状态、工作流怎么了——`notRunningWords`）。不自动重起：重起会和残留的会话、分支撞，要人判。
  - 问 Temporal 抛错：这一张记进 unchecked，这张的旧提醒不撤。
  - 撤：开着的 `reconcile:workflow:*` 里，对应任务这一轮查成了且没事（在跑、已结束、回到排队、库里没了）的撤掉，写原因。
- 为什么不从 GitHub 列开放 issue 再查：库里的任务行已经由对账补漏（每 15 分钟）按白名单开放 issue 补齐；这里只查「任务行 ↔ 工作流」这一段，不重复读 GitHub。

## 二、合了的 PR 都记了账

- `packages/github/src/reconcile.ts` 已有 `auditMergedPrs`（镜像没记成 merged 就补、查合并人、查合并队列记录），但一直没接上；它的「合并人必须是引擎」「必须有合并记录」对人开的 PR（帅位本机开、GitHub 自动合并）会误报。改成：镜像那一项对所有合并的 PR 都查（能安全自动补），合并人和合并记录只查我们两个机器人开的 PR（`deps.bots.is('engine'|'agent', 作者)`）。同步改它现有的测试（`packages/github/test/` 里调它的几处），加一条「人开的 PR 不报合并人」。
- 在 `GitHub` 接口（`packages/github/src/github.ts`）加 `auditMergedPrs(repoFullName, since)`，直接调同一份实现（不用为它造接活的 intake）。
- `checkMergedPrs`：逐个受管的仓（新查询 `reconcileRepos(db)`，同一个文件）调它，since = 现在往回 26 小时（每小时一轮，漏一天以内都补得回）。scanned 加审到的 PR 数，found 加发现的；`fixed` 的写日志不报警；没补上的问题（合并人不对、没有合并记录）按 PR 报 `reconcile:pr:<owner>/<name>#<号>`，用 `insertOnce`（出了回看窗口就查不到了，不自动撤，要人点处理）。仓的结果是 unscanned、partial 的写进 unchecked。

## 三、每个账号池的额度读数不超过 30 分钟

- 直接用 `quotaTable(db, { now })` 的 `readOverdue`（和驾驶舱、选路同一个判法），只看 `channelEnabled` 的池。
- 过期的汇成一条 `reconcile:quota-stale`（alert 级，`raise` 原地更新）：列每个池、「从没读成过」或「上次读成在 北京时间 X（Y 前）」、上游数据冻住的另写。一个都不过期就撤。读不了额度表记 failed 这一部分。
- 现在没有定时读额度（#76 没做），上线后多半所有池都会报：这就是真相，一条汇总提醒，不按池刷屏。

- `hourly-reconcile.ts`：deps 加 `activeTasks`、`repos`、`auditMergedPrs`、`quotaPools`；`round` 在提醒那部分之前跑三项核对（新报的提醒这一轮不被再推）；`HOURLY_RECONCILE_JOB.name`、文件头注释、`unscanned` 的原因改成五项。
- `real/hourly-reconcile.ts`：接上面几个查询，`gh` 从 `real/index.ts` 传进来（`githubReconcile` 已经有它）。

- `docs/design.md` 第六节第 4 层：改成已做三处核对、各自怎么判，去掉「上面举的三处核对不在它里面」。
