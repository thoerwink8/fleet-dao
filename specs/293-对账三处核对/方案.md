# 方案：每小时对账补上两处核对（#293）

需求见同目录 `需求.md`（以主线上帅位 2026-09-27 重写的那份为准：本单只做两处，额度读数那处随 #76）。两项都做成每小时对账（`packages/engine/src/jobs/hourly-reconcile.ts`）的新部分，和已有的「工作树」「提醒」两部分并列：各返回一个 `SweepPart`，由 `combineParts` 并成这一轮的结局；提醒自己报、自己撤（不进 `alert-sweep.ts` 的判法表，只在它开头「谁来撤」的清单里补一行）。判法在 `packages/engine/src/jobs/reconcile-checks.ts`。

## 一、开着的单都有着落（`checkWorkflows`）

- 查询 `activeTaskRefs(db)`（`packages/db/src/queries/reconcile.ts`）：没结束的任务，带仓的 owner/name、issue 号、state、`updatedAt`、项目「让 AI 接活」开没开（`repos.auto_dispatch_since` 不空）。
- 项目接活关着的单：不查、不计 scanned；它的旧提醒撤掉（「这个项目「让 AI 接活」关着」）。
- 其余的问 Temporal 它的需求工作流：在跑就有着落。问不了：这一张记没查成，旧提醒不撤。
- 不在跑、而且这张单 10 分钟内更新过：这一轮不查（工作流刚收尾、状态还没写的那一下），旧提醒不撤。
- 排队中的单：读这张 issue 最近一次的 issues 投递（新查询 `latestIssueDelivery`：按 `github_event_versions` 里这张 issue 那一版的时刻取最新，评论事件不算）。
  - 投递上记着为什么不派，算有着落：接活记的 `workflow=<原因>` 是 `unscheduled`、`not_current_version`、`mother_ticket`、`sub_issue`、`opened_before_switch` 之一（`HELD_REASONS`），或投递记成等着（`waiting`，对账补漏每轮重放它）。`dispatch_off`（开关现在开着，这条是旧的）、`version_unreadable`、`created_at_unreadable`（没判成）不算，要重判。
  - 读投递抛错：记没查成，不补拉。
  - 两样都没有：补拉一次——重放这次投递（带 force），走的是对账补漏重放同一道接活的门（`real/github-reconcile.ts` 抽出 `reconcileIntake`，两处共用 `createGitHubIntake`）。重放完接活判了不派、或记成等着，算补上；拉起了（再问 Temporal 在跑）算补上；门没收、没有投递、重放抛错、重放完工作流还是不在跑，报卡住。那条投递正在处理（`in_flight`）这一轮不动。补上的计 found，写日志。
- 在做的单（分诊、等人回答、写方案、在干、在合并、停滞）工作流不在跑：不补拉——接活对在做的单判 `in_progress`，重放拉不起来；也不自动重起（会和残留的会话、分支撞），直接报卡住。
- 卡住报 `reconcile:workflow:<taskId>`（alert 级、带 taskId 和 issue 链接），正文写库里状态、工作流怎么了、补拉的结果。
- 撤：开着的 `reconcile:workflow:*` 里，对应任务这一轮查成了且有着落、单结束了、库里没了、项目接活关了的撤掉，写原因。

## 二、合了的 PR 都记了账

### 记账（`checkLedgers`，新）

- 新查询 `mergedPrLedgers(db, { since, prs })`：镜像里 `state = merged` 的 PR，按头分支对上同仓一张单的会话（`session_runs.branch = pull_requests.head_ref`）——对得上的就是引擎开的；`since` 以后更新过的，外加 `prs` 点名的（还开着的 `reconcile:ledger:*` 提醒要复查，出了回看窗口也查得到）。每条带上那张单所有的会话（结局、起止、token）。
- 回看 26 小时；合并 30 分钟以内的不查（关单那一步还在走）。
- 缺什么（`ledgerGaps`）：
  - 会话没有结局（`ended_at` / `outcome` 空）；
  - 跑过的会话 token 记成了 0（读不到要留空、关单评论写「没读到」，不记 0）；留空的不算缺；
  - 合并关单那一步没写完：单不是 `done`（0003 第 7 步关单之后工作流把单记成做完）。
- 缺的按 PR 报 `reconcile:ledger:<owner>/<name>#<号>`（alert 级，`raise` 原地更新），正文一行一张单写明缺什么；不自动补。都齐了、或镜像里这条 PR 不再对得上，撤掉。
- 读库抛错：这一部分 failed，旧提醒不撤。列提醒抛错：照查照报，记没查成，旧提醒不复查、不撤。

### 镜像、合并人（`checkMergedPrs`，保留）

- `GitHub.auditMergedPrs(repo, since)`（`packages/github`）：每个受管的仓最近 26 小时合了的 PR，镜像没记成已合并的自动补（算发现、写日志）；我们两个机器人开的 PR 还要是「引擎」合的、有合并队列的合并记录，没有就按 PR 报 `reconcile:pr:<仓>#<号>`（`insertOnce`，不自动撤）。人开的 PR 不查这两项。列 PR 失败、有的没查成：这个仓写进 unchecked。
