# #554-3 按改动面分档判据 tier.ts（#588）· 结果

关联 PR：#590 · 分支 `feat/554-3-tier`（已挂自动合并）

## 做了什么

- 新增 `packages/engine/src/runner/tier.ts`：纯函数 `decideTier(changedFiles: readonly string[]) → { tier, effort, reason }`，zod schema 钉住返回形状；reason 必填（给验收与事后复盘看）。
- 判据按任务三行**严格顺序**应用（`tier.ts` 头注有完整解读）：
  1. 空列表 → 抛 `TierError(EMPTY_DIFF_INPUT)`，**不默认 fast**（通用段底线第三条）。
  2. 文件数 > `TIER_HEAVYWEIGHT_FILE_THRESHOLD`（=50）→ 直接 heavyweight，不再 refine。
  3. **一个文件 → fast / effort=medium**（不管是不是碰接口包）。
  4. **同一 `packages/<包>/` 内几个文件 → medium / effort=high**（不管是不是碰接口包）。
  5. 其余 → heavyweight / effort=high；reason 里点出「碰接口包：packages/api|core|shared」（任务 §四钉的三包）。
- 「一次定死，不升档、不回退」：函数不接 tier 入参，调用方也不能再传档位让它改。
- **不接 engine**：不读 git、不调网络、不起子进程；由调用方把 `git diff --name-only <base>..<head>` 的结果喂进来。
- 新增 `packages/engine/test/runner/tier.test.ts`（9 条）：
  - happy path 三档各一（任务指定例子：`packages/api/src/cli.ts` 单文件 → fast；`packages/shared/src/*.ts` 同包多文件 → medium；`packages/api + packages/core` 跨包 → heavyweight）；
  - 故意造红：空列表 → 抛 TierError，不默认 fast；
  - 边界：>50 → heavy 不 refine；恰好 50、同包非接口 → 仍走 refine（medium）；同包接口内多文 → medium（顺序第 4 条先于第 5 条）；跨「包内+非 packages」路径 → heavy；reason 三档都非空。
- `packages/engine/src/runner/index.ts` 加 re-export（含一行头注说明 tier 是纯函数）。
- 规格落档 `specs/588-554-3-tier/需求.md`（由 `pnpm issue:new` 生成骨架后补齐设计依据）。
