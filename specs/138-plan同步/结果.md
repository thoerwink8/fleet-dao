# 版本快照写回仓：结果（#138）

## 做了什么

- `pnpm plan:snapshot`（`packages/conventions/src/plan-snapshot.ts`，入口 `packages/conventions/src/bin/plan-snapshot.ts`）：从 GitHub 读版本里程碑、说明里的先后、母单和子单，重写 `docs/plan.md` 两行快照标记之间的「现在的目标」「未排期」「已关的版本」三节；读 GitHub 的几样加在 `packages/conventions/src/github-api.ts`。
- `docs/plan.md`：开头说明改成「以 GitHub 为准、这几节是生成的」，加上两行快照标记，快照段换成真跑生成的（北京时间 2026-09-27 04:30 的快照）；标记外面（P0–P6 的原计划）一字没动。
- 文档指针、欠账检查不查快照段（`packages/conventions/src/markdown.ts` 按两行标记认出这一段）：第一次真跑时，#139 的标题里写着还没建的设计目录、#69 的标题里有「验收后做」，照抄进 plan.md 这两样检查就报。快照标题带括号的时间也改了写法：标题末尾的括号里再套括号，design 里指「现在的目标」的五处就指不到了。
- README「常用」「文档各管什么」、design 第七节「标签与里程碑」写明先后怎么写、什么时候跑。

## 怎么验证的

- `pnpm exec vitest run packages/conventions` 全过；方案.md 列的每条失败都有故意造出失败的测试。故意改坏几处（去掉没登录的判断、去掉序号检查、快照段照查），对应的测试都红。
- 本机真跑 `pnpm plan:snapshot --at 2026-09-27T04:30+08:00`：写出来的和 GitHub 上对得上——v1 的先后 #169、#191、#199，#191 的子单 #129、#164，未排期 41 张（10 张单独的、7 张母单和它们的 24 张子单，子单先后和迁移表一致）；同样的参数再跑一遍，说「和原来一样」、不写；快照标记外面和生成前一字不差；全仓文档指针检查、`pnpm debt:check` 都过。
