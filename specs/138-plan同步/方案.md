# 版本快照写回仓：方案（#138）

范围以需求.md 末尾「现状」里写的为准（2026-09-26 晚改，#169 第 5 件）：计划以 GitHub 为准，这张单只做版本快照写回仓；原稿里双向同步、开单改成写 plan 的部分作废。

## 怎么做

- 命令：`pnpm plan:snapshot [--at 2026-09-27T09:00+08:00]`，代码在 `packages/conventions`：`src/plan-snapshot.ts` 读、核、排、写，`src/bin/plan-snapshot.ts` 是入口，读 GitHub 的几样加在 `src/github-api.ts`。每个版本开始和结束时由总指挥跑，生成的改动照常开 PR；不定时跑、不接 CI。
- 读什么（REST，逐页读完）：全部里程碑（带说明）、开着的 issue、每个版本里程碑里的 issue（开着的、关了的都要）；贴了「母单」标签或 GitHub 记着有子单的，用[子议题接口](https://docs.github.com/en/rest/issues/sub-issues)读它的子单，子单下面还有的接着读。子单的先后取接口回的顺序：文档没明说按位置排，但改顺序的接口（Reprioritize sub-issue）改的就是这份列表里的位置，本仓 #191、#193、#197 实测和迁移表的先后一致。
- 写什么：只重写 `docs/plan.md` 两行快照标记（HTML 注释）之间的三节——「现在的目标」（开着的版本，版本号从小到大）、「未排期」（没挂里程碑的开着的单，按单号，母单下面列子单）、「已关的版本」（版本号从大到小）。标记外面的开头说明和 P0–P6 的原计划一字不动：PR「对应计划」的旧写法、引擎核需求文档、文档指针检查还在引用那几节。
- 每个版本一节：标题、里程碑链接和单数；里程碑说明照抄，先后标记那一段换成排好的列表，母单下面按 GitHub 上的先后缩进列子单、标出关了几张；版本里没排进先后、也不在排了的单下面的，另列「先后里没排的」，命令也提醒一句。关了的单写「已做完」「不做了」，挂在别的版本或未排期的子单标出来。标题照抄前把起 Markdown 作用的字符转义，说明里的标题行前加 `\`，免得打乱分节。
- 快照段是照抄 GitHub 的：文档指针、欠账检查按两行标记认出这一段、不查它（标题里写着还不存在的路径、推后的话，要改去 GitHub 改）；标记不成对就整份照查。
- 输出确定：只由读到的数据和快照时间定；版本按号、单按号排，子单按 GitHub 上的先后；文件里唯一的时间是快照时间，由 `--at` 传入（不传取当前时间），写成北京时间。
