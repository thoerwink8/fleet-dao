## 一、业务说明

### 1.1 替谁、干成什么、怎么算干成

- **谁**：创始人（付拼车、独享两份 reclaude 月套餐的人）；法国引擎（以后还有本机 WSL 演练台的引擎）起的无头 Claude 会话；创始人本机自己的 Claude Code 主会话和指挥官的子代理（固定挂独享）。
- **在什么场合**：引擎派 Claude 的活（三段的动手、验收）时；拼车本人额度用满、或拼车整辆车被别人用光时；拼车恢复时。
- **要干成什么**：拼车额度不用就作废、还会被同车的陌生人抢，所以**拼车能用就一直用、用到被拒为止**；拼车用不了时切到独享接着干，活不停、不白等；拼车一恢复就回拼车，**少烧独享**（独享贵，还要留给创始人自己用）。
- **干成的标志**（上线后按这几个数验收，第五节末尾有怎么量）：
  1. 有 Claude 活排队的窗口里，拼车本人额度用到 95% 以上才离开拼车（现在最多只用到 90%，见第二节 G1）；
  2. 从拼车第一次被拒到活在独享上接着跑：2 分钟以内（现在最多二十来分钟）；
  3. 拼车恢复后还挂在独享上的时间：宽限 G（建议 10 分钟）加 1 分钟以内（现在最多 15 分钟，且一到点就把在跑的全停）；
  4. 没有来回抖：任意 5 小时里自动切号不超过 6 次，切回后马上又被拒（白切）连着 3 次就停下要人看；
  5. 每次切号都在操作记录里写清凭什么切（哪一种用不了、证据从哪读来）；读不到、切不成都有提醒，不悄悄卡住。

### 1.3 查到的 reclaude 事实（2026-10-04 读）

官方文档（`https://docs.reclaude.ai/llms.txt` 列的那套，Mintlify 托管，下面每条都是原文意思）：

- **三种方案**：独享（一个账号专属于你）、拼车（N 人共享一个账号，单人限额 = 1/N）、按量（独立美元额度，按真实接口成本扣）。——[订阅](https://docs.reclaude.ai/account/subscription)
- **拼车的 5 小时配额**：「拼车套餐为了均衡成员之间的用量，会有 5 小时**滚动窗口**的配额上限。主页能看到当前窗口已用、剩余、距离归零的时间。配额参数会随实际运营调整。」——[订阅](https://docs.reclaude.ai/account/subscription)
- **两层额度**：「拼车的 5 小时配额由 ReClaude 自己均衡，**不是** Anthropic 的官方窗口」；主页的整体用量透传自 Anthropic。——[工作原理](https://docs.reclaude.ai/how-it-works)。也就是：拼车本人有一层 reclaude 的 $80/5 小时，底下整辆车还有一层官方的 5 小时 / 周窗口（B3）。
- **一台设备一个组织**：「每台设备同一时刻只走一个组织。不同电脑可以绑不同组织」「不同组织的额度完全独立」「不会自动 fallback：当前组织额度用完了请求会直接失败（提示订阅过期 / 额度耗尽 / 5h 配额耗尽），需要 `reclaude org use` 手动切」。切完「下一次请求就走新组织的账号和额度」。——[订阅](https://docs.reclaude.ai/account/subscription)、[命令参考](https://docs.reclaude.ai/cli/commands)
- **设备**：「每跑一次 `reclaude login` 都会注册一台设备」；设备数有上限（满了批准页提示「已达 X 台设备上限」）；会被自动撤销的常见原因有「同一账号在多台机器同时高频使用，触发风控」「CLI 版本过低」。——[设备](https://docs.reclaude.ai/account/devices)
- **换号**：分配的账号不可用（被风控、暂停）时系统自动重新分配，月套餐期内不计次。——[设备](https://docs.reclaude.ai/account/devices)、[常见问题](https://docs.reclaude.ai/help/faq)
- 被拒、出错的提示：「所选组织没有可用的绑定账号」「401 device_revoked」「403 x-claude-code-session-id missing（CLI 版本低）」「频繁 502 换 gateway」。——[排查问题](https://docs.reclaude.ai/help/troubleshooting)

创始人给的开放接口（2026-09-25 起在用；**公开文档里没有**，读取器是 `packages/adapters/src/quota/readers/reclaude.ts`，网页「设置 → API Key」生成的账号级 Key，Bearer 调，只读）：

- `GET /api/v1/carpool/quota`：拼车本人这一层。真机回包（`packages/adapters/test/quota/fixtures/reclaude-carpool-quota-2026-09-25.json`，编号换成了假的）字段：`enabled`、`quota_usd: "80.00"`、`used_usd`、`resets_at_ms`（毫秒，带零头，不是整点）、`status` / `state: "active"`、`notice_i18n_key: "billing:carpool_5h.notice_provisional"`（上限是暂定的）、`account_id`。
- `GET /api/v1/orgs`：各组织的类型（team / personal）、`has_assigned_account`（分没分到官方账号）、`subscription_expires_at`；另有 `current_org_id`。
- 账号级：不看这台设备挂哪个组织、不起 Claude Code、不花额度；挂着独享时照样读得到拼车的数——**这就是「在独享上记得拼车几点恢复」的数据来源**。

没写清、要核的（列进第八节问题清单或上线后实测）：

1. 「滚动」到底是到点一下子归零，还是用过的钱满 5 小时一笔笔退回来？文档只说「距离归零的时间」，回包只有一个 `resets_at_ms`。
2. 开放接口有没有限流、多久更新一次 `used_usd`（是不是每个请求后就变）。
3. `current_org_id` 是账号网页上选的组织还是某台设备挂的——不能拿它当「法国那台挂的是哪个」（设备挂哪个只认 `org list` 带 `*` 那行，design 第九节）。
4. 有没有设备列表、用量明细这类接口（多台机器协调时想知道「别的设备在不在用拼车」）。
