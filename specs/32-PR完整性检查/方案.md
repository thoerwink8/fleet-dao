# 方案：PR 完整性检查、开单脚本、文档指针检查（#32）

需求见 [需求.md](需求.md)。三块都放新包 `packages/conventions`，只用 Node 自带的东西：CI 不装依赖就能跑。

## 拆成三块、各改哪里

1. **PR 必填栏**（`packages/conventions/src/pr-fields.ts`）
   - 新工作流 `.github/workflows/pr.yml`，任务名 pr-fields：PR 的 opened、edited、synchronize、reopened、labeled、unlabeled、milestoned、demilestoned 都跑。和 ci.yml 分开，改个标签不连带重跑、打断整套 check。
   - 读这次事件里的标签、里程碑、正文，对着检出来的 docs/plan.md 和 specs/ 查。缺一样报一句「缺什么、怎么补」，退出码 1；事件或 plan.md 读不到退出码 2，同样是红。
   - 「对应计划」的写法：阶段加那一条的原话开头，如 `P1「工作流」`；跨两条用顿号隔开，引号里能再套引号。阶段得在 plan.md 里，原话得在那个阶段下面找得到，里程碑的阶段得在里面。
   - 「specs」：`specs/<号>-<短名>/`（这个 PR 里得有），或「不适用」。
   - PR 模板和 `packages/github` 的 renderPrBody 一起加这两栏；renderPrBody 的两栏必填，给空的写「（没写）」，CI 照样红。
2. **开单脚本**（`packages/conventions/src/issue-new.ts`，命令 `pnpm issue:new`）：先查参数和正文文件，再用 gh 把 P1 换成里程碑全名，最后一条 `gh issue create` 带上标签和里程碑；带 `--specs` 就按新单号建骨架。哪一步没成都照实报，退出码非 0。
3. **文档指针**（`packages/conventions/src/doc-pointers.ts`，由 `packages/conventions/test/doc-pointers.test.ts` 接进 pnpm check）
   - 认：路径（反引号里的、链接、正文里「顶层目录/…」）、`第 X 节`、`X.Y`、`第 N 条`（件）、`「标题」一节`、文档名紧跟 `「标题」`、`plan.md P1「…」`。
   - 不查：围栏代码块和 HTML 注释（示例、占位）、别的仓的路径、不以仓里顶层目录或文件开头的路径、没有小节编号的文档里的小数（版本号）。

## 先后

三块互不依赖。PR 模板和 renderPrBody 得一起改：它们有一条「栏目一致」的测试。

## 不做的

- 不把 pr-fields 加进主线规则集的必过检查：那是 GitHub 上的设置，另拍。
- 不查 docs/reference/、AGENTS.md 和 agents/（agents/ 有 PR #27 自己的测试）。
