# 方案：会话用户在本机开的口只许它自己和 root 连（#35）

需求见同目录 `需求.md`。和需求里原定的做法不一样的一处写在最后。

## 现场（2026-09-27 法国只读核对）

- 会话用户 `fleet-agent-carpool` 的 reclaude 守护在 `127.0.0.1` 上听两个临时端口（32768–60999 里内核挑的），一个是代理口、一个是 MITM 口。
- 以 `pilot`、`fleet` 的身份连代理口、发无害的 `CONNECT 127.0.0.1:1`，都回 `502 Bad Gateway`：接了、没要身份，能借。口子开着。
- 守护这时跑在 root 登录会话的 scope 里（`user.slice/user-0.slice/session-….scope`），不在 `fleet-agents.slice`：谁先起它，它就落在谁的 cgroup 里。按 cgroup 认不住它，只能按 uid 认。

## 比过的做法

| 做法 | 挡得住吗 | 能写进 france.sh、每次装机都生效、读得回吗 | 碰不碰引擎 |
|---|---|---|---|
| A. 防火墙按属主拦，看应答的一方（选这个） | 挡得住：别人发起、会话用户的套接字应答的回环连接一律拒，任何端口 | 能：进现成的 nft 表 `inet fleet_dao` 和 `fleet-firewall.service`，重载在一个事务里换整张表；读回真连 | 不碰：会话连自己的 reclaude、引擎连 Temporal 和库、会话连 fleet 命令接口都不经过这几条 |
| B. 防火墙按属主拦，按目的端口（经典写法，需求里原定的） | 端口每次变，写不死；退一步挡 pilot、fleet 连整个临时端口段能挡住 | 能 | 连带挡掉 pilot、fleet 自己在临时端口上的东西（测试里 `listen(0)` 的服务；pilot 以后自己登 reclaude 时它自己的代理口），而且只挡点名的两个用户 |
| C. 改成 Unix socket，靠文件权限挡 | 最干净 | 不能：要 reclaude 自己支持，Claude Code 的 `HTTPS_PROXY` 也只认 `http://主机:端口`；reclaude 是外面发的二进制，本仓改不了 | — |
| D. 代理加令牌（`Proxy-Authorization`） | 挡得住 | 同 C，要 reclaude 改 | — |
| E. 会话用户一个网络命名空间 | 回环各自独立，挡得住 | 要配 veth、NAT、DNS 让会话出网（reclaude 上游、git、npm），会话连 `127.0.0.1:8788` 的 fleet 命令接口也得改地址，还要改 sudo 放行的 root 脚本 `fleet-agent-scope`：改架构，要单独拍，不是当场修 | 碰 |

出处：

- 本地的隧道、代理在回环上开口子，本机任何用户都连得上，经典的挡法就是在 OUTPUT 上按属主拦（owner match）：Mick Bauer, *Paranoid Penguin: Using iptables for Local Security*, Linux Journal 2002 — https://www.linuxjournal.com/article/6091 。它按固定的目的端口拦（`--dport 992 -d localhost -m owner ! --uid-owner root -j REJECT`），reclaude 的端口不固定，所以 A 改看应答方。
- nft 的 `meta skuid` 是「发出这个包的套接字的属主」（UID associated with originating socket）：https://wiki.nftables.org/wiki-nftables/index.php/Matching_packet_metainformation 。
- SYN-ACK 由监听套接字发出：内核把它挂在请求套接字上，SYN 洪水下改发 syncookie 时不挂任何套接字（Linux v6.8 `net/ipv4/tcp_output.c` 的 `tcp_make_synack`，https://github.com/torvalds/linux/blob/v6.8/net/ipv4/tcp_output.c#L3689-L3697 ）；nft 取 `skuid` 时把请求套接字换成它的监听套接字，取的是那个套接字文件的属主（`net/netfilter/nft_meta.c`，https://github.com/torvalds/linux/blob/v6.8/net/netfilter/nft_meta.c#L134-L150 ）。所以 SYN-ACK 的 `skuid` 就是监听的一方。
- Unix socket 靠文件权限挡：连一个流式 Unix socket 要对它有写权限（unix(7)，https://man7.org/linux/man-pages/man7/unix.7.html ）。
- 网络命名空间只带一个自己的回环、没有别的网卡（systemd.exec(5) 的 `PrivateNetwork=`，https://man7.org/linux/man-pages/man5/systemd.exec.5.html ）：要出网就得另配。

## 规则（`deploy/france/fleet-dao.nft` 第二道隔离）

都在 `output` 链、都只看回环（`oifname "lo"`，本机连本机的包都走它，127.0.0.1、::1、本机自己的地址都算）：

1. root、会话用户以外的人发起的连接，第一个 SYN 在连接跟踪上记一位（`ct mark` 的 0x10000000）。
2. 会话用户的套接字应答这种连接，一律拒（`reject with tcp reset`：复位送给会话用户那头，它丢掉这条半开的连接；发起的一方等不到 SYN-ACK，连不上，等到它自己的超时）。
3. 应答的套接字不归会话用户的，记另一位（0x20000000）：对面证实过不是会话用户。
4. syncookie 的 SYN-ACK 不挂套接字，第 2、3 条都认不出：别人发起、又没证实过对面的连接，往 32768 起的临时端口发的后续包（不含 SYN、RST）一律复位，握手完成不了、数据到不了对面。

连接跟踪标记只按位或进去、按位与出来，只动这两位。模板里只写得下一个会话用户：`france.sh` 渲染时核对会话用户只有一个，多了判红、不写。

规则只管新连接（标记打在第一个 SYN 上），表载上之前就连着的别人的连接不受它管（第二意见 #343 第 1 轮提的）。不在规则里补：要补只能看连接中途的包，而连接跟踪中途接手（`nf_conntrack_tcp_loose`，表项过期或被清掉以后）时把哪头当发起方说不准，会把会话连 fleet 命令接口的连接当成别人的、误杀。所以 `france.sh` 载完表当场收：会话用户那头是它在听的口、对端套接字的属主不是 root 和它的已连接连接，用 `ss -K` 断掉（内核要开 SOCK_DESTROY，法国的开着），断完再查一遍，断不掉判红停下；表换上以后新的连不上，这一收就收干净了。读回也查，还有就红、写清是谁。

## 验证

- 法国内核（6.8、nft 1.0.9）上先在一次性的网络命名空间里实测（不碰宿主的防火墙）：别人连会话用户的口超时连不上，会话用户、root 连得上，别人之间照常通，::1 也挡；强制 syncookie、拿掉第 4 条时，别人的连接真到了会话用户那头（它接到了、收到了数据），加上第 4 条就到不了；整张表删掉，别人又连得上。
- 自测 `deploy/test/session-ports.test.sh`（CI 的 deploy 那一步以 root 跑）：上面这些都真连一遍，外加读回的每种判红、每种没查成，规则载上之前就连着的连接照样通、装的时候断掉；法国上用 `--inner` 拿真账号在一次性命名空间里跑过一遍，61 项全过、34 秒。
- 读回（`france.sh`）：`fleet`、`pilot` 真连会话用户此刻在听的口和现起的探针，连得上判红；会话用户连不上自己的探针判红；`pilot` 连不上 `fleet` 起的临时口判「挡多了」；文件和模板、内核里的表和文件逐字比。修之前在法国宿主上跑这段读回：6 项红（两个用户 × reclaude 两个口 + 探针）。

## 不挡的、剩下的

- root 连得上：root 本来什么都拿得到。
- 会话用户自己的进程都连得上：会话本来就该用它的 reclaude。
- `fleet` 本来就能经 sudo 以会话用户起任何命令（引擎起会话就这么起），挡它直连只是少一条路，不是把 `fleet` 挡在会话用户之外。
- 代价：正被 SYN 洪水压着（内核改发 syncookie）的临时口，root、会话用户以外的人正常连也会被复位；32768 以下的固定端口（Temporal、库、驾驶舱后端、fleet 命令接口）不受影响。
- 需求里「两个会话用户互相借」那一半：法国现在只有一个会话用户，没了；将来再加，渲染时就判红，得先改规则（按两头的 uid 比）。

## 和需求里原定的不一样的

需求写的是「先按 skuid 挡住 pilot 和 fleet 连会话用户的代理口」，真正的修法（网络命名空间、令牌、Unix socket）留到以后，跟踪在 #192。原来认为 nft 的 skuid 只认发起方、认不出监听口归谁；其实 SYN-ACK 的 skuid 就是监听方，配上连接跟踪标记就能表达「只许会话用户自己连它的口」。所以改成 A：不点名挡两个用户，而是除了 root 和会话用户谁都挡；不挡整个临时端口段，只挡会话用户的口，pilot、fleet 自己的临时口照常用。这样需求里说的「真正的修法」要堵的口子已经堵上，不另开单：网络命名空间是改架构（E），令牌、Unix socket 要 reclaude 改（C、D），都不再为 #35 需要。
