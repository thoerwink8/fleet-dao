怎么做的、比过哪几种做法、出处见 [方案.md](方案.md)。

## 做了什么

- PR #343（2026-09-27 合并，先审后合，第二意见两轮：第 1 轮「必须改 1 条」，第 2 轮通过）：
  - `deploy/france/fleet-dao.nft` 加第二道隔离，按应答一方的属主拦：root、会话用户以外的人发起的回环连接，第一个 SYN 在连接跟踪上记一位；会话用户的套接字应答这种连接一律拒；syncookie 的 SYN-ACK 认不出是谁，另补一条挡住没证实过对面的连接往临时端口发的后续包。任何端口都挡，pilot、fleet 自己的临时口照常用。
  - `france.sh` 载完表当场断掉规则载上之前就连着会话用户的口的别人的连接（`ss -K`，第二意见第 1 轮提的：规则只管新连接），断不掉判红停下。
  - `france.sh` 读回（判据在 `deploy/lib/session-ports.sh`）：fleet、pilot 真连会话用户此刻在听的口和现起的探针，连得上判红；会话用户连不上自己判红；pilot 连不上 fleet 的临时口判「挡多了」；还连着的旧连接判红；另核文件和模板一样、内核里的表就是这份文件。查不到用户、ss 跑不成、没以那个用户跑起来都记没查成，不当成挡住了。渲染时核对会话用户只有一个，多了判红不写。
  - 自测 `deploy/test/session-ports.test.sh`：一次性网络命名空间里载真模板、临时用户真连（CI 的 deploy 那步以 root 跑，过了）。
- 文档：ops 第五节「会话用户的口只许它自己连」替掉原来的「已知口子」，第二、三、四节和 design 第十四节跟着改。

## 法国真机（2026-09-27 晚）

- 修之前（只读核对）：会话用户的 reclaude 守护在 127.0.0.1 上听两个临时口；pilot、fleet 连代理口发无害的 `CONNECT 127.0.0.1:1` 都回 `502 Bad Gateway`，能借。新读回在宿主上跑一遍判了 6 项红（pilot、fleet × reclaude 两个口 + 探针）。
- 合进去以后：先看引擎没有在跑的会话、自动发布这时没在发，把 `/srv/fleet-dao` 快进到合并后的主线，跑 `deploy/france.sh`。改了 3 处和防火墙有关的：写 `nftables.nft`、写 `fleet-firewall.service`、重载 `fleet-firewall`；没有要断的旧连接。读回：
  - ✓ 内核里的 nft 表 inet fleet_dao 就是 /etc/fleet-dao/nftables.nft 那一份
  - ✓ 会话用户和 pilot 都连不上 Temporal 和库，fleet 连得上
  - ✓ 别的用户（fleet、pilot）连不上会话用户在本机开的口（现起的探针，和它此刻在听的 2 个口），也没有规则载上之前连上的；它自己连得上；别人之间照常通
  - ✓ 起会话走得通；装机前后旧系统的单元状态、监听端口、防火墙都没变
  - 同一轮的另外一项红、九项待配都不是这次的：一项红是 #323 的配置对账（engine.env 的 `FLEET_MACHINE_NAME` 和仓里期望不一致），八项待配是它还没记指纹的私有值，一项是拼车用户家里的派活垫片还在。
- 手动探测（和修之前同一个 CONNECT）：pilot、fleet 连代理口和 MITM 口都是 5 秒超时、一个字都读不到；会话用户连代理口 39 毫秒回 `502 Bad Gateway`，连 MITM 口照常连上。
- 会话照常能用：重载在 23:35:31（北京时间）；23:37 那一轮路由探针以会话用户起 Claude 会话，拼车那条「答上了：OK · 用时 19 秒」。
- 上线前在同一台的一次性网络命名空间里拿真账号跑过 `deploy/test/session-ports.test.sh --inner`：61 项全过、34 秒。

## 「怎么算做完」逐条

- 故意用 pilot 或 fleet 身份探测会话用户的代理口，从 502（能借用）变成连不上或被拒：做到了，上面的手动探测，两个用户都连不上；读回每次跑都真连一遍。
- 会话用户自己连自己的代理口不受影响，有测试：做到了，会话用户照样回 502，路由探针的 Claude 会话照常答上；自测和读回都钉着这一条。
- 两个会话用户互相借用那半：法国只剩一个会话用户（2026-09-26 起），这半没了；将来再加，`france.sh` 渲染时判红、不写，得先改规则（按两头的 uid 比）。

## 剩下的

方案.md「不挡的、剩下的」：root 连得上；fleet 本来就能经 sudo 以会话用户起命令；正被 SYN 洪水压着的临时口，别人正常连也会被复位；UDP 不在这次范围（reclaude 的两个口都是 TCP，守护没开 UDP 口，也没有在听的 Unix socket）。不另开单：需求里说的「真正的修法」（网络命名空间、令牌、Unix socket）要堵的口子这次已经堵上。
