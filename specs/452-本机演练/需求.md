# 演练仓全流程在本机环境跑通（开单到合并）（#452）

对应计划：v1 Fusion 接活
设计依据：ops 第五节「每小时对账」（全流程巡检）、design 第九节「接活」

原话（创始人 2026-09-28 下午）：「仓库要存放一个代码库，不管是通过docker还是什么方式，保证本地环境和vps相同，然后本地全流程走通，该做的事情全做完，再正式上线到vps；之前做法存在很大问题」「本机其实帥位可以当前会话修断链，其他场景可以放到这个wsl上，用grok模型去干活，批量快速干完，走普通模式」；帅位出方案、GPT 挑错后他选「1」＝照方案做。决定记在 `specs/169-Fusion形态/需求.md`「删减清单全按帅位的做；本机建一个和法国一样的环境」一节。

AI 理解：本机环境装好后，要在里面把演练仓（fleet-dao-canary）的一张单从头跑到合并（开单→引擎接活→写码→PR→CI→合并→关单），这就是「本地全流程走通」。本机没有公网入口，GitHub 的事件收不到；本机引擎靠对账补拉（每几分钟拉一次演练仓），不开隧道。本机引擎只接演练仓，不碰 fleet-dao 本仓（两个引擎打同一个仓会抢活）。

## 要什么
- 本机环境用自己的 GitHub 机器人（或同一个机器人只装在演练仓上，二选一，写明理由），只对演练仓有权限。
- 本机引擎收单靠补拉：补拉间隔可配，重复拉到同一张单不重复派（去重有测试）。
- 一条命令起一次完整演练：在演练仓开一张固定的小单，等引擎做到合并、关单，打印每一步用时；任一步失败照实报出停在哪一步。
- 现有「每 6 小时全流程巡检」在本机环境也能跑（同一份代码，不另写一套）。

## 怎么算做完
- 本机环境里演练连续 3 次从开单跑到合并、关单，没人插手。
- 故意造出的失败，每条一个测试：补拉读不到 GitHub → 报没查成、不当成没单；同一张单被补拉两次 → 只派一次。
- 用时和停在哪一步的记录能看到（驾驶舱或日志）。
