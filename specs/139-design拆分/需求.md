# design 拆分：决定表拆成 docs/decisions 一决定一文件、计划性内容搬走、按模块拆 `docs/design/<模块>.md` 并对上 packages，动了包没动设计文件就留言提醒（文档整套改法第③步）（#139）

对应计划：plan.md P0「design 拆分」
设计依据：design 第七节「plan、design、ops 的整套改法」第 7–9、12 条，`docs/decisions/0001-plan-design-ops.md`。

原话：design 的决定表拆成决定记录 `docs/decisions/<编号>-<短名>.md`，一决定一文件、只增不改；计划性内容全部搬进 plan 或 issue；按模块拆 `docs/design/<模块>.md`，和 packages/<包> 用一张对照清单对上，docs/design.md 只留一句话、架构图、目录；PR 动了某包 src/ 没动对应设计文件就留言提醒、不挡合并。（创始人 2026-09-26 拍「plan、design、ops 整套改法」，第③步）
AI 理解：design.md 现在一整份六百多行，拍板记录、设计、还在讨论的事混在一起。这一步把它拆成三样：决定记录（`docs/decisions/`，已有 0001）、按模块的设计文件、只剩目录的 `docs/design.md`；再加一个只留言不挡合并的提醒。

## 要做什么

照 `docs/design.md` 第七节「plan、design、ops 的整套改法」第 7–9、12 条：

- 决定记录：把 design 第三节决定表逐条搬成 `docs/decisions/<编号>-<短名>.md`（0001 已有，其余接着编号），每条写日期、谁拍的、决定、出处；被后来的推翻的标「已被 xx 替代」；第三节只留目录。
- 计划性内容搬走：design 第十九节「待讨论」、第二十节「下一步」、标题里带「讨论中」「待讨论」的各段，搬进 plan 条目或开单，design 不留。
- 按模块拆：`docs/design/<模块>.md`，和 `packages/<包>` 对应（engine、adapters、cli、api、web、feishu、github、db、jev、conventions、hygiene、agents-sync 等），加一张明确的对照清单（放一份机器能读的文件，检查和提醒都读它）；跨包的（流程、派工、额度、安全、驾驶舱）各一个文件并写明管哪些包。`docs/design.md` 只留一句话、架构图、目录。
- 提醒：PR 动了某包 `src/` 却没动对应的设计文件，由一个 Action 在 PR 上留言提醒（同一个 PR 只留一条、原地更新），不挡合并。
- 跟着改（第 12 条）：文档指针检查（`packages/conventions/src/doc-pointers.ts` 的 DOCS 清单和「design 第 X 节」这类写法）改成认新文件；全仓指向 design 章节的指针（specs、plan、ops、README、代码注释）改到新位置，一处不断。
- 每条读不到、认不出的路径（对照清单缺包、设计文件缺）明确报错，各配一条故意造出失败的测试。

## 怎么算做完

- 仓里：`docs/decisions/` 下 design 第三节的每条决定各一个文件；`docs/design.md` 只剩一句话、架构图、目录；`docs/design/<模块>.md` 每个文件在对照清单里，`packages/` 下每个包都对得上一个设计文件；design 里没有「待讨论」「下一步」「讨论中」。
- 测试：对照清单缺一个包时检查报错；文档指针检查在新结构上跑，故意改断一个指针报 文件:行；CI 绿。
- 真 PR：一个只改某个包 `src/`、不改对应设计文件的测试 PR 上出现提醒留言，再推一个提交留言原地更新不重复，PR 照样能合。
