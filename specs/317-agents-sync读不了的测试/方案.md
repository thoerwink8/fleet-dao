# 方案：agents-sync 几处「读不了」补测试（#317）

需求见同目录 [需求.md](需求.md)。只加测试，不改 `packages/agents-sync/src`。这五条现在已经是「读不了就明确失败」；本单把测试补上，并各拿「读不了就当没有」改坏一次，确认会红。改坏只在工作区，测完还原，不许进提交。

已有的两条不重复做：仓里没有 `agents/skills/`（`cli.test.ts`）、清单不是 JSON（`skills.test.ts`）。家里全局文件读不了（`rules.test.ts`「文件读不了」）也不重复。`agents/hooks/` 读不了只影响钩子那一段，不挡规矩和 skill，本单不测。

## 怎么造「读不了」

照 `packages/agents-sync/test/rules.test.ts`「文件读不了」：`chmod 0o000`，`finally` 里改回（文件 `0o644`，目录 `0o755`）。`it.skipIf(PLATFORM === 'win32' || IS_ROOT)`。目录改成 `0o000` 之后，测试自己也列不出里面的东西，断言放在 `finally` 改回之后；不改回的话临时目录删不掉。本机和 CI 是 Linux、不是 root，这几条会真跑。

## 五条测试

### 1–3. `readSources`（`test/cli.test.ts`，走 `runCli`）

失败发生在 `cli.ts` 动手之前（还没写规矩、没动 skill）。只单测 `readSources` 返回失败，证明不了「一个文件都不写」。

家目录事先放好装过的一份：`~/.claude/skills/grill-me/SKILL.md` 内容固定为 `装过的\n`，清单 `~/.fleet-dao/agents-sync.json` 的 `skills[".claude/skills"]` 记着 `grill-me`。仓用 `makeRepo`，里面也有 `grill-me`，但内容不同。读不了若被当成「仓里没有这个 skill」，`--apply` 会把家里这份撤掉；若读成功并往下走，会新建 `~/.claude/CLAUDE.md`。

每条都跑 `--check` 和 `--apply`：

- 退出码 2；stdout 是空的（还没进入各段）。
- stderr 含 `没查成`，并含下面这一句（三句用括号分开，避免「目录」那句被「下面的文件」那句包含）。
- 家里 `grill-me` 还在，内容仍是 `装过的\n`。
- `~/.claude/CLAUDE.md` 仍不存在。
- 清单原文一个字节不变。

| 改什么权限 | stderr 里要有 |
|---|---|
| 仓里的 `AGENTS.md`（文件） | `读不了仓里的 AGENTS.md（` |
| `agents/skills` 这个目录 | `读不了仓里的 agents/skills/（`，且不含 `没有 agents/skills/` |
| `agents/skills/grill-me/SKILL.md` | `读不了仓里的 agents/skills/ 下的文件（` |

三句里都要有 `EACCES`。

### 4. `readManifest`（同样 `test/cli.test.ts`，走 `--check` / `--apply`）

「清单不是 JSON」那条只调 `applySkills`，而且默认两家都装了。本条走命令，才能对上需求里的 `--apply`。`run()` 默认 PATH 里只有 claude；这条要自己放上 claude 和 codex 两个假命令。只装 claude 时，把清单当成空的也不会往第二家的目录里装，改坏了测试仍是绿的。

1. 仓里只有 `grill-me`。`--apply` 一次，退出码必须是 0（两家都装上；不是 git 检出，同步位置是跳过，和现有 CLI 测试一样）。不是 0 就先改测试摆法，不要改生产代码。
2. 删掉 `~/.agents/skills/grill-me`。清单读得成、或被当成空清单，`--apply` 都会把它装回去。
3. 家里另放 `~/.claude/skills/chain-first/SKILL.md`（内容固定），并把 `chain-first` 写进清单的 `.claude/skills`。仓里没有它；清单读得成就会撤掉。
4. 把清单文件 `chmod 0o000`。
5. `--check`：退出码 2（有缺失或漂移会是 1）；stdout 含 `没查成` 和 `读不了（EACCES）`；不含 `没有 skill 可分发`。
6. `--apply`：stdout 含 `没做成`、`读不了（EACCES）`、`一个没动`；不含 `装上了`、不含 `撤掉了`。`chain-first` 内容不变；`~/.agents/skills/grill-me` 仍不存在；`.claude` 里的 `grill-me` 内容不变。改回权限后清单原文不变。

`--apply` 退出码是 1（没做成算红，压过没查成）。这是现有退出码规矩，需求没另写。

### 5. `retireOld`（`test/retire.test.ts`，直接调函数）

只建 `~/.claude/skills`，里面一个指向临时「旧仓」的目录链接。别的 skill 目录不建，两个旧子代理也不放。把 `~/.claude/skills` `chmod 0o000` 再跑：

- 有一条 key 是 `~/.claude/skills`、kind 是 `unknown`，文字含 `没查成`、`读不了`、`EACCES`。
- 没有一条文字含 `没有要撤的`。
- `exitCode` 是 2。
- 改回权限后，那个链接还在。

目录不存在时现在是直接跳过，最后可能报「没有要撤的」。这条证明「在但读不了」不走那条。

## 故意改坏

一次只改一处，只跑对应那一条，确认红，然后把该文件还原，再改下一处。五处都还原后，再跑下面的验证命令，确认全绿。提交之前 `git diff origin/main -- packages/agents-sync/src` 必须是空的。

1. `sync.ts` 读 `AGENTS.md` 的 `catch`：不返回失败，改成 `agentsMd = ''` 再往下。stderr 不再是 `读不了仓里的 AGENTS.md`，第 1 条红。
2. 读 `agents/skills/` 的 `catch`：`EACCES` 时 `entries = []` 继续（当成空目录）。`--apply` 撤掉家里的 `grill-me`，第 2 条红。
3. 读 skill 树的 `catch`：改成跳过读失败的那个 skill，仍返回成功。家里的 `grill-me` 被当成仓里删了、撤掉，第 3 条红。
4. `manifest.ts` 的 `readManifest`：`EACCES` 走 `ENOENT` 那条，返回空清单。`--check` 不再是退出码 2，`--apply` 会把 `~/.agents/skills/grill-me` 装回来，第 4 条红。
5. `retire.ts` 的 `retireOld`：`EACCES` 和 `ENOENT` 一样 `continue`，不记没查成。结果变成「没有要撤的」，第 5 条红。
