# agents-sync 几处「读不了」的分支补上故意造出失败的测试（#30 留的）（#317）

对应计划：未排期
设计依据：AGENTS.md 通用段「底线」（读不到要返回明确的失败，每条这样的路径配一条故意造出失败的测试）；`specs/30-规矩同步/结果.md`「还欠什么」

原话：无（2026-09-27 帅位派工清单时发现：#30 的结果.md「还欠什么」里记着这几条测试，一直没开单）。

AI 理解：agents-sync 读仓里的 AGENTS.md、`agents/skills/`、本机的清单文件、要撤的旧链接目录时，读不了（权限不够这类，不是不存在）都已经返回明确的失败；可只有「目录不存在」「清单不是 JSON」两种配了测试。底线要求每条这样的路径配一条故意造出失败的测试，没配的哪天被改成「读不了就当没有」也没人发现——那样会把装过的 skill 当成仓里删了、一起撤掉。

## 怎么算做完

- `packages/agents-sync/src/sync.ts` 的 `readSources`：仓里的 AGENTS.md 读不了、`agents/skills/` 读不了（在，但没权限）、它下面某个文件读不了，各一条测试：`--check` 报没查成、退出码 2，`--apply` 一个文件都不写、一个 skill 都不撤。
- `packages/agents-sync/src/manifest.ts` 的 `readManifest`：清单文件在但读不了，一条测试：不当成空清单，`--apply` 一个 skill 都不撤。
- `packages/agents-sync/src/retire.ts` 的 `retireOld`：要扫的 skill 目录读不了，一条测试：那一项报没查成，不当成「没有要撤的」。
- 读不了靠改权限造，照 `packages/agents-sync/test/rules.test.ts`「文件读不了」那条的写法：Windows 和以 root 跑时跳过，CI 上跑。
- 每条都拿「读不了就当没有」的改法故意改坏一次，确认会红。
