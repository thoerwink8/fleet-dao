- 装载器 `packages/db/src/catalog.ts`、命令行 `packages/db/src/bin/catalog.ts`、样例 `deploy/examples/catalog.example.json` 和它的测试 `packages/db/test/catalog.test.ts` 早在主线上（#17）。本单改样例、补测试，不另起一份。
- 发布脚本 `deploy/release.sh` 里**还没有**装目录这一步：需求「起因」里的「发布时在迁移之后跑」是装载器注释里的设想。main 上没有；#28 的分支 p1-ports（已提交的、工作树里没提交的）也都没碰 `deploy/release.sh`。所以本单在迁移之后补上这一步，不和 #28 重复。
- 目录里没有账号、邮箱、组织编号这类值：`CatalogSchema` 是严格模式，没有这类字段；账号池 id 是代号，账号和凭据在会话用户自己的 reclaude、`/etc/fleet-dao` 下的额度读取器配置和 Jev 配置里。所以法国的真文件和样例取值一样，只有开头那句说明不同。它进保险箱，是因为它是法国 `/etc/fleet-dao` 下的一个文件（保险箱照它的 README 给整个目录留加密副本）。
- 保险箱只有创始人电脑上的钥匙解得开（design 第三节第 33 条），法国解不开：「把保险箱里的真文件放到法国」只能在创始人电脑上做，发布脚本在法国只查它在不在、属主权限对不对，再装。

## 目录怎么排

| 阶段 | 顺序（开着的在前） |
|---|---|
| 分诊、需求文档、方案、写码、审查、调研 | 独享号 Opus 5.5、拼车号 Opus 5.5 开着；中转的 Opus / GPT / Kimi / DeepSeek、Cursor Auto、Grok 挂在后面关着 |
| UI | 同上，但不挂 GPT（硬禁令，关着也不行） |
| 判断（Jev） | TypeSafe 的 Jev 开着；独享号、拼车号的 Opus 5.5 挂在后面关着 |

- 两个 Claude 池：独享号 `claude-solo`（会话用户 `fleet-agent-dedicated`，主池，并发 5），拼车号 `claude-carpool`（会话用户 `fleet-agent-carpool`，备池，并发 2，照 design 第九节「并发起步 2」）。
- 「拼车号派短而独立的活」不靠排序，靠引擎的主备池规则：#28 的分支里引擎读路由时，会话用户是 `fleet-agent-carpool` 的池算备池；备池只接短而轻的活、同时最多 2 个、排在主池后面（主线 `packages/engine/src/routing/filter.ts` 的 backupBlocks、`packages/engine/src/routing/rank.ts` 的 backup-pool；哪些阶段算轻在 `packages/engine/src/routing/policy.ts` 的 stageWeight：分诊、判断题、需求文档、审查算轻，巡检任务由引擎标轻）。所以每个阶段都是独享在前、拼车在后。
- 判断阶段照 `packages/jev`：它按判断阶段排第一的路由起后端（`packages/jev/src/config.ts` 的 backendForRoute），眼下只接得了 TypeSafe（执行方式 api-shell、模型钉死 jev-1.13.0；法国 `/etc/fleet-dao` 里已有它的配置和钥匙）；Claude 判断会话在接上 fleet-agent-scope 之前一律拒。所以样例里新加族 `jev`、模型 `jev-1.13`、路由 `jev:jev-1.13:api-shell`（挂在原有的 `jev` 池下）。两条 Claude 挂着但关着：接不了的开着，选路一旦轮到它就是装机错。
- 中转、Cursor、Grok 先挂上、关着：P3 接好插头、会话用户登录之后，在驾驶舱打开就行。装载器每个阶段只排一次，现在不挂，以后就得去驾驶舱一条条加。

## 发布怎么装

1. 放文件（一次，在创始人电脑上）：保险箱仓里解密，经 ssh 放到法国 `/etc/fleet-dao/catalog.json`，root:fleet 640。写法同 ops 第九节里飞书网关通行证那一段（先落临时名、改属主权限、再换上），命令写进 ops 第九节「目录配置」。
2. 发布脚本迁移之后、切版本之前多一步「装目录」：
   - 这一版没有装载器（老提交）：跳过。
   - 文件不在、是符号链接、不是 root:fleet 640：报红、停下、不切版本。
   - 读回装之前的行数和装载器最近一次的操作记录编号；读不到、认不出：报红、停下。
   - 以 fleet 跑装载器（同迁移那一步的身份和库连接）。装不成（格式错、引用不存在、撞禁令）：把装载器的话原样打出来、报红、停下；装载器整批不写，库里一行不动。
   - 装完读回账号池、路由、阶段、阶段里挂的路由四张表的行数，哪张是 0 行都报红、停下；读不回也报红。
   - 操作记录编号变了（装载器只在改了库时记一笔）记一处改动，没变就是「一行没改」：同一版再发一遍，这一步改动 0 处。
3. 为什么挡在切版本之前：和迁移一样，装不成就停在原版本，不会切过去才发现派不出活；装载器只补缺，旧版本照样认这些行，退回不受影响。

## 等你定（先按推荐做了，改起来都是一两行）

1. **判断题先用哪个**。现在：TypeSafe 在前——`packages/jev` 眼下只接得了它；按量计费，但 design 第三节第 21 条算套餐内，每天 0.3 美元封顶（`packages/jev/src/policy.ts`）。另一种：Opus 5.5 在前，照「构建期全程 Opus 5.5」和 design 第十一节「构建期先用 Opus 5.5」；代价是 `packages/jev` 的 Claude 后端接上之前，判断题一道都答不了（全走默认）。推荐 TypeSafe 在前。
2. **独享号同时跑几个**。现在：5，照 plan 第七节「每个账号池设并发上限，从 5 个起步」和 design 第四节「6 个会话（约 5 个子任务 + 1 个审查）」。另一种：3，样例原来的保守值——本机总指挥也在用独享号，法国再并 5 个，同一个号上的会话更多。推荐 5。
3. **真文件怎么到法国**。现在：创始人电脑上一条命令放上去，发布脚本只查、只装（上面第 1 步）。另一种：france.sh 照样例建一次（和 engine.env 那几份一样），保险箱靠 refresh.sh 拉回来——省掉手放，但法国的目录就成了「照样例建」，和本单说的「真文件从保险箱来」反了。再一种：保险箱仓加个「解密放回服务器」的脚本——这是新机制，没做。推荐现在这样。
4. **装不成挡不挡发布**。现在：挡，停在原版本报红。另一种：切过去之后再装，装不成报红但发布算完成。推荐挡。

另有两件事实，不用拍，但要知道：

- 目录里记不了「哪个池对应哪个账号」：表里没有这一栏。要记的话得改表结构，另开单。
- 保险箱的 `refresh.sh` 是「服务器 → 保险箱」的方向：服务器上没有的文件，它会从保险箱删掉（git 历史里还在）。目录是先进保险箱、再放到法国的，所以法国放上去之前别跑 `refresh.sh`；保险箱仓 README 里写了一句。放上去之后两边一样，照常刷新。
