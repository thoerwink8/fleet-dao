# 方案（#47）

## 先读清的现状

- 装载器 `packages/db/src/catalog.ts`、命令行 `packages/db/src/bin/catalog.ts`、样例 `deploy/examples/catalog.example.json` 和它的测试 `packages/db/test/catalog.test.ts` 早在主线上（#17）。本单改样例、补测试，不另起一份。
- 发布脚本 `deploy/release.sh` 里**还没有**装目录这一步：需求「起因」里的「发布时在迁移之后跑」是装载器注释里的设想。main 上没有；#28 的两个分支 p1-ports（PR A，#50）、p1-worker（PR B，#53）也都没碰 `deploy/release.sh`。所以本单在迁移之后补上这一步，不和 #28 重复。
- 目录里没有账号、邮箱、组织编号这类值：`CatalogSchema` 是严格模式，没有这类字段；账号池 id 是代号，账号和凭据在会话用户自己的 reclaude、`/etc/fleet-dao` 下的额度读取器配置和 Jev 配置里。所以法国的真文件和样例取值一样，只有开头那句说明不同。它进保险箱，是因为它是法国 `/etc/fleet-dao` 下的一个文件（保险箱照它的 README 给整个目录留加密副本）。
- 保险箱只有创始人电脑上的钥匙解得开（design 第三节第 33 条），法国解不开：「把保险箱里的真文件放到法国」只能在创始人电脑上做，发布脚本在法国只查它在不在、属主权限对不对，再装。
- 装进去之后能改什么（读代码核过）：装载器对已有的池只补空着的会话用户、到期日，不改并发；阶段排过一次（`stage_policies.catalog_applied_at` 有值）就不再动。驾驶舱后端写目录只有两个口：阶段（顺序、挂上摘下、钉住；新挂上的是开着的）和渠道开关。池的并发、路由的字段、阶段里单条路由的开关，驾驶舱和装载器都改不了。

## 目录怎么排

| 阶段 | 顺序（开着的在前） |
|---|---|
| 分诊、需求文档、方案、写码、审查、调研 | 独享号 Opus 5.5、拼车号 Opus 5.5 开着；中转的 Opus / GPT / Kimi / DeepSeek、Cursor Auto、Grok 挂在后面关着 |
| UI | 同上，但不挂 GPT（硬禁令，关着也不行） |
| 判断（Jev） | TypeSafe 的 Jev 开着；独享号、拼车号的 Opus 5.5 挂在后面关着 |

- 两个 Claude 池：独享号 `claude-solo`（会话用户 `fleet-agent-dedicated`，主池，并发 4），拼车号 `claude-carpool`（会话用户 `fleet-agent-carpool`，备池，并发 2，照 design 第九节「并发起步 2」）。合起来 6 个，对上 design 第四节「6 个会话（约 5 个子任务 + 1 个审查）」；每个会话按 1.2–1.6G 算，12G 的机器放 7 个太紧。
- 「拼车号派短而独立的活」不靠排序，靠引擎的主备池规则：#28 的分支里引擎读路由时，会话用户是 `fleet-agent-carpool` 的池算备池；备池只接短而轻的活、同时最多 2 个、排在主池后面（主线 `packages/engine/src/routing/filter.ts` 的 backupBlocks、`packages/engine/src/routing/rank.ts` 的 backup-pool；哪些阶段算轻在 `packages/engine/src/routing/policy.ts` 的 stageWeight：分诊、判断题、需求文档、审查算轻，巡检任务由引擎标轻）。所以每个阶段都是独享在前、拼车在后。
- 判断阶段在 Claude 判断后端接上之前先用 TypeSafe 的 Jev（design 第十一节，2026-09-25 定）。`packages/jev` 接进引擎以后，按判断阶段排第一的路由起后端（`packages/jev/src/config.ts` 的 backendForRoute）；这个函数现在还没有调用方——main 和 #28 的分支都没接，现有的单里也没有哪张认领这一步。它只接得了 TypeSafe（执行方式 api-shell、模型钉死 jev-1.13.0；法国 `/etc/fleet-dao` 里已有它的配置和钥匙），Claude 判断会话在接上 fleet-agent-scope 之前一律拒。所以样例里新加族 `jev`、模型 `jev-1.13`、路由 `jev:jev-1.13:api-shell`（挂在原有的 `jev` 池下）。两条 Claude 挂着但关着：接不了的开着，选路一旦轮到它就是装机错。
- 中转、Cursor、Grok 先挂上、关着：P3 接好插头、会话用户登录之后再打开（驾驶舱里没有单条开关，摘下再挂上就是开着的）。装载器每个阶段只排一次，现在不挂，以后就得去驾驶舱一条条挂。

## 发布怎么装

1. 放文件（一次，在创始人电脑上）：保险箱仓里解开，直接经 ssh 管给法国 `/etc/fleet-dao/catalog.json`，root:fleet 640。法国那头先落临时名，收到的是空的、不是完整的 JSON 就不换：解密失败时那头收到的是空的；传到一半断了，那头的 `cat` 照样正常收完，半截文件不是空的，所以光看空不空挡不住，还得在那头核对 JSON。命令写在 ops 第九节「目录配置」；飞书网关通行证那条同样改成那头核对整行格式再换。
2. 发布脚本迁移之后、切版本之前多一步「装目录」：
   - 这一版没有装载器（老提交）：跳过。
   - 文件不在、是符号链接或目录、属主权限读不到或不是 root:fleet 640：报红、停下、不切版本。
   - 读回装之前的行数和装载器最近一次的操作记录编号；读不到、认不出：报红、停下。
   - 以 fleet 跑装载器（同迁移那一步的身份和库连接）。装不成（格式错、引用不存在、撞禁令）：把装载器的话原样打出来、报红、停下。不光信它「整批不写」，再读回一次和装之前比，照实写：读回核过（行数、操作记录都一样）、库变了要人看，或者没查成。
   - 装完读回账号池、路由、阶段、阶段里挂的路由四张表的行数，哪张是 0 行都报红、停下，带上装之前的行数：只有阶段里挂的路由是驾驶舱摘得光的（阶段排过一次装载器就不再补），就提示去驾驶舱挂上；别的表是 0 行要人看。读不回也报红。
   - 操作记录编号变了（装载器只在改了库时记一笔）记一处改动，没变就是「一行没改」：同一版再发一遍，这一步改动 0 处。
3. 为什么挡在切版本之前：和迁移一样，装不成就停在原版本，不会切过去才发现派不出活；装载器只补缺，旧版本照样认这些行，退回不受影响。

## 定了的（2026-09-25，#55 审查时总指挥拍板）

1. **判断阶段**：TypeSafe 的 Jev 排第一。Claude 判断后端接上之前只有它答得了；Jev 本来就是判断用的小模型，创始人已同意先跑一周看账单。design 第三节第 8 条、第十一节跟着写明了这个例外。
2. **独享号并发 4**：独享 4 + 拼车 2 = 6，对上 design 第四节起步的 6 个会话；plan 第七节「独享号从 4 个、拼车号从 2 个起步」跟着改了。
3. **真文件怎么到法国**：在创始人电脑上跑一条命令（上面第 1 步）。
4. **装不成挡住发布**：停在原版本，报红。

改这几样什么时候是「一两行」：只在第一次装进法国库之前——改样例和保险箱里那份就行。装进去之后，照上面「先读清的现状」最后一条：阶段顺序、渠道开关在驾驶舱改；池的并发这类只能在法国库里直接改，改完再把样例、保险箱里那份改成一样，换机重装时才不会装回旧值（ops 第九节「目录配置」写了怎么改）。

另有两件事实，要知道：

- 目录里记不了「哪个池对应哪个账号」：表里没有这一栏。要记的话得改表结构，另开单。
- 保险箱的 `refresh.sh` 是「服务器 → 保险箱」的方向：服务器上没有的文件，它会从保险箱删掉（git 历史里还在）。目录是先进保险箱、再放到法国的，所以法国放上去之前别跑 `refresh.sh`；保险箱仓 README 里写了一句。放上去之后两边一样，照常刷新。
