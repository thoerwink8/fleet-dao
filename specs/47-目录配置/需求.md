# 法国的目录配置：账号池、路由、各阶段顺序写好、进保险箱、发布时装进库（#47）

对应计划：plan.md P1 的「数据表 v1」一条；取值照 plan.md P3 的「调度」一条（其中「构建期关着，全用 Opus 5.5」「每个账号池的并发」）。
设计依据：design 第九节（选路、主池与备池）、第十节（账号池的实际划分）、第十一节（Jev 判断题服务）、第三节第 8 条（构建期全程 Opus 5.5）、第三节第 33 条（密钥副本放保险箱）。

## 起因

2026-09-25 开跑前只读核对发现：法国库里族、渠道、账号池、模型、路由、各阶段顺序这些目录表**全是 0 行**，机器上也没有目录文件。装载器写好了（`packages/db/src/catalog.ts`，读 `/etc/fleet-dao/catalog.json`，发布时在迁移之后跑），但真正的目录文件没人写。没有它，引擎起来也不知道把活派给谁。

## 要什么

- 写出构建期的真目录：按 design 第九节（选路）、第十节（账号池：独享号是主池，拼车号派短而独立的活）和「构建期全程 Opus 5.5」。两个会话用户是 `fleet-agent-dedicated`、`fleet-agent-carpool`（法国已装好 reclaude 并登录）。每个阶段的路由顺序照设计排；Jev 阶段按 `packages/jev` 的配置。
- 真文件里凡是账号、邮箱、组织编号这类值，放私有的 `fleet-dao-vault` 仓（按它的 README 加密放法国那一份）；公开仓只放 `catalog.example.json`（占位值），CI 用样例跑校验。
- 发布时把真文件放到 `/etc/fleet-dao/catalog.json`（root:fleet 0640），迁移后装载；装载第二遍零改动。
- 装载失败、文件缺、引用不存在都明确报错，库里一行不写（装载器已是这样，补上发布那一层的读回：装完查几张表的行数，0 行判红）。

## 怎么算做完

- PR 审过合进 main；需求文档放 `specs/47-目录配置/需求.md`（照本单抄）。
- 本地：样例目录装进测试库，行数对得上；故意写错一处引用，装载报错、库里 0 行。
- 法国：随 #28 的发布装进去，pools、routes、stage_policies 都有行；再发一遍零改动。
