## 要修的两处

1. **会话内存上限**：会话的内存软上限 1.5G、硬上限 2G（`packages/engine/src/limits.ts` 的 `sessionMemoryHighMb`、`sessionMemoryMaxMb`）是 2026-09-25 照旧仓估算定的起步值，design 第四节写着「实测后调」，一直没实测。vitest 5.0.1 默认开「核数 − 1」个进程（法国 6 核 → 5 个），每个进程在内存里建一份 PGlite 数据库（`packages/db/src/testing.ts`）。#160 的写码会话跑 `vitest run packages/api packages/db` 用到约 1.77G，被内核持续回收，十几分钟一动不动。
2. **交活核对**：fleet-dao 在库里的测试命令是 `pnpm check`，交活要求会话跑过它、最后一次通过；它最后一步卫生检查要读敏感值名单，会话用户按设计读不到，永远退出 2。AGENTS.md 又规定本机只跑改动涉及的包、不跑全量，两条互相矛盾，任何会话都交不了活。

## 定了的修法（创始人 2026-09-26 同意）

- vitest 按当前 cgroup 的内存上限算开几个进程，没有上限（本机、CI）照默认；读不到、认不出上限就报错，不猜。会话内存上限按法国实际容量重算：11G 扣掉常驻服务，除以同时跑的会话数，算法写进注释。
- 仓里加「改动影响到的测试」命令 `pnpm test:changed`（`vitest run --changed origin/main --passWithNoTests`）。vitest 顺着 import 找不到的依赖（迁移 SQL、测试里直接读的文档）放进 `forceRerunTriggers`，改到就全跑。
- 引擎的交活核对只认「会话跑过 test:changed、最后一次通过」；全量检查和卫生检查只归 CI 和引擎推分支时自己的扫描。测试命令改在真正的出处（写进库的那个源头），免得下次发布又写回 `pnpm check`。

## 追加（创始人 2026-09-26 拍，design 第三节第 39 条）

- 先改测试、不加机器：测试共用一个真 Postgres，每个测试进程从模板库克隆自己的测试库（克隆一次几十毫秒；做法参考 IntegreSQL，https://github.com/allaboutapps/integresql），测试库和正式库分开装、AI 会话碰不到正式库；没配这个库时（本机、CI）照旧用 PGlite。估计每个测试进程从约 0.9G 降到约 0.3G，要实测。
- 法国 VPS 不买、不升级（现在按月付，以后打算包年）。
