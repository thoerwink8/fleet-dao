# 方案：ssh 标准错误里的 GBK 中文还原成能读的字（#409）

## 断在哪

两处叠在一起：

1. **ssh 自己转义**：OpenSSH 打致命错误前把非 ASCII 字节按 `\NNN`（八进制）转义。Windows 中文系统上 `getaddrinfo` 给的原因是 GBK 字节，「不知道」＝ `B2 BB D6 AA`，于是打成 `\262\273\326\252…`。
2. **本机外壳按 UTF-8 解**：`seat.mjs`、`claim.mjs` 的 `spawnSync(..., { encoding: 'utf8' })` 把标准错误当 UTF-8 解。万一 ssh（或别的版本）直接吐 GBK 原字节，解出来是一串 `�`，原字节已经丢了，后面再怎么认都救不回。

所以修在两步：外壳把 ssh 的标准错误**原字节**交给 `seat-lib.mjs`；`seat-lib.mjs` 在取第一行、抹字（`scrubText`）之前统一还原。

## 怎么做

### `seat-lib.mjs`：新增导出 `readableStderr(raw)`（字符串或 Buffer 都收）

- **Buffer（原字节）**：先按 UTF-8 严格解（`TextDecoder('utf-8', { fatal: true })`），成了就用；不成再按 GB18030（GBK 的超集）严格解；都不成，就把每个非 ASCII 字节写成 `\NNN` 八进制（和 ssh 同一个样子），ASCII 部分照原样——不吞、不出 `�`、不抛错。
- **字符串**：找连续的 `\NNN` 转义段（只认 `\200`–`\377` 这种高位字节，ASCII 范围的反斜杠照原样，免得误伤路径之类），每一段还原成字节，同样先 UTF-8 严格、再 GB18030 严格；哪段解不开，那段原样留着（保留 `\NNN` 原文）。
- 运行环境没有 GB18030 解码器（Node 用了精简 ICU，`new TextDecoder('gb18030')` 抛 RangeError）时，当作「认不出」走原样留着的路，不抛错。
- `firstLine` 改成先 `readableStderr` 再取第一行、再 `scrubText`（先还原再抹：转义里藏着的东西还原后才抹得到）。`callFrance` 里用到 `r.stderr` 的两处（255 连不上、退出码认不出）都经 `firstLine`，不用另改；`r.stderr || r.stdout` 这里对空 Buffer 要按「没有」算（长度 0 的 Buffer 是真值），改成先判长度。
- `claim.mjs` 里 git 的 `firstLine(g.stderr)` 也经同一个函数，字符串输入不受影响。

### `seat.mjs`、`claim.mjs`：ssh 的标准错误交原字节

- `spawnSync` 不带 `encoding`，`stdout` 自己 `toString('utf8')`（法国回的 JSON 是 UTF-8，照旧），`stderr` 原样交 Buffer。
- `claim.mjs` 的 `run` 同时给 git、gh 用：只给 ssh 这一路改（加个参数或单独写一个 `ssh` 函数），git、gh 照旧 utf8 字符串。
- 文件头注释补一句「ssh 的标准错误交原字节，由 seat-lib 认编码」。

### 不碰

- `worker-lib.mjs`、`france-lib.mjs` 里各自的 `firstLine`／抹字不在这张单里（没撞到 ssh 中文报错）；`scrubText` 本身不改。
- 退出码、「按不是帅位算」的判法不变。

## 怎么验证

测试加在 `agents/test/seat-claim.test.ts`（不是 `agents/test/rules/`，不算改标准）：

1. 纯函数 `readableStderr`：
   - GBK 原字节 `Buffer`「ssh: Could not resolve hostname contabo: 不知道这样的主机。\r\n」→ 还原成那句中文。
   - ssh 转义后的字符串（同一句的 GBK 字节写成 `\NNN`）→ 同上。
   - UTF-8 原字节的中文 → 照旧能读（别被当成 GBK）。
   - 【故意造出的失败】坏字节（如 `FF FE 80`，UTF-8 和 GB18030 都解不开）→ 不抛错，输出里是 `\377\376\200` 原样；坏的 `\NNN` 转义段原样留着；ASCII 反斜杠（如 `C:\Users\a`）不动。
2. 走一遍 `seat check` / `claim show`：假 ssh 回 255、stderr 是 GBK 原字节（和转义字符串各一条），`err` 里出现「ssh 连不上法国：… 不知道这样的主机。」，退出码仍是 2。
3. 本机跑 `pnpm test:changed`、格式和类型检查。Windows 真机复现不在本机做（本机是 Linux）；由上面按字节构造的用例覆盖。
