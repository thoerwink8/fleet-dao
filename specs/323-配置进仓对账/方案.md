# 方案：配置和开关进仓、偏离了报警（#323）

## 先读清的现状（2026-09-27 晚）

- 代码：主线 → 自动发布（每 5 分钟拉一次主线，CI 绿、引擎空闲才发，健康检查不过自动退回）→ 法国。每一版一个目录，`current` 指着在用的；应用单元跟着版本走。
- 配置：法国 `/etc/fleet-dao` 下的 `engine.env`、`api.env`、`release.env` 第一次照 `deploy/france/*.env.example` 建，之后「归人改」。france.sh 只补样例后来加的键（只补缺）、钉住三项、查属主权限。期望的值在哪都没有带版本的记录：`FLEET_CANARY_REPO` 只在机器上；`release.env` 的 `FLEET_SERVICES`、`FLEET_HK_PARTS` 和样例不一样，仓里也没写法国上应该是什么。
- 法国上逐项核对过（只比键名、和样例一不一样，一个值都没读进对话）：`engine.env` 15 项和样例一样，多一项 `FLEET_CANARY_REPO`；`api.env` 和样例不一样的 4 项都是私有值（驾驶舱地址、webhook 密钥、飞书两项）；`release.env` 的服务、往香港发的几样是公开值，域名是私有值；`france.env` 两项都私有。
- 私有值：机器上明文；保险箱仓（fleet-dao-vault）有 age 加密副本，方向是「机器 → 保险箱」（创始人电脑跑 `refresh.sh`，整个 `/etc/fleet-dao` 打包加密）；只有创始人电脑上的钥匙解得开，法国解不开（design 第三节第 33 条）。
- 开关：「让 AI 接活」是库里的 `repos.auto_dispatch_since`，法国 root 跑 `fleet-api dispatch` 改，同一事务记操作记录；0003 第 10 条把它归「指令（法国库，马上生效）」。

## 业界怎么做（2026-09-27 查）

| 出处 | 说的是 |
|---|---|
| OpenGitOps 四条原则 https://github.com/open-gitops/documents/blob/main/PRINCIPLES.md | 期望要声明式、有版本且不可改、由程序自动拉、持续对账 |
| Argo CD「Automated Sync Policy」https://argo-cd.readthedocs.io/en/stable/user-guide/auto_sync/ | 默认不自愈：线上被手改只标 OutOfSync，不改回；自动同步一个提交只做一次；自愈（selfHeal）是单独的开关 |
| Argo CD「Secret Management」https://argo-cd.readthedocs.io/en/stable/operator-manual/secret-management/ | 强烈建议密钥在目标机器那一侧管（Sealed Secrets、External Secrets），部署工具不经手密钥；密钥更新和普通发布分开 |
| Argo CD 的 diff 把 Secret 的值打成 `++++++++` https://github.com/argoproj/argo-cd/issues/6640 | 私有值照样比，只是不显示值 |
| Flux「Manage Kubernetes secrets with SOPS」https://fluxcd.io/flux/guides/mozilla-sops/ | SOPS + age 加密后进仓，解密钥匙放在集群里，集群自己解；推荐 age |
| Sealed Secrets https://github.com/bitnami-labs/sealed-secrets | 用集群的公钥加密，密文可以进公开仓，只有集群解得开 |
| age https://github.com/FiloSottile/age | 一个文件可以加密给多把钥匙；v1.3.0 起有抗量子的钥匙 |
| Helm「Automatically Roll Deployments」https://helm.sh/docs/howto/charts_tips_and_tricks/ | 把配置的 sha256 写进声明（`checksum/config`），拿指纹跟配置走 |
| GitGuardian《State of Secrets Sprawl 2026》https://blog.gitguardian.com/the-state-of-secrets-sprawl-2026/ | 私有仓里明文密钥比公开仓多约 6 倍：私有不等于安全 |
| ENISA《Pseudonymisation techniques and best practices》（2019）https://www.enisa.europa.eu/publications/pseudonymisation-techniques-and-best-practices | 不带钥匙的哈希对低熵的值能被字典撞出来，要用带钥匙的 HMAC |
| Martin Fowler《Feature Toggles》https://martinfowler.com/articles/feature-toggles.html | 能静态的开关进源码、跟发布走；运维开关、急停要能在运行时改（放应用库） |

## 私有值放哪：比一比

| | P0 删掉整层：私有值不查 | P1 age/SOPS 加密给法国 | P2 私有配置仓（明文） | P3 只在法国，指纹进仓（推荐） |
|---|---|---|---|---|
| 做法 | 只查在不在 | 密文进仓（公开仓或保险箱），法国有自己的私钥，拉下来解开、照着写 | 新开一个私有仓放明文，法国用只读部署钥匙拉 | 值照旧只在法国（保险箱有加密副本）；公开仓里只记指纹：HMAC-SHA256，钥匙是法国本机随机生成的 |
| 手改私有值查得出吗 | 查不出（需求里「私有值不一致只报不一致」做不到） | 查得出 | 查得出 | 查得出 |
| 私有值自动拉下来写上 | 不 | 能 | 能 | 不能：换值还是人从保险箱放（OpenGitOps 第 3 条对私有值只做到一半） |
| 新的钥匙和凭据 | 无 | 法国一把 age 私钥；放保险箱还要一把部署钥匙 | 一把部署钥匙 | 一把本机指纹钥匙（root 600，不出机器，跟着 refresh.sh 进保险箱） |
| 公开仓里有什么 | 无 | 密文（放公开仓时）：永远在历史里，以后钥匙漏了全能解 | 无 | 只有指纹：没有钥匙猜不出值 |
| 要不要改已拍的规矩 | 不 | 要：改「只有创始人的钥匙解得开」（design 第三节第 33 条）；refresh.sh 现在一份收件人名单加密全部文件，法国加进去就能解香港的，得按机器分 | 不，但明文进 GitHub | 不 |
| 代价 | 最小 | 装 sops/age、钉版本校验和、按机器分收件人、改保险箱的方向（保险箱变成期望的源头） | 新仓、部署钥匙、同步脚本；密钥还得另找地方 | 一份期望文件、一个指纹钥匙、一个算指纹的命令 |
| 风险 | 私有值被改没人知道 | 法国被攻破时历史密文全能解；多一条钥匙分发链 | 仓被误设公开、账号被盗就全漏（出处见上：私有仓明文更多） | 指纹看得出「哪天换过」；钥匙丢了私有值全记没查成（一条报警，重算即可） |

推荐 P3：需求要的（期望进仓有版本、每轮对账、私有值只报不一致）全做得到，不改已拍的规矩，不加外部服务，也不给法国新的解密能力。以后要私有值也自动写上，再照 P1 加（改第 33 条，等创始人拍），P3 的期望文件格式留着位置。

GPT 挑错（2026-09-27，一轮）：框架对，P3 更合已拍的规矩，不建议改成 P1（P1 多一条私钥分发和轮换的链，扩大泄密面）。它提的几条都收了：钥匙编号用 HMAC 派生、带版本、32 位十六进制；文件名、键名、分隔符固定进输入；钥匙缺、编号对不上、算法不认识都只报一句「没查成」，不展开成一堆不一致；写明指纹会漏「相等」和「换过的时间」（输入绑了文件名和键名，跨项的相等看不出来）；期望文件不能被没审过的 PR 改——加进先审后合的清单。

## 做法

### 一、期望文件 `deploy/france/desired-config.json`

- 法国 `engine.env`、`api.env`、`release.env`、`france.env` 的每一项：公开的写值（能带一句说明），私有的写 `{ "private": "<指纹>" }`；还没记指纹写 `null`（对账记没查成）。`selfHeal` 是自动改回的开关（先关着），`fingerprint` 写算法和钥匙编号。
- 跟着版本走：对账拿在用的那一版（`current`）里的这一份，还没发出去的期望不算偏离（Argo CD 也是比同一个提交）。所以它不算装机层（自动发布的 `INSTALL_PATHS` 排除它），改了不用重跑 france.sh。
- 先审后合：它定了监听地址、敏感值名单的位置、起哪些服务，以后还会照它写生产配置；读私有值、算指纹的 `config.mjs` 也一样（加进 `packages/conventions/high-risk-paths.json`）。

### 二、指纹

- 钥匙：`/etc/fleet-dao/config-fingerprint.key`，64 位十六进制一行，root:root 600，france.sh 第一次跑时生成，之后不动；在 `/etc/fleet-dao` 里，保险箱的 refresh.sh 自动带上。
- 指纹 = HMAC-SHA256(钥匙, `fleet-dao/config/hmac-sha256/v1\0<文件>\0<键>\0<值>`)；钥匙编号 = HMAC(钥匙, 固定串) 取前 32 位。
- 算指纹只在法国以 root 跑：`node /srv/fleet-dao/deploy/france/auto-release/config.mjs fingerprint <文件> <键>`（`--stdin` 算还没放上去的新值，`--all` 一次算全部），只打印指纹。

### 三、每轮对账（这一期做）

- 自动发布每一轮最后（`deploy/france/auto-release/lib.mjs` 的 configStep，判法在 `config.mjs` 的 judgeConfig）：照 systemd 的读法读线上文件（和 `deploy/lib/app-config.sh` 的 env_parse 同一批样本钉住），一项一条报警 `auto-release:config:<文件>:<键>`：公开的值不对、私有值和指纹对不上、缺了、写了几行、多出来期望里没有的键。和上一轮一样的不重发；改回去了按整个键撤（键之间可能是前缀关系，不按前缀撤）。
- 没查成（期望读不到、认不出，钥匙读不到、不是记的那一把，私有值还没记指纹，对账自己抛了）：一条 `auto-release:config-unchecked`，不当成一致；查成了自己撤。
- 值不进报警、状态文件、读数：报警里只有文件、键名、期望里公开的值。
- france.sh 的读回跑同一份判法（不一致判红、没查成记待配），另查钥匙是 root:root 600 的普通文件。

### 四、发布时照期望写（下一步，这一期不做）

- `release.sh` 切版本（activate）时，照这一版的期望写公开的值：只写「这一版的期望和上次写的不一样」的键（上次写的记在 `/srv/fleet-dao-releases/.config-applied.json`），所以人手改的偏离不被改回（Argo CD 不开自愈的样子），`selfHeal` 开了才改回；第一次没有记录只记基线、不写；退回时照旧版的期望写回去。写不成（期望认不出、线上文件认不出、那个键写了几行）判红、不切。私有值不写，只对账。
- france.sh 新机器上照期望建环境文件（替掉 `engine`、`api`、`release` 三份样例，一件事只存一处），不再「只补缺」。
- 做完这一步，运维文档「改配置」那条才变成「改期望、等发布」。

### 五、开关放哪：要创始人拍

需求里写「开关写成声明进项目配置，对账照声明改库，命令行改的是期望」。和已拍的两条冲突：0003 第 10 条把「开关 AI」归「指令（法国库，马上生效）」；「一件事只存一处」。还有 0003 第 8 条「不许机器给自己派活」：开关进了仓里的 `.fleet/flow.json`，AI 自己开的 PR（CI 绿就自动合）就能把接活打开。

| 选项 | 怎么做 | 代价、风险 |
|---|---|---|
| 1（推荐） | 开关留在法国库当指令：只有创始人的通道（驾驶舱登录、法国 root）改得了，马上生效，有操作记录，丢库时默认关（安全方向）；仓里不放开关。「巡检仓在哪」是引擎配置，走上面的配置对账（`engine.env` 的私有项，指纹进仓） | #323 的第 3 件（开关写成声明）不做，「开关的期望和现状不一致，对账照期望改」那条测试不要 |
| 2 | 开关进仓：`.fleet/flow.json` 写 `autoDispatch`，对账每 15 分钟照声明改库并留痕；命令行、驾驶舱改开关＝机器人开 PR 改声明；动这一项的 PR 要创始人同意才合；急停另加「暂停」指令（库里、马上生效） | 要改 0003 第 10 条、design 15.7 和驾驶舱开关页（#131）；开关要等 PR 合、对账一轮，最多十几分钟 |
| 3 | 两处都放：仓里是基线，基线变了才照着改库；命令行临时改库只报不一致、不改回 | 违背「一件事只存一处」，每次临时改都报警成噪音 |

GPT 挑错（2026-09-27，一轮）：推荐 1 没有根本错，最合「马上生效、创始人拍、机器不能自派、一处存」；要补上只有驾驶舱、法国 root 改得了，所有改动留痕，「暂停」和开关同属运行时指令，仓里只放不需要马上生效的配置。选项 2 把运行时的权限绑在 PR 和对账周期上，既慢又容易漏人闸；选项 3 违背一处存。它另给了第 4 种：开关仍只在库里，仓里只声明「哪些项目允许打开」，对账发现不允许的开着就关掉并报警——私有项目的名字不能进公开仓，这一种要把名单放进各项目自己的配置，等于选项 2 的一半，列在这里供拍。

## 测试（拿改动前的代码跑都红）

- 线上配置被手改，下一轮报出偏离，指明哪份文件的哪一项；改回去下一轮报警自己撤（`deploy/test/config.test.mjs`、`deploy/test/auto-release.test.mjs`）。
- 私有值不一致只报「不一致」：结果、报警、状态文件、读数里都搜不到线上的值和原来的值。
- 期望读不到、认不出、钥匙不对、对账自己抛了：记没查成、报一条，不当成一致。
- 开关那条等第五节拍了再写。
- 另有：读法和 bash 那份同一批样本；期望文件认不出的每一种；指纹绑文件名键名；报警不每轮重发、库连不上下一轮再发再撤；命令行算指纹、对账都不打印值；仓里那份期望钉住的值和 france.sh 一样。

## 真机验（这一期合并、自动发布发出去之后）

1. 在法国重跑 france.sh：装上新的自动发布（多了 config.mjs）、生成指纹钥匙；读回里「配置对账」那几行照实说（私有值还没记指纹，记待配）。
2. 在法国以 root 跑 `fingerprint --all`，把钥匙编号和私有值的指纹写进期望、合进主线；之后配置对账一致。
3. 手改一项公开配置 → 下一轮自动发布报警、指明那一项 → 改回 → 下一轮报警自己撤。

## 分几个 PR

1. 这一期：方案、期望文件（私有值的指纹先空着）、每轮对账和报警、france.sh 生成钥匙和读回、运维文档、AGENTS 本仓段一句。
2. 指纹：法国生成钥匙后，把钥匙编号和私有值的指纹写进期望（改动小）。
3. 发布时照期望写（第四节）、france.sh 照期望建新机器的文件、去掉三份样例；第五节拍了以后照拍的做开关；写结果、关单。
