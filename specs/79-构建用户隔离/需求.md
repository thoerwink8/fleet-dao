# 发布构建换成读不到 /etc/fleet-dao 的专用构建用户（#79）

对应计划：plan.md P5「发布构建和密钥隔开」
设计依据：design 第十四节（安全）。

原话：还欠（发布这块）：构建以 fleet 身份跑，构建期间的第三方代码（前端构建工具等）读得到 /etc/fleet-dao 里 fleet 能读的全部密钥。（docs/ops.md 第九节，2026-09-25）
AI 理解：法国发布时 pnpm 构建以 fleet 跑，前端构建工具这类第三方代码执行时能读到 fleet 能读的密钥。换成一个读不到 /etc/fleet-dao 的专用构建用户，构建产物再交给 fleet 装。#67 清点「推后没落单的话」时开出来的单。

## 要什么

- france.sh 建一个专用构建用户：没有 sudo，读不到 `/etc/fleet-dao`，有自己的 pnpm 和依赖缓存。
- release.sh 的构建一步以这个用户跑，产物目录的属主交接给 fleet；装依赖、构建两步都在它下面。
- 读不到、建不成、属主交接失败：发布明确失败，不退回用 fleet 构建；每条配一条故意造出来的测试（deploy/test）。

## 怎么算做完

- `deploy/test` 里一条测试：以构建用户读 `/etc/fleet-dao` 下的文件被拒；构建脚本里故意去读密钥文件，构建失败并报出路径。
- 法国真机：发一次版，日志里构建一步的用户是构建用户；`sudo -u <构建用户> cat /etc/fleet-dao/<任一密钥文件>` 被拒。
- ops 第九节里「还欠（发布这块）」那一段删掉或改成已做。
