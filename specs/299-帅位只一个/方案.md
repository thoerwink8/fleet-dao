# 帅位只一个：方案（#299）
> 本文档是历史原话，一字不改。帅位的座位（接班、租约、续约、任期、受保护动作前现查、交接存法国库）和认领账（库里认领、心跳作废、改派要原话、推前钩子查认领）已被后来的决定取代：指挥官就是创始人正在对话的会话。现行口径见 [#509](https://github.com/thoerwink8/fleet-dao/issues/509) 和 `docs/goals.md`。


对应需求：`specs/299-帅位只一个/需求.md`；设计：design 第三节第 41 条、第五节（合并闸、先审后合）、第九节「在哪能做与接活开关」；0003 第 7、16 条。

一句话：法国库加两张表——帅位一行（任期号只增不减）、每张单一行认领（认领号）；帅位和本机工人经 ssh 调法国的 `fleet-api seat …`、`fleet-api claim …`；引擎派活、交单和本机认领在同一行上抢；引擎机器人在 PR 上贴「认领对得上」，合并闸认它；认领作废（宽限期没心跳、强制改派）当场撤自动合并、贴红。帅位任期只挡「只有帅位能做的动作」，工人认领另算，换帅位不作废工人的认领。

## 一、业界做法（2026-09-27 查）

- **k8s Lease**（coordination.k8s.io/v1）：一个对象记持有人、租期、拿到的时刻、上次续约、换过几手；别人按「上次续约 + 租期」判能不能抢。client-go 的选主包自己写明「This implementation does not guarantee that only one client is acting as a leader (a.k.a. fencing)」：租约只说谁是头，挡旧头的写得靠栅栏号。<https://kubernetes.io/docs/concepts/architecture/leases/>、<https://pkg.go.dev/k8s.io/api/coordination/v1#LeaseSpec>、<https://pkg.go.dev/k8s.io/client-go/tools/leaderelection>
- **Kleppmann 的栅栏号**（《How to do distributed locking》，2016-02-08）：每次拿锁发一个只增不减的号，存储那一侧记住见过的最大号，带旧号的写一律拒；进程停顿、网络延迟会让拿着过期租约的一方以为自己还持有，各机器的时钟也不可靠。Chubby 的 sequencer（锁名、模式、锁的代号）是同一个思路（Burrows，OSDI 2006）。<https://martin.kleppmann.com/2016/02/08/how-to-do-distributed-locking.html>、<https://research.google.com/archive/chubby-osdi06.pdf>
- **时间用库的**：心跳、过期一律用 Postgres 的 `now()`（事务开始的时刻），不用各机器的时钟。<https://www.postgresql.org/docs/current/functions-datetime.html>
- **GitHub 必过检查**：要在最新提交上通过，旧提交上的不算；可以钉到某个 App，别人贴的同名状态不算；commit status 要 `statuses` 写权限，check run 只能由 App 建（`checks` 写权限）；自动合并可用 GraphQL `disablePullRequestAutoMerge` 撤掉。<https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches>、<https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/troubleshooting-required-status-checks>、<https://docs.github.com/en/rest/commits/statuses?apiVersion=2022-11-28>、<https://docs.github.com/en/graphql/reference/mutations#disablepullrequestautomerge>

照这些定的：帅位是一份租约（谁、第几任、上次续约），任期号就是栅栏号；库里的受保护动作在同一个事务里核任期号，旧号当场拒。GitHub 上的动作（改里程碑、排先后）没有栅栏，只能动手前现查、把空档缩到几秒。工人的认领是另一份锁，认领号是它的栅栏号；真正挡旧工人的是合并闸认的「认领对得上」，推前钩子只算早提醒。

## 二、库（迁移只建表）

### 帅位 `seat_leases`（一个座位一行）

| 列 | 说明 |
|---|---|
| `scope` 主键 | `main` 是真帅位；演练用 `drill:<名字>`，和真帅位互不影响 |
| `term` | 第几任，只增不减 |
| `holder_machine`、`holder_session` | 谁：机器名（`doing.mjs machine` 那个）加会话编号 |
| `acquired_at`、`renewed_at` | 库的 `now()` 写 |
| `previous_machine`、`previous_session` | 上一任，接班时从旧行抄过来，旧的查到换了人时说得出「帅位已交给 X」 |
| `handoff`、`handoff_at` | 最新一份交接说明（只算补充，交接以现算的为准） |

- **接班**：一条语句 `insert … on conflict (scope) do update set term = seat_leases.term + 1, previous_* = seat_leases.holder_*, holder_* = excluded.holder_*, acquired_at = now(), renewed_at = now() returning *`。不看旧帅位同不同意、过没过期：后说的算，任期号一直往上加。
- **续约**：`update … set renewed_at = now() where scope = $1 and term = $2 and holder_machine = $3 and holder_session = $4 returning …`。任期、持有人对得上就续（过了期也能续：过期只说明联系不上，没有别人接班就还是它）；对不上回「帅位已经换成 X（第 N 任）」。
- **现查**：只读，按库的 `now()` 算。对得上而且没过期才算「是帅位」；过期了算「不是帅位」（fail closed），先续约再动手；读不到、认不出也算「不是帅位」。
- **受保护动作**（认领新单、改派、交单给引擎、派新工人）在同一个事务里先核「任期对得上、没过期」，再做事；核不过整个事务不做。
- 租期写进配置：`settings` 表的 `seat.leaseMinutes`（默认 45；帅位每 15 分钟续一次），没写用默认、写明用的默认；写了认不出明确失败，不拿默认顶。

### 认领 `issue_claims`（每张单一行）

| 列 | 说明 |
|---|---|
| `repo_id`、`issue_number` | 主键：每张单一行 |
| `claim_id` | 认领号（uuid），每认领一次换一个；工人的栅栏号 |
| `owner_kind` | `engine` / `seat` / `worker` |
| `owner_machine`、`owner_label` | 哪台机器、哪个会话或工人；引擎的是空 |
| `seat_scope`、`seat_term` | 哪个座位、第几任帅位认领的（引擎自动派的是空） |
| `state` | `pending_start`（引擎：待起）→ `claimed` → `doing` → `pr_open` → `done` / `released` / `voided` |
| `workflow_id` | 引擎的：要起的工作流编号，照旧 `req:<仓>#<号>` |
| `pr_numbers` | 这份认领开过的 PR（一张单可以分几个 PR；工人登记、贴状态时见到带着认领号的也记上） |
| `heartbeat_at`、`claimed_at`、`updated_at`、`ended_at` | 库的 `now()` 写 |
| `grace_minutes` | 这份认领的宽限期（默认取 `settings` 表的 `seat.claimGraceMinutes`，120；演练时认领带短的） |
| `end_reason`、`note` | 为什么结束；最近一句进度 |

- 结束了（做完、放弃、作废）的行留着，直到这张单下一次被认领时整行换掉：旧工人拿着旧认领号来，查得出「已作废，现在归 X」。
- 流水进 `audit_log`（`target = claim:<仓>#<号>`）：认领、每一步、开 PR、结束、作废、改派各一条，谁做的、带哪个认领号。
- 抢：`insert … on conflict (repo_id, issue_number) do update … where issue_claims.state in ('done', 'released', 'voided') returning *`。没回行 = 别人拿着，回谁拿着；拿到的回新认领号。引擎和本机、两台本机都走这一句，只有一边拿到。
- 只管库里有的仓（驾驶舱导入过的项目，`repos` 表）；没导入的项目照旧只靠单上的「在做」评论。「认领对得上」和推前钩子先只在 fleet-dao 上。

## 三、法国命令行（`fleet-api seat`、`fleet-api claim`）

本机经 ssh 以 root 调（ops 第五节：创始人的电脑本来就以 root 登法国）：`ssh <法国> 'bash /srv/fleet-dao-releases/current/packages/api/bin/fleet-api seat …'`。机器名、会话号放参数里（经 ssh 进来的一律是 root，看不出是谁）。每条都读回再打印，退出码：0 好了，1 没做成（连不上库、库出错、设置认不出），2 参数不对（不连库）；3 = 不是你的（帅位换了人、过了租期、认领在别人手里、认领号对不上）。都能带 `--json`：只往标准输出打一行 JSON，给本机脚本认，认不出按「不是帅位、没查成」算。实现在 `packages/api/src/seat-cli.ts`。

| 命令 | 谁调 | 做什么 |
|---|---|---|
| `seat take --machine M --session S [--scope drill:x]` | 被指定的帅位 | 接班，打印新任期和上一任 |
| `seat renew --machine M --session S --term N` | 帅位，每 15 分钟 | 续约；对不上退出码 3、写明现在是谁 |
| `seat check --machine M --session S --term N` | 帅位，每个受保护动作前 | 现查，是帅位退出码 0，过期、换人 3 |
| `seat show [--scope]` | 谁都行 | 帅位是谁、第几任、上次续约，加现算的交接：在做的认领（谁、状态、上次心跳、PR）、引擎在跑的任务、没答的提问、没处理的提醒 |
| `seat handoff --machine M --session S --term N` | 帅位；刚被换下的上一任 | 存一份交接说明（从标准输入读）：现任整份换掉，上一任接在后面补一段（退役时把没记的话转进交接） |
| `claim take <仓> <号> --machine M --session S --term N --label L [--owner worker|seat] [--grace-minutes m] [--note …]` | 帅位（派工人、自己动手前） | 在同一个事务里核任期、抢这一行；打印认领号 |
| `claim step <仓> <号> --claim C [--note …] [--pr P]` | 工人每一步、开了 PR | 心跳加一句进度；带 `--pr` 的记进这份认领开过的 PR、状态到 `pr_open`；认领号对不上退出码 3 |
| `claim done` / `claim release <仓> <号> --claim C --note …` | 工人 | 做完 / 放弃 |
| `claim reassign <仓> <号> --to worker\|engine … --term N [--founder "<原话>"]` | 帅位 | 改派：作废了的直接改；还活着的要带创始人原话，旧 PR 撤自动合并、关掉、留言指向新主 |
| `claim show <仓> [<号…>] [--all]` | 谁都行 | 谁拿着、状态、心跳、认领号前 8 位（默认只列还活着的） |
| `claim sweep` | 引擎定时（演练时手动） | 宽限期过了没心跳的作废，接着撤自动合并、贴红、留言（#348 接上；引擎每轮 GitHub 对账跑同一段） |

交单给引擎（`fleet-api handover`）也是受保护动作：多带 `--term`（帅位调）；运维以 root 手敲、不带任期的，要带 `--founder "<原话>"`，照写进操作记录。

## 四、引擎怎么接

- **接活**：过了开关、版本、母单子单几道之后，在同一个事务里给引擎抢这一行（`owner_kind = engine`、`state = pending_start`、`workflow_id`）：别人（本机）拿着就不派，记 `claimed_local`，原因写谁拿着；引擎自己已经拿着（重投、重放）照旧往下起。起成了改 `doing`；起失败这条投递照旧记成出错、对账重放，认领留着待起。（第 4 个 PR 做了，`packages/api/src/issue-intake.ts`。）
- **待起的补起**：投递重放最多 5 次就不再自动重放，所以每轮 GitHub 对账（15 分钟）另扫一遍 `pending_start` 超过 5 分钟的认领，照行里的 `workflow_id` 经同一个拉起实现再起：起成了、或者回「已经在跑」（上一次其实起成了），都改 `doing`；起不成记没查全（这一轮 partial，驾驶舱「定时任务」页 `why` 写哪张没起成；没另报提醒），下一轮再来。编号每张单固定，Temporal 按编号去重，不会起两份。只起任务还在排队的：工作流已经在跑的只改 `doing`；上一轮已经结束的（重开再起那种）放下认领、交回还在等的投递按重开的规矩再起——这里也起会和那条投递各起一轮；开关关了、GitHub 上关了的也放下。
- **交单**（handover）：同一句抢，本机拿着的拒（退出码 3），除非带创始人原话（`--founder`）强制改派：本机那份认领当场作废、给引擎；它开着的 PR 撤自动合并、关掉随第五节那个 PR 接上，之前打印出来手动做。帅位上线后（库里有 `main` 座位）交单要带任期（`--machine`、`--session`、`--term`，和认领同一个事务里核）或创始人原话；座位上还没人时照旧只要 `--reason`（上线过渡，不然现行的帅位技能交不了单）。这次新认领的没起成就放下（这次什么都没派）。（第 4 个 PR 做了。）
- **「本机做」标签**：认领表上线后改成库里认领的镜子——`pnpm issue:new --local` 开单后当场替帅位认领这张单（经 ssh 调 `claim take`），标签留着挡开单那一刻（开单事件可能比认领先到）；接活看到标签又没有认领记录，照旧不派。
- **结束**：Fusion 做完、叫停、失败时（任务进结束状态），这一行在写任务快照的同一个事务里跟着结束（`done` / `released`）；没派出去就关单的（任务从排队直接叫停）同样放下。工作流在跑、这张单却没有还活着的认领（认领上线前起的任务、交单时起工作流超时其实起成了），写快照时补一份引擎的（在做）：引擎在做的单库里就归引擎；本机拿着的不碰。（第 4 个 PR 做了。）
- **引擎的 PR**：认领归引擎、PR 是「干活的」机器人开的，就算对得上；不改 Fusion 的输入。引擎不用 GitHub 的自动合并，自己的合并队列在 `mergePr` 前照样核必过检查，合并闸认了「认领对得上」以后引擎的 PR 也要有它，所以机器人自己开的 PR 事件（不叫醒工作流的那种）也要贴。
- 操作记录的「谁」：本机的帅位、工人记成 `{ kind: 'ai', id: '<机器名>/<会话或工人>' }`（这个类别库里早有、一直没用上），引擎的照旧 `engine`。

## 五、「认领对得上」

- **谁贴**：引擎机器人，commit status，名字 `认领对得上`，贴在 PR 当前头上。时机：PR 开了、推了新提交、改了正文、重开（webhook 和 15 分钟对账补收都走同一处）；认领变了（认领、登记 PR、作废、改派）时对这张单开着的 PR 重贴。GitHub Actions 不连法国：它只读 PR 头上的这个状态。
- **怎么判**（判法进 core）：PR 正文「需求」栏或标题里的单号（和 `pr-labels` 同一个认法）——
  - 没挂单：过（写「没挂单，不查认领」）。
  - 这张单没有认领记录：过（写「没有认领记录」；上线前开的、创始人自己开的 PR 不被挡）。
  - 认领还活着：引擎的认领、PR 是「干活的」机器人开的——过；本机的认领、PR 正文「认领」栏写的认领号和现在的一样——过；别的一律红，写清现在归谁、PR 上写的是哪个号。
  - 认领结束了（做完、放弃、作废）：红，写清为什么结束、现在归谁。
- **合并闸认它**：merge-gate 多判一条——PR 挂了单，当前头上要有引擎机器人贴的、通过的「认领对得上」，没有、没通过、贴的人不是引擎机器人都判不过（写明原因）。不另加规则集的必过检查：「能不能合」照旧只看 merge-gate 一处。merge-gate 的触发条件加上这个状态。
- **作废**：引擎每轮 GitHub 对账（15 分钟）跑一次 `claim sweep`（演练时手动跑）：按库的 `now()` 找宽限期过了没心跳的本机认领，改成 `voided`；对它开着的 PR（正文「认领」栏是这个认领号的）先撤自动合并（`disablePullRequestAutoMerge`），再贴红、留一句评论。撤、贴没成的记下来、报提醒，下一轮再做（认领已经作废，合并闸那一侧照样红）。引擎自己的认领不按心跳作废：它的死活归工作流和停滞检测管。
- **强制改派**：旧 PR 撤自动合并、关掉，留言「这张单改派给 X（创始人原话：…）；分支留着，新主接着用」，分支不删。
- **要的 App 权限**：引擎机器人要 `statuses` 写权限。创始人 2026-09-27 晚在 App 设置里加上、在安装处接受了，同晚在法国用引擎的凭据读回核过是 write；`REQUIRED_PERMISSIONS` 已加上它，自检（`selfCheck`，原来写了没人调）接进了引擎的每小时对账：缺了、没查成都报 `github-app:*` 提醒，后端 `/healthz` 的 `github_app` 项跟着红。贴状态那一步读得到权限才贴，没权限明确报错，不当成过。
- **和「必过检查必须确定」**（创始人 2026-09-27 晚拍，不叫例外、把规矩说准；design 第五节「发现问题当场修」第 5 条、AGENTS 本仓段随 #299 的库和命令那个 PR 改了）：CI 里跑的检查（`pnpm check`）照旧必须确定、只看检出来的文件；合并闸本来就汇总 PR 此刻的状态——草稿、冲突、各项检查的结果，「认领对得上」是它多认的一样。它只因为这个 PR 的认领不对才红，不会像 #83 那样一关单所有 PR 跟着红。合并闸能看的只有这几样，由 `packages/conventions/test/merge-gate-inputs.test.ts` 钉着。
- **已知的口子**：仓库管理员能绕过规则集（本机的 gh 登的是创始人账号），`gh pr merge --admin` 能跳过合并闸；规矩上本来就不手动合，堵它要改钩子（改标准），另开单。

## 六、本机这边（技能脚本）

- **`seat.mjs`**：接班、续约、现查、看现状、交接，都是经 ssh 调第三节的命令。法国的 ssh 主机名放 `~/.fleet-dao/france-ssh`（不进仓，和机器名文件一个地方）；没有这个文件（手机、网页会话）就明说「这台没有登法国的钥匙，接不了班」。ssh 连不上、输出认不出，一律退出码 2、说「没查成，按不是帅位算」，不当成没事。续约成功的时刻记在本机（`~/.fleet-dao/seat.json`）：离上次续约成功超过租期，现查直接判「不是帅位」、不必等法国回话。
- **`claim.mjs`**：工人的认领、每一步、开 PR、做完、放弃，经 ssh 调 `claim …`；库里成了，再照 `doing-lib` 的样子改单上的「<机器名> 在做」评论（只给人看，是库的镜子）。认领时把「这个分支属于哪张单的哪个认领号」记进本地 git 配置（`branch.<分支>.fleetClaim = <仓>#<号>:<认领号>`），开 PR 时正文「认领」栏写上认领号。
- **推前钩子**（`.githooks/pre-push` 多调一步）：推的分支带着 `fleetClaim` 的，推之前经 ssh 查一次：认领号不是现在这张单的（作废了、改派了、放下了）就拦，写清现在归谁；连不上法国只警告、照推（早提醒，不能让法国一挂连修法国的分支都推不上），真正的边界是合并闸。没带 `fleetClaim` 的分支不查。
- `doing.mjs` 留着当镜子的写法；技能说明改成用 `seat.mjs`、`claim.mjs`（改标准，最后一个 PR）。
