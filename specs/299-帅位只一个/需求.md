# 帅位只一个：调技能换班、旧的自动退，认领进法国库、引擎和本机同表仲裁，本机任务登记，合并前查认领，换班演练（#299）

对应计划：v1 Fusion 接活
设计依据：`docs/design.md` 第三节第 41 条（帅位）、第五节（本机干活照第五节走、先审后合）、第九节「在哪能做与接活开关」（自动派、handover）、第六节「断链怎么被发现」；`docs/decisions/0003-fusion-flow.md` 第 7 条（单模型模式）、第 16 条（帅位）

原话（创始人 2026-09-27 晚）：
- 「其实我也没办法分身乏术，一个"帅位"就够了。但是关于这个"帅位"，我觉得需要通过一种 skills 的方式来指定。比如通过我口头表达，或者手动调用触发，来指定它是"帅位"，然后原来的"帅位"就会自动退役。」
- 「如果帅位闲着，是不是帅位和vps可以互相感知到状态，帅位接一点活来干？」
- 「本机不走引擎流程，但相当于走的是另一套流程。这套流程就像德文（Devin）的普通模式，只有一个 main agent……所以，帅位和本机其实走的是同一套模式。」
- 「从我的角度来看，包括"帅位退役"的方案，比如假设调用 skills 另一台设备时，这台本来在执行"帅位"的设备会发生什么事情，这些边际情况你也要考虑清楚。」
- 帅位列的四个前提：「全都按照你推荐的来吧」；版本怎么切，三选一回「1」：v1 做防撞车和换班这一整块，v2 做本机步骤全卡和对照检验（v2 那块是 #257 下的子单）。

AI 理解：
- 全局只一个帅位。帅位是和创始人对话、记决定、排先后、派本机工人、把单交给引擎的那个会话。
- 创始人口头说或调技能，就当场换班；旧帅位自己发现后退役。
- 本机干活算引擎的单模型模式，只是换了个地方跑：认领、归属、心跳、结果和引擎记在同一处，两边互相看得见、不撞车。
- 前提四条、原话和 GPT 三轮挑错的结论（第 3 轮「一致」）记在 `specs/169-Fusion形态/需求.md`「帅位改回只一个」。

## 定下的（前提四条 + GPT 三轮一致）

1. 全局只一个帅位，管所有项目。
2. 换帅位时，旧帅位的工人各自拿着自己的认领，把手上的 PR 做到合并再停，不接新活。
3. 分活：
   - 独立的单，引擎先拿；
   - 本机拿这几类：改引擎本身的、急的、先审后合的、要本机资源的，以及在法国排队太久的。
4. 本机干活就是单模型模式（0003 第 7 条），只对高风险的单找别家验证。
5. 帅位任期和工人认领分两层：
   - 帅位任期只管「只有帅位能做的动作」：派新工人、认领新单、交单给引擎、记决定、排先后；
   - 工人各自持有「这张单的认领」，有自己的认领号和心跳；换帅位不作废工人的认领。
6. 库里的动作靠任期号、认领号挡死（fencing）。
   - GitHub 上的动作（改里程碑、排先后）查完到做完之间有几秒空档，只能缩小，不能消除；每个受保护动作前都现查，不用缓存。
   - 推前钩子只算早提醒，真正的边界是「认领对得上」必过检查，外加认领作废时撤掉自动合并。

## 要做什么

1. **占座与换班（法国库）**
   - 帅位记录：谁（设备名加会话）、第几任、上次心跳、最新交接说明。
   - 换班是一条原子的 UPDATE…RETURNING，心跳和过期都用库的 now()，不靠各机器的时钟。
   - 帅位经 ssh 调法国的命令行接班、续约、现查、看现状。租期写进配置。
   - 续约超过租期没续上的，自己当作已经不是帅位（fail closed）。
2. **认领进库**
   - 每张单一行、唯一约束，记归谁：引擎，或某台设备上的帅位、工人；另记认领号、心跳，最小状态：认领 → 在做 → 开 PR → 合并 / 放弃。
   - 引擎派活、交单和本机认领，在同一个事务里抢这一行。
   - 认领和起工作流用同一个编号：先写「待起」，再起工作流，起失败的由对账补起。
   - GitHub 上的「<机器名> 在做」评论（`doing.mjs`）改成库里认领的镜子，只给人看。
3. **本机任务登记**：本机工人开工、每一步、开 PR、结果，都经 fleet 记进同一处，和引擎的任务一起算。
4. **合并前查认领**
   - 加一个必过检查「认领对得上」：由引擎机器人在 PR 事件上现查库，然后贴结果，不让 GitHub Actions 往里连法国。
   - 认领一作废，就当场撤掉那个 PR 的自动合并，并把检查重跑成红。
   - 创始人强制改派时，旧 PR 撤掉自动合并、关掉并留言指向新主，分支留给新主接着用。
   - 改分支保护、加必过检查算碰安全，先审后合。
5. **换班后的交接**：新帅位开场从库里现算一份，包括在做的单和认领、开着的 PR、等创始人拍的、最近的决定。旧帅位最后写的那份只是补充。
6. **帅位技能改写（改标准，要创始人同意才合）**：`agents/skills/commander-seat/SKILL.md` 的座位规矩和交接两节，写清下面几件：
   - 接班怎么接；
   - 受保护的动作有哪些，每次动手前现查；
   - 旧帅位怎么退：停派新活、关定时自检，在旧窗口说一句「帅位已交给 X」，之后只回「我已退役，帅位在 X」；
   - 创始人在旧窗口说的还没记的话，转进交接；
   - 新帅位开场先重建自检。
7. **旧说法一起改**：
   - design 第 41 条、0003 第 16 条、AGENTS.md 本仓段里的「帅位不设独占……」；
   - `specs/199-驾驶舱帅位栏/需求.md` 里多帅位的说法。驾驶舱显示帅位在哪台设备、第几任，归 #199。

## 换设备时的边界（推演，每条都要有测试或演练）

1. 新设备接班，当场生效，不等旧帅位同意。
2. 旧设备还开着：下一次受保护动作前现查，发现换了人就照第 6 条退役。它的工人照旧把手上的 PR 做完。
3. 旧设备关机或断电：工人的认领超过宽限期没有心跳，就作废。宽限期默认两小时，写进配置。作废后撤掉自动合并、检查变红，新帅位直接改派，不用等创始人说。本机没推上去的改动会丢，所以工人每做完一步就推分支。
4. 旧设备醒过来：工人推分支被钩子拦下，PR 被必过检查挡住，合不进去；旧帅位一动手就查到换了人，退役。
5. 两个窗口都被说了「你当帅位」：后说的算，任期号一直往上加。
6. 法国连不上：换不了帅位。现任也停下派活、交单、认领，只许修法国；恢复后照库里的核对。
7. 手机或网页会话没有登法国的钥匙：接不了班，要明说原因。
8. 现查读不到、认不出，算「不是帅位」，不算「没事」。

## 怎么算做完

- **故意造出失败的测试**，每条都要拿改动前的代码跑红：
  - 带旧任期号的认领、交单被拒；
  - 引擎和本机同时抢一张单，只有一边拿到；
  - 换帅位后，工人的认领照旧有效；
  - 工人超过宽限期没心跳 → 认领作废 → 自动合并被撤、检查变红；
  - 创始人强制改派 → 旧 PR 被关掉，并留言指向新主；
  - 法国连不上时接班失败，明说原因，受保护动作全停；
  - 现查读不到，算「不是帅位」；
  - 旧帅位什么都没写，新帅位也能从库里算出交接；
  - 认领写成了、起工作流失败的，由对账补起，不会起两份。
- **法国真机加两个会话演练**（同一台机器上模拟两台设备；创始人有第二台设备时再真演一遍）：
  1. A 的工人正在做一个 PR 时，把帅位换给 B：A 在下一次受保护动作时退役，它的工人把 PR 合进去；
  2. B 派新活；
  3. 杀掉 A 和它的工人，模拟断电，演练时把宽限期调短：B 改派，旧 PR 的自动合并被撤；
  4. 把 A 拉回来：推不上、合不进，A 说「我已退役」；
  5. 引擎和本机抢同一张单，只有一边拿到。
- 上面「旧说法一起改」那几处都改完。技能那个 PR 经创始人同意才合。
