# 讨论与定期巡审：写方案时几家模型快速讨论、参数在驾驶舱可调；普通 PR 不再逐个审，定期巡审新合进来的改动（方案讨论稿，P1 验收后做）（#69）

对应计划：plan.md P5「定期巡审」
设计依据：design 第五节（流程只为快，不当绊脚石；讨论）、第九节（阶段类型）。

两件事一起做（创始人 2026-09-25）：审查看代码，讨论定方案，是两回事；但都是「几家模型怎么配合」，调度台和驾驶舱里放在一起想。

## 要什么：讨论

原话：盲设计题也要作为驾驶舱的一个模块；用几家、哪几家、思考强度、字数这些都属于配置；各渠道模型之间要有控制关系，让我在驾驶舱里控制输出 500 字还是 400 字、中等还是高强度。这不是盲设计题，也不是审查，应该叫讨论。具体做不做成单独模块、放驾驶舱哪里、怎么和别的功能联动，由 AI 判断。

讨论稿（AI 的初步判断，开工前按规矩先讨论一轮再定）：

1. **做成调度台里的一种阶段「讨论」，不另起一个模块**：它和分诊、写码、审查一样，是「挂一串路由、按顺序选」的活（design 第九节），另起模块就要另一套路由和额度逻辑。
2. **配置项**（调度台「讨论」阶段上，每个仓可覆盖，单个任务可临时改）：
   - 第 0 轮几家独立答、哪几家（从路由里选，禁令照样生效）；
   - 第 1 轮谁来挑错；最多几轮；
   - 每家的思考强度、字数上限、单轮超时；
   - 什么时候自动走讨论（写方案时默认走；重大方案必走；小方案可关）。
   现在本机用的起步值：第 0 轮两家、medium、400 字、最多 3 轮。
3. **驾驶舱里看得到**：任务详情的「规划」一步下面挂讨论记录——各家原答、一致的、分歧、推荐、每条意见收没收；「等你拍」卡片只放一致、分歧、推荐三样，点开才看原答。另有一个「发起讨论」入口：不挂任务的临时问题也能问几家。
4. **联动**：讨论的结论写进需求文档的方案一节（引擎只认需求文档）；用量进各路由的账；某家讨论里的意见被收的比例进战绩，帮调度台排序。
5. **读不到、没答完、结论认不出**：这一家记「没答成」，照样交人拍但写明哪家没答成；不当成「同意」。

## 要什么：定期巡审

普通 PR 测试绿就合、不再逐个审之后，逐 PR 审查和自动测试都抓不到的问题交给定期巡审：跨 PR 的走样、重复实现、同类错误反复出现、测试盲区、文档和代码对不上。

下面是讨论稿（2026-09-25 三家讨论：GPT、DeepSeek 各自独立答，合并后 GPT 挑错 3 条已收），开工前按当时的现状再讨论一轮定稿：

1. **节奏**：每天一次轻量，看当天合进来的改动和受它影响的依赖模块；每周一次深度，看跨 PR 的走样，再抽查一段没改动的关键路径。不扫整仓：整仓太大，模型一次只能看得很浅。
2. **先机械后模型**：静态检查、测试覆盖、重复代码、热点文件先捞候选，模型只判候选和跨模块的问题。
3. **谁审**：一家不是当周主写码厂商的模型，按周轮换；判为严重、或证据不足的，再请第二家复核。
4. **出单**：只出带证据的单（文件行、提交、复现或影响），和已开的单自动去重。先按风险排序；每轮普通问题最多 5 张，严重的不受这个限制。
5. **定级不只靠模型**：碰高风险路径的（数据迁移、权限、往公开处写东西、引擎核心——和第二意见「先审后合」同一份路径规则）按规则直接升级。严重的当天派修，其余进下一批队列；修复走普通流水线。不要人确认。
6. **补检查**：同一类问题出现第二次，尽量补一条自动检查，下次不靠审。
7. **判有没有用**：按严重程度分开记：确认成真的比例、误报、同一问题重复报、问题从合进来到被发现隔了多久、花掉的额度；抽查「关掉说不是问题」的单；统计巡审范围里后来才暴露的问题（漏检）。一月看一次，效果差就改写法或砍掉——不只看确认率，免得它靠少报把比例做好看。

## 怎么算做完

- 驾驶舱里把「讨论」阶段的字数上限从 400 改成 500、强度从中等改成高，下一次讨论按新值跑；任务详情里看得到各家原答和结论，等你拍卡片只有一致、分歧、推荐。
- 法国真机：巡审按天、按周各跑一次，出的单带证据、去了重、严重的当天被派出去；驾驶舱和日报里看得到巡审结果和上面几个数。
- 读不到改动、模型没答完、结论认不出：记成「这次没巡成」，不当成「查了没问题」；每条这样的路径配一条故意造出来的测试。
