# 讨论与定期巡审：写方案时几家模型快速讨论、参数在驾驶舱可调；普通 PR 不再逐个审，定期巡审新合进来的改动（方案讨论稿，P1 验收后做）（#69）

对应计划：plan.md P5「定期巡审」、P5「讨论（#69」
设计依据：design 第五节（流程只为快，不当绊脚石；讨论）、第九节（阶段类型、「讨论」阶段的配置）、15.4（三种群各管什么）、15.5（讨论页）。

## 要什么：讨论

原话（2026-09-25）：盲设计题也要作为驾驶舱的一个模块；用几家、哪几家、思考强度、字数这些都属于配置；各渠道模型之间要有控制关系，让我在驾驶舱里控制输出 500 字还是 400 字、中等还是高强度。这不是盲设计题，也不是审查，应该叫讨论。具体做不做成单独模块、放驾驶舱哪里、怎么和别的功能联动，由 AI 判断。

原话（2026-09-26，大意）：讨论渠道的提速暂时搁置，现在以 Cursor（cursor-agent 无头只读）和 Mirasim 云端为主，以后再接 OpenRouter 这类直连接口（#118）；驾驶舱要有「讨论」这个页面；讨论和原来的盲设计题是同一种东西；怎么和驾驶舱其他模块衔接，由总指挥设计。同日创始人拍了总指挥推荐的方案：讨论是需求工作流里的一个环节，驾驶舱「讨论」页只当它的视图。

已定（创始人 2026-09-26 拍；规则以 design 第五节「讨论」为准，这里只写做成什么样）：

1. **讨论是需求工作流里的一个环节**：库里一张表，驾驶舱「讨论」页（design 15.5）只是视图。一条讨论记题面、第 0 轮各家独立答（原来的盲设计题）、之后每轮挑错、每家的答案和耗时、谁没答上及原因、各家一致的、分歧、总指挥推荐、拍板结论和方案版本；挂在一张需求、一个 PR 或「规矩」上。状态：讨论中 → 等你拍 → 已拍板；人主动叫的小方案到点按推荐做，讨论中 → 已定。
2. **什么时候触发**：只在重大方案时（碰人闸、和已拍规则冲突、新加外部服务、改架构或改阶段划分），VPS 引擎和本机总指挥用同一条判据；拍板期到点归纳时判为重大或群里有分歧，自动接进来；规划阶段碰上重大方案也自动发起。人随时可以叫一次：飞书群里 @机器人「讨论一下」、驾驶舱需求卡上的「发起讨论」按钮；总指挥会话用 `fleet discuss`。
3. **和飞书群衔接**：结果卡（一致的、分歧、推荐、选项按钮，推荐的在第一个）发进这张需求的讨论群，没有讨论群就发项目群，不为每张需求自动开群；一条讨论一张卡、原地更新。人点按钮或回复；只有带新材料的回复才再跑一轮挑错（Jev 判断题判「是不是新材料」）；AI 自动挑错最多 2 轮，人触发的再跑最多 3 轮，到数就停下等人。
4. **拍板**：点了哪个，引擎把结论写进需求或方案文档，绑定当时方案的版本（方案文档的提交号）；挂「规矩」的由引擎开 PR 改 AGENTS.md 或 design。讨论变「已拍板」，需求卡上显示结论链接。
5. **没人拍、飞书不可用**：重大方案到拍板期没人点，停在「等你拍」、不自动执行，引擎照常做别的需求；小方案到点按推荐做。卡片发不出去就进驾驶舱提醒中心的「要人拍」，写明原因，照样等人。
6. **调度台「讨论」阶段**（design 第九节）：它和分诊、写码、审查一样挂一串路由、按顺序选，不另起一套路由和额度逻辑。配置：参与哪几家、每家走哪条渠道（Cursor 命令行 / Mirasim 云端 / 以后的直连接口 #118）、每家硬超时 30 秒、同时最多几家（起步 3：本机 2026-09-26 五家齐跑加工人把进程数顶满、宿主崩过）、连不上自动换下一家；第 0 轮几家、谁挑错、最多几轮、字数上限（起步 400）、思考强度（起步中等）。每个仓可覆盖，单条讨论可临时改；禁令照样生效。驾驶舱里看得到每条渠道最近的成功率和中位耗时。
7. **联动**：用量进各路由的账；某家意见被收的比例进战绩，帮调度台排序。
8. **读不到、没答完、结论认不出**：这一家记「没答上」和原因，照样往下走但写明哪家没答上，不当成「同意」；一家都没答上算「没讨论成」，停在讨论中、提醒总指挥，不出推荐。

本机现状（引擎接活之前）：`~/.local/share/second-opinion/ask.mjs`，四家经 cursor-agent 并行、30 秒上限；2026-09-26 实测 GLM 21 秒、Kimi 25 秒、GPT 27 秒，Grok 常超时。

## 要什么：定期巡审

普通 PR 测试绿就合、不再逐个审之后，逐 PR 审查和自动测试都抓不到的问题交给定期巡审：跨 PR 的走样、重复实现、同类错误反复出现、测试盲区、文档和代码对不上。

下面是讨论稿（2026-09-25 三家讨论：GPT、DeepSeek 各自独立答，合并后 GPT 挑错 3 条已收），开工前按当时的现状再讨论一轮定稿：

1. **节奏**：每天一次轻量，看当天合进来的改动和受它影响的依赖模块；每周一次深度，看跨 PR 的走样，再抽查一段没改动的关键路径。不扫整仓：整仓太大，模型一次只能看得很浅。
2. **先机械后模型**：静态检查、测试覆盖、重复代码、热点文件先捞候选，模型只判候选和跨模块的问题。
3. **谁审**：一家不是当周主写码厂商的模型，按周轮换；判为严重、或证据不足的，再请第二家复核。
4. **出单**：只出带证据的单（文件行、提交、复现或影响），和已开的单自动去重。先按风险排序；每轮普通问题最多 5 张，严重的不受这个限制。
5. **定级不只靠模型**：碰高风险路径的（数据迁移、权限、往公开处写东西、引擎核心——和第二意见「先审后合」同一份路径规则）按规则直接升级。严重的当天派修，其余进下一批队列；修复走普通流水线。不要人确认。
6. **补检查**：同一类问题出现第二次，尽量补一条自动检查，下次不靠审。
7. **判有没有用**：按严重程度分开记：确认成真的比例、误报、同一问题重复报、问题从合进来到被发现隔了多久、花掉的额度；抽查「关掉说不是问题」的单；统计巡审范围里后来才暴露的问题（漏检）。一月看一次，效果差就改写法或砍掉——不只看确认率，免得它靠少报把比例做好看。

## 怎么算做完

- 驾驶舱调度台里把「讨论」阶段的字数上限从 400 改成 500、强度从中等改成高，下一次讨论按新值跑；「讨论」页上看得到各家原答、耗时、没答上的原因和结论，飞书结果卡只有一致、分歧、推荐和选项按钮。
- 渠道：给一家配一个连不上的渠道，这一轮自动换下一家、结论里写明换了谁；每家超过 30 秒记「没答上」；配 5 家时同一时刻在跑的不超过 3 家；调度台和「讨论」页上看得到每条渠道最近的成功率和中位耗时。
- 拍板流（法国真机，巡检仓）：一张判为重大的需求自动发起讨论，结果卡发进它的讨论群（没有讨论群就项目群，不自动开群）；点推荐项后需求文档里写进结论和方案版本，讨论变「已拍板」，需求卡上有结论链接。回一条带新材料的消息再跑一轮挑错，回一条不带新材料的不跑；AI 自动挑错到 2 轮、人触发的到 3 轮就停下等人。
- 没人拍、飞书不可用：重大的到点没人点，停在「等你拍」，同时另一张需求照常做完；小方案到点按推荐做、状态「已定」。关掉飞书发卡，这条讨论出现在驾驶舱「要人拍」里、写明原因、照样等人。
- 在飞书项目群里 @机器人「讨论一下」，对话题里那张需求发起一条讨论。
- 一家都没答上记「没讨论成」、不出推荐；飞书发卡失败不当成发出去了。这两条各配一条故意造出失败的测试。
- 法国真机：巡审按天、按周各跑一次，出的单带证据、去了重、严重的当天被派出去；驾驶舱和日报里看得到巡审结果和上面几个数。
- 读不到改动、模型没答完、结论认不出：记成「这次没巡成」，不当成「查了没问题」；每条这样的路径配一条故意造出来的测试。
