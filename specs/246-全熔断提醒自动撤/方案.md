# 方案：全熔断提醒（routing:all-open）熔断解了由每小时对账自动撤（#246）

## 思路

「全熔断」这条提醒是 `chooseRoute` 走到 `allOpenTrial` 那一支（没有能派的、活着的候选 ≥2 条且全都只被熔断挡着）时，
store-ports 的 `pickRoute` 顺手 upsert 的。判它还在不在，就用**同一段判法**再算一次，只是不派、不写库：

1. **纯函数（routing/choose.ts）**：把 `chooseRoute` 里「排序 → 每条算 blocks → 分组」那段抽成内部的 `judgeStage(input, ctx)`，
   `chooseRoute` 照旧用它（行为不变，现有 choose 测试全绿即证）；新导出 `stageAllOpen(input: ChooseRouteInput): AllOpenCheck`：
   - `{ allOpen: true }`：没有 ready 的，且 `allOpenTrial(judged)` 非空——和 chooseRoute 给出 `trial: 'all-open'` 的条件一字不差；
   - `{ allOpen: false, detail }`：detail 写哪条路由现在不在熔断（有 ready 的写第一条 ready；否则写「不再是只被熔断挡着」+ 各条被挡原因摘要）。
   - 阶段没配顺序、一条都没配：也是 `allOpen: false`（那已经不是全熔断，是别的提醒管的）。
   不看 `taskRouteId`、不抽签（试探用的随机数不影响这个判断）。经 `routing/index.ts` 导出。
2. **只读端口（real/store-ports.ts）**：`createStorePorts` 返回值多一个 `stageAllOpen(stage)`（加进本文件的 `StorePorts` 类型，
   不进 `EnginePorts`）：和 `pickRoute` 同一个 `loadStage`（同一份路由事实和熔断 `breakerOf`）、同样把暂停的账号池放进 avoid、
   同样读会话用户挂的组织；不带流程配置的模型过滤（提醒是整个阶段的）。**不调 `allOpenAlarm`、不写任何表**。
   组织还没读完（pending）或库读失败：抛错（PortError），不返回 false 冒充「解了」。
3. **对账规则（jobs/alert-sweep.ts）**：`AlertSweepDeps` 加 `stageAllOpen(stage): Promise<AllOpenCheck>`；`RULES` 加一条
   「全熔断」：`/^routing:all-open:([a-z]+)$/`，阶段认不出（`isStage` 不过）→ keep；`allOpen` → keep；否则
   `resolve: "<阶段中文名>有路由不熔断了：<detail>"`。撤时现有 `resolve()` 已经把正文开头写成「已撤：…」、处理人记
   `engine:hourly-reconcile`；抛错走现有 catch 记进 unchecked、不撤。文件头注释：从「判不了」清单里删掉 routing:all-open，
   改列进「各种提醒谁来撤」。
4. **接线（real/hourly-reconcile.ts）**：`stageAllOpen: w.stageAllOpen ?? ((s) => store.stageAllOpen(s))`（wiring 加一个测试用注入）；
   顺手把 `stageRoutable` 上面那句「要一个不写库的判法见 #246」的注释改准（stageRoutable 仍走 pickRoute，不在本单改）。
5. **文档**：`docs/design.md` 15.3 那句（现第 570 行）改成：全熔断（`routing:all-open`）由每小时对账判，阶段里有路由不熔断了就撤。

## 怎么验证（对着「怎么算做完」）

- choose.test：同一份输入 `chooseRoute` 给 `trial: 'all-open'` 时 `stageAllOpen` 为 true；有一条熔断解了（ready）/某条不只被熔断挡时为 false 且 detail 写明。
- store-ports.test（PGlite 真库，照现有「连着失败三次熔断」那条造数据）：两条路由都熔断 → `stageAllOpen` 为 true，且
  **库里 `routing:all-open:<阶段>` 提醒没被新建、已有的那条 `updated_at`/正文/`resolved_at` 都没变**（判一次不刷新、不重开）；
  一条的失败过了冷却（或加一次成功）→ false；库读失败（关掉/弄坏 db）→ 抛错不返回 false。
- hourly-reconcile.test（sweepAlerts）：还全熔断 → 不撤、不调 updateOpen/raise；解了 → 撤，正文以「已撤：」开头、含「有路由不熔断了」，
  处理人 `engine:hourly-reconcile`；`stageAllOpen` 抛错 → unchecked 多一条、不撤。
- 本机 `pnpm test:changed`、格式、类型检查通过。
