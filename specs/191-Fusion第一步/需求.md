## 拆活草案（开工时主导模型可以改）

- 主脑和帮手：一张单一个主脑会话，把界定清楚的块派给帮手；写代码的分支同一时间只一个模型写（加锁）；主脑随时存档，断了新会话从存档接着做。
- 验证员：开 PR 前另一家模型对照「怎么算做完」核一遍改动；开工前方案一问一答给别家挑错。
- core 包：这一步新写的判断（执行的状态机、派活先过滤再打分）放进新建的 core 包，只做判断、不碰网络和库；讨论出的边界表变成它的测试。
- 记账：每张单每一步的耗时、各模型花的额度写进库，驾驶舱看得到。

## 怎么算做完

- fleet-dao 一张真小需求由法国引擎按 Fusion 做法（主脑会话、帮手、开 PR 前别家验证员）从收单做到合并、关单，全程没人插手。
- 在有副作用的步骤之间（推分支后、开 PR 后、合并前）各杀一次主脑，新会话从存档接着做完：不重复推、不重复开 PR、不重复合并和关单，读回核对只有一个 PR、一次合并。
- 引擎只把活派给探针判在线的路由；登录失效演练里探针能发现并恢复（#129 剩的两条）。
- 会话内存上限、测试进程数是实测定的，交活核对只跑改动影响到的测试（#164）。
- 驾驶舱看得到这张单每一步的耗时和各模型花的额度。
- 这一步新写的判断在 core 包里，有测试。
