# 引擎打磨：方案（#257）

v2 开工时，由主导或帅位把「需求.md」里的 A 到 H 拆成子单。本文件先记已经查清的几项，开工后再往下补。

## 代码地图：用 codegraph（2026-09-27 查）

**结论**：有用，接进开工的材料包。它给的是代码结构，和仓库经验库（人写的规矩）是两样东西，分开存，都放进材料包。

- **它是什么**：npm 包 `@colbymchenry/codegraph`，MIT 许可，[GitHub](https://github.com/colbymchenry/codegraph)。
  - Rust 内核加 tree-sitter，支持 20 多种语言，含 TypeScript。
  - `codegraph init` 在仓里建 `.codegraph/codegraph.db`（SQLite）。
  - Linux 能无头跑，命令行和 MCP（stdio）都行。
  - 注意：没有 scope 的同名包 `codegraph` 是另一个不相关的包，别装错。
- **给引擎的用处**：
  - `explore`：一次调用给出相关符号的源码、调用链、影响范围，主导就少自己翻代码。
  - `impact` 和 `affected`：给出影响范围和受影响的测试，用来判「改动影响多大」（讨论分档的一个客观因素），也用在开 PR 前的验证。
  - 厂商自己测的数是少 88% 的工具调用、少 62% 的 token。这不是独立测评，要用我们自己的检验比「带它」和「不带它」才算数。
- **坑和对策**：
  - **换了提交不会自动更新**：纯命令行用法下，要先跑 `codegraph sync` 再查，每张单开工时由引擎跑。
  - **每个工作树各一份索引，开销随并行的单子数线性涨**：先实测一个仓建一次多久、多大；太贵就按主线提交建一份共享的，工作树只补增量。
  - **准确率自报 TS/JS 约 96%**：动态分派、反射、依赖注入会漏。它的结果只当「优先看这些」，不当「只有这些」。
  - **两张单撞同一批代码，它没有现成的比对**：各跑一次 `impact`，由引擎自己求交集。
  - **遥测默认开**：文档说只发用量计数和语言名，不发代码。法国机器照样显式设 `DO_NOT_TRACK=1`。
- **别家做法**：
  - [Aider repo map](https://aider.chat/docs/repomap.html)：现算一段按重要性排好的符号清单塞进提示，最轻，但没有调用链和影响范围。
  - [SCIP](https://github.com/sourcegraph/scip) 和 LSP：精确的跳转和引用，但要自己在上面拼出材料包。
  - codegraph 是这几家里唯一把「一次调用给 AI 现成材料」当目标的。

## 仓库经验库按路径带上（2026-09-27 查）

**结论**：源头只放一份，在仓里；由引擎开工时按改到的路径和活的类型挑出相关条目，放进材料包，不靠各家自带的加载机制。

- 各家「碰到某些文件自动带上某段规矩」的机制不统一：
  - Claude Code：`.claude/rules/*.md` 加 `paths:`，碰到文件时动态加载（[文档](https://code.claude.com/docs/en/memory#path-specific-rules)）。
  - Cursor：`.cursor/rules/*.mdc` 加 `globs:`，也能按子目录放 AGENTS.md（[文档](https://cursor.com/docs/rules)）。
  - Codex：按目录层级读 AGENTS.md，会话开始时算一次，上限 32KiB，不是按文件动态命中（[文档](https://developers.openai.com/codex/guides/agents-md)）。
  - Devin：Knowledge 按自然语言的触发条件做语义匹配（[文档](https://docs.devin.ai/product-guides/knowledge)）。
- 一份源头可以机械地转成 Claude Code 和 Cursor 的格式，但转不出 Codex、Devin 的。所以由引擎自己挑最稳。以后要给本机会话用，再从同一份源头生成 Claude Code、Cursor 的格式。

## 上下文压缩阈值（2026-09-27 查，参考 Mirasim）

**Mirasim 的做法只有两层**：
- 各家命令行自带的默认比例，只读：Claude 0.95、Codex 0.9、Kimi 0.85。
- 每家命令行一个全局百分比，界面上有 50/60/70/80/90 几档可选；改了只对之后新开的会话生效。
- 它按上下文用到的百分比算，不按 token 数；没有「某个会话单独改」这一层。

**我们照它按百分比设，再加两层**：全组织默认 → 项目 → 单子。
- 开工时沿用通用设定；单子上改了，从下一个存档点起生效。
- 通用设定放在仓里的流程配置里（规则）；单子上的改动是驾驶舱发的指令，存法国库，马上生效（0003 第 10 条）。

**两道压缩**：
- 我们自己的软阈值先到：主导写存档点，换新会话，读交接包。这就是我们的压缩，换模型也挑这个时候。
- 各家自带的自动压缩当兜底：阈值设得比我们的晚，防止软阈值没触发。

**落到各家**：单位各不一样，引擎按各自的上下文长度换算，起会话时传进去。
- Claude Code：`CLAUDE_CODE_AUTO_COMPACT_WINDOW`（token 数，优先级最高），或 `--autocompact`（[设置参考](https://code.claude.com/docs/en/settings-reference)）。在 `-p` 无头模式下是否生效，要实测。
- Codex：`-c model_auto_compact_token_limit=<token 数>`，注意 `model_auto_compact_token_limit_scope` 两种算法触发时机不同（[配置参考](https://developers.openai.com/codex/config-reference)）。
- Kimi：`[loop_control]` 的 `compaction_trigger_ratio` 和 `reserved_context_size`，两条件哪个先到就触发。
- Gemini：`model.compressionThreshold`，改了要重启进程才生效。
- cursor-agent：没有这个开关，只能靠我们自己的软阈值。这就要引擎读得到它的上下文用量，读不到就明说读不到，不猜。
