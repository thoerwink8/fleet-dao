# #299 认领对得上：引擎给 PR 贴状态、合并闸认它，作废和改派当场撤自动合并（#348）

对应计划：v1 Fusion 接活
设计依据：`specs/299-帅位只一个/方案.md`「认领对得上」「法国命令行」（`claim reassign`）两节；`docs/design.md` 第五节「合并闸」

原话：创始人 2026-09-27 晚「行，都按照你推进」（#299 方案「认领对得上」那节，`specs/299-帅位只一个/方案.md`）；帅位同晚要把 #299 剩下的步骤拆成子单。

AI 理解：认领进了库、引擎也按认领派活了，但 PR 这一侧还没有挡：旧工人（认领被作废、被改派的）开的 PR 照样能合。方案「认领对得上」那节：引擎机器人在 PR 头上贴 commit status「认领对得上」，合并闸认它；宽限期过了没心跳的本机认领作废时，撤它 PR 的自动合并、贴红；强制改派关掉旧 PR。这一步碰合并闸，先审后合。

## 要什么

- 判法进 core：按 PR 正文「需求」栏或标题里的单号（和 pr-labels 同一个认法）——没挂单：过；这张单没有认领记录：过；认领还活着：引擎的认领、PR 是「干活的」机器人开的过，本机的认领、PR 正文「认领」栏的认领号和现在的一样过，别的红，写清现在归谁；认领结束了（做完、放下、作废）：红，写清为什么结束、现在归谁。
- 引擎贴状态：PR 开了、推了新提交、改了正文、重开时（webhook 和 15 分钟对账补收走同一处），认领变了（认领、登记 PR、作废、改派）对这张单开着的 PR 重贴；读得到 `statuses` 写权限才贴，没权限明确报错，不当成过。引擎自己开的 PR 事件也要贴。
- 合并闸（merge-gate）：PR 挂了单，当前头上要有引擎机器人贴的、通过的「认领对得上」，没有、没通过、贴的不是引擎机器人都判不过（写明原因）；`packages/conventions/test/merge-gate-inputs.test.ts` 的名单跟着加上。
- 作废：每轮 GitHub 对账跑 `claim sweep`，作废的认领对它开着的 PR（正文「认领」栏是这个认领号的）先撤自动合并（GraphQL `disablePullRequestAutoMerge`），再贴红、留一句评论；撤、贴没成的记下、报提醒，下一轮再做。
- 改派命令 `fleet-api claim reassign <仓> <号> --to worker|engine … --term N [--founder "<原话>"]`（方案「法国命令行」那节的表里有，#320 没做）：作废了的直接改；还活着的要带创始人原话；引擎在做的改给本机时叫停它的工作流。
- 强制改派（`fleet-api handover --founder`、`claim reassign`）：旧 PR 撤自动合并、关掉，留言「这张单改派给 X（创始人原话：…）；分支留着，新主接着用」，分支不删。

## 怎么算做完

- 合进主线：先审后合（第二意见 `--high-risk` 过了再挂自动合并，最多 2 轮）。
- 故意造的失败各一条：旧认领号的 PR 状态红、合并闸判不过；状态不是引擎机器人贴的判不过；没权限贴状态明确报错；认领作废后自动合并被撤、状态变红；强制改派后旧 PR 关掉、分支还在。
- 法国发上这一版后，fleet-dao 上一个挂了单的 PR 头上看得到引擎贴的「认领对得上」，读回写进这张单的结果。
