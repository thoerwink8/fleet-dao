# 旧坑验收用例（新内核、新驾驶舱必须过）

每条都是旧系统真出过的事（带单号或 PR 号），新系统按「怎么验」过了才算这一片能切。
「测试」＝新包里一条自动化用例，CI 跑；「真机」＝法国上真调一次、库里有记录；「截图」＝两种屏宽和 ashare-Copilot 并排。
没写出处的推测不进这张表。

## 一、会话起不来、卡住、没人收

| # | 坑 | 出过的事 | 新系统怎么验 |
|---|---|---|---|
| A1 | 第一行输出就算「起来了」，之后卡在 `Syncing config…` 一直不出活，worker 又没有空闲时限 | #3749 调查：claude-sub 两成的跑挂在这一步；#3756 | 测试：假 CLI 只吐一行就不动，N 秒内判「起来后无进展」并杀掉重试；判据是「有实质事件」不是「有输出」 |
| A2 | 驱动的总时限和插头的时限各算各的，先到的那个回 aborted 盖掉真正的超时原因 | #1824 前后、60073a0a0 | 测试：总时限到点，失败原因写「总时限 X 分钟用完、停在哪一步」，不是 aborted |
| A3 | 起会话没等到应答就挂起等人，其实会话已经起来了 | 5dee7d3b7 | 测试：应答丢了，按工作目录和起始时间对账接回同一会话，不挂起 |
| A4 | 自测活动限时 20 分钟短于自己的 35 分钟预算，4 张单反复超时重跑 | 84a5f5bc3 | 测试：每层时限从一个预算表派生，子层时限 > 上层时限时启动就报错 |
| A5 | 子进程卡死要靠调大超时 | #264、75b745f65、b130bbedf | 测试：所有子进程走同一个带上限的起法，到点连进程组一起杀；禁用 spawnSync 的 lint |
| A6 | 进程收场丢 OOM 归属证据（退出码 143 看不出是谁杀的） | #3451 | 真机：杀一个会话，库里记录退出码、信号、内存峰值、谁发的信号 |
| A7 | 引擎重启后 schedule_runs 留下 ended_at 为空的孤儿行，看着永远在跑 | #1524、#3623 | 测试：启动时把上一代没收尾的行一次收成「被重启打断」，驾驶舱不显示为在跑 |
