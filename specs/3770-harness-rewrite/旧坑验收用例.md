# 旧坑验收用例（新内核、新驾驶舱必须过）

每条都是旧系统真出过的事（带单号或 PR 号），新系统按「怎么验」过了才算这一片能切。
「测试」＝新包里一条自动化用例，CI 跑；「真机」＝法国上真调一次、库里有记录；「截图」＝两种屏宽和 ashare-Copilot 并排。
没写出处的推测不进这张表。

## 一、会话起不来、卡住、没人收

| # | 坑 | 出过的事 | 新系统怎么验 |
|---|---|---|---|
| A1 | 第一行输出就算「起来了」，之后卡在 `Syncing config…` 一直不出活，worker 又没有空闲时限 | #3749 调查：claude-sub 两成的跑挂在这一步；#3756 | 测试：假 CLI 只吐一行就不动，起步时限（默认 180 秒，进预算表）内没有实质事件就判「起来后无进展」、杀掉重试；实质事件白名单：助手消息、工具调用开始、工具结果，`system`/`init` 类不算 |
| A2 | 驱动的总时限和插头的时限各算各的，先到的那个回 aborted 盖掉真正的超时原因 | #1824 前后、60073a0a0 | 测试：总时限（预算表里的值，含清理和回写）到点，失败原因写「总时限 N 分钟用完、停在哪一步」，不是 aborted |
| A3 | 起会话没等到应答就挂起等人，其实会话已经起来了 | 5dee7d3b7 | 测试：应答丢了，按库里登记的会话号（init 帧里的 `session_id`）对账接回同一会话，不挂起；同一单同时出现两个会话号判冲突、停后起的那个 |
| A4 | 自测活动限时 20 分钟短于自己的 35 分钟预算，4 张单反复超时重跑 | 84a5f5bc3 | 测试：子层继承上层的绝对截止时刻，自己的时限只能更早；子层预算比剩余时间长时启动就报错 |
| A5 | 子进程卡死要靠调大超时 | #264、75b745f65、b130bbedf | 测试：所有子进程走同一个带上限的起法，到点按本次运行的 scope（带 `FLEET_RUN_ID` 标记）收，不杀别人的进程；PID 复用时不误杀；禁用 spawnSync 的 lint |
| A6 | 进程收场丢 OOM 归属证据（退出码 143 看不出是谁杀的） | #3451 | 真机：杀一个会话，库里记录退出码、信号、cgroup 的内存峰值、发信号的是内核自己（带原因种类）还是 OOM（读 cgroup 事件计数） |
| A7 | 引擎重启后 schedule_runs 留下 ended_at 为空的孤儿行，看着永远在跑 | #1524、#3623 | 测试：启动时把上一代没收尾的行收成「被重启打断」，只收确认进程已不在的（看 scope，不只看心跳时刻），驾驶舱不显示为在跑 |

## 九、挑错补的（新内核的新机制，旧系统没出过事，但不过就不能切）

这几类不是旧坑，是新内核去掉 Temporal、并行跑之后必须有的保证（discuss 第 1 轮意见）。不过它们是新机制的验收条件，不是给旧系统加的护栏。

| # | 场景 | 怎么验 |
|---|---|---|
| S1 | 同一条流并发追加 | 测试：两个写者同时追加，`seq` 不重、不跳；后写者重试 |
| S2 | 重复、乱序事件，认不出的 `schemaVersion` | 测试：重复按 `(stream_id, seq)` 去掉，乱序等补洞，认不出的版本拒并报 |
| S3 | 投影删了重建、投影处理中途崩 | 测试：删投影从事件重建，结果和原来逐行一致；中途杀掉再起，结果一致 |
| S4 | outbox 执行成功、写回执前崩 | 测试：假 GitHub 已开 PR、内核在回执前被杀；重起后按幂等键查到已有 PR，补记，不开第二个 |
| S5 | outbox 有一条一直失败 | 测试：毒消息退避、到上限进死信，不挡后面的 |
| S6 | 恢复库以后 | 演练：从备份恢复的库起新内核，已做过的外部动作不再做（回执在）、没做完的按状态继续 |
| O1 | 失去所有权后才收到结果 | 测试：fencing 已加一，旧执行方交回的结果和外部动作被拒并记账 |
| O2 | 网络分区两边都以为自己有 | 测试：租约过期期间原执行方仍在跑，单只标「待确认释放」，确认原会话停了才转手 |
| O3 | 每种切回状态 | 真机：讨论稿第五节 3 的切回表每行演练一次 |
| GH1 | 两个请求同时开同一张单的 PR | 测试：第二个查到开着的 PR 就不开 |
| GH2 | 分支在、库里没记录 | 测试：按分支名和单号对上，补记，不另建 |
| GH3 | PR 被人手动关、改目标分支、改标题 | 测试：下一轮按现读的状态走，不按库里的旧值 |
| GH4 | 合并成功但回执丢了 | 测试：周期对账按 PR 号现读，补记合并 |
| SEC1 | 单、评论、仓库文件里的提示词注入 | 测试：指挥官和工人的提示词里外部内容放在标明「数据」的块里；工人改到仓外路径、读宿主密钥目录被拦 |
| SEC2 | MCP 工具越权 | 测试：工人会话的令牌调指挥官才有的工具被拒；令牌只绑一个会话 |
| SEC3 | SSE 令牌泄漏 | 测试：SSE 不把令牌放在网址里；令牌撤销后连接断开 |
