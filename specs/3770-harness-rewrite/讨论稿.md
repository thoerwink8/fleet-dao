## 一、提出的问题

### 1. 为什么整套重写，而不是接着修

- **现象**：近五周引擎、适配器、核心包 660 个提交，其中带「卡、挂、超时、重复、漏、孤儿」字样的修复上百个（实测：`git log --since=2026-09-25 -- packages/engine packages/adapters packages/core`）。#3749 调查：从开单到合并慢，主要是引擎空转、返工和会话卡住，CI 不是主因（实测，`specs/3749-ci-slim/讨论稿.md`）。
- **根因**：内核的状态散在 Temporal 工作流、`tasks`/`runs` 表、GitHub 标签、通知表几处，每处各有一份「这张单现在怎样」，每修一处就要在另几处补对账（按代码：`packages/engine/src/jobs/` 下对账、看门狗、巡查、清扫各一套）。
- **需求方的思路**：新包整套重写，并行跑、比对、可切回。
- **判断**：成立。旧系统最值钱的是踩过的坑和对应的测试场景，不是 Temporal 编排本身（同行调研的结论一致）。原地重写会让新旧状态源在同一批表里继续混，新包加独立 schema 才能把「一张单的状态只有一处」做出来。
- **做法**：见第五节「总设计」。
- **不做什么**：并行期旧包除一道派单闸（第五节 3.2）外不改；不删任何旧表；桌面壳（#3754）不在这里。

### 2. 新旧并行怎么比、怎么不抢单

- **现象**：已经撞过两次：#3721/#3722 两个指挥官同题各开一个 PR；#3737 本机修的同时引擎开了 #3744（实测）。
- **根因**：认领散在 GitHub 标签、本机租约文件、`tasks` 行三处，谁都能在另一个还没写下之前开工（按代码：`packages/core/src/dispatch.ts` 的 `localGate` 看标签，`pnpm work claim` 写本机和法国登记）。
- **判断**：「比对」和「切换」是两件事，要分开设计（第五节 3.2）。
- **做法**：比对用影子模式（新内核零真实副作用）；切换用单级所有权表加旧引擎一道闸加 GitHub 侧兜底。

### 3. 界面参照参考工作台

- **现象**：参考工作台是 React 19、Vite、Tailwind 4（令牌全写在 CSS `@theme`）、Radix；电脑左侧栏 208px 可收成 64px，手机 768 以下换底部页签 56px 高；页栏吸顶 56px；内容外边距手机 12、电脑 24；只用 4 的倍数、按 px；只有浅色（按代码，参考仓 `web/src/styles.css`、`components/app-shell.tsx`）。
- **判断**：它没有对话区、没有波次图，所以借的是外壳、令牌和组件规矩，会话工作台和波次图的版式我们自己排（第五节 4）。
- **和旧规矩的冲突**：决定 0121 第 3 条「不借参考工作台配色」与这次方向冲突，按需求方 2026-10-31 的方向改成照参考工作台的蓝灰浅色；0121 第 1、2 条（尺寸写 px、正常态只画灰点）照旧，对比度闸照旧（第四节）。

## 二、另外查出来的

### 合并闸把每条状态事件放大成全部开着的 PR

- **现象**：#2908、#2909 的头上各攒了 900 多条 `merge-gate` 状态，到 GitHub 每个 context 1000 条上限后每轮写回 422（实测，run 41117088105）；10-30 晚 GitHub core 限额两次耗光（#3758、close-on-merge）。
- **根因**：合并闸收到 `cold-verify` 或策略来源状态时把开着的 PR 全重算（按代码：`packages/conventions/src/merge-gate.ts` `targetPrs`）。
- **做法**：#3771 只算挂着的那张 PR，已开 PR。新内核的对外调用一律经 outbox 计数（旧坑 E1）。

### 备份和恢复（需求方要求重写前确认）

- **现象**：法国每天 04:10 备份 fleet、temporal、temporal_visibility 三个库，restic 加密存香港；每周日演练一次恢复进临时库 `fleet_drill_restore` 核对每张表行数和最新时刻再删；香港每天把仓库复制一份留 14 天（按代码 `docs/ops.md` 第十一节）。最近一次备份 10-30 04:10 成功；最近一次演练 10-25 成功；10-31 03:42 手动又跑一次演练（结果见第七节）。

## 五、要拍板的

### 总设计

#### 1. 新包和分层

同一个 pnpm 工作区新开七个包，旧包不依赖、也不被依赖；旧适配器里要用的代码复制进来再改：

| 包 | 层 | 做什么 | 借鉴 |
|---|---|---|---|
| `harness-contract` | 接口 | zod 契约唯一一份、事件类型、`schemaVersion`（认不出的版本拒） | oh-my-openagent 线协议；旧 `shared/web-api.ts` 双向契约核对 |
| `harness-store` | 存储 | Postgres 同实例独立 schema `fleet2`，独立数据库用户只授 `fleet2` 的权限、独立连接池；不跨 schema 外键、不写旧表（旧表只读视图授权）；`events`（同一事务追加，`(stream_id, seq)` 唯一，先落库后广播）、投影表（可删了从事件重建）、`command_receipts`（幂等）、`outbox`（一切对外副作用，至少一次投递） | T3 的事件、投影、回执、outbox |
| `harness-runner` | 运行 | 指挥官每说一句起一轮 `claude -p --resume`（经 reclaude），提示词走 stdin，挂内核托管的 HTTP MCP；进程组收尸、脱离接回、叫停分种类、时限从一张预算表派生 | 旧 `engine/src/real/intake-chat.ts`、`adapters/src/{process,detached,stop-reason}.ts` |
| `harness-workers` | 运行 | 工人槽位三层：传输（子进程分帧）、壳（Claude Code、Grok、Cursor、pi）、模型来源（DeepSeek 等 API）；渠道表、角色表，快/好档是一张可拆的路由表 | T3 适配器注册表；pi-mono provider；oh-my-pi 两档 |
| `harness-orchestrator` | 编排 | 单拆子任务和依赖；依赖都完成、有空位、写范围不重叠就放行，波次只是按深度显示；交回先机械核验（diff 统计、越界、跑检查），四态 `unverified/passed/failed/unknown`；重派有历代累计上限 | oh-my-openagent 放行规则；cc-master 就绪由依赖推出、`verified` 和状态正交 |
| `harness-api` | 接口 | HTTP、SSE（按 `seq` 续传，补不全发 `resync`、重放有上限）、指挥官 MCP（Streamable HTTP，令牌绑会话） | T3 `ThreadStream` 重放上限；旧 `api/src/sse.ts` |
| `cockpit` | 客户端 | 新驾驶舱：React 19、Vite、Tailwind 4 令牌、Radix；五块（会话、任务、决策、法国、设置）；`lint-design` 照旧守 | 参考工作台外壳和令牌；`specs/3752` 五块 |

**为什么不用 Temporal**：旧系统靠 Temporal 保证在途任务不丢，代价是 `patched()` 版本管理、发版暂停和接回、`TMPRL1100` 僵尸这一串坑（旧坑 D1、A7）。新内核的在途状态全在事件表里，内核重启从事件重建投影。代价是持久定时器、重试、心跳、超时、取消传播、重启恢复都要自己做，等于自建一个小调度器，这是重写里最容易翻车的地方（挑错第 1 轮的意见，收了）。所以调度器单独成第 2 片，带故障矩阵（杀进程、断网、重复事件、重启、时钟跳）全过才进任何真实执行；过不了就在新内核里接回 Temporal 只管定时和恢复，不拖整个重写。

**会话收发目录只当输出缓存**：沿用旧 `detached.ts` 的按行号读，但会话游标、租约、最后心跳、恢复状态的权威在 `fleet2` 表里；目录丢了按「输出丢失」记 unknown，不当成会话没了。

**外部副作用怎么不重复**：outbox 至少一次，不宣称恰好一次。每类外部动作（推分支、开 PR、评论、合并、发版）有唯一操作键，按「预留（写回执，带操作键和 fencing）→ 执行 → 查 GitHub 确认 → 写结果或补偿」走。请求超时、响应丢了的结果记 `unknown`，不当失败盲重试：先按操作键查 GitHub（分支在不在、这张单有没有开着的 PR），查到就补记，查不到（含 GitHub 短暂 404）进对账队列等下一轮再查。outbox 自己有领取租约、死信、积压告警。

**调度器的硬要求**（第 2 片）：`due_at` 一律按数据库时间判，轮询事务要短；恢复后积压按队列、按仓、按模型服务分层限速，带抖动和优先级，追赶速率和积压上限写成数值；健康检查看调度有没有往前走（最老到期任务的年龄、outbox 最老一条的年龄、租约续期成没成），不只看进程活着。故障矩阵：内核和工人在领取、续租、事务提交前后各被 `SIGKILL`、OOM、`SIGSTOP`；新旧内核进程并存；库断线、锁等待、死锁、磁盘满、只读、重启；网络延迟、乱序、单向不通（内核与库、工人与库、工人与 GitHub、法国与香港分开测）；GitHub 超时但实际成功、限流、权限被撤、分支被人删、PR 被外部关或合；大量任务同时到期、重试风暴、毒任务；时钟前跳、后跳；发版时新旧版本并存、迁移没跑完、回滚。验收断言：任何时刻至多一个有效所有者做危险动作；未知结果不盲重试；取消和截止最终看得见；停机 6 小时后追赶不打爆 GitHub 限额和额度。

**为什么不用 Effect、不换语言**：沿用 TypeScript、Hono、zod、Drizzle，和旧包同一套工具链和 CI。

许可证：oh-my-openagent、cc-master、cc-haha 不允许拷代码进公开仓，只学做法、自己写。

#### 2. 指挥官怎么跑

- 每说一句起一轮，按会话号续上，空闲时没有进程；工人交回时指挥官不在跑，内核把交回排进它的收件箱，空闲时合成一条消息续一轮，带上核验证据包。续轮幂等键＝会话号加收件箱游标。
- 指挥官只读：工具只有读、派工（`spawn_worker`，`task/expected/must_do/must_not/context/stop_when` 必填，schema 层拒）、查、停、开单、拍板卡。动手全靠派。拍板卡上的批准绑定计划的版本哈希、批准人和过期时刻，计划改了批准作废。
- **本机已实测（2026-10-31）**：`reclaude -p` 配 `--mcp-config` 指向内核托管的 Streamable HTTP MCP（令牌放请求头），第一轮调到工具；`--resume` 同一会话号第二轮再调到工具、记得上一轮结果（会话 `03bf8d28…`，探针服务日志两次调用都记到）。法国真机第 3 片再验一次。

#### 3. 新旧并行

**比对（同一张单两边都跑）＝影子模式，新内核零真实副作用**

1. 冻结一张批次清单：单号、基线提交、取快照时刻；两边从同一个基线起。
2. 新内核只读单的快照和旧引擎的派单事件，不抢派。
3. 所有对外写只经 outbox，影子模式下 outbox 的真实处理器不装配，只记「本来会做」。光靠令牌不够（工人能 `git push`、`curl`、`ssh` 绕过），影子工人另外：跑在单独的会话用户下、拿不到任何 GitHub 凭据和宿主密钥；出网默认拒绝，只放模型服务（nftables 按用户放行）；工作目录是临时的、跑完删；MCP 只注册读工具。启动自检缺一不起：只读探测没有写权限、outbox 真实处理器未装配、影子用户出网规则在。
4. 影子产物（补丁）存 `fleet2.shadow_runs`，分支名 `fleet2-shadow/…` 只在临时目录里、不推；任何自动流程不消费影子补丁。
5. 旧 PR 合并后，拿合并 diff 当参照给影子补丁评分：改了哪些文件、越界没有、测试过没有、用时、用量、核验结论，写 `fleet2.shadow_compare`，新驾驶舱有一页看。旧的结果永远是权威。除了补丁好坏，也记影子期旧系统的排队时长、失败率、额度消耗和影子前一周比。
6. 影子补丁和参照 diff 先规范化（按文件、去掉空白和格式化差异）再比；影子一整天没跑出一条也报警，防「影子静默不跑」。
7. 额度：影子烧同一批订阅额度。默认同时最多 1 条影子、只挑小单、每条有时长上限，拼车池压力高于旧引擎的退让线时影子先停（用已买的订阅，不掏新钱）。

**切换（一批里一部分真交给新的做）＝一张单只有一个执行方**

1. **认领只有一处**：所有权表 `issue_owner(repo, issue, owner, fencing, lease_until)` 放旧库（旧引擎直接读得到），主键是单，取得用条件更新，每次易手 `fencing` 加一。**旧引擎拉单和点名派单都先走这张表取得所有权**，读不到按「不确定」不派（`dispatch-standing` 的纪律）；标签「引擎v2」只给人看，不当锁（挑错第 1 轮：标签和库写之间有窗口，收了）。这是并行期对旧引擎的唯一改动，先于任何影子上线。
2. **每个状态写和外部副作用都带 fencing**：入队、执行前、提交前、重试、补偿、取消、释放租约、写回状态，一律用带 `fencing` 条件的原子更新，对不上就丢弃并记账。GitHub 不认 fencing，所以已发出的推送、开 PR 靠操作键对账收拾，不靠 fencing 撤销。认领表只经一条命令路径写入，库里加约束，旧引擎、点名派单、本机领单绕不过去。
3. **租约过期不自动转手**：过期只把单标成「待确认释放」，先确认原执行方的会话已停（进程没了、scope 收了），才交给另一方。
4. GitHub 侧兜底：分支前缀分开（`fleet/` 对 `fleet2/`）；开 PR 前查这张单有没有开着的 PR；同一张单两个执行方的 PR 同时开着，合并闸拒合并并报警。
5. **按状态切回**，不是一个总开关：

| 单走到哪 | 切回时怎么办 |
|---|---|
| 没开始 | 直接释放给旧引擎 |
| 开始了、没有外部动作 | 停会话、确认进程没了，释放重派 |
| 有本地提交、没推 | 停会话，补丁存进 `fleet2` 留档，释放重派 |
| 推了分支、没开 PR | 分支改名 `fleet2-abandoned/…` 留着，释放重派 |
| 开了 PR | 不开第二个；PR 转给旧引擎接管（续这个 PR）或关掉重派，按单逐张记 |
| CI 在跑、等合并 | 等这一轮结果再按上一行办，不在半路转手 |
| 合了 | 不回退成没做完；有问题走 revert PR |
| 外部动作结果未知、在对账 | 不转手，等对账出结论再按上面对应的行办 |
