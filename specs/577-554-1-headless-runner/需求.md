## 怎么算做完

1. **runner/one-shot.ts**：起一次无头会话的真实进程（起、看守、收 stdout、记退出码）。
   - **不许**续会话（不接 resume / fork / session 接手参数）。
   - **不许**拿超过 N 分钟（默认 60；调用方可传 `timeoutMinutes`），到点 `kill`，outcome=`'timeout'`。
   - 起前做内存准入（沿用 `real/memory-admission.ts`，依赖注入可换，本机跳过）。
   - 会话 fd / stdout / stderr 写到 `_tmp/<runId>/`，结束后 24h 自动清（沿用现有 `_tmp` 架子的清理机制，没有就在本切片加一个最小版）。
   - Spawner 依赖注入：真实生产 spawn（经 `real/exec.ts` 同一份 `fleet-agent-scope`），测试可换 fake。
2. **runner/brief.ts**：Brief 类型 + 渲染三份（scope / manual / verify）。照 `ports.ts` 的 SessionBrief 借字段（title / request / acceptance / touches / branch / prNumber / head / specDir），**不加** `stepName` / `fusionStage` / `lead.step` 这类 Fusion 专词。Verify Brief **必须**能表达「diff + 要什么 + 怎么算做完」。
3. **runner/verdict.ts**：判一次运行的成败。
   - 输入：exit code + stdout / stderr tail + 可选的「验收证据」（PR#、branch、changedFiles）。
   - 空 stdout + 非零 exit 一律**明确失败**，**不拿空当跑完**。
   - manual / verify 必须回「PR# 存在 + branch 起了 + 有 changedFiles」；缺任何一项算失败，写明缺哪一条。
4. **segments/scope.ts / manual.ts / verify.ts**：每个文件导出一个 async 函数，签名形如 `run<Segment>(brief: <Segment>Brief, deps: { oneShot, spawn, memoryAdmission, ... })`。**verify.ts 必带 prNumber + baseSha + headSha**（不许跨 process 拿「上一段的 PR#」）。
5. **runs 表占位**：写一笔（单号 / segment / model / channel / 起止 / token / costUsd / memoryPeakMb / outcome）——**用 `runner/not-wired.ts` 占位写入**（NotWired 形状照 `packages/api/src/draft-opening.ts`），等 #556 建表后换真实现。本切片同时把「runs 写入约定接口」的意图交一份给 #556（在它的 specDir 里留一行说明，或另开一句）。
6. **测试** `packages/engine/test/runner/`：
   - fake spawner 跑通 happy path：one-shot 起 → 拿 stdout → verdict 给 ok → notWired runs 被调一次。
   - **故意造红**：fake 进程 exit 1 / 退出码为 null（超时）/ 不写 PR——verdict 必须明确失败（outcome ≠ 'ok'，写明哪一条），**不拿空当 ok**。
   - 失败路径不许鲁式化：缺 spawner / 缺 brender 依赖明报，不默认。
7. **测试全绿**：`pnpm exec vitest run packages/engine/test/runner/` 全绿；`pnpm test:changed` 退出码 0。
