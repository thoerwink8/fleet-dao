AI 理解：v3 三段一条龙（对题 → 动手 → 验收）第三段的第一片。审官不是岗位、不是常驻——就是合之前那一次冷调用。本切片只做「**纯接口**」：**喂 diff + 要什么 + 怎么算做完 → 起一次 one-shot 冷调用（换一个不同家族）→ 回 pass/fail + 问题清单**。它不被 Fusion 调（`packages/engine/src/workflows/verify.ts` 是 Fusion 句号后的老链路，本切片不动它），下一片（555-2）才把它接到合闸上。

## 场景

v3 三段流水线里，验收是「合之前一次机会把不对的拦下来」的最后闸；它和「Fusion 的 verifyRound」的差别：

- 不再是常驻 Lead 喂材料，而是一次性「取这单 + 这 PR 的 diff、挑一个不同家族、起一次一次性进程、看结论」。
- 单子「要什么」「怎么算做完」从 `#` 单和需求文档**现读**（不造「交接条」物件）。
- diff 由调用方现算（本模块**不调 git / gh**——注入 `FetchDiff`），调用方决定从哪读（GitHub / git 工作树 / fake）。
- 家族挑错照 docs/decisions/0006-discussion-model-order.md 的顺序（gpt → claude → deepseek → grok → kimi），**跳过** `modelFamilyAvoid`；挑不出 → 「没讨论成」明确失败，不许拿默认模型顶上。

## 怎么算做完

1. **输入 zod 钉死**：`{ prNumber, branch, baseSha, taskId, what, howToFinish, modelFamilyAvoid, round }`；缺一项直接拒。
2. **输出 zod 钉死**：`{ pass: boolean, problems: string[], notes?: string, round: 1 | 2 }`。
3. **diff / spec 注入**：`FetchDiff`、`FetchSpec` 由调用方提供；本模块**不**调 git / gh / GitHub。
4. **「读不到」必明确失败**（通用段底线 + specs/555 第 4 条）：
   - `fetchDiff` 抛错 → `pass: false`，problems 写明「读不到 diff：…」
   - `fetchDiff` 返回空 diff 或空 changedFiles → `pass: false`，problems 写明「不许拿空当没改动」
   - `fetchSpec` 抛错 → `pass: false`，problems 写明「读不到单子」
5. **家族选择（0006）**：按 `gpt → claude → deepseek → grok → kimi` 顺序；跳过 `modelFamilyAvoid`；所有不同家族都 `chooseModelForFamily` 返回 `undefined` → `pass: false`，problems 写明「没讨论成」（**不许拿默认模型顶上**）。
6. **只有三种能挡**（specs/555 第 3 条）：判 fail 时 problems 里的每条必须以「没做到验收条 / 弄坏了原有功能 / 安全或丢数据」开头；模型的风格意见**不许**进 problems（丢、但记进 notes）。
7. **one-shot 没跑成**（exit!=0、kill、空 stdout、结论行没说清 pass/fail）→ `pass: false`、problems 写明「冷调用没跑成」——不拿空当 pass。
8. **测试** `packages/engine/test/verifier-invoke.test.ts`：
   - happy path：diff 拉到、家族跳开 avoid、模型说 pass → `pass: true`、`problems=[]`
   - 家族顺序钉死：avoid=kimi → 这家不出现；avoid=claude → 第一家问 gpt
   - 模型判 fail（说要 A 做了 B）→ problems 带「没做到验收条」
   - 模型判 fail（弄坏原有功能）→ problems 带「弄坏了原有功能」
   - 模型顺手提风格意见 → 被丢、不进 problems
   - **故意造红**：`fetchDiff` / `fetchSpec` 抛错、`fetchDiff` 返回空、全家族不可用 → 都必 `pass: false`、problems 写明哪一步
   - one-shot exit != 0 → `pass: false`
9. `pnpm exec vitest run packages/engine/test/verifier-invoke.test.ts` 绿；`pnpm exec tsc -b` 绿；`pnpm exec biome check` 对新增两个文件绿。

## 不做（本切片范围之外）

- 接到合闸上（merge-gate / 驾驶舱）。那是 555-2 的事：本切片**只**给纯接口。
- 真的生产 Spawner（`segments/sessions-segment.ts` 那份 SEGMENT_NOT_WIRED 的兜底在本切片一样有效——本模块的测试全 fake，生产接 Spawner 在 554-2）。
- 「要不要起第 2 轮」的判（specs/555 默认 1 轮、最多 2 轮）：`round: 1 | 2` 是入参透传，**判上限**在装配那一侧。
- 「这些 problems 算不算挡住」的最终判：本模块只收集，judge 在 decisions/ 或驾驶舱。
