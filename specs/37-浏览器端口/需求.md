# 浏览器端口：网页操作交给 Jev 选点，一次调用跑完一段（#37）

对应计划：plan.md P3 的「浏览器端口」一条。
设计依据：design 第十一节接入点「浏览器操作」及其下「浏览器操作怎么接」；第八节「为什么是命令不是 MCP」；第三节第 21 条（花钱的定义）。

## 要什么

- 调用方（AI 会话）一次交代：起始网址、目标、要填的值、做完怎么核对。端口在页面上一步步挑、执行，跑完一次性交回：做到哪、每步做了什么、核对结果、这次花了多少 token。
- 每一步：把页面上能点能填的元素编成带编号的表，一次 Jev 请求同时问「做哪个动作」和「每种动作点第几个」。做法参照 [browser-use/jev-ultrafast](https://github.com/browser-use/jev-ultrafast)（MIT，借用的代码注明出处）。
- Jev 的回答只能是表里已有的编号；不变成选择器、坐标或能执行的代码。执行前核对页面没变、目标没被遮住，变了就重看，不硬点。
- 要打的字由调用方给，不另接写字的模型；需要值但没给，停下交回，说清缺哪一栏。
- 按了收不回的动作（付款、删除、停用、发布、退订、注销、解散、移除、撤销等）停下交回，调用方确认后才按；只许去调用方允许的域名。
- 只读的看页面、核对结果不调模型，不花钱。
- Jev 走 `packages/jev`：钉死模型版本，花费进记账表，受每日花费闸管（月度上限由创始人看完一周账单再定，见 #37）。连不上、答不出、答得不在表里，都是「没判」：停下交回，不当成做完。
- 驱动本机专用 Chrome（独立 profile，不碰创始人日常用的那个）；也能起无头浏览器，给服务器上的验收用（P4「自动操作飞书网页版」）。
- 做成 `fleet` 命令（design 第八节：命令，不是 MCP）。
- 读不到页面、连不上浏览器、Jev 没判、核对没过，都返回明确的失败；每一条都有一条故意造出来的测试。

## 怎么算做完

- PR 审过合进 main；单元测试和本地假页面的端到端（假 Jev）全绿，测试不调付费接口。
- 本机真跑一条飞书开发者后台流程（例如给应用开通一项权限、不发布版本）：一次调用做完，代码核对通过，花费进 Jev 记账表。
- 垫片退役：卸掉本机的 `jev-ultrafast` MCP、删掉 `~/.local/share/jev-ultrafast-mcp`，PR 正文登记「合并时退役」，终审核对。
