# Fleet2 做成 ADE：脱钩 GitHub（#3914）

- 状态：在做（2026-11-12）。discuss 没讨论成：Cursor 上 gpt、kimi、glm 都因 Ultra 额度退出（没答上），不把没答上写成同意。下面几处是按代码和验收自己收紧的。
- 起因：创始人 2026-11-12 看了 Fleet2 驾驶舱：「现在相当于和以前一样，其实没有和 github 脱钩……正常的 ade 类似 mirasim，你起个 web 看看他的功能」。
- 代码版本：origin/main `d5919484d`
- 范围：看了 Mirasim 自带的 `atoms` 清单（650 个，按组：session、turn、workspace、orchestrator、tasks、messaging-frames、terminal、agenda、issue-sync 等）；读了新内核 `harness-*` 的契约、存储、工人壳、本机装配、驾驶舱后端和前端。没碰法国 VPS、验收闸。

## 一、问题和根因

现象：驾驶舱顶部「新内核 · 只读」，会话列表空着等指挥官会话产生事件；人在界面上开不了会话、发不了话、停不了。

根因（按代码核过）：

1. **活只能从 GitHub 进来**：`harness-dispatch` 的 `taskFor`/`readMerged` 在本机是桩（「没接任务来源」），派工只认 `real_batch_items`/`shadow_batch_items`（GitHub 单冻结出来的批次）；3851 稿 6.6「任务来源 GitHub App 只读」把它写成了设计。
2. **对外动作写死 GitHub**：契约已有 `change.*` 名，但 `harness-dispatch/src/publish.ts` 仍写 `git.push`、`github.pr.open`，outbox 行是 `repo + issue + fencing`（GitHub 单号形状），没有「平台」这一维。
3. **驾驶舱是事件的只读投影**：没有任何写接口；会话只能由 `harness-api` 的 MCP（指挥官）或批次驱动间接产生。

所以换了皮、形态还是「GitHub 单 → 引擎派工 → 只读看板」。

Mirasim 的形态（实测 atoms）：工作区（本机文件夹）→ 会话（`newSession`、`getHistory`、`interact`、`forkSession`、`rewindFiles`、队列 `queue/steer/jump`）→ 右侧坞看改动（`getWorkspaceChanges`、`getGitDiff`）→ 目标（`createGoal(members)`、`assignGoalWork`）→ 会话间消息（`peerSessionMessage`）；GitHub 只是 `agenda`/`issue-sync` 这组里的一个可选「事项」来源。

## 二、做法

### 2.1 对象

| 对象 | 存哪 | 说明 |
|---|---|---|
| 工作区 Workspace | 表 `ade_workspaces`（id、名字、本机路径、是不是 git 仓、forge 类型、远端地址） | 加一个本机文件夹就有；forge 默认 `local`，从 `git remote` 推 github/gitlab，推不出就 local |
| 会话 Session | 表 `ade_sessions`（当前状态）＋流 `session:<id>`（事件日志） | 选工作区、agent、模型、是否新工作树；父会话 `parent_id`、关联单 `task_id` |
| 单 Task | 表 `ade_tasks`（工作区、标题、正文、状态、来源 json） | Fleet2 自己建自己存；来源 `manual` 或 `github:<owner/repo>#<n>`（导入），可选同步回 GitHub |
| 会话间消息 | 事件 `session.message` 写进收件人的流 | from、to、正文、要不要回 |

表和事件的分工：**实体的当前状态进表**（人建的、会被改的：工作区、单、会话的标题/状态/所属），**发生了什么进事件**（每条消息、每个轮次、每一步过程）。表里的会话状态每次轮次起止同步更新，事件流是审计和 SSE 的来源；会话状态能从事件流重算（测试守着）。这是对 0124「事件是唯一真相」的一处收窄：配置类实体不走事件重放。

### 2.2 会话怎么跑

- 新事件类型（契约，加类型不升 `SCHEMA_VERSION`）：`session.created`、`session.message`。沿用已有 `session.turn.started/settled`（载荷带 `turnId`、`text`、`runId`、`agent`、`model`；`settled` 带 `outcome`）。`deriveWorkerState` 认带 `outcome` 的 `session.turn.settled`：`lost` 算卡住，其余算空闲。没有 `outcome` 的旧事件照旧跳过，不改法国会话的判法。
- 过程仍写 `transcript:<runId>`，不塞进会话流。会话页按轮次载荷里的 `runId` 再订这条过程流（工人会话本来就这么拼）。塞进会话流的话，最近 24 条 tail 会被工具输出挤掉，轮次还在跑也会被判成空闲。
- 会话运行放在 `harness-dispatch/src/ade`（不新建包）。`harness-api` 仍不自己起进程；本机网关把 `/api/ade` 交给这边。每个会话同一时刻最多一个在跑的轮次。
  - 发话：空闲就起一轮；在跑就进队列（事件 `session.message` 带 `mode: queue`），这一轮结束自动接着跑；「插队」＝停掉当前轮再先跑这句；追问续接 agent 自己的会话号（Claude `--resume`）。
  - 停：`POST …/stop` → 对在跑的进程发 `StopReason('user-stop')`，轮次记 `outcome: stopped`。
  - 起进程只经 `harness-runner` 的 `ProcessHost`（`FLEET2_HOST=hostd` 时走 hostd，默认本机/jobrun），Claude 经 `reclaude`；环境用 `buildWorkerEnv` 白名单；本机权限档沿用 `acceptEdits`，不许 `bypassPermissions`。
  - 内核重启：库里状态是「在跑」但进程已不在的轮次，启动时补记 `settled(outcome: lost)`，不假装还在跑。
- agent 列表：`claude`（reclaude，stream-json，可续）、`codex`、`pi`（命令行存在才列；输出按文本行当助手的话，续接靠把上文拼进提示词，页面标明「无原生续接」）。模型从渠道配置里选，不写死。
- 新工作树：工作区是 git 仓才给；`git worktree add <数据目录>/worktrees/<会话> -b fleet2/<会话短号>`；会话结束不删，人在界面上点「清理」才删。

### 2.3 单、会话、GitHub

- 任务页能直接新建单；单上「开会话」把标题和正文做成第一句话。
- 「从 GitHub 导入」只是一个按钮：配了 `FLEET2_GITHUB_TOKEN`（只读）才可用，没配返回明确的「没连 GitHub」，不影响别的功能。「同步回 GitHub」同理走 forge 适配层的 `comment`，没连就不出现。
- 本版开发栈、验收、测试**不需要任何 GitHub token**。

### 2.4 对外动作中性化

- 新写入沿用契约里已经落地的名字：`change.push`、`change.pr.open`、`change.comment`、`change.merge`（不改叫 `change.open`，避免再改一版刚落地的名字）。载荷带 `forge`。`gitlab` 领到就进 dead，原因写「还没实现」。`local` 不连平台：把补丁写进数据目录。`github` 仍走现有推送和开 PR，只是新行用新名字并带 `forge:'github'`。库里的旧名 `git.push`、`github.pr.open` 仍处理。
- 本地单没有 GitHub 单号：outbox 的 `repo`＝`local/<工作区号>`、`issue`＝本地单号、`fencing`＝0（令牌核对只对 github forge 做）。验收闸照旧管外送：本版会话页「交付」按钮只发 `change.*` 请求进 outbox，由处理器执行；闸重设计不在本片。

### 2.5 会话间消息和子会话

- `POST /api/ade/sessions/:id/messages` 带 `from: {kind:'session', id}` 即会话间消息，写收件人流 `session.message`。
- 子会话轮次结束、队列空时，给父会话投一条 `kind: report` 的 `session.message`（结果末段和 outcome）。**report 不自动开父会话的下一轮**，只出现在父会话的流里。人对会话的话才开跑；`expectReply` 且 `hops < 1` 的会话间消息才自动开一轮，开出来的轮次不再自动往外发（`hops` 加一后只投递）。这样子会话结束回报不会和父会话对吵。
- 不做：指挥官 agent 通过 MCP 自己开子会话（接口留好，MCP 工具下一片）；目标（goal）看板；定时任务；回退、分叉、steer（agent CLI 不支持中途注入，只做「停后插队」）。

### 2.6 接口和界面

接口前缀 `/api/ade/*`，只在本机装配启用（`/api/local/status` 里 `ade: true`），本机令牌鉴权（沿用）；写接口要求 `content-type: application/json`（跨站表单发不出，浏览器要先预检）。

| 方法 路径 | 作用 |
|---|---|
| GET/POST `/workspaces`、DELETE `/workspaces/:id` | 工作区 |
| GET `/agents` | 能用的 agent 和模型 |
| GET/POST `/tasks`、POST `/tasks/import-github` | 单 |
| GET/POST `/sessions`、GET `/sessions/:id` | 会话列表、新建（工作区、agent、模型、是否新工作树、可带 taskId/parentId/第一句话）、详情 |
| POST `/sessions/:id/messages`、`/stop` | 追问/排队/插队、停 |
| GET `/sessions/:id/changes` | 工作树里的改动（状态＋diff） |
| 沿用 `/sessions/:id/events`（SSE）、`/history` | 流式和历史 |

驾驶舱（本机装配）：去掉「只读」；侧栏「会话」页左列表＋「新会话」，右会话页（流式消息、输入框带「发送/排队/插队」、停止按钮、右侧坞「改动」）；「工作区」入口（加本机文件夹）；「任务」页上方「新建单」和「从 GitHub 导入」。法国驾驶舱（`/next/`）维持现状，由 `status.ade` 开关控制。

## 三、怎么算做完

1. 不设任何 GitHub 变量起本机装配：加本机仓当工作区 → 新建会话 → 发一句 → 看到流式回答 → 追问一次 → 停一次（端到端测试，agent 用假执行体；另手动用真 reclaude 跑一次记结果）。
2. 任务页新建一张单 → 从它开会话；子会话结束后父会话流里出现 `session.message`（测试）。
3. outbox 带 `forge`，GitHub 实现在适配层，local forge 出补丁文件（测试）；旧名行仍能被处理（测试）。
4. 内核重启补记 lost（测试）；接口鉴权、非 JSON 写请求被拒（测试）。
5. `pnpm check` 过；碰界面的带 1440、390 截图；PR 开出。

## 五、没核实的、风险

- codex、pi 的无头输出格式本片只按文本行处理，没逐个核结构化输出；只保证能起、能看到文字、能停。
- hostd 路线在本机默认不开（需先 `cargo build`），走 `ProcessHost` 一致性套件保证行为一致；本片端到端用本机/jobrun。
- 会话流里直接放 transcript：单会话长跑事件量大，沿用 `TRANSCRIPT_MAX_ROWS` 按轮次限额，超了记 `transcript.dropped`。
