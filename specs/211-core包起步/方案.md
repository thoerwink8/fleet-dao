# 方案：core 包起步（#211）
> 本文档是历史原话，一字不改。Fusion 0–7 步（含 core 里的执行状态机、任务简报、副手验收、验证结论）已被后来的决定取代：换成指挥官 → 工人 → Review 三段一条龙。现行口径见 [#509](https://github.com/thoerwink8/fleet-dao/issues/509) 和 `docs/goals.md`。


需求见 [需求.md](需求.md)。依据：`docs/decisions/0003-fusion-flow.md` 第 5、9、12 条。

## 做法

新建 `packages/core`，只依赖 shared 和 zod，全是纯判断，不碰网络、库、文件（`test/structure.test.ts` 扫 import 盯着）。五样：

| 文件 | 判什么 | 读不到、认不出时 |
|---|---|---|
| `src/flow.ts` | 执行状态机：0–7 步、母单按块循环、母单级验证；打回最多 2 次后 Lead 接手、验证最多 2 轮、CI 最多修 3 轮；单模型模式第 3 步关、第 5 步只对高风险开；哪一步都能停下等人、恢复回原步 | 不该出现的组合、坏状态（负数、块号越界、等人却没记回哪步）一律 `ok: false` 带原因 |
| `src/brief.ts` | 任务简报：目标、范围、约束、只许改的文件、怎么算合格、交回格式；同时派最多 3 份、两两不许改到同一处；副手改了简报外的哪些文件 | 缺栏、路径绝对 / 带 .. / 反斜杠、重复都列出来不收 |
| `src/acceptance.ts` | Lead 验收：空交付、测试红或没跑成、碰到别的块简报里的文件，Lead 说收也不收；简报外、别的块没认领的由 Lead 定，收下的交回给外壳记下来（2026-09-27 #246 验收暴露后改，原来简报外的一律不收）；打回满 2 次再不行 Lead 接手 | 打回不写理由、次数认不出、别的块认不出直接报错 |
| `src/verdict.ts` | 开 PR 前验证：逐条做到 / 没做到 / 看不出带证据；只三种能挡，其余进 PR 当备注；Lead 带证据驳回记下来 | 交回认不出、审的不是送检的头、同族、漏答、答了清单外的、驳回不带证据：判「作废」，不当成过了 |
| `src/config.ts` | 流程配置：格式、全组织默认合并项目差异、禁令项目改不掉、按类别或单上指定选配置、改到的文件算不算页面代码 / 高风险 | 全组织默认坏了 `scope: 'org'`（全部停派），项目的坏了 `scope: 'project'`（这个项目停派、报红），都不拿默认顶 |

引擎的 decide 表接上这几样（`fusionFlow`、`brief`、`parallelBriefs`、`acceptance`、`verdict`、`flowConfig`），工作流照样经 decide 调、结果进历史；#214 的 Fusion 工作流用它们。

## 流程配置放哪（这张定下来）

- **项目**：各项目仓根的 `.fleet/flow.json`，只写和全组织默认不同的；没有这个文件就用全组织默认，驾驶舱标出来。
- **全组织默认**：fleet-dao 的 `packages/core/flow.default.json`，和判它的代码放一起，测试直接读它核对格式。改它算改标准（人闸第四类）——#133 按路径自动判改标准时，把这个文件加进名单。
- **格式版本**：`formatVersion`，现在是 1；引擎认当前和上一版。
- **起步值**：模型顺序照 `deploy/examples/catalog.example.json` 里的模型编号先填一版（Lead 用 Opus 5.5，副手先 Cursor、Kimi、DeepSeek、最后 Claude 顶，评审和验证 GPT、Kimi），跑出战绩后再调。
