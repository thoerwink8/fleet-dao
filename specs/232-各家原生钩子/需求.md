# 各家 AI 的原生钩子接上：Codex、Kimi Code、Antigravity、Gemini CLI（拦命令、开会话同步）（#232）

对应计划：未排期
设计依据：design 15.7 第 8 条（机器上的标准由 agents-sync 装，含钩子）；ops 第五节「钩子」那条

起因（2026-09-26 查断链）：拦命令、开会话同步这两个钩子原来只在一台电脑上，这次搬进仓、由 agents-sync 装到各台开发机，但只登记在 Claude Code 的 `~/.claude/settings.json` 里（Grok、Devin CLI、Cursor 命令行默认借道读这份）。别的几家有自己的钩子、协议不一样，这次没接，agents-sync 逐家报「没装钩子——为什么」。AI 理解：把这两条也装到这几家，用它们开的会话同样拦危险命令、同样开会话就跟上主线的规矩。

## 要接的几家（2026-09-26 查的文档和本机装的版本）

- Codex：`~/.codex/hooks.json`，格式和 Claude 的一样，默认开着；但每条非托管的钩子要人在 Codex 里用 `/hooks` 审过、信任了才跑，改了命令要重新信任。
- Kimi Code：`~/.kimi-code/config.toml` 的 `[[hooks]]`（TOML），事件名和 Claude 一样（SessionStart、PreToolUse），退出码 2 拦下。
- Antigravity 命令行：`~/.gemini/config/hooks.json`，没有开会话事件；调工具前的输入输出是另一套 camelCase 的 JSON（`toolCall.name` 是 run_command，输出 `decision`），没有 cwd 字段。
- Gemini CLI：`~/.gemini/settings.json` 的 hooks，调工具前叫 BeforeTool，终端工具叫 run_shell_command。
- 不接的：pi 没有配置式钩子（要写成 TypeScript 扩展）；dsh 没有自带的全局钩子（只有要手动挂的桥接插件）。出处见 `packages/agents-sync/src/targets.ts` 的 HOOK_GAPS 上面那段注释。

## 怎么算做完

- 装了上面几家的机器上，`agents-sync --apply` 给它们登记这两个钩子（没有开会话事件的那家只登记拦命令那条，并写明），`--check` 逐家报一致、漂移或缺失；只动本脚本登记的那几条，别的钩子不碰，各配一条「别人的钩子原样留着」的测试。
- 要人确认才生效的（Codex 的信任）：`--check` 查得出信没信任就报出来，查不出照实报「没查成」，不当成装好了；文档写明人要点哪里。
- `agents/hooks/pretool.mjs`、`agents/hooks/session-start.mjs` 认得这几家的输入输出格式，每家配一条故意造出失败的测试（格式认不出按拦处理；开会话的结论在它们那里进上下文）。
- 接上的那几家从 HOOK_GAPS 里删掉；ops 第五节「钩子」那条跟着改。
