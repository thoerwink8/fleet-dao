# 结果（#598 / 555-4）

Fusion 工作流不再调 `workflows/verify.ts` 的 `verifyRound` / `rebutRound` / `verifyLines`。验收那一遍改由 `segments/verify.ts`（#554-1 已合的无头一次性会话入口）在 PR ready 时单独起，结论给合并闸（#555 母单，verifier-invoke → 合并闸的接线属于 #556-× 子单）。

## 改了什么

- Fusion 工作流（`packages/engine/src/workflows/` 下的 `fusion.ts`，代码于 #556-1 删除）
  - `doVerify` 直接 return `{ kind: 'verified', verdict: 'pass' }` —— 不再起 verify 会话。
  - `doOpenPr` 不再调 `verifyLines`；PR 正文里「开 PR 前验证」的内容段不交（`lines = null`）。
  - `doFinalReview` 的 `notes` 不再从 `rounds.at(-1)?.final.notes` 取（没有「上一轮别家验证」notes）。
  - 三处改动都用 `patched('no-fusion-verify-555-4')` 包着——在途任务的历史（含 `readCriteria` / `recordVerification` / rebut 会话）重放还能走老步序，老历史重放测试三色不红（代码于 #556-1 删除）。新起的（或重放回这一点的）都打标记、走短路。
  - `workflows/verify.ts`、`routing/verifier.ts` 本切片都没动；second-opinion.mjs 也没动（先审后合 #253 那条线还在用）。`decisions/verify.ts`、`decisions/triage.ts` 当时没动——后面的 #556-1 已删除。
- Fusion 工作流测试（`packages/engine/test/` 下的 `fusion.test.ts`，代码于 #556-1 删除）
  - 新增 `noVerifySession(w)` 断言钩子：任一 `stage === 'verify'` 的 `pickRoute` / `startSession` 都判红。所有走全流的测试把它钉进去（任一回归都会变成「Fusion 又起了 verify 会话」由这些测试当场红掉）。
  - 新增 **「555-4 钉死：Fusion 这条工作流一次都不起 verify 会话」**——用 fake 世界的 `verify: BLOCKING` 钩子挂进去，结果 `parked` 一次都没被填，PR 照样 open → CI 绿 → merge → close。整条「PR merged via 新 segments verify 钩子位」的「Fusion 这边既不挡也不起」由这张测试钉死（那张「Fusion 还当 verifyRound 派了个别家」「Lead 还跑去驳回」的老场景在这张名下留不下来）。
  - 删了两张原本属于「Fusion 内联 verifyRound 挡住」的用例：「没有别家可验 → 停下等人」「开 PR 前「怎么算做完」被删 → 停下等人补」——这两件事在 Fusion 这边都不再管了（验收自己读）。
  - 各处 `trail(w)` 期望删掉 `'verify'` 这一格；`w.verifications` 一律期望空数组（`recordVerification` 不再被调）。
- `specs/598-555-4-fusion-no-verify/需求.md`：本切片的需求文档（pnpm issue:new 生成）。
