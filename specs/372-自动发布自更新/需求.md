## 现在是怎么装的

- `deploy/france.sh` 的 `setup_auto_release` 把 `deploy/france/auto-release/` 下的 `lib.mjs`、`fleet-auto-release.mjs`、`config.mjs` 拷到 `/usr/local/lib/fleet-dao/auto-release/`（root 644），`fleet-auto-release.service` 跑的就是这份副本。注释写的理由：不从检出直接跑，因为检出每次发布都会快进，主线上一个坏提交不该把自动发布本身弄坏。
- france.sh 碰防火墙、sudoers，按规矩只人跑（ops 第九节）。它的读回会比副本和检出一不一样，但只在有人跑它的时候才比。
- 后端 `/healthz` 的 `deploy_lag`：france.sh 管的文件（`INSTALL_PATHS`，含 `deploy/france/auto-release/`）在主线上改过、超过 24 小时没重跑才红（`DEPLOY_LAG_LIMITS.systemMs`）。
- 信任边界今天已经是：主线上 CI 全绿的提交，自动发布会把检出 `/srv/fleet-dao` 快进到它，再以 root 跑它自己的 `deploy/release.sh`（装这一版的单元、跑迁移、切版本）。所以「root 跑没人看过的主线代码」本来就有，france.sh 留给人的是防火墙、sudoers、用户、系统包，外加自动发布自己这份副本。

## 几种做法和安全代价

1. **维持人跑，只把「副本落后」当场报出来**：自动发布每一轮比自己这份和在用那一版里的一不一样，不一样就当场报警（不等 24 小时），报警里写明在法国跑哪条命令。安全上不加任何东西。代价：每次改自动发布还是要人动手，人不在就一直是旧逻辑；可以当第一步先上。
2. **发成一版、健康检查过了，从那一版的目录自己装新副本**：从 `/srv/fleet-dao-releases/<提交号>/deploy/france/auto-release/`（换属主后 root 所有、只读）取文件。装之前在新副本上跑自检（能载入；用假的 io 跑一轮，自检入口要新加），过了才原子换上，留着上一份。再加一个不跟着换的小启动器（france.sh 装，很少改）：新副本下一轮崩了、没写读数，就退回上一份、报警，这个提交的副本不再装。只装在主线上、CI 全绿、健康检查过了的版本，`--unmerged` 手动发的不装。
   - 安全代价：root 那侧多了「从主线自己换代码」这一处，但和今天 `release.sh` 的信任边界一样（主线上 CI 全绿的代码本来就以 root 跑）。
   - 新增的风险主要在可用性：坏提交把自动发布弄坏，就没人来发修复。靠启动器退回和后端「自动发布 20 分钟没报到」兜住。
   - 恶意提交今天就能以 root 跑一次、顺手改掉这份副本，这条做法并没有多开口子。
3. **启动器直接跑在用那一版里的自动发布，不拷副本**：最简单。代价：`--unmerged` 手动发的版本也会被 root 当自动发布跑（要另外只认 `on_main=1` 的版本）；人退回版本时，自动发布的代码也跟着退，行为跟着变，排查更难。启动器照样要兜底。
4. **france.sh 加一个只装自动发布副本的模式，由自动发布发完调它**：装的逻辑只在 france.sh 一处。代价：一份碰防火墙、sudoers 的大脚本，多了一条由自动路径触发的入口；拆模式时写错一处就可能动到别的，要审的面最大。
5. **可以叠在 2、3 上的加固**：只装 GitHub 签名的合并提交（squash 合并由 GitHub 的 web-flow 钥匙签，本机能验），挡住绕过 PR 直接推主线的；只装必过检查 `check` 在那个提交上是绿的。代价：多一处要维护的钥匙和读法，读不到就不装、照实报。

AI 推荐：1 先上（当场报，小改动），再做 2（加上 5 的签名校验）；3、4 不做。理由：2 不扩大今天的信任边界，把「坏提交弄坏自动发布」这个真风险交给能自己退回的启动器兜；3 让手动发的未合并提交以 root 当自动发布跑；4 把自动路径接进了碰防火墙的脚本。

## 怎么算做完

- 合进一个只改 `deploy/france/auto-release/` 的提交，法国上不用人登录：自动发布发成那一版以后，下一轮就用新逻辑。读回：`/usr/local/lib/fleet-dao/auto-release/` 下的文件和在用那一版里的一字不差，journal 里有一行写明换成了哪个提交的副本。
- 故意造出的失败，每种配一条测试：
  - 新副本载入不了、自检不过：不换、报警、这个提交的副本不再试；
  - 换上以后下一轮崩了：启动器退回上一份、报警；
  - 读不到在用那一版的文件：记没查成、不换，不当成一致；
  - `--unmerged` 手动发的版本、没过健康检查的版本：不装；
  - （做了 5 的话）签名对不上、读不到签名：不装。
- 防火墙、sudoers 这些 france.sh 管的其余部分照旧只人跑；后端「装机脚本落后」不再把自动发布这几个文件算作要人重跑（`INSTALL_PATHS` 和 deploy-lag 两边的测试跟着改）。
- 做成之前先上第 1 条：副本和在用那一版的不一样就当场报警，写明在法国跑哪条命令，好了自己撤。
- ops 第九节「自动发布」、design 第三节第 42 条写明：谁装自动发布、root 跑主线代码的边界、新副本坏了怎么退。
