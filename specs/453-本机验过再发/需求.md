## 要什么
- 「本机验过」标记放在 GitHub 上（提交状态或标签，二选一写明理由），本机环境验完自己打；法国的自动发布只认它。
- 急修绕过：帅位一条命令打「急修直上」标记，发布记录写明谁、为什么；之后本机补跑演练，没补的进日报。
- 前端静态包在本机构建一次，法国原样用（或写明为什么两边构建结果一定一样）。
- 法国自动发布的配置在先审后合的路径里（`deploy/france/auto-release/config.mjs`），这张单的 PR 走先审后合。
- ops 第九节「自动发布」改成两段的说法。

## 怎么算做完
- 故意造出的失败，每条一个测试：没标记的提交 → 法国不发；标记在更老的提交上 → 发那个老的、不发主线头；急修标记 → 直接发、记录里有、日报提醒补演练。
- 法国真跑：连续一天只上带标记的版本，重启次数按批算（不再每个 PR 一次）。
