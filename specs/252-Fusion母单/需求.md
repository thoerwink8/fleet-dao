AI 理解：
- #214 做 Fusion 工作流时先只做了「一张单一块」，这是 v1 的第一步目标：一张真小单无人插手做完。
- core 的状态机已经会走块循环和母单级验证（`nextFlow` 的 blocks、mother-verify），可工作流里一张单只有一块，母单走不到。
- 本单把 0003 定的母单接上：
  - 一张母单一个 Lead，从头管到尾；
  - GitHub 子议题（子单）是它的输入，它拆成块（块不开单），每块走第 4–7 步、各自一个 PR；
  - 块全合完，做一次母单级验证；
  - 开工后范围冻结：新来的相关单只通知 Lead，不自动挂；只有「不修它，『怎么算做完』里某一条就过不了」的才换进来，写明理由；
  - 按目标关：验证达成就关，不要求子单全关；没做完的写去向。
- 0003 第 5 条允许「拆得开时最多 3 个副手同时干」。本单先做一块一块按顺序（同一时间只一个在写）。并行的做法等 v2 检验制度（#257）量过再定，那时要改 0003 第 5 条，得创始人拍。
- 派活口在这之前先挡着：带「母单」标签的单和它下面的子单都不自动派，只能 handover 一张一张明着交（派活修复 PR 里做）。本单做完后改成：母单整张交给 Lead，子单不单独派。

## 怎么算做完

- Lead 规划时拆块：每块一份任务简报，写明接口和谁改哪些文件；子单逐条对上是哪一块在做，没对上的写去向。
- 验收接上别的块（#246 验收暴露后留的口子）：`decideAcceptance` 的 `otherBlocks` 填同一张单别的块的简报，碰到的硬挡；这一块的改动按净改动比——工作流现在的 `blockChanged` 是几轮累计的，撤回了的也在里面，拿它硬挡会重演 #246「撤了也过不了」的死结。
- 每块走第 4–7 步，各自一个 PR，按块的先后合进主线。一块被打回、CI 红，照一张单的规矩处理，不拖垮别的块。
- 块全合完后，别家模型对照母单的「怎么算做完」做一次母单级验证：
  - 过了就关母单，关单评论列出每块的 PR 和各模型用量；
  - 没过的写清差什么，开后续单。
- 派活：母单整张交给一个 Lead；挂在它下面的子单不单独起工作流。
- 每小时对账的记账核对（#293，`packages/engine/src/jobs/reconcile-checks.ts` 的 `ledgerGaps`）现在按单认「合并关单那一步写完」（单记成做完）：
  按块合 PR 以后，中间一块合了、母单还在做会被报记账不全，要改成按块认（这一块收尾写完了）；配故意造出失败的测试：中间块合了不报、
  最后一块合了单却没记成做完照报。
- 开工后新挂上来的子单：不自动加进这一轮，只通知 Lead；「不修它就验收不了」的换进来时写明理由。
- 故意造出的失败，各配一条测试：
  - 拆块交回缺简报；
  - 副手碰了别的块的文件：Lead 说收也打回；撤回来之后不再挡；
  - 一块验证挡两轮；
  - 母单级验证不过；
  - 开工后新挂子单；
  - 子单查不到父母单。
- 法国真机：交一张带两三张子单的小母单，无人插手按块做完，母单级验证过了自动关。
