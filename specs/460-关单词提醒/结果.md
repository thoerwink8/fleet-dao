# 结果：「做完就关单」填了是却没写关单词（#460）

## 做成什么样

- PR 检查页的必填栏提醒（`packages/conventions/src/pr-fields.ts` 的 `checkPrFields`）加一条：「这个 PR 做完就关单」填了「是」、正文里却一个关单词（Closes/Fixes/Resolves……）都没写（`closingIssues` 认不出）时，提醒该补哪一行——号从「需求」栏取，取不到就写通用的「写上要关的单号」，不瞎编号。只提醒、不挡合并（和别的必填栏一样，走 `merge-gate.ts` 的 `reminders()`）。
  - 号怎么取：`pr-columns.ts` 把 `linkedIssue` 里「需求」栏那部分拆成新导出的 `issueColumnNumber`（`linkedIssue` 改成在它基础上加标题兜底），行为不变，`pr-labels.test.ts` 那张边界表照样全过。
- 每天的关单对账（`packages/conventions/src/close-sweep.ts`）加一种 `merged`：合并了的 PR 填了「是」、挂的那张单（「需求」栏，其次标题）却还开着——单上留言一次、驾驶舱一条日报级提醒（写明 PR 号和单号，和「due」「mother」同一套键位规则）；两处都认不出挂的是哪张单时记 `unchecked`（没查成），不当成没关系。评论里按老规矩不写别的 `#号`（写了会在那个 PR 上多一条「被提到」），改用「编号 91」这种不带 `#` 的写法；驾驶舱提醒不是 GitHub 评论，写 `#号` 没事。
  - 读现状加了「最近合并的 PR」这一路（`packages/github/src/close-facts.ts` 新增 `CLOSE_MERGED_PULLS_QUERY`）：`pullRequests` 没有 `issues` 那样的 `filterBy: since`，改成按 `updatedAt` 从新到旧翻页、翻到一条早于 `since` 就停（`pages()` 加了个可选的 `stop` 断言参数，别的调用点不传，行为不变）；`updatedAt` 认不出（解析不出时间）当场抛错，不当成「不用停」。
  - 引擎 `jobs/close-sweep.ts` 的 `KIND_WORDS`、收尾汇总日志加了 `merged` 这一种；单上留言、驾驶舱提醒的循环本来就是遍历 `CLOSE_KINDS`，不用改。

## 怎么算做完（对照需求）

- 填「是」没写关单词 → 检查页有这条提醒、合并闸照样判绿：`merge-gate.test.ts` 新增「④b」，证明 `state` 还是 `success`；写了关单词（Closes/fix/大小写/GH-号都试了）→ 没有这条提醒：`pr-fields.test.ts`、`merge-gate.test.ts` 都各有一条。
- 合并后单还开着 → 对账列出这张单（带 PR 号、单号）：`close-sweep.test.ts`（纯判断）、`engine/test/close-sweep.test.ts`（单上留言、驾驶舱一条的接线）两层都有；单已经关了（不在开着的单列表里）→ 不列；认不出挂的是哪张单 → 记没查成，不当成没有（【故意造出的失败】那条）。
