# 开着的 PR 由对账自动挂上自动合并（改标准的除外），不再靠人记得（#242）

对应计划：未排期
设计依据：`docs/design.md` 第五节「合并闸」「人闸第四类：改标准」

原话：无。同一个坑踩了两次：09-25 一个 PR 全绿却没人合；#163 全绿 12 个小时没挂自动合并。

AI 理解：
- 「PR 开出来就挂自动合并」现在只靠开 PR 的人记得跑 `gh pr merge --auto`，漏了没有任何兜底。
- 能不能合本来就只看合并闸，所以没理由让一个 PR 因为没挂自动合并而干等。

## 怎么算做完

- 对账程序在几分钟内给「开着、不是草稿、没挂自动合并」的 PR 挂上自动合并。
  - 用机器人（GitHub App）的身份挂，不用 Actions 自带的 GITHUB_TOKEN：它挂的自动合并合进主线后，不会触发主线上后面的工作流，法国自动发布就会一直等不到主线的 CI。
- 碰改标准路径的 PR（照 `packages/conventions/standard-paths.json` 判）不挂：合并闸还拦不住它们，要等 #133 的闸做好。
- 挂不上的（权限不够、GitHub 报错），报警并写明原因，不当成已经挂上。
- 测试，每条都故意造出来：
  - 没挂的普通 PR，会被挂上；
  - 改标准的 PR，不挂；
  - 草稿，不挂；
  - GitHub 报错时报警。
- AGENTS.md 本仓段「PR 开出来就挂自动合并」那句后面，注明对账兜底。
