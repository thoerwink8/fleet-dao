# #242 方案：开着的 PR 由对账自动挂上自动合并（改标准的除外）

对应：specs/242-自动挂自动合并/需求.md

## 怎么做

引擎的每小时对账（`packages/engine/src/jobs/hourly-reconcile.ts`）多跑一步「自动合并兜底」
（`jobs/auto-merge-check.ts` 的 `checkAutoMerges`）。每个受管的仓、每张开着的 PR：

- 开着的、作者是我们机器人开的（「干活的」机器人）、不是草稿、没挂自动合并；
- 当前头上必过检查（主线规则集里那几条）是绿的；
- 改到的文件不碰 main 上 `packages/conventions/standard-paths.json` 列的路径（照 `parseRiskPaths` + `riskyFiles` 判，现在借合并闸那一份）；
  - TODO(#133)：standard-paths.json 自己的判法（支持 `**/*.md` 这类通配、认得「通用段」等 section）落地后再换；

全中就用「引擎」机器人身份挂 squash 的自动合并（`enablePullRequestAutoMerge`，GraphQL），下一次 CI 走完
自动合进主线；不再开着的（合了、关了）、或不再符合挂上条件的那条旧提醒撤掉。

读 `openPulls` / `pullFiles` / `readRepoFile` / `requiredChecks` / `readCi` 哪一步没读成、或 `enableAutoMerge`
GitHub 报错：不挂、报一条「查 <仓>#<号> 要不要挂自动合并未查成」的提醒（dedupe 到 `reconcile:auto-merge:<仓>#<号>`），
写明原因；查成了（挂上、或这张 PR 不再符合挂上条件的）那条自己撤。

挂在 `HourlyReconcileJobDeps.gh` / `HourlyReconcileJobDeps.autoMergeAlerts` 两个新字段上
（不动 `merge-gate.ts`、不动 `alerts` 那一套）；`AutoMergeWiringGitHub` 把 `createGitHub` 拿到的
`GitHub`（`claims`、`pullFiles`、`readRepoFile`、`deps`）接进来，类型认得「作者是不是机器人」
（`claims.isAgentBot`）和「自动合并开没开」（`PullFacts.autoMerge`）。

## 为什么这样

- 「PR 开出来就挂自动合并」只靠开 PR 的人记得跑 `gh pr merge --auto`，漏了没有任何兜底；能不能合
  本来就只看合并闸，没理由让一个 PR 因为没挂自动合并而干等。
- 用机器人（GitHub App）的身份挂，不用 Actions 自带的 GITHUB_TOKEN：它挂的自动合并合进主线后，不会触发
  主线上后面的工作流，法国自动发布就会一直等不到主线的 CI（需求文档明写）。
- 碰改标准路径的 PR 不挂：合并闸还拦不住它们（#133 的闸做好之前）。草稿挂上也没用（GitHub 不给草稿起 CI）。
- 只挂自动合并，不手动合（`gh pr merge`）：合并队列的状态、合并闸的判定都还是合并那边的事。
