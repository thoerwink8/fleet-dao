# 老会话端口调查（母单 #901，接 `测试体量审查.md` 第五节 5.4）

调查日期 2026-10-05（本机日期 2026-10-04）。方法：从生产入口（`real/index.ts` 的 `realPortsFromEnv`、`worker.ts` 的 `runEngineWorker`、`workflows/`、`activities.ts`、`main.ts`）反向查调用；`_tmp/graph.mjs` 列出每个文件的非测试导入方。

## 结论

- `startSession` / `awaitSession` / `stopSession` 没有任何生产调用方：`EnginePorts` 里没有它们，`workflows/`、`activities.ts`、`task-*.ts` 里没有一处调用；`createSessionPorts` 返回的这三个，`real/index.ts` 一个都没取。
- 它们撑着的整串 `real/session-*.ts`（十八个文件）只被 `real/sessions.ts` 导入，`sessions.ts` 只被 `real/index.ts` 导入，而 `index.ts` 只取了 `reapOrphanSessions`、`orgSwitch`、`drainStop`、`releaseDetached` 四样。
- 那四样里：`orgSwitch`、`drainStop`、`releaseDetached` 操作的 `registry` 只有 `startSession` 往里写，生产里永远是空的，等于空转；**`reapOrphanSessions` 不是空转**——它除了收老会话的 scope、收发目录，还干三件三段流程在用的事：收掉上一轮引擎留下的 scope、清会话临时目录、`closeOpenRuns`（runs 表里没收场的一次性会话）、`clearReservations`（选路预占的名额）。这部分必须留，改成不依赖老会话登记的小函数（`real/orphan-reap.ts`）。
- #971 加的 `one-shot-sessions.ts` 是三段会话自己的登记，`drainStop` / `org_switch`（`stop`、`live`）现在都由它供给，不是死代码。

## 要创始人知道的一件事

`docs/goals.md` H 节有一行「发布不打断在跑的会话＝会话脱开引擎跑，重启后接回（#412，已做，留）」。这件事**只有老 Fusion 会话做过**；三段会话从来没脱开，发布靠 #957 的排空（到截止停下、交回 `org_switch`、新引擎起来重跑这一段）。删老端口等于把「脱开/接回」这套代码删了（git 里留着）。若创始人仍要给三段会话做「脱开」，要重做（底子在 `adapters/detached.ts`，没删）。

## 没删（证据不足或不在这一刀的范围里）

- **库表 `session_runs`、`pool_reservations` 等**：删表是创始人人闸；`db` 里只被老端口用的查询（`getSessionRun`、`requestSessionStop`、`createSessionRun` 一类）也没删：它们挂着 db 包自己的测试和 `store`/`web` 的读法，要和删表一起做。
- **`adapters/src/detached.ts`、`process.ts` / `cli-run.ts` 的 `io`/`attach`、`hosts.ts` 的 `resume / fork / attach / ContinueMode`**：执行体驱动是路由探针和三段会话共用的；`segment-spawner` 不传 `io`，说明脱开那一支在生产里没人走，但拆驱动接口是单独一刀。
- **`failure/` 里 KL2 / KL3 / KL4 / ES1 规则和 `failure-samples.json` 里对应的样本**（认 `oom_killed`、`engine_stop`、`signal_unexplained`、`ENGINE_STOPPING`）：生产方（老会话端口）没了，规则成了没有来源的规则；但 `failure/` 自成一块、样本钉着，没动。
- **`ports.ts` 里老会话的类型**（`StartSessionInput`、`SessionLaunch`、`SessionHandle`、`SessionOutput`、`SessionEnd`、`StopSessionInput`、`LeadBrief`、`SegmentLaunch` 等）和 `TimingEntry` 里 `kind: 'session'` 那一支（`store-ports.recordTiming` 里的 `finishSessionRun` 分支，两条测试在用）：没有外部引用，下一刀可删，这次没扩大范围。
- **`deploy/france.sh` 建 `/var/lib/fleet-sessions`、`deploy/france/fleet-engine.service` 的注释、`deploy/france/desired-config.json` 和 `deploy/local/desired-config.json` 里的 `FLEET_FORK_MAX_CONTEXT_TOKENS`**：`desired-config.json` 在 `high-risk-paths.json` 里（要走第二意见），部署脚本不在这一刀；引擎已经不读这两个环境变量，留着无害。
- **`conventions` 的 `checkPlanValue`**（`spec-doc.ts` 删了以后只剩 conventions 自己的测试用）、**`engine-jev` 的 `.port`**（原来给老会话的失败分流、停滞预判问 Jev 用，现在只剩 `register()` 在用）：不在引擎会话端口里，没动。
- `docs/goals.md` H 节「发布不打断在跑的会话＝会话脱开引擎跑」那一行没改：见上面「要创始人知道的一件事」。
