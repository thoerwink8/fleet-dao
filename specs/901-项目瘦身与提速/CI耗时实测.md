# CI 耗时实测（母单 #901，只管 CI 与测试耗时）

创始人 2026-10-05 原话：「项目臃肿+ci流程慢，需要优化重构各个模块和流程」。

接着 `docs/ci-speedup-plan.md` 前三轮往下量：那里的验收（小 PR ≤ 60 秒、deploy PR ≤ 90 秒、重推命中缓存 ≤ 40 秒）都已达到，这份只回答「现在最慢的几块是什么、有没有证据支持的、安全的提速」。**不降低必过检查的覆盖面、不改合并闸判红口径、不动第二意见流程。**

## 怎么量

`gh run list --workflow ci.yml` 取最近 60 次，取其中成功的 40 次（2026-10-04 夜到 10-05 凌晨，PR 24 次、主线推送 16 次），每次 `gh api repos/{r}/actions/runs/{id}/jobs?filter=latest` 取每个 job 和每一步的起止时间；跳过的 job 不算。「墙钟」= 第一个 job 开始到最后一个 job 结束；「关键路径」= 最后一个（不含 check）收工的 job。再下 5 次全量 PR 轮的完整日志，读 vitest 每台的 `Duration` 行和每个测试文件的耗时。

## 实测表（切片之前）

### 整轮

| 事件 | 轮数 | 墙钟中位 / 最大（秒） | job 数中位 | 机器秒中位 |
|---|---|---|---|---|
| PR | 24 | 83 / 146 | 11 | 446 |
| 主线推送 | 16 | 51 / 62 | 3 | 59 |

主线推送 16 轮里大多数同树复用了 PR 的检查（第三轮的成果）、只剩 changes + lint + check 三个 job，**关键路径每一轮都是 lint**（中位 43 秒：装依赖 4；并行三样里 tsc 29 秒最慢、docs 22 秒、biome 12 秒）。PR 轮：关键路径是测试台 16 轮、lint 6 轮、web 1、deploy 1。

### 每种 job 最慢那一台（秒）

| job | 出现在 | 最慢一台中位 / 最大 | 说明 |
|---|---|---|---|
| lint | 24/24 | 34 / 48 | 检出、装依赖约 14 + 三样并行那一步 20 |
| changes | 24/24 | 8 / 13 | 检出 3（`fetch-depth: 0`）+ 起 job |
| test | 18/24 | 81 / 102 | **整轮最长的一块** |
| deploy | 9/24 | 71 / 77 | 三台那一步 41 / 49 / 58 秒，已匀 |

### 带测试的 PR（8 台全跑，15 次）墙钟拆开

| 段 | 中位（秒） |
|---|---|
| 整轮墙钟 | 100 |
| changes | 8 |
| changes 完到第一台测试开始 | 2 |
| **测试台（第一台开始到最后一台结束）** | **84** |
| 最后一台结束到 check 开始 | 2 |
| check | 6 |

测试台占整轮的 84%。每一台里：起 job、检出、setup-node、装依赖约 12 秒（单步都在 1–4 秒），vitest 一步中位 42、最大 83 秒。

### 测试台是否匀（PR 全量）

- 普通台之间差得多：同一轮里最快 52–63、最慢 82–102 秒（`37219209031`：54 到 102；`37219911540`：61 到 87）；vitest 自己报的 Duration，`37219911540` 的普通 6 台是 38.6 / 43.0 / 45.7 / 49.8 / 58.7 / 66.3 秒，pg 两台 25.8 / 19.2 秒。
- 原因：装箱用的耗时表 `packages/conventions/test-timings.json` 是 2026-10-03 量的、359 个文件；仓里现在 455 个测试文件，**96 个新文件表里没有、按中位数 98 毫秒估，实际合计 99.6 秒**；几个旧文件现在的耗时也和表里差得远（`db/test/migrations.test.ts` 表里 20.4 秒、现在 11.2 秒；`engine/test/watchdog.test.ts` 5.3 秒对 11.7 秒；`db/test/catalog.test.ts` 9.6 秒对 3.3 秒）。
- 留出一轮检验（用另外 4 轮的中位数装箱、拿 `37219911540` 的真实耗时当真值算每台合计耗时）：旧表装箱，普通台最大 116 秒、最小 84；新表装箱，最大 93、最小 80；pg 台从两台（53 + 48）变成一台（101，vitest 里约 45 秒，不是长杆）。

### 依赖安装 / 缓存 / 重复构建

- `pnpm install --frozen-lockfile` 每台 2–4 秒（pnpm store 缓存已在 setup-node 里开了，命中）。
- 没有两个 job 做同一件事：`tsc` 在 lint 里只跑一遍；web 的 `build:demo` 只在 web 受影响时一台。
- 按改动路径跳过：`changes` 已按包依赖图选 test、web、deploy；纯文档 PR 只起 changes、lint（docs 一步 10 秒）、check，整轮 35–39 秒；主线同树复用已省掉主线的大部分测试。
