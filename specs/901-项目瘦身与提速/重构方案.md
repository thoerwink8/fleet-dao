## 1. ① 共用小工具收进 `packages/shared`

### 1.1 业务说明（它守着什么）

- **错误转文字**：任何 `catch (err)` 里，抛出来的东西不一定是 `Error`（字符串、对象都可能），要给人看的原因时不能显示 `undefined`。守的规则：**非 Error 也要有可读文字，不许吞成空**（底线「读不到要返回明确的失败」）。
- **isRecord / asRecord**：认外部来的 JSON（配置、`gh` 输出、库里的 jsonb）是不是「一个对象」。守的规则：认不出就走「认不出」那条路、不当成空对象（`standard-paths.ts:35` 注释「认不出返回一句为什么」）。数组算不算对象在各处是**判断的一部分**，不能混。
- **sleep / abortableSleep**：等一会儿，叫停（`AbortSignal`）时立刻醒。守的规则：**叫停要打断等待**，且假时钟的测试要能快进（用全局 `setTimeout`，不用 `node:timers/promises`，后者 vitest 的假时钟碰不到）。
- **iso**：时间落成 ISO 字符串，给 jsonb、接口用。

### 1.2 现状证据

见第 0 节第 2 条的数字与 `文件:行`。完整清单用 `_tmp/count.mjs`（正文最后给了复现命令）。

### 1.3 隔离现有实现：它们「怎么做」的部分不作为起点

- 每处各取一个本地名字（`message`、`errText`、`errorText`、`describeError`、`why`……），**名字不是业务，统一成 `errMessage`**。
- 北京时间用 `Intl` 还是手算偏移：从业务推（北京时间无夏令时），两者对同一时刻输出相同；唯一不同是 `Intl` + `hour12:false` 午夜给 `24:00` 的老毛病。**本方案不顺手修这个行为**，`feishu/src/words.ts` 整体留在原处，另开小单（第 6 节）。
- `(err as Error).message`（不判 instanceof，非 Error 时显示 `undefined`，如 `db/src/routing-config.ts:72,111`、`quota-reserve-apply.ts:38,58`、`agents-sync/src/*.ts`）是**另一种行为**，不在「纯重构」里改。

### 1.4 目标形状

新文件 `packages/shared/src/util.ts`，**只**从子路径 `@fleet-dao/shared/util` 引（`package.json` 的 `exports` 加一条，和现有的 `./workflow-ids` 同一个做法），**不**加进 `index.ts` 的 `export *`：index 会带出 zod 和全部接口约定，工作流沙箱、`cli` 这类只想要一个小函数的地方不该为此付代价。

```ts
export const errMessage = (err: unknown): string => (err instanceof Error ? err.message : String(err));
export const isRecord = (v: unknown): v is Record<string, unknown> => typeof v === 'object' && v !== null && !Array.isArray(v);
export const asRecord = (v: unknown): Record<string, unknown> | null => (isRecord(v) ? v : null);   // 排数组的那一族
export const sleep = (ms: number): Promise<void> => new Promise((r) => setTimeout(r, ms));
export function abortableSleep(ms: number, signal: AbortSignal): Promise<void> { /* 叫停 reject(signal.reason ?? new Error('被叫停了'))，和 task-activities.ts:78 逐字一致 */ }
```

约束（写成守卫测试，见 1.6）：`util.ts` **没有任何 import**、不碰 `node:` 内置、`process`、`Date.now()`、`Math.random()`——工作流沙箱里能 bundle、也能重放（Temporal 文档：沙箱里「可以 import 任何不引用 Node 或 DOM API 的包」，`Date`/`setTimeout`/`Math.random` 被替换成确定性版本；<https://docs.temporal.io/develop/typescript/workflows/basics>，2026-10-04 读）。`sleep` 在工作流里不该用（工作流有自己的 `sleep`），文件头写明。

**不收的**：`iso` 族（四种签名）、北京时间（八份没有两份行为相同，见 0 节）、`(err as Error).message`、数组也放行的 `asRecord` 两处、带信号 resolve 的两种 sleep、各包的自定义 Error 子类、重试退避。理由都在 0 节。`iso` 的取舍经第 7 节挑错后定为**不收**（一行函数，加一条依赖边不值）。

**不替换的地方（零安装区 + 单文件脚本）**：`packages/conventions`、`hygiene`、`agents-sync`、`mirasim-reclaude`、`adapters/src/mirasim/bridge.ts`、`deploy/`、`agents/`、`engine/src/workflows/*`（工作流文件：改它要走重放测试，价值只有一行 `iso`，不碰）。守卫（挑错后改成覆盖「所有形式」，见第 7 节第 1 条）：新测试 `packages/conventions/test/package-boundaries.test.ts`，对零安装区每个包的 `src/` 逐文件扫三种引入形式——① 裸包名 `@fleet-dao/*`（`import`、`import()`、`export … from`）；② **相对路径跑出自己包的目录**（`../../shared/…` 这种绕过包名的写法）；③ `new URL('../…', import.meta.url)` 指向别的包。每一处命中必须在名单里登记（理由 + 目标），名单初始只有：conventions 三个发布用文件引 `@fleet-dao/shared`（发布 workflow 装过依赖）、`mirasim-reclaude → adapters/src/mirasim/wire.ts`、`agents-sync → mirasim-reclaude/bin/migrate`、`agents-sync → agents/hooks/*`。这条和 ⑥ 的「跨包相对路径白名单」是**同一份测试同一份名单**（见第 4 节），不是两套。配故意造的违规用例（往零安装区文件里塞三种写法各一，必须红；名单里登记了但文件里已没有这一处，也红，免得名单越攒越多）。

### 1.6 风险与回退

- **零安装区误引**：已用守卫测试挡；回退就是 revert 单个 PR。

## 3. ⑤ `github` 包夹带 db：变成纯 GitHub API 包

### 3.1 业务说明

- **幂等账**（`idempotency.ts`）：每个 GitHub 写操作先占键、回查远端、再写、记回执——「同一件事重试不会写成两份」。账记在 Postgres 的 `idempotency_keys`，换机器、多个工人、备份恢复后重放都认得出（`idempotency.ts:1-3`）。
- **PR 镜像账**（`ledger.ts`）：驾驶舱和 `fleet done` 只读库里的 PR 镜像，不直接查 GitHub，所以写入要按 GitHub 的 `updated_at` 防倒退（`ledger.ts:1-3`）。
- **跨工人的锁**（`pgLocker`）：锁是幂等账里的一行，不占库连接（`ledger.ts:23-31` 的注释是血的教训：PGlite 只有一条连接，占着连接就卡死）。
- 这三样是**数据库的活**，不是 GitHub 的活。`github` 包的名字叫「GitHub：令牌、推分支、开 PR、等 CI、合并、issue 进度、事件、对账」，它拿数据库表（`@fleet-dao/db` 的 `pullRequests`、`repos`、`tasks`、`idempotencyKeys`）当成自己的一部分，是历史上「先放这、以后别的包也要用再挪」留下的（`ledger.ts:2`）。

### 3.2 现状证据

- `github/package.json:11-14` 依赖 `conventions`、`db`、`hygiene`、`drizzle-orm`；**只有两个文件**碰 db：`src/ledger.ts:4`（`pullRequests, repos, tasks`）、`src/idempotency.ts:11-16`（`claimIdempotencyKey, completeIdempotencyKey, idempotencyKeys, ClaimResult`）。
- 两个文件各自是「**接口 + 内存实现 + 纯逻辑**」和「**Postgres 实现**」混在一起：`idempotency.ts` 里 `once`、`holdLease`、`idempotencyKey`、`memoryIdempotencyStore`（纯）与 `pgIdempotencyStore`（`:40-79`，约 40 行）；`ledger.ts` 里 `Ledger/PrMirror` 接口、`memoryLedger`（纯）与 `pgLedger`（`:112-246`）、`pgLocker`（`:33-57`，含 `acquireLock`）。
- 使用方：`api/src/main.ts:11,72`、`engine/src/real/index.ts:18,479-480` 生产里造 `pgLedger/pgLocker`；`engine/test/github-reconcile.test.ts:16,151`；`github/test/ledger.test.ts`（494 行，**几乎全是 PGlite 上的 PG 实现测试**）；`github/test/e2e/github-e2e.ts`（手动脚本，真 GitHub + PG 账）。`store` 已经依赖 `github`、`db`、`core`、`shared`（`store/package.json:12-15`），而且 `store` 的定位本来就是「后端和引擎共用、不碰 HTTP 的那一层」。
- `packages/conventions/test/package-layers.test.ts` 现在只钉两条：任何包不许依赖 `api`；`store` 不许依赖 `engine`。`github → db` 没被钉。

### 3.3 隔离现有实现

「接口和纯实现留在 github、PG 实现挪走」这个**切法**是从业务推的：GitHub 包需要「有个账能占键、能记 PR 镜像」，不需要知道账记在哪。不是「原来文件就这么分」——原来是两个文件**各混着**两样。

另外三个自造的东西要点名：① `ClaimResult` 类型（`db/queries/idempotency.ts:7`）被 github 直接借用；② `pgLocker` 的 `sleep` 选项内联了一个 `new Promise(setTimeout)`；③ 文件名 `claims.ts` 是历史名（审查报告已提）。①：`IdempotencyStore` 是 github 的接口，`ClaimResult` 属于它的返回值，**定义搬回 github**；db 保留自己那份（表层结果），结构一致，由 store 里的适配代码在类型层核对（赋值不通过 `tsc` 就红）。③ 不动。

### 3.4 目标形状
