## 场景

v3 三段一条龙里每一段（scope / manual / verify）跑完都要记一笔：跑了什么模型、花了多少 token、什么结局。Fusion 老流程把「验证的那一轮」记在 `verify_rounds`；新流程把「每一段的那一次」记在一张统一的 `runs` 表，structure 由 `packages/engine/src/runner/not-wired.ts` 的 `RunRecord` 钉死（`#554-1` 已经写好）。

本切片先建这张 `runs` 表、把 verify 那一端改写进来（segment='verify'），读的时候先试 `runs`，再回落 `verify_rounds`（老数据不迁、不丢，仍读得到）。**不删 `verify_rounds` 那张表**（那是 #556-1 的活）。

## 怎么算做完

1. **`packages/db/src/schema/runs.ts`**：新表 `runs`，列字段对照 `RunRecord`：id（uuid primary key）、segment（`scope` / `manual` / `verify` 三择一，写死的检查）、taskId（可空，外键 → tasks；不属于任何需求的会话为空）、issueNumber（可空）、model（非空字符串）、channel（可空）、startedAt（非空）、endedAt（可空）、outcome（枚举：done / timeout / killed / spawn_failed / admission_blocked / failed；还在跑的时候为空）、inputTokens / outputTokens / cacheReadTokens / cacheWriteTokens / costUsd / memoryPeakMb（可空，**不拿 0 顶**）、prNumber（可空）、branch（可空）、workflowId（可空）、temporalRunId（可空）、retryOf（可空，自引用，指向 runs.id）、createdAt（非空默认 now）、updatedAt（非空默认 now）。
2. **`packages/db/migrations/<下一份>_runs.sql`**：只 `CREATE TABLE runs ...`、加约束，**不 DROP、不 ALTER `verify_rounds`**；生成到 drizzle-kit 下一份迁移编号。
3. **`packages/db/src/queries/verify.ts`**：`saveVerifyRound` 同一次写入**两头都写**：`verify_rounds` 记细节（criteria / report / verdict / 驳回，照原样），`runs` 记一笔流水（segment='verify'，**id 与 verify_rounds 同根**，当 join 键用）；runs 里读不到的字段（token / 花费 / 真起止 / outcome 那只跑完）写成这一笔的临时刻度，`#556-4/-5/-6` 装上真 RunsWriter 之后到了会话真正结束再整行覆盖。`verifyRoundsOfTask` 照旧返回 `VerifyRoundRow`——**老行（只有 verify_rounds、没 runs 流水的）由 LEFT JOIN 不命中自然带出**，不手工合并、不迁移老数据。
4. **`packages/db/test/runs.test.ts`** 新建：
   - `saveVerifyRound` 调一次：`runs` 里多一行流水（segment='verify'，同一 id），`verify_rounds` 里也照样写一行（老路还读得到细节）。
   - 老数据照样读得到：手工在 `verify_rounds` 直接写一行（**绕过** `saveVerifyRound`，模拟本切片上线前的老行）；`verifyRoundsOfTask` 照样返回它。
   - **故意造红**：
     - segment 写不在 `scope | manual | verify` 里的值：**库拒收**（约束名 `runs_segment_known`）。
     - outcome 给空、同时给了 endedAt：**库拒收**（`runs_outcome_iff_ended`——参照 `verify_rounds_invalid_shape` 的做法）。
     - `retryOf` 自引用指到不存在的 runs.id：**库拒收**（外键 `runs_retry_of_self_fk`）。
     - 直接插 runs 时把 `inputTokens` / `costUsd` 给成负数：**库拒收**（`runs_usage_nonneg`）——「读不到就不写、不拿 0 顶」由 NULL 保证。
     - `saveVerifyRound` 找不到路由对应的 model：**明确报错**（「不拿空顶」），不是塞进空字符串。
5. **测试全绿**：`pnpm exec vitest run packages/db/test/runs.test.ts` 全绿；`pnpm test:changed` 退出码 0。
6. **不动** `verify_rounds` 表的 DROP / 老数据迁移；Fusion 工作流 lua 不动。
