- 「我希望全局都生效」→ 调研各家怎么设后，回「选 1」（先做 Grok、Devin、Kimi、Codex 四家，Gemini 和 Antigravity 等装上能实测再补，pi、dsh 做不到只在文档里写明）

AI 理解：#516 只让 Claude Code 吃上仓里那份权限（defaultMode、allow、deny）。要把同一份意图翻译成 Grok、Devin、Kimi、Codex 各自的配置格式，由 agents-sync 同步到每台机器，并且有文档、有一条命令能一次把这台机器上装了的各家都同步好。

## 要什么

- 仓里仍只有一份权限意图（`agents/config/claude-permissions.json`），每家一个翻译，各写各的位置，只补缺、不删机器上自己加的，读不懂就不动、报出来（同 #516 的规矩）：
  - Grok：`~/.grok/config.toml` 的 `[permission]`（allow/deny/ask，`Bash(git:*)` 可照抄）。先实测它是否已读 `~/.claude/settings.json` 的 permissions，读了就不重复写、免得两边冲突。
  - Devin：`%APPDATA%\devin\config.json`（Linux `~/.config/devin/config.json`）的 `permissions`，写成 `Exec(git)` 这类；不读 Claude 的权限，必须翻译；默认模式用 `smart`（最接近 auto）。
  - Kimi Code：`~/.kimi-code/config.toml` 的 `[permissions]`。它的 `auto` 是「什么都不问」，不是 Claude 的 auto；同步用 `yolo`（该问才问）。
  - Codex：`~/.codex/rules/` 下的 rules 文件（`prefix_rule(pattern=[...], decision=...)`，只按前缀、无通配符，翻译不了的写明并报出来）。
- 做不到的两家在文档里写明为什么：pi（没有审批功能）、dsh（只有 ask/never，不能按命令区分）。Gemini CLI、Antigravity：装上能实测后再补（写在同一份文档的「待补」里）。
- 一键全生效：一条命令在这台机器上先把 fleet-dao 检出快进到主线、再跑同步（含权限）、最后读回检查，打印每一家「生效 / 没装 / 没做成」。命令进 `package.json` 脚本（暂定 `pnpm agents:sync`），Windows 和 Linux 都能跑；机器上 git 或 node 不能用时明确失败，不拿空当成功。
- 文档：一份说明各家权限怎么设、装到哪、怎么看是否生效、怎么撤回的文档（放 `docs/`，`docs/ops.md` 链过去），含上面的对照表；AGENTS.md 通用段不改（改了是改标准，另说）。
- `--user`（法国装机）仍整段不写；要不要给法国写，另请创始人拍。
- 每家的翻译在本机装得上的先实测（写一份配置，跑那家自己的检查命令，确认认出来）；装不上的标「文档所述、未实测」。每条读不懂、写不成、格式认不出的路径配一条故意造出失败的测试。

## 怎么算做完

- 分期：第一期 Grok + Kimi；第二期 Devin + Codex；第三期 一键命令 + 文档（可与前两期的 PR 并行，最后一期合并时单才关）。
- 每一期：新增翻译有测试（装、合并不动别的、幂等、备份、没装跳过、`--user` 跳过，加故意造出失败的读不懂路径），`--check` 报每家一行，读回一致。
- 一条命令跑完，在这台机器上输出每家结论，退出码对得上（有没做成就非 0）。
- 文档进主线，`docs/ops.md` 有链接。
- 每一期改到 `packages/agents-sync/src/targets.ts`，都是改标准：PR 正文写「人闸：改标准」，贴创始人的原话，等他同意再挂自动合并。
