# 引擎对账开的后续单、超出范围的单连需求文档一起开，自动派下去不停在收单（#295）

对应计划：未排期
设计依据：docs/design.md 第五节「没人拍板」（对账给提问另开单）、第九节「在哪能做与接活开关」

原话：无（#259 第 2 个 PR 做到时发现。帅位派工时说「按 #287，挂在当前版本上的独立单会被自动派，这正是想要的」）。

AI 理解：#259 起，引擎每轮 GitHub 对账给提问另开单：创始人合并后才改选的开后续单（挂原单的同一个版本，挂在当前版本上的由接活自动派），超出范围的开未排期单。引擎不往主线直接写，开出的单没有 `specs/<号>-<短名>/需求.md`，正文里也没有「文档：」那一行（正文末尾写了请人补）。自动派下去的后续单会停在 Fusion 第 1 步收单「认不出需求文档」，要人补文档、点继续。要让它不用人补就能接着做。

## 怎么算做完

- 引擎对账开的后续单、超出范围的单，需求文档跟着进主线（比如引擎开一个只加 `specs/<号>-<短名>/需求.md` 的 PR、CI 绿自动合；或者别的不直写主线的办法，方案里定），单子正文补上「文档：」那一行。
- 测试：对账开出后续单，需求文档合进主线，下一轮接活派下去，Fusion 收单认出需求文档、不停下。
- 故意造出的失败：需求文档没开成、没合进去时，单子不当成有文档——不派，或者派了照旧停在收单、报提醒写明原因。
