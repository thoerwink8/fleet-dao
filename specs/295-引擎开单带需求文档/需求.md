# 引擎对账开的后续单、超出范围的单连需求文档一起开，自动派下去不停在收单（#295）

对应计划：v1 Fusion 接活
设计依据：docs/design.md 第五节「没人拍板」（对账给提问另开单）、「第 5 步开 PR 前验证怎么做」，第七节「分工」，第九节「在哪能做与接活开关」

原话：无（#259 第 2 个 PR 做到时发现。帅位派工时说「按 #287，挂在当前版本上的独立单会被自动派，这正是想要的」）。

AI 理解：#259 起，引擎每轮 GitHub 对账给提问另开单：创始人合并后才改选的开后续单（挂原单的同一个版本，挂在当前版本上的由接活自动派），超出范围的开未排期单。引擎不往主线直接写，开出的单没有 `specs/<号>-<短名>/需求.md`，正文里也没有「文档：」那一行（正文末尾写了请人补）。自动派下去的后续单会停在 Fusion 第 1 步收单「认不出需求文档」，要人补文档、点继续。要让它不用人补就能接着做。

做法（2026-09-27 帅位把这张单挪进 v1、让比两个方向定）：定了方向 2，收单时认正文里写全了的需求，比较见同目录 `方案.md`；下面「怎么算做完」照定下的改过。

## 怎么算做完

- 引擎对账开的后续单、超出范围的单（正文写全了需求、没有「文档：」那一行）派下去，Fusion 收单照收、不停下；Lead 把照正文写的需求文档和方案一起提交，随 PR 进主线；开 PR 前验证照单子正文的「怎么算做完」核；PR 的「对应计划」照单子挂的版本写。
- 测试：`engine/test/fusion.test.ts`「正文写全了需求、没有需求文档的单」一组，含对账真开出来的后续单、超出范围的单（core 的 `askIssueText` 写的正文）做到合并。
- 故意造出的失败，拿改动前的代码跑都是红的：正文没写全（没有或空的「怎么算做完」）照旧停在收单；Lead 没提交需求文档不收方案、几次都不交停下等人；开 PR 前正文里的「怎么算做完」被删了停下等人，不当成验过了；照单子挂的版本写「对应计划」时读不到单子，不开 PR、不当成未排期。

## 现状

做了（方向 2，见 `方案.md`）：收单认正文里写全了的需求，引擎照正文写需求文档交给 Lead、随 PR 进主线，验证照正文核，「对应计划」照单子挂的版本；对账开的单正文照这个写；欠账定时任务不再把这种单算成欠需求文档。
