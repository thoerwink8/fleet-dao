# fleet-api：deploy 侧接上 systemd socket activation（fleet-api.socket），让 #364 那次做好的进程侧真正生效（#405）

对应计划：未排期
设计依据：docs/design.md 第十三节「高可用与高响应」——「服务挂了自动重启」是这一节定的既有目标，这单只是把「重启」做到连接不丢（systemd socket activation），不改设计、不加新目标。

原话：创始人没有直接提过这张单；是帅位在派「fleet-api 平滑重启」（收 #364）时定的边界——deploy/、packages/engine、单元文件的 KillMode 当时正有另一位工人在改「引擎排空发布」，怕撞车，交代这次不碰。AI 理解：这张单是把那次没做完的那一半（systemd socket activation 的 deploy 侧接线）单独立出来，等那边的改动落定、没有文件冲突风险了再接。

## 背景

fleet-api 平滑重启那次（`packages/api/src/listen.ts`、`shutdown.ts`）已经把**进程这一侧**的 systemd socket activation 支持写完、测试覆盖了（含一条 Linux 专属的 `systemd-socket-activate` 真 fd 集成测试，CI 是 ubuntu 会跑）：`startListeners()` 认 `LISTEN_PID`/`LISTEN_FDS`，有就从 systemd 接手已经听上的 fd（重启时连接排在内核队列里、不会被拒连），没有就照旧自己 bind，两条路都测过、都安全。但这条能力要真正生效，还差 **deploy 侧**——装一个 `fleet-api.socket` systemd 单元、把 `fleet-api.service` 改成 `Requires=`/`After=` 它、发布脚本要在切版本时把这个单元也当成「这一版带不带它」去同步。这一半当时没做，是因为会改到 `deploy/release.sh`、`deploy/france/fleet-api.service`——这两个文件另一位工人正在改「引擎排空发布」（KillMode、会话排空相关），怕两边并发改同一个文件互相踩。

## 怎么算做完

1. 确认「引擎排空发布」那次改动已经合并、`deploy/release.sh` 和各服务的 `.service` 单元文件稳定下来，不会再和这张单的改动并发冲突。
2. 新增 `deploy/france/fleet-api.socket`：两个 `ListenStream`（驾驶舱接口、fleet 命令接口，地址要和 `api.env` 的 `FLEET_COCKPIT_LISTEN`/`FLEET_AGENT_LISTEN` 保持一致）、`FreeBind=yes`（隧道没起时也能先攥住驾驶舱接口那个地址）、`Service=fleet-api.service`、`WantedBy=sockets.target`。下面「参考稿」一节有一份完整草稿，字段和理由都写了注释，可以直接抄，只需要跟当时最新的 `api.env`/`fleet-api.service` 核对地址是否还一致。
3. 改 `deploy/france/fleet-api.service`：`[Unit]` 段加 `Requires=fleet-api.socket`、`After=` 里加上 `fleet-api.socket`（放最前面）——没装这个单元的机器（还没发过这张单的改动、或者以后有意撤掉）要能照旧自己 bind，不能因为 `Requires` 硬依赖一个不存在的单元起不来（草稿里这条注释写了怎么两全）。
4. 改 `deploy/release.sh`：
   - `build_release()`：单元文件从提交里取的那一步，`.socket` 后缀的文件是可选的（不是每个服务都有），有就跟着 `.service` 一起存进 `.fleet-release`/`.units`。
   - 新增一步（草稿里叫 `sync_socket_unit`）：切版本时按「这一版带不带 `.socket`、机器上现在有没有」这两个维度，处理三种情况——①带、机器上没有：先停掉正占着端口的旧服务、装上 socket 单元、`enable --now`，然后走原来的重启逻辑把服务本身起来（这时端口已经归 systemd 攥着，服务从 fd 接手）；②带、机器上已经有：不碰 socket 单元本身（改监听地址是人工操作，涉及 `api.env`、`release.sh` 里的地址常量、`docs/ops.md` 端口表一起改，不该让发布脚本自动做），只照常重启服务；③不带（回退到没有它的老版本）、机器上有：撤掉 socket 单元（`disable --now`、删文件、`daemon-reload`），回到服务自己绑端口。
   - `settle_services()`、`do_check()`：装了 `.socket` 的话，确认它本身也在跑（不在跑的话下一次重启这个服务又会拒连，等于白装）。
5. `packages/api/src/main.ts`、`listen.ts` 不需要再改——上次那次已经把「有 fd 就接、没有就自己 bind」两条路都写好测过了，这张单只是让 deploy 侧真正开始传 fd。
6. 发一版，确认：`fleet-api.socket` 装上、`active`；重启 `fleet-api.service` 时（比如手动 `systemctl restart fleet-api`）连到驾驶舱接口/fleet 命令接口的新连接不再瞬时拒连（可以用一个紧凑的轮询脚本在重启前后连续发请求，确认没有 `ECONNREFUSED`）；`fleet-api` 日志里能看到「从 systemd 接手 fd」这条路径被走到（不是本机 bind 的日志）。
7. `specs/<本单号>-…/结果.md` 写清楚验证过程和读数。

## 参考稿（上次做到一半时写好、因为文件冲突风险撤掉的内容，供接手直接抄）

### `deploy/france/fleet-api.socket`

```systemd
# fleet-dao 驾驶舱后端的监听套接字：deploy/release.sh 从要发布的那个提交里取这份，装到 /etc/systemd/system/；
# 改这份、再发布一次，别在机器上手改。装了它，fleet-api.service 重启（发布切版本就会重启）不再丢请求——两个端口
# 一直归这个 socket 单元攥着，systemd 把重启期间进来的新连接排进内核队列，等新进程起来接着 accept，不回 502、不拒连
# （sd_listen_fds(3) 的约定，见 packages/api/src/listen.ts；Lennart Poettering「systemd for Developers I」原话
# "we can restart the service while keeping around its sockets … Not a single connection is lost"，
# https://0pointer.de/blog/projects/socket-activation.html）。#364：香港 nginx 经隧道转来的请求（webhook、驾驶舱）
# 回 502、本机 AI 会话的 fleet 命令连 127.0.0.1:8788 被拒，都是没有它的时候、重启那几秒会出的老问题。
# 两个监听要和 fleet-api.service 的 api.env（FLEET_COCKPIT_LISTEN、FLEET_AGENT_LISTEN）写同一个地址——装了这个单元，
# 后端就不自己 bind 端口了，改地址要两边一起改（deploy/france/api.env.example 也是同一份，deploy/release.sh 的
# COCKPIT、AGENT_API 两个常量同样要跟着改）。
# 一个 socket 单元里的两个 ListenStream 没法各起各的名字：FileDescriptorName 对整个单元生效，两个监听会拿到同一个
# 名字，区分不了谁是谁。所以 packages/api/src/listen.ts 不靠名字分：先把 systemd 传来的每个 fd 都听上，再拿
# server.address() 和这两行地址逐一比对，对不上就报错退出，不悄悄自己再 bind。
[Unit]
Description=fleet-dao 驾驶舱后端的监听套接字（驾驶舱接口 + fleet 命令接口）
Documentation=https://github.com/thoerwink8/fleet-dao/blob/main/docs/ops.md

[Socket]
ListenStream=10.99.0.2:8787
ListenStream=127.0.0.1:8788
# 隧道（wg-fleet）这时可能还没起：这个单元不等它，先把驾驶舱接口的地址攥住；FreeBind 允许绑一个本机现在还没有的地址
# （IP_FREEBIND），隧道起来之后这个绑定照样管用，不用重新绑。fleet-api.service 的 [Unit] 仍然
# After=wg-quick@wg-fleet.service：服务本身要不要真正起来（读配置、连库）还是等隧道就绪，这里只管端口攥没攥住。
FreeBind=yes
Service=fleet-api.service

[Install]
WantedBy=sockets.target
```

（地址 `10.99.0.2:8787`、`127.0.0.1:8788` 是当时 `api.env` 里的值，接手时要核对没变。）

### `deploy/release.sh` 的 `sync_socket_unit`（草稿，插在 `activate()` 里装单元那一步之前）

```bash
# socket 单元的三种转换（#364，deploy/france/fleet-api.socket）：这一版带没带它、机器上有没有已经在跑的：
# - 带、机器上没有（头一次上 socket 激活）：服务自己正占着端口，得先停掉才腾得出来装；装上 socket 单元、
#   enable --now，端口这时候起归 systemd 攥着；调用方（activate）看 SOCKET_FORCE_RESTART 知道这一轮要重启服务——
#   服务这时候还没起（刚被停掉），要靠后面重启逻辑把它起来，起来时从 systemd 接手 fd，不再自己 bind。
# - 带、机器上已经有在跑：不碰 socket 单元——改 socket 的监听地址是人工操作（会牵扯改 api.env、release.sh 的
#   COCKPIT/AGENT_API 常量、docs/ops.md 端口表，一起改一起发），不是发布脚本自动做的事；只照常重启服务，这正是
#   要的效果：重启时连接排在内核队列里，不会被拒。
# - 不带（退回到没有它的老版本）、机器上有：撤掉 socket 单元（disable --now、删文件、daemon-reload），回到服务
#   自己绑端口——不撤的话老代码不会去读 systemd 传来的 fd，端口反而没人监听。
SOCKET_FORCE_RESTART=0
sync_socket_unit() { # 单元名 这一版的目录
  local u=$1 dir=$2
  local socket_file=/etc/systemd/system/$u.socket has_now=0
  SOCKET_FORCE_RESTART=0
  if [[ -e "$socket_file" ]]; then has_now=1; fi
  if [[ -f "$dir/.units/$u.socket" && "$has_now" == 0 ]]; then
    if [[ "$(systemctl is-active "$u.service" 2>/dev/null)" == active ]] && ! systemctl stop "$u.service"; then
      red "头一次装 $u.socket 之前，停不掉正占着端口的 $u.service"
      return 1
    fi
    put_file "$socket_file" root:root 644 "$(<"$dir/.units/$u.socket")"
    if ! systemctl daemon-reload; then
      red "systemctl daemon-reload 失败（装 $u.socket 之后）"
      return 1
    fi
    if ! systemctl enable --now --quiet "$u.socket"; then
      red "$u.socket 起不来：journalctl -u $u.socket -n 50 看现场"
      return 1
    fi
    changed "头一次给 $u 装上 socket 单元（往后重启 $u 时连接排队、不拒连）"
    SOCKET_FORCE_RESTART=1
  elif [[ ! -f "$dir/.units/$u.socket" && "$has_now" == 1 ]]; then
    if ! systemctl disable --now --quiet "$u.socket"; then
      red "撤 $u.socket 失败"
      return 1
    fi
    rm -f -- "$socket_file"
    if ! systemctl daemon-reload; then
      red "systemctl daemon-reload 失败（撤 $u.socket 之后）"
      return 1
    fi
    changed "撤掉 $u.socket（这一版没带它，回到 $u 自己监听端口）"
    SOCKET_FORCE_RESTART=1
  fi
}
```

`build_release()` 取单元文件那一步要加：

```bash
if git -C "$CACHE" cat-file -e "$sha:deploy/france/$u.socket" 2>/dev/null; then
  git -C "$CACHE" show "$sha:deploy/france/$u.socket" >"$stage/.units/$u.socket"
fi
```

`activate()` 里装 `.service` 之前调 `sync_socket_unit "$u" "$dir" || return 1`，`SOCKET_FORCE_RESTART` 为真时把 `fresh[$u]` 也标成 1（强制重启，即使 `.service` 内容本身没变）。撤用不到这个服务时（`release.env` 没启用它），顺带把它的 `.socket` 也撤掉。

`settle_services()`、`do_check()` 里加一段：`.socket` 文件存在的话检查它 `is-active`，不是就报红（装了但没在跑，等于白装，下次重启这个服务照样会拒连）。
