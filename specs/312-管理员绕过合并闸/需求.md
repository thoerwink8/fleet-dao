# 堵上管理员绕过合并闸：执行命令前的钩子拦 gh pr merge --admin 和直接调合并接口（#312）

对应计划：未排期
设计依据：`docs/design.md` 第五节「合并闸」（能不能合只看 merge-gate）、「人闸第四类：改标准」；`specs/299-帅位只一个/方案.md` 第五节「已知的口子」

原话：帅位 2026-09-27 转述 #299 方案（`specs/299-帅位只一个/方案.md`「还拿不准的」）第 3 件——「管理员绕过合并闸：开一张小单，写清口子在哪、怎么堵（钩子拦 `gh pr merge --admin`，改标准）」。

AI 理解：主线的规则集「主线保护」把仓库管理员放进了绕过名单，本机各个会话的 gh 登的都是创始人（管理员）账号，一条 `gh pr merge <号> --admin` 就能不等必过检查（`check`、`merge-gate`，#299 之后还有「认领对得上」）直接合。规矩上不手动合，可没有东西拦着；#299 靠合并闸挡住旧工人的 PR，这个口子一开就白挡了。

## 口子在哪

- 规则集「主线保护」（仓库设置里）：绕过名单有仓库管理员角色（always）和一个集成（always）。
- 本机会话的 gh 是创始人账号，就是管理员：`gh pr merge <号> --admin` 不等必过检查；直接调合并接口（`gh api -X PUT repos/<owner>/<repo>/pulls/<号>/merge`）在允许绕过时也一样。
- 现在拦它的只有 AGENTS 本仓段「能不能合只看 GitHub 上的必过检查，不手动合」这一句话。

## 怎么堵

- 在各家 AI 执行命令前的钩子（`agents/hooks/pretool.mjs`）里拦：`gh pr merge` 带 `--admin` 的，和直接调合并接口的 `gh api`（PUT 到 `…/pulls/<号>/merge`）。拦下时说清：合并只靠自动合并等必过检查；法国挂了要修法国时，由创始人自己在网页上合。
- 钩子的规矩由 `agents/test/rules/pretool.rules.test.ts` 钉住：加规矩、加钉住它的测试都是改标准，PR 正文写「人闸：改标准」，等创始人同意再合。
- 不动规则集的绕过名单：法国连不上时修法国的 PR 还得靠创始人以管理员身份合（`specs/299-帅位只一个/方案.md`「换设备的边界落在哪」第 6 条）。

## 怎么算做完

- 故意造出的失败：钩子的测试里 `gh pr merge 12 --admin`、`gh pr merge --admin --squash 12`、`gh api -X PUT repos/o/r/pulls/12/merge` 都被拦，提示写清为什么；`gh pr merge 12 --auto --squash` 照放。拿改动前的钩子跑，前三条要红。
- 改标准的 PR 经创始人同意合进主线；各台机器同步以后，在本机会话里真敲一次 `gh pr merge <号> --admin` 被拦下。
