# 驾驶舱里看欠账和阶段收口：各里程碑开着的单、没需求文档的单、推后没落单的话；有没处置的单就关不了里程碑（#80）

对应计划：plan.md P2「后台第一批页面」
设计依据：design 第三节第 35 条、第七节「标签与里程碑」、第十五节（驾驶舱）。

原话：阶段收口：一个里程碑要关之前，列出里面还开着的单，每张要么做完、要么挪到后面的里程碑并写明原因；有没处置的就不许关（脚本 + 驾驶舱里看得到）。（创始人 2026-09-25，#67 第 4 条）
AI 理解：脚本那半边在 #67 做了（`pnpm milestone:close-check P1`、`pnpm debt:check`）；这张做驾驶舱那半边：每个里程碑还开着几张、哪几张，开着却没需求文档的单，文档里推后却没落到开着的单上的话，在驾驶舱里一眼看得到；里程碑有没处置的单时，驾驶舱里关不了。

## 要什么

- 后端定时（或收到 GitHub 事件时）算一遍：各里程碑开着的 issue 和 PR、开着却没有需求文档的 issue、推后没落单的话，结果进库；算法和 `packages/conventions` 的两个脚本用同一份代码，不另写一套。
- 驾驶舱总览里一块「欠账」：按里程碑列，点进去是单子和文档行号。
- 里程碑的「关」按钮：还有开着的单就点不了，并列出是哪几张。
- 读不到 GitHub、算不出来：显示「这次没查成」和上次成功的时间，不显示成 0。

## 怎么算做完

- 接口测试：造一个里程碑里有一张开着的单，接口返回它；造一次 GitHub 读失败，接口返回「没查成」而不是空列表。
- 驾驶舱里：P1 还有开着的单时，总览「欠账」一块列出它们，P1 的「关」按钮点不了；全部处置完以后能关。
