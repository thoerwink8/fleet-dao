# #902 驾驶舱首页恢复流程图：best-practice-first 六步记录

创始人 2026-10-05 原话：「驾驶舱的首页 react-flow 怎么没了」。09-28 原话：「驾驶舱要能给人看、体现流程运转」。
答案：旧的多人看板（react-flow 画布，`382c77b4` 加、`f49cef8f` 删，#556 / #612）按 `docs/goals.md` E 节「一屏三块」有意删掉了；这次按「要恢复流程可视化」办：首页仍是三块，「在跑的」那块换成三段流水线图。

## 1. 业务说明

- 谁、什么场合、干成什么：创始人（也会给别人演示）打开首页，一眼看到三件事——要我拍的、每张开着的单走到对题 / 动手 / 验收的哪一段、做完的。干成的标志：不点进任何单子，就知道「哪张单卡在哪一段、谁在做、已经多久、在等谁拍什么、最近发生了什么」，并且先看到的是要我拍的。
- 业务规则（出处）：
  1. 三段固定先后：对题 → 动手 → 验收（决定 0010 第 1 条）。
  2. 「还没验」不许显示成失败，真失败（超时 / 失败 / 没起来）才用红（0010 第 8 条、方案 §十三.3）；额度、中转、引擎关是持续状态，不伪装成失败（`health-strip.tsx` 注释）。
  3. 读不到不拿空顶：库读不到 `/api/home` 回 500，前端写「没读成」并带重试（`goals.md` E 节、通用段底线）。
  4. 平均耗时没有样本不写 0（通用段底线）；读不出起止的笔不进样本（`shared/src/segment-runs.ts`）。
  5. 同一个业务对象只在一处出现：一张单只有一张卡，不并存「列表 + 图」两份（best-practice-first 第 4 步）。
  6. 点卡片进单子详情（原「在跑的」卡片的链接）。

## 2. 隔离现有实现（都不作为设计起点）

旧看板的「多人、思维导图、ELK 自动排版、三级缩放、右键菜单」；现首页的「三列并排、一列卡片」；`segment` 一律 null 的接口。只继承规则 1–6。

## 3. 业界对照（2026-10-05 取）

| 来源 | 它们怎么做 | 对我们的启发 |

要的是：列 = 阶段（GitLab）、卡片带状态和耗时（GitHub / Temporal）、整体一屏。

## 4. 从业务重推：方案与代价

- 操作剧本：打开首页（0 次点击）→ 看到要我拍的 → 看三条泳道里谁卡着 → 点一张卡进详情。动手 / 搬运 / 离开：0 / 0 / 0（改前：要点进每张单才知道在哪一段，离开次数 = 开着的单数）。
- 三个方案：

| 方案 | 做法 | 代价 |
|---|---|---|
| A 现状 | 一列卡片，每张文字写「在干活」；段不知道（接口一律 null） | 零成本；看不出先后，不满足 0010 第 8 条「有先后依赖」 |
| B 静态 HTML/CSS 三列 | 同样的版式，不用 react-flow | 体积 +0；没有平移 / 缩放；创始人明确问的是 react-flow |
| C react-flow（采用） | 节点 = 三条泳道 + 每张单的卡片，布局算死、不让拖；平移 / 缩放留着；泳道之间的边会在有在途时流动 | 体积 +62.7 KB gzip（全站 js+css 354.8 → 417.5 KB gzip；home 路由 4.4 → 64.5 KB js，另 +2.0 KB css），客户端构建 1.73 → 4.54 s（各测一次，有噪声）；只有首页路由加载，其他页面不受影响 |

- 为什么选 C：创始人点名 react-flow；并且「删掉整层」（B）的收益只是 62.7 KB，而旧依赖 `@xyflow/react` 本来就还在 package.json 里、主题 CSS（`app.css`「看板画布跟随主题」那段）也还在。**如果之后想省这 62.7 KB，换 B 只动 `flow-board.tsx` 一个文件**：版式（`lib/home-flow-layout.ts`）、卡片、接口都不依赖 react-flow。
- 后端：`segment` 从三段流水（runs 表）推（`shared/src/home-flow.ts`，后端和假后端同一份）；store 新增 `listSegmentRunsForTasks` 一次读完（一张张读要几十个往返）。

## 6. 落库与版面验收

截图都在 `_tmp/home-flow/`（`compare-1920x1080.png`、`compare-1366x768.png` 左边是本方案真组件 + 假后端数据，右边是对照产品截图）。

1. 屏幕用满了没有？
   - 1920×1080：整页一屏放下，没有滚动；右边流水线图下方有约 180 px 空着（左列「要你拍的 + 做完的」比右边高，不刻意撑高图）。页面不再限 1320 宽（`max-w-none`），两侧没有空白。
   - 1366×768：要你拍的（三张并排）整块可见，流水线图的三条泳道头和每条第一张卡可见，其余要往下滚——11 张在途的单一屏放不下，这是数量决定的；要你拍的永远在流水线前面。
2. 要紧的细节是不是一眼可见？单号、标题、谁在做、本段多久、在等什么、最近事件都直接写在卡上，没有藏进悬停 / 抽屉；只有超长标题被截断（悬停看全，因为一行放不下）。平均耗时在泳道头上。
3. 最显眼的是不是下一步（要我拍的）？1920 下左上角第一块是要你拍的，带紫色边框；卡片里等你拍的也带紫色边框和「等你」点。1366 下要你拍的是第一块。是。

## 补：#914 之后 e2e 查出的三处（D9 / D11 / D7，`specs/902-驾驶舱用户视角e2e/缺陷清单.md`）

- **D9 右边缘被截**：根子不是边距而是视口偏移。react-flow 先按退路宽度（1200）排一遍，视口被居中到错位置（真实 DOM 量到 `translate(13px)`，换成精确移动范围后变 26.5px，证明是首次排版的偏移），容器量到真宽以后它不会自己回正。修在必经的那一步：`useElementWidth` 在画面画出来之前（`useLayoutEffect`）先量，量到了才挂画布；容器宽度、横竖排变了就把视口放回原点（`ViewportHome`）；移动范围收成精确的 `[0,0]–[版式宽,版式高]`。React Flow 水印不动（MIT 不强制，去掉要订阅 Pro 是花钱，创始人定）。
- **D11 手机上要横拖**：窄屏（横排每条泳道装不下 250px，即容器约小于 840px）改成三条泳道竖着叠，每条占满宽、一样宽；这时不能拖、没有缩放按钮，并把 d3-zoom 写在图上的 `touch-action:none` 盖回 `pan-y`，手指按在图上页面照常竖向滚动。
  - 对照（2026-10-05 取）：GitHub Mobile 的 Actions 是「检查列表 → 点进某个 workflow / job」，不在手机上画横向图（https://github.blog/changelog/2022-10-04-introducing-actions-on-github-mobile/ 、https://github.blog/2023-01-20-bringing-github-actions-to-github-mobile/ ；两篇只说看检查、点进 job 看日志，没写版式细节，版式一层没取到对照截图，不硬说）；web.dev 响应式基础：「用户习惯竖着滚动网页，不习惯横着滚，强迫横滚或缩小才能看全会损害体验」（https://web.dev/articles/responsive-web-design-basics）。结论：竖叠、不横拖。
- **D7 引擎那一格**：主页读 `/healthz` 里同一个 engine 探针（`packages/api/src/home-engine.ts`，结果留 15 秒，不每次开主页都去问 Temporal）：on / off（已停用，黄、不红）/ down（没连上，红）/ unknown（没有探针，没查成）。连不上调度服务、探针超时一律是 down，就是 D7 里「temporal、engine 都 unreachable 还写正常」的那种情况；只有这台后端压根没有引擎探针（开发、内存版）才是「没查成」。
  - 一处取舍：「读不到就写没查成」我只留给「没有探针」；探针在却读不到引擎（Temporal 连不上）按「引擎没连上」处理，因为那时引擎一定不在干活。
- 截图（本机 `_tmp/home-flow2/`）：`home-*`（D9、D11 修后）、`engine-down-*`（D7，三个尺寸）、`engine-off-1920x1080`、`engine-unknown-1920x1080`。
