# 方案：接上 SuperGrok 的 Grok 4.7——会话端口、探针、失败分流、装机（#266）

需求见同目录 `需求.md`。照 #212 接 Cursor 那一套（`specs/212-接第一个别家渠道/方案.md`）：每种执行方式一个驱动，起会话、看守、结局判定、失败分流、记账和路由探针只认驱动整理出来的同一个形状。和派工交代不一样的有两处：开新会话时会话号先不算数（第二节）；装的时候不让安装脚本碰 `~/.local/bin` 和 shell 启动文件（第四节）。

## 一、做了什么

1. **插头从 adapters 导出**（`packages/adapters/src/index.ts`）：grok 的 args、run、stream 三个文件整套导出。读取器多记一样：最后一段回答（`answer`，最后一次 say 的全文）——终帧里没有回答正文，探针靠它看是不是只回了 OK。`grokRunFacts` 拼执行体原话时，stderr 里已经有的 error 帧不再拼一遍：grok 报错退出时 error 帧和 stderr（「Error: 」开头）各打一遍，不去重的话失败信息、「要人拍」的提醒里同一句出现两次。
2. **驱动**（`packages/engine/src/real/hosts.ts`）：`WIRED_HOSTS` 加 `grok`，探针跟着就探、选路跟着就派。干活的会话带 `--always-approve`（理由和 Claude 放开权限一样：会话用户读不到引擎的配置和机器人凭据，无头会话没人批；`--permission-mode auto` 每条命令还要确认，GK-04），探针不带（要权限的工具无头模式下一律被拒）。实际模型取终帧 `modelUsage` 的键（`grok-4.7-build`，插头按「同一代带渠道后缀」认得是 `grok-4.7`）；token 照终帧记（输入、输出、缓存读写）；终帧的 `total_cost_usd` 不记（订阅下是折合 API 价的数，不是账单，和 Cursor 一样不记）。
3. **grok 怎么起**：装在会话用户家里的 `~/.grok/bin/grok`（`FLEET_GROK_BIN`，默认 `/home/{user}/.grok/bin/grok`，要绝对路径，写错了引擎起不来）。引擎进不去会话用户的家，所以由会话用户自己先看它是不是能跑的文件（`grokLaunchCommand`：`-f` 且 `-x`——`-x` 对目录也成立），是就 exec 成它（进程号不变），不是就退出 127、stderr 写「spawn grok ENOENT：<位置> 不在或不能跑（会话用户家里没装 grok 命令行…）」，失败分流按 CF1 认。位置经参数传给脚本、不拼进脚本，整条命令没有换行（要经 sudo 记日志）。插头在前面再垫一个 `cat`：`--prompt-file /dev/stdin` 只认真管道，Node 给子进程的 stdin 是 socketpair（直接给它报 ENXIO，法国实测）。
4. **会话用户**：Grok 的池不绑会话用户，用法国唯一的会话用户（和 Cursor 一样）。
5. **失败分流**（`packages/engine/src/failure/rules.ts`）：
   - **AU7 Grok 登录失效**（新加，排在 AU2 前面）：认「Not signed in. 」（无头模式一样凭据都没有，法国实跑）、「Run `grok login`」（令牌过期、续不上、被服务端拒、要重新登录的几种，xai-org/grok-build f0e3be1 的 `crates/codegen/xai-grok-login/src/error.rs`）、「grok login --device-code」、「Auth recovery exhausted」。整池暂停、推「要人拍」，修法写清在哪台机器以哪个会话用户跑 `grok login --device-code`；不算路由的账；下一次跑通撤掉。续期时一时连不上是「auth refresh failed: …」，不带 grok login，不在这里认。
   - **CF1** 加认「No such device or address (os error 6)」：stdin 不是真管道，是起法坏了，不是没登录。没装由起法那段 sh 报成「spawn grok ENOENT」，CF1 本来就认。
   - **MD1** 加认「unknown model id」「Couldn't set model '」：点的型号 grok 不认（法国实跑）。
   - 回话的不是点名那一代（点 grok-4.7、回 grok-4.6-build）：插头判模型不符，MD3 认。
   - 额度用满：插头按「run out of credits」「need a … subscription」这类说法认成 quota_exhausted，走 QT1。
6. **探针**（`packages/engine/src/real/route-probe.ts` 不用改）：和干活的会话同一个驱动、同一套判法。一次最小会话光系统提示就上万输入 token、扣的是 SuperGrok 订阅的额度，所以和 Cursor 一样探通了隔 2 小时再真探（`packages/shared/src/web-api.ts` 的 `ROUTE_PROBE_HOST_EVERY_MINUTES`）。
7. **装机**（`deploy/lib/grok.sh`，`france.sh` 接上）：第四节。
8. **测试**（每条失败路径故意造出来）：`packages/engine/test/real/hosts.test.ts`——起法的 sh 真跑（在、不在、不能跑、是目录，参数原样到 grok）；Linux 上真插头接真起法（提示词经真管道到 grok，开新会话、续会话，没装退出 127）；驱动拼的参数、报告的形状、会话号什么时候算数；位置和装机脚本一样。`route-probe.test.ts`、`sessions.test.ts` 的 grok 那组——探通、放慢、没登录、登录过期、没装、型号不认、回话的不是点名那一代、stdin 不是真管道、额度用满；写码会话、分诊、开 PR 前验证、副手的材料过卫生检查、续会话、换池接力、换执行方式接力。`store-ports.test.ts`：验证阶段 Luna 第一、Grok 第二时，一般的单派 Luna，碰界面的单 GPT 被硬禁令挡掉、派给 Grok。失败样本 X91–X98（没登录、型号不认、ENXIO 是法国实跑的原话）。`deploy/test/grok.test.sh`：装、查和登录态读回的判据（要 root，CI 跑）。

## 二、会话号什么时候算数

- grok 的会话号由我们定（`-s <UUID>`，续会话 `-r`），终帧回同一个号。但号是我们定的不等于会话建成了：没登录、stdin 不是真管道、没装、点的型号不认时，它在开会话之前就退出。拿这个号 `-r`，本地没有它就去服务端找，找不到报「Failed to restore session from remote: … 404 Not Found」（法国实测）。
- 工作流拿会话结局里的号续下一次（`packages/engine/src/workflows/kit.ts`：`end.sessionId` 非空就换成它）。如果没登录那一次也交回我们给的号，人登录好、点「继续」之后，下一次会去 `-r` 一个根本没建成的会话，一直失败。
- 所以 grok 的驱动开新会话时回 `known: false`：会话号照样是我们起的 UUID、库里开工就记它，但交回工作流的要等 grok 真开了会话——终帧回的号，或者没有终帧（半路被停、断了）但见到了报错以外的帧（它开会话之后才出帧，头一帧是 `available_commands`，法国真跑记录）；一帧都没有、只有 error 帧就是没开成，交回空串，下次开新会话。续会话（`-r`）照旧一开始就算数。

## 三、续会话

照 #212 的 `decideContinuation`，grok 不用加分支：同池、同会话用户、同执行方式、同一个目录、真号（UUID）→ `-r`；grok 不能 fork（它的 `--fork-session` 是同一账号下分支，换了池原会话不在那个账号下），换了池一律接力。

## 四、装机：装、登录、读回

- **装**（`deploy/lib/grok.sh` 的 `ensure_grok`）：`~/.grok/bin/grok` 不是能跑的文件时，以会话用户自己的身份把官方安装脚本 `https://x.ai/cli/install.sh` 整个下下来再跑，装完照读回的判法再核一遍；在就不动。不钉版本（docs/reference/deploy.md P33：跟最新、只留一份），也不核校验和（官方没给，安装脚本只核下下来的能跑；只以会话用户的身份跑）。
- **和派工交代不一样**：跑安装脚本时 PATH 里只有系统目录、SHELL 给 `/bin/sh`。官方安装脚本会往 PATH 上会话用户写得动的目录（`~/.local/bin`）里链 `grok` 和 `agent`——`agent` 这个名字 cursor-agent 的安装脚本也在用，会被盖掉——SHELL 是 bash、zsh、fish 还会改它们的启动文件（SHELL 空着也不行：安装脚本是 bash 跑的，bash 起来时会自己照 passwd 填上登录 shell，CI 上撞到过）。这样它只写 `~/.grok` 下面（引擎只认 `~/.grok/bin/grok`）。
- **不自己升级**：插头起 grok 时关了更新检查（`GROK_DISABLE_AUTOUPDATER=1`，免得会话半路换二进制）。要升级以会话用户跑 `grok update`（ops 第五节「会话用户的 grok」第 2 步）。
- **登录**：创始人以会话用户 `grok login --device-code` 登录一次，已经做了（法国 2026-09-27，1.0.41）。登录态是 `~/.grok/auth.json`：grok 自己写成 600、自己续期，是普通文件（不像 Cursor 交给系统钥匙串），家目录在根分区的 ext4 上，重启还在（官方随装文档 `02-authentication.md`：「Grok stores credentials in ~/.grok/auth.json and reuses them across sessions」，没给期限的按 30 天算）。不用 `XAI_API_KEY`：那是 console.x.ai 的接口钥匙，不走 SuperGrok 订阅。
- **读回**（`check_grok`、`check_grok_login`）：以会话用户照引擎的判法跑 `grok --version`，没装、跑不成、卡住、输出认不出都判红；登录态只看在不在、是不是真文件、属主、权限、大小，不读内容：还没登录记待配（写清登录的那条命令），在却不对判红。grok 认不认、续没续上期由路由探针判。

## 五、花费

走 SuperGrok 订阅，没有按量计费：用完是请求被拒（插头按额度用满认，走 QT1、整池等清零），不多扣钱。和创始人自己在 grok.com 上用的是同一份额度，所以探针放慢（第一节第 6 条）。不碰人闸「花钱」。
