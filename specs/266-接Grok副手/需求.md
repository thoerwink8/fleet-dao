# 接 SuperGrok 的 Grok 4.7：当副手，也做碰界面的单的验证（Composer 2.5 不用）（#266）

对应计划：v1 Fusion 接活
设计依据：`docs/decisions/0003-fusion-flow.md` 第 5、7、9 条；`specs/212-接第一个别家渠道/方案.md`（同一套接法）；母单 #191

创始人原话（2026-09-27）：「验证用gpt-5.6 luna，界面改单用supergrok的grok4.7」「副手也用grok4.7；composer2.5性能太差了，弃用」。当时问他的是「Cursor 先接哪几个环节、用哪个模型」。

AI 理解：
- 开 PR 前的别家验证，一般单子用 Cursor 上的 GPT-5.6 Luna。
- 碰界面的单不许用 GPT，改用他 SuperGrok 订阅里的 Grok 4.7。
- 副手也用 SuperGrok 的 Grok 4.7，这就是 v1 要接的「第一个副手渠道」（#191）。
- Cursor 的 Composer 2.5 不用（创始人：性能太差），不给它配路由。
- 本单只管 Grok 这一路。Cursor 的 GPT-5.6 Luna 那一路，是在 #212 已经接好的通道上改配置，不归本单。
- 现状：
  - 插头 `packages/adapters/src/grok/`（起命令、读输出、判型号）早就写好了，在法国实跑过；
  - 目录样例里已经有账号池 `grok`（渠道「Grok 订阅（Grok Build）」）和路由 `grok:grok-4.7:grok`，默认关着；
  - 引擎的会话端口只接了 `claude-code`、`cursor-agent`（`packages/engine/src/real/hosts.ts` 的 `WIRED_HOSTS`），遇到 `grok` 会报「没接上」。
- 做法照 #212 接 Cursor 那一套：
  - 会话端口、探针、失败分流接上 `grok`；
  - 法国给会话用户装好 grok 命令行，并确认在没有桌面的服务器上登录态能存下来；存不下就像 Cursor 那样另找办法，先查官方文档；
  - 副手阶段排第一；验证阶段排在碰界面的单要用的位置。

## 怎么算做完

- 引擎起得来 `grok` 会话：新开会话、续会话、判输出，都和 Claude、Cursor 走同一套。几种失败各配一条故意造出来的测试：没装、没登录、登录过期、型号不对。
- 法国上以会话用户装好 grok 命令行，登录态重启后还在。登录要创始人亲手做的（比如在浏览器里点批准），就停下来找他，把命令一行写好给他跑。
- 探针判 `grok:grok-4.7:grok` 在线（routes.alive）。
- 一张单的副手活派给了 Grok 4.7，交回的改动被主导验收；换它的理由写进派工记录。
- 一张碰界面的单走到开 PR 前的验证时，派给了 Grok 4.7，没派给 GPT；PR 正文写着验证是谁做的。
- 额度只记不限（创始人 2026-09-27）：SuperGrok 的额度读取接上以后在驾驶舱能看到；读不到就写「没读到」。
