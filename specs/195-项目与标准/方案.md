# 项目与标准：方案（#195）

**拍板**：创始人 2026-09-27 早上选 1——按这个方案做，排在 v1 之后。
**已做的第一步**：
- 法国跟着主线自动部署（#233）；
- 开发机开会话时自己同步规矩、技能和钩子（#234）。

**分到哪张单**：
- 项目那半归 #131–#134（design 15.7 分步①到④）；
- 机器那半归 #239。

起因是创始人 2026-09-27 的话：「这种都是属于自上而下的机制，其他项目也要能复用……有很多边界」。他举了四种情况：
1. 机器上有 fleet-dao，能不能自动同步；
2. 有 fleet-dao 但不是最新版；
3. 机器上没有 fleet-dao，想从驾驶舱在本机一键配好；
4. 给某个项目清掉同步。

|---|---|---|

## 方案

1. **标准只从主线发，带版本和签名**：
   - 每合一个改标准的 PR，机器人打一个版本 std-N，签上名，写明这版改了什么。
   - 机器和项目只认这些版本，不认谁的检出。
   - GPT 挑错时指出「机器人打个标签不等于可信」，所以要签名、验签，只打标签不够。
2. **机器那半**：
   - 每台机器上一个小工具（暂叫 `fleet std`），按版本从 GitHub 拉取、验签、安装、记账、报到驾驶舱。
   - Claude Code 走官方插件，开会话时自动更新。
   - 别家照旧写受管块，由 `fleet std` 在开会话的钩子里、每小时的定时任务里各拉一次。
   - 一份清单写清每一项归哪种装法，同一个文件不许两套都管。插件的版本也对到 std-N 上。
   - 拉不到就用上次装好的，报「没查成」，不挡干活。
3. **项目那半**：
   - 项目仓里的 `.fleet/standard.json` 写跟哪个版本（默认跟最新，可以钉住）、哪几项不要（要写理由）。
   - 能引用的引用 `@std-N`；引用不了的由驾驶舱开补齐 PR，升级也走 PR。
4. **驾驶舱看得见**：
   - 每台机器报到：哪个用户、装了哪几家 AI、在用哪一版、落后几版、哪些项目退出了、最后报到时间。
   - 每个项目显示：跟的版本、落后几版、缺哪几项、豁免了哪些和理由。
5. **退出和卸载能还原**：
   - 项目退出：一个 PR 改 `standard.json`、删掉受管的文件；机器这头看到就不管它（Claude Code 在这个项目里关掉插件）。
   - 只在某一台机器上不管某个项目：本机记一条，驾驶舱标出来。
   - 整台机器卸载：`fleet std remove`，撤掉受管块、插件、钩子，按备份还原。
6. **一键装**：驾驶舱「加一台电脑」给一行命令（PowerShell 或 bash），带一次性配对码。它下载钉住校验和的 `fleet std`，装好当前版本，登记进驾驶舱，设好自动更新。没装 node 先提示装。
7. **防坏版本**（GPT 补的）：
   - 新旧版本并排装、装完自检，原子切换；不过就自动退回上一个健康的版本。
   - 钩子连续失败自动跳过。
   - 有不依赖钩子的 `fleet std safe-mode` 和 `rollback`，断网也能用。
   - 驾驶舱能撤回某个版本，不让它继续往别的机器扩散。
8. **实验模式**（GPT 补的）：
   - 只给开发 fleet-dao 的人用，装本机检出或某个分支。
   - 记下提交号、谁开的、到期时间，驾驶舱标「未发布实验版」。
   - 这台不算合格，也不许被别的机器或项目引用。正式的账只有主线发布的 std-N 这一本。

## 各种情况怎么处理

| 情况 | 怎么处理 |
|---|---|
| 1. 机器上有 fleet-dao，能自动同步吗 | 能，而且和有没有检出无关：开会话时、每小时各拉一次发布的版本 |
| 2. 有 fleet-dao 但不是最新 | 不影响这台机器上的标准，只影响在这台机器上开发 fleet-dao；开会话时照旧快进主线 |
| 3. 没有 fleet-dao，想从驾驶舱一键装 | 「加一台电脑」给一行命令，带一次性配对码：装工具、装当前版本、登记、设好自动更新。1 分钟内驾驶舱里出现这台；没装 node、配对码过期、连不上 GitHub，都照实报错 |
| 4. 某个项目退出 | 驾驶舱里点退出（整个退出，或只退其中几项，都要写理由），给那个仓开 PR；机器看到就不管它 |
| 5. 只在某台机器上不管某个项目 | 本机记一条，不进仓，驾驶舱标出来 |
| 6. 机器离线几天 | 用上次装好的照常干活，连上自动跟上；驾驶舱标「最后报到 X 天前」 |
| 7. 有人手改了受管的内容 | 下次同步改回来，原样先备份；受管范围以外的一律不碰 |
| 8. 新装了一家 AI | 下次同步认出来就装；这家没有钩子的照实标出 |
| 9. 一台机器上有几个用户（法国） | 每个用户各装一份、各自报到 |
| 10. 整台机器不用了 | 一条命令撤干净，按备份还原 |
| 11. 开发 fleet-dao 要试没合的标准 | 实验模式：记下提交号、谁开的、到期时间，驾驶舱标「实验版」，不算合格 |
| 12. 有人冒充来源下发钩子 | 只装主线上发布、签过名的版本；插件市场只信这一个来源 |

## 推演（交 GPT 挑错前从创始人的角度走一遍）

- **装**：新笔记本 → 驾驶舱点「加一台电脑」 → 复制一行命令到终端 → 1 分钟内驾驶舱里出现这台，状态「最新」。
  - 边界：没装 node、配对码过期、公司网络连不上 GitHub → 装不成，照实报错，不装一半。
- **日常**：创始人同意一个改标准的 PR、合进去 → 机器人打 std-13 → 各机器下次开会话时、或一小时内跟上 → 驾驶舱里全部机器变「最新」。
  - 边界：某台离线三天 → 照旧用 std-12 干活，驾驶舱标「最后报到 3 天前」，连上以后跟上。
  - 边界：有人手改了受管的规矩 → 下次同步改回去并备份，驾驶舱标出来。
- **项目**：新导入一个项目 → 体检出缺 CI 和 PR 模板 → 驾驶舱开补齐 PR → 合了 → 复查通过。
  - 这个项目要退出更新日志机制 → 驾驶舱里点退出、写理由 → 开 PR → 合了以后每天复查不再报它缺。
- **最坏情况**：
  - std-13 有 bug，把所有机器的钩子弄坏，每个会话一开就报错 → 主线回退、出 std-14，各机器跟上（回退不用再问）。那几十分钟里不能干等，所以要有第 7 条的自动退回、跳过钩子和安全模式。
  - 有人冒充来源下发钩子，等于往每台机器发会执行的代码 → 第 1 条的签名，加第 12 行的只信一个来源。
- **对照**：chezmoi 一条命令装、定时拉；Renovate 升级走 PR、可以钉版本；Claude Code 托管设置能限定只信某个市场。

## 挑错（GPT，2026-09-26 晚，一轮，意见全收）

| GPT 说的 | 收没收、落在哪 |
|---|---|
| 最大的漏洞是「下发并执行代码」的信任链和自救链：打标签不等于可信签名，坏版本会随自动更新同时扩散到所有机器 | 收。第 1 条加签名和验签；第 7 条加并排装、自检、退回、断网也能退 |
| 开发 fleet-dao 的人要有明确的「开发覆盖模式」：记提交、操作者、过期时间，标成未发布实验版，不能满足正式标准，也不能被别处引用 | 收，就是第 8 条 |
| 插件和受管块并存，风险是同一条规则被注入两次、更新时序不同、卸载不完整 | 收。第 2 条：一份清单写清每项只归一种装法，插件版本对到 std-N |
| 自救必须完全不依赖坏钩子：独立的 safe-mode 和 rollback，连续失败自动跳过钩子，保留最后一个健康版本，驾驶舱撤回坏版本 | 收，就是第 7 条 |

GPT 的结论：方向对，成败在于把发布的信任、原子回滚和开发覆盖做成一等能力，不能只靠脚本约定。

## 还拿不准、做的时候再定

- **签名用哪种**：GitHub 自带的构件证明、Sigstore、GPG，还是别的。开工时照 `best-practice-first` 先查再定，写回本文件。
- **插件自动更新的时机**：Claude Code 插件开会话时自动更新，这个行为要在本机和法国实测过才算数；要是不可靠，就由 `fleet std` 的定时任务兜底。
- **旧装法退到哪天**：`agents-sync`（按家写受管块、装技能目录）是现在的装法，第 2 条的受管块就从它扩出来。本机和法国都跑通 #239 以后，退掉 `agents-sync --apply` 的人手用法，AGENTS.md、design、ops 里的旧说法一起改掉。
