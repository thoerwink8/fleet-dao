## 要什么

- `agents/skills/commander-seat/scripts/seat.mjs`：接班、续约、现查、看现状、交接（take / renew / check / show / handoff），经 ssh 调法国的 `fleet-api seat … --json`。法国的 ssh 主机名读 `~/.fleet-dao/france-ssh`（不进仓），没有这个文件就明说「这台没有登法国的钥匙，接不了班」；ssh 连不上、输出认不出一律退出码 2、说「没查成，按不是帅位算」。续约成功的时刻记在 `~/.fleet-dao/seat.json`：离上次续约成功超过租期，现查直接判不是帅位，不等法国回话。
- `claim.mjs`：工人的认领、每一步、开 PR、做完、放下，经 ssh 调 `fleet-api claim …`；库里成了再照 `doing-lib` 的写法改单上的「<机器名> 在做」评论（只给人看，是库的镜子）。认领时把 `branch.<分支>.fleetClaim = <仓>#<号>:<认领号>` 记进本地 git 配置，开 PR 时正文「认领」栏写上认领号。
- 推前钩子（`.githooks/pre-push` 多一步）：推的分支带着 `fleetClaim` 的，推之前经 ssh 查一次，认领号不是这张单现在的（作废了、改派了、放下了）就拦、写清现在归谁；连不上法国只警告、照推（真正的边界是合并闸）；没带的分支不查。
- `pnpm issue:new --local` 开单后当场替帅位认领这张单（经 ssh 调 `claim take --owner seat`），「本机做」标签成为库里认领的镜子；这台没有登法国的钥匙就明说只贴了标签、没认领。
- 演练要的一样：`fleet-api claim take --owner engine`，只在演练座位（`drill:…`）下允许，记成演练，待起补起不碰它，不起工作流。

## 怎么算做完

- 上面几样合进主线，CI 绿（技能脚本和同步工具的代码，CI 绿就合）。
- 每条失败路径各有一条故意造出失败的测试，退出码和说法对：没有 `france-ssh` 文件、ssh 连不上、输出认不出、不是帅位、过了租期、认领号对不上、推前查不到法国（只警告不拦）、推前认领已作废（拦下）。
- 本机真跑一次：演练座位 `drill:299` 上接班、认领一张演练单、报一步、做完，脚本输出和法国库里读回的对得上，读回写进这张单的结果。
