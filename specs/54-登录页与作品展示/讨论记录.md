# 登录页的几轮讨论（#54，2026-09-26）

**状态：暂停，等创始人重启。** 创始人看完第四版「飞书蓝」的最后一轮后，觉得还是不够好看，不收正式版，也不开上线 PR。

代码存在远端分支 `p2-54-login-page`，只推了、没开 PR。那里有四版登录页、飞书蓝主题、账号密码登录的前端和手机首屏测试，重启时从这个分支接着做。

## 创始人每一轮的意见

原话标「原话」，经总指挥转述的标「转述」。

1. **原话**：「驾驶舱登录页你做的太丑了，完全没有我之前提到的登录页要有创新，用你认为最佳的 UI 方式呈现；并且我希望能多支持账密登录，账密首次没有的，进入了驾驶舱有设置页；可以随时改。」
2. 看过第一批手画稿（三个静态 HTML）后，**转述**：三版长得差不多，要换成三种真正不同的风格；登录页必须手机、电脑都好用。
3. 看过第二批手画稿后，**原话**（四条）：
   - 是假的，跟真实驾驶舱登录进去后看到的样子根本不一样；
   - 三版风格几乎一样，只是换了动图；
   - 手机版适配差，要划到第二屏才能登录；
   - 「有创意」指的是三个不同的创意点子，不是同一个点子做三遍，而且效果一般。
4. 看过 a、b、c 三版之后，**转述**：想要第四版，照飞书网页版的风格来，内容用我们产品自己的。
5. **转述**：手画的假页面没问题，首页可以是假的；说的「假」是**流程假**——演示里走的步骤和真实流程对不上（比如编出来的「4 家模型一起干活」「1 次要你拍板」、每张需求都几家讨论）。
6. 看过第四版（飞书蓝）之后，**转述**：看起来不错，但美观度还不够。要加点底图、动效多一点。飞书扫码和账密登录不要靠页签切换，要像飞书客户端那样同时摆出来。
7. **转述**：选定第四版「飞书蓝」，准备收成正式版。
8. **转述（最后结论）**：仍然不够好看，暂停登录页上线。

## 已经定下的硬要求（重启时照这些做）

- **手机首屏能登录**：390×844 下不滚动就看得到飞书、账号密码两个入口；1440×900 下一屏装下。分支里有测试：`packages/web/src/login/first-screen.test.ts` 用本机 Chrome 打开假数据的打包，量入口按钮的底边，另有一条故意把按钮挪出第一屏、看它拦不拦得住的测试。目前覆盖 a、b、c 三版；飞书蓝版手机上直接摆着账号密码表单，要让测试认得这张表单。
- **流程照 `docs/design.md` 第五节那张图**：收单 → 分诊 → 拍板期 → 到点归纳方案 → 重大的才讨论、等人拍，小的直接写需求文档、推「我理解为」卡 → 规划拆子任务 → 执行 → 验证（高风险才要第二意见）→ 碰发布、花钱、删数据才等人点头 → 合并队列 → 收尾。数字和说法不编，拿不准照图上原话；「互审」「几家模型一起讨论」这类说法不用。
- **扫码用飞书官方的网页扫码登录 SDK**（QRLogin，二维码是飞书自己的 iframe），扫码拿到的 tmp_code 走现有授权回调。不放假二维码；没接上之前，只留「跳到飞书授权页」这个链接。
  - 接的时候要后端给一个地址，返回带好 state 和 PKCE 的授权链接，不能直接 302 跳走，这条接口还没做。
  - 目前仓里没设 CSP；以后要是加了，要把 SDK 脚本的域名和二维码 iframe 的域名写进白名单。
- **错误码**按统一错误体 `{ error: { code, message, details } }` 里的 code 判：
  - 401 `bad_credentials`：没这个人和密码错说同一句，不区分。
  - 429 `locked`：`details.until` 写明锁到几点。
  - 403 `recent_feishu_login_required`：提示「先用飞书重新登录一次再来设密码」，并给一个跳去飞书登录的按钮。
  - 401 `session_revoked`：跳回登录页。
  - 登录配置里读不到 `passwordLogin`，就不显示账号密码入口，不默认显示。
- **设置页**：
  - 显示设没设过密码、用户名是什么。
  - 能设、能改用户名和密码。改密码要带当前密码；还没设过、且 10 分钟内刚用飞书登录的，可以直接设。
  - 改完用响应里换上的新 Cookie 接着用，当前页不用重新登录，CSRF 令牌不变。
  - 「退出」的文案写明是所有设备一起退出。
- 飞书蓝做成主题里的一套配色，登录前后长得一致。状态字对比度要过 `lib/contrast.test.ts`，分支里已经调过、测过。看板上「远 / 中 / 近」选中那一档要改成蓝色，和别处统一。
- 登录鉴权相关的改动属于先审后合。
