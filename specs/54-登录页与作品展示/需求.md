# 登录页做成作品门面：有趣、能进演示；演示版＝同一套代码只换假数据、刷新复原；两边都不露仓名（#54）

对应计划：plan.md P2「飞书账号登录」
设计依据：design 第十四节「演示版」

起因：创始人 2026-09-25：「这个产品是简历的作品，所以有个演示页更方便理解。」「我指的是登录页有趣一点，演示页和真实驾驶舱页面肯定长得一样的。」「别暴露我的 github project name 了；演示版都是假数据，拿一些大众熟悉的形式来展示；我自己个人的，除了数据不一样，其他按道理都一样；演示版交互要做到，但是刷新就没了。」「我个人用的真实驾驶舱和演示页面，用的应该是同一套代码，这样才能持续维护。」「飞书登录演示版，就禁用功能提示一下。」

拍板（2026-09-25，最新一版以这里为准；design 第十四节「演示版」同步）：
1. 没登录打开就是登录页，要做得有意思、符合产品风格；两个入口：飞书登录（白名单）、进演示。
2. 演示版＝正式驾驶舱同一套代码、长得一模一样，只换数据：演示版把真后端放在浏览器里跑，数据放内存库；几个大众熟悉的假项目（外卖小程序、网店后台、个人博客之类）和假流程，都真能点、真改假数据，刷新或点「重来」回到最初。
3. 会离开页面或要真身份的操作（飞书登录、发到飞书、打开 GitHub）在演示版里点了只提示一句「演示版里不会真的发生」。
4. 不暴露 GitHub 上的项目：页面、标签页标题、打包产物、域名、飞书授权页上的应用名都不出现仓名、GitHub 账号名和地址；左上角两边都写「驾驶舱」，真仓名、执行方式的名字登录后从数据里来。
5. 域名和飞书应用显示名换成和仓名不沾边的，由总指挥做，不在本单。
6. 作废：「换一套不相关的名字和图标」「演示版放另一个域名」「产品名照用 fleet-dao」。

## 要什么

- 登录页：简历上的人不用登录 10 秒内看懂产品在干什么；先出 3 版不同思路的登录页设计稿（可交互的静态页 + 桌面、手机各一张截图），总指挥挑一版、给创始人看过再做。
- 品牌合一：`brand/cockpit.tsx`、`brand/demo.tsx` 合成一份中性的（「驾驶舱」），演示版只多「演示」标记和「重来」；写死在代码里的真名（执行方式名等）改成从数据来。
- 演示版在浏览器里跑真后端：`packages/api` 的驾驶舱接口（`buildApps`）+ `createMemoryStore`（种子换成演示数据）+ 变化推送（`createChangeHub`），前端用正式版的 http 客户端，请求直接交给页面里的后端，不走网络；状态只在页面内存里，刷新即复原。删掉 web 里手写的假后端（`packages/web/src/api/mock/`）。
- 演示种子：大众熟悉的假项目 + 一段假流程剧本：一个小小的假引擎经内存库让任务自己往前走，中途停在一张「要你拍板」的卡上，等看的人点一下再继续。
- 检查：一条测试在演示模式下把每个页面打开一遍，报错就红。打包扫描：正式版、演示版两份产物都扫，出现仓名、GitHub 账号名或地址、真域名（名单在本机，不进仓）就失败，故意造一条会红的测试。

## 怎么算做完

- PR 审过合进 main；需求文档放 `specs/54-登录页与作品展示/需求.md`（照本单抄）。
- 本地：没登录打开是登录页；进演示能走完一段假流程、点一次拍板；刷新复原；演示版点飞书登录只出提示；两份产物扫描对造出来的仓名判红。
- 发布到根地址（换掉现在根地址上的旧演示版）是对外发布，先给创始人看过再发。
