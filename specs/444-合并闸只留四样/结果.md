# 结果：合并闸只留四样（#444）

## 做成什么样

- 合并闸（`packages/conventions/src/merge-gate.ts`、`merge-gates.ts`）判红只留：草稿、和主线冲突、改到先审后合的路径而当前头上没有通过的 second-opinion；必填栏只提醒。「挂了单要有引擎机器人贴的、通过的『认领对得上』」（#348）、「写了关单却没带那张单的结果.md」（#325）这两项从判红里去掉——`gatePr` 不再算「挂的是哪张单」、不再读 claim-match 状态，也不再调 `close-rule.ts` 的 `closingTargets`/`missingResults`。合并闸只报「合并闸自己」的那一份原因，其余留给每天的关单对账事后发现。
- `merge-gates.ts` 删掉了 `ClaimMatchStatus`/`claimMatchFrom`/`checkClaimMatch`（只有合并闸自己用，没有别处引用，直接删）；`ENGINE_BOT_LOGIN`、`CLAIM_MATCH_CONTEXT` 两个常量搬去了 `pr-columns.ts`——这两个常量本身还在用（`packages/api/src/claim-status.ts` 认领贴状态、`packages/api/test/fake-claims-github.ts` 等测试都在引），只是不该再算进「合并闸自己的判法」；挪走之后 `pr-columns.ts`、`close-rule.ts` 也不再在合并闸的先审后合清单里（两处相对导入都从 `merge-gate.ts` 里去掉了），`packages/conventions/high-risk-paths.json` 同步去掉这两个文件的条目，改了 `merge-gates.ts` 那条的理由。
- `.github/workflows/merge-gate.yml` 的 `status` 事件触发条件去掉「认领对得上」，只在 `second-opinion` 状态写上来时才重算所有开着的 PR（合并闸不再读这个状态，不用再为它重算）。
- 引擎因为合并闸连红停下的原因（`packages/engine/src/workflows/fusion.ts` 的 `GATE_ONLY_RED_LIMIT` 分支）以前写死猜测文案「多半是别的原因（认领对得上、关单要带结果……）」；现在原样带出合并闸自己贴的说明（`ci.digest`，即被判失败的那个检查的名字加它自己的 description），读不到时明说「没读到状态说明」，不再瞎猜。`packages/engine/src/jobs/github-app-check.ts` 里一句提醒文案也改了同一处：statuses:write 缺失时不再说「合并闸会一直等它」（合并闸的状态是 GitHub Actions 用 `GITHUB_TOKEN` 写的，跟引擎的 App 权限没关系；真正受影响的是 second-opinion 和「认领对得上」两条引擎机器人自己贴的状态）。
- design 第五节「合并闸」「发现问题当场修」第 5 条、「认领对得上」bullet 里提到合并闸的那几句，第七节「关单要有结果」，README、PR 模板里对应的提示都改成了新说法；不改 AGENTS.md（帅位另外统一改）。

## 发现的一个缺口（没有在这张单里补，写下来留给帅位定）

「这个 PR 做完就关单」填「是」却一个关单词（Closes/Fixes/Resolves）都没写：GitHub 不会关那张单，单子留着开。以前合并闸会直接挡住这种 PR；#444 之后没人挡了，而且这个具体情形现在的每天关单对账（`close-sweep.ts`）也捞不到——它只查「已经关掉却没结果」和「开着、有结果文档、没有 PR 在引用」两种，这里单子既没关、也没结果文档，两条都够不着。已经在 `docs/design.md` 第七节里把这句写实了（不是编的「反正有对账兜底」），要不要单独补一条对账规则，请帅位看着办、决定要不要开单。
