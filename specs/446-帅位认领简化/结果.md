# 结果：帅位只记现在是谁、认领账只留记录（#446）

## 做成什么样

边界按创始人同日追问后定的那条（需求.md「要什么」第一条）：只删拦人、催人的，给人看的都留着，数据一行不删。

- **帅位（`seat.mjs`/`fleet-api seat`）**：删了 `renew`、`check` 两个子命令，没有租约、没有续约、没有受保护动作前现查这回事了。`seat take` 永远成功、后说的算；换了人，旧帅位下次自己 `seat show` 看到就退，不是系统判的。保留 `seat take`/`show`/`handoff`/`board`。`seat_leases` 表不删（`term` 只增不减但不再是栅栏号；`renewed_at` 列名没改，语义改成「最后活动时间」，只给人看）。
- **最后活动时间（新加，K8s Lease `renewTime` 式）**：加了 `lastActivityAt`——真实写动作（take/handoff/board 写）才顶新，`show`/读操作不顶。CLI（`seat show`）和驾驶舱帅位栏都显示它。`packages/shared/src/web-api.ts` 的 `SeatBoardResponse` 加了 `seat: {term, holder, lastActivityAt} | null`；`packages/web/src/board/seat-bar.tsx` 顶部新加一行「帅位：第 N 任 谁，最后活动多久前」（没人接过班显示「帅位：还没人接班」）。
- **认领账（`issue_claims`）**：留作记录（`claim.mjs`/`fleet-api claim`），删的是拦人的部分——心跳宽限期自动作废（`claim sweep` 整个删了，命令、定时任务都没有了）、推前钩子查认领（`.githooks/pre-push` 现在只跑卫生检查）、引擎在 PR 上贴「认领对得上」（`claim-status.ts` 整个文件删了，`packages/github/src/claims.ts` 留着，second-opinion 还在用同一套读写 GitHub 的接口）。改派（`claim reassign`、`handover`）不再要创始人原话：`force` 一个参数就决定改不改派，`founder` 降级成纯记录用的一句话注解；改派也不再碰 GitHub——旧工人开着的 PR 原样留着，要收尾自己关（行为变化，SKILL.md 里写实了）。
- **认领的默认宽限期**：`settings` 表的 `seat.leaseMinutes`、`seat.claimGraceMinutes` 两个配置键不再读；认领行的 `graceMinutes` 列还在（NOT NULL），新认领填 core 里的常量 `DEFAULT_CLAIM_GRACE_MINUTES`（120，纯记录）。
- **分工**：单标签「本机做」＋ `localGate`（`packages/core/src/dispatch.ts`）不变，这条本来就是止血机制，#446 没有改它，确认它和自己的「故意造出的失败」测试仍然通过。
- **迁移**：没有加迁移，没有删列、删表——`seat_leases`、`issue_claims` 两张表原样在，只是应用代码不再拿 `graceMinutes`/`heartbeatAt`/旧任期号做判断依据。
- **一个真的 bug**：写这次改动时发现 `seatTerm: term ?? null` 在 `--term` 变成可选之后会撞上 DB 约束 `issue_claims_seat_shape`（`seatScope` 非空时 `seatTerm` 也必须非空）；改成沿用 drill 认领已有的哨兵值 `0`（`pgSeatStore`、`memorySeatStore` 两处都改）。
