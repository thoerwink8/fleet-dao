# 结果：帅位只记现在是谁、认领账只留记录（#446）

## 做成什么样

边界按创始人同日追问后定的那条（需求.md「要什么」第一条）：只删拦人、催人的，给人看的都留着，数据一行不删。

- **帅位（`seat.mjs`/`fleet-api seat`）**：删了 `renew`、`check` 两个子命令，没有租约、没有续约、没有受保护动作前现查这回事了。`seat take` 永远成功、后说的算；换了人，旧帅位下次自己 `seat show` 看到就退，不是系统判的。保留 `seat take`/`show`/`handoff`/`board`。`seat_leases` 表不删（`term` 只增不减但不再是栅栏号；`renewed_at` 列名没改，语义改成「最后活动时间」，只给人看）。
- **最后活动时间（新加，K8s Lease `renewTime` 式）**：加了 `lastActivityAt`——真实写动作（take/handoff/board 写）才顶新，`show`/读操作不顶。CLI（`seat show`）和驾驶舱帅位栏都显示它。`packages/shared/src/web-api.ts` 的 `SeatBoardResponse` 加了 `seat: {term, holder, lastActivityAt} | null`；`packages/web/src/board/seat-bar.tsx` 顶部新加一行「帅位：第 N 任 谁，最后活动多久前」（没人接过班显示「帅位：还没人接班」）。
- **认领账（`issue_claims`）**：留作记录（`claim.mjs`/`fleet-api claim`），删的是拦人的部分——心跳宽限期自动作废（`claim sweep` 整个删了，命令、定时任务都没有了）、推前钩子查认领（`.githooks/pre-push` 现在只跑卫生检查）、引擎在 PR 上贴「认领对得上」（`claim-status.ts` 整个文件删了，`packages/github/src/claims.ts` 留着，second-opinion 还在用同一套读写 GitHub 的接口）。改派（`claim reassign`、`handover`）不再要创始人原话：`force` 一个参数就决定改不改派，`founder` 降级成纯记录用的一句话注解。**改派掉人的 PR 原样留着**，要收尾自己关；**改派掉引擎的例外**：工作流叫停成了（或已经不在了）就跟着关它登记过的 PR（撤自动合并、留言，分支留着）——第二意见指出这条是 `specs/169-Fusion形态/需求.md`「删减清单全按帅位的做」第 1 条第 5 点里 GPT 两轮标了不能删、创始人收了的例外（引擎不是人，不算「拦人」），第一版实现把它和人对人那条一起删掉了，是回归，已按第二意见改回来（`seat-cli.ts` 的 `reassign`、新的 `ClaimCliDeps.closeEnginePr`，`cli.ts` 新增 `openClaimsGitHub` 懒连接）。
- **认领的默认宽限期**：`settings` 表的 `seat.leaseMinutes`、`seat.claimGraceMinutes` 两个配置键不再读；认领行的 `graceMinutes` 列还在（NOT NULL），新认领填 core 里的常量 `DEFAULT_CLAIM_GRACE_MINUTES`（120，纯记录）。
- **分工**：单标签「本机做」＋ `localGate`（`packages/core/src/dispatch.ts`）不变，这条本来就是止血机制，#446 没有改它，确认它和自己的「故意造出的失败」测试仍然通过。
- **迁移**：没有加迁移，没有删列、删表——`seat_leases`、`issue_claims` 两张表原样在，只是应用代码不再拿 `graceMinutes`/`heartbeatAt`/旧任期号做判断依据。
- **一个真的 bug**：写这次改动时发现 `seatTerm: term ?? null` 在 `--term` 变成可选之后会撞上 DB 约束 `issue_claims_seat_shape`（`seatScope` 非空时 `seatTerm` 也必须非空）；改成沿用 drill 认领已有的哨兵值 `0`（`pgSeatStore`、`memorySeatStore` 两处都改）。
- **第二个真的 bug（PR 开出来之后现场撞上的，帅位报的）**：`seat-lib.mjs` 的 `pickState`——本机记着「我是谁」的文件不带 `--session` 时，按「这个座位只有一份」猜是谁在问；09-28 19:00 左右另一个会话没带 `--session` 查，这台上只有别的会话留的记录，就被当成了那个会话，误以为自己是帅位。根因是「只有一份」和「问的就是那一份」是两回事——哪怕真只有一份，问的人也可能是台上从没 `take` 过的第三个会话。改法：`seatHandoff`、`claimTake`、`claimReassign`、`p.mjs handoff`（board-cli.mjs 的 `seatOf`）这几处算身份判断的一律要求显式带 `--session`、不给就退出码 1 明说「要带 --session」，不再兜底猜；`p.mjs` 其余报进度的命令（`head`/`add`/`step`/`log`/`link`/`needs`/`show`/`pending`/`record`）不算身份判断，仍旧可以不带（这一层本来就不核是不是现任，写错了顶多是进度栏挂错名字，不是「以为自己能接活」那种事故）。连带修了 `runSeat` 的 `handoff` 分发漏了 `await`（`return seatHandoff(...)` 没等，`seatHandoff` 里的 `UsageError` 会变成没接住的 rejection 而不是退出码 1）——这条以前就有，只是没有测试走到 `seatHandoff` 同步抛错的路径，这次加严 `--session` 校验后第一次被踩中。
