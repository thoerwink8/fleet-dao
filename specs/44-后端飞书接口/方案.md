# 方案（#44）

## 怎么做

- **数据**：四张新表（`packages/db/src/schema/feishu.ts`，迁移 `0004_feishu`）：草稿、关注、推送的送达状态、卡片登记。收到的话（按飞书消息编号）和卡上「改一下」（按请求编号）的幂等记录放现有的 `idempotency_keys`，和草稿同一事务写。
- **门**：九条接口在 `packages/api/src/feishu-routes.ts` 按 `FeishuRoutes` 逐条挂，方法、路径、acting 都取自表；只认网关通行证，acting=required 的认出是哪位创始人（操作记录 via=feishu），none 的只验通行证。驾驶舱那道门（`session.ts`）对网关通行证只放行 `FEISHU_GATEWAY_WEB_ROUTES` 三条，表里没有的 403——约定本来就这么写，原来的实现漏了（通行证能调驾驶舱全部接口）。
- **一句话**：还没接模型理解，按原话记草稿、标拿不准；只有一个仓、或原话里恰好提到一个仓名，就放那个仓。回复某张卡按卡片登记分流：草稿卡 = 改理解；AI 追问卡 = 回答（和驾驶舱回答同一条路：写库、叫醒等着的 `fleet ask`、发信号）；要人拍的卡只算追问；别的卡如实说「还答不了」，不编。
- **确认 →「待开单」**：记下确认人和仓，当场调一次开单（`TaskIntake`：开 issue、建任务行、拉起需求工作流），8 秒内开成就把任务号带回卡上；没成就记下原因，留在「待开单」，后端每分钟补开一轮（按次数退避，最多隔 30 分钟；进程刚起来全试一遍）。
  - 为什么不在确认时就建 `tasks` 行：`tasks.issue_number` 必填，约定里草稿的 `task` 也要 issue 号；issue 没开出来就没有号。所以「待开单」记在草稿上（确认了、还没 `task_id`），任务行由开单那一步建——它和接活入口（#43）按「仓 + issue 号」共用一行，不会建两行。
- **待推送不另存一份队列**：推什么从源头现算——没答的和最近答过的追问（`ask:<编号>`）、没处理的和最近处理过的通知（`notification:<编号>`，要人拍 / 卡住 / 日报）。`feishu_outbox` 只记「第几版、这版内容的指纹、回执到哪一版、上次送到哪张卡」；内容一变指纹就变、版本加 1，网关按版本原地改卡。这样引擎照常写 `asks`、`notifications` 就会推到飞书，不用另调接口，也不会有「写了库、忘了进队列」。
  - 待推送 = 当前这一版没收到「发了 / 改了 / 不发了」，也不在推迟、没发成的等待期内（到点再多等 2 秒，防两台机器的钟差一点）；已经了结、又从没发过卡的不给。
  - 回执按条处理：认不出的跳过并记日志，不让整批 4xx；旧版本的「发了 / 改了」只记下送到的卡；回执没记上时按卡片登记里的 `ref.outboxId` 补「上次送到的卡」；通知类的回执同时写进通知的送达记录（驾驶舱「通知」页）。库写不进就 500，网关留着下次再送。
  - 长轮询：追问、通知、需求有变化就醒，另每 3 秒回库看一眼（别的进程写的不一定叫得醒）。免打扰时段读驾驶舱设置，设过却读不懂就 500，不当成「不设」。
- **盘面**：从库里算——在干（没结束、没卡住的需求，带「此刻在干什么」）、卡住（需求或子任务卡住，最久的在前，写明卡在哪）、等你们（没答的追问 + 没处理的要人拍）、今天合并（北京时间今天进入「已合并」的子任务）、快清零还剩不少或快用完的额度（读数太旧的不上）、最新登记的盘面卡。
- **关注**：只存谁关注了哪个需求（取消只改标记，不删行）。
- **网关顺手改一处**：确认了、issue 还没开出来的草稿卡，原来会退回成带「确认」按钮的样子；改成「已确认，正在开成任务」（`packages/feishu/src/cards.ts`）。

## 谁来接

- **开单的真实现**：接口 `TaskIntake`（`packages/api/src/ports.ts`），由 #28（引擎接 GitHub 与 Temporal）/ #43（接活入口）的作者接，在 `packages/api/src/main.ts` 把 `notWiredTaskIntake()` 换掉。要求：按草稿编号幂等（确认和补开可能同时来）；开 issue（机器人写，贴类别标签和里程碑）、建或复用「仓 + issue 号」的任务行、拉起需求工作流；交回任务编号和 issue 号；没接上或暂时不通抛 `IntakeUnavailableError`。接上之前确认的草稿都在「待开单」里，接上后自动补开。
- **关注的推送**：到关键节点（方案好了、PR 开了、合并了、卡住了）私聊推给关注的人，要引擎报出关键节点；推送条目按 `follow:<需求>:<open_id>` 加进待推送的源头即可（`composeOutbox`）。
- **要人拍的卡上的按钮**：网关按追问回答（`askId` + 选项）；引擎那边的人闸批准记在 `approvals`（#28），不是追问，所以现在这类卡只有「打开驾驶舱」。两边对齐后在 `composeOutbox` 里给要人拍的条目带上回答的去处。
