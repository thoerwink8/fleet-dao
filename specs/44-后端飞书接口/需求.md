# 后端实现飞书网关的 9 条接口：群里说的话记成草稿、确认建任务、盘面与推送（#44）

对应计划：plan.md P4 的香港网关一条。
设计依据：design 15.4（飞书）。

## 起因

2026-09-25 创始人在「fleet 总控」群 @ 机器人，收到「这句话没记成；后端一直没响应」。查下来：香港网关好好的，但法国后端**网关要调的 9 条接口一条都没实现**——约定写在 `packages/shared/src/feishu-api.ts`（`FeishuRoutes`），后端 `packages/api` 只做了网关通行证的认证。就算把 fleet-api 起起来，机器人也只会从「没响应」变成「404」。

## 要什么

按 `FeishuRoutes` 的约定把 9 条接口在后端实现，数据都落 Postgres：

- `POST /feishu/messages`：一句话记成草稿。第一版可以不接模型理解，按原话记、标 `unsure`（约定允许），确认卡照常出。
- `POST /feishu/drafts/:draftId/revise`、`/confirm`：改草稿、确认。确认后建任务行；开 issue、拉起需求工作流要等 #28 的引擎和 GitHub 接好，在那之前记成「待开单」，接好后自动补开，不丢。
- `GET /feishu/tasks`（按 issue 查）、`POST /feishu/follows`（关注）。
- `GET /feishu/board`：盘面快照，从库里算。
- `GET /feishu/outbox`、`POST /feishu/outbox/acks`：待推送队列和回执。
- `PUT /feishu/cards/:messageId`：卡片登记。
- 每条接口：参数认不出、库读不到、状态冲突都返回约定里的明确错误，不返回空列表或 ok 冒充；每条这样的路径有故意造出来的测试。

## 怎么算做完

- PR 审过合进 main；需求文档放 `specs/44-后端飞书接口/需求.md`（照本单抄），方案、结果写同一目录。
- 本地：用网关的真客户端代码（`packages/feishu`）对着后端跑一遍：记一句 → 确认 → 查任务 → 关注 → 盘面 → 推送与回执 → 卡片登记，全通。
- 法国：随 #28 上线后，创始人在总控群 @ 机器人说一句，收到确认卡，点确认后库里有任务。
