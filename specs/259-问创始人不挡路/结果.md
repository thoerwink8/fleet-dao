## 做了什么

PR #456：

- **退回重问到数不再停**（`packages/engine/src/workflows/kit.ts` 的 `stageLoop`）：会话 `fleet blocked --needs human|info` 被退回带推荐重问 `reaskRounds`（默认 2）次，到数了还说要人的，原来一律 `askAndWait` 发卡停下等；现在先看会话这次报卡住到底写没写点什么（`blocked.question ?? blocked.reason`，新函数 `assumedFromBlocked`），写了就当它自己的推荐或假设，续着同一个会话往下跑（塞进 `brief.answers`，会话看到「答案」接着干）。
- **记进 PR 正文和照常发卡片**：这一条记进新加的 `kit.assumedNotes`（不经 `fleet ask`、`asks` 表里没有这条，`assumedLines` 读不到），Fusion 开 PR 时并进「按推荐先做了」一栏（`fusion.ts` 的 `doOpenPr`）；同时 `raiseAlert` 发一张「已按推荐先做」的提醒（驾驶舱、飞书按现成的提醒机制收到）。
- **一个字都拿不出才走失败梯子**：`assumedFromBlocked` 传空字符串（`question`、`reason` 都没有实质内容）回 `null`，这一步不再假装按推荐放行，落到现成的失败分流（`judge(kit, 'failure', ...)`，新码 `BLOCKED_NO_ASSUMPTION` 认不出规则表、走兜底梯：重试 → 换路由 → 换模型 → 挂起报警），不无限重试——这是和分诊说不清（`triage.ts`）不一样的地方：分诊好歹有一份「AI 理解为」兜底，会话明说卡住却什么都拿不出时没东西可接，换一条路由或模型更可能有用。
- **仍然照旧停下等的只有三类**：`--needs access`（只有创始人本人才有的东西）继续只挡那一块；碰人闸四类（`--hold`）的机制完全没碰，继续只挡合并那一步；安全边界（密钥、登录鉴权、CI 工作流、卫生检查）不在这次改动范围内。
- **重放安全**：新分支包在新的 `patched('blocked-proceed')` 里，`patched('blocked-reask')` 的调用位置和改动前一字不差（没有抽成变量吃掉短路求值，否则到数那一轮会多问一次，`packages/engine/test/replay.test.ts` 会拦下来）；老执行重放照原样落到 `askAndWait` 停下等人。
- **文档**：`docs/design.md` 第五节「没人拍板」、`docs/decisions/0003-fusion-flow.md` 第 5 条改成这套说法；`packages/engine/src/limits.ts` 的 `reaskRounds` 注释一起改。没碰 AGENTS.md（帅位另外统一改）。
