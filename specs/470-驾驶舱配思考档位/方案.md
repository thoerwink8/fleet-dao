# 方案：驾驶舱按模型配会话的思考档位，默认 high（#470）

## 现状（2026-09-28 读代码）

- 帅位的启动器 `agents/skills/commander-seat/scripts/worker-lib.mjs` 自己有一份 `EFFORTS`、`DEFAULT_EFFORT = 'high'`，只认命令行 `--effort`。
- 引擎起会话（`packages/engine/src/real/sessions.ts` 拼 `HostRunSpec`，`hosts.ts` 按执行方式转给插头）**根本不传档位**：Claude 用它自己的默认，grok 用它自己的默认 xhigh（正是创始人看到的那个）。需求里「引擎的会话由各自路由里写的档位定」不准确，路由表里没有档位。
- 插头已经会传：Claude `effort`（`--effort`）、grok `reasoningEffort`（`--reasoning-effort`）、Mirasim `effort`；cursor 没有档位参数。
- 「以后都这么跑」的配置按 0003 第 9 条放在仓里的流程配置：全组织默认 `packages/core/flow.default.json`、项目 `.fleet/flow.json`，格式和合并在 `packages/core/src/config.ts`；引擎对账每 15 分钟同步进库里的副本（`repos.flow_config`），起会话前看副本（`engine/src/real/flow-gate.ts`），认不出就停派、报提醒。档位是「规则」类（specs/169 第 127 行的四类），就放这里——这就是「启动器和引擎从同一处读」的那一处，不另起一份文件、不进路由表（路由表在不进仓的目录配置里）。
- 驾驶舱还没有「改流程配置开 PR」的通道（design 第九节说派单页是流程配置的编辑器，但还没做）。本单把这条通道做成通用的，档位是第一个能改的字段。

## 做法

### 1. 配置格式（core）

- `config.ts` 的 `optionalFields` 加 `efforts`：`z.record(模型 id, z.enum(['low','medium','high','xhigh']))`，键是目录里的模型 id（和 `steps` 里写的一样，如 `opus-5.5`、`grok-4.7`）。全组织默认和项目都能写，合并时按键覆盖（项目写的盖全组织默认的）；`FlowConfig.efforts` 永远是个对象。
- 导出 `EFFORTS`、`DEFAULT_EFFORT = 'high'` 和 `effortFor(config, modelId)`：配了用配的，没配用 high。值写错（`max`、`XHIGH`、非字符串）在解析时就被拒，走现有「认不出 → 停派、报提醒」，不会悄悄当 high。
- `flow.default.json` 显式写 `"efforts": {}` 并在说明里写一句默认 high 的来历（创始人 09-28 拍）。不改模型顺序、禁令，不算改标准。

### 2. 引擎起会话带上档位

- `db` 的 `TaskContext.repo.flow` 已带副本整份配置；`flow-gate.ts` 加 `sessionEffortOrStop(task, modelId)`：副本不能用（`replicaVerdict`）就抛 `CONFIG_MISSING`，副本里 `efforts` 形状认不出（旧副本、被手改）也抛，不当 high。
- `HostRunSpec` 加 `effort`（干活的会话必填；探针不带，保持最便宜）。`sessions.ts` 用 `route.modelId` 取档位；会话元数据（`metaOf`/session meta）记下这次的档位，接回时照原样。
- `hosts.ts`：Claude → `effort`，grok → `reasoningEffort`，Mirasim → `effort`；cursor 不支持，不传（元数据记「不支持」，不假装传了）。

### 3. 启动器读同一处

- `worker-lib.mjs` 不再自己定默认：`start` 时读目标仓默认分支的 `.fleet/flow.json`（`git show origin/<默认分支>:.fleet/flow.json`，文件不存在＝项目没写）和 fleet-dao 主线的 `packages/core/flow.default.json`（`gh api` 读），按同样规则合并取 `efforts[模型 id]`，没配 high。模型 id：`--model-id` 给了用它，不给按 grok→`grok-4.7`、codex→`gpt-5.6-luna`。
- 读不到（git/gh 出错、JSON 坏、档位值不认得）一律退出 2、不起会话；`--effort` 保留作单次覆盖（「指令」类，记在 meta 里，status 标出是覆盖的）。
- 技能说明 SKILL.md 不动（没写档位，不碰改标准）；worker-lib 文件头注释照新做法改。

### 4. 驾驶舱改档位 → 开 PR 自动合

- `packages/github` 加通用的 `proposeFileChange`：从默认分支头建分支 `fleet/flow-config-<时间戳>`、在分支上写文件（contents API，写前过 `assertPublishable`）、开 PR、`enablePullRequestAutoMerge`（squash）。不直写主线。
- `packages/api` 加 `PUT /api/projects/:repoId/flow/efforts`（带 `{ model, effort | null }`，null＝删掉这一项回到默认）：读项目默认分支的 `.fleet/flow.json`（没有就新建 `{formatVersion:1}`），只改 `efforts`、其他字段原样保留，改完用 core 的 `ProjectConfigSchema` + `resolveFlowConfig` 和全组织默认一起校验，过了才开 PR；回 PR 号和链接。要登录，只有项目主人能改；同一个项目已有开着的档位 PR 就在它上面续写，不开第二个。
- `packages/web` 派单页（`routes/dispatch.tsx`）加「思考档位」一块：列出这个项目流程配置里出现的模型，显示当前生效的档位（来自副本，标「默认 high」还是「项目配的」），下拉改；改完显示「已开 PR #n，合并、同步后下一个会话生效」和在途 PR。mock 数据同步加上。
- 驾驶舱没有权限写仓（App 没装、没写权限）照实报错，不假装改成了。

### 5. 文档

- `docs/design.md` 第九节流程配置那段加一句 `efforts`、默认 high、驾驶舱改走 PR。

## 验证

- core：`effortFor` 没配给 high、项目盖全组织默认；`efforts` 写错值 / 写成数组时 `resolveFlowConfig` 判认不出（故意造出失败）。
- engine：改副本里某模型的档位后，下一个起的 Claude 会话命令行带 `--effort <新档>`、grok 带 `--reasoning-effort <新档>`（用 `hosts` 的假 runner 截参数）；副本 `efforts` 坏了起会话抛 `CONFIG_MISSING`、不登记会话（故意造出失败）；探针不带档位。
- worker：配置里 `grok-4.7: medium` → 命令行 `--reasoning-effort medium`；没配 → high；`.fleet/flow.json` 坏 JSON、`gh api` 失败、档位值不认得 → 退出 2 且没 spawn（各一条）。
- api：PUT 后 github 假实现收到分支、文件内容（只改了 efforts、其它字段不动）、开 PR 和自动合并；值不合法 400、不开 PR；读仓失败 502、不开 PR。
- web：派单页组件测试：显示生效档位，改了发请求、显示 PR 号。
- 本机只跑 `pnpm test:changed` 和类型、格式检查；全量交给 CI。

## 不做的

- 不给探针配档位；不改路由表、目录配置；不做「按阶段配档位」（需求只要按模型）。
- 单张单临时换档位（「指令」类）不在本单：需要时另开单。
