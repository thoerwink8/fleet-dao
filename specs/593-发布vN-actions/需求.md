## 怎么算做完

- 测试（vitest，packages/conventions/test/）：
  - 开「发布 vN」PR 的 CLI：mock `gh` 回 PR 号 → 拿到 PR 号；mock 没有 GITHUB_TOKEN → 明确失败、不伪造 PR 号。
  - release.yml 触发过滤：**head 是 release/v<N>、base 是 main、merged=true → proceed**；merged=false（发布 PR 关上了）→ noop 不动作也不算错；**head 是普通 feat/… → noop**（仓里一天到晚合的是普通 PR，每张都红一次会让 Actions 红到看不见真问题）；**head 带 release/ 但版本号模样不对（release/vNext）、或 base 不是 main → error**（想走这条线但走错了，发起人要看一眼）。判定在 `packages/conventions/src/publish.ts` 的 classifyPullRequestClosed。
  - `nextState`、`planFinalize` 各半截状态照已有用例跑通；在错的顺序下不让走。
  - 核心 Bash 判定从 release.yml 抠出来进 `packages/conventions/src/publish-release-logic.ts`：pickOpenMilestone 词边界（v1 不撞 v10、撞多张拒绝）、extractReleaseBody（找不到标题/正文空/只剩占位「还没有」都拒绝）、飞书幂等标记（appendFeishuNotifiedMark/feishuAlreadyNotified）。每个失败分支都配一条故意造出的失败。
- 故意造出的失败，每条一个测试：打 tag 已存在 → 跳 tag、其余照走；建 release 失败 → 不关 milestone、不通知。
- 真机：下一个版本收尾时本单自证——「发布 vN」PR 合并 → Actions 出 tag、出 release、关 milestone、飞书一条；半截失败时 milestone 没关；状态能在 Actions 日志里看见。
