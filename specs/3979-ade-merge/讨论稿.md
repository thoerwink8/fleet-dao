- 状态：讨论中
- 起因：需求方 2026-11-15 提了：fleet-dao 和 fleet-ade 能不能合二为一；以后驾驶舱的形式往 ADE 靠
- 范围：查了两个仓的模块、大小、工具链、CI 用时、仓类型判定、驾驶舱现有页面、ADE 现有页面和服务端模块、总单 #3979 整体思路第二、三节、相关决定（0039、0042、0081、0090、0101、0108、0124、0125）。没查：法国库里的登录记录、法国机余量、驾驶舱各读接口认不认机器通行证、t3code 网页能不能挂在子路径下。
- 怎么查的：读代码和文档；`git ls-files` 数文件和行数；`gh run list` / `gh run view` 读 CI 用时；在 fleet-ade 上只读地跑仓类型判定和 `repo:check`。证据标实测 / 按代码 / 推断。
- 代码版本：`79a36db03`（fleet-dao）；`93a9fa0fd`（fleet-ade）

## 一、提出的问题

### 1. 两个仓能不能合二为一

**结论：产品上合成一个，仓不合。** ADE 当唯一的操作界面，驾驶舱的功能做成 ADE 里的页面；引擎、驾驶舱后端、规矩、技能、钩子、检查留在 fleet-dao，当后端服务和规矩来源（下面的做法 C）。

**现状：两边各有什么**

| 模块 | 仓 | 跑在哪 | 谁在用 | 和对面重叠吗 |
|---|---|---|---|---|
| 引擎 `packages/engine`（约 19.5 万行） | fleet-dao，公开 | 法国 | 自动拉单、派活、合并、发版 | 不重叠 |
| 驾驶舱后端 `packages/api`、`db`、`store`（约 11.8 万行） | fleet-dao，公开 | 法国，经香港对外 | 创始人的网页；各机器用机器通行证上报会话、租约、开单（`packages/api/AGENTS.md:22`） | 不重叠；ADE 只该经接口读写它 |
| 旧驾驶舱 `packages/web`（约 10.2 万行） | fleet-dao，公开 | 驾驶舱域名首页，手机当 PWA 用 | 创始人（决定 0042，后端白名单，`packages/api/src/auth.ts`） | 和 ADE 界面重叠：它看法国的单，ADE 看本机的会话 |
| 新驾驶舱 `packages/harness-web`（约 1.4 万行，已冻结） | fleet-dao，公开 | 域名 `/next/`（`deploy/hk/nginx-https.conf:92`）和本机桌面 | 试用 | 和 ADE 界面大块重叠 |
| 本机 ADE 后端 `packages/harness-dispatch/src/ade`（已冻结） | fleet-dao，公开 | 本机 | 试用 | 和 t3code 服务端大块重叠（git、终端、账号、额度、ssh） |
| 桌面外壳 `apps/desktop`（Tauri） | fleet-dao，公开 | 本机 | 试用 | 和 ADE 自带的 Electron 壳重叠 |
| 规矩、技能、钩子 `agents/` 加 `agents-sync`（约 5.2 万行） | fleet-dao，公开 | 每台机器 | 所有会话，包括在 fleet-ade 里干活的 | 不重叠 |
| 检查和 pnpm 命令 `packages/conventions`（约 7.5 万行） | fleet-dao，公开 | 本机和 CI | fleet-dao 的每个 PR | fleet-ade 有自己的一套（oxlint、vp、`ui-no-english`） |
| 新 ADE：网页、服务端、各家智能体接入 | fleet-ade，私有，含 MIT 第三方代码和许可 | 本机，只听 127.0.0.1:3773 | 创始人试点；主入口仍是 mirasim | — |

规模（实测，`git ls-files`）：fleet-dao 4389 个文件，ts/tsx/rs 约 66 万行。fleet-ade 30192 个文件，`apps` 加 `packages` 约 163 万行 TS，另有 `.repos/` 24120 个文件（Effect 参考源码）。

几块重叠：
- **会话管理**：fleet-dao 有法国引擎的会话（任务页、单次会话页）和本机会话上报（`/api/nodes/sessions`）。ADE 有会话列表、编排、子任务（`apps/server/src/mcp/OrchestratorMcpService.ts`，按代码）。
- **渠道和额度**：fleet-dao 有额度读数（`packages/adapters/src/quota`、`quota_windows` 表）、选路和渠道状态页。ADE 底座有额度页（`apps/web/src/routes/_chat.usage.tsx`），只读各家自己的数。整体思路第 4 条已定：额度读 fleet-dao 的。
- **旁观提醒**：两边都没有，整体思路第 5 条排在后面。
- **多机协作**：fleet-dao 有本机领单租约（`/api/nodes/claims`）、法国页机器表。ADE 有机器互连和 ssh（`apps/server/src/peer/`、`packages/ssh`、`packages/tailscale`，按代码）。

**几种做法比较**

| | A：fleet-ade 并进 fleet-dao | B：驾驶舱和引擎搬进 fleet-ade | **C：两个仓，产品合一（推荐）** | D：C 再把 fleet-ade 改公开 |
|---|---|---|---|---|
| 要动什么 | 私有代码和历史并进公开仓；fleet-dao 从 pnpm 11 升 12、Node 22 升钉死的 26（两边 `package.json`，实测），法国引擎环境跟着升；检查要么扫整个 ADE，要么开口子 | 引擎、后端、库、检查约 34 万行搬进 Effect 写法的私有仓；部署链重写；法国发版改等私有仓 CI | fleet-ade 认成自用仓、换本仓协作约定；ADE 里加驾驶舱页面，经接口读 fleet-dao；旧驾驶舱逐页冻结，最后删 | 同 C，另先给 fleet-ade 装防密钥、防公司内容的卫生检查再公开 |
| 多久 | 并进来 2–3 天；工具链和检查改造几周（推断） | 按月算（推断） | 立规矩 1–2 天；之后每页约一个 PR（推断） | C 再加几天（推断） |
| 公开和私有 | 冲突：一合进来就公开，收不回 | 引擎的合并闸、改标准路径都在公开仓 CI 上，全要重搭 | 不冲突 | 公开了收不回 |
| CI | fleet-dao 每个 PR 从约 10 分钟（实测）涨到 80 分钟以上；决定 0101 规定一律全套 | 引擎每次修和发版都排进私有仓额度 | fleet-ade 的检查单独解决（#122 已在做：拆并行+法国自建跑机） | 公开仓分钟不限 |
| 规矩体系 | 整仓扫会扫到上百万行别人的代码，只能排除 | 规矩来源要搬家或两边各一份 | fleet-ade 认成自用仓后，仓合同和钩子管得到它 | 同 C |
| 法国引擎派活要不要改 | 要 | 要，整条重做 | 不用 | 不用 |
| 能不能回退 | 难 | 难 | 容易：页面是新加的，旧驾驶舱不动，换首页只是改一条转发 | 公开那一步回不去 |

- **判断**：需求方要的「合一」是用起来是一个东西——一个界面、一个入口，在里面能看引擎、能派活、能验收。C 就能做到。A、B 换来的只是「一个仓」，代价是公开私有冲突、工具链被迫一起升级、检查变慢、回退难。后端更不能搬：各机器都靠它上报和领单，得一直在法国开着。
- **做法**：选 C。分工写死：fleet-dao 管法国引擎、驾驶舱后端（一律经接口）、库、规矩、技能、钩子、检查、合并闸；fleet-ade 管所有人用的界面，包括以后的驾驶舱页面。接口契约只有一份 `packages/shared/src/web-api.ts`，ADE 用到的接口登记进 fleet-dao 的契约测试，fleet-dao 改接口能看见会碰到 ADE。
- **不做什么**：不合仓、不并 git 历史；不把引擎、后端、规矩搬进 fleet-ade；ADE 不直连法国的库，只经接口；不在 fleet-ade 里重写一遍规矩，规矩还从 agents-sync 来；现在不删旧驾驶舱。

### 2. 「驾驶舱往 ADE 靠」具体要 ADE 有什么

旧驾驶舱页面（`packages/web/src/routes.ts:9-31`）逐个对：

| 旧驾驶舱的页 | 干什么 | ADE 里现在有没有 | 要做什么 |
|---|---|---|---|
| 工作台（首页） | 要你拍的、在跑的、卡住报警、最近上线、系统状态 | 没有；ADE 的「等你处理」只管本机会话 | 新做，先只读，最先做 |
| 通知中心 | 看门狗提醒、受控修复 | 没有 | 新做；先只读，修复按钮放后面 |
| 任务列表、任务详情、单次会话 | 法国引擎的单和每一步 | 没有 | 新做，就是整体思路第 6 条的引擎面板 |
| 提需求 | 和指挥官聊清楚再开单（决定 0090） | 能聊，没有开单动作 | 指挥会话加开单工具，调现成开单服务 |
| 额度 | 各渠道额度窗口 | 部分有（`_chat.usage.tsx`） | 改成读 fleet-dao 的读数 |
| 路由、渠道状态 | 选路和每渠道近 60 次情况 | 部分有：智能体设置页 | 渠道页 |
| 法国页 | 引擎总开关、发版、机器表 | 只有引擎健康检查原文（`apps/server/src/fleetEngine/http.ts:17`） | 先只读；开关和发版按钮最后搬 |
| 资源、定时任务、操作记录、发布记录 | 法国机资源和记录 | 没有 | 新做，只读 |
| 设置 | 引擎设置 | 没有 | 留在旧驾驶舱，最后再定 |
| 登录 | 飞书或账密 | 一次性配对；香港那道门在第 2b 步做 | 照第 2b 步 |

新驾驶舱（`/next/`）的会话、收件箱、远程机器、定时任务，ADE 底座都有对应的（按代码），第 3 步主力迁移过了就退役，不搬。

**和整体思路对不对得上**
- 第 2b 步照旧：挂在新路径或子域名上，旧驾驶舱留在首页。
- 第 3 步改一处：「主力迁移过了就把 ADE 换成域名首页」改成两件都做到再换：(a) 工作台、通知、在跑的三块在 ADE 里有了；(b) 第五节第 2、3 条定了。第 3 步只验 ADE 自己的会话干活，验不到这些驾驶舱功能。
- 第 5 步从「引擎面板和单子流程的只读部分」扩成「驾驶舱页面按上表逐页搬」，每搬完一页，旧驾驶舱那页冻结。

## 二、另外查出来的

1. **fleet-ade 的 CI 分钟**：一次 CI 一个 job 78 分钟（run 43614457633，实测），11-14 当天 31 次、约 836 分钟（实测），私有仓每月免费 2000 分钟。需求方 2026-11-14 已定：拆并行 + 法国 VPS 自建跑机（fleet-ade #122 在做）。另可照决定 0101 第 2 条做「主线和 PR 同一棵树就复用」，再省近一半。
2. **fleet-ade 被自动判成「对外仓」，仓合同和钩子都不管它**：`repoKindInfo` 返回 `external`，因为 `upstream` 远端（pingdotgg/t3code）不在创始人账号下（决定 0108 第 1 条）；`repo:check` 回「仓合同不管对外仓……什么都没动」（实测）。定了 C 就跑 `pnpm repo:kind self D:\frank\fleet-ade`（只改本机 git 配置）。
3. **fleet-ade 的 AGENTS.md 还是上游英文原文**，写着「三个界面：网页、桌面、手机」（`AGENTS.md:1-40`，实测），和「不做手机端」「只经 reclaude」对不上。换成本仓协作约定，上游开发知识挪进 `docs/` 当参考。
4. **ADE 服务端跑在创始人电脑上，电脑一关，驾驶舱域名就看不到法国的情况。** 整体思路第 9 条只写了「显示离线」；旧驾驶舱是手机上看「要你拍的」的入口，ADE 成了唯一界面就得有退路。列进第五节第 2 条。
5. **另一位创始人也在用驾驶舱**（决定 0042，后端有白名单）。第 2b 步的第一道门只放创始人本人（门后是他电脑的命令行）。首页换成 ADE 后另一位看什么，没人定过。列进第五节第 3 条。
6. **`.repos/` 还在 fleet-ade 仓里**（24120 个文件）。整体思路第 1 条把它列在第一批删的里，但可能是写码查 Effect 源码故意留的，要在 fleet-ade 开单确认。

## 五、要拍板的

1. **「合二为一」照哪种做**：推荐 C（两个仓、一个产品），理由见第一节第 1 条的表；备选 A（并进 fleet-dao）。定了 C 也就等于定了「fleet-ade 是自用仓」。
2. **电脑关机时驾驶舱域名上看什么**：推荐旧驾驶舱挪到子路径，当只读退路长期留着、只修不加，手机照样看「要你拍的」。备选：法国机上也起一份 ADE 服务端，关机也能用，但法国多一个能跑命令的服务挂在公网后面，要再过一遍两道门。
3. **另一位创始人以后用什么**：推荐继续用旧驾驶舱（子路径），ADE 只给你本人。备选：ADE 加一个只看法国、不连你电脑的只读模式给他，要先做完第 2 条的备选，代价大。
4. **fleet-ade 要不要改公开（做法 D）**：推荐不改，CI 分钟已经由 #122 自建跑机解决；公开了收不回，还要先装卫生检查。
