## 一、已定的方向和能力盘点

### 1. 已定的（需求方 2026-11-15）

- 以后唯一的产品是 fleet-ade（私有，t3code 底座，已瘦身中文化，Claude 只经 reclaude）。驾驶舱往 ADE 靠。
- 法国引擎做成 fleet-ade 的新功能「各个机器互相通信」，分三步：①法国起无界面的 ADE 服务端，只走内网隧道，本机 ADE 把它当远端机器开会话；②ADE 里加「自动拉单 → 派会话 → 开 PR → 等检查 → 合并」流水线，合并闸、冷验收等判法照 fleet-dao 现有规矩重写成 ADE 模块，只挑真在用的；③新的稳跑一两周再停旧引擎和旧驾驶舱。③之前旧引擎照常跑。
- fleet-dao 从现在起不加新功能，只修坏的。技能、规矩、钩子（`agents/` + `agents-sync`）、检查、开单开 PR 命令留在 fleet-dao 继续改。

**原稿的做法比较（压缩）**：原稿比了 A 合仓、B 把引擎和驾驶舱整个搬进 fleet-ade、C 两仓各管一摊（引擎留在 fleet-dao），推荐 C。11-15 定的是第四种：产品只剩 fleet-ade，引擎的能力只挑在用的、在 ADE 里重写，fleet-dao 退成规矩库加账本后端。和 B 比：不搬 19.5 万行，不搬 Temporal，只写下表标「迁」的十来样。和 C 比：引擎不再是另一套会话系统。代价：要新写拉单、认领、冷验收、合并判法、选路、通知六块；并存期两边都要养。仓还是不合（公开和私有冲突、工具链、CI）。

**批次 0：立规矩加止血（马上开单，3–5 天）**
- 做什么：fleet-dao 写新决定，按第四节标「批次 0」的几行一次改完。停掉新内核三个服务，用 `real.ts release` 把 #3864–#3866 按状态切回（`docs/ops.md`）。fleet-ade 跑 `pnpm repo:kind self`，AGENTS.md 换成本仓约定。

- 风险和回退：文档退 PR；服务 `systemctl start` 就能起回来。
- 之后冻结：`packages/engine`、`adapters`、`web`、`api` 只修不加；harness 几个包、`apps/desktop`、`crates/` 不再改。

**批次 1：法国无界面 ADE，本机连上（①，1–2 周）**
- 做什么：fleet-ade 写法国装法：专用系统用户，Node 26 装在用户目录，构建指定提交，systemd 起 `t3 serve --host <隧道地址>`，更新就是「拉提交、构建、重启」。电脑加进现有 WireGuard 当一个节点（运维，不算新功能）；法国防火墙只对隧道网卡开 ADE 端口。打开机器互连开关，配对一次。
- 依赖：批次 0；fleet-ade 主线全绿。
- 怎么算做完：法国 ADE 只听隧道地址；从公网连 ADE 端口不通；本机 ADE 环境列表里法国显示「已连接」；在法国环境开一个 grok 会话改一行、推一个草稿 PR；撤销会话后本机断开；服务起来 24 小时日志里没有连上游域名的记录。
- 风险和回退：法国内存吃紧，并发会话先限 2 个。回退：停服务、撤隧道节点。

**批次 2：结束事件加流水线骨架，只跑 fleet-ade 自己的单（②上半，1–2 周）**
- 做什么：ADE 服务端加子会话带状态的结束事件。新加「流水线」模块，只在法国那台打开、默认关：读单（贴了「交给 ADE」的）→ 认领 → 建工作树 → 开会话 → 收结束事件 → 开 PR → 等检查。不合并，合由人来。加「流水线」页：在跑的、卡住的（带原因）、最近开的 PR。
- 怎么算做完：3 张真单从贴标签到开 PR 全自动；重启服务单子不丢；同一张单不会起两个会话（测试先红后绿）；会话失败、检查红、超时三种各真遇到一次，都进卡住并带原因。
- 风险和回退：关设置。旧引擎从来不碰 fleet-ade，不会撞单。

**批次 3：冷验收、合并判法、预算、通知，在 fleet-ade 仓上自动合（②下半，1–2 周）**
- 冷验收：换一家没写过这张单的模型来验；材料是 diff、改了哪些文件、单子的验收条、PR 正文；默认 1 轮、最多 2 轮，第 2 轮还不过就交人。没跑起来算 failure，等资源算 pending，状态没写上算没验过，只认当前头。结论贴 GitHub 状态 `cold-verify`。
