# 账本迁移盘点（#4078）

- 盘点日期：2026-11-17。
- 范围：`packages/api` 的 `/api/nodes/*`、命令与合并闸调用方、账本相关表和备份部署。
- 证据口径：以下行号来自本工作树当前快照；“按代码”是静态读取，不等同于法国线上实测。法国服务、生产库未连接。
- 工单要求：批次 6 将账本后端、合并闸 CI 策略读口、备份搬进 fleet-ade；迁移期双写并对账，切读后旧后端和旧库保留 30 天；备份不得低于 7 天 + 4 周。

## 一、结论先行

1. `/api/nodes/*` 当前有 **11 个 HTTP 方法/路径组合**：节点快照 1 个写口、节点列表 2 个登录读口、本机会话 1 写 1 读、本机租约 1 读 1 写、开单账本 1 开单写口 + 1 过程写口 + 1 读口、派单 1 写口。
2. `X-Fleet-Node-Token` 由 `packages/api/src/node-report.ts:76-97` 的统一认证器现读 `node_keys` 与旧配置 `FLEET_NODE_KEYS`，覆盖快照、会话收取、租约、开单和派单；驾驶舱读口只走登录 Cookie。
3. 账本不是独立表：开单事件和过程记录都追加到 `audit_log`；`audit_log_ledger_events_idx` 支撑增量读，`audit_log_ledger_note_key_idx` 保证同仓同 `idempotencyKey` 的过程记录幂等。
4. 地址没有一个集中配置源。命令端和本机会话共用 `~/.fleet-dao/local-sessions/config.json`；节点快照另由 `FLEET_NODE_REPORT_URL` 配置；驾驶舱读口走浏览器同源，不另配后端地址。迁移不能只改一个 URL。
5. 建议顺序：只追加账本读写 → 节点快照/会话和租约读口 → 开单/派单写口 → CI policy 读源和合并闸切换。

## 四、合并闸读的 CI 策略
API 另有 `GET /api/public/ci-policy/v1/repos/:githubId`，可带严格的 `?pr=&head=`。它在 `packages/api/src/ci-policy-public.ts:6-25` 注册，公开精确 GET、不认 Cookie/Bearer、`Cache-Control: no-store`，最后调用 `deps.ciPolicyBridge.read(id)`（接口 `ci-policy-bridge.ts:27-36`）。

权威地址不是命令配置：`packages/api/src/github-mirror.ts:79-96` 用公开 `publicUrl.origin` 装配策略桥，再经 `packages/shared/src/ci-policy-bridge.ts:98-119` 生成无凭据、无端口、无路径的规范 HTTPS endpoint。策略值来自 `repos` 行，`find` 和 `findByGithubId` 都读库。

合并闸实际调用点不是这个公开 HTTP 路径：`packages/conventions/src/bin/merge-gate.ts:59-68` 将 `policyReader(api, gh, GITHUB_REPOSITORY)` 注入 `runMergeGate`。`policyReader` 在 `ci-policy-bridge.ts:317-341` 先从 GitHub 核仓身份、PR 当前 head、公开性和可信 engine writer，再从当前头的 source URL 读策略。HTTP 协议在 `ci-policy-bridge.ts:121-147,209-242`：每次 GET 10 秒，最多两次；只有没收到响应头的网络错误才重读，收到响应后状态码、重定向、content-type、缓存头和串仓均按失败处理。合并闸写 GitHub `merge-gate` 状态，不写 `/api/nodes/*`。

迁移边界：不要把公开 CI policy 路径误归入节点证接口；要迁的是 policy source/bridge 的权威地址和协议。权威策略仍是 `repos` 行，ADE 必须继续校验 `githubId + repo + PR/head`，保留 10 秒、两次和失败分类。

## 六、备份范围、频率、保留期

按 `deploy/backup/lib.sh:7-45` 和 `fleet-backup.sh:205-252`：法国备份 `fleet`、`temporal`、`temporal_visibility` 三库；每晚 restic 加密，经 WireGuard 送香港 `/srv/fleet-dao-backup/restic`；每日保留 7 份、每周保留 4 份。manifest 与 dump 使用同一只读 repeatable-read snapshot。

每周从香港取最近快照恢复到临时库 `fleet_drill_restore`，核每张表行数和时间列最新值，再删除临时库（`fleet-backup.sh:288-412`）。定时器：每日 04:10 备份、周日 05:40 恢复演练、每小时 17 分磁盘巡检。香港 root 每天 09:10 复制 restic 仓到 root-only 副本，保留 14 天（`deploy/backup/hk-repo-copy.sh:1-9`）；香港每小时 25 分检查快照，超过 26 小时报警（`hk-snapshot-freshness.sh:1-14`）。

ADE 最低备份合同：三库和 manifest、restic 加密传输、7 日 + 4 周在线保留、香港 14 日副本、26 小时新鲜度报警、每周真恢复演练。只跑 shell 测试不算工单要求的真恢复。

## 七、迁移顺序、双写、对账、回退

### 0. 前置

1. 批次 5 完成并稳定；旧后端、旧库可用，先核现有备份和恢复演练。
2. ADE 先建兼容的 `node_keys`、`node_reports`、`node_sessions`、`audit_log`、`tasks/repos` 最小 schema 和备份/恢复环境。
3. 导入旧库快照，逐表核行数、最大 `audit_log.id`、每节点 `received_at`、有效/作废钥匙数；读不到写“没查成”，不能用 0 代替。

### 1. 只追加账本

1. `POST /notes` 旧端和 ADE 各写一份，用相同 `repo + idempotencyKey`；按 `action,target,after` canonical JSON 和 created/id 对账。
2. `GET /events` 双读相同 `after,limit`，比较 id 顺序、action、target、after、ok；账本只拉 cursor 之后的新行。
3. 连续至少 24 小时无差异后切账本读；旧端写和读保留 30 天。

### 2. 节点和租约

1. report、sessions 旧写 + ADE 写，以 `node_id` 为键、按接收端 `received_at` 取最新，比较 payload schema/hash。
2. claims 先双读，不双写状态；比较 `repo,issue,claimedBy,leaseUntil,executor,state,fencing`。任务状态只能有一个 writer，避免租约覆盖。
3. 先切四个读口（claims、nodes、sessions、node detail），再切写端；写端切换要有单调 writer 标记/租约 fencing，不能靠时间先后。

### 3. 开单、派单、CI policy

1. `/issues` 最后切。双写不等于开两张 GitHub 单：迁移控制面先以 idempotencyKey 占键，第二端只接收同一 GitHub 回执；未知回包停并核对，不 fallback 重开。
2. `/dispatch` 随后切，核任务和 audit 只出现一份；保留 503 “不知道派没派”，禁止自动重试。
3. CI policy 先让 ADE 只读旧 source，对 `githubId/repo/pr/head` 双读；策略值、source、缓存头和失败分类一致后再改 merge-gate 地址。

### 4. 七天验收和回退

每个接口分别计成功、鉴权失败、503/超时、协议不识别、对账差异。`issue:new`、`work claim`、`pr:open`、merge-gate 各自迁移失败必须为 0；连续 7 天后才算切换完成。旧端只读保留 30 天，差异时把该能力地址改回旧端；写回前按幂等键/版本确认，禁止盲目补写。
