## 二、现状和问题（带数字）

### 2.1 先纠正一个前提：原始色阶已经是 0

单上「页面不再直接写 `text-gray-500`、`bg-blue-600`」这条现在**已经成立**：src 里 Tailwind 原始色阶类 0 处（只有 `text-white` 10 处、`bg-black/50` 3 处，都在 `ui/` 和外壳）。#182 和主题体系把颜色这一层守住了。真正乱的是下面几层。

### 2.2 字号：两套并存，实际用了 12 种像素

| 来源 | 用法次数 | 档位 |
|---|---|---|
| #182 令牌 | 392 | micro 10、caption 11、sub 13、label 14、strong 15、stat-num 17、title 22、stat 28 |
| Tailwind 默认 | 401 | xs 12（231）、sm 14（155）、lg 18（7）、base 16（5）、xl 20（3） |

合起来页面上出现 10、11、12、13、14、15、16、17、18、20、22、28 共 12 种字号；10–15px 之间就有 6 档，肉眼分不出层次，只觉得「碎」。11px 的 `text-caption` 用了 227 次、10px 的 `text-micro` 42 次，中文在 10–11px 笔画糊在一起（线上截图里灰色小字一片）。

区块标题同一个 `<h2>` 有 5 种写法：`text-xs`（`routes/notifications.tsx:274`）、`text-sm`（`components/page.tsx:104`）、`text-strong`（`routes/france.tsx:231`、`routes/settings.tsx:115`）、`text-base`（`routes/routing.tsx:376`、`components/engine-master-card.tsx:86`）、`text-lg`（`components/home/board/detail-panel.tsx:127`）。

### 2.5 对比度：只验了状态色，次要文字有 7 套主题不达标

`src/lib/contrast.test.ts` 只验七个状态色的「墨色」。我按同一套 oklab 混色算了次要文字（`--muted-foreground` = 前景 64% 混底色）和 `--faint`（44%）：

- `muted-foreground` 在 16 套里有 7 套某种底上不到 4.5:1：东京夜亮 3.63、原子亮 3.96、炉火暗 3.84、北境亮 4.10、日晒暗 4.38、原子暗 4.42、日晒亮 4.47。
- `faint` 在 16 套里全部 2.3–3.5:1，当文字用了 22 处（如 `components/job-row.tsx:49`、`components/probe-log.tsx:96`），一律不达标。

### 2.6 #182 那版做到哪、哪里没守住

做到的：任意尺寸值清到 0，`lint-arbitrary` 守住（含故意造红的测试）；顶栏、侧栏、容器宽等专用尺寸进了 `@theme`；`theme-tokens.test.ts` 钉住命名空间写错不生效的坑；状态墨色对比度闸。

没守住、或方向偏了的：
1. **给乱值起了名字，没收档**：#182 的做法是「每一档就是原来写死的那一档像素」（`app.css` 第 76–85 行注释原话），8 个字号令牌对着 8 个历史像素，没有合并；Tailwind 默认字号也没关，两套一起用。
2. **只拦方括号**：`lint-arbitrary` 只认 `xxx-[13px]`，`text-xs`、`p-3.5`、`rounded-2xl`、`shadow-lg`、`bg-st-fail/5` 都合规，所以各页照样各写各的。
3. **令牌层和版式常量混在一起**：`@theme` 里 39 个一次性尺寸（`--spacing-routing-desk`、`--container-quota-cell`、`--grid-template-columns-efforts`…）和设计档位并排，读不出哪些是「规范」、哪些是「某页要的数」。
4. **没有版式组件这一层**：令牌只管单个值，卡片、行、标签、空状态这种「几个值的组合」仍在每页手写。
5. 「16 页五种状态」那一半后来由别的单（RefreshBar、LoadError）做了大半，本方案不重做，只把它们收进版式组件。

### 2.7 线上截图看到的（`_tmp/vps-verify/shots3/`）

整体干净，石墨主题的「框架黑白灰、颜色留给状态」是对的，问题在细处：灰色小字太多太小（法国页、路由页底部说明、渠道状态左栏）；数字一律等宽字体，和中文混排时字距忽宽忽窄（「19 秒后读」「5 天 3 小时」）；卡片套卡片（法国页大卡里再套两张卡）；同一屏三四种筛选条样式（路由页胶囊、任务页灰底分段、通知页两组分段）；原生下拉和自绘下拉混用（任务页）；页头右侧「刷新 + 最后更新」和计数小标签挤在一起（渠道状态页）。

## 四、候选做法

### A. 在现有 shadcn + Tailwind 上收口：令牌三层 + 版式组件 + 检查（推荐）

做什么：
1. 令牌按 Primer 的三层重排：主题基色（已有 16 套）→ 语义令牌（颜色语义、6 档字号、限定的间距档、3 档圆角、3 档阴影、3 档时长）→ 版式组件内部用。页面只许用语义令牌。
2. 补齐一层版式组件（第七节），页面拼组件，不手写卡片、标签、空状态。
3. 一个新检查 `lint-design`（并入 `lint-arbitrary`），拦第八节列的九类写法；没迁的文件进「旧账清单」按条数冻结，只许减不许加。
4. 规范写成 `docs/design/驾驶舱界面.md`，加一页只在 mock 模式出现的「陈列页」，所有组件 × 状态 × 亮暗一屏看完。
5. 逐页迁移，每片带改前改后截图。

代价：9 个 PR（第十节），总改动约 150 个文件；迁移期间新旧并存几周，靠旧账清单兜着；每片要更新一批断言类名的单测（约 50 处）。好处：主题体系、16 套主题、手机适配、已有测试全保留；改动可逐片回退；检查长期有效。

### B. 换 Radix Themes 这类成套组件库

做什么：用 Radix Themes 的 `Theme`、`Card`、`DataList`、`Callout`、`Badge`、`SegmentedControl`、`Table` 替掉 shadcn 组件和手写版式，档位由库给。

代价：20 个 `ui/` 组件和 159 个文件几乎全改；Radix Themes 自带一套 CSS 和自己的命名，和 Tailwind 预置样式、层级要专门调；我们 8 套自定义主题色要改成它的 12 级色阶生成（它的强调色是固定色板，自定义要另生成整套 12 级）；状态墨色和对比度闸要重写；手机 40 高等已做的适配要重做。换来的是「档位天然统一」，但这一点 A 用检查也能做到，且库的密度和外观仍要再调。**不推荐**：成本是 A 的数倍，收益 A 都能拿到。

### C. 换 Ant Design 6 这类中文后台成套库

做什么：用 antd 6（2025 年底发布，具体日期未核实；默认纯 CSS 变量、可零运行时）整站重写。

代价：比 B 更重——组件 API、表单、弹层全换，和 Tailwind 共存要处理样式优先级；外观是典型企业后台，离「Linear/Vercel 那种克制」更远；我们的主题体系作废。好处是中文排版、密集表格开箱即用。**不推荐**。

另一个没列为候选的变体：A 只做令牌和检查、不做版式组件。不选：截图里难看的地方大多是「组合」不一致（卡片套卡片、四种筛选条、十几种小标签），单个值统一了组合照样乱。

**推荐 A。** 理由：问题出在「没档位、没组件、没闸」，不在组件库本身；A 保住已经投入的主题体系和手机适配，按页可回退，检查长期守住，B、C 的好处 A 都拿得到。

## 五、视觉基调

参照：**Linear 的克制（框架黑白灰、颜色只给状态、减少噪音）+ Vercel Geist 的字阶分工（单行标签 / 多行正文）+ GitHub Primer 的行密度和令牌分层**。密度目标接近 shadcn 的 Mira「为密集界面做的紧凑风格」，但不重拉组件。

具体八条（判断，落在令牌和组件里）：
1. **字少几档、字大一点**：6 档字号（第六节），中文最小 12px；次要文字全部 ≥4.5:1，灰字不再「看不清」。
2. **数字用 Inter 的等宽数字（tabular-nums），不用等宽字体**：`num` 改成无衬线 + 等宽数字；只有编号、提交号、路由号、模型 id、代码用 `font-mono`。中文和数字混排不再忽宽忽窄。
3. **最多两层容器**：页面 → 区块（Section）；区块里用分隔线和行，不再套卡片。法国页「大卡里两张卡」改成一个区块两栏。
4. **圆角收紧**：控件 6px、卡片和弹层 10px、标签全圆；去掉 14px、16px 的大圆角，观感更利落。
5. **阴影只表示「浮起」**：卡片亮色下只有一根下边线、暗色下无阴影靠边框；只有弹层、菜单、对话框有投影。
6. **状态色统一三种用法**：实色（点、条、图标）、淡底（12%）、描边（40%），各有令牌；标签一律「点或图标 + 字」，不靠颜色单独传意思。
7. **页头一行**：标题左、操作右（刷新收进页头的固定位置）；说明 ≤1 行，长说明进 ⓘ（#1820 已在手机上这么做，桌面也照此）。区块说明同理。
8. **控件高度**：桌面 32px（`h-8`），手机最少 40px（沿用 #1820）；列表行桌面 40px、手机 44px；手机上输入框字号 16px，防 iOS 放大。

字体：沿用 Inter Variable + 系统中文字体（苹果 PingFang SC、Windows 微软雅黑 UI），不引中文网络字体（体积几 MB，收益不抵）。标题不另引 Inter Display（判断：中文标题为主，收益小）。

### 6.3 间距（4px 网格）

- 宽高（`h-*`、`w-*`、`size-*`）不限档，但不许任意值（沿用 #182）。

## 十一、风险和回退

| 风险 | 办法 |
|---|---|
| 和在做的界面单冲突（#1842 渠道状态页；引擎也会接「动手 · 界面」类的单） | 片 1 合在 #1842 之后；片 8 等 #1842；检查一合进主线，任何新界面 PR 写新的违规都会红——这是想要的效果，报错写清该换成什么；旧账清单的条数只许减，别的 PR 顺手改坏同文件会红在 CI 上 |
| 全局改动一次影响所有页（片 1 的次要文字颜色、片 2 的圆角/阴影/`num`/控件高） | 放在页面片之前一次做完，免得每页返工；这两片 PR 贴全部 12 页改前改后截图；不好看就整片回退 |
| 单测断言类名（约 50 处，如 `routes/france.test.tsx:175` 断言 `text-ink-stall`） | 改到哪页同片改测试，改成断言 `data-tone`；不为迁就测试保留旧类名 |
| e2e 依赖样式 | 查过：e2e 用角色和文字定位，只有首页用 React Flow 自带类名（`.react-flow__node`），不受影响 |
| 字号放大后密度下降（11→12、13→14），某些表（额度矩阵、三段表）挤 | 这几张表在片 6、片 3 里单独看 1366 截图；必要时用 `text-meta` 而不是加回 13px；陈列页先让创始人看一眼（只报不等） |
| 等宽数字改无衬线后，编号类东西失去等宽 | 片 2 全局改 `num`，各页片把编号、提交号、路由号改用 `Code`，截图核对 |
| 检查误报（扫字符串会扫到非类名的英文词）或漏报（动态拼接类名） | 规则只认「像 Tailwind 类」的词（带已知前缀）；动态拼接本来就被 Tailwind 扫不到，规范里禁止；误报进白名单要写理由（沿用 #182 白名单格式） |
| 回退 | 每片一个 PR，`git revert` 即回；旧账清单让「部分迁移」始终是合法状态，回退某一页片只需把那几行清单加回 |

人闸四类：本方案只有 **9b 一处改标准**（`.claude/agents/` 在标准清单里）。不对外发布（合进主线不触发上法国，发版照常由「发布到法国」走）、不花钱、不删数据。
