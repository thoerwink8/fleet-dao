# 标准体检：fleet-dao 放一份带版本号的标准，对每个项目和机器只查不改、每天复查报落后几个版本，对账表代码部分，缺了就不能开工那档没过接活开关点不动（项目与标准分步②）（#132）

对应计划：plan.md P2「标准体检」
设计依据：design 15.7「二、标准」第 8–11、14 条。

原话：fleet-dao 放一份带版本号的「标准」，推给机器和仓；先做体检（只查不改），每天复查、报落后几个版本；对账表里结构化的部分全用代码查；「缺了就不能开工」那档没补齐，「让 AI 接活」开关点不动。（创始人 2026-09-26 拍「项目 + 标准」方案选项 1，分步②）
AI 理解：先把「标准」写成 fleet-dao 里一份机器能读的清单（带版本号、每项标档位和怎么查），再做只读的体检：对每个项目的仓、每台机器逐项查，给出达标、缺项、豁免、落后几个版本；对账表里用代码查的规矩（标签、里程碑、路径、状态）收 webhook 就查、每天全量扫。这一步一个字都不改别人的仓和机器，补齐是分步③。

## 要做什么

照 `docs/design.md` 15.7「二、标准」第 8–11、14 条里「只查」的部分：

- 标准文件：放在 fleet-dao 里，带版本号；每项写明对象（机器 / 仓）、档位（「缺了就不能开工」/ 提醒）、怎么查（代码 / Jev）、在哪个环节查、自动补还是提醒人（这就是对账表）；豁免写在被查的仓或机器那边，要带理由，没理由的豁免不算。
- 仓的检查项起步：派单接入（GitHub App 装了、webhook 通）、流程约定（PR 模板和开单表单来自账号下 `.github` 仓或仓自己有、标签和里程碑齐、CI 引用 fleet-dao 的可复用工作流）、文档（仓根 AGENTS.md 有、栏目固定、`specs/` 在）、这个仓要用的 skill 和 MCP 清单。
- 机器的检查项起步：agents-sync 的通用段和 skill 是最新版、MCP、命令行工具齐。
- `fleet project check`：本机 AI 用的只查命令，输出每项达标没有、缺什么、落后几个版本，退出码非 0 表示有「缺了就不能开工」的缺项；驾驶舱「体检」按钮调同一份代码。
- 体检状态存库：发现 → 补齐 PR 待合 → 已合 → 复查通过 / 复查失败 / 已豁免（这一步只会写「发现」「复查通过 / 失败」「已豁免」）；同一个事件（同一个 webhook 投递、同一次复查）重复来只处理一次。
- 驾驶舱：项目详情里看体检结果；「缺了就不能开工」那档没过时，「让 AI 接活」开关点不动、写明缺哪几项；引擎每次真正派活前再查一遍，不达标不派、写明原因。
- 对账表的代码部分：驾驶舱后端收 webhook 就查、每天全量扫（Temporal 定时，结局记进 `schedule_runs`）；读 GitHub 失败算「没查成」，不当成达标。
- 每条读不到、认不出的路径（标准文件格式不对、GitHub 读失败、机器上读不到配置）返回明确失败，各配一条故意造出失败的测试。

## 怎么算做完

- 测试：标准文件缺字段、档位写错时读取报错；一个缺 PR 模板和标签的假仓，体检列出这两项、档位对；同一个 webhook 投递来两次只记一次；GitHub 读失败时体检结果是「没查成」、不是「达标」；「缺了就不能开工」有缺项时接活开关的接口拒绝打开，引擎派活前复查不过不派。
- 本机：对一个故意缺 PR 模板和标签的测试仓跑 `fleet project check`，列出缺的几项和落后几个版本，退出码非 0；补上后再跑，退出码 0。
- 法国真机：驾驶舱里 fleet-dao-canary 的体检结果和本机命令输出一致；定时任务页有「标准复查」一行，上次跑成的时刻、查了几个项目对得上。
