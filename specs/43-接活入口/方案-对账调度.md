# 方案与结果：对账补漏接上定时（#43）

需求见 [需求.md](需求.md)「漏收的补回来」；对账本身怎么查见 [方案.md](方案.md) 第 3 条。定时怎么调在 [方案.md](方案.md)「谁来定时调对账」已拍：引擎里一个 Temporal 定时任务，每 15 分钟、往回看 2 小时，登记成 `github-reconcile`（`expect_every_minutes` 45），结局记进 `schedule_runs`。这份只写怎么接上。

## 方案

- **放哪**：引擎（design 第四节：Temporal 替代旧系统的 systemd 定时器）。代码在 `packages/engine/src/jobs/`：
  - `schedules.ts`：Temporal Schedule，编号固定 `github-reconcile`，每 15 分钟起一条 `githubReconcileWorkflow`；上一轮没完就跳过这一轮（overlap SKIP），Temporal 停了一阵只补最近一轮（catchupWindow 15 分钟），一轮失败不停掉定时。
  - `github-reconcile.ts`：一轮 = 记开始 → 调后端的 `reconcileGitHub`（`@fleet-dao/api`）→ 记结局。
  - 工作流 `workflows/github-reconcile.ts` 只调一个活动 `reconcileGitHub`（档位 `job`：10 分钟、不重试——每次尝试记一行 `schedule_runs`，没跑成的等下一轮）。
  - 真装配 `real/github-reconcile.ts`：后端的 `createPgStore`、`createGitHubIntake`（同一道门、同一本投递账）、`@fleet-dao/github` 的真轮询；发信号、拉起需求工作流（后端的 `createTemporalRequirementWorkflows`，和 webhook 那条同一份实现，#93）用这次活动自己的 Temporal 客户端，起在这个工人取活的任务队列上。
- **幂等**：引擎（真端口）每次启动先登记 `scheduled_jobs`，再按固定编号建 Schedule；已经有了（`ScheduleAlreadyRunning`）就按声明更新间隔、要起的工作流和策略，人手动暂停的照旧停着。对账本身重复跑不重复建任务、不重复拉起：任务行按（仓, issue 号）唯一，轮询按「对象 + 版本」去重（方案.md 第 1 条）。
- **失败要显式**：
  - 读不到 GitHub、认不出 GitHub 回的形状、拉起需求工作流时 Temporal 连不上：这一轮记成 `unscanned` / `partial`，原因写进 `schedule_runs.why`；驾驶舱「定时任务」页标「没扫到」或看得到原因。
  - 对账本身抛错（读库失败等）：记成 `failed`，活动报不重试的 `RECONCILE_FAILED`，Temporal 里这条工作流也是失败的；定时任务页标「没跑成」。
  - 记不上开始（库连不上）：这一轮不去对账、活动失败；库里没有这一轮，登记表上它过了 45 分钟变成「过期」。
  - 假端口的工人接到这一轮：报 `JOB_NOT_CONFIGURED`，不回空的 ok。假端口的工人不建这个定时任务。
  - 登记或建 Schedule 失败：引擎不起（连不上 Temporal、没权限都照实抛），不带着「对账没人跑」接活。
- **不碰的**：没改库表、迁移（用已有的 `scheduled_jobs`、`schedule_runs`）；没改部署脚本；没碰后端 `main.ts` 和 `RequirementWorkflows` 的实现，只调它。

## 结果

- 新文件：`packages/engine/src/jobs/github-reconcile.ts`、`packages/engine/src/jobs/schedules.ts`、`packages/engine/src/workflows/github-reconcile.ts`、`packages/engine/src/real/github-reconcile.ts`、`packages/engine/test/github-reconcile.test.ts`。
- 改了：`contract.ts`（工作流名、输入输出）、`activity-options.ts`（活动和 `job` 档）、`activities.ts`（`EngineJobs`）、`worker.ts`（真端口启动时登记、建 Schedule）、`real/index.ts`（装 jobs）。
- 测试（`packages/engine/test/github-reconcile.test.ts`，14 条，库是 PGlite 上的真迁移）：
  - 库里缺一条 issue → 经 Temporal 测试服务端跑一轮：任务行补上、需求工作流经真 Temporal 起来了、`schedule_runs` 一行 ok；再跑一轮 found 0、任务行不变、同一个工作流编号还是那一次执行。
  - 故意造的失败各一条：GitHub 500（unscanned、定时任务页「没扫到」）、issue 列表形状认不出（不记 ok）、拉起需求工作流时 Temporal 连不上（不记 ok）、对账抛错（failed + `RECONCILE_FAILED`、「没跑成」）、定时任务没登记记不上开始（活动失败、不去对账）、假端口工人（`JOB_NOT_CONFIGURED`）、记结局失败（原样抛）。
  - Schedule：假客户端验「没有就建、有了就更新、暂停照旧、别的错原样抛」；真 Temporal 开发服务端对两遍只有一个、间隔 15 分钟、第二次更新了任务队列、手动暂停保留。
  - 故意改坏三处（对账抛错时不报失败、更新时不保留原来的状态、补回的 issue 不真起工作流），对应用例红。
- 法国上的验收并进需求.md「怎么算做完」的那一条（随 #28 上线）：巡检仓开一张 issue 并让那次 webhook 送不到，15 分钟内库里有任务行、需求工作流起来了、`schedule_runs` 里这一轮是 ok。
