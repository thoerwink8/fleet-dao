# 拼车号用完切独享号、手上的活原地接着干，窗口回来再切回（P1 验收的一条）（#59）

对应计划：plan.md P1「Claude Code 插头」
设计依据：design 第九节（拼车用完，手上的活原地接着干）、第十节（Claude 订阅一个组织一个账号池）。

## 要什么

- 拼车号的会话被拒（额度用满）时：拼车会话用户切到独享组织（`reclaude org use`），再把它手上每个在跑的会话 fork 续上（`--resume <编号> --fork-session`）：同一个家目录、同一棵工作树，上下文都在。
  - 切号是整个用户一起切：切号后直接回原会话会被拒「此 session 已绑定另外的ai账号」，所以切的那一刻手上所有在跑的会话都要 fork 续上。
  - 组织编号运行时从 `reclaude org list` 认（team = 拼车、personal = 独享），不写死、不进仓。
- 切过去的会话照样跑完；之后派活时，它们占独享池的名额和额度。
- 切回：拼车用户手上没活、而且过了拼车的清零时刻（被拒原文里带），再切回拼车组织接轻活。
- 独享号的会话用户永远不切。
- 引擎不以会话用户身份直接跑命令：切号走 `deploy/france/fleet-agent-scope.sh` 新加的子命令（root 帮手），参数校验照现有写法。
- 切号、fork、切回都进操作记录，驾驶舱看得到；切号失败才在飞书报警。
- 读不到组织列表、认不出类型、`org use` 失败、fork 续不上：明确失败，不当成切好了。fork 续不上时才照现有办法带接力任务书开新会话。每条都配一个故意造出来的测试。

## 怎么算做完

- 单元测试：假 reclaude 造「被拒 → 切号 → 手上两个会话都 fork 续上 → 跑完 → 过了清零时刻、手上没活 → 切回」全程；上面每条失败路径都有测试。
- 法国真机：拼车号真用满一次时，手上的活切到独享号接着跑完，驾驶舱看得到切号记录；过了清零时刻、手上没活时自动切回。
- 这是 P1 验收的一条（plan.md P1 的验收）。
