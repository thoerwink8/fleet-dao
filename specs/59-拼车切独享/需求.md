# 拼车号用完切独享号、手上的活原地接着干，窗口回来再切回（P3 验收的一条）（#59）

对应计划：v1（母单 #194，创始人 2026-09-27 挪进）
设计依据：design 第九节（一个会话用户，同一时刻只挂一个组织；拼车用完，切独享接着干）、第十节（Claude 订阅一个组织一个账号池）。

## 前提（创始人 2026-09-26 拍）

reclaude 一个账户最多挂 4 台设备（一个家目录算一台），本机和另一台机器已占两台，法国只能占 1 台。所以法国只留一个会话用户跑引擎的全部会话：沿用 `fleet-agent-carpool` 的家目录和登录（名字是历史沿用，不改名免得重新登录），平时挂拼车组织。原先挂独享号的 `fleet-agent-dedicated` 已删；pilot 不登录 reclaude。两个 Claude 池（拼车、独享）不同时跑：会话用户挂着哪个组织，只有那个池能派。

## 要什么

- 拼车额度用满（会话被拒）时：会话用户切到独享组织（`reclaude org use`），再把它手上每个在跑的会话 fork 续上（`--resume <编号> --fork-session`）：同一个家目录、同一棵工作树，上下文都在。
  - 切号是整个用户一起切：这一刻这个家目录下的会话全断（都是无头会话，没人在上面干活）；切号后直接回原会话会被拒「此 session 已绑定另外的ai账号」，所以切的那一刻手上所有在跑的会话都要 fork 续上。
  - 组织编号运行时从 `reclaude org list` 认（team = 拼车、personal = 独享），不写死、不进仓。
- 切过去的会话照样跑完；之后派活时，它们占独享池的名额和额度。
- 切回：按账号级 API Key 读到的拼车窗口恢复时刻（`reclaude-carpool` 读数的清零时刻，读不到再用被拒原文里的），到点切回拼车组织；手上在跑的会话同样 fork 续上。
- 引擎不以会话用户身份直接跑命令：切号走 `deploy/france/fleet-agent-scope.sh` 新加的子命令（root 帮手），参数校验照现有写法。
- 会话用户此刻挂哪个组织，换成读真实状态：已做（2026-09-27，v1 母单 #191 范围里当场修）。原来是常量 `SESSION_USER_ORG = 'carpool'`，09-26 下午人切到独享后引擎还按拼车派、额度记错池；现在选路、路由探针每次用之前以会话用户跑 `reclaude org list`、认带 `*` 的那行的类型（`packages/engine/src/real/session-org.ts`），认不出两个 Claude 池都不派、不探。切号后不用另告诉引擎，它下一次选路就读到。
- 选路里原先给「两个会话用户、两池同时跑」写的备池规则（只接轻活、并发另有上限、排在主池后、额度未知只放一个试探、失败分流 QT1 的备池梯子先换池）随两个会话用户一起作废：端口已一律填主池（2026-09-26 的 PR 起），这里删掉，或改成「拼车用满先切号」。
- 切号、fork、切回都进操作记录，驾驶舱看得到；切号失败才在飞书报警。
- 读不到组织列表、认不出类型、`org use` 失败、fork 续不上、拼车恢复时刻读不到：明确失败，不当成切好了、不当成到点了。fork 续不上时才照现有办法带接力任务书开新会话。每条都配一个故意造出来的测试。

## 怎么算做完

- 单元测试：假 reclaude 造「被拒 → 切号 → 手上两个会话都 fork 续上 → 跑完 → 到拼车恢复时刻 → 切回（在跑的也 fork 续上）」全程；上面每条失败路径都有测试。
- 选路里的备池规则删掉或改成切号，对应测试跟着改（`SESSION_USER_ORG` 常量换成真实状态已做，见上面「要什么」）。
- 法国真机：拼车号真用满一次时，手上的活切到独享号接着跑完，驾驶舱看得到切号记录；到拼车恢复时刻自动切回。
- 这是 P3 验收的一条（plan.md P3 的验收；原在 P1，创始人 2026-09-25 挪到 P3）。

## 现状

切号、切回的最小版已由 #157 做了（2026-09-27）：root 帮手的 `org-use` 子命令、引擎在路由探针每一轮之前判、操作记录和健康检查（见 specs/157 的现状）。

代码已做（2026-09-27，本单的 PR）：
- 切号不再等空闲：切之前把挂着的那个组织的池上在跑的 Claude 会话停下（会话端口 `orgSwitch.stop`，交回失败码 `org_switch`），等它们都收场（最多 2 分钟，登记了还没起来的等它起来再停），再切；等不齐这一轮不切，记没成、写 `session-org:switch` 提醒（`packages/engine/src/real/org-switch.ts` 的 `drain`）。切号的操作记录写明停了哪几个（`stopped`）。
- 停下的会话怎么续：失败分流新规则 OS1（`org_switch`）：马上续同一个会话，不算失败、不进路由失败率、不记重试的账（`budget: 'free'`）。续的时候选路带着原来那条路由，切了号它挡着，照常选到切过去的那个池，会话端口按池判换了池 fork 续上；续上的每个会话记一条 `session-org.resume`。
- 被拒的那个：Claude 订阅池（路由带组织类型）的额度用满（QT1）不原地睡到清零，换成新的一级 `waitRoute`：马上回去选路、续同一个会话等这条路由，切了号就换池 fork 续上；要等超过 6 小时的照旧换池、挂起。原先「备池先换池」的梯子（`backupLadder`）删掉。
- 选路里的备池规则删掉（只接轻活、并发另压到 2、排在主池后、额度未知只放一个试探，连同 `poolRole`、活的轻重、`quota-probe` 试探），对应测试跟着改。
- 测试：`packages/engine/test/real/org-switch-sessions.test.ts` 用真库、真会话端口、真选路、假 reclaude 走完「一个被拒、一个在跑 → 切独享（在跑的先停下）→ 两个都 fork 续上跑完 → 到拼车恢复时刻、手上两个在跑 → 停下、切回拼车 → 两个都 fork 续上跑完」；工作流那一层（`subtask.test.ts`）验被拒后不睡到清零、切了号换池续上；停不齐、停下后续不上（fork 续不上走接力任务书，#50 的判法）等失败路径各有测试。
