# #554-2 测试移出会话：done-check 看 PR CI 而非会话自报（#592）

对应计划：v3 三段一条龙
设计依据：specs/577-554-1-headless-runner/结果.md「欠的东西」第 1 条；docs/goals.md；母单 #554

创始人 2026-10-02 原话：「流程不要想得太复杂」「重做的是那套流程太复杂」。552-554 各张切片都把「跑哪测」那一条从会话里拿走。

AI 理解：554-1 交付了「无头一次性子进程不在会话里跑测试」的骨架；本切片把「交活核实」从「会话最后一次跑测试的绿」改成「这张 PR 的 CI 全绿」。是「测试由 CI 跑、会话里不跑」正式落地前的最后一刀。

## 场景

v3 三段一条龙里，写码的无头进程（manual 段）只交提交和 PR。done 的核实不该再问「你这次会话里跑没跑过仓的测试命令、跑成没有」，而该问「**这张 PR 的 CI 现在是不是绿**」。

`packages/api/src/done-check.ts` 现在还看 `lastSessionTest.passed === true`（Fusion 时代的判法）。本切片把判法翻过来：**读 `pull_requests.checks` 的汇总**（mirrorChecks 已经把必过检查合成 success/failure/pending/none）。

## 原话

创始人 2026-10-02：「我觉得先做简单点吧，流程不要想得太复杂」。

554-1 结果.md「还欠什么」第一条：「会话结束后现算 PR#、真 changedFiles，再调 judgeManual」——交活核实这一端也变成「看 PR」，不写 runner 内部。

## 改什么

1. **`packages/api/src/done-check.ts`**：判 done 改成两种入口：
   - 调用方带了 PR 编号（主流程、554-1 之后是常态）：**判 done = 这张 PR 的 CI 全绿**（`pr.checks === 'success'`）。CI 红的权当核实不过（422）；CI 没跑完（pending）、一条必要检查都还没出现（none）、PR 镜像库里还没有，都是 not_verifiable_yet（409）。
   - 没带 PR 编号（Fusion 旧流程「会话只在本地提交、PR 引擎后开」还没拔完，不改 `packages/engine/src/workflows/`）：**保留** 旧判（`lastSessionTest`），不动。
   - **不拿空当绿**：拿不到 PR 镜像、CI 还没起，都不能当成功。

2. **`packages/engine/src/real/prompts.ts`**：写码阶段提示词**删掉**「交活只认原样跑 test:changed」一句（在 codeBlock 里），改成「测试由 CI 跑，会话里不跑」。

3. **不动**：
   - `packages/engine/src/real/flow-gate.ts`（起会话前的 testCommand 链路）：554-2 不拔，之后 556-4 再动。
   - `.fleet/flow.json` 的 `testCommand` 字段：556-4 的事。
   - `packages/engine/src/real/sessions.ts`：554-2 不接入。

## 怎么算做完

1. `packages/api/src/done-check.ts` 改判；判法如上。
2. `packages/engine/src/real/prompts.ts` 删掉「原样跑 test:changed」一句，写码阶段提示词改成「测试由 CI 跑」。
3. 测试 `packages/api/test/done-check.test.ts`：
   - 带 PR + `checks='success'` → `ok: true`，即便 `tests` 全空。
   - 带 PR + `checks='failure'` → 422，reasons 里点出这张 PR 的 CI 是红的。
   - 带 PR + `checks='pending'` / `'none'` → 409 not_verifiable_yet。
   - **故意造红**：带 PR 编号但 PR 镜像库里是 null → 409 not_verifiable_yet（**不当成功**）。
   - 旧路径（无 PR 编号）→ 原判法不动（已有测试不动）。
4. `pnpm exec vitest run packages/api/test/done-check.test.ts` 全绿。
