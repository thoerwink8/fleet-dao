- 起因：需求方 2026-11-15 提了：magpie 集中到法国 VPS、各机一套 key；fleet-dao 和 vault 是否弃用改 fleet-ade 加新仓

## 一、提出的问题

### 1. magpie 集中到法国 VPS，各台机器经香港用一套 key

- **现象**：模型网关 magpie 只装在本机，路由组（工程组、grok 池、GPT 池、Luna 池）、渠道 key、插件、指令库都只在这台；换一台机器或让 VPS 上的 fleet-ade 用，要整套再配一遍（实测：配置在本机 `~/.config/magpie`）。
- **根因**：模型渠道的配置没有单一来源，每台机器各自维护。
- **需求方的思路**：magpie 放到法国 VPS 当唯一网关；各机器经香港 VPS 用 key 访问；本机只再加一层本机独有的（reclaude 的 Claude、Antigravity 的 Gemini），公司电脑再加公司 key。订阅号（Grok、Cursor、Devin）也放到 VPS 上。
- **判断**：成立，而且比「每台各装各同步」更好：路由组和 key 只维护一份；订阅号只在一个出口 IP 登录，比本机和 VPS 两处同时登录更不容易被风控。出口放法国、香港只当通道是对的，多数上游不服务香港地区（推断，未逐家核对）。要补四件事：
  1. **单点**：法国挂了所有机器都没模型。本机那层 magpie 兼当兜底：远端不通时走本机直连的中转站 key。
  2. **延迟**：本机 → 香港 → 法国每次请求多一段往返（推断约 200 毫秒，要实测）；智能体一件活几十上百次请求，总时长会变长。
  3. **暴露面**：法国 magpie 的网关只在 WireGuard 内网可达，不开公网；每台机器发独立 key，可单独吊销（magpie 有调用方 key，按代码：本机有 `caller-keys.json`）。
  4. **公司数据边界**：公司电脑走个人 VPS 和个人中转站，公司的代码、对话会经个人设施出去，需求方拍（见第五节）。
- **做法**：法国装 magpie 网关模式（实测：`magpie web --gateway` 是只开网关、不要界面的模式），配置用 magpie 自带的加密 GitHub 同步拉齐（实测：`magpie github on github://<owner>/<repo>`，只传口令加密后的文件，可选带订阅登录 `sign-ins=yes`）。本机 magpie 加一个「远端 magpie」提供方，路由组指向它，本机直连 key 留作兜底。先拿一个路由组试点，量延迟和稳定性。
- **不做什么**：Antigravity（Gemini）不上 VPS，只在本机经 agy 用（防封）；Claude 不经 magpie，仍只走 reclaude；不开公网端口。

### 2. 弃用 fleet-dao 和 vault 仓，改 fleet-ade 加一个新仓

- **现象**：fleet-dao 现在同时承担：规矩、技能、钩子，经 `agents:sync` 装到各机；开单、开 PR、合并闸；创始人引导和进度账本；法国引擎和驾驶舱（只修不加，决定 0126）。vault 放各机器连接方式和凭证（按仓里文档）。
- **根因**：fleet-dao 最初是规矩库加引擎，后来产品挪到 fleet-ade（决定 0126），留下的职责散在多处，有的还在跑生产（引擎、驾驶舱、账本）。
- **需求方的思路**：fleet-dao 和 vault 弃用，只留 fleet-ade 加一个新仓。
- **判断**：方向成立，但要分步，不能先停：
  - 法国引擎、驾驶舱、账本在跑，按决定 0126 引擎要分三步迁进 fleet-ade，迁完前 fleet-dao 不能停。
  - 规矩、技能、指令、MCP、记忆，magpie 资源库本来就能写进每个智能体（实测：`magpie library` 显示指令、技能、MCP 已下发给 claude、codex、grok、pi 等），加上加密 GitHub 同步，能取代 `agents:sync` 的大部分。Claude Code 专用的钩子（守卫、无人值守）要看 magpie 资源库的 Hooks 能不能承接（未核实）。
  - 「新仓」放：magpie 加密配置、装新机器的脚本（omp 锁版本安装、mirasim 的 omp 接法、WireGuard 接入）。不放代码。
  - vault 里的凭证分两类：模型 key 进 magpie 加密配置；SSH、WireGuard 等基础设施凭证还要一个去处（未定，见第五节）。
- **做法**：见第六节三批。弃用一律是归档（只读、可恢复），不删仓。
- **不做什么**：不在引擎迁完前停 fleet-dao；不删历史决定和单。

## 二、另外查出来的

- **订阅号上 VPS 的风控**：订阅号登录放到法国机房 IP，有的服务会把机房 IP 当可疑（推断）。试点时先只放一个订阅号观察。
- **Linux 无桌面下的订阅登录**：Cursor、Grok、Devin 这些在 magpie 里是登录态，能否经加密同步带到 Linux 上直接用，未核实。

## 五、要拍板的

1. **「新仓」放什么**：建议只放 magpie 加密配置和装机脚本，不放代码；备选：把规矩原文也放进去（magpie 资源库读它）。不定的话第二批没法开工。
2. **公司电脑**：建议公司项目只用公司 key、不经个人 VPS；备选：全部统一经法国 magpie（公司数据会经个人设施出去）。不定的话公司电脑先不接。
3. **第一批试点现在开做**：法国装 magpie 网关、本机接一个路由组试，量延迟和稳定性，可撤回、不碰在跑的引擎。建议做。
4. **基础设施凭证（SSH、WireGuard）去处**：建议放新仓、用同一口令加密；备选：留在 vault 直到引擎迁完。
