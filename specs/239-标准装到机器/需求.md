# 标准装到机器：只认主线发布的签名版本，按版本装、报到驾驶舱、能卸载、坏版本自己退回（#239）

对应计划：未排期
设计依据：`docs/design.md` 15.7 第 8 条；方案 `specs/195-项目与标准/方案.md`

创始人原话（2026-09-27）：「这种都是属于 自上而下的机制，其他项目也要能复用；其他项目怎么复用，我希望你还是能仔细思考个合适方案，有很多边界，我随便举几个 1. 机器上有fleet-dao，能自动同步机制吗？ 2. 机器上有fleet-dao，但是不是最新版 3. 机器上没有fleet-dao，但是想从驾驶舱在本机快速配置好 4. 机器上想给特定项目清除同步机制 等等」。帅位出了方案，GPT 挑过一轮，创始人选 1：「按这个方案做，排在 v1 之后」。

AI 理解：标准里「机器那半」（通用规矩、技能、钩子、命令行工具）要从「开发机开会话时拿本机的 fleet-dao 检出去同步」改成「只认主线上发布、签过名的标准版本」。每台机器按版本装、到驾驶舱报到、能卸载还原，坏版本自己退回上一版。项目那半（体检、补齐 PR、`.fleet/standard.json`）归 #132、#133。方案全文在 `specs/195-项目与标准/方案.md`。

## 要做什么

- 发布：每合进一个改标准的 PR，机器人打一个带签名的标准版本 std-N，写明这版改了什么。
- 装：每台机器上有一个小工具（暂叫 `fleet std`），按版本拉取、验签、并排装、自检、原子切换，然后记账、报到驾驶舱。
  - Claude Code 走官方插件：fleet-dao 仓就是插件市场。
  - 别家照旧写受管块。
  - 一份清单写清每一项归哪种装法，同一个文件不许两套都管。
- 一键加电脑：驾驶舱给一行命令，带一次性配对码。
- 退出和卸载：
  - 某个项目退出，由它自己的仓里的 `.fleet/standard.json` 决定（归 #133）；机器这头看到就不管它。
  - 只在某一台机器上不管某个项目：本机记一条，驾驶舱标出来。
  - `fleet std remove` 撤干净，照备份还原。
- 防坏版本：
  - 装完自检不过就自动退回上一个健康版本；
  - 钩子连续失败自动跳过；
  - 有不依赖钩子的 `safe-mode` 和 `rollback` 命令，断网也能用；
  - 驾驶舱能撤回某个版本，不让它继续往别的机器扩散。
- 实验模式：开发 fleet-dao 时可以装没发布的标准。要记下提交号、谁开的、到期时间，驾驶舱标「未发布实验版」，这台不算合格，也不许被别的机器或项目引用。

## 怎么算做完

- 合进一个改标准的 PR 以后，自动出 std-N：带签名，附改了什么。
- 新机器照驾驶舱给的一行命令装好，1 分钟内驾驶舱里出现这台，状态「最新」。
  - 配对码过期、没装 node、连不上 GitHub，都各自照实报错，不装一半。每种各配一条故意造出失败的测试。
- 已装的机器：开会话时、每小时各跟一次新版本。
  - 离线的照旧用上次装好的版本干活，驾驶舱标出最后报到的时间。
  - 拉不到新版本时报「没查成」，不当成最新。
- 清单里每一项只有一种装法：测试钉住，同一个文件被两套都管就拒装。
- 签名不对、或者不是主线发布的版本，就拒装并报警。配一条故意造出假版本的测试。
- 坏版本：
  - 故意发一个装完自检不过的版本：机器自动退回上一版，驾驶舱标红；
  - 撤回以后，别的机器不再装它；
  - 钩子连续失败会被跳过；
  - `safe-mode` 和 `rollback` 断网也能用。
- `fleet std remove` 以后，各家全局说明、技能目录、钩子、插件都和装之前一样（逐项读回）。
- 实验模式装的机器：驾驶舱标「实验版」，不算合格，到期自动回到正式版本。
- 法国的几个会话用户各装一份、各自报到。本机和法国都跑通以后，退役 `agents-sync --apply` 的人手用法，并改掉 AGENTS.md、design、ops 里的旧说法。
