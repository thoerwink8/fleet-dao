# 建议筛子第一片：只读库存和每周进度

单 #3587；方案 PR-B 的「只记数据、不进 pnpm check、不变红」是本片口径。方案前文提到的必过登记检查不在本片实施。

## 交付

- `packages/conventions/guards.json` 以 2026-10-23 为库存基线，回填 43 个顶层 hook 文件、11 个 workflow 文件、3 个 `reconcile-checks.ts` 静态报警前缀。文件数是库存单位，不是逻辑护栏数量，更不是有效拦截数。
- 每条包含 evidence、proposer、expires、keepIf、hitSource、一进一出或保留理由。存量明确写「存量未自证」，来源 unknown、命中来源 null；统一 2026-11-22 到期。登记不是补出了有效性证据。
- `pnpm exec node packages/conventions/src/bin/guard-inventory.ts` 现读库存；读不到目录、源码或登记表，明确 unknown / 没查成，退出 2。已知空目录才是 0。缺证据、未登记增量和到期条目只展示，既不拦 PR，也不自动删东西。
- 复用每天的 `github-audit.yml` audit job，在原对账前增加一个 `continue-on-error` 报告步骤。报告写进运行摘要；周一 UTC 的这一轮把同一报告记到 #1055，按当天标记避免顺序重跑重复写。沿用工作流原 concurrency，不增加任务、定时器、表、报警或自动开单。原对账的 0/1/2 判法不变。
- 净变是「本次实际库存 − 登记基线条目数」，明确标注基线日期，不冒充滚动一周净增。改动登记条目会改变比较基线，复审时须同时更新 `asOf`。

## 删减案例和保留的业务规则

PR #3599 已按决定 0114 删除 `audit-alarm.ts` 自动开单层；原有 GitHub 对账、各单留言和失败退出仍保留。删除候选及近 14 天量化在原方案；没有有效来源或拦截证据的数字仍为没查成，不补零。

## 核验和边界

- 内存仓测试覆盖实际新增/删除、已知空目录与读失败、坏登记表、静态/动态报警表达式、未接命中、到期不自动删除、证据和元数据缺口。
- 周报测试覆盖非周一不读写、周一报告含未知、当天重复不再写、跨周继续写、读失败不冒空、写失败不冒成功。
- 本机实跑零安装入口、相关测试、conventions 包类型、格式和卫生检查；首次全仓类型受依赖未就位时的增量缓存影响，依赖就位后 `pnpm typecheck --force` 重建通过，完整检查仍交 CI。周一的真实定时发送须等首次计划运行，当前测试不代表通知必达。
- command 可登记但没有自动扫描口径；hook 内部新分支、规则文案等不在文件库存计数里。报警只支持静态字符串 `const` 声明，不支持的声明报告未知。
- 命中计数、自动到期复审、推测候选池、冷验收规则调整属于后续方案 C/D/E，本片没有做、没有改变现有准合或验收责任。

## 依据和成本取舍

查阅日期：2026-10-23（北京时间）。

- [Google SRE：Eliminating Toil](https://sre.google/sre-book/eliminating-toil/) 把随业务线性增长、重复且没有持久收益的操作列为 toil，并为运营工作设置时间预算。本片据此先让库存和未知可见，复用现有轮次，避免给每个 PR 再增加登记税；文件库存不能证明节省了多少 toil。
