## 要什么

1. **引擎自己拉单**：一个 Temporal Schedule 每 5 分钟起一轮，对每个开了「让 AI 接活」的仓，到 GitHub 现读当前版本里程碑下的开着的单，过 `dispatchDecision` / `autoDispatchGate` 那几道（开关、当前版本、不是母单子单、没贴「本机做」），再过三栏齐不齐，对每张能派的单起一个 `taskWorkflow`（工作流编号按仓和单号定死，同一张单不会起两条；做完的、停下的不会自己重来，要人在驾驶舱点「继续」）。
2. **`taskWorkflow`**：读单子和需求文档拼出交代 → 按「已知的模块」一次定档、挑路由 → 起动手进程写码 → 推分支开 PR → 等 CI（红了带着失败日志回去改，最多 3 轮）→ 合之前验收冷调用（换家族；没过带着问题表回去改，最多再 1 轮）→ 合并 → 关单 → 每段一行记 `runs`。额度满挂起到清零换路由接着干；进程死、网络断原地重跑；同一个原因连着挂 2 次停下报创始人并写出每次原文。
3. **把无头会话接到真执行体**：生产 Spawner 经 `UserExec` 以会话用户身份在受限 scope 里起命令；各家执行体的无头启动命令按路由挑。
4. 合并之前的人闸（改标准、删数据、碰安全要第二意见）照旧由合并闸挡着，工作流只负责等、报，不绕。

## 怎么算做完

1. 演练仓里一张带三栏的小单，**没人插手**从被拉起跑到合并、关单，连续 3 次（#452）；每一步用时和停在哪一步看得到。
2. 故意造出的失败，每条一个测试：读不到单子 / 三栏缺 → 不派并写清缺什么（不当成可派）；拉单读不到 GitHub → 报没查成，不当成「没有单」；同一张单被拉两次 → 只起一个工作流；动手进程没产生真提交 → 明确失败不开 PR；CI 红 3 轮仍红 → 停下报；验收读不到 diff / 单子 / 作者族 → 失败不放行；额度满 → 挂起到清零再接着干；同一原因连挂 2 次 → 停下报并写原文；碰人闸 → 停下等人，不自己合。
3. 一张单的交接 ≤ 2 次（对题→动手、动手→验收），任何时刻常驻进程 0 个，单会话内存 ≤ 0.5G（`runs` 里记着，没读到的标没读到，不记成 0）。
4. 旧的接活（`issue-intake.ts`、认领、Fusion 的 core 状态机）在同一批 PR 里删干净（#556），不留开关、不并存。
