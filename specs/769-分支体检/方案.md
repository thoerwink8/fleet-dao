# 分支体检（#769）方案

## 业务说明

- **替谁、干成什么**：远端分支是几台机器（本机 Claude 工作树、法国引擎、另一台机器上人手开的会话）推上来的。合并了的有仓库设置 `delete_branch_on_merge` 自动删；没合并的（关掉没合的 PR、从没开过 PR、合并后又动过）没人管，攒多了就要创始人一条条拍（#654 剩 31 条）。要一个每天自己跑的机制：GitHub 上的现状说了算（不靠哪台机器的本地状态），能判的机器自己判、自己删，删了会丢东西的才列给创始人勾。**干成的标志**：远端只剩在做的、有人提到的、创始人定了留的；创始人只在一张固定的单上勾选，不用敲命令，也不会被同一条问第二次。
- **业务规则**（出处）：
  1. 默认分支、受保护分支不碰；开着的 PR 的分支（当头或当目标分支）不碰——同类工具全这么做（见下「对照」）。
  2. 有已合并 PR、分支头就是合并时的 PR 头 → 删：内容全在主线和 `refs/pull/N/head`（决定 0009 第 104 行；#654 H 已按它删了 426 条）。
  3. 被开着的单、开着的 PR 的标题、正文或评论提到 → 留（创始人 2026-10-04 原话「要看 GitHub 的 issues 区和 PR 区到底有没有这个远程分支」）。分支体检自己写的清单（巡检单、带 `fleet:branch-hygiene` 记号的留言）不算提到。
  4. 删了会丢东西的（有主线上没有的改动）不经创始人点头不删（人闸「删数据」）；删了不丢东西的（改动是空的、或每个文件的这个版本主线历史上有过）机器自己删。
  5. 读不到 GitHub、读回来认不出：报「没查成」，不当成没有；整份清单读不到就一条不删（底线）。
  6. 结果随时间、随单子开关变：只跑在定时任务里、不挡 PR（#87、#299）。

## 对照（2026-10-04 查）

| 做法 | 出处 | 我们取什么 |
|---|---|---|
| 没有开着的 PR、不是开着 PR 的目标分支、不受保护、不在忽略名单、最后一次提交超过 N 天 → 删；默认只演练 | [cbrgm/cleanup-stale-branches-action](https://github.com/marketplace/actions/cleanup-stale-branches-action)、[phpdocker-io delete-abandoned-branches](https://github.com/marketplace/actions/delete-abandoned-branches)、[int128/stale-branch-action](https://github.com/int128/stale-branch-action) | 前几条照搬；「默认只演练」照搬（本机手跑默认不删，`--delete` 才删） |
| 先在最后一个提交上留言提醒，过几天再删 | [fpicalausa/remove-stale-branches](https://github.com/marketplace/actions/remove-stale-branches)、[crs-k/stale-branches](https://github.com/marketplace/actions/stale-branches) | 不照搬：提醒发给提交人，我们的提交人是机器人和创始人自己的号；改成列到一张单上 |
| 一张固定的单，机器人维护正文，人勾选框批准，下一轮照做 | [Renovate Dependency Dashboard / dependencyDashboardApproval](https://docs.renovatebot.com/configuration-options/) | 照搬：巡检单正文一条分支一行，勾「删」「留」 |
| 合并后自动删分支 | [GitHub 文档：自动删除分支](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-the-automatic-deletion-of-branches) | 已开（#654 H 复核 `delete_branch_on_merge=true`） |

**和同类不同的地方**：同类工具只看「多久没动」，到期就删，不管里面有没有别处没有的东西；我们多一道「有没有产出」，删了会丢东西的交给人勾——因为删数据是人闸。

## 判法（一条分支从上往下，命中就停）

| 顺序 | 条件 | 判 |
|---|---|---|
| 1 | 默认分支 / 受保护 | 留 |
| 2 | 开着的 PR 的头（本仓的）/ 开着的 PR 以它为目标分支 | 留 |
| 3 | 巡检单上勾了「删」，勾的那个头就是现在的头 | 删（人定的） |
| 4 | 巡检单上勾了「留」，勾的那个头就是现在的头 | 留（人定的） |
| 5 | 开着的单或 PR 的标题、正文、评论提到它 | 留 |
| 6 | 有已合并 PR，分支头就是合并时的 PR 头 | 删 |
| 7 | 内容读不到（本地没有这个提交、git 跑不成） | 没查成 |
| 8 | 没产出，最后动静 ≥ 14 天 | 删 |
| 9 | 最后动静 < 14 天 | 留（还在做） |
| 10 | 有产出（或和主线没有共同祖先，判不了） | 等人定 |

- **有没有产出**：分支比主线多出来的改动＝`git diff <和主线的分叉点> <分支头>`（只算分支自己的改动）。是空的，或改到的每个文件的这个版本在主线历史上出现过（删掉的文件主线上现在也没有）→ 没产出。「历史上出现过」照顾「合进去以后主线又改过这个文件」的情况。只看提交说明写没写 WIP 不算：WIP 提交里有别处没有的改动，照样是产出。
- **最后动静**：分支头那个提交的提交时间、GitHub 动态记录（`/activity`）里这条分支最后一次推送，取晚的那个。
- **谁开的**（写进理由，给人定的时候看，不改判决）：分支名（`worktree-agent-*` 本机 Claude 子代理的工作树、`fleet/<号>-t…` 法国引擎三段任务、`fleet/<号>-f…` 法国引擎 Fusion）、动态记录里谁建的、谁推的（`fleet-dao-agent[bot]` 是法国引擎；`thoerwink8` 是创始人的号，本机和另一台机器都用它，分不出哪台）、提交作者和 `Co-Authored-By` 里的模型。都认不出写「不知道谁开的」。
- **关掉没合的 PR 的分支**：删了以后在那个 PR 页面上点「Restore branch」就能恢复（[GitHub 文档](https://docs.github.com/articles/deleting-and-restoring-branches-in-a-pull-request)），理由里写明，方便创始人定。

## 跑在哪、怎么跑

- 逻辑在 `packages/conventions/src/branch-hygiene.ts`（判法、巡检单正文的写和读）和 `branch-git.ts`（内容那几样从本地 git 读）；GitHub 读写加在 `github-api.ts`；入口 `src/bin/branch-hygiene.ts`。
- 每天：`.github/workflows/github-audit.yml` 新加一个 job `branches`（和查单子的 `audit` 分开，只有它要 `contents: write` 删分支）：检出全部历史（`fetch-depth: 0`），跑 `branch-hygiene.ts --delete --board`。
- 本机：`pnpm branch:hygiene` 只打判决不删（先 `git fetch origin`）；`--delete` 删、`--board` 写巡检单。
- 删：删之前再读一次分支头，和判的时候不一样就不删（下一轮重判）；一条删失败记下来、接着删别的。
- 巡检单：带 `<!-- fleet:branch-hygiene board -->` 记号的那张开着的单，没有就开一张（贴「杂项」、不挂版本）。正文每轮重写：等你定的（每条两个勾选框：删 / 留，不再问）、定了留着的、上一轮删掉的；新进「等你定」的另在单上留一条言（单子正文改了 GitHub 不发通知）。
- 退出码：0 正常（有等人定的也是 0：那是排着的事，不是坏了）；1 有删失败的；2 没查成（读不到、认不出、巡检单没写成）。

## 代价表

| 方案 | 代价 | 风险 |
|---|---|---|
| **从零（本方案）**：判法 + 内容比对 + 巡检单勾选 | 一个 TS 模块、一个 job；每天约 100–150 次 API | 内容比对写错会误删有产出的分支：每条判法配故意造出失败的测试；关掉的 PR 的分支还能在 PR 页面恢复 |
| 现状：一次性脚本 + 每次请创始人拍 | 每攒一批就要人拍一次 | 没人跑就一直攒；创始人不知道怎么判 |
| 更重：同类工具（到期就删） | 装一个第三方 action | 有产出的也删，过不了「删数据」人闸；第三方 action 要审 |

## 已定（我拍的，理由）

- 有等人定的不把定时任务标红：那是排着等人的事；标红留给「机器自己坏了」（删失败、没查成），免得天天红、红了没人看。
- 「有产出、还新（< 14 天）」判留、不问：在做的活不打扰人。
- 只认「开着的」单和 PR 提到：关掉的单提到的分支，那件事已经结束了。

## 要创始人定的（经指挥官转）

- 关掉没合的 PR 的分支，删了能在 PR 页面一键恢复：要不要也让机器过了 14 天自己删（不再列给你）？本方案先按「有产出就问你」做。
