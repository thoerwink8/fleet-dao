- 状态：讨论中
- 单：#3752
- 起因：创始人 2026-10-30 定了整个 VPS 驾驶舱（`packages/web` 和 `packages/api` 面向页面的部分）要重写。交互照会话工作台的样子做（左边会话列表，点进去看全文、接着说话），网页和手机都能用；任务面板照「波次图」做：按依赖分波，一格一个子任务，点进去到对应会话；功能参照「指挥官拆单、派工人、看进度」。旧设计逐项讨论怎么改，不是推倒不看。

- 代码版本：`b7a2b21c2`（origin/main）

**代码量**：`packages/web/src` 下非测试源码 299 个文件，其中 `routes/` 25 个、`components/layout/` 77 个、`components/ui/` 21 个、`components/shell/` 9 个；e2e 用例 18 个文件。

**驾驶舱用的不是 Arco 组件库**：全仓没有 `@arco-design` 依赖，是照 Arco 的数值复刻了令牌和样式（`app.css` 文件头），组件自己写（底下 Radix，上面 `components/layout`）。

**后端已经有、能直接用的**：

- **全局实时推送**：整个进程一条 Postgres LISTEN 连接，经 SSE 推「哪张表、哪一行变了」，页面自己回库重拉；断线带 `Last-Event-ID` 补发，补不全发 resync（`packages/api/src/sse.ts`、`changes.ts`）。推送的表清单在 `packages/shared/src/realtime.ts` 的 `REALTIME_TABLES`，不含 `run_transcript`。
- **会话全文**：`runs`（`packages/db/src/schema/runs.ts`）一笔会话一行；`run_transcript` 一条记录一行，主键 `(run_id, seq)`，读接口已能分页（`packages/api/src/run-transcript.ts`，带 `after`、`limit`），一笔最多 3000 条。
- **指挥官对话**：`request_chats` 一条需求一个指挥官会话，存会话号，每轮按「上次看到的消息」续上；回话流每 500 毫秒查一次库再推（`request-routes.ts` 的 `COMMANDER_STREAM_POLL_MS`）；原话逐条在 `request_messages`。
- **决策卡**：`notifications`，库里约束「要你拍」级必须带至少两个选项和原因；回答接口带代次和 CAS；未处理的有局部索引 `notifications_open_idx`。
- **子任务依赖图**：`subtasks`、`subtask_deps`（`packages/db/src/schema/work.ts`），表注释「子任务只在引擎里，不开 issue」，和 0122 决定 1 一个意思；引擎快照会写这两张表。
- **单**：`tasks` 表注释「需求：一张 GitHub issue 一行」，库里「任务」就是「单」。
- **本机会话心跳**：`node_sessions` 只有元信息，没有全文。
- **事件账本**：#3739 第 1 片（PR #3747）用 `audit_log` 里 target 以 `issue:` 开头的行当账本，按 `id` 往后读，配局部索引 `audit_log_issue_events_idx`。
- **PWA**：能装成应用（`manifest.webmanifest`、`sw.js`），但 service worker 不收推送，`lib/pwa/notify.ts` 写明「不走谷歌推送（国内 FCM 不稳）」。

**和新方向冲突的现行规矩**：

- 0121 第 4 条「首页三块常驻」。0121 写「决定 0093 定的就是这三块」，可 0093 正文里没有「三块」「首页」「主页」。真正管着首页的只有 0121 第 4 条和 `docs/design.md` 15.1。
- 界面规范第三节「工作台」「任务页」两小节按旧版式写，「资源页」一节随页面删。
- `docs/design.md` 第十五节写「支持多套主题色」，界面规范第一节写「主题只有一套」，旧矛盾这次一起收。

## 二、另外查出来的

- 驾驶舱没用 Arco 组件库，只是照 Arco 的数值复刻了令牌和样式（`app.css` 文件头），组件自己写。
- 决定 0121 说「首页三块」是决定 0093 定的，0093 正文里没有这个说法。
- 法国库 `subtasks` 几乎是空的：拆成两个以上子任务的单只有 1 张，波次图现在没料（见第七节）。
- 香港门面只走 HTTP/1.1，同一域名最多 6 条连接（见第七节）。
- 会话在库里分三处存（`runs`、`request_chats`、`node_sessions`），没有统一索引。

## 三、根因归拢

| 根因 | 管到的问题 |
|---|---|
| 驾驶舱按「表」长出来，一张表一页，没有以「谁在干活」为中心的主视图 | 17 页里 6 页是同一件事的不同切面（任务、任务页、会话抽屉、提需求、通知、工作台的在跑），看全一张单要跳几页 |
| 「会话」在库里分三处存（`runs` 加 `run_transcript`、`request_chats` 加 `request_messages`、`node_sessions`），没有统一索引 | 没法有一个「所有会话」列表；首页的在跑要在内存里拼两个来源 |
| 实时推送只有「哪张表、哪一行变了」一种粒度 | 会话全文要么不实时，要么像提需求那样每 500 毫秒查一次库 |
| 概念随功能一层层加（节点、笔、用途、池、路由） | 一个词两个意思（节点），一个东西三个名字（单、任务、需求） |

## 五、要拍板的

### 总设计

#### 1. 一级信息架构：五块

| 一级 | 地址 | 是什么 | 从旧页面接收什么 |
|---|---|---|---|
| **会话工作台**（首页） | `/`、`/s/:sessionId` | 左边会话列表，按最后活动排，置顶「待你拍 N」；中间会话全文；底下输入框，只对指挥官会话出现；右边可收起的侧栏，放这个会话挂的单、PR、改动文件、用量 | 工作台的「在跑的」、会话全文、提需求页、任务页「用量与模型」页签 |
| **任务波次图** | `/work`、`/work/:repo/:issue` | 左边开着的单；右边选中单的波次图：一列一波，一格一个子任务，写标题、状态、工人渠道、用时，点格子进对应会话 | 任务列表、任务页的结论块和「这一回合走到哪」；改动文件进格子详情 |
| **决策卡** | `/decide` | 只放「要你拍」和没人接的卡住报警，一张卡一件事：选项按钮、推荐、自己输入；拍完折叠，结果写回单的评论 | 通知页、工作台的「要你拍的」「卡住报警」、设置里的「提醒」 |
| **法国运维** | `/ops` | 运行概况、引擎开关、版本与发版、机器、资源、定时任务、发布记录、操作记录 | 法国、资源、定时任务、发布记录、操作记录、工作台的「最近上线」「系统状态」 |
| **设置** | `/settings` | 仓库、渠道表（含额度）、角色表、路由规则、账号 | 设置、额度、路由、路由状态 |

**手机**：宽度小于 768 时，会话工作台变成两个画面：列表一个，点进去是全文加输入框，左上角返回。底部四格：会话、任务、决策（带件数）、更多（运维、设置）。和 0090 第 2 条一致。

**老链接**：`/tasks/:id`、`/tasks/:id/runs/:runId`、`/intake?r=`、`/notifications` 做跳转，通知正文里存着大量旧链接（`notifications.link`），不能断。

#### 2. 概念收敛

| 旧词 | 新世界里是什么 | 怎么处理 |
|---|---|---|
| **单** | GitHub 上一个可验收的目标（0122 决定 1） | 留，界面只用「单」 |
| **任务** | 库里 `tasks` 一行，就是一张单 | 界面删掉「任务」这个词；`t-12` 只留在库里，地址用 `仓/单号` |
| **需求** | 提需求页的一条对话（`requests`） | 变成「指挥官会话」，开出单后挂在单上 |
| **子任务** | 一张单拆出来的一步，只进账本、不开单 | 留，就是波次图里的一格，用现有 `subtasks`、`subtask_deps` |
| **节点** | 两个意思：任务拆出的步骤；代码里 `/nodes` 指机器 | 拆名：前者一律叫「子任务」，后者一律叫「机器」；`/nodes` 接口名先不改，界面和文档改 |
| **会话** | 一段 AI 对话，有角色（指挥官、工人、复核）和渠道 | 做成一级；旧任务页的「笔」就是会话，「笔」这个词删掉 |
| **回合** | 返工的一轮 | 降成会话侧栏里的分组 |
| **工人** | 会话的一个角色 | 删掉独立概念，进角色表 |
| **渠道** | 创始人真有的付费入口：reclaude 的 Claude、Grok、DeepSeek API，以后可能 Devin | 留，渠道表只列真有的 |
| **账号池** | 渠道下面的一份额度 | 收进渠道详情；表照旧 |
| **额度** | 池的窗口余量 | 并进渠道行，不再单独成页 |
| **用途** | 动手、动手·界面、验收…… | 换成「角色」：指挥官、工人、复核，绑到渠道 |
| **路由** | 渠道加池加模型加执行方式 | 降成「路由规则」：快档、好档这类可拆的规则，挂在角色下面，不写死 |
| **看门狗** | 卡住自动修的机制 | 界面不出现这个词，它的卡就是决策卡里的「卡住报警」 |

#### 3. 后端

**照旧用的**

| 东西 | 新用途 |
|---|---|
| `notifications` 加回答接口 | 决策卡，契约不动 |
| `runs` 加 `run_transcript` | 工人、复核会话的全文，分页接口照旧 |
| `request_chats` 加 `request_messages` | 指挥官会话的全文和续会话机制，先照旧 |
| `subtasks` 加 `subtask_deps` | 波次图的数据 |
| `audit_log` | 操作记录，加上 #3747 起的开单账本（target `issue:` 开头的行） |
| `/api/events` 全局 SSE | 照旧，列表、决策卡、波次图收「哪行变了」再重拉 |
| PWA（manifest、sw） | 照旧，补推送 |

**要新建的**

1. **会话索引表 `sessions`**：一个会话一行：会话号、角色、渠道、挂的单和子任务、状态、开始时刻、最后活动时刻、最后一句摘要、来源（`runs`、`request_chats`、以后的 harness 指挥官）和来源主键。在 `runs`、`request_chats` 写入时同一事务一起写，老数据回填一次。列表只读这张表，按 `(last_activity_at desc, id)` 键集分页。不用视图拼三处：拼出来的结果没法用一个索引分页，每翻一页三张表各扫一遍。
2. **账本里的子任务事件**：拆子任务、派工、交付、观测照 0122 写进账本；子任务当前状态由账本推出来写进 `subtasks`（投影），波次图读投影，不回放账本。账本先沿用 #3747 的做法（`audit_log` 的 `issue:` 行）。要留意：`audit_log` 的 `actor_kind`、`via` 是固定枚举（`packages/db/src/schema/enums.ts`），没有指挥官、工人、复核这几种；配置操作和账本混在一张表，两种查询靠局部索引隔开。子任务事件量上来、或枚举不够用时，再拆独立账本表（第五节第 7 条）。
3. **会话全文的实时流**：在现有 `/api/events` 上加订阅参数 `?watch=session:<id>`，切会话时带新参数重连；后端收到「某会话来了新记录」只推给订阅了它的连接，推 `seq` 大于上次的那几条，SSE 的 id 用 `seq`，断线带 `Last-Event-ID` 接着补。不用 WebSocket：上行本来走 POST，下行 SSE 够用，现在已经过香港门面在跑，浏览器自己会重连。不每个会话一条连接：门面要是 HTTP/1.1，同一域名最多 6 条连接，开几个标签页就占满。提需求的 500 毫秒轮询改走同一机制。
4. **手机怎么连**：和桌面一样走 SSE；切到后台断开，回前台带最后一个 `seq` 重连补齐，补不全就重拉最后一页。
5. **推送**：service worker 加 `push`，后端存订阅、用 VAPID 发；完成、卡住、要你拍三类推给创始人个人（0122 决定 6），同一条同时发飞书个人消息兜底。风险：Chrome 推送走谷歌，国内可能到不了；苹果装到桌面的应用、Windows Edge 多半能到，要在创始人真实设备上实测。

**读放大的账**：读的行数都和一页显示的条数成正比。

| 场景 | 读多少 | 靠什么 |
|---|---|---|
| 会话列表一页 | 30 行 | `sessions` 的 `(last_activity_at desc, id)` 索引，键集分页 |
| 打开一个会话 | 最后 200 条；往上滚再取 200 条 | `run_transcript` 主键倒着取；要加「往前翻」参数，现在只有 `after` |
| 会话新来记录 | 只读 `seq` 大于上次的几条 | 同一个主键 |
| 波次图 | 一张单的子任务数（个位到几十） | `subtasks` 按 `task_id`；分波在后端算（最长路径分层），不在前端拿全图算 |
| 决策卡 | 开着的条数 | `notifications_open_idx` |
| 全局 SSE | 不读库，只转发「哪行变了」 | 照旧；不把 `run_transcript` 放进 `REALTIME_TABLES`，否则每条工具调用都推给所有浏览器 |
| 单的时间线 | 一页 50 条 | 账本按单和编号的索引 |

**会话能不能接着说话**：推荐只对指挥官会话开输入框，每说一句就在法国按会话号续一轮，和 `request_chats` 现在一样：不常驻进程，空闲不占内存，引擎重启不丢上下文。工人、复核会话只读，侧栏给「交给指挥官」按钮，把这个会话的引用发进指挥官会话，由指挥官决定补派、返工还是叫停。

#### 5. harness 内核和前端的关系（创始人 2026-10-30 已认可）

**定了的**：VPS 上跑一套 harness 内核，前端只做网页（驾驶舱），不另造桌面应用，也不把 Mirasim 搬上 VPS。桌面套壳先不做，进未排期单 #3754；先只做 VPS 网页版，后面的入口慢慢接。

**内核只暴露一套接口，前端可以随便换**：HTTP、实时推送（SSE）、MCP 三样。网页（浏览器、手机 PWA、以后的桌面壳）、本机 Mirasim（经 #3748 的 MCP 工具）、飞书都只是客户端。

| 层 | 做什么 | 借鉴 |
|---|---|---|
| 接口层 | 会话、单和子任务依赖图、账本、决策卡、渠道和角色表，统一从这里出 | — |

## 七、没核实的

- **推送在创始人设备上能不能到**：要在常用浏览器和手机上实测，影响第五节第 4 条。

**已核实（2026-10-30，只读）**：

- **波次图现在没料**：法国库 `subtasks` 里有子任务的单 25 张，拆成两个以上的只有 1 张（最多 3 个），`subtask_deps` 一共 2 条。现在的引擎基本是一单一个工人，波次图的数据要等内核编排层真去拆单才有。所以第 4 批排在编排层之后，先做的第 1 到 3 批不依赖它。
- **香港门面只走 HTTP/1.1**：`/etc/nginx/sites-enabled/fleet-dao` 的 443 不开 http2（443 端口和同机其它站点共用，开关是整个端口一起的）；`/api/events` 单独 `proxy_read_timeout 1h`、`proxy_buffering off`。浏览器对同一域名最多 6 条连接，所以每个标签页只用一条 SSE、切会话换订阅参数（第五节「总设计」第 3 条）是必须的；长连接一小时会被切一次，靠 `Last-Event-ID` 续上。
- **harness 指挥官会话的全文落在哪**：官方客户端的对话记录在法国本地文件里，要有东西收进库 `sessions` 才列得出来；harness 没建，第 5 批等它。
- **参考产品**：公开页面只说了布局和功能，没说实时怎么传；波次的排法（从没有依赖的开始按最长路径分层）是推的，不是照抄。cc-master 没打开。
- **清点**：0093、0090、0121 正文已补读；旧页面「待定」三项（额度、路由、路由状态）的去处随第五节拍板定。
