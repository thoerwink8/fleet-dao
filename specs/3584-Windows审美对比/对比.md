# 驾驶舱在 Windows 上和 Arco、Mirasim 的审美深度对比（#3584）

创始人 2026-10-22：驾驶舱在 Windows 上「一股不合适味道」，Mirasim 桌面端和字节的 Arco 在同一台 Windows 上「很自然」。这份报告量的是浏览器**真实算出来的样式和真实落到的字体**，不是看 `font-family` 写了什么，也不是像素比对。审美由创始人拍，这里给差异排序、三个样板备选和对比图，**没有改任何令牌默认值**。

图都在孤儿分支 `shots/3584-windows-arco-mirasim`，raw 链接前缀：`https://raw.githubusercontent.com/thoerwink8/fleet-dao/shots/3584-windows-arco-mirasim/`。

## 一句话结论

颜色、边框、圆角、阴影、图标线宽、间距、字号档位，驾驶舱和 Arco 已经几乎一样（第四节逐项量过）。**差在字体**：驾驶舱是整页唯一「Inter 网页字体 + 思源黑体」混排、且全局强开等宽数字的；Arco 在 Windows 上整页是微软雅黑，Mirasim 是 Segoe UI + 微软雅黑，都是系统自带、为 ClearType 做过栅格对齐的字体。

## 一、怎么量的

- 同一台 Windows 11（1920×1080，100% 缩放，ClearType 开着）、同一个 ego 浏览器窗口，视口 1440×900、DPR 1、注入 `html{font-size:16px}`（ego 默认 12），亮暗各量（`prefers-color-scheme`；Arco 站用 `body[arco-theme=dark]`）。
- 驾驶舱：本工作树 `react-router dev --mode mock`，路由 `/`（工作台）。Arco：`arco.design/react/components/table`（文档站，本身是 Arco 做的壳）和 `react-pro.arco.design/login`（Arco Pro 预览站登录页）。Mirasim：本机安装版 0.0.576。
- 真实字体：CDP `CSS.getPlatformFontsForNode`（返回 PostScript 名和字形数）。计算样式：`getComputedStyle`。字形尺寸：canvas `measureText`。笔画密度和锐度：同一串字、同一字号、白底黑字截图，自己解 PNG 数像素。
- Mirasim 安装版不开调试口（`ui-cli` 文档写明 `:4970 never opens CDP`），所以字体栈和令牌读它的 `renderer/assets/index-CjmK0aPj.css`；字体落地用同一份前端资源在本机静态服务后的 CDP 量（`@font-face` 与 `body` 样式一致，但没有真实界面）；真实界面只有 `ui-cli screenshot`。`ui.state` 读到它当前是暗色 nord 主题、`fontScale: large`（窗口缩放 1.15）。截图时亮暗各切了一次 `theme.mode`，已切回 `dark` 并核对过。

## 二、字体：三家实际落到的是什么

| | Latin 实际字体 | 中文实际字体 | 证据 |
|---|---|---|---|
| 驾驶舱（现状） | Inter（网页字体，`@fontsource-variable/inter` 打包） | **Noto Sans SC**（本机 `C:\Windows\Fonts\NotoSansSC-VF.ttf` 装了，栈里排在雅黑前面） | 工作台一行「等你点头：发布 v2.3」：`Noto Sans SC Medium ×7 + Inter Medium ×5（web）` |
| Arco（文档站、Pro 登录页） | **Microsoft YaHei**（栈里的 `Inter`、`noto sans` 没装，Latin 直接落到雅黑） | Microsoft YaHei | 同类行：`Microsoft YaHei ×12`，只有一个字体 |
| Mirasim | Segoe UI（栈里 `-apple-system`、`SF Pro Text` 没有） | Microsoft YaHei，`@font-face` 加 `size-adjust:93%` | `Segoe UI ×10 + Microsoft YaHei ×4` |

栈原文：

- 驾驶舱 `packages/web/src/app.css:145`：`"Inter Variable", Inter, -apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Noto Sans SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif`
- Arco：`Inter, -apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "noto sans", "Microsoft YaHei", "Helvetica Neue", Helvetica, Arial, sans-serif`（Pro 登录页另有 `nunito_for_arco` 打头，没装同样落到雅黑）
- Mirasim：`"Mirasim CJK Apple", "Mirasim CJK", -apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI", system-ui, sans-serif`；`Mirasim CJK` 的 `src` 是一串 `local()`，Windows 上命中 `Microsoft YaHei`。

## 三、差异排序（影响大到小）

### 1. 中文走的是没做过栅格对齐的思源黑体，笔画发灰发糊

- 同一串「数据概览 Dashboard 等你点头：发布 v2.3 额度 12/30 路由」，白底黑字截图数像素。「锐度」= 墨迹像素里亮度低于 25% 的占比，越高笔画越实：

| 常规字重 | 现状 Inter+思源 | A 整页雅黑 | B Segoe+雅黑 | C Inter+雅黑 | Mirasim 原样 |
|---|---|---|---|---|---|
| 14px | **23%** | 41% | 39% | 36% | 40%（14.95px） |
| 12px | 16% | 35% | 33% | 30% | 33%（12.65px） |

- 同批截图里 70%–81% 的墨迹像素带彩色边（|R−B| 大于 24），说明 DOM 文字走 ClearType 子像素抗锯齿；雅黑、Segoe UI 为 ClearType 栅格对齐过，思源可变字体和 Inter 网页字体不是，同样 14px，前者竖笔画落在整像素上，后者被抹成灰边。
- 笔画密度（14px 每字平均覆盖量）：思源 400 = 57.7，雅黑 400 = 62.8（雅黑重 9%）。
- 这条和机器有关：这台装了思源，栈里 `"Noto Sans SC"` 抢在 `"Microsoft YaHei"` 前面命中。没装思源的 Windows 上中文已经是雅黑，第 1 条不成立，第 2、3、4 条仍成立。
- 改哪：`app.css:145` `--font-sans`，把 `"Microsoft YaHei"` 挪到 `"Noto Sans SC"` 前面（样板 C）。

### 2. 一行字里两套字体：Inter 网页字体配系统中文

- 现状一行里 `Noto Sans SC ×7 + Inter ×5（web）`，Arco 是 `Microsoft YaHei ×12`；Mirasim 也是两套，但都是系统字体、同一套栅格。
- Inter 字面比雅黑、Segoe UI 更宽更高。100px 下 x 高：Inter 55 / Segoe UI 50 / 雅黑 54 / 思源 55；大写高：73 / 70 / 76 / 74；「Data overview」400 字重宽度：674 / 623 / 683 / 661。Mirasim 为让雅黑中文和 Segoe 英文看着一样大，给中文加了 `size-adjust:93%`；驾驶舱没有这一层。
- 改哪：`app.css:145` 去掉 `"Inter Variable", Inter` 打头（样板 A、B），并删 `root.tsx:2` 的 `import '@fontsource-variable/inter'` 和 `packages/web/package.json` 里的依赖；代价是品牌感从 Inter 换成系统字。

### 3. 字重 500/600：雅黑只有两档，思源和 Inter 是真的 500/600

- A 栈下 `font-weight:500` 的「工作台」落在 `MicrosoftYaHei`（常规体），600 才是 `MicrosoftYaHei-Bold`；现状是 `Noto-Sans-SC-Medium` / `Bold`。笔画密度（14px）：思源 500 = 70.3，雅黑 500 = 62.8（和 400 一样）。驾驶舱的「中号字重」在 Windows 上比 Arco 同一档重 12%，Arco 的 500 在 Windows 上其实就是常规。
- 驾驶舱用了 `font-medium` 36 处、`font-semibold` 5 处，加令牌 `--text-heading--font-weight:500`（`app.css:256`）、title/display 600（`app.css:259,262`）。
- 样板 B 里 Segoe UI 的 500 默认会落到 Semibold（实测 `Segoe UI Semibold`），和雅黑常规不一致，所以 B 用 `@font-face` 把 500 映射回 Segoe UI 常规。
- 改哪：换成系统字体（A/B）自然收敛；要显式控制就在 `app.css` 加 Windows 专用字重令牌，不建议先做。

### 4. 全局强开 `font-variant-numeric: tabular-nums`，Inter 的数字被撑宽

- `app.css:420` `body{font-variant-numeric:tabular-nums}`。Inter 14px 下「1111111111」：不开 57.0px、开了 90.8px（+59%，「1」两侧被撑出空隙，截图里 `#1745` 看得见）；「#1745 v2.3 12/30」112.4 → 123.8（+10%）；「8 分钟前 2026-10-22」137.1 → 149.4。雅黑、Segoe UI 数字本来就等宽（「1111111111」雅黑 82.1、Segoe 75.5，开不开一样）。Arco、Mirasim 都是 `normal`。
- 改哪：`app.css:420` 去掉 body 上的 `font-variant-numeric`，只在要对齐的列和指标上用已有的 `num` 工具类（`app.css:438`）。风险：没加 `num` 的数字列在 Inter 下会参差，样板 C 保留 Inter 所以要看这条；A、B 换系统字后无影响。

### 5. 阅读尺度：Mirasim 实际比驾驶舱大一圈，中文又缩了 7%

- Mirasim 令牌行字 13px、对话 14px、元信息 11px（`--text-row/head/meta`），本机设置 `fontScale: large`，窗口 `zoomFactor: 1.15`，实际约 15 / 16 / 12.7px；中文再乘 0.93，约 13.9 / 15 / 11.8px。驾驶舱正文 14/22、元信息 12/20，无缩放。所以 Mirasim 看着「舒展」有一部分是 1.15 倍放大，不是字体本身。
- 改哪：不是令牌问题，是显示尺度问题。要靠近就整体放大（浏览器缩放 110% 或加字号设置）。这张单不建议动字号档位（#3509 刚把根字号定在 16px）。

## 五、样板：三个备选（只在工作台 `/` 用运行时样式表覆盖，没改令牌默认值）

用法：在 mock 页面里往 `<head>` 追加一个 `<style>`，颜色、图标都不动。

**A 整页雅黑（Arco 原栈）**：最像 Arco 在 Windows 上的样子

```css
body{font-family:Inter,-apple-system,BlinkMacSystemFont,'PingFang SC','Hiragino Sans GB','noto sans','Microsoft YaHei','Helvetica Neue',Helvetica,Arial,sans-serif !important;font-variant-numeric:normal !important}
```

实际落字体：中英全是 `MicrosoftYaHei`，500 落常规、600 落 Bold。落地：`app.css:145` 换栈；`app.css:420` 去 tabular-nums；`root.tsx:2` 和 `package.json` 去掉 Inter 包。

**B Segoe UI + 雅黑（Mirasim 路线）**：英文更利落，中文不缩（驾驶舱有「中文最小 12px」的规则，Mirasim 的 93% 会把 12px 压成 11.2px，试过，不采用）

```css
@font-face{font-family:'Cockpit Sans';font-weight:100 500;src:local('Segoe UI'),local('SegoeUI')}
@font-face{font-family:'Cockpit Sans';font-weight:501 1000;src:local('Segoe UI Semibold'),local('SegoeUI-Semibold')}
body{font-family:'Cockpit Sans',-apple-system,BlinkMacSystemFont,'Segoe UI','PingFang SC','Hiragino Sans GB','Microsoft YaHei',system-ui,sans-serif !important;font-variant-numeric:normal !important}
```

实际落字体：Latin `SegoeUI`，中文 `MicrosoftYaHei`。`@font-face` 把 500 映回 Segoe UI 常规，避免英文半粗而中文常规。

**C Inter + 雅黑 + 数字不再等宽**：保留 Inter，只修栈序和数字特性，改动最小

```css
body{font-family:'Inter Variable',Inter,-apple-system,BlinkMacSystemFont,'PingFang SC','Hiragino Sans GB','Microsoft YaHei','Noto Sans SC','Helvetica Neue',Arial,sans-serif !important;font-variant-numeric:normal !important}
```

实际落字体：Latin `Inter`、中文 `MicrosoftYaHei`。只改 `app.css:145` 栈序和 `app.css:420`，不动依赖。

## 六、推荐

先 **A**，B 备用，C 是最小步。

- A 照字节的做法：创始人 10-22 拍过「字节怎么做我们就怎么做」（#3509），A 就是 Arco 原栈，在 Windows 上和 Arco 站落到同一个字体，锐度 41%、整行单一字体，还少一个网页字体包。代价：英文和数字也是雅黑，品牌感弱；500 字重在 Windows 上和 400 一样，层级靠字号和颜色。
- B 在 Windows 上英文更利落，是 Mirasim 的路线，macOS 上落到系统字（`-apple-system`）。
- C 只改栈序和数字特性，保留 Inter，能解第 1、4 条，第 2 条（Inter 与雅黑不是一套）还在，锐度 36%，不如 A、B。

三个备选都没改字号档位，不影响布局。落地要同时改 `docs/design/驾驶舱界面.md:86` 的字体一行（令牌和文档一起改）。

## 七、没查成的

- **Arco Pro 登录后的工作台**：预览站要点「登录」，表单里是预填的演示账号，我没点（不替人登录第三方站点），所以 Arco 的对比对象是文档站（表格、菜单、标题）和 Pro 登录页，不是 Pro 仪表盘页。字体、字重、颜色、圆角、阴影这些令牌层结论不受影响，版式密度缺 Pro 仪表盘的逐项对比。
- **Mirasim 计算样式**：安装版没有调试口，不能对真实界面 `getComputedStyle`；字体、字号、字重来自 CSS 源文件加静态前端 CDP 测量，图标线宽没逐个量。Mirasim 粗体中文：`font-weight:600` 时中文落 `MicrosoftYaHei`（常规体，没有粗体 `@font-face`）、英文落 `Segoe UI Semibold`，推断中文是合成粗体，没单独量。
- **只有一台机器**：思源装在这台上，别的 Windows 没装则第 1 条不成立。没读 ClearType 调校，也没在 125%/150% 缩放下对比（这台 100%）。
- **锐度是我自己定的指标**：亮度低于 25% 的墨迹占比，和栅格对齐强相关，但不等于人眼的好看；样板最终要创始人眼睛拍。
- 没跑 `lint-design` 和单测：这张单只加文档，没改 `packages/`。
