# 引擎接真端口，法国跑通 P0 验收（#28）

对应计划：plan.md P0 的验收（「你好」工作流、健康检查页），P1 核心闭环（工作流接真活动）。
设计依据：design 第五节（一个任务怎么走完全程）、第四节「会话断了接着干」、第九节（选路）、第十二节（卡住与自愈）。

## 要什么

- 引擎的活动换成真实现：Claude 经 reclaude 以会话用户身份起（fleet-agent-scope）、GitHub（packages/github）、库（packages/db）、后端（packages/api）。假实现只留给测试。
- 注册 helloWorkflow，供 deploy/hello.sh 做 P0 验收。
- 错误分类器接进引擎：额度用满挂起到清零、续同一个会话；非换池不可才带接力任务书开新会话（拼车切独享用 `--resume <编号> --fork-session`）；封号整池避开；reclaude 设备被撤销单独一类（整池暂停、飞书叫人重新登录）；推分支被卫生检查拦下退回会话，名单读不到挂起报警。
- 按进展判停滞；工作流事件数报警；say、plan 不进需求工作流。
- 引擎开 PR 带上 issue 的类别标签和里程碑，正文走 renderPrBody。
- worker 主进程、systemd 单元，接进 france.sh 和发布脚本；发布时不往香港根地址发正式驾驶舱（根地址放演示版，见 #29）。

## 怎么算做完

- 两个 PR（A 引擎接真端口，B worker 上机）审过合进 main；每条失败路径都有故意造出的用例。
- 法国 P0 验收：两个装机脚本各跑两遍、第二遍零改动；从驾驶舱域名打开健康检查页，看到库、Temporal、引擎都在线；hello 工作流跑完、耗时进库。
- PR B 正文登记：上线后退役法国拼车用户家里的派活垫片（~/bin/carpool-run.sh）。
