# 方案：引擎接真端口，法国跑通 P0 验收（#28）

需求见 [需求.md](需求.md)。拆成两个 PR，按顺序做：A 让引擎的活动接上真实现，B 让引擎和后端在法国起来、跑 P0 验收。

## PR A：引擎接真端口

活动的真实现都放在 `packages/engine/src/real/`，只有 `worker.ts` 引用它们。工作流文件不许引用真端口，也不许引用 db、github、adapters 包（`test/structure.test.ts` 查）。假实现 `fakes.ts` 原样留给测试。

1. **库**（`real/store-ports.ts`，接 `packages/db`）
   - 选路：调度台的顺序和候选事实（`routeFactsForStage`），加上近 7 天会话结局现算的熔断和这个阶段的战绩，一起交给纯函数 `chooseRoute`（#19）。三种结果原样换成端口的派、等、派不出。
   - 点名的路由先试，用不了就照常选，理由里写明。
   - 续同一个会话的路由：暂时派不了就等它；用不了（下线、被禁）才照常选。
   - 执行方式还没接上的路由不派。目前只接了 Claude Code。
   - 报警、提问、人闸、计时、任务快照各落各的表，按编号幂等。
2. **GitHub**（`real/github-ports.ts`、`real/mirror.ts`，接 `packages/github`，#11 加上这次补的并主线、打包、写需求文档）
   - 引擎不以自己的身份在会话目录里跑 git（design 第十四节）。推分支时，由会话用户把新提交打成 bundle 交出来，github 包导入、核实后再推。并主线后，由会话用户从镜像的 bundle 快进。
   - 开 PR：正文给结构，由 renderPrBody 生成；照抄需求 issue 的类别标签和里程碑。
   - 在新头上跑测试就是等这个头的 CI。CI 没查成就抛 CI_UNKNOWN，不退回会话。
3. **工作树**（`real/worktrees.ts`，接 `deploy/france/fleet-agent-scope.sh`）
   - 子任务的树放在 `/var/lib/fleet-work/<owner>_<name>/<分支去掉 fleet/>`。分诊、需求文档、方案、审查的检出副本放在 `<需求号>.<阶段>[.<子任务>]`。
   - 每棵树归会话用户、权限 700。建树、改属主、删树都由帮手脚本以 root 做：本次新增 remove 子命令，adopt 改成不在就建。
4. **会话**（`real/sessions.ts`，接 `packages/adapters` 的 Claude Code 插头）
   - 会话经 reclaude 无头起，以会话用户的身份跑在 fleet-agent-scope 的 scope 里。
   - 起会话按 runId 幂等，叫停过的 runId 不再起。进程起来才算开工，记下进程号和 scope。
   - 看守时心跳；进度事件攒一小批就写库（fleet done 的核实要读会话自己跑过的测试）；额度读数顺手记账。
   - 交活核实：写码类看 fleet done 和工作树，要有新提交、不能有没提交的已跟踪改动。其余阶段读 `.fleet-out/` 下的结论文件，形状不对就算交错了。
   - 接不上（工人重启过）：按记下的 scope 收掉旧会话，回 SESSION_LOST。工人起来先收掉上一轮留下的会话。
5. **会话断了接着干**（design 第一节、第九节）
   - 同一个会话用户：`--resume` 续上。
   - 换了会话用户、上一轮上下文小于 10 万 token：先 `fleet-agent-scope adopt` 交树、拷过程记录，再 `--resume <旧> --fork-session --session-id <新>`。
   - 上下文大了，或过程记录没拷成：开新会话，带接力任务书，写明做到哪了、已经提交了什么。
   - 失败分流（#10）接进引擎：
     - 额度用满：主池挂起到清零时刻再续同一个会话；备池（拼车号）先换池。
     - 设备被撤销：单独一类，整池暂停，挂起等人重新登录。
     - 卫生检查拦下（#21）：退回会话，同一处连续被拦两次就挂起。名单读不到：挂起报警。
     - 插头报的 agent_error 也经分类器。
   - 要人修的整池问题（设备被撤销、封号、登录失效、欠费）：会话端口写一条 `pool-hold:<池>` 的「要人拍」提醒，写清哪台机器、哪个会话用户、怎么修。选路避开整个池；续会话的那一单是试探，跑通了就撤掉这条提醒。
6. **别的几条**
   - 按进展判停滞（#10 的 judgeStall）：绕圈、工具卡死就停掉。光是没动静，由插头自己的 idle 超时管。
   - 工作流事件数报警：到 5000 报一次。
   - say、plan 不叫醒工作流（后端 #9 只对 ask、done、blocked 发信号）。
   - hello 工作流。
   - CI 用和法国同版的 Temporal 命令行，版本和校验和从 `deploy/france.sh` 读，按版本缓存。
   - 合并队列空闲收工的时长不短于 30 秒。
7. **装配**（`real/index.ts`、`worker.ts`）：`FLEET_ENGINE_PORTS` 必须写 real 或 fake。真端口缺的配置一次列全，缺哪一样都不起，不带着半套配置接活。

A 在前：B 发布的引擎要有真端口，健康检查页的「引擎」一项要有工人在取活。A 依赖已经合进主线的这几块：#9（后端）、#10（错误分类器）、#11（GitHub）、#17（库）、#19（选路）、#21（卫生检查）、#24（renderPrBody）。#41 合进来以后，PR 正文的「对应计划」「specs」两栏要按它的签名补上。

## 定下的几处做法（审查时请看）

- **跨会话用户接着干**：用 design 第十四节的「交树、拷过程记录、fork」，没用 design 第九节的 `reclaude org use` 切组织。切组织会打断这台机器上这个用户的所有会话，所以没做成自动的。
- **设备被撤销怎么认**：按 reclaude 文档的 `401 device_revoked`（样本 X05）和线上见过的「此设备已被解绑」（样本 S05）。手上还没有真的过程记录样本，写在「还欠」里。
- **需求文档**：由「引擎」机器人经 Contents API 直写默认分支。这是临时做法，design 还没写清由谁提交、写到哪个分支。
- **引擎的 info 级报警**（封号、事件数到线、全熔断）和「卡住了」一样进提醒中心：量很小，都是要人知道的事。

## 还欠（PR A 不做）

- Jev 没接：停滞拿不准时不问它，失败认不出时也不问它。
- 接活入口没做：issue 进来建任务行、拉起需求工作流，GitHub 事件落库。另有单。
- 人批、人拒经驾驶舱或飞书走回引擎的路没真跑过；飞书推送（outbox）另有单。
- 设备被撤销没有真的过程记录样本；跨会话用户 fork 续、拷过程记录没在法国演练过。
- 建树时不装依赖，由会话自己装；优雅停（停在干净的点）还没做，一律立刻停，已提交的不会丢。
- 并主线时带着 `.github/workflows/` 改动推送没在真仓验过（`docs/reference/github.md` Q1）。
- 两个活着的子任务互换 index 时，任务快照会撞唯一索引（db 查询的注释里写了）。
- 只接了 Claude Code 一种执行方式。
- 检出副本和被强行终止的工作流留下的会话，还要每小时对账收掉。
- 法国会话用户的 reclaude 版本没核对（插头要求 ≥ 2.1.277）。
