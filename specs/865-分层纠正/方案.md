需求见 GitHub #865（创始人 2026-10-04 夜转来的审查第 2 条，要求 V3 前做完）。

## 现状（origin/main 1e02f12c 上核过）

- `packages/engine/package.json` 依赖 `@fleet-dao/api`。引擎源码用到的：`createPgStore`、`User`、`jsonLogger`/`Logger`、`createGitHubIntake`、`reconcileGitHub`/`reconcilerOptions`/`GitHubReconcileResult`、`deployFacts`/`handlingOf`/`pgAlertWork`、`readDeployLagInput`、`@fleet-dao/api/whitelist`（`githubWhitelist`、`isTrusted`、`memberFor`、`actorFor`）。涉及 `real/intake.ts`、`canary.ts`、`hourly-reconcile.ts`、`github-reconcile.ts`、`jobs/intake.ts`、`jobs/github-reconcile.ts`、`test/intake.test.ts`。
- api 不依赖 engine，所以不是 npm 环，只是分层反了：Store 在 HTTP 包里，被引擎倒着引用。
- 这些东西本身都不碰 HTTP：`ports.ts` 里的 Store 契约、`pg-store.ts`、`memory-store.ts`、`whitelist.ts`、`alert-work.ts`、`deploy-lag.ts`、`reconcile.ts`、`github.ts` 里的 `createGitHubIntake`（进门的判法）。

## 搬到哪：新建 `@fleet-dao/store`，不并进 db 或 shared

- 不进 `shared`：shared 是跨前后端的纯类型和 zod，Store 带 Drizzle、Postgres、文件读取，会把这些拖进网页打包。
- 不进 `db`：db 是表结构、迁移、查询，只依赖 shared。Store 契约要用 core 的类型（`AskHold`）、`pg-store.ts` 2000 行、`memory-store.ts` 1600 行，并进去 db 会又胖又和 core 缠在一起。
- 新包依赖方向：`store → core、db、shared（、github 只取类型）`；`api → store`，`engine → store`；store 不依赖 api、engine。
- 命名：包里除了 Store，还有进门判法、对账、告警处理现算、线上落后判断，它们的共同点是「后端和引擎共用、不碰 HTTP」，所以叫 store 而不是 api-core；README 目录表按这个说法写。

## 依赖图

前：`engine → api → (db, core, shared, github, jev …)`
后：`engine → store → (db, core, shared)`；`api → store`；没有任何包依赖 api。

## 留在 api 的

- 所有 Hono 路由、登录、会话、令牌、健康检查、飞书、SSE、Temporal 信号：`auth.ts`、`health.ts`、`session.ts`、`tokens.ts` 等不动（`auth.ts`、`health.ts` 是创始人点名不碰的，登录白名单、站内跳转校验、登录节流、密码校验、健康检查不吐内部地址都不许削弱）。
- 抛 `PublicHealthError` 的地方：`PublicHealthError` 这个类在 `health.ts`，不动它；所以抛它的函数都留在 api（`probeDb`、`deployLagCheck`、`githubAppMissing`、`githubEventsCheck`），否则 store 要反过来依赖 health.ts。顺带 `health-public-text.test.ts` 数 `new PublicHealthError(` 的扫描范围（api/src）也不用改，不会漏扫。
- `ports.ts` 里只给 api 用的接口留在 `api/src/ports.ts`：`DraftOpener`、`TaskSignal`/`WorkflowControl` 及三个错误、`TemporalConnection`、`ChangeFeed`、`HealthCheck`、`FeishuAuth`/`FeishuIdentity`。这份文件末尾 `export * from '@fleet-dao/store'`：`auth.ts`、`health.ts`、`session.ts` 从 `./ports.ts` 取 `NewAuditEntry`、`Logger`、`Store`、`User` 这些类型，不跟着改（安全文件，改了就要走第二意见）。这一层转发是长期留着的，不在「最后清掉」之列。
