# 子代理分档：调研（#1641）

2026-10-10 指挥官（Opus 5.5）读的。每条标来源和读的日期。「官方」是 Anthropic 写的。「社区」是第三方，没人审过，只当参考。「我们实测」是本仓量过的。

## 一、官方：子代理怎么写

来源：Claude Code 文档《Create custom subagents》 https://code.claude.com/docs/en/sub-agents （2026-10-10 读）

1. 同一类活反复派、交代每次都一样，才值得写成定义。
2. 主会话靠 `description` 决定派谁，所以描述要写清、要短。所有自定义子代理的描述加起来超过 1.5 万 token，启动时就报警。细节放进正文：正文只在它跑起来时才载入。
3. 描述里写「use proactively」一类的话，主会话会更主动地派。
4. 工具按最小权限给：`tools` 是白名单，`disallowedTools` 是黑名单，两个都写时先减黑名单。不让它再起子代理，就别给 `Agent`。
5. `model` 可以写别名（`haiku`、`sonnet`、`opus`）、完整 id 或 `inherit`。
   - 生效顺序：派的时候传的参数 → 定义里的 `model` → 环境变量 `CLAUDE_CODE_SUBAGENT_MODEL` → 主会话的模型。
   - 同族别名会解析成主会话那个确切型号。所以要写完整 id，本仓定义一律写完整 id（决定 0036）。
6. `--agents` 命令行参数可以带一份 JSON 定义，只在这次会话里有效。非交互（`-p`）模式下可以给文件路径（v2.1.281 起）。
7. 同名定义的优先级：
   - 托管设置第 1；
   - `--agents` 第 2；
   - 项目 `.claude/agents/` 第 3；
   - 用户 `~/.claude/agents/` 第 4；
   - 插件第 5。
8. `isolation: worktree` 让它在临时 git 工作树里干活，默认从默认分支拉，没改动就自动删。
9. `maxTurns` 到了就停，结果标「部分完成」，可以续。
10. `permissionMode` 不写就跟主会话。主会话是 `bypassPermissions`、`acceptEdits` 或 auto 时，子代理照主会话来，定义里写的不管用。
11. 什么时候用：
    - 好用：旁支活会产出大量用不上的输出（搜索结果、日志、文件内容），子代理在自己的上下文里做完、只回摘要；要限工具、限权限；活本身自成一块、能交摘要。
    - 不好用：要来回改很多轮；几个阶段共享大量上下文；改一处的小活；在乎延迟（子代理冷启动要重新读上下文）。
12. 成本：子代理的请求算在同一份用量里。并发默认上限 20（`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`），嵌套默认最深 3 层。

## 二、官方：子代理在工作流里放在哪

来源：Claude Code 文档《Best practices》 https://code.claude.com/docs/en/best-practices （2026-10-10 读）

1. 头一条：给它能跑的核对（测试、构建、截图对比）。没有核对，「看起来做完了」就是唯一的信号。
2. 调研交给子代理，主会话的上下文留给实现。
3. 做完之前，加一道对抗式评审：子代理在新上下文里只看 diff 和验收条。被要求找毛病的评审几乎总能找出几条。所以要让它只报影响正确性和需求的，其余算可选，免得过度工程。
4. 写的和审的分开（Writer/Reviewer）：新上下文审得更好，不偏袒刚写的代码。测试也可以一个写测试、另一个写实现。

来源：Anthropic 工程博客《How we built our multi-agent research system》 https://www.anthropic.com/engineering/multi-agent-research-system （2025-06-13 发，2026-10-10 读）

5. 编排者加工人：Opus 4 当主、Sonnet 4 当子代理，在他们的内部调研评测上比单个 Opus 4 高 90.2%。
6. token：单代理约是聊天的 4 倍，多代理约 15 倍。值得做的前提是活够值钱、能并行。
7. 不适合：所有代理要共享同一份上下文、彼此依赖多的活。编码就是一例，真能并行的子任务比调研少。
8. 交代要写四样：目标、产出格式、用什么工具和来源、边界。交代含糊，子代理会重复别人的活。
9. 规模按难度给：查一个事实 1 个代理、3–10 次工具调用；比较 2–4 个；复杂调研 10 个以上。
10. 评测：先用约 20 条真实用例。早期一句提示词能把成功率从 30% 拉到 80%，小样本就看得出。LLM 当裁判时，单次调用打 0–1 分加过不过最稳。机器评测之外还要人看。

## 三、官方和半官方：三档怎么分

来源：
- 本仓 `agents/skills/commander/references/子代理选模型.md`（决定 0034、0035，2026-10-09）里记的官方数字；
- 2026 年 10 月的第三方指南转引官方的说法：
  - https://www.developersdigest.tech/blog/claude-opus-5-5-vs-sonnet-5-5-vs-haiku-5-5
  - https://www.ayautomate.com/blog/opus-vs-sonnet-vs-haiku
  - https://beam.ai/agentic-insights/which-claude-model-ai-agents

（均 2026-10-10 读）

1. 转引官方：Haiku 5.5「搭配 Opus 5.5、Sonnet 5.5 做编码活的子代理很合适」。官方的大致分法是：简单活 Haiku，多数生产活 Sonnet，最复杂的推理 Opus。
2. 两种起步法：
   - 先便宜后升档：从 Haiku 起，测出能力不够的地方才升。适合原型、要快、量大的活。
   - 先强后降：从 Opus 起，稳定后降 effort 或降档。适合复杂推理、自主跑得久的活。
   两种都要求拿自己的活去测，不靠猜。
3. 换档之前先调 effort。
4. 官方基准（决定 0035 记的）：长链命令行编码 Terminal-Bench 4.0，Haiku 5.5 是 39.2%，Sonnet 5.5 是 70.6%。
5. 官方价（决定 0035 记的）：Haiku 5.5 输入 0.10、输出 0.50 美元/百万 token。命令行回的 `costUSD` 对 5.5 不准，不当账。

## 四、社区：别人怎么分档

来源：
- https://github.com/wshobson/agents （读的是 README 和 docs/agents.md 的转述）
- https://github.com/VoltAgent/awesome-claude-code-subagents

（2026-10-10 读，都没人审过）

1. wshobson/agents 的分法：
   - Opus：架构、安全、代码评审、生产要紧的活；
   - Sonnet：文档、测试、调试；
   - Haiku：快的运维杂活；
   - 量大的交给 inherit。
   它认为复杂活上 Opus 用的 token 少约 65%，能抵掉单价。它的分档跟着实测在变：context-manager 从 Opus 降到 Haiku，语言专家从 Sonnet 升到 Opus。
2. VoltAgent 的分法：
   - opus 深推理（安全审计、架构评审）；
   - sonnet 日常编码；
   - haiku 快活（文档、构建）。
   工具按角色给：评审只读，调研加联网，写代码的给写和 Bash。
3. 实践者的共识（同一批搜索结果，2026-10-10 读）：
   - 按「决定有多难」选档，不按「要读多少」：读 10 万 token 日志出一个分类，不用顶配。
   - 便宜模型给精确规格，结果不对就换强的重跑。
   - 描述互相重叠，主会话就会派错或干脆不派。
   - 有人报过 Haiku 子代理用 SendMessage 回结果时会挂住不动。

## 五、我们实测过的（本仓）

1. Agent 工具写 `model: "haiku"`，在本机派到的是 Haiku 4.5，不是 5.5（决定 0035，2026-10-09）。所以本仓定义写完整 id `claude-haiku-5-5`。
2. 16 个 `fleet-*` 定义落地后（决定 0036），这一轮派活都按定义起：#1637 的 builder 汇报首行是 `claude-sonnet-5-5`，对得上。
3. 还没量过的：每一档在每种场景上的通过率。这一块由本单的「能力探查」补上，结果见同目录 `能力探查.md`。

## 六、对本仓的结论（方案的前提）

1. 现在的 16 个定义已经合上官方写法的几条要点：一个子代理一件事、工具白名单、写完整模型 id、写代码的独立工作树、Haiku 限回合。不需要推倒重来。
2. 缺的是官方一再强调的那一步：拿自己的活去量。分档要从「按经验」改成「按探查数据」，并且能重跑。
3. 官方建议加的对抗式评审，本仓已经有了：`fleet-review-screen` 用 Haiku 筛，`fleet-reviewer` 用 Opus 下结论。要补的是写明「什么时候必须过一遍」。
4. 法国上的会话现在只有在 fleet-dao 的工作树里，才读得到项目定义。要用 `--agents` 统一带上，并且限制每个会话的子代理并发，免得一个会话把池的额度吃光。
