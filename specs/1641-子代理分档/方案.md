# 子代理分档：方案（#1641）

前提见同目录 `调研.md`。创始人原话（2026-10-10 10:33）：「本机实现的subagent，我希望.agent规划n种各个opus sonnet haiku 5.5作为subagent的场景，按照网上的最佳实践走，探查每个的能力；然后vps和本机也要实装上」。

## 一、结论

1. 三档十六个的骨架留着（决定 0036）。官方写法要的几条它都有了：一个子代理一件事、工具白名单、写完整模型 id、写代码的独立工作树、Haiku 限回合。
2. 分档从「按经验」改成「按探查数据」，补一套能重跑的能力探查：
   - 每种场景出真题，三档各跑一遍；
   - 脚本判分，记下提示词、产出原文、用时、token；
   - 按下面第四节的规则定档。
3. 法国上的会话统一带上这批子代理：
   - 引擎起 Claude 会话时，用 `--agents` 把定义带进去；
   - 去掉 `isolation`，会话本身已经在任务的工作树里；
   - 每个会话限 2 个并发子代理。
4. 本机照旧用仓里的项目级定义，补一次三档实测核对。

## 二、场景规划（每档 n 种）

「核对」是派完之后用什么判它做对了没有。一种场景就是一个子代理，名字照旧。

### Haiku 5.5：产出能被脚本或一条命令核对的活（6 种）

| 场景 | 子代理 | 做什么 | 不做什么 | 工具 | 核对 |
|---|---|---|---|---|---|
| 读码检索 | `fleet-scout` | 找文件、谁调谁、行为在哪实现 | 不解释原因、不给修法 | 只读加 codegraph | 回 `文件:行`，抽一行读回来对得上 |
| 归纳输出 | `fleet-log-digest` | 测试、CI、巡查输出缩成证据行 | 不归因 | Read、Grep、Bash | 证据行在原文里找得到 |
| 分类准入 | `fleet-triage` | 单子、任务书、PR 范围逐条对规矩 | 不下合不合的结论 | 只读 | 和 `check-brief.mjs` 的结论一致 |
| 评审初筛 | `fleet-review-screen` | 清单式查越范围、碰标准、疑似密钥、删断言、测试没点名 | 不判逻辑对错 | 只读 | 每条附行号，命中种下的问题 |
| 小修 | `fleet-fixer` | 规格明确的小函数、已有失败测试的 bug | 不碰交代以外的文件 | 可写，独立工作树 | 点名的测试由红转绿 |
| 写任务书 | `fleet-brief-drafter` | 需求写成四节单的草稿 | 不开单 | 只写 `_tmp/` | `check-brief.mjs` 是 PASS |

### Sonnet 5.5：没有机器核对、要写进仓里的默认档（6 种）

| 场景 | 子代理 | 做什么 | 核对 |
|---|---|---|---|
| 写代码 | `fleet-builder` | 后端、脚本、配置、测试，一个 PR | CI 和点名的测试；藏起来的验收测试 |
| 界面 | `fleet-ui-builder` | 驾驶舱页面新做和重做 | 截图加自己点一遍 |
| CI 归因 | `fleet-ci-triager` | 哪次改动弄红的、根子在哪 | 指出的提交和根因对得上 |
| 页面点验 | `fleet-ui-verifier` | 已上线页面真点一遍 | 截图和报错清单 |
| 上网调研 | `fleet-researcher` | 文档、最佳实践、价格 | 每条带来源和日期 |
| 审单 | `fleet-groomer` | 做完没有、过期没有、该不该拆 | 结论和主线事实对得上 |

### Opus 5.5：错了代价大、要下结论的（4 种）

| 场景 | 子代理 | 做什么 | 核对 |
|---|---|---|---|
| 改标准 | `fleet-standard-editor` | `agents/**`、通用段、钉规矩的测试 | 规矩和钉它的测试同一个 PR，测试过 |
| 架构方案 | `fleet-architect` | 新机制设计、几种做法取舍 | 方案里前提、取舍、推荐齐全；拍板前 `discuss` |
| 疑难调试 | `fleet-debugger` | 同档连败两次的、根因不明的 | 先红后绿的测试和写清的根因 |
| 评审下结论 | `fleet-reviewer` | 逻辑错、漏边界、假测试 | 种下的问题找到几个、误报几个 |

### 候选（看探查结果再定，先不加）

- `fleet-test-writer`（Sonnet）：官方「一个写测试、另一个写实现」的做法。只有探查显示 builder 自己写的测试常漏验收条时才加。
- 不加通用的「万能子代理」：描述一重叠，主会话就派错（调研第四节第 3 条）。

## 三、能力探查怎么做

### 放哪

- 新包 `packages/agent-eval/`：
  - `src/` 放跑题和判分的代码；
  - `cases/<场景>/` 放每道题的题面、夹具、判分函数；
  - `results/` 不进仓，写到 `_tmp/agent-eval/`。
- 入口：`pnpm agent-eval [--case <名>] [--model haiku|sonnet|opus|all] [--dry-run]`，结果写 JSON 和 Markdown。

### 一道题怎么跑

1. 每道题在临时目录里跑：拷夹具，或者从固定提交建一个只读检出。
2. 起无头会话：`claude -p --model <完整 id> --output-format stream-json --verbose --no-session-persistence --permission-mode dontAsk --allowedTools <这个子代理定义的工具> --append-system-prompt <这个子代理定义的正文>`，提示词走 stdin。本机的命令和工人用的同一个（见 `worker-lib.mjs`）。
3. 限时 10 分钟，回合上限照定义的 `maxTurns`，没写的给 40。
4. 判分函数拿产出和临时目录判过没过，写理由。能用代码判的不叫模型；实在要判开放式答案的（架构题），用一次 LLM 打 0–1 分加过不过，评分标准写进题里（调研第二节第 10 条）。
5. 记下：题、模型、过没过、理由、用时、输入和输出 token、提示词原文、产出原文（截到 2 万字）。

### 题（每种场景至少 1 道，能判的尽量 2 道）

| 场景 | 题 | 判分 |
|---|---|---|
| scout | 定时路由探针一轮的入口函数在哪个文件哪一行（固定提交） | `文件:行` 对得上（行号差 3 行以内） |
| log-digest | 一段录好的 CI 红灯日志 | 回的证据行包含全部失败用例名和断言行，且都在原文里 |
| triage | 5 份任务书草稿 | 每份过不过和 `check-brief.mjs` 一致 |
| review-screen | 种了 4 个问题的 diff（碰标准路径、像密钥的串、删断言、`it.skip`） | 4 个都报出、行号对，误报不超过 1 个 |
| fixer | 小包里一个有 bug 的函数加一条红测试 | 测试转绿，测试文件没改 |
| brief-drafter | 一段场景描述 | 草稿 `check-brief.mjs` 是 PASS |
| builder | 小包里按规格加一个功能 | 藏起来的验收测试全过、原有测试不红 |
| ci-triager | 一段红灯日志加 3 个候选提交的 diff | 指出弄红它的那个提交 |
| groomer | 4 张单加一份主线事实 | 每张「做完 / 没做完 / 过期」判对 |
| researcher | 「Claude Code `--agents` 的优先级排第几」这类有标准答案的文档题 | 答案对、带官方链接 |
| standard-editor | 一份规矩文档加钉它的测试，按要求改一条规矩 | 测试过，规矩和测试一致 |
| debugger | 夹具里一个根因藏得深的 bug（跨时区的日期边界）加红测试 | 测试转绿，diff 最小（改动行数有上限） |
| reviewer | 种了 3 个逻辑错、2 个看着像问题其实没问题的 diff | 3 个找到 2 个以上，2 个干扰项不报 |
| architect | 一道有已知最优解的取舍题（附约束） | LLM 按题里的评分标准打分，≥ 0.7 算过 |
| ui-builder、ui-verifier | 要浏览器，自动探查先不做 | 方案里写明这两种靠截图人看 |

### 成本和节奏

- 14 种场景，每种 1–2 道，三档各跑一遍，约 60 次会话。
- 一次跑一个会话，不并行，不占本机的并发名额以外的资源，约 1.5–2 小时。
- 用的是订阅额度，不另外花钱。

## 四、按数据定档的规则

1. 一种场景定在通过率 ≥ 80% 的最便宜那一档。题少于 3 道时，要全过。
2. Haiku 在 Sonnet 档的场景上全过：建议降到 Haiku，并在定义里写明核对办法。没有机器核对的不降。
3. 某档在自己的场景上没过：升一档，写明哪道题没过。
4. 用时和 token 记在结果里，同档几个子代理比 effort 用。调研第三节第 3 条：换档之前先试 effort。
5. 结论进 `能力探查.md`。分档改了，同一个 PR 改 `.claude/agents/`、钉名单的测试和指挥官的参考页。这是改标准，正文贴创始人的原话。

## 五、法国装上

1. 定义从发布目录里的 `.claude/agents/*.md` 读：发的哪一版就用哪一版，归 root、会话改不了。
   - 转成 `--agents` 要的 JSON：description、prompt、tools、model、effort、maxTurns。
   - 去掉 `isolation`：会话已经在任务自己的工作树里，嵌一层工作树改出来的东西不在要交付的分支上。
   - 去掉 `mcp__` 开头的工具：法国的会话带 `--strict-mcp-config`，没有 MCP。
   - JSON 写成发布目录里的一个文件，比如 `deploy` 时生成，或者引擎启动时生成到 `/var/lib/fleet-work/_agents/<提交号>.json`，644。起会话时带 `--agents <文件>`。
2. `--agents` 的优先级高过项目 `.claude/agents/`（调研第一节第 7 条）。所以在 fleet-dao 的工作树里，用的也是发布版的定义，不是分支上正在改的那份。这是有意的：分支上没合的定义不该在法国生效。
3. 每个会话环境里加 `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS=2`，免得一个会话起一堆子代理、把池的额度吃光。
4. 要确认 `Agent` 工具没被挡：
   - 写码阶段是 `bypassPermissions`，本来就放行；
   - 只读阶段（冷验收这类）用 `dontAsk` 加 `--allowedTools`，要把 `Agent` 加进去，子代理自己的工具照它定义里的白名单。
5. 给会话的提示词里加一句：可以派哪些子代理、什么时候派。比如查代码派 `fleet-scout`，自审派 `fleet-review-screen`。要短。
6. 调工具前那条钩子（`--settings` 带的 PreToolUse）对子代理的工具调用一样生效。这一点要在法国实测里核一下。
7. 验证：发版后，在法国以会话用户起一次无头会话，三档各派一个子代理，各回一行自己的模型 id，对得上才算装上。原文贴在 #1641。

## 六、本机

1. 本机在 fleet-dao 里干活，读的是仓里的 `.claude/agents/`（项目级），不另装。
2. 别的仓不装这批：定义里写的是 fleet-dao 的规矩（`pnpm pr:open`、`pnpm issue:new`、codegraph），放到别的仓会教错。别的仓要用，按那个仓的规矩另写。
3. 验证：开新会话，三档各派一个，汇报首行的模型 id 对得上。
