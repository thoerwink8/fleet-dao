### 3. 中转上 claude 执行体认不认 claude-haiku-5-5

### 4. claude-code 执行方式恢复以后：`--agents` 加 `--setting-sources project`

结论：
- 同名的定义按优先级取：托管 1，`--agents` 2，项目 3，用户 4，插件 5。不同名的合在一起用，`--agents` 不清掉别处的定义。
- `--setting-sources project` 会不会挡住用户级 `~/.claude/agents/`，**文档没写，拿不准**。它对项目级没影响：项目这一层本来就开着。
- 对我们够用：16 个名字全用 `--agents` 带上，同名就压住工作树里分支上的那份。用户级目录在法国现在是空的。

证据：
- sub-agents 文档的优先级表，原文「When multiple subagents share the same name, Claude Code uses the one from the higher-priority location.」（2026-10-10 读）。
- 文件路径的写法，原文「In non-interactive mode, `--agents` also accepts the path to a JSON file … The file form requires Claude Code v2.1.281 or later.」法国 `claude --version` 是 `2.1.282 (Claude Code)`（以会话用户跑的）。
- 字段：`prompt` 加上 frontmatter 那些字段：`description`、`tools`、`disallowedTools`、`model`、`permissionMode`、`mcpServers`、`hooks`、`maxTurns`、`skills`、`initialPrompt`、`memory`、`effort`、`background`、`omitClaudeMd`、`isolation`。`color` 会被忽略。值不合法时启动就退出（v2.1.242 起）。
- 另外有用的两条：`--strict-mcp-config` 不过滤 `--agents` 里内联的 `mcpServers`；`--append-subagent-system-prompt` 只在 `-p` 下有效（2.1.205 起）。

定义放哪：
- 放发布目录，归 root、644（推荐）。会话改不了；发哪一版就用哪一版，分支上没合的定义在法国不生效。坏处只有一个：分支上改了定义，法国要合进去发版以后才看得到。这是有意的。
- 装进会话用户家里 `~/.claude/agents/`（不推荐）：
  - `~/.claude` 归会话用户 700，会话自己就能改、能删。改了的定义对之后所有会话都生效：engine 起的、Mirasim 起的都是这一个用户。一次坏会话能把后面所有会话带偏，事后很难查出是哪次改的。
  - 要装就得改 `packages/agents-sync/src/targets.ts` 的 `SUBAGENT_TARGET.files`。它在 `standard-paths.json` 里，**算改标准**。
  - `PRETOOL_SCRIPT` 当初不用家里那份钩子，也是同一个理由（`packages/adapters/src/claude-code/args.ts:52-57` 的注释）。

### 5. 每种执行方式的改动点

现状里和方案第五节不一样的几处：
- 引擎里**没有「dontAsk 加 allowedTools」的只读阶段**。claude-code 只有两种权限：路由探针 `dontAsk`、不给工具；其余一律 `bypassPermissions`，冷验收也是（`packages/engine/src/real/hosts.ts:427-430`）。所以第五节第 4 条「只读阶段把 `Agent` 加进 allowedTools」不用做。反过来，**探针不能带 `--agents`**：每 15 分钟一问一答，带上只是白加启动成本。
- 第一帧的模型核对现在碰巧不会被子代理带偏，但没守住：
  - claude-code：`stream.ts:322-326` 只认第一条 assistant 帧的 `message.model`。主会话总要先发一条带 `Agent` 调用的消息，子代理才起，所以眼下第一条一定是主会话的。可这条代码没看 `parent_tool_use_id`（下一行 `:328` 才取）。要补一个 `!parent` 条件和一条测试。
  - Mirasim：`packages/adapters/src/mirasim/run.ts:450-453` **每一帧**都拿快照的 `model` 和点名的比，不符就 `model_mismatch` 叫停。快照里的 `model` 是 Mirasim 每帧回写的（`packages/adapters/src/mirasim/session.ts:302`）。子代理跑的时候，Mirasim 会不会把快照的 model 换成子代理的模型，**没查成**。要是会换，主会话派一个 Haiku 子代理就会被我们自己叫停。第六节的验收必须量这一条，量出来会换就要改核对办法。

具体改动见第二节。

### 6. 发版后怎么验「装上了」

不碰拼车池（整池暂停，不起它的任何会话），不白烧中转额度：

  2. 我们读到的快照 `model` 全程是不是 `claude-sonnet-5-5`，也就是第 5 条那个没查成的问题。

## 二、推荐做法

### A. claude-code（现在没流量，恢复后马上用得上；改动小，先做）

1. 生成 JSON：新文件 `packages/adapters/src/claude-code/subagents.ts`。
   - 读发布目录的 `.claude/agents/*.md`，解析 frontmatter 和正文，转成 `{名字: {description, prompt, tools, model, effort, maxTurns, omitClaudeMd}}`。
   - 去掉 `isolation`：会话已经在任务工作树里，再嵌一层工作树，改动不在交付分支上。
   - 去掉 `mcp__` 开头的工具：引擎会话带 `--strict-mcp-config`，没有 MCP。
   - 去掉 `color`。
   - 解析不了就抛错，不起会话。不拿空定义冒充装上了。
   - 写到 `/var/lib/fleet-work/_agents/<发布提交号>.json`（root、644），引擎启动时生成一次。也可以 deploy 时生成到发布目录里，这样更干净；哪种看引擎能不能写发布目录，由写码的人定。
2. `args.ts:30-50` 的 `ClaudeArgsSpec` 加 `agentsFile?: string`。`buildClaudeArgs`（`args.ts:94`）在 `--strict-mcp-config` 之后推 `--agents <文件>`。
   - 必须放在 `--allowedTools` 之前：`--allowedTools` 吃变长参数（`args.ts:129-130` 的注释）。
3. `hosts.ts:409-437` 的 claude-code 主机：`purpose !== 'probe'` 时才给 `agentsFile`。
4. `run.ts:84-89` 的 env 加 `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS: '2'`。探针不派子代理，带上也无害，统一加。
5. `stream.ts:323` 加 `!str(frame.parent_tool_use_id)`，补一条「子代理的帧先到也不当观测模型」的测试。
6. 提示词里加一句：交代会话「可以派 `fleet-scout` 查代码、`fleet-review-screen` 自审 diff、`fleet-reviewer` 交之前过一遍；不派写代码的子代理，自己写」。加在引擎拼任务提示词的地方，片 4 的写码人用 codegraph 找 prompt 构造处。
   - 写代码的那几个，在 A 里已经去掉 isolation，派了也能用。可同一个任务两路写同一棵树容易打架，所以引擎会话里一律不派。

### B. Mirasim 的 claude 执行体（现在唯一在跑的，重点）

Mirasim 的会话加不了 `--agents`：参数是 Mirasim 自己拼的，附加参数要经 `setAgentLaunch` 改，改了会杀掉所有在途回合（MS-21，`adapters.md:573`），还要挑空闲窗口、改服务端配置。所以不走参数这条路，改用 Mirasim 本来就读的「本地设置」这一层：

1. fleet-dao 的会话**现在已经读到 16 个项目级定义**（第一节第 2 条）。不另装定义。canary 仓那边没有定义，也不需要。
2. 引擎建好任务工作树后，往 `<工作树>/.claude/settings.local.json` 写一份：
   ```json
   {
     "env": { "CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS": "2" },
     "permissions": { "deny": ["Agent(fleet-builder)", "Agent(fleet-fixer)", "Agent(fleet-debugger)", "Agent(fleet-standard-editor)", "Agent(fleet-ui-builder)"] }
   }
   ```
   - deny 的这 5 个就是带 `isolation: worktree` 的那几个（`.claude/agents/` 里 grep 出来的就是这 5 个）。它们在 Mirasim 会话里会嵌一层工作树，改动丢在交付分支外面，必须硬挡。
   - 路由模型不是 Claude 的（例如经 claude 执行体跑的 `deepseek-flash`），deny 整个 `Agent(fleet-*)`。名字逐个列出来，通配支不支持没核过。不然一个 deepseek 的会话会派出 Claude 模型的子代理，扣中转的 Claude 额度，选路和记账都看不见。
   - 本地这一层只在不限 setting-sources 时才读。Mirasim 现在正是不限（第一节第 2 条）；引擎的 claude-code 会话带 `--setting-sources project`，不读它，所以两边互不影响。
   - 这个文件本机靠全局 gitignore 挡着（`~/.fleet-dao/gitignore_global:5`），**仓里的 `.gitignore` 没列它**。法国的工作树里会成为未跟踪文件，会话一 `git add -A` 就进 PR。所以要在同一片里把它加进仓根 `.gitignore`；或者由引擎写进那棵工作树的 `info/exclude`。推荐改 `.gitignore`：一眼看得到。
   - 会话自己能改这个文件（工作树归会话用户）。可它只影响这一张单的这一棵树，下一张单重新写，不会传染。这一点比装进家目录好。

## 三、风险和回退

1. **`settings.local.json` 的 deny 在 `bypassPermissions` 下管不管用**：Mirasim 起会话带的是 `--permission-mode bypassPermissions`。文档写的是 bypass「skips permission prompts」，deny 规则照不照常生效，这次没逐字核到。第六节第 4 项要量；不管用就退到 B 的 5。
2. **模型核对误杀**（第一节第 5 条）：Mirasim 那条要是会换 model，在量之前就上线 B，主会话一派子代理就被叫停。所以 B 的第 2、3 条要等第六节量完再开。顺序是：先合 A 和 B 的代码，Mirasim 的提示词那一句先不放（引擎配置开关，默认关），量过再开。
3. **非 Claude 模型的会话烧 Claude 额度**：B 的 2 已经挡了。没挡之前现在就有这个口子：fleet-dao 的 deepseek 会话已经看得到 16 个定义。好在提示词里没让它派，实际派到的概率低。
4. **额度**：子代理的请求和主会话算在同一份额度里（sub-agents 文档）。中转池并发上限 5（`pools.max_concurrency`）。每个会话限 2 个子代理：中转同时最多 5 个主会话，加上 10 个子代理。中转额度按 token 扣，不按并发扣。所以 2 这个数是防一个会话失控，不是在保护池的并发。
5. **回退**：
   - A：`agentsFile` 不传就回到原样。生成函数抛错时会话不起，所以要有开关让它降级成不带 `--agents`。降级时进度里记一条，不悄悄吞掉。
   - B：引擎不写 `settings.local.json`、提示词不放那一句，就回到原样。
   - 两边都不动 Mirasim 服务和它的配置。
