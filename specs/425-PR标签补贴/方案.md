# 方案：PR 标签补贴接上不挂单的 PR（#425）

设计依据：design 第七节「标签和里程碑不靠人记得贴」。单子挂在哪个版本上，开 PR 时照 GitHub 上那张单现读，不在这里猜。

## 前提

主线上没有 `specs/425-PR标签补贴/需求.md`。单子正文指了这份（`文档：specs/<本单号>-PR标签补贴/需求.md`），仓里和这台机器上都没有开单时写的那一份，所以下面按单子正文里的三处断点写，没有「怎么算做完」可照抄。

开 PR 前验证读的是主线上那份，不读分支上的。现在主线上没有，验的时候会停下来等人把需求文档合进主线。在这张单的分支上另写一份不算数，这一步也不写。

按推荐先做了：不挂单的 PR 缺里程碑时，挂当前版本（还开着的 `v<N>` 里号最小的那个）。正文「对应计划」写了未排期的仍不挂。创始人之后改选了别的，下一个存档点再改。

## 断在哪

- **写方**：`.github/workflows/pr-labels.yml`（PR 打开、改正文、重开、推新提交时跑主线上的 `packages/conventions/src/pr-labels.ts`）。只会照抄对应 issue 的一个类别标签和里程碑。引擎自己开的 PR 在开的时候照抄，不经这条。
- **存放处**：GitHub 上 PR 的标签和里程碑。版本记录、更新日志按里程碑收已合并的 PR，再按类别分组。
- **读方**：人看 PR 列表和版本；合并闸只提醒，不挡合并（创始人 2026-09-26：不判红）。
- **报警方**：补不上时写 job summary，并打一条 `::warning::`。检查是绿的，没人看。design 里写的「每小时对账把没贴的 PR 捞出来补判」没有做成。所以一晚上没人发现。

三处接不上：

1. 不挂单的 PR（断链当场修，标题末尾只有自己的 `(#号)`）没有可抄的单。`planLabels` 直接返回，只留一句提醒。
2. 标题认号要求括号里紧贴着右括号：`( #345 )`、`（#43）` 认得出，`（#345，创始人…）` 认不出。#392 的标题是 `（#345，…） (#392)`，第一条对不上，退到 ` (#392)`，又被当成「是这个 PR 自己」。
3. 对应的单自己没挂里程碑（未排期）时，PR 也不挂。这是已拍的规矩（没挂＝未排期；必填栏提醒也写了「对应的单未排期就不用挂」），不是断点。不改。

## 改法

认号和补贴仍是同一份（`linkedIssue`，合并闸认「认领对得上」、PR 镜像、关单对账都用它）。`pr-columns.ts` 在先审后合的清单里：只改认标题这一处，认严不认松（多认出真挂了的单，不会把本来挂了的看成没挂）。

1. **标题里的 #号**（`linkedIssue`）：左括号后面允许只有空白，接着 `#` 和数字，数字后面可以有别的字，取第一处。`（#345，创始人…） (#392)` 认成 345。`（见 #12）`、不带括号的 `#43` 仍不认。正文「需求」栏仍优先。
2. **不挂单**（认不出号，或认到的就是这个 PR 自己）：
   - 缺类别：看标题开头。`fix`（可带范围、可带 `!`）→ 缺陷，`feat` → 需求，其余（`docs`、没有前缀、`请fix:` 这种不在开头的）→ 杂项。已有类别不动。
   - 缺里程碑：正文「对应计划」以「未排期」开头（和 `pr-fields` 现有的那条是同一份，导出它，不要复制）→ 不挂、不提醒。否则挂当前版本：`milestones()` 里还开着的、标题是 `v<N>` 的，N 最小的那个（和 core 的 `currentVersion` 同一条；这个包不依赖 core）。两个号一样时用列表里先出现的。没有这样的里程碑：提醒，不编一个名字。
3. **挂了别的单**：仍只照抄那张单。单上恰好一个类别就抄；没有或有好几个，只提醒、不拿标题猜。单上有里程碑就抄；没有就提醒，**不用当前版本填**（未排期的单不要被 PR 带进当前版本）。「对应计划」写了未排期时，这条里程碑提醒也不发。号在 GitHub 上没有、或是另一个 PR：仍只提醒，不改当不挂单。
4. **提醒**：补不上的仍不让检查变红。不新做报警、不改每小时对账（两套写方会对不上）。写方把该写的写上之后，夜里那种「全空还是绿的」就没有了。

`runPrLabels` 仍是只算、再写、再核对 GitHub 回的。读里程碑列表失败、挂完读回不对，退出码 2，不当成没这回事。不挂单且不用挂里程碑时，不去读里程碑列表。

## 改哪些文件

- `packages/conventions/src/pr-columns.ts`：标题认号。注释写明括号里 #号后面可以有字。
- `packages/conventions/src/pr-labels.ts`：不挂单的补法；`planLabels` 多一个可选参数，传入当前版本标题（没有是 `null`）。文件头的「只会照抄」改掉。
- `packages/conventions/src/pr-fields.ts`：把「对应计划写着未排期」导出，行为不变。
- `packages/conventions/src/bin/pr-labels.ts`、`.github/workflows/pr-labels.yml`：文件头改成跟新行为一致。触发条件不改（不扫已经合并的）。
- `packages/conventions/test/pr-labels.test.ts`：改旧断言、加上下面的失败测试。`pr-links.test.ts` 若被认号带红，只改断言。
- `docs/design.md` 第七节那一句「按对应 issue 自动补贴」、`README.md` 同一句：补上不挂单时怎么补。别的段不动。

## 怎么验证

`pnpm test:changed`。至少这些故意造出的失败：

- 标题 `（#345，创始人…） (#392)`、正文没有号：认 345，不认 392。
- 标题 `（见 #12）`、`fix: x #43`（没有括号）：认不出。
- 不挂单、标题 `fix(engine): x`、没有类别和里程碑、有一个开着的 `v1 …`：补「缺陷」和这个版本；标题 `feat: x` 补「需求」；`账密登录的测试` 补「杂项」。
- 不挂单、对应计划是未排期：补类别，不挂里程碑，也不提醒里程碑。
- 不挂单、里程碑列表里没有开着的 `v<N>`：类别照补，里程碑只提醒，不写一个编出来的名字。
- 里程碑列表读失败：退出码 2，标签可以已经补上，但整体没补成。
- 对应的单自己没里程碑：不挂当前版本。对应计划是未排期时不提醒。
- 对应的单有两个类别：不猜。PR 已有的类别和里程碑不动。

## 不做的

- 不给已经合并的那 32 个补标签（这台没有 GitHub 凭据；工作流只在 PR 还有新事件时跑。已经开着的，要等下一次改正文或推送）。
- 不把未排期的单挂进当前版本。
- 不新做推送到驾驶舱的报警，也不在每小时对账里再写一遍标签。
