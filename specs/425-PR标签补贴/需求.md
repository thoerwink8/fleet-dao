# PR 的类别标签和里程碑补贴接不上不挂单的 PR：凌晨 32 个里 9 个没类别、18 个没里程碑（#425）

对应计划：v1 Fusion 接活
设计依据：`docs/design.md` 第七节「标签和里程碑不靠人记得贴」。

原话：「我发现你很多pr的没有打标签，存在断链吗」（创始人 2026-09-28 早）

AI 理解：
- 09-28 凌晨 1 点起合并的 32 个 PR，9 个没有类别标签、18 个没有里程碑。
- 写方是 pr-labels 工作流（`packages/conventions/src/pr-labels.ts`）：只会照抄 PR 对应 issue 的类别和里程碑。三处接不上：
  1. 不挂单的 PR（断链当场修、PR 就是记录，这种现在是多数）没有可抄的来源，只在 job summary 里提醒，没人看；
  2. 标题里认单号只认 `(#345)`，`（#345，创始人…）` 这种认不出（#392）；
  3. 对应的 issue 自己未排期、没里程碑时，PR 合并了也没有版本。
- 报警方：只有 job summary，所以一晚上没人发现。

## 要做的
1. 不挂单的 PR：类别按标题的约定前缀认（fix→缺陷，feat→需求，docs/chore/test/drill/std/refactor→杂项；带括号范围的 `fix(engine):` 也算），里程碑挂当时的当前版本（最小号开着的 `v<N>`）。标题没有前缀、又没挂单：在 PR 上留一条评论说明缺什么、怎么补（不判红），同一个 PR 只留一条。
2. 认单号：标题括号里 `#号` 后面跟着别的字（`（#345，…）`）也认。`pr-columns.ts` 在先审后合清单里，改它要第二意见。
3. 对应 issue 没有里程碑的：PR 挂当时的当前版本。
4. 回填：把 09-27 以来合并了、缺类别或里程碑的 PR 按同一套规则补一遍（一次性脚本或给 pr-labels 加一个回填入口），打出补了哪些。

## 怎么算做完
- 上面 1–3 各有测试，每条读不到、认不出的路径配一条故意造出失败的测试（读 GitHub 出错仍判「没补成」退出码 2，不当没事）。
- 回填跑过：09-27 以来合并的 PR 都有类别标签和里程碑，列表贴进结果。
- design 第七节「标签和里程碑不靠人记得贴」改成新说法。
