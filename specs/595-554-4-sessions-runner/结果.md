## 做了什么

- 三段（对题 / 动手 / 验收）走 runner 的**骨架挂上**：会话要起的时候，brief 给了 `segment` 就走 runner/one-shot 起无头进程；没给照旧走 Fusion 老链路。
- `packages/engine/src/ports.ts`：`SessionBrief` 加可选 `segment: SegmentLaunch`（`{kind:'scope'} | {kind:'manual';branch;baseSha} | {kind:'verify';prNumber;baseSha;headSha;changedFiles;diffText}`）。**不动 StageKind**（加的字段向后兼容）。
- `packages/engine/src/real/prompts.ts`：加 `segmentBriefFrom(session: SessionBrief): AnyBrief`——把 SessionBrief 转成 runner/one-shot 的 `AnyBrief`（zod 把形）。形状不对当场抛，不鲁式化。
- `packages/engine/src/real/sessions-segment.ts`（新）：`launchSegment(input, deps)`。调 `runOneShot` 起子进程、拿 `OneShotResult + SegmentVerdict` 包装成 `SegmentOutcome` 返回。依赖注入：`spawner / buildCommand / runs`——**任何一个没装当场 `SEGMENT_NOT_WIRED`**（不起、不落 runs、不造空会话、不鲁式化）。
- `packages/engine/src/real/sessions.ts`：
  - `SessionPortsDeps.segment` 是 runner 段的依赖（生产 Spawner 还没接，本切片先给测试入口）。
  - `startSession`：`brief.segment` 给了 → 走 runner 分支、登记 `segments: Map<runId, Promise<SegmentOutcome>>`、**立即返回** `StartSessionResult { sessionId: runId, resumed: false }`；没给走原 `launch()`。
  - `awaitSession`：先查 segments map，查到等那个 promise、把 `SegmentOutcome` 折成 `SessionEnd` 交回；查不到走原链路（registry / db / reattach）。
  - `reapOrphanSessions` / `stopSession` / `drain` / Jev / `screenForOtherVendor` / `flow-gate` / `hostDrivers` / `OUTPUT_FILES` 都不变。
- `packages/engine/test/real/session-segment.test.ts`（新）：9 个测试。**三段各走通一次**（scoping / manual / verify）；**故意造红**：exit=1 + 非空 stderr、exit=0 但 stdout 空（「不许拿空当跑完」）、verify verdictLine 又 pass 又 fail（一句话说不清当没结论）；**依赖没装当场 SEGMENT_NOT_WIRED**；brief.segment 没给当场 BAD_INPUT；spawner 自己抛打回。**NotWired JSONL**：verify 段跑完 `_tmp/runs-not-wired/<日期>.jsonl` 落一行，断言 `runId / segment / model / startedAt / endedAt / outcome / notWired` 全在。
- `specs/595-554-4-sessions-runner/需求.md`：本切片需求（554-3 那种形状：第一个 `## 场景` 之前带「对应计划/设计依据/原话/AI 理解」）。
- **不动**：`packages/engine/src/workflows/{fusion,requirement,subtask,merge-queue}.ts`（Fusion 完全不受影响）、`packages/api/src/done-check.ts`（554-2 统一动）、`packages/db/migrations/`（runs 真表是 #556 的事）、554-1 runner / segments 包内部。
