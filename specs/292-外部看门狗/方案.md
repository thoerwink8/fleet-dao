# 方案：外部看门狗（#292）

需求见 [需求.md](需求.md)。规矩在 design 第六节第 5 层、第十三节；做法写进 docs/ops.md 第五节「外部看门狗」。#203 的引擎看门狗照登记表报「停了」，本单不另写一套报警。

## 结论

一个不挂在香港、法国上的 Cloudflare 定时 Worker（`edge/watchdog`），每 5 分钟从公网看两台。香港看驾驶舱首页有没有 HTTP 应答（nginx 活着）；法国看公网 `/healthz`：200 或 503 算活着（503 是后端在、某一项不好，交给健康页和引擎），连不上或 502/504 算法国挂了。香港首页没有应答时只报香港，不再判法国。挂了立刻推飞书（哪台、从几点起、连着几次）；同一次挂着每小时最多再推一次；恢复推一条「恢复了，挂了多久」。

法国认它：请求头 `X-Fleet-Edge-Watchdog` 带一把令牌（香港 nginx 只清 `Authorization` 和 `X-Fleet-Acting-Feishu`，这个头会原样进隧道）。对上了就在 `schedule_runs` 记一轮 `ok`（扫了 1、发现 0——这一行只表示「来过」，不表示两台都健康）。没来超过 15 分钟，#203 按 `scheduled_jobs` 的 `edge-watchdog` 报停了。

真域名、飞书 webhook、令牌只放 Worker 的 secret 和法国 `/etc/fleet-dao/edge-watchdog.token`，不进仓。账号停在 Workers 免费档，不填付款方式。

## 为什么这样

设计已经定了 Cloudflare 定时 Worker（第三节第 14 行）。对照过的做法：

| 做法 | 出处 | 取舍 |
| --- | --- | --- |
| Cron Trigger + KV | [Workers 限额](https://developers.cloudflare.com/workers/platform/limits/)（2026-09-05）：免费档每天 10 万次请求、定时触发每个账号 5 个、定时触发 CPU 10ms（等 `fetch` / KV 不算）。[KV 定价](https://developers.cloudflare.com/kv/platform/pricing/)（2026-04-21）：免费档每天写 1000 次、读 10 万次，超出当次失败，不自动改成付费 | 用这个。`2-57/5 * * * *`（避开整点和半点，[飞书自定义机器人](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot) 说整点半点容易被限流）一天 288 次，KV 一轮最多写 1 次，都在免费档里 |
| 现成的外部探活（只配 URL） | — | 表达不了「503 算活、502 算法国挂、香港没应答别连坐法国」，代码也不进仓。不选 |
| Durable Object | 同一份定价页：免费档有，但是另一套按量和存储 | 5 分钟才读一次上次的状态，KV 够用。不选，免得碰上付费档才有的用量 |
| 不做这层 | — | 法国或香港整台挂了，引擎里的看门狗和巡检一起停，报不出来。创始人要的就是这层。不删 |

不改 nginx、`desired-config.json`、`ci-plan.ts`、`.gitignore`、迁移。这些是先审后合；探活打在已经公开的 `/healthz` 上，自定义头 nginx 本来就会往前传。`edge/` 不在 CI 的依赖图里，改到它会整库全跑，测试跑得到，不必为了少跑去改 CI 判法。

## Worker 怎么判

代码在 `edge/watchdog`（`src/judge.ts` 纯函数，`src/run.ts` 串起来，`src/index.ts` 只接 Cron）。不引用 `@fleet-dao/*`（别把节点和数据库打进 Worker）。类型用仓里的 `tsconfig`，不加重依赖；部署时 `npx wrangler@4`，wrangler 不进 lockfile。

`wrangler.toml`：名字 `fleet-edge-watchdog`，`workers_dev = false`，不绑域名（国内 workers.dev 已作废，这个 Worker 也不用网址）。cron `2-57/5 * * * *`。KV 绑定 `STATE`，`id` 写 `REPLACE_ME`。真 id 只写在部署那台机器的副本上，不提交。

Secret（值不进仓）：

- `COCKPIT_ORIGIN`：`https://<驾驶舱域名>`，只有协议和主机，没有路径。
- `EDGE_WATCHDOG_TOKEN`：至少 32 个字符，和法国那个文件是同一把。
- `FEISHU_WEBHOOK_URL`：飞书自定义机器人的 webhook。
- `PROBE_ORIGIN`：平时不设。演练时改成「要查的假地址」。

缺了前三个、或 origin 不是 https、或带了路径：这轮直接失败，不发「都好了」，也不改状态。

平时（没设 `PROBE_ORIGIN`）一轮：

1. `GET {origin}/`，不带令牌，不跟随跳转，10 秒。任何 HTTP 应答（含 3xx/4xx/5xx）都算香港回得来；超时、DNS、连不上算法国不判，只报香港。
2. 香港回得来才 `GET {origin}/healthz`，带令牌，不跟随跳转，20 秒（香港 nginx 对 `/healthz` 15 秒没回音会回 504，我们等到 20 秒，好接到这个 504）。
3. 200 或 503：法国活着，而且这轮来查记下了（法国只在记下之后才回这两个码）。502、504、超时、连不上：法国挂了。401、500、429、其他码：法国没挂（进程或代理有应答），但这轮没记下。

设了 `PROBE_ORIGIN` 时，第 1、2 步打假地址并且**不带令牌**（假地址会看见请求头）；另外再向真 `COCKPIT_ORIGIN/healthz` 带令牌打一记，只用来登记，不拿它的状态码判两台。演练完必须删掉 `PROBE_ORIGIN`。

状态一个 KV 键，三路独立（香港、法国、没记下）：挂了记起始时刻、连续次数、上次推送时刻；这轮没观察到的路冻结（不加次数、不恢复、不按小时再推）。推送正文一定带「外部看门狗」五个字，用北京时间，不写域名、地址、令牌。飞书：`POST`，`{"msg_type":"text","content":{"text":"…"}}`。HTTP 不是 2xx，或 JSON 里 `code` 不是 0，算没推成——不把状态写成「已推」，下一轮再试。推成了才写 KV；KV 写失败就抛，不当成记上了。

## 法国怎么认

`packages/api/src/edge-watchdog.ts`（子路径 `@fleet-dao/api/edge-watchdog`，跟 `agent-token` 一样，不把 Hono 再导出一遍）。

- 登记：`id` = `edge-watchdog`，名字「外部看门狗（从外面查香港和法国）」，计划「每 5 分钟」，期望 15 分钟。**不进 `ENGINE_JOBS`**（那边每条都有一个 Temporal 定时任务）。`main.ts` 的 `assemble()` 在库好了之后登记；登记抛错就让进程退出，别听着端口假装有人记。文件不在不挡启动。
- 令牌文件 `/etc/fleet-dao/edge-watchdog.token`（一行，root:fleet 640）。不进 `api.env`，也不进 `desired-config.json`。没有文件、读不了、空的、短于 32 个字符：启动照常，来查记成 `failed`，原因分别是「没放令牌」「令牌文件读不了」「令牌是空的」「令牌太短」。比较用 `tokens.ts` 的 `safeEqual`。日志不写令牌。
- `/healthz` 没这个头：跟现在一样，不记。头在、端口没接上：500，不当成记下了。头在、令牌不对：记 `failed`，对外 401，`error.code` = `edge_watchdog_rejected`，话是「不认这次来查」（对外不区分没放和对不上；原因在 `schedule_runs.why` 和日志里）。头在、令牌对：先做完健康检查，再记 `ok`（`scanned` 1、`found` 0）；记下了才按报告回 200 或 503。记的时候抛了：500，`edge_watchdog_unrecorded`，「这轮没记下」，不能回 200/503。

香港整台挂超过 15 分钟时，来查到不了法国，引擎会同时报「外部看门狗停了」。这是路径只有一条（法国不对公网开端口），不是 Worker 真停了。ops 写明：先看飞书里 Worker 自己那条「香港」；香港恢复后的下一轮会再记下，引擎那条自己撤。

- `vitest.config.ts`：`include` 加上 `edge/**/*.test.ts`。根 `tsconfig.json` 加上这个项目。

## 故意造出的失败

Worker（`edge/watchdog/test/run.test.ts`），每条都是假的 `fetch` / KV，不出网：

- 首页抛错：只推香港，不请求 `/healthz`，不说法国。
- 首页有应答、`/healthz` 回 502：只推法国。504、超时走同一条（各断言一次）。
- `/healthz` 回 503：不推法国。
- 上一轮挂着、这一轮好了：推「恢复了，挂了多久」。
- 仍挂着、离上次推送不到 1 小时：不再推；满 1 小时再推一次，次数加上。
- 飞书 HTTP 200 但 `code` 不是 0：状态不前进，下一轮还会推。
- KV 里的状态不是 JSON：抛错，不推「恢复了」。
- 这轮函数没被调用：状态原样，不会自己变恢复。
- 设了 `PROBE_ORIGIN`：打到假地址的请求没有那个头；带令牌的只有真 origin 的 `/healthz`。

法国（`packages/api/test/edge-watchdog.test.ts`，PGlite）：

- 没带头：不新增 `schedule_runs`。
- 令牌对：`ok`，然后才是 200；健康检查整体 503 时仍然是 `ok` 加 HTTP 503。
- 令牌不对、没放令牌：`failed`，对外 401，正文不带文件路径和令牌。
- 令牌对但写入抛错：不是 200/503。
- 头在、但没装这个端口：不是 200。

引擎（`watchdog.test.ts`）：`edge-watchdog` 登记超过 15 分钟、一轮都没有，看门狗推它停了（标题里是登记的那个名字）。这就是「看门狗自己没来」。

## 怎么验证

副手：`pnpm exec vitest run edge/watchdog packages/api/test/edge-watchdog.test.ts packages/engine/test/watchdog.test.ts`，再 `pnpm exec tsc -b --pretty false`。两处都过才算这步做完。

真跑不在副手这步（这台机器没有 Cloudflare 凭据，也不推远端）。授权之后按 ops 做：把 `PROBE_ORIGIN` 指到一个对 `/` 和 `/healthz` 都回 502 的 https 地址，不停真服务；5 分钟内飞书收到「法国」报警、没有「香港」；删掉 `PROBE_ORIGIN` 之后收到「法国恢复了」。演练地址会看到不带令牌的请求；令牌只打真域名。

## 不做的

- 驾驶舱搬到 Cloudflare、GitHub 事件改道、改 nginx、改法国配置对账、改 CI 怎么少跑。
- 飞书机器人的签名和 IP 白名单（出口 IP 不固定，开了白名单就推不出去）。安全设置只设关键词「外部看门狗」。
- 升到 Workers Paid，或为了强一致改用 Durable Object。
- 引擎看门狗自己的判法和文案（#203）。
