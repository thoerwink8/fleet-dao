# 一键补齐与人闸第四类：仓里开补齐 PR（.github 仓、模板仓、可复用工作流）、机器直接装，fleet project check/init，改标准要驾驶舱写的创始人已同意状态才合（项目与标准分步③）（#133）

对应计划：plan.md P2「一键补齐」
设计依据：design 15.7「二、标准」第 8–13 条、design 第五节「人闸第四类：改标准」。

原话：一键补齐，先仓后机器：仓里开补齐 PR、不直接改主线，含账号下的 `.github` 仓、模板仓、CI 可复用工作流；机器上直接装；本机 AI 用 skill 加 `fleet project init` 自己建仓、改造老仓；人闸加第四类「改标准」，合并前只认驾驶舱写的「创始人已同意」状态；任何仓的 AI 发现通用做法直接给标准开 PR。（创始人 2026-09-26 拍「项目 + 标准」方案选项 1，分步③）
AI 理解：在体检（分步②）之上加「补」：仓的缺项开一个补齐 PR（能引用的引用、引用不了的调接口对齐），机器的缺项由扩出来的 agents-sync 直接装；本机和驾驶舱按钮用同一份代码。同时把「改标准」做成真的人闸：按路径判、自动贴 `人闸`、进「要人拍」和飞书、驾驶舱写的同意状态绑提交、合并闸认它；再加自下而上的提案列表。

## 要做什么

照 `docs/design.md` 15.7「二、标准」第 8–13 条里「补」的部分和 design 第五节「人闸第四类：改标准」：

- 仓的补齐：建账号下的 `.github` 仓（公开）放 PR 模板、开单表单这类默认社区文件；fleet-dao 里放 CI 可复用工作流，各仓的 CI 引用它；建一个模板仓，新项目从它建；标签、里程碑调 GitHub 接口对齐；仓根 AGENTS.md 缺了按固定栏目起草。以上缺哪样补哪样，一律开一个补齐 PR，不直接推主线；同一项目同一时刻只有一个补齐 PR，已开着就更新它。
- 机器的补齐：agents-sync 扩出来装 skill、MCP、命令行工具，机器上直接装，装完读回核对。
- `fleet project init`：本机开补齐 PR 的命令；配一个 skill 教本机 AI 什么时候用 check、什么时候用 init、怎么建新仓；驾驶舱「一键补齐」按钮调同一份代码。补齐 PR 合进去后第二天复查，状态走到「复查通过 / 复查失败」。
- 人闸第四类：改标准的路径清单（照 `packages/conventions/high-risk-paths.json` 的做法，每条写为什么；起步是 AGENTS.md 通用段、`agents/`、标准文件、可复用工作流）；PR 改到它就自动贴 `人闸`（只作显示），进驾驶舱「要人拍」和飞书，1 天、3 天没点各再提醒一次；驾驶舱应用在 PR 当前头上写「创始人已同意」状态，合并闸认它，新推的提交上没有就判红；点「不同意」自动关 PR 并写原因。不认 GitHub 账号的批准。引擎的人闸种类（`packages/engine/src/holds.ts` 现在只有 release、spend、delete 三种，分诊提示词、库里 holds 的说明同）加上「改标准」。
- 自下而上：给标准开的 PR 要写清至少两个仓或场景；驾驶舱列出这些提案；超过 2 天没人处理推给总指挥。
- 每条做不成的路径（建仓失败、开 PR 失败、装不上、写状态失败）返回明确失败，各配一条故意造出失败的测试。

## 怎么算做完

- 测试：改到改标准路径的 PR 头上没有「创始人已同意」时合并闸判红，有时放行，再推一个提交判红；改标准以外的 PR 不受影响；点不同意后 PR 关掉、评论里有原因；补齐同一个项目两次只开一个 PR。
- 真机：一个故意缺 PR 模板和标签的测试仓，在驾驶舱点「一键补齐」，开出一个补齐 PR（PR 模板来自 `.github` 仓的引用、CI 引用 fleet-dao 的可复用工作流、标签里程碑已对齐），合进去后第二天复查通过。
- 真机：一个只改 AGENTS.md 通用段的测试 PR 自动贴 `人闸`、出现在驾驶舱「要人拍」和飞书；点同意后能合；再推一个提交同意作废、合并闸判红；另开一个点不同意，PR 自动关并写原因。
- 本机：`fleet project init` 对同一个测试仓开出的补齐 PR 和驾驶舱按钮开的内容一样。
