# 要不要「分支必须跟上最新主线」：观察到 P1 验收，过时检查漏过就开并配自动更新分支（#75）

对应计划：plan.md P1「合并队列」
设计依据：design 第六节「主线一变，在途分支自动同步」

原话：能不能全部检测都做在 GitHub 上（创始人 2026-09-25，#74 拆出来的一条）；「渐进式实现可以，渐进式记忆绝对不可以——剩下的必须在系统里留下机器可追踪的未完成承诺，带验收标准」（同日）。

AI 理解：主线规则现在不要求「分支跟上最新主线」：PR 的检查可能是在别的 PR 合进来之前跑的，结果过时（9/25 #56、#58 的检查就是在 #50 合进来之前跑的，迁移号撞了）。先不开的理由：并发 PR 多时每合一个其余都要重跑、会排队。先观察，再定。

## 要什么（二选一，都要有数）

- 观察到 P1 验收为止，数「检查过时、合进去后主线红了」的次数。
- 是 0：写明数据、关单（#75 本单关掉即可），不开。
- 大于 0：打开「分支必须跟上最新主线」，加一个 Action：主线有新提交就给开着自动合并的 PR 点「更新分支」（限频）。

## 怎么算做完

- 是 0：需求文档或结果文档里写明观察到的数据（0 次），关单不开。
- 大于 0：打开规则并配自动更新分支；验收——开两个都挂自动合并的 PR，合掉一个，另一个自动更新、重跑检查、绿了自己合，全程没人动手。

## 现状

未开工，正在观察期：数「检查过时、合进去后主线红了」的次数，到 P1 验收再定要不要开（#75 本单）。
