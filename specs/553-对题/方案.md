## 一、业务说明

### 1. 替谁、干成什么

| 环节 | 谁 | 什么场合 | 要干成什么 | 干成的标志 |
|---|---|---|---|---|
| 说 | 两位创始人（主要是创始人本人，多半语音输入） | 手机或电脑上的飞书：团队群里两人商量，或私聊机器人随口记 | 想到的事说出来就算交出去了：不用想格式、不用点按钮、不用 @ 谁 | 说完不用再做别的；几分钟内在同一处看到一张「意图卡」，看得出 AI 理解成了什么 |

## 二、现有实现里不当起点的

现状：网关 `packages/feishu`（源码约 4150 行、测试约 3600 行），后端 `feishu-routes.ts`、`feishu-records.ts`、`feishu-views.ts`、`draft-opening.ts`、`gateway-seen.ts` 共约 1750 行（测试约 4500 行），约定 `packages/shared/src/feishu-api.ts` 446 行，库里四张表（`packages/db/src/schema/feishu.ts`）。它是 09-25 按「飞书做五件事」长出来的，而且：

- **从没接过模型**：`packages/api/src/feishu-routes.ts:3`「还没接模型理解：一句话按原话记成草稿、标『拿不准』」；
- **草稿从没开成过单**：`packages/api/src/draft-opening.ts` 的 `notWiredDraftOpener`（#91 一直没接），确认了的草稿全停在「待开单」。

下面这些「怎么做」一律不当起点（后面要是又选中，必须是从业务推出来恰好一样）：

- 一句话一张草稿、「我理解为」确认卡、「改一下 / 确认」两个按钮——这就是要删的「开单界面」；
- 通用推送 outbox（五种卡、按版本回执、免打扰、求人预算）；
- 卡片登记表 `feishu_cards`（为「回复哪张卡就是在说哪件事」服务的）；
- 盘面快照缓存和置顶卡、私聊菜单；
- 九条飞书接口，和网关能进的三条驾驶舱接口（查任务、叫停、回答追问）；
- 「群里只收 @机器人」的收法（`lark.ts:76` 的 `requireMention: true`）。

| 业界 | 我们 | 怎么办 |
|---|---|---|
| 只认人主动触发：@ 才动（Cursor、Linear） | 创始人语音输入、两人对聊，每句都 @ 机器人太累；他要的是「把群聊理成意图」，伙伴不 @ 的话也是意图的一部分 | 固定群里每条都收、自动理；@机器人 只当「现在就理」。**这是要拍的第 1 条里的分歧点** |

## 四、操作剧本（改前、改后）

改前（现在的样子）：

1. 群里说一句，要 @机器人 才收；伙伴不 @ 的那半收不到。——每句多动手 1 次。
2. 机器人回一张「我理解为」卡（其实是原话照抄、标「拿不准」），点确认 → 「待开单」，永远开不出来（#91 没接）。——断在这。
3. 对题时指挥官看不到飞书里说过什么，创始人得再说一遍，或把聊天复制给指挥官。——搬运至少 1 次、离开 1 次（切到飞书翻记录）。

改后：

1. 群里、私聊照常说话，不用 @、不用格式。——动手 0。
2. 停下来几分钟，这段第一条原话下面出现一张意图卡：AI 归纳 + 「N 条原话已存」。看一眼；归纳不对就回复这张卡补一句。——动手 0，想改时 1。
3. 坐到电脑前对题：指挥官开头就列出新的意图（原话 + 归纳），聊清楚，`pnpm issue:new … --intent 42` 开单，「原话」栏自动原样照抄；飞书里那张卡变成「已开成 #N」，伙伴也看得到。——搬运 0、离开 0。

## 五、方案（推荐的 A）

一句话：**香港网关收下创始人在飞书里说的每一句、原样转给法国；法国按段存成「意图」，引擎用 GPT-Luna 归纳；网关把归纳回成一张没有按钮的意图卡；指挥官对题时经 `pnpm intents` 读，开单时原话照抄。** 旧的草稿、推送、盘面、菜单整套退掉（第七节）。

```
飞书（团队群 / 私聊）
   │ 事件：每条消息（不计调用量）
   ▼
香港网关 ── POST /api/feishu/intake/messages ──► 法国后端：存原话、切段 ──► intents / intent_messages
   ▲                                                         │
   │ GET /api/feishu/intent-cards（长轮询）                    │ 引擎每分钟一轮 intent-summarize
   │ POST /api/feishu/intent-cards/acks                        ▼
   └──────────────── 发 / 改意图卡 ◄──────────── GPT-Luna 归纳（cursor-agent，一次性、只读）
                                                             │
本机指挥官 ── pnpm intents（ssh）──► fleet-api intent list / show / link / drop
```

### 5.1 意图从哪进、怎么触发

- **入口用现有的**：香港网关已经连着的飞书长连接（`im.message.receive_v1`），不另开一套事件订阅；改的是收法。
  - 私聊：创始人发给机器人的每一条都收（现在就收）。
  - 群：只在允许的群（团队群、测试群）里收，**创始人的每一条都收，不用 @**。要在飞书开发者后台给应用加「获取群组中所有消息」（`im:message.group_msg`，敏感权限）并发一版应用——只有创始人能做（第〇节「要你做的」）。没开这个权限时网关照样只收得到 @ 和私聊，并在 `fleet-gateway-deploy status` 和后端 `/healthz` 里写明「没开群消息权限，只收得到 @ 和私聊」，不装作全收了。
  - 不收：陌生人（私聊一天礼貌拒一次）、机器人的话（包括它自己的意图卡）、别的群。
- **网关不判这句话是什么意思**，收到就原样转给法国，归到哪段由法国定。
- **切段**（这句归到哪段意图），法国按顺序判，第一条命中就定：
  1. 在飞书话题里（有 `thread_id`）：同一个话题 = 同一段。
  2. 回复了某张意图卡，或回复了已经在某段里的话（`parent_id`）：进那段。
  3. 「@机器人 另起」：从这句起另起一段。这是唯一的口令——飞书上不再有菜单和别的命令。
  4. 都不是：同一个会话里，上一句离现在不到 15 分钟、且那段还没被对题用掉，就接着那段；否则另起一段。

  切错了不在飞书里修：对题时指挥官能把几段并成一张单，或只抄其中几条（5.5）。业界是靠人主动触发圈定范围（第三节 Linear、Cursor），这里改成默认全收、对题时再修，因为创始人用语音、两人对聊，事前圈定太累——这是要拍的第 1 条里的取舍。
- **什么时候归纳**：一段停下来（私聊 90 秒、群里 5 分钟没新话）就归纳；有人在这段里 @机器人 就马上归纳；之后又来了新话，等它再停下来重新归纳、原地改那张卡。群里等 5 分钟，是为了不在两人说到一半时插一张卡（第一节规则 10）。
- **撤回、编辑**：收到撤回就把那条标「已撤回」（行不删），不再进归纳和原话栏、卡上的条数跟着变。飞书撤回、编辑事件的确切名字和要不要另开权限，开发时实测；编辑过的另存一版，原来那版不覆盖；拿不到编辑事件就以第一次收到的为准，并在 `pnpm intents show` 里注明「飞书里可能改过」。

### 5.2 存哪、什么形状

两张新表，在法国库（只建表，不动旧表；按合并闸的判法只建表不算先审后合）：

**`intents`**（一段意图一行）

| 字段 | 说明 |
|---|---|
| `id`、`seq` | `seq` 是给人看的号（「意图 42」） |
| `chat_id`、`chat_kind`、`thread_id` | 哪个会话（团队群 / 测试群 / 私聊）、哪个话题（可空） |
| `status` | `new` 没用过 / `linked` 开成或并进了某张单 / `dropped` 放下（必带理由） |
| `links` | 用到了哪几张单（`owner/repo#N`，可多张）、谁、什么时候 |
| `message_rev` | 每来一条、撤回一条加 1 |
| `summary`、`summary_covers_rev`、`summary_model`、`summary_route`、`summary_at`、`summary_run_id` | 归纳正文；覆盖到第几版；执行体报回的实际模型（只写观测值）；走的路由；几点写的；`runs` 表里那一笔 |
| `summary_state`、`summary_error`、`summary_attempts`、`summary_next_try_at` | `waiting` 等归纳 / `running` / `done` / `failed` / `capped`（到每日上限）；没成的原因和每次的原文；第几次；下次几点 |
| `card_message_id`、`card_rev`、`card_error` | 飞书上那张卡、卡上显示到哪一版、没发成的原因 |
| `first_message_at`、`last_message_at` | 起止 |

**`intent_messages`**（一条飞书消息一行，原话就在这）

| 字段 | 说明 |
|---|---|
| `message_id` | 飞书消息编号，主键（幂等） |
| `intent_id`、`chat_id`、`thread_id`、`parent_id` | |
| `sender_user_id`、`sender_name` | 创始人在 `users` 里的号；当时的显示名（存快照） |
| `sent_at`、`received_at`、`source` | 飞书的发出时刻；收到时刻；`event` 事件 / `backfill` 补漏 / `legacy_draft` 旧草稿导入 |
| `msg_type`、`text`、`raw_content` | 类型；规范化后的原文（@ 换成名字、富文本取文字，**不截断**）；飞书给的原始内容，留底对账 |
| `recalled_at` | 撤回了就标，不删行 |

形状上的几条讲究：

- 原话和归纳分开存，归纳带「谁写的、几点、覆盖到第几版」——「归纳之后又来了 2 条」一眼看得出，不会拿旧归纳冒充新的。
- 非文字消息不丢、不悄悄跳过：图片、文件记成「[图片]」「[文件 名字]」并留 `file_key`；语音消息记成「[语音：飞书接口拿不到文字]」；认不出的类型记成「[认不出的消息类型 xxx]」并留原始内容。都进原话，明说是什么。
- 合并转发（把别的群里一段话转给机器人）：展开成里面的每一条（读一次飞书接口）。飞书文档没写子消息保不保留原说话人和时间，开发时实测；保留不了就写「转发自……，原说话人未知」，不编。
- 旧草稿里的原话搬进来：`feishu_drafts` 里没开成单的草稿（因为开单器从没接上，可能就是全部）是创始人真说过的需求，建表的同一个迁移把它们按「一条草稿一条原话」导入（`source = legacy_draft`，`INSERT … SELECT`，只加不改），再删旧表时就不丢话。表里现在几行这次没查（只写方案、不碰法国），导入是幂等的，0 行也照样过。

**给指挥官读的口**（指挥官在本机；法国不对外开口子）：

- 法国：`fleet-api intent list|show|link|drop`（和 `fleet-api alert …` 同一个命令行；`--json` 给机器读）。
- 本机：`pnpm intents [list | show 42 | link 42 --issue 812 [--comment] | drop 42 --why …]`，经已有的 ssh（`~/.fleet-dao/france-ssh`，和 commander 技能的 `france.mjs` 同一条路）跑上面那个命令。
- 形状只写一份：`packages/shared` 里的意图约定，命令行 JSON 和以后驾驶舱接口共用。驾驶舱的「意图」页等驾驶舱按个人用重做时再加（goals E），这次不做页面、不做没人用的接口。
- 为什么不开 HTTP 口给本机读：要新发一种长期令牌、改登录鉴权（`session.ts` 是先审后合的碰安全路径），多一个对公网的口子；ssh 本来就有，不新增攻击面。代价是要这台配了 ssh——没配就明说读不到（第六节 C1）。

给人看的样子（`pnpm intents show 42`；飞书卡上同样分两块）：

```

原话（原样，没改一个字）：
  [14:02 甲] 我觉得驾驶舱首页太乱了
  [14:05 乙] 对，要一眼看到要我拍的
  [14:09 甲] 还有在跑的卡在哪一环
AI 归纳（GPT-5.6 Luna 写的，不是原话 · 14:11 · 覆盖到第 3 条）：
  首页改成一屏三块：要我拍的、在跑的（显示卡在哪一环）、做完的。
```

### 5.3 模型怎么调

- **在哪跑**：法国引擎（`fleet-engine`）里一个定时任务 `intent-summarize`，每分钟一轮（Temporal 定时任务，和 `quota-read` 同一个机制）。不放香港（AI 活只能在法国）；不放驾驶舱后端进程（后端没有起执行体的权限：起会话要以会话用户身份经 `fleet-agent-scope`，sudoers 只放行引擎，给后端加就是改 sudoers，碰安全）。
- **选路**：路由两层（#574）的用途表加一个用途 `intent`，模型顺序只写 `gpt-5.6-luna`（创始人定的；以后要加后备模型是改配置，不改代码）。这个模型现在开着的路由是 `cursor:gpt-5.6-luna:cursor-agent`；`mirasim-relay:gpt-5.6-luna:mirasim` 按 09-27「mirasim 额度不太够」关着（`packages/db/routing.default.json`）。选路照常先过「这条路由活着吗」（探针、额度、禁令）。
- **怎么起**：复用引擎的一次性执行器（`packages/engine/src/runner/one-shot.ts` + `real/segment-spawner.ts`，#632 已接上生产），不另写启动命令：新会话、不续；cursor-agent 不带 `--force`（什么命令都跑不了）；工作目录是空的临时目录；提示词走 stdin；总时限 3 分钟；起之前照常做内存准入。
- **喂什么**：这段的原话（带说话人、时间、按顺序；撤回的不喂），加一段固定说明：「用一段话归纳他们想要什么；只写原话里有的，不补、不猜怎么实现；没说清的写『没说清：……』；只输出一行，以『归纳：』开头，不超过 300 字」。
- **收回来怎么判**：先过 `judgeRun`（adapters 里判「跑完了没有」的那一份），再判内容——恰好一行以「归纳：」开头、去掉前缀后非空、不超过 300 字，才算做成；不合就是没做成，原文落盘留查。
- **记账**：每次调用回来记 `runs` 表（token、起止、结局）。段记 `scope`：归纳是对题段的一部分（#553 第 4 条），记在指挥官那段的花费里；不另加段名，免得改 `runs` 的检查约束（`packages/db/src/schema/runs.ts:89`，改约束就是改库）。
- **重试按表办**（0010 第 7 条：每类都带总次数和最长等待，超了停下报人；停下那一刻写出这个原因出现过几次、每次的原文）：

| 没成的原因 | 怎么办 | 上限 |
|---|---|---|
| 没有活着的 GPT-Luna 路由 | 不换别家模型，等路由活过来 | 最长等 6 小时，过了标 `failed`、进驾驶舱提醒 |
| 额度用满 | 等到清零时刻（读得到就按它，读不到 30 分钟后再试） | 同上 |
| 起不来、超时、被杀、内存放不下 | 1、5、15 分钟后再试 | 总共 3 次 |
| 模型回了空的、格式不对、太长 | 马上再试一次 | 总共 2 次 |
| 同一个原因连着 2 次 | 停，标 `failed` | — |

- **每天上限**：一天最多归纳 60 次（可配）；到了标 `capped`，卡上写「今天归纳次数到上限，明天 0 点后接着归纳；原话已存」。为什么要有：cursor-agent 点名具体模型，扣的是 Cursor 订阅里「按月美元额度」那个桶（`packages/adapters/src/cursor/args.ts:7`），和创始人在编辑器里用的是同一份；一次最小会话就约 1.3 万输入 token（`docs/design.md:464` 实测）。按一天 20 段、每段归纳两次估，一个月约 1800 万 token；GPT-5.6 Luna 在 Cursor 里的单价这台查不到（要看 Cursor 后台），所以先上上限、`runs` 表记实数，跑一周再调。
- **引擎没开时**：现在法国引擎按「生效中的临时调整」关着（`docs/PROGRESS.md`，复查 10-15）。关着时原话照收照存，归纳排着队、卡上写明「法国引擎没开，开了自动补」；后端 `/healthz` 加一项 `intent_summarizer`：有意图在等归纳、引擎超过 10 分钟没跑这一轮，就报「排着 N 条，最早等了多久」，不报「好」。什么时候开见要拍的第 2 条。

### 5.4 网关剩什么（`packages/feishu`）

| 留 | 改成什么样 |
|---|---|
| 长连接收事件 | 白名单群里不再要求 @（`requireMention` 关掉）；照旧不合并连发、晚到 6 小时内的照收 |
| 收到就转后端 | `POST /api/feishu/intake/messages`，代表说这句话的那位创始人（后端照旧按 open_id 认人）；5 秒超时 |
| 2 秒内表情回应 | 只对私聊和 @机器人 的那句加；群里对聊不逐句加 |
| 没记成要看得见 | 转不过去（连不上、超时、5xx、被拒）就在那句话上加一个「没记成」表情、记错误，并标「这个会话要补漏」 |
| 补漏（#42） | 网关起来时、长连接重连后、后端从连不上变回连得上时：问后端每个会话最后存到哪（`GET /api/feishu/intake/cursors`），从那里起翻飞书历史（话题再按话题翻），把缺的按原顺序补送（幂等）；补上了，那句的「没记成」换成正常。香港不写磁盘、不建本地队列：飞书自己就存着原话，它就是缓冲。只在这几种时候翻，每次每个会话一两页，离每月 1 万次很远 |
| 发、改意图卡 | 长轮询 `GET /api/feishu/intent-cards`（有要发或要改的就马上回）→ 发卡（回复这段第一条原话，带 uuid 防重复）或原地改卡（飞书只让改 14 天内的，改不了就新发一张）→ 回执 `POST /api/feishu/intent-cards/acks`。卡上没有按钮。这段最后一句话离现在超过 30 分钟的（例如引擎刚开、补归纳一批），照驾驶舱设置的免打扰时段等时段过了再发 |
| 自己看着自己 | 心跳照旧；看的定时活从「推送、盘面」换成「意图卡长轮询」；5 分钟没走通往团队群报一次（不经后端）；免打扰时段从长轮询回包里带 |
| 日志 | 照旧只记长度不记原文；「消息处理完」这几个字香港 `status` 在数（`deploy/hk/fleet-gateway-deploy.sh:29`），不改 |

旧卡上的按钮、私聊菜单还会有人点：网关回一句「这个按钮（菜单）已经停用：飞书现在只收意图」，不悄悄不理（菜单要创始人在开发者后台删掉，第〇节）。第一次上线时，把团队群置顶的旧盘面卡改成「盘面已搬到驾驶舱」并取消置顶（用旧的 `/feishu/board` 读出卡号；这条旧接口下一版才删，第八节）。

### 5.5 指挥官怎么用（对题那段）

- **起步多看一样**：commander 技能「起步」第 2 步的四样之外，加「飞书里还没处理的意图」（`pnpm intents`）；读不到就说读不到，不说「没有」。
- **开单**：`pnpm issue:new … --intent 42[,43] [--only 42:1,3]`
  - 「## 原话」栏先放意图里的原话，原样照抄（一条一行，带说话人、时间、意图号）；指挥官自己写的「## 原话」（对题时创始人在会话里说的）接在后面，两个小标题分开；
  - AI 归纳不进「原话」栏；
  - 正文末尾带一行隐藏标记 `<!-- fleet:intent 42 -->`，留来历；
  - 开完自动 `intent link 42 --issue <这张>`；单开了、意图没标上，退出码单独一个（4），打出补标的命令，不当成都做完了。
- **并进已有的单**：`pnpm intents link 42 --issue 812 --comment`：把原话作为一条评论贴到 #812，再标 `linked`。
- **原话进的是公开仓**：照抄之前，指挥官先把要抄的那几条给创始人看一眼，不想公开的用 `--only` 挑掉（群里随口说的不一定想公开）。
- commander 技能说明要改的原文见附录；它是改标准，拍方案时一起看，算同意。
