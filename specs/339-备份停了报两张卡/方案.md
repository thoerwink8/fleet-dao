# 方案：备份停了只留看门狗那一张卡（#339）

需求见 [需求.md](需求.md)。看门狗（`packages/engine/src/jobs/watchdog.ts`）已经按 `scheduled_jobs` 报「停了」：期望间隔里没开跑，推 `watchdog:job:<编号>:…`，`packages/engine/test/watchdog.test.ts` 里「停了照报」那条核对过。备份每小时巡查 `deploy/backup/fleet-backup.sh` 的 `watch_fresh` 用 `backup.stale:<编号>` 再推一张。两边阈值都是登记的期望间隔。删巡查里这段判断，一件事只留看门狗。

## 怎么改

删掉 `watch_fresh`（读 `backup.nightly`、`backup.drill` 的上次开跑、超了就 `alert_raise`、没超就按新鲜解除）。磁盘用量（`watch_france`、`watch_hk`、`check_disk`）不动。不改成「照查、不报警、记进这一轮的扫到/查出」：那样「没开跑」还在巡查的结局里存第二份。

已经开着的 `backup.stale:` 没有别人撤（看门狗的键是 `watchdog:job:`）。`cmd_watch` 在看完磁盘之后，对 `backup.stale:backup.nightly` 和 `backup.stale:backup.drill` 各 `alert_resolve` 一次。只撤、不读登记表、不加进 `WATCH_SCANNED` / `WATCH_FOUND`、绝不 `alert_raise`。下一轮巡查把旧卡收掉，之后是空更新。这两行上面写一句：这两个键是退役的「没开跑」卡，判断在看门狗，这里只收旧卡。

扫到的项少两个（不再数那两个任务）。`bk_outcome` 不用改：

| 情形 | 现在 | 改完 |
|---|---|---|
| 两台盘都正常 | `ok\|4\|0` | `ok\|2\|0`（法国一块、香港一块；同盘去重照旧） |
| 法国盘到线 | `ok\|4\|1` | `ok\|2\|1`，仍只报 `backup.disk:france:/` |
| 香港连不上 | `partial\|3\|0` | `partial\|1\|0`（只扫到法国那块；香港两个路径仍算没查成） |
| 每晚从没跑过、演练过了期望间隔 | `ok\|4\|2`，推两张 `backup.stale:` | `ok\|2\|0`，`raised` 里没有 `backup.stale` |
| 登记表查询失败 | `partial\|2\|0` | `ok\|2\|0`（巡查不再读这份登记，不当成没查成） |

结局那句改成「看了 N 项，超线 M 项」，去掉「或过期」。给人看的名字去掉「新鲜度」（看门狗标题用登记表里的名字，`install.sh` 重跑时按 `BK_JOBS` 更新）：

- `deploy/backup/lib.sh` 的 `backup.watch`：`磁盘用量（法国、香港）`。计划仍是「每小时 17 分」，过期分钟仍是 90。
- `run_start` 的名字：`磁盘巡检`（没做成的卡用这个）。
- `units/fleet-backup-watch.service`、`fleet-backup-watch.timer` 的 `Description`，以及 service 文件头那句，不再写新鲜度。时刻、用户、路径不改。
- `fleet-backup.sh` 开头：`watch` 只写两台磁盘用量；每晚备份和演练停了由看门狗报。
- `docs/ops.md` 第十一节那一行改成：两台磁盘用量（线仍在法国 `backup.env`）；每晚备份和演练多久没开跑由看门狗报（上文「看门狗」那段），这里不报。紧跟着加一句：巡查不再推 `backup.stale:`；机器上还开着的这种旧卡，新脚本每小时只撤不重判；停了的那张卡是看门狗的 `watchdog:job:backup.nightly` 或 `backup.drill`。

## 不改

- 看门狗和 `watchdog.test.ts`。
- `packages/engine/test/real/hourly-reconcile.test.ts` 里用 `backup.stale:nightly` 当样本的那条（测的是「没人处理再推」，不是巡查会报这个键）。
- `docs/design.md`：没写巡查自己查没开跑。第六节第 5 层已经是看门狗按登记表看，包括备份。
- 磁盘报警、演练对不上（`backup.drill:mismatch`）、三个任务自己的「没做成」（键以 `<编号>:run` 开头）。
- 钥匙、仓库、restic、定时器时刻、`install.sh` 的逻辑。登记名字它已经会按 `BK_JOBS` 写进 `scheduled_jobs`。

## 测试

`bash deploy/backup/test/backup.test.sh`。`stub_watch` 继续用 `bk_sql` 吐出两行年龄，这样谁把 `watch_fresh` 加回来，下面两条会红。

- 都正常：期望改成 `0 ok|2|0`。解除列表不变（两块盘、两个 `backup.stale:`、`backup.watch:run`）——后两个是收旧卡。
- 法国盘到线：`0 ok|2|1`，仍只报 `backup.disk:france:/`。
- 香港连不上：`0 partial|1|0`。连不上出现两次、不解除香港盘、只报 `backup.watch:run`，这三条不动。
- 把「两个都报」改成故意造的失败：`AGE_NIGHTLY=never`、`AGE_DRILL=700000`。期望 `0 ok|2|0`，`raised` 里没有 `backup.stale`。
- 把「登记表读不到 → partial」改成：`bk_sql` 失败时期望 `0 ok|2|0`，不推 `backup.stale`。
- 「配置读不到 → 没做成」「什么都没查成 → 没做成」不动。
