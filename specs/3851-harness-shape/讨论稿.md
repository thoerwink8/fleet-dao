## 一、提出的问题

### 1. 整体形态的主轴：AI 调度、人验收

- **现象**：#3770 已按片落地内核（事件、调度、派工、工人壳、只读驾驶舱），但各片是按「替换旧引擎」拆的，没有回答「人在哪一步介入」「另一个工作环境怎么用」「会话、编排、子代理、远程宿主各长什么样」。#3782（指挥官会话）开工前需求方叫停，要先定整体形态（实测：#3782 评论 2026-11-03）。
- **需求方的思路**：另一个工作环境的项目要人工验收，调度全部交给 AI；高级模型调度、低一级模型执行，人在验收这一环把控；这一环以后也能自动，和 VPS 驾驶舱改造的初衷一致。
- **判断**：成立，而且两种环境本来就是同一套东西，差别只在「验收闸」的策略。人工验收要成立有三个前提：①每张交回带全证据，人是核对不是重查，否则人成瓶颈；②便宜模型失败或被退回时自动换强一档重做，不需要人；③自动放开按「模型 × 任务类型」一格一格按数据放，不一刀切。
- **做法**：见 1.2 概念模型和 1.3 验收闸。
- **不做什么**：不改 0124 的影子 → 真执行 → 金丝雀 → 切换梯度；不动旧引擎。

## 五、要拍板的

1. **验收闸怎么放开**：A 一格达标就自动开闸、事后通知；B 系统出「可开闸」卡，人点了才开，出撤回就自动降回；C 一直人工。**建议 B**：每一格放开都有人一次确认、能回溯。阈值：已成熟（合并满 7 天）≥20 件、首次成功率 Wilson 95% 下界 ≥90%、最近 10 件零撤回零重开（口径同 #3842 稿第一节第 4 条）。不定的话：全部人工，等于现在的行为。
2. **另一个工作环境里，过了验收谁推送、开 MR**（承接 #3849 第五节第 1 条）：A 内核经 outbox 推分支、开 MR；B 只出本地分支和补丁，人自己推。**建议先 B 一周再开 A**：有人工验收闸，「过」本身就是授权；同事照常在 MR 上评审。
3. **另一个工作环境的代码能发给哪些模型、那边跑不跑 Claude 订阅**：只走那边统一网关里的模型；在那台机器跑 reclaude 会占第 5 台设备（决定 0018 写了四台已满），可能要掏新钱。**建议那边只走统一网关，不跑 reclaude。**
4. **远程宿主要不要往远端放常驻帮手 hostd**：A 放（单文件、要 node），断线照跑、能看终端；B 不放，纯 `ssh` 加远端 `tmux`，更脆、接回难；C 只看终端不派活。**建议 A**；往别人的服务器放东西要先确认有没有权限。
5. **能不能直接对在跑的工人说话**：A 只能对指挥官说；B 另外允许对在跑的工人发「引导」，只补方向不派新活，记成事件并抄给指挥官。**建议 B**：omo 的节点引导、Mirasim 的 steer 都证明有用；不开新活，不绕过指挥官的派工判断。

需求方 2026-11-03 拍板，总原则：**一律做成可配置**。

- 第 1 条定：验收闸做成配置，项目 × 任务类型一格一个档位（人工 / 按战绩自动 / 自动），全局一键冻结＝全部降回人工；默认 local 全人工、VPS 按战绩自动加硬人闸名单；一格达标出「可开闸」卡，人点了才开，出撤回自动降回（即 B 作为默认行为）。
- 第 2 条定：外送做成配置项（本地分支加补丁 | 内核推送），local 默认本地分支加补丁，验收过后由需求方自己推、开 MR。
- 第 3 条定：另一个工作环境不用 Claude 订阅。模型来源自定义：像 Mirasim 那样可自定义渠道，每个渠道填启动命令（reclaude、claude 或别的 CLI）、参数、环境变量（base URL、密钥变量名）、协议（anthropic / openai 兼容）、可用模型；路由按环节选渠道加模型；密钥仍走回环代理，不进工人。
- 第 4 条定：A，远程主机放常驻帮手 hostd。
- 第 5 条定：B，能对在跑的工人发引导。
- 追加：本机装法的主形态是 Windows 桌面软件，选型评估中（见 6.4a、#3754）；界面和产品文案做通用，不写本仓私有说法（见 6.4 末尾）。

### 6.2 概念模型

```
环境 Environment（装法：france | local）──1:1── 内核实例（一份 fleet2 库）
 ├─ 项目 Project ＝一个仓：平台(github|gitlab)、仓类(自用|对外→决定留不留痕)、验收策略
 │    └─ 单 Task：需求原文、验收条、任务类型（缺陷/功能/重构/测试工具/文档配置 × 域 × 碰界面 × 规模，派工前定）
 │         ├─ 指挥官会话 Session(role=commander)：一张母单或一批一个，强模型
 │         │    └─ 计划 Plan vN（带版本哈希）：子任务 + 依赖 + 写范围 → 波次＝依赖深度（只是显示）
 │         │         └─ 子任务 Subtask ──1:N── 尝试 Attempt(runId)：工人会话 + 路由 + 宿主 + 工作目录
 │         │              ├─ 一题多派：同一次 fan-out 里 N 个候选，择优出一个
 │         │              └─ 交回 Handback → 核验 Verify（机器四态 + 不同家模型）
 │         └─ 验收 Acceptance（每个要外送的改动一条）：策略判 人工|自动 → 过 / 退回(理由) / 改派 / 放弃
 │                └─ 外送 Change：PR/MR/本地补丁（经 outbox）→ 最终结局（合并、7 天内撤回、单重开）
 ├─ 宿主 Host：local | ssh | vps；能力、隔离档位(强/中/弱，读回不自称)、槽位
 ├─ 渠道 Channel：协议(anthropic|openai|grok-cli)、baseUrl、密钥环境变量名、可用模型
 ├─ 路由 Route：键＝环节(commander|plan|code|verify|quick) [+任务类型]；值＝{渠道、模型、壳、兜底链、fanout、并发键}
 └─ 战绩 Track：模型 × 任务类型一格，从事件增量算 → 喂验收策略
注意力条目 Attention：任何「要人」都投影成一条（拍板、验收、卡住、没看过的完成），带理由
```

- 认领、所有权仍在 `tasks.owner/fencing`；宿主只是执行地点，不持有权威状态，hostd 的输出只当缓存。
- 路由命中哪条规则写进 `worker.spawned`，战绩靠它分格；验收结论和策略改动都是事件，能回溯。

### 6.3 验收闸

### 6.4a 桌面软件与技术选型

本机装法的主形态是 Windows 桌面软件（需求方 2026-11-03 定，决定 0125 第 8 条）。

**选型（已定，评估人设计子代理，指挥官拍，2026-11-03，#3754）：Tauri 2 外壳加现有 TS 内核作 Node 附带进程**。内核随包带 `node.exe` 加打包后的 JS，先不用 Node SEA。新开片 6（#3858）的 `fleet2 up` 是这个附带进程的入口。

**为什么**：
- 竞品里带界面的四家（cc-haha 从 Tauri 迁回 Electron、Mirasim、omo/T3、stablyai/orca）都是 TS 后端加极小的 Rust 或原生件；全 Rust 的只有纯终端的 herdr。
- 旧坑（状态散、对账、认领撞车）是设计层问题，换语言修不好。
- Windows 收尸现状是真缺口：`harness-runner/src/process.ts:170-176` 用 `taskkill /T`，`procs.ts:131` 在 Windows 下 leftovers 为 undefined。

**不走的**：内核全 Rust 重写（量大，旧坑不因语言消失）；Electron 全栈（体积和内存更大，也没解决收尸缺口）。

**Rust 边界**（只有三样）：

| 件 | 为什么是 Rust |
|---|---|
| 桌面外壳（`apps/desktop`，Tauri 2） | 外壳本身；不含业务代码、不给页面开调外壳的接口，Tauri 与 Electron 可互换 |
| `jobrun`（`crates/jobrun`） | Windows Job Object，Node 没有；要比内核活得久 |
| `hostd`（`crates/hostd`） | 本机与 SSH 远端同一个程序；远端没有我们的运行时，不需要 node；PTY（ConPTY、setsid）也放这 |

判据：(a) 要 Node 没有的系统原语；(b) 要在没有我们运行时的机器上跑；(c) 必须比内核活得久。三条都不沾的留 TypeScript。

**迁移路径**：`harness-runner` 抽 `ProcessHost` 接口，`local`（现状）、`jobrun`、`hostd` 三个实现跑同一套一致性测试，装配档案（6.6）决定用哪个。先 R1（jobrun），再 S1（外壳），H1（hostd 本机）与外壳并行。

**签名与体积**：先不签名（签名要掏钱，掏钱前问创始人）。安装包推断约 45–55MB、装好约 130MB（推断）；第 0 片实测（见下）：带内核安装包 27.0MiB、装好 110.5MiB，空壳 1.03MiB，更正 3752 稿「约 10MB」。

**不确定点**（第 0 片实测）：
- PGlite 写入中被强杀后能否恢复（目标 50 次 0 损坏）；
- 原生模块打包：随包带 node.exe 时原生模块（若有）能否装进去并加载；
- 杀毒 / EDR：未签名 exe 和 Job Object 行为是否被拦；
- WebView2：目标机缺失或版本旧时的行为。

**第 0 片实测结果**（#3868，2026-11-03，本机 Windows 11 Pro 10.0.26300；脚本都在 `scripts/desktop-probe/`，输出原文在 PR 描述里）：

**和推断的差异**：
- 安装包推断 45–55MB：实测带内核 27.0MiB，**比推断小**（没算页面静态文件，页面加几 MB）。装好推断 130MB：实测 110.5MiB，同样偏小。数量级对，推断偏高。
- 3752 稿"约 10MB"：空壳实测 1.03MiB，比那个数还小；但带内核后 27MiB，不是 10MB。Electron"约 150MB"：空壳实测 115.6MiB、带内核 142.5MiB，数对得上。
- 内存：推断里没有，实测内核 PGlite 一个进程 230MB 是大头；若要压内存，要看的是内核，不是壳。

**实测中查出来的两个打包缺陷**（内核运行代码的问题，本片不改，已另开 #3889）：
- `packages/harness-store/src/index.ts` 的 `MIGRATIONS_FOLDER` 用 `new URL(...).pathname`，没有解码；安装路径里有空格或非 ASCII 字符（`C:\Program Files\…`、中文用户名）时变成 `%20` 之类，开库报 `Can't find meta/_journal.json`。实测：安装到 `D:\frank\probe sp ace\` 内核起不来，换成无空格路径就好。应改成 `fileURLToPath`。
- local 档案在运行时按 `../../package.json` 读版本号，打包后这个路径不存在，直接崩；应在构建期内联版本号。

### 6.5 四条关键流

**① 讨论 → 计划卡 → 拍板 → 拆成波次 → 派工人**
1. 输入框说一句，内核起一轮指挥官（`claude -p --resume`，路由 `commander`，强模型）；在跑时再说话默认进队列，「引导」注入当前轮下一步，「插队」打断后先跑这句（照 Mirasim `queue steer/jump`）。
2. 指挥官调 MCP `propose_plan`（子任务、依赖、写范围、任务类型、建议路由、预计 token），会话里出**计划卡 vN**（带版本哈希），按钮：批准、要改（一句话）、否。
3. 批准写 `plan.approved{hash, by, expiresAt}`；计划再改，批准作废（0124 已定）。
4. 编排放行：依赖都完成、有空位、写范围不重叠，每放一个写 `worker.spawn.requested{subtaskId, route}`；右侧坞「工人」标签出子代理卡片（状态点、名字、模型、宿主、用时、一句话活动），点开看过程。

**② 一题多派择优**
1. 路由写 `fanout: [{grok-4.7}, {glm-5.3}, {kimi-k3.1}]`，或计划卡上单个子任务勾「多派」；每个候选各自工作目录、同一基线。
2. 都交回后机器择优，判据按顺序：核验四态只认 passed → 检查命令过几条 → 越界 0 → 改动行数小优先 → token 少优先；同分并列进验收卡由人选。
3. 落选补丁存进 `fleet2`（同 `shadow_runs` 做法），工作目录删掉，不推分支。
4. 每个候选都进战绩，正好补 #3842 要的同题配对数据。

**③ 注意力队列**
1. 工人状态判读改成写事件 `worker.state.judged{state, rule, evidence, fallback}`，加 `unknown`；规则仍只有 `worker-state.ts` 一份，投影存当前态。
2. 「待我」投影四类：卡住（带理由）、待拍板（计划卡、改标准）、待验收、完成没看过；排序照 herdr，同类按等了多久。
3. 推送沿用 #3752 稿第五节第 3 条第 5 项：网页推送，飞书个人消息兜底；local 用系统通知。

**④ SSH 远程宿主，在会话里看远程终端**
1. 设置 → 宿主 → 添加：填 ssh 别名（读内核用户 `~/.ssh/config`，私钥只在内核机器），点「体检」；内核跑 `ssh -T <别名> fleet2-hostd --stdio`，帮手不在先 `scp` 单文件包过去（远端要 node、版本对得上）；读回 OS、/proc、git、壳、隔离档位、建议槽位。
2. 派工时路由或计划卡指定宿主或按标签选；hostd 在远端建工作目录（远端已有克隆或镜像；没有就内核经 ssh 送 `git bundle`），起工人（脱离会话跑，输出写文件、记行号）。
3. 模型调用：内核开 `ssh -R 127.0.0.1:<口>` 反向隧道到自己的回环模型代理（#3849 稿第一节第 4 条 b），远端工人只拿每轮一次性假令牌。**远端没有模型密钥、没有推送凭据**；交回时内核经 ssh 取回 `git bundle`，推送只经内核 outbox。
4. SSH 断了工人照跑；内核按租约重连，按 `runId` 和行号接着读；hostd 自报进程在不在。确认不了进程停没停就不转手（沿用 0124 切回表最后一行）。
5. 会话右侧坞「终端」显示工人所在宿主的实时输出（只读跟随）；「打开交互终端」点一次解锁，输入经 POST 上行、SSE 下行，每次输入进审计。指挥官没有任意执行命令的工具，只多一个固定白名单的只读 `host_probe`（磁盘、负载、git 状态）。

### 6.9 风险和回退

- 范围比 0124 原稿大一圈：按上面顺序一片一片落，VPS 的影子 → 切换梯度不变。

## 七、没核实的

- 各家模型当工人稳不稳：#3849 第 1 片的体检；影响第五节第 1 条阈值能不能达到。

- 远端宿主本身是 Windows 时 hostd 怎么收进程树：第一版只支持 Linux 和 macOS 远端。
