# 方案：路由探针（#129）

需求见 [需求.md](需求.md)。规矩写在 design 第九节「路由探针」，运维（看结论、手动跑一轮、离线了怎么办）在 docs/ops.md 第五节「路由探针」。

## 拆成几块、各改哪里

1. **库**（迁移 `0010_route_probe`，只加类型、列和约束）
   - `routes` 加三列：`probe_state`（ok / failed / not_wired / skipped）、`probed_at`、`probe_detail`。没探过三列都空。
   - 三条约束：`alive` 为真时结论必须是 ok（空的也不行，不许拿默认值、手改冒充在线）；结论和时刻同空同有；不是 ok 必须写原因。
   - `packages/db/src/queries/probe.ts`：`routeProbeTargets` 读每条路由探得了探不了的事实（渠道计费和开关、池的会话用户和组织、模型串和下架时刻、有没有阶段开着它、上一次的结论）；`saveRouteProbe` 一条语句写 `alive` 和结论（只有 ok 在线），路由被删了回 `route_not_found`。
2. **一轮的记账**（`packages/engine/src/jobs/route-probe.ts`，不碰真执行体）
   - 逐条定探不探（先后就是优先级）：按量计费 → 插头没接 → 渠道下架 → 模型下架 → 没有阶段在用 → 会话用户挂着别的组织。不探的写 skipped / not_wired 和原因。
   - 该探的交给这种执行方式的探法；没通隔 20 秒同一轮再探一次（要人修的整池问题不再试）；额度用满被拒算通。
   - 结局记进 `schedule_runs`：scanned = 写下结论的条数，found = 其中不在线的条数；读不到路由、一条都没写进去记 failed 并让活动报错；只写进去一部分记 partial；一条路由都没有记 unscanned。
3. **Claude Code 的探法**（`packages/engine/src/real/route-probe.ts`）
   - 和干活的会话同一个插头（`runClaudeCode`）、同一份 reclaude、同一个模型串；以池的会话用户经 fleet-agent-scope 在 `<工作树的根>/_route-probe/<会话用户>` 里起，问一句「只回 OK」，`dontAsk`、`--no-session-persistence`（插头加了 `persistSession: false`，只许新会话）。
   - 报告 → 结论：答上了、去掉首尾空白后整句就是 OK（不分大小写）才算通；其余按失败分流的同一张规则表认：登录失效、设备被撤销这类整池问题写 `pool-hold:<池>`「要人拍」，探通了撤掉；探的时候读到的额度记账（complete=false）。
   - 法国实测 reclaude 没登录时不报错，开始设备授权、一直等到起不来被强杀：规则表的登录失效（AU2）加认「no valid login detected」，探针在整段 stderr 里找这一句；原因进库前去掉网址的查询串（授权链接带一次性的 state）。
4. **定时**：Temporal Schedule `route-probe`（每 15 分钟、偏 7 分钟，SKIP 重叠，一轮最长 15 分钟），工作流 `routeProbeWorkflow` 调一个活动 `probeRoutes`（job 档：10 分钟、不重试）；登记进 `scheduled_jobs`（期望间隔 45 分钟，连着三轮没跑成算过期）。引擎启动时和对账补漏一起建或更新。
5. **驾驶舱**：契约 `RouteSchema` 加 `probe`（没有 = 还没探过），去掉 `routeProbeNotWired` 占位；调度台顶上「路由在线状态」（在线几条、最近一次探测、每条在线 / 离线（原因）/ 还没探过，45 分钟没新结论写「探针可能停了」）；阶段里的路由、渠道页、换路由对话框都照探针的结论写原因。

## 频率怎么定

现在真探的只有 Claude 订阅。法国实测一次 8–10 秒、约 7700 输入当量（按 API 价折合 $0.045，套餐内）；每 15 分钟一次，一个 5 小时窗 20 次，约占拼车号一个窗的 0.5%。以后接上别的插头，按它一次的成本定自己的频率。

## 不做的

- 熔断（连续失败判不在线）归 P5。
- 别的插头（codex、cursor-agent、Grok、Mirasim、接口外壳）的探法：插头接上时一起做，现在记 not_wired。
- 按量计费的路由不自动探，所以一直不在线、派不到；要用按量的路由得先有月度上限（design 第三节第 21 条）。
