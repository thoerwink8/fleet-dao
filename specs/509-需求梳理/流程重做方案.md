# 流程重做方案（2026-10-02 讨论定稿，待创始人拍）

起因：创始人 2026-09-29 叫停引擎、10-02 说「必须重做，因为那套流程太复杂，而且既不快又不省，也不一定好」。
这份是 10-02 一整轮拷问 + 讨论后的最终形状。**还没拍，还没开工。**

## 一、一句话

**三段一条龙：对题（含建单）→ 动手 → 验收。每段一个用完就退的无头进程，段之间不传副本、现读单子和 PR。**

## 二、三段

| 段 | 谁 | 想多久 | 交出来 |
|---|---|---|---|
| **对题** | 跟你对话的那个会话（不新设角色） | 中 | 单子：场景、你的原话、你提过的模块 |
| **动手** | 主 Agent（按改动面分档挑档位） | 快 | 提交 + PR |
| **验收** | 冷会话，**换一个跟主力不同的家族** | 中 | pass/fail + 问题表；直接改或退回 |

**不设常驻环节。** 名字用动词不用名词（「审官」这种叫法就是它后来想变成常驻环节的原因）。

## 三、对题：建单就把上下文写下来

创始人 2026-10-02：「从拿到需求、建立 GitHub issue 的时候，这个环节其实就已经带有上下文了……这个上下文是建这张单子的 AI 去处理的。」

**单子必须有这三栏**（缺了 `pnpm issue:new` 拒开，跟现在缺类别、缺里程碑一样硬拦）：

1. **场景**：这是干什么的、为什么现在做
2. **原话**：创始人当时说的，逐字抄
3. **已知的模块**：建单时会话**确实知道**的（它跟你聊的时候你提到的）

**涉及面一律不写。** 那是算出来的、不是知道的：建单的 AI 动手前没读过代码，它写的只是猜。
**「要什么」和「怎么算做完」** 也在这张单上——它们是验收那一遍唯一的对照物。

**为什么这一条是整份方案里唯一一个「加东西」**：它换掉的是「下游空手开始」。Anthropic 那篇多 agent 研究点名过这个失败模式——子代理假设下游继承了它的上下文，而下游是空手开始的。

## 四、动手：分档一次定死

**按改动面分档**（`git` 数得出来，不猜、不升档、不回退）：

| 档 | 判据（派工时一眼可见） | 主 Agent |
|---|---|---|
| 简单 | 一个文件 | DeepSeek / Flash 这类快档 |
| 中等 | 一个模块内几个文件 | Claude 或 Grok |
| 复杂 | 跨模块 / 碰接口 | Claude 主力档 |

**判据为什么是改动面而不是难度**：查过的路由器生产基准里，难度分类**跟的是对话轮数、不是难度**——一句话说得清的难活永远拿不到强模型。难度信息在仓库里，不在需求文字里；而改动面是仓库里的事实。

**不升档、不回退**（创始人 2026-10-02 拍）：中途发现错了，**原地改**（留一条备注说明改了什么），不重开上游。理由：回退上游 = 一次完整的上下文重载，而整条流水线就是在省这个。

## 五、验收：合之前一次冷调用

**不是岗位、不是常驻、不是一段流水线——就是合之前那一次调用。**

喂三样：

| 喂什么 | 从哪来 | 为什么 |
|---|---|---|
| diff | PR 自己算 | 改了哪些文件、改了什么 |
| 怎么算做完 | 单子 | 判得了「要 A 写了 B」 |
| 要什么 | 单子 | 同上 |

**只喂 diff 是不够的**：diff 能查语法、逻辑、边界；查不了「单子说要 A、代码写了 B」——那是**要求没被满足**，而 diff 里看不到要求。

**换一个跟主力不同的家族。** 依据：自审会把准确率从 95.5% **拉低**到 89.0%（GSM8K，arXiv 自演化综述）——自审不是省了保险，是做了件倒扣分的事。而「不同会话、同一模型」是文献里写明的标准做法，只有一家时用它顶。

**只有三种能挡**：没做到验收条、有证据弄坏原有功能、安全或丢数据。默认 1 轮、最多 2 轮。

## 六、交接条：不造这个东西

创始人 2026-10-02 问：「单子存什么、要什么是要的，PR 正文存什么也是需要的，这些东西都要转接给审官呀。」

**审官需要什么，交接条就该是什么。** 而审官要的三样（diff、要什么、算不算做完）**全在已有的两个地方**：

| 存哪 | 存什么 | 时间常数 |
|---|---|---|
| **单子** | 要什么、怎么算做完、场景、原话 | 跟单子一辈子 |
| **PR 正文** | 做了什么、怎么验证的、还欠什么 | 一次性，合了归档 |

**验收那一遍现读，不存副本**——不存副本，就没有副本和原件不一致的问题。

**创始人 2026-10-02 提的硬要求**：「内容写得详细，这一块的交接过程就不能断掉。」

所以要有**机器检查**，不能靠自觉：

- 单子那三栏缺了 → `issue:new` 拒开（已有机制，扩一栏）
- PR 正文的栏由 `.github/pull_request_template.md` 定，**已有的「做了什么 / 怎么验证的 / 还欠什么」正好是这三样**
- **缺栏只提醒不挡合并**（照现在的规矩），但**验收那一步读不到必填栏就明确失败**，不许拿「读不到」当「没问题」（通用段底线第三条）

## 八、路由配置改成两层

创始人 2026-10-02：「opus 5.5 有很多个供货渠道，是不是在这个模型里面还要选供货渠道的优先级。」

现在是一串**平铺的路由**（渠道 + 账号池 + 模型 + 执行方式）。改成**两层**：

```
opus5.5:   [独享, 拼车, mirasim]
gpt-4.7:   [mirasim, coso]
deepseek:  [mirasim]
```

**为什么改**：加一个能跑 Opus 的新渠道，平铺要插三行，两层只加一个子项。配置该跟着人的想法走。

**必须配一条**：两层的**每层都要能一眼看出「这条现在活着吗」**（接得上、额度够、没被禁令挡）。不然层级一深，你会看着一份很整齐的配置，不知道它一条都派不出去（`#293` 那次断 47 分钟就是这个形状）。

## 九、留什么、删什么

| 删 | 留 |
|---|---|
| Fusion 0–7 步、存档点、换 Lead、单模型模式、多套流程配置 | 三段一条龙（本方案） |
| 帅位的座位、认领账（#443、#446、#250 已在删除计划里） | GitHub 当计划：单子、PR、版本 |
| **编排层**：状态机、认领租约、重试策略 | **引擎层**：起进程、喂什么、判档位、记一笔 |
| 「两个模式」（模式 A/B）这个概念 | 四类人闸、先审后合那两种 |
| 「交接条」这个物件 | `runs` 表（记账） |
| 「判难度」这一层（一个模型都不用起） | **Temporal**（见下） |

**Temporal 留**（创始人 2026-10-02 拍）：它负责①**额度切号**（拼车 5 小时窗口用满 → 切独享 → 再满切 Mirasim）②**跑一半被打断后从断点续上**。这两件在创始人那儿是常事，不是可选项。

**记账不进 Temporal**：每段花多少从每次调用回来时记（token、起止）→ `runs` 表；池子剩多少从渠道读（`reclaude` 那个开放接口，design 第三节第 30 条）。

**重试不判、按表办**：

| 打断原因 | 怎么办 |
|---|---|
| 额度满 / 被切号 | 挂起，到清零时间从断点续上 |
| 进程死 / 网络断 | 原地重跑，从最后一次成功那步起 |
| 测试红 | 回主 Agent 改，最多 3 轮 |
| 同一个原因连续挂 2 次 | **停下报创始人** |

**第四条是关键**：真正需要判断的不是「这次重试吗」，是「这条路是不是整体不对了」——那个找人或起一次讨论，模型判不了趋势。

## 十、验收标准（可证伪）

重做的理由是「太复杂」，所以新设计要**可数地**更简单：

| | 现在（Fusion） | 目标 |
|---|---|---|
| 一张单的交接次数 | **7.7** | **≤ 2** |
| 任何时刻的常驻进程 | 多 | **0 个** |
| 单会话内存 | 3.5G（会话里跑测试） | **≤ 0.5G** |

第三条是并行的前提，创始人 09-28 拍过、**没落地**，这次补。

## 十一、落地顺序

1. **测试移出会话**（并行的前提，拍过没落地）
2. **单子加三栏 + 拒开**；PR 模板确认三栏
3. **三段一条龙**（无头进程 + 现读单子/PR + 分档），同一个 PR 删掉 Fusion 0–7 步
4. **路由配置改两层**
5. **驾驶舱按这个形状重画**（一屏三块：要你拍的 / 在跑的 / 做完的）

## 十二、没验证的

- 单会话内存 0.2–0.5G 是文档里的**空闲值**，长输出时的峰值没测过——`runs` 表要记这个
- 「10 张单同时在跑」的实际内存没测过（推演是大多数单在等 CI / 等验收，那部分是 0）
- 改动面分档的准确率没数据（这正是「先跑 20 张单」要拿的东西）
