## 一、业务规则（每条要有落点、有测试钉住）

1. **单子写全四节**：场景、原话、已知的模块、怎么算做完。检查和 `pnpm issue:new` 用同一份代码（`packages/conventions/src/issue-new.ts`），不另写一份。
2. **原话逐条存、逐字拼**：每条原话存说话人、渠道（网页／手机）、时间。开单时「原话」一节由系统按时间拼出来，AI 碰不到原话。AI 的归纳另起一段，并写明是 AI 写的。
3. **身份以服务端会话为准**：谁说的、谁提的、谁拍的板，都取登录会话里的用户，不取前端传来的值，也不取正文里写的字。能给哪个项目开单、要不要拍板，都由服务端按 users 表判定。
4. **只能给已导入的项目开单**（`repos` 表）。
5. **AI 会话手上没有 GitHub 令牌**。开单、评论、贴标签都由引擎和后端代码执行；正文写进 GitHub 前过卫生检查（参照 `packages/engine/src/real/groom.ts`）。
6. **开单按版本、要幂等**：草稿每改一次，版本号加 1。确定或拍板时带上版本号，服务端只开这一版；幂等键是「需求号 + 版本号」。超时了不让人重点，页面去查这一键开没开成，再回显结果。
7. **拍板在开单之前**。合伙人发起的需求要创始人拍「做」才开单。头两周对合伙人一律要求拍板，以后改成按人设置。碰四类事（发布、花钱、删数据、改标准）的单，照旧贴「要人拍」。
8. **结案锁死**：结案后对话、草稿、原话都不能再改。要改，只能在电脑上点「接着这条提」，新开一条需求挂在原来那条下面。
9. **读不到、没查成，就明说失败**：查重、GitHub 状态、会话起不来，都照实写原因，不拿空列表冒充「没有」。

## 三、列表、归档、删除（这一版新增）

对照：
- ChatGPT 的归档和删除分开：归档只是从侧栏藏起来，能取消；删除后 30 天内从系统清掉。
  - https://help.openai.com/en/articles/8983778-how-to-delete-and-archive-chats-in-chatgpt
  - https://help.openai.com/en/articles/8809935-deleting-and-archiving-chats-in-chatgpt
- Claude 删除前要确认，移出历史后 30 天内从后端删掉：https://support.claude.com/en/articles/8230524-delete-or-rename-a-conversation （页面日期 2026-08-10）
- Slack 归档的频道历史保留、能搜、能取消归档；删除是永久的，只有所有者或管理员能删：https://slack.com/help/articles/213185307-Archive-or-delete-a-channel
- Linear 的单完成后自动归档；删除后 30 天内能在「最近删除」里恢复：https://linear.app/docs/delete-archive-issues
- GitHub 的 issue 只有仓库管理员能永久删：https://docs.github.com/en/issues/tracking-your-work-with-issues/administering-issues/deleting-an-issue
- Mirasim 本机版：
  - 会话在跑时不能删，要先停；
  - 删除时提示「删除后无法恢复」；
  - 归档是一个布尔字段，有单独的「已归档对话」面板，能取消归档；
  - 有置顶、重命名、搜索、多选；
  - 操作按钮悬停时才出现。

检索日都是 2026-10-13。

### 两个查看的地方

- **进行中**（默认）：讨论中、待拍板，以及已结案·做但还没上线的。顶上三个筛选：「等我的 N｜全部｜我发起的」。「等我的」算这几种：
  - 等我拍板；
  - 引擎在问我；
  - 指挥官在问我（我发起、轮到我答的）；
  - 有我没读的新消息。
- **已归档**：列表底部一个入口「已归档（N）」，进去是同样的列表，能搜、能看，都是只读的。里面最下面还有一个「最近删除（N）」。

### 什么时候进归档

| 情况 | 去哪 |
|---|---|
| 已结案·做，单子上线（或单子关了）满 3 天 | 自动归档 |
| 已结案·不做 | 马上自动归档 |
| 讨论中，14 天没人说话 | 不自动归档，列表上标「搁置 14 天」，提醒发起人「放下」或接着聊 |
| 手动归档 | 只有已结案的能手动归档 |

讨论中的需求不能手动归档。没聊完的事要么接着聊，要么「放下」（写理由），免得藏起来就忘了。归档的需求能「取消归档」，回到进行中，但内容仍然锁着。

### 能不能删

**删除只给「还没留下任何决定、也没牵扯别人」的需求。** 理由：
- 拍过板、开过单的需求，被 GitHub 的单和 PR 引用着，是做过的事的记录。Slack、GitHub 都只让管理员删，Linear 也留 30 天可恢复。
- 别人说过的话，不该被另一个人删掉。

| 状态 | 能删吗 | 不能删时怎么办 |
|---|---|---|
| 讨论中，只有发起人自己说过话（指挥官的话不算），从没提交过拍板 | **能**，只有发起人能删 | — |
| 讨论中，另一个人也说过话 | 不能 | 「放下」（写理由，结案·不做） |
| 待拍板 | 不能 | 拍板人点「不做」，或发起人撤回到讨论中再放下 |
| 已结案（做或不做） | 不能 | 只能归档 |
| 指挥官会话正在跑 | 先停 | 页面提示「指挥官正在回话，停下后才能删」 |

删除的规则：
- **删除是软删**：先弹确认框，写明「30 天后彻底删除，之前可以在『最近删除』里恢复」。删了的需求进「最近删除」，30 天后由定时任务硬删，消息一起删。
- 删不了的需求，菜单里不出现「删除」，而不是让人点了再报错。悬停在「放下」「归档」上，写明为什么不能删。
- 驾驶舱里**不提供**删除已结案需求的入口。真要删属于「删数据」，要创始人点名，在服务器上用命令删，删完留操作记录。

### 其他管理

- **置顶**：每人各自的，不影响对方。
- **重命名**：只能改讨论中的需求，改的是草稿标题。结案后锁死。
- **搜索**：进行中和已归档都能搜，范围是标题、原话、单号（输 `#12` 能找到）。
- **多选**：能批量归档已结案的需求。批量删除只对能删的那些生效，删不了的留在选中状态，并写明原因。
- **操作按钮**：电脑上悬停时在行尾出现「⋯」；手机上长按出菜单。
- **列表一行**：发起人头像（参与人小角标）、标题、最后一条消息预览、时间、状态小点或「等我」角标，右边还有：
  - 「搁置 N 天」；
  - 结案后的 `#12`、`PR #34` 标签，状态从 GitHub 读。
- **「接着这条提」**：开出来的新需求缩进挂在原条下面。

## 四、对话（版面第三版）

- **头部只有一行**：标题、状态小标签、下一步轮到谁、参与人头像、「单子 · 第 N 版」按钮、「⋯」菜单（项目、需求号、复制链接、归档、删除或放下）。
- **消息排法**：自己发的在右边、带气泡；别人在左边，小头像，连续几条只在第一条上面写名字；指挥官在左边，不加气泡。
- **指挥官**：每一轮先把能从代码和对话里推出来的草稿栏填上。出方案之前一次问一个问题，带 2～4 个选项，外加「我自己说」。人第 3 次发言之后这一轮必须给出方案卡（完整草稿摘要）：点「确认开单」就按现有确定开单开出去，点「改」打开那一栏的输入框。过了这一轮又有新信息，下一轮直接给更新后的方案，不回到逐条提问。每条聊满 40 轮仍是硬上限。只有一个人在聊时，每句都回；两个人都说过话以后，只在被 @指挥官 或有人点「让指挥官接着问」时才说话。
- **草稿改动**：显示成指挥官那条消息底下的小芯片「改了单子：……」。人改过的栏，指挥官不能直接改，只能在聊天里出一条「建议改」卡。
- **单子面板**：默认收起，点了从右边滑出，约 420px，开或关会记住。里面每一栏都能改（原话除外），还有查重、「让别家挑错」。
- **模型**：输入框左下角一个小芯片，默认用「提需求」用途配的模型，可以只给这一条需求换。换的时候在对话里出一条分隔线；Fable 只有创始人配进这个用途才会出现。
- **单子卡、拍板卡、结案分隔线、进度卡、引擎提问都是对话流里的消息**：
  - 单子卡：草稿齐了，指挥官发一张紧凑的卡；
  - 拍板卡：只有拍板人能点「同意做 / 不做 / 再聊聊」；
  - 进度卡：一张折叠的「#12 动手中 · 第 3/6 步」；
  - 引擎提问：带「回答」按钮，答复写回那条 GitHub 评论。
- **结案后**：输入框换成一条细栏「已结案，内容不再改 · 接着这条提」。点「回答」时才出现输入框，答的是引擎的问题。
- **让别家挑错**：平时手动点；单子带「要人拍」时，确定前自动跑一遍。别家的意见是一张卡，每条可以采用或不用。

## 五、指挥官会话

- **起会话**：沿用临时指挥官整理（groom）起会话的那条路（`real/groom.ts`）：
  - 选路用途新加 `intake-chat`；
  - 建一份主线的只读检出；
  - 会话里没有 GitHub 令牌；
  - 登记进一次性会话清单，切号、发布排空时都能停下它。
- **多轮怎么续**：用同一个会话续（`--resume`）。闲置 30 分钟就收掉会话、删掉检出；下次有人说话，再按存下来的消息和草稿重起。换模型也走「按存档重起」。
- **会话只交两样东西**：回话正文，加一份草稿补丁。补丁只能改这些字段：标题、类别、场景、已知的模块、要什么、怎么算做完、不做什么、规模建议、要不要人拍。补丁碰到人改过的栏，服务端拒掉，转成一条「建议改」。
- **输出**：流式推到页面（SSE），页面显示「正在读代码……」。
- **限额**：每人同时最多 3 条在聊，每条最多 40 轮，这是软闸，可以调。额度熔断或切号时，页面明说「指挥官暂停了：原因」，输入框里的字不丢。

## 六、开单之后

- **开单**：后端用「引擎」机器人身份同步开单（`packages/github/src/issues.ts` 的 `openIssue`），不走发件箱。正文末尾写上提出人、拍板人，以及「来自驾驶舱 需求 N」和链接；同时把 `requested_by` 写进库，这才是引擎认人的依据。
- **进度**：在做、已合并、已上线都从 GitHub 和引擎任务表读，经 SSE 推到对话里的进度卡。
- **引擎提问**：引擎在单上提问时，在对话里生成一条「引擎提问」消息，绑定那条评论的号。在这里回答，答复写回那条评论下面；写失败了显示原因，可以重试。
- **对应关系**：任务页每张单旁边显示「来自需求 N」。

## 七、PWA 和通知

- **装成 APP**：manifest 加 service worker，能装成桌面 APP，有独立窗口和图标。
- **角标**：数字等于「等我的」件数（Badging API，Chrome、Edge 81 以上支持，只在装好的 APP 里显示：https://web.dev/articles/web-apps/badges ）。
- **系统通知**：APP 开着时，用现成的 SSE 收到事件，再调 Notification API 弹出来，不走谷歌推送；国内用 FCM 不稳，见 https://support.pushy.me/hc/en-us/articles/360043920371 。关掉 APP 以后的推送，这一版不做。
- **手机**：用同一个路由做响应式，宽度小于 768 时切成「列表 → 对话」两个画面。手机上能做这些：看、发言、拍板、回答引擎、提新需求（先说一句）。不能做这些：改草稿、选项目、换模型、让别家挑错、接着这条提。
