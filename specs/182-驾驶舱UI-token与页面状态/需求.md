# 驾驶舱 UI：设计 token 替掉写死的尺寸，每页做齐加载、空、出错重试、刷新、最后更新（#182）

对应计划：plan.md P2「后台第一批页面」
设计依据：design 第十五节「驾驶舱」（视觉放开设计、多套主题色），#169「第 4 题后半、第 5 题」（分层看板）

原话（创始人 2026-09-26）：「每一个模块的具体页面，只要涉及到的地方，都要有刷新按钮之类的功能。比如骨架屏、loading 状态这些，我看你之前好像都没做，我希望你在 UI 设计上考虑得更全面一些……你好像没有参考。比如 Tailwind CSS 这种做一个类似于 CSS token 的方案，你现在大小都是随心所欲的。我觉得 UI 方面也要大改，但是这一方面可以排期后一点。」

AI 理解：驾驶舱网页（packages/web）现在有 200 处写死的尺寸（像 `text-[13px]` 这种任意值），骨架屏只有 3 个文件用了，刷新、重试只零散有。要改成一套设计 token（字号、间距、圆角、颜色、动效都从 token 取），每个页面把「加载中、空、出错能重试、刷新、最后更新时间、数据过期」这几种状态做齐，并让以后没法再写回任意尺寸。排期靠后：等 Fusion 设计定稿、按新的分层看板（项目 → 版本 → 母单 → 子单）重排驾驶舱各模块时一起做。

## 要什么

- 设计 token：在 Tailwind 主题里定一套字号、间距、圆角、颜色、阴影、动效的档位，参考成熟设计系统（给出处），浅色深色两套。
- 页面状态：每个取数据的地方都有骨架屏（加载中）、空状态、出错状态（写清原因、能重试）、刷新按钮、「最后更新 x 分钟前」、数据过期的标记。
- 防回退：加一条检查，页面代码里出现任意尺寸值（`[13px]` 这类）就报红，配一条故意造出失败的测试。

## 怎么算做完

- packages/web 里任意尺寸值为 0（允许的例外写进白名单并写理由），检查进 CI，故意写一个任意值的测试会红。
- 16 个页面逐个过一遍：加载、空、出错重试、刷新、最后更新时间五样都在，有截图对照（浅色、深色、手机宽度）。
