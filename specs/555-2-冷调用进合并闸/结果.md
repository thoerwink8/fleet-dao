## 做了什么

**架构（已成文的那一条，本切片照做不重新设计）**：合并闸跑在 CI 里，判法必须确定（同一份代码什么时候跑结果都一样），
所以**闸里不起模型调用**。冷调用的结论由装配侧起、**贴成 PR 当前头上的提交状态 `cold-verify`**，闸只读这条状态。

- `packages/conventions/src/merge-gates.ts`：加 `COLD_VERIFY_CONTEXT = 'cold-verify'`（**新开一个 context**，不复用
  `second-opinion`——问的不是同一件事，共用一个会互相盖掉）、`COLD_VERIFY_MAX_ROUND = 2`；读状态的活抽成
  `statusByContext()`（`secondOpinionFrom` / `coldVerifyFrom` 都走它，省得两条读法偷偷不一样）；加 `checkColdVerify()`
  （**没有这条状态 = 判红「还没验」**，不是放行；error 也当没过）和 `coldVerifyNeed(flowPr)`（要不要验：**引擎任务工作流（#632）开的 PR
  要，人手开的 PR 不要**——验收是三段流程的第三段，由引擎在合之前跑并贴状态，人手的 PR 没有引擎替它们验，要了就永远卡在「还没验」；
  碰先审后合路径的 PR 照旧只要第二意见）。2026-10-02 夜重定范围：原来写的是「改到先审后合路径的 PR 要」，那样引擎的普通 PR 没有
  结构上的保护、人手的高风险 PR 反而被卡死。
- `packages/conventions/src/flow-branch.ts`（新，已加进先审后合清单）：`isFlowBranch()` 认引擎任务工作流起的分支名
  `fleet/<单号>-t<8 位十六进制>`；引擎那边 `task-branch.ts` 有一份同样的正则（工作流代码不能引这个包），
  `packages/engine/test/task-branch.test.ts` 逐条对着测，`taskBranch()` 起不出合规名字就当场报错。
- `packages/conventions/src/merge-gate.ts`：`gatePr` 读 PR 的分支名（`head.ref`，读不到＝没查成），在原来读 second-opinion 的**同一次 `statuses()` 调用**里再读一条
  cold-verify——**没加任何新的 GitHub 读口子**（`GitHubReads` 一个方法都没多，钉住它那条测试没动）；`targetPrs` 的
  status 事件放行加上 `cold-verify`（贴上来要重算）。
- `.github/workflows/merge-gate.yml`：job 的 `if` 放行 `cold-verify` 的 status 事件。
- `packages/conventions/test/merge-gate-inputs.test.ts`：`ALLOWED_CONTEXTS` 加 `cold-verify`（钉住合并闸能看哪些现状的那条测试；
  它不在 `standard-paths.json` 列的路径里，不算「改标准」，这个 PR 的档位是先审后合）。
- `packages/engine/src/cold-verify-status.ts`：结论 → 状态（**只有 `pass === true` 才 success**，其余一律 failure）；
  `coldVerifyNotRun()`（起不来也是 failure，不是 pending、更不是 success）、`coldVerifyPending()`、
  轮数（`COLD_VERIFY_ROUNDS_MAX = 2`、`nextRound()`、`canStartRound()`——到顶不再起下一轮，不许拿新轮盖旧结论）。
- `packages/engine/src/cold-verify-post.ts`：`runColdVerifyAndPost()` 串起「起一次调用 → 贴结论」；写状态抛错包成
  `ColdVerifyWriteError` **抛出去**（吞掉 = 验过了但闸看不到 = 死锁）。
- `packages/engine/src/cold-verify-pick.ts`：`verifier-invoke` 的 `ChooseModelForFamily` 的**生产实现**
  （`pickFamilyModel()` 按 0006 顺序跳过作者族；`familyPickerFrom()` 接到引擎现成的 `pickRoute` 端口上，把别的族全避开）。
  #555-1 收尾时留下的「挑模型还是注入的」这一条，本切片补上——不再只是接口。
- `packages/engine/src/cold-verify-run.ts`：装配入口 `runColdVerifyForPr()`——取三样（PR、diff、单子/作者族）→ 起一次
  冷调用 → 贴状态。**读不到任一样都贴 failure**（不贴 = 闸判「还没验」，和「没跑过」看不出来）。
- 测试：`packages/engine/test/cold-verify-status.test.ts`（16）、`cold-verify-post.test.ts`（11）、
  `cold-verify-pick.test.ts`（11）、`cold-verify-run.test.ts`（12），`conventions` 两份各加一组。
