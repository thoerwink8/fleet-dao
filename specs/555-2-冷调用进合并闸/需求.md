# 555-2 验收那一遍的结论接通合并闸（#555 切片）

对应计划：v3 三段一条龙（#509；排期见 `docs/decisions/0009-v3-implementation-plan.md` 第 6 行）
母单：#555（验收：合之前一次冷调用，喂三样、换家族）

## 要什么

三段的第三段（验收）在合并之前跑一遍，结论要挡得住合并。决定依据：`docs/decisions/0010-three-segment-flow.md` 第 4、5 条（验收 = 合之前那**一次**冷调用、换家族、只有三种能挡），做法见 `specs/555-验收/需求.md`。

**范围（2026-10-02 夜重定）**：只管**引擎任务工作流（#632）开的 PR**——按分支名认（`fleet/<单号>-t<8 位十六进制>`）。人手开的 PR 不要这一条：没有引擎替它们起这一遍，要了就永远卡在「还没验」。

1. 合并闸多读一条提交状态 `cold-verify`：认出的 PR 当前头上要有引擎机器人贴的**通过的**那条。
2. 没有这条状态 = 判红「还没验」（**不是放行**）；`pending` / `failure` / `error` 都不放行；分支名读不到 = 没查成。
3. **闸里不起模型调用**：闸跑在 CI 里、判法必须确定（同一份代码什么时候跑结果都一样）。冷调用在引擎侧跑，结论贴成状态，闸只读。
4. 装配侧要有「谁跑这一遍」的真入口：取三样（diff / 要什么 / 怎么算做完）、按 0006 的顺序换家族、起一次会话、把结论贴成状态；**读不到任一样都贴 failure**（不贴 = 和「没跑过」分不开）。

## 怎么算做完

1. `packages/conventions/src/flow-branch.ts` 的 `isFlowBranch()` 认 `fleet/<单号>-t<8 位>`，认不出的不是引擎分支；和引擎侧 `task-branch.ts` 的同款正则逐条对照（`packages/engine/test/task-branch.test.ts`）。
2. `coldVerifyNeed(flowPr)` / `checkColdVerify(head, got, need)`：引擎任务 PR 缺状态判红、`pending` / `failure` / `error` 判红、通过放行；**人手开的 PR 不要这条**（`packages/conventions/test/merge-gate.test.ts` 里 flow-PR 那一组，含近似分支名的反例）。
3. `.github/workflows/merge-gate.yml` 放行 `cold-verify` 的 status 事件，`packages/conventions/test/merge-gate-inputs.test.ts` 的放行清单里有它（摘掉这条放行，测试要红）。
4. 装配侧 `packages/engine/src/cold-verify-{status,post,pick,run}.ts`：只有 `pass === true` 才写 success；起不来写 failure（不是 pending）；写状态失败往外抛（`packages/engine/test/cold-verify-*.test.ts`）。
5. 故意的失败都能造出来、且测试抓到：没状态、pending、failure、error、state 认不出、statuses 读不到、`head.ref` 读不到、读不到 diff / 没家族可挑 / 冷调用没跑成。
