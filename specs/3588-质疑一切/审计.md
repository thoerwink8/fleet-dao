# 质疑一切：上下文和钩子的成本与用处审计（单 #3588）

- 状态：做完

> 只读审计，2026-10-22 夜。数据：本机会话记录 `~/.claude/projects/D--frank-fleet-dao*`（近 14 天 50 个主会话、6,913 次调模型、缓存读 18.5 亿 token）；`~/.fleet-dao/logs/hook-timing.jsonl`（10-19～10-22，20,271 行，只覆盖 `main-thread.mjs` 和 `pretool.mjs`）；法国 `runs` 表只读查询；15 个 grok 会话目录逐个按会话号读。token 估法：（中日韩字符 × 1 + 其他字符 ÷ 3.6）× 1.33，系数由本机会话首轮实测 34,989 token ÷ 公式原始估值 26,238 校准（本机没有分词器）。

## 结论

1. **最该先动的是钩子，不是文档。** 收轮钩子 `stop.mjs` 每轮结束等 7.1 秒（p50），86 次里 85 次输出「没查成」，没找到拦下过有用东西的证据。派子代理前的 `pretool.mjs` 每次都取 origin/main：p90 5.2 秒、最长 9.83 秒，紧贴 10 秒超时；超时就挡住派活（`onFailure: block`），2026-10-22 夜就挡过一次。两处删掉或收窄，把握高。
2. **交互会话开场约 3.5 万 token，fleet-dao 自己能管的只有约 8～10K。** 其余是 Claude Code 自带和本机装的 MCP（光 rea 的工具名清单约 5K token）。开场这段每次调模型都要重读：开场大小 × 调用次数 ≈ 缓存读的 29%。
3. **法国引擎的大头是 grok-4.7，占动手段输入当量的 65%。** 每次会话开场 3 万多 token，其中 25 个工具定义约 52.9K 字符，有 image_gen、image_to_video 这类写码用不上的；预载文件原文占提示词 90%。但每次调用平均上下文 130K，大部分来自会话中途的工具输出和带回的推理。单子四节和原话很便宜（不到开场的 3%），不值得删。
4. **决定记录、引导、specs、design.md 都不进引擎提示词，交互会话按需读——这已经是 Pi 的做法**，不是 token 大头，不需要为省 token 归档。真正的大头是按目录自动注入的 `packages/engine/AGENTS.md`，约 16.7K token。

## 和 Pi 的对照

来源：作者博客 <https://mariozechner.at/posts/2025-11-30-pi-coding-agent/>（仓库 github.com/badlogic/pi-mono 现跳到 earendil-works/pi；被收购一事来自二手来源，没核原文）。

| Pi 的做法 | 它靠什么保住效果 | 我们 |
|---|---|---|
| 系统提示加工具定义合计不到 1000 token | 模型本来就会写码，不重复教 | 照搬：grok 关掉没用的工具，AGENTS.md 只留不变量 |
| 默认只有 read/write/edit/bash 4 个工具 | CLI 工具配 README 按需读 | 照搬：fleet-dao 会话禁用 rea 等 MCP |
| 不用 MCP（作者举例 Playwright MCP 一家约 13.7K token） | 按需读 | 同上 |
| AGENTS.md 分层加载，追加在系统提示末尾 | 文件要短 | engine 那份 16.7K token 太长，要缩 |
| 不设权限弹窗、不设护栏 | 一个人用，自担风险 | 我们有理由不同：无人值守 + 多家模型轮换，密钥闸有真拦截（27 次）要留；不做事的钩子（收轮对账、每次写回执）要删 |
| 不在背后塞上下文 | 进上下文的东西都看得见 | 照搬：SessionStart 只报新鲜、可动手的事，不报过期消息 |
| 不要子代理、待办、计划模式 | 用文件写待办和方案 | 我们有理由不同：一个人指挥多工人，子代理是核心；grok 的计划和调度工具可以关 |

## 减法清单（按「省得多 × 有把握」排）

1. **派子代理前只在建工作树时取远端，总预算压到 6 秒以内**。省：不建工作树的派工每次从约 0.8～5 秒降到几十毫秒，消掉 10 秒超时挡派活。把握高，无风险（建工作树的派工照旧取）。验：`hook-timing.jsonl` Agent 行前后对比；`fresh-main.test.ts` 新用例。
2. **收轮对账只在无人值守开着时跑**。省：每轮结束约 7 秒，85/86 的「没查成」噪声一起没了。把握高；风险：人在场时「队列还有活就别收」（#2731）不再提醒，无人值守照旧。验：`stop.rules.test.ts` 新用例；会话记录 `stop.mjs` 耗时前后对比。
3. **`continuation-progress.mjs` 没开无人值守直接退出**。省：每次调工具约 100 毫秒（每天约 494 次调用约 50 秒）。把握中高；看 continuation 相关测试。
4. **缩 `packages/engine/AGENTS.md`（16.7K token）和 `packages/conventions/AGENTS.md`（8.5K）到 3K 以内**。省：碰 engine 的每个会话约 13K token × 剩余调用次数，一次会话可达百万级缓存读。把握中高；风险是丢不变量，先把对应第五节第 1、9、11 条的部分写成检查。
5. **grok 起会话加 `--disallowed-tools`（关 image_gen、image_edit、image_to_video、reference_to_video、send_feedback、workflow、scheduler_*）和 `--no-plan`**。省：约 20.4K 字符≈6K token × 52 次调用，每会话约 30 万 token，每天约 1600 万 token（多数是缓存读）。把握中（要发版到法国，先用探针验参数）。
6. **fleet-dao 会话禁用 rea 等用不上的 MCP**。省：每会话开场约 5～8K token × 每天约 494 次调用，每天约 250 万～400 万 token 缓存读。把握中（本机配置）。
7. **SessionStart 注入压到约 600 字内、去掉过期消息；`bootstrap.mjs` 改后台跑**。省：开场 5～25 秒 + 0.3～1.5K token。把握中。
8. **预载改成单文件超 2 万字只给大纲、总量 3 万字**。省约占 grok 输入 4～5%。把握中低，按决定 0093「多久第一次改文件」先做 A/B。
9. **`main-thread.mjs` 并进 pretool 同一个进程**。省每次调工具起一次 node，约 25～200 毫秒。把握中。
10. 小项：MEMORY.md 压缩（约 1K token）；通用段移约 1K 字进技能（改标准）；拆 design.md。都省得少。

这些刀都不丢第五节 12 条：第 4、7、12 条照旧由密钥闸、建工作树前取远端和 prompt-log 守着。
