# 结果：Fusion 开的 PR 碰到先审后合的路径：引擎请别家出第二意见、写合并闸认的状态（#253）

## 做成什么样

- PR #417（帅位派的 Sonnet 工人做的，草稿，等帅位验收转正）。
- Fusion 工作流开 PR 之后等 CI 那一步（`packages/engine/src/workflows/fusion.ts` 的 `waitCiEvent`）现在和等 CI 并行跑一轮「第二意见」（`secondOpinionRound`）：
  - 先按 `checkHighRisk`（新引擎端口）判这个头碰没碰先审后合的路径——读主线上那份 `packages/conventions/high-risk-paths.json`（和合并闸同一份判法、同一个清单）、这个 PR 现在的改动文件（新增 `packages/github` 的 `pullFiles`，带 patch，才判得出新迁移是不是只加不改）。
  - 碰了才派会话：复用现有的 `review` 阶段派发（和 Fusion 第 5 步「开 PR 前验证」同一套路由、同一套兜底梯——主审连不上自动换下一家，都派不出由 `runStage` 自己挂起报警），不新增一套派工逻辑。
  - 结论经新引擎端口 `postSecondOpinion` 写回 GitHub：贴提交状态 `second-opinion`（合并闸认的那个 context，`state`/`description` 和本机第二意见垫片 `second-opinion.mjs` 写的格式一致）、留一条评论（列必须改、小毛病，和本机垫片同一个格式）。评论被卫生检查拦下、GitHub 一时不通只记下没贴上，不影响状态照贴——状态是合并闸认的唯一信号。
  - 「必须改」的条目并进开了 PR 之后修一轮的反馈（`kind: 'review'`），和 CI 红走同一条账（`doFix` 派会话去改）；连着 2 轮还是必须改就停下等人，原因写清（`第二意见连着 N 轮都要改`）。
  - 合并闸报「等第二意见」时不再被当成 CI 红：`waitCiEvent` 把 `failedChecks` 里的 `merge-gate` 单独摘出来判——只有它红、没有别的失败检查，多半是状态刚贴上、合并闸还没重算追上，稍等再查一次；连着 3 次都这样才停下等人（不是第二意见能解的，多半是认领对得上、关单要带结果这类别的原因）。
- 老历史（在途的 Fusion 任务）没有调过 `checkHighRisk`/`postSecondOpinion` 这两个新活动：整段改动包在 `patched('second-opinion-253')` 里，没打过这个标记的照老步序重放，一个字都不多问（`packages/engine/test/replay.test.ts` 钉住，5 条 fusion 夹具重放都过）。
- 工作流文件（`workflows/`）会被 Temporal 的 webpack 打进沙盒执行的包：开发过程中一度直接 `import { GATE_CONTEXT } from '@fleet-dao/conventions'`，把 conventions 的整个 index.ts（连带 `issue-new.ts` 用到的 `node:path`、`node:util` 等 Node 内置模块）一起带进了工作流包，webpack 打不出来（`packages/engine/test/worker.test.ts` 当场测出）。改成在 `packages/engine/src/workflows/fusion.ts` 里写死 `MERGE_GATE_CONTEXT = 'merge-gate'` 常量（注释写明要和 `packages/conventions/src/merge-gates.ts` 的 `GATE_CONTEXT` 对上）。

## 怎么验证的

- 本机：`pnpm test:changed` 判出的范围全跑，158 个测试文件、3747 条测试全过；`pnpm typecheck`、`pnpm exec biome check` 过。
- 场景测试（`packages/engine/test/fusion.test.ts`「#253 先审后合」这组，共 5 条）：
  1. 碰安全的 PR：请第二意见 → 必须改 → 修一轮 → 再审通过 → 照常合并；合并闸单独报 `merge-gate` 红那一次没有被当成「CI 没过」喂给 Lead。
  2. 不碰高风险路径：一次都不请第二意见（`postSecondOpinion` 调用数为 0）。
  3. 连着两轮都必须改：停下等人，不再拖第三轮。
  4. 【故意造出的失败】高风险路径清单读不到：查不出碰没碰，停下等人。
  5. 【故意造出的失败】贴第二意见状态没权限：停下等人，不当「贴上了」。
- 端口层测试（`packages/engine/test/real/second-opinion-ports.test.ts`）：命中/不命中清单、【故意造出的失败】清单文件读不到、清单不是合法 JSON、PR 改动文件翻不完页；`postSecondOpinion` 通过/必须改贴的状态和描述、【故意造出的失败】贴状态没权限要抛错不能拿评论顶、评论被拦下不影响已贴好的状态。
- github 包层测试（`packages/github/test/pull-files.test.ts`）：`pullFiles` 翻完页、带 patch 和改名前的名字；【故意造出的失败】一条认不出（没有 filename）就抛错，不当空文件处理。
- `packages/engine/test/replay.test.ts`（老历史按现在的代码重放，含 5 条 fusion 夹具）、`packages/engine/test/worker.test.ts`（workflow 包真跑 webpack 打包）都过。

## 还欠什么

- 合并闸报「等第二意见」连着 3 次还查不到别的失败检查时停下等人：这个「别的原因」目前只写「多半是认领对得上、关单要带结果……」，没有再往下追认领对得上、关单结果具体是哪一种——这部分本来就不是这张单要解的（#253 只管第二意见这一段），碰上了帅位或后续单再细化。
- 这个 PR 本身没有改到 `packages/conventions/high-risk-paths.json` 里列的文件，档位按帅位交代写「先审后合」，等第二意见和验收。
