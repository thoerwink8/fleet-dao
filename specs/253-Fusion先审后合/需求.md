原话：无。#214 做 Fusion 工作流时发现：合并闸对两种路径（迁移里有删改语句、碰安全）要有第二意见的状态才放行（design 第五节），这个状态现在只有本机开 PR 的人跑第二意见垫片写；引擎开的 PR 碰到这些路径，合并队列合不进去，退回几次后停下等人。

- #213 定了开 PR 前验证不写成合并闸的状态（两道闸各管各的）。
- Fusion 做的单碰到先审后合的路径时，引擎要自己请别家出第二意见（审一轮、最多 2 轮，主审连不上换下一家），过了写成合并闸认的状态；审出要改的回 Lead 修。

## 怎么算做完

- Fusion 工作流开 PR 后，按合并闸同一份判法判这个 PR 要不要先审后合；要的，派别家只读会话按 design 第五节审，结论写成合并闸认的状态（绑在 PR 当前的头上）。
- 审出必须改的回 Lead 修一轮（和 CI 红同一本账）；主审派不出换下一家，都派不出停下等人，不写成过了。
- 工作流测试（假端口）：不用审的照常合、审过了合、审出要改修完再审、派不出别家停下等人，各一条；失败的每条都故意造出来。
