## 怎么做

- 标记：一对 HTML 注释（`fleet-dao:通用段 开始…` / `fleet-dao:通用段 结束`），只认整行。标记外原样保留；第一次接管（文件里没有标记）先把原文件整份备份到 `~/.fleet-dao/backups/<时间>/`，再整份换成受管块，输出写明原文件几行、备份在哪。比对前去掉 `\r`。
- 装没装：看命令在不在 PATH 和家里的 `.local/bin`，不看配置目录（法国的会话用户装了 codex、pi，家里却没有 `~/.codex`、`~/.pi`）。不跟 `CODEX_HOME` 之类的环境变量：跟了就会随调用者的环境写到别处。
- skill 用拷贝不用链接（仓和家常不在一个盘；Claude 在 Windows 上不建议软链）。清单 `~/.fleet-dao/agents-sync.json` 记下自己装过的：只更新、撤掉清单里的；同名但不是自己装的（插件链进来的、旧仓的 junction）一律不碰、判红。清单读不懂就停手，不当空清单。
- 任务书里列了 `~/.pi/agent/skills`，没放：pi 0.87 也扫 `~/.agents/skills`，两处各一份拷贝，pi 会逐个报 name collision。Grok、Devin 查过文档：Grok 默认扫 `~/.claude/skills` 和 `~/.agents/skills`，Devin 扫 `~/.agents/skills`，都不单放。
- 法国：root 带 `--user` 跑，先读好仓里的原件，再换成那个用户（initgroups、setgid、setuid）才动手，写出来的都归他；root 不带 `--user` 往别人家里写直接拒绝。`france.sh` 最后一步给两个会话用户和 pilot 各写一份，读回带上 `--check`。
- 退出码：有漂移、缺失或没做成为 1；只有没查成为 2（和装机脚本一样红压过没查成）；「没装」不影响退出码，但逐项列出、不算进一致。

## 本机切换的先后（和需求里写的不一样）

需求写的是 `--apply` 在 `--retire-old` 前面。但旧仓那 7 个方法类 skill 在 `~/.claude/skills` 里是指向旧仓的 junction，名字和新装的一样；按「不是本脚本装的一律不碰」，`--apply` 会跳过它们并报红，撤掉之后再查就是缺失（沙盒彩排两种顺序的结果见 [结果.md](结果.md)）。所以先撤再装：

1. 废掉旧仓的开会话自愈（旧仓 `.claude/settings.json` 的 SessionStart 钩子 `scripts/lib/onboard-session-hook.mjs`，旧仓各工作树里也各有一份）。
2. `node packages/agents-sync/bin/agents-sync --retire-old --old-repo <旧仓在本机的位置>`
3. `node packages/agents-sync/bin/agents-sync --apply`
4. `node packages/agents-sync/bin/agents-sync --check`：全绿（退出码 0）。

前提：本 PR 已合进 main、本机 fleet-dao 主树已拉到最新（不然第 3 步没有同步脚本、也没有 skill 可装，旧的却已撤）。
