# Jev 按用途分钥匙：一类一把 API key，一把额度用完不连累别的（#40）

对应计划：plan.md P3「花费进 Jev 记账」
设计依据：design 第十一节「按用途分钥匙」

起因：创始人 2026-09-25：「后续记得给 Jev 分类。我后续会接入 n 个 API key，每个分类的事情用不同的 Jev key 干，这样可以防止某个 key 对应的账号额度耗尽，影响其他。」

## 要什么

- Jev 的每次调用带用途类别：design 第十一节接入点表的每一行一类，另加「浏览器操作」和「考题」。
- 每类可绑自己的 TypeSafe 密钥（一把密钥 = 一个账号，各有额度和花费上限）；没绑的走默认密钥。
- 每把密钥登记用途、创建时间和指纹（不记值），看得出用了多久、账单对得上、该换时能提醒。
- 一把密钥用完、被限流或被拒，只停它那一类（按「没判」走默认），别的类照常；驾驶舱的额度页和通知里能看出是哪一把、哪一类停了。
- 绑定在调度台的 Jev 阶段里配；记账表 `jev_answers` 按类、按密钥分开统计，只记密钥编号，不记值。
- 密钥文件放法沿用现在的（服务器上 root:fleet 0640，不进 git）。

## 怎么算做完

- 两把假密钥分给两类，其中一把模拟额度用完：只有它那一类停、另一类照常答题，有测试。
- 读不到某一类绑的密钥文件时明确失败（这一类不判、报警），不悄悄换成默认密钥，有测试。
