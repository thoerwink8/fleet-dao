# 真接 GitLab 时做来源平台抽象和成员多平台账号（项目与标准分步⑤，以后再做）（#135）

对应计划：plan.md P6「接 GitLab」
设计依据：design 15.7「一、项目」第 1、2、7 条、「三、分步」。

原话：真接 GitLab 时做平台抽象和成员多平台账号。（创始人 2026-09-26 拍「项目 + 标准」方案选项 1，分步⑤；以后再做）
AI 理解：分步①只做 GitHub，导入页的 GitLab 是「待实现」占位；成员身上现在只记一个 GitHub 账号。真要接 GitLab 时，把导入、收事件、体检、补齐、写回这几处抽成「来源平台」一层，GitHub 和 GitLab 各一份实现；成员能同时记多个平台的账号。没有要接 GitLab 的项目之前不开工。

## 要做什么

照 `docs/design.md` 15.7「一、项目」第 1、2、7 条：

- 来源平台抽象：列仓、导入、按平台内部编号认仓、收事件（webhook 验签）、开 PR / MR、读写标签和里程碑、读 CI 状态，GitHub 和 GitLab 各一份实现，上层（项目、体检、补齐、引擎）只认抽象。
- 成员多平台账号：一个成员可以记 GitHub、GitLab 各自的账号；操作记录、白名单作者过滤按平台认人。
- 导入页的 GitLab 从「待实现」换成真的；标准里的 `.github` 仓、可复用工作流在 GitLab 上找对应做法（到时先查 GitLab 现行文档，写出处）。
- 每条读不到、认不出的路径返回明确失败，各配一条故意造出失败的测试。

## 怎么算做完

- 连一个 GitLab 账号、勾选导入一个仓，体检、补齐 MR、收事件和 GitHub 的项目一样走通（有真机记录）。
- 一个成员同时记着 GitHub 和 GitLab 两个账号，两边开的单、评论都认得是他；陌生账号在两边都被白名单挡掉（测试）。
- GitHub 这一侧的现有测试全绿，行为不变。
