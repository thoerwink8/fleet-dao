# 拼车用完自动切独享、恢复了自动切回（#59 最小版）（#157）

对应计划：plan.md P3「调度」
设计依据：design 第九节（一个会话用户，同一时刻只挂一个组织；拼车用完，切独享接着干）、第十节（Claude 订阅一个组织一个账号池）

原话（创始人 2026-09-26）：「这个提醒能不能自动自愈，而不是靠你提醒？」；排第几选了「1」——排在 P1 验收之后、项目模型之前。

AI 理解：拼车 5 小时额度用完时，法国的会话用户要能自己切到独享组织接着接活，拼车恢复后再自己切回，不靠人记着去切（2026-09-26 下午拼车用完，法国停着等人手动切，就是这个坑）。这是 #59 的最小版：只在手上没有在跑的会话时切；切号那一刻手上的活原地接着干（fork 续上）留在 #59（P3 验收）。

## 要什么

- 引擎发现拼车额度用完（会话或探针被拒、原文带恢复时刻，或额度读数到顶）：不再往拼车派；等手上没有在跑的会话，经 root 帮手（`deploy/france/fleet-agent-scope.sh` 新加的子命令，参数校验照现有写法）把会话用户切到独享组织；下一轮探针读回独享在线才算切成。
- 到拼车恢复时刻（额度读数里的清零时刻，读不到再用被拒原文里的）：等手上没有在跑的会话，切回拼车；探针读回拼车在线才算切成。
- 组织从 `reclaude org` 读（team 是拼车、personal 是独享），不写死、编号不进仓。「现在挂着哪个组织」那部分由 P1 验收时的修复先做（换掉 `SESSION_USER_ORG` 常量），这里直接复用。
- 切号、切回、切失败都进操作记录，驾驶舱看得到；切失败在健康检查里报红。
- 读不到组织列表、认不出类型、`org use` 失败、恢复时刻读不到、切完探针读回不在线：明确失败，不当成切好了、不当成到点了，每条配一个故意造出失败的测试。

## 怎么算做完

- 单元测试：假 reclaude 造「拼车被拒 → 等到没有在跑的会话 → 切独享 → 探针读回独享在线 → 到恢复时刻 → 没有在跑的会话时切回 → 探针读回拼车在线」全程；上面每条失败路径各有一条测试。
- 法国真机：拼车下一次真用完时没人动手，引擎自己切到独享、接着派活；到拼车恢复时刻自己切回；操作记录里切号、切回两条都在。
- 本机总指挥会话里「到点提醒切回拼车」那个定时提醒撤掉。

## 不做
