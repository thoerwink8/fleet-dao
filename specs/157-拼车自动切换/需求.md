# 拼车用完自动切独享、恢复了自动切回（#59 最小版）（#157）

对应计划：v1（母单 #194，创始人 2026-09-27 挪进）
设计依据：design 第九节（一个会话用户，同一时刻只挂一个组织；拼车用完，切独享接着干）、第十节（Claude 订阅一个组织一个账号池）

原话（创始人 2026-09-26）：「这个提醒能不能自动自愈，而不是靠你提醒？」；排第几选了「1」——排在 P1 验收之后、项目模型之前。

AI 理解：拼车 5 小时额度用完时，法国的会话用户要能自己切到独享组织接着接活，拼车恢复后再自己切回，不靠人记着去切（2026-09-26 下午拼车用完，法国停着等人手动切，就是这个坑）。这是 #59 的最小版：只在手上没有在跑的会话时切；切号那一刻手上的活原地接着干（fork 续上）留在 #59（P3 验收）。

## 要什么

- 引擎发现拼车额度用完（会话或探针被拒、原文带恢复时刻，或额度读数到顶）：不再往拼车派；等手上没有在跑的会话，经 root 帮手（`deploy/france/fleet-agent-scope.sh` 新加的子命令，参数校验照现有写法）把会话用户切到独享组织；下一轮探针读回独享在线才算切成。
- 到拼车恢复时刻（额度读数里的清零时刻，读不到再用被拒原文里的）：等手上没有在跑的会话，切回拼车；探针读回拼车在线才算切成。
- 组织从 `reclaude org` 读（team 是拼车、personal 是独享），不写死、编号不进仓。「现在挂着哪个组织」那部分已做（2026-09-27，换掉了 `SESSION_USER_ORG` 常量：以会话用户跑 `reclaude org list`、认带 `*` 的那行的类型，`packages/engine/src/real/session-org.ts`），这里直接复用。
- 切号、切回、切失败都进操作记录，驾驶舱看得到；切失败在健康检查里报红。
- 读不到组织列表、认不出类型、`org use` 失败、恢复时刻读不到、切完探针读回不在线：明确失败，不当成切好了、不当成到点了，每条配一个故意造出失败的测试。

## 怎么算做完

- 单元测试：假 reclaude 造「拼车被拒 → 等到没有在跑的会话 → 切独享 → 探针读回独享在线 → 到恢复时刻 → 没有在跑的会话时切回 → 探针读回拼车在线」全程；上面每条失败路径各有一条测试。
- 法国真机：拼车下一次真用完时没人动手，引擎自己切到独享、接着派活；到拼车恢复时刻自己切回；操作记录里切号、切回两条都在。
- 本机总指挥会话里「到点提醒切回拼车」那个定时提醒撤掉。

## 不做

- 切号那一刻在跑的会话 fork 续上、手上的活原地接着干：留在 #59（P3 验收）。

## 现状

代码已做（2026-09-27，本单的 PR）：
- root 帮手 `fleet-agent-scope org-use <carpool|solo> --user <会话用户>`：以会话用户读 `org list`、认出那一类的组织、切、回读核对，没切成、核对不了都切回原来的，整个流程有总时限（`deploy/test/agent-scope-org-use.test.sh` 把每种没切成的路径造了一遍）；adapters 的 `switchSessionOrg` 调它。
- 判法（`packages/engine/src/jobs/org-switch.ts`）和装配（`real/org-switch.ts`）：路由探针每一轮探之前判一次；只在没有没结束的 Claude 会话时切，切之前让选路停下、等 15 秒再数一遍；切完这一轮探的就是切过去的池，探通才算切成。
- 切号、核对进操作记录（`session-org.switch`、`session-org.verify`）；没切成、切完读回不在线、拼车恢复时刻读不到写 `session-org:*` 提醒，驾驶舱后端健康检查 `session_org` 跟着红。
- 全程测试 `packages/engine/test/real/org-switch.test.ts`：拼车被拒 → 等到没有在跑的会话 → 切独享 → 读回在线 → 到恢复时刻 → 空着时切回 → 读回在线；失败路径各一条。

还没做成的：「怎么算做完」的法国真机那条要等拼车下一次真用完（合进去、发到法国后先读回一次：法国现在挂独享、拼车读数没用满，引擎会在第一轮空着时切回拼车，这一次切回的操作记录就是真机上的第一条）；本机总指挥会话里「到点提醒切回拼车」那个定时提醒由帅位撤。「手上有会话在跑就等」已由 #59 换掉（2026-09-27）：切之前先把在跑的停下、切完 fork 续上，见 specs/59 的现状。
