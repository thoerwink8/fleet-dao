# 能不能合全在 GitHub 上判：一个合并闸 `merge-gate`，全绿就自动合（#74）

对应计划：plan.md P1「GitHub：两个新机器人」
设计依据：design 第五节（流程只为快、合并闸）、第七节（PR 必填栏、标签与里程碑）。

原话：能不能全部检测都做在 GitHub 上，这样我人为肉眼一扫就知道能不能合并了，然后你的检测也能更加顺畅。（创始人 2026-09-25）
起因：9/25 #56、#58 在 PR 列表上是两个绿勾，其实和主线冲突，以为全绿却没人合。

## 要什么

- **一个信号**：PR 当前头上的提交状态 `merge-gate`，就是「按我们的规矩能不能合」（创始人 2026-09-25 拍：做成统一的合并闸，不零散加规则）。它要：
  1. 不是草稿；
  2. 和主线没冲突；
  3. 改到先审后合的路径（2026-09-26 下午起只剩两种：迁移里有删改语句；碰安全——密钥与登录鉴权、卫生检查和 CI 工作流，外加 deploy/ 里法国防火墙两份、sudoers、香港 nginx 两份这 5 份对公网开口子和提权的配置；其余部署脚本 CI 绿就合，见 design 第五节）时，当前头上要有通过的 `second-opinion` 提交状态；没有、没过、还在跑、只在旧头上有，都不通过，报出是哪几个文件。按路径判、不看 PR 自己写的档位；清单在 `packages/conventions/high-risk-paths.json`，每条写为什么，新迁移只建表、加列不算。
- PR 必填栏（类别标签、里程碑、对应计划、specs、档位）只在检查页上提醒，不挡合并（创始人 2026-09-26「流程只为快」）。欠账检查只看文件的那一半也只报告（`.github/workflows/debt.yml`），不进必过检查。
- 哪条不满足就 failure，说明里写卡在哪条，全文在详情链接里。读不到、认不出写 failure「没查成」，GitHub 还没算完冲突写 pending，都不当通过。
- **什么时候算**：PR 的各种事件；主线有新提交（逐个重算所有开着的 PR——冲突是主线一变才出现的，有冲突的 PR 上 pull_request 工作流跑不起来）；`second-opinion` 状态写上来时。判法和清单用主线上的那份，PR 改不了自己的门槛。
- 冲突在 PR 列表上看得见：有冲突的 PR 自动贴「有冲突」，解掉自动撕（只是显示）。
- AI 开 PR 就挂自动合并（`gh pr merge --auto --squash`），不轮询、不手动合。

## 不在这一单

- 第二意见本身：以后做成「PR 一开就自动跑、和 CI 并行、会话死了也不丢」的质量检查，另开单；这里只认 `second-opinion` 状态。
- 主线必过检查从 `pr-fields` 换成 `merge-gate`：2026-09-26 已换（规则集读回核对过），`pr.yml` 随后删掉。
- 「分支必须跟上最新主线」先不开，观察一周再定。

## 怎么算做完

五个场景，每个都有单元测试（`packages/conventions/test/merge-gate.test.ts`），也在真仓里用临时 PR 跑一遍（跑完关掉、删分支）：

1. CI 绿、没冲突、不是草稿、没改到那三种地方 → `merge-gate` 通过，挂着的自动合并真合了。
2. CI 绿、有冲突 → 不通过。
3. CI 绿、草稿 → 不通过。
4. CI 绿、没贴标签、没挂里程碑、没写档位 → 照样通过，检查页上提醒缺了什么。
5. CI 绿、改到那三种地方、当前头没有通过的第二意见 → 不通过（档位写什么都一样）。

另外：读不到 PR、改动文件、提交状态、清单，状态写不上，每条都有一个故意造出来的测试，判「没查成」不当通过；必填栏那一半读不到只变成提醒，也有测试证明它改不了结论。

## 现状

合并闸、冲突标签、PR 模板和引擎开 PR 的「档位」一栏在本单的 PR 里。
