# 写法

给别的仓用。整份抄进那个仓自己的 `AGENTS.md` 才生效。不装钩子，不要求这个仓接入 fleet-dao，同步也不会写进那个仓。

## 需求

需求写四节，缺一节不算写完：

- 场景：谁、在什么情况下、要干什么。
- 原话：提出人怎么说的。不改写。
- 已知的模块：会碰到的路径或模块。写得出来的才写。
- 怎么算做完：做完时看得到的东西。写成能对上的结果。

做成了什么写在改动说明里。不回头改已经写好的需求。

## 方案

要写才写。做法有取舍，或者别人接不上的时候才写。放在 `specs/<短名>/方案.md`。有单号就用单号当短名。不改已经写好的需求和结果。

## 设计

设计写系统怎么工作、边界在哪、什么不做。放在 `docs/design.md`。改界面先读这个仓的界面设计。没有就先写下来再改。
