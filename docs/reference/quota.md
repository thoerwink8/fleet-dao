# 额度短索引

全文在 git 历史。选路测试 `packages/engine/test/routing/pitfalls.test.ts` 覆盖 Q7、Q8、Q11、Q17。Q1–Q6、Q15、Q27 仍被方案文档点名。并发 6 是旧系统实测的起步值（Cursor、Grok 目录说明里引用的就是这个数）。

名册帧：`{type:'modelRoster', agent, entries:[{id, label, contextWindow, enabled, defaultOn}]}`。`enabled` 是桌面端「模型管理」里勾没勾。空名册、帧形不对、命令非零，都是没查成，不当成全部下线。

中转账号是一份共用额度（5h、7d），另有只扣某一族模型的窗口。额度用完的通知可能被当成回答回来（adapters MS-32），不能当上游抖动（adapters GK-08）。

- **Q1** 用满那一刻可能没有利用率字段。探针非零退出、最后一条 `rate_limit_event` 只有 `{"status":"rejected"}`、正文写着约 N 分钟后重置：记该池 5h 已用满，刷新点按这句算，不得记成没查成。输出里根本没有 `rate_limit_event` 才判没查成，不得当 0%。
- **Q2** 切号只认正面证据。`org use` 退出 1 但本机设置已经写成目标号：判失败并切回原号。回滚也失败就如实报这台现在可能起不了会话。
- **Q3** 组织编号运行时从 `org list` 认，不写死。目标那一类已经没有可用组织，就守在当前组织并报原因。
- **Q4** 切回看拼车的刷新点，不看独享自己的窗口。
- **Q5** 额度探针要便宜、没有副作用：小模型、只加载项目级设置，不得带 `--bare`。
- **Q6** 同一个 reclaude 账号挂在多台机器上，额度是账号级共享的。任一台读到用满，挂该组织的路由一起判满。切号只由一处发起。
- **Q7** 5h 和 7d 两个窗口各存一行。不得只存最紧的那个，否则「快清零但几乎没用」的信号会丢。
- **Q8** 模型组窗口（如 `7d_fable`）只卡对应模型。别的路由照常。
- **Q11** 读数超过约 30 分钟不当现值。调度应判没查成并进对账，不得继续当还够。
- **Q15** 按分钟限流（429、每分钟额度已满）是上游限流，只让这条路由短冷却。带 402 / insufficient_quota / billing / 周限 / 余额的才归账号类，才停整个池。
- **Q17** 账号的失败不算到模型头上。同一个模型在另一个池上正常，就只暂停坏的那个池。
- **Q21** Mirasim 会话服务带 `MIRASIM_NO_AGENT_EGRESS=1` 和 `MIRASIM_ACCOUNT_USAGE_PROBE=0`。这两个开关不许当成多余去掉。reclaude 日志里出现 `non-cc-client` 应当判红。
- **Q27** 5h 窗零用量时，读到的刷新点经常是「采集时刻 + 5 小时」。这个边界在漂，不当成锁定的锚点。
