## 来自 design 第十一节「Jev 判断题服务」

- **它是驾驶舱流程里用来提速的一个判断环节，不是独立产品**（创始人 2026-10-05 约 19:10（北京时间）：「5是驾驶舱的流程，而不是独立产品，是服务于整体流程环节的，用来提速」，#1073）。代码在 `packages/jev`，不单独配一套配置和文档；它留成包不并进引擎，只因为引擎和驾驶舱后端（`/healthz` 的 judge 项）两边都调它，并进引擎会让后端反过来依赖引擎。
- 选择题 + 把握度；把握低 = 没判出来，走默认；连不上 = 没判，不当成「否」。
- **能拦不能放**：它可以让一件事停下、退回或换路，不能批准合并、不能动账号、不能删东西。
- 创始人要求「能接的地方都按场景和性价比接上」。下表是设想的接入点，**真接上、引擎还在问的只有 issue 归类**；错误分流、停滞预判的题还在题库里，引擎不再登记、不再问。没接的那几行代码里没有题（题库只留三道），要接再加题、加调用方：

| 接在哪 | 它判什么 | 为什么值 |
|---|---|---|
| 分诊 | 哪类活、是不是 UI（GPT 禁令靠这个）、有没有说不清的地方、该问哪一句、会不会碰花钱或删数据 | 每条需求只判一次，结果直接喂调度 |
| 查重 | 新需求和在途的是不是同一件事、会不会改到同一块地方 | 避免重复干、并行撞车 |
| 需求文档质检 | 「怎么算做完」能不能验证、缺哪条 | 开工前拦住含糊需求，最省返工 |
| 交活核实 | 改动和测试结果是否真做到了需求文档的「做完标准」 | 专治假完成 |
| 审查意见分级 | 哪些必须改、哪些是小毛病（小毛病攒起来定期批量修） | 减少返工轮数 |
| 错误分流（#1072 起不再问） | 规则认不出的报错：重试、换路由、换模型还是挂起。失败分流瘦成按「打断原因」办的一张表后，没有换路由、换模型这些要它选的动作，认不出的按临时的办一两次再停下报人；题库里这道题还在，引擎不再登记、不再问 | 只触发能撤回的动作 |
| 停滞预判（引擎不再问） | 会话没动静时读最近的过程记录：在等、在绕圈还是死了。题库里这道题还在，没有工作流再问，引擎不再登记、不再问 | 决定先提醒还是重开 |
| 飞书消息理解 | 开新任务、问进度还是下命令 | 机器人不再听不懂；拿不准就弹二选一卡片 |
| 日报挑重点 | 今天这些事里哪几件最该人看 | 日报短而准 |
| 浏览器操作 | 页面上这一步做哪个动作、点哪个元素（元素带编号喂进去，一次请求同时问动作和落点） | 网页操作从「一步一轮大模型」变成「一次调用跑完一段」；它只从页面上真实存在的元素里挑，不许自己造选择器 |
| issue 归类（已接） | 新开（或重新打开）的 issue 该贴需求/缺陷/杂项哪一类 | 省得人手动分诊；不贴、只按标题猜的旧办法准头差（#425 实测凌晨 32 个里 9 个没类别）|

- **浏览器操作怎么接**（创始人 2026-09-25 拍板，issue #37）：
  - 调用方（AI 会话）定目标、给要填的值；Jev 只挑「下一步做哪个动作、点表里第几个」，一次请求同时问动作和落点。要打的字由调用方给，不另接写字的模型；缺值就停下交回。只读的看页面、核对结果不调模型。
  - 和「能拦不能放」的关系：它挑的是调用方已经定好的目标的下一步；按了收不回的（付款、删除、停用、发布、退订等）照样停下交回调用方，碰人闸的由调用方问创始人。
  - 本机先装现成的 jev-ultrafast-mcp 当垫片，照上游直接用；正式版做成浏览器端口、接 `packages/jev`（花费闸和记账表），驱动本机专用 Chrome（独立 profile），排在 P3。
  - 花费先不设上限，跑一周看账单和实际用量再定月度上限（#37）。
- **按用途分钥匙**（创始人 2026-09-25 提）：Jev 的调用按用途分类（上表每个接入点一类，另加浏览器操作、考题）。每类可以绑自己的 TypeSafe 密钥，一把密钥对应一个账号、各有各的额度和花费上限；一把的额度用完只停它那一类（这一类按「没判」走默认），别的照常。没绑的走默认密钥。绑定在调度台的 Jev 阶段里配；记账表按类、按密钥分开统计（只记密钥的编号，不记值）。
- **不接**：能用代码算清的（数字、阈值、代码差异、测试结果）；批准合并、动账号、删东西；选哪条路由（旧系统里这道题占了 64% 的调用、价值最低）。
- **怎么管住它**：每道题登记成「只记不拦」，每一问记进判断记录；每天问多少次、按量计费的后端每天花多少有上限，到了就停调、走默认；模型版本钉死，不用「latest」；拿不准、连不上时当它不存在、走默认。原设想的「攒满 50 条且准确率过线自动转真拦、巡检考试掉下去自动退回」（#144）创始人 2026-09-28 拍了不做，转真拦、逐题复核、巡检考试、考题的代码在 #1073 随收成流程里的部件一并删掉，没有任何代码会把一道题转成真拦；真拦中的题漂了（答了题面外的选项、回话的不是钉死的模型）当场退回只记不拦这一道保险还在（库里手改成真拦才会用到）。
- **接到哪了**（2026-09-26；issue 归类 2026-09-28 随 #448 接上；错误分流 2026-10-05 起不再问，#1072；停滞预判 2026-10-06 起引擎不再登记、不再问）：引擎现在只问 issue 归类。错误分流、停滞预判两道题还在 `packages/jev` 题库里（jev 自己的测试和样题还用 error-next），没有工作流再问，引擎起来时也不再登记。配置在法国 `/etc/fleet-dao/jev.json`（`FLEET_JEV_CONFIG` 可改），后端按路由两层里判断用途排第一、不是死的那条路由起（Jev 按量计费、探针不探，「接得上」是不知道的照样取；死的——开关关着、渠道关了、模型下架、命中禁令、额度用满、探针真探了没通——跳过），每次问都现找，库里两层的顺序、开关改了下一道就换；默认位置上没有这个文件才算没接，文件在却读不到、认不出、判断用途派不出路由（写明是这个用途没有模型、模型下没路由，还是每条死在哪）、钥匙读不到都报错（引擎日志 + `/healthz` 的 judge 项红，最近一次真调用没成也红）。失败后超过 30 分钟没有新调用时，引擎定时任务 `judge-self-check`（每 30 分钟，每小时 17、47 分）发一道固定自检题（答案是 yes，不计入每日次数和花费），结果写进判断记录当作最近一次：自检通过就恢复，自检也失败则继续红并在日志原因里写明是自检失败；最近一次已经成功的不发。issue 归类接在 `github-reconcile` 每小时对账里（第七节「标签与里程碑」），问的是同一份 `/etc/fleet-dao/jev.json`、同一个 `resolveJevBackend`，题是 `issue-kind`，装配在 `packages/engine/src/real/issue-kind-jev.ts`，起来时在 registerJobs 里登记；先只记不拦，把握不够或连不上就不贴、记进日报，不当成错误。
- 它本身也是一个阶段类型：用哪个模型、每天最多调多少次，驾驶舱里能配、能看每道题的准确率。套餐内调用不算花钱。判断阶段在 Claude 判断后端接上之前先用 TypeSafe 的 Jev，其余阶段构建期全用 Opus 5.5（2026-09-25 定，#47；先跑一周看账单）。
