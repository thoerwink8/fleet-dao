# 驾驶舱界面规范

母单 #1844，方案 `specs/1844-驾驶舱设计规范/方案.md`。这份是定稿：改驾驶舱界面（`packages/web`）先读它。
令牌在 `packages/web/src/app.css`，检查是 `packages/web/scripts/lint-design.ts`，由 `src/test/lint-design.test.ts` 守着（CI 必过）。
令牌改了，同一个 PR 改这份文档。

## 一、视觉基调

参照 Linear 的克制、Vercel Geist 的字阶分工、GitHub Primer 的行密度和令牌分层。八条：

1. 字号只有七档（含只给画布用的 canvas），桌面根字号放大到 125%（实测依据，见下面「字号」一小节），中文最小 12px。次要文字在每套主题上都 ≥4.5:1。
2. 数字用无衬线加等宽数字（tabular-nums）。只有编号、提交号、路由号、模型 id、代码用 `font-mono`。
3. 最多两层容器：页面 → 区块。区块里用分隔线和行，不再套卡片。
4. 圆角：控件 6px，卡片和弹层 10px，标签全圆。
5. 阴影只表示「浮起」。卡片在亮色下只有一根下边线，暗色下没有阴影。
6. 状态色三种用法：实色（点、条、图标）、淡底（12%）、描边（40%），各有令牌。标签一律「点或图标 + 字」。
7. 页头一行：标题在左、操作在右。说明最多一行，长说明收进 ⓘ。
8. 控件高：桌面标准 40px、紧凑 35px（`h-control`，设计值 32 / 28 乘根字号 1.25），手机至少 40px。手机上输入框字号 16px。

### 2.2 字号

**桌面根字号放大到 125%（#1937）。** 依据是实测：创始人 2026-10-12 在 Windows、Chrome、100% 系统缩放的 1x 屏（1568–1920 宽）上看，原来照苹果 macOS HIG 定的 13px 正文偏小，浏览器缩放 125% 刚好（原话「排查一下，为什么100%字体会偏小；感觉125%刚刚好？」）。macOS 的 13pt 在视网膜屏上观感大，搬到 1x 屏上小一圈，中文尤其。

- 做法：`app.css` 的 `html { font-size: calc(100% * var(--root-scale)) }`，`--root-scale` 手机（<48rem）是 1、桌面（md，48rem 起）是 1.25。字号、控件高、行高、间距、顶栏侧栏宽、抽屉宽全写 rem，一起等比放大，默认就是 125% 的观感。手机完全不变。
- 1 rem 在桌面是 20px、手机是 16px。`app.css` 和下表的「设计值」按 16px 根字号写（字阶比例沿用 macOS：Body 13/16、Title 3 15/20、Title 1 22/26、Large Title 26/32），**桌面实际像素 = 设计值 × 1.25**，表里两列都写了。
- `@media` 里的 rem 按浏览器初始字号（16px）算、不随根字号变：断点仍是 768 / 1024 / 1280 / 1536 像素。所以同样宽的屏，放大后比浏览器缩放 125% 时的布局宽（浏览器缩放会把断点一起往下推）。1024、1280、1366、1568、1920 五个宽度都截图验过没有横向滚动。只挪了一个门槛：侧栏默认展开从 ≥1280 改成 ≥1440（展开的侧栏放大后 290 宽，1366 上正文只剩 1000 上下）。容器查询里的 rem 按实际根字号算，跟着放大（额度页 `quota-matrix`）。
- JS 里按像素算的尺寸（窗口化列表的定高行和窗口高、主页画布的节点尺寸和排版间距、「看会话」抽屉的默认宽）乘 `lib/root-scale.ts` 的倍数，读的就是 `<html>` 的实际字号 ÷ 16。新写这类常数也照办，不然行框比 rem 写的字小一圈、字被切。
- 主页画布整张图（节点、间距）等比放大 1.25，和浏览器缩放 125% 一模一样；缩放档位、「读得出」的下限（`fit-view.ts`）不用改。
- 写 px 的只剩不该放大的：边框、聚焦圈、竖线（1–3px）。

| 类名 | 桌面设计值（≥48rem） | 桌面实际像素 | 手机（<48rem） | 字重 | 用途 |
|---|---|---|---|---|---|
| `text-meta` | 12 / 16 | 15 / 20 | 12 / 16 | 400，可 500 | 时间戳、表头、计数、标签里的字、辅助说明（中文最小 12） |
| `text-body` | 13 / 16 | 16.25 / 20 | 14 / 20 | 400，可 500 | 默认：列表行、表格、正文、按钮、输入、菜单 |
| `text-heading` | 15 / 20 | 18.75 / 25 | 16 / 24 | 600 | 区块、卡片、抽屉、对话框标题 |
| `text-subtitle` | 20 / 26 | 25 / 32.5 | 18 / 24 | 600 | 一页最多一处的主标题块（路由页的用途名，#1914）：比页标题小一档、比区块标题大一档 |
| `text-title` | 22 / 28 | 27.5 / 35 | 20 / 28 | 600，字距 -0.01em | 页面标题 |
| `text-display` | 26 / 32 | 32.5 / 40 | 28 / 32 | 600 | 指标大数字（配 tabular-nums） |
| `text-canvas` | 11 / 14 | 13.75 / 17.5（再乘画布缩放） | 11 / 14 | 400 / 500 | 只在 `components/home/board/` 的画布里用 |

行高、字重绑在字号上，不另写 `leading-数字`。字重只用 `font-normal`、`font-medium`、`font-semibold`。
旧名 `text-micro`、`caption`、`sub`、`label`、`strong`、`stat-num`、`stat` 已在收口片（#1855）从 `app.css` 删除。

### 2.3 间距

内外边距、`gap`、`space` 只用这些档：`0`、`px`、`0.5`、`1`、`1.5`、`2`、`2.5`、`3`、`4`、`5`、`6`、`8`、`10`、`12`、`16`。
宽高（`h-*`、`w-*`、`size-*`）不限档，但不许写任意值。

### 2.6 动效

时长只用 `duration-100`（悬停变色）、`duration-200`（展开收起）、`duration-300`（抽屉进出）。
缓动：`ease-out`（进入、展开），`ease-in-out`（来回切换）。
系统设置或设置页打开「减少动效」时，全部停下。

### 2.7 组件令牌和密度

学 Ant Design 的组件令牌和紧凑算法（方案第十三节）：只给会随密度变的六个尺寸起名，切一组值整站一起变。值写 rem，表里是 16px 根字号下的设计值；桌面根字号放大到 125%（见上面「字号」一小节），桌面实际像素在括号里。

| 类名 | 是什么 | 标准 | 紧凑 | 用在 |
|---|---|---|---|---|
| `h-control`（`size-control`、`min-h-control`） | 控件高 | 32（桌面 40） | 28（35） | 按钮、输入、下拉、开关组、筛选标签 |
| `h-row`（`min-h-row`、`size-row`） | 行高 | 40（桌面 50） | 32（40） | 列表行、大号按钮 |
| `min-h-row-tall` | 两行的行高（名字一行加一行小字） | 48（桌面 60） | 40（50） | `RowFrame tall`（路由页的模型行、路由行，#1914）、`ListRow tall`（任务列表，#1919） |
| `p-section`（`px-`、`py-`、`mb-`） | 区块内边距 | 16（桌面 20） | 12（15） | 区块的页头和正文、空状态、展开明细 |
| `gap-section-gap` | 区块间距 | 24（桌面 30） | 16（20） | 页头和内容之间、两栏区块之间（lg 起） |
| `gap-stack`（`py-stack`、`px-stack`） | 区块内间距 | 12（桌面 15） | 8（10） | 页头、区块页头、行内元素之间、横幅左右 |

- 值在 `app.css` 里的密度变量块，`<html data-density="comfortable|compact">` 切换；`ThemePref.density` 存在浏览器本地，默认标准，认不出的值回到标准。设置页「外观」有「密度：标准 / 紧凑」，陈列页 `/_design` 顶上也有。
- 紧凑只在桌面（md，48rem 起）生效。手机上不变，所以 390 宽两种密度完全一样，40 的可点区（#1820）照旧。
- 字号不跟着缩：中文最小 12，紧凑只收框的高度和留白。
- 任何一棵子树挂 `data-density` 都按它自己的来，嵌套的 `data-palette` 不会把密度重置回标准。
- 只许 `components/layout/`、`components/ui/` 用（lint-design R10）。页面要尺寸就用版式组件，不自己写这六个类。
- 不随密度变的尺寸（标签、图标、徽标、小号按钮 `xs`）不起令牌：小号按钮最矮 24px，是可点区的下限，紧凑也不再缩。
- 两个比例：列表行上下内边距 = (`h-row` − 一行正文 20px，桌面正文 16px 时由 `min-h-row` 兜底) / 2，键值行 = `h-row` / 5，筛选标签和 `sm` 号控件比 `h-control` 少 4px。都写成 `calc(var(--spacing-…) …)`，只在 layout、ui 里。

## 三、版式组件（片 2 起）

组件放 `packages/web/src/components/layout/`。页面拼组件，不手写卡片、标签、空状态。
页面只传内容和语义（`tone`、`variant`）。`className` 只留给布局：宽度、栅格位置、外边距。
状态类组件渲染 `data-tone`。单测断言 `data-tone`，不断言类名。

| 组件 | 替掉的手写 |
|---|---|
| `Page` | 页头：标题左、操作右，刷新在固定槽位（见下面「页头」） |
| `Section`、`SectionGrid` | `Panel` 和手写的 `rounded-* border bg-card` |
| `List`、`ListRow` | 各自定行高的 `divide-y` 列表、`ExpandRow` |
| `KeyValue` | 四种 `<dl>` 排法 |
| `StatusBadge`、`Tag` | `StatusChip` 和页里手写的状态小块 |
| `EmptyState` | `Empty` 和手写的虚线框 |
| `Toolbar`、`FilterTabs`、`FilterTabGroups`、`FilterTabNote`、`SearchInput`、`NativeSelect` | 四种筛选条、手写的分组筛选和悬着的组说明、手写带图标的搜索框、原生 `<select>` |
| `Notice` | 手写的出错、提醒横幅 |
| `RowFrame`、`RowDetail`（`list.tsx`） | 自己管 `li` 的列表（拖动排序）里手写的行高、内边距、展开明细的缩进 |
| `RowMenu`、`RowMenuItem`、`RowMenuRadioItem`、`RowMenuLabel`（`row-menu.tsx`） | 一行里并排的四五个小按钮、行内的下拉 |

### 行：一个主信息、一个状态，次要操作收进「⋯」（#1914，路由页样板）

参照 macOS 系统设置、Linear 列表行、Vercel 设置页：每行只有一个主信息和一个状态，层级靠字重和灰度，不靠边框和色块。

- 一行从左到右：（拖动柄）序号或状态点、名字加一行灰字小字、一个状态、开关、行尾「⋯」。别的都不进行里。
- 状态只放一个：有状态色的用 `StatusBadge`（行里挤的时候 `variant="dot"`，点加字、没有底），没有状态色的用 `Tag`。
- 偶尔才动的操作（挪位置、档位、移出……）收进 `RowMenu`。鼠标设备上「⋯」平时在原位极淡（`opacity-40`，右边不空一块），拖动柄平时整个藏着；悬停这一行、键盘焦点进到这一行、菜单开着时变实；触屏一直实着。菜单项手机上至少 40 高。键盘快捷键（Alt+方向键挪位置）照旧挂在拖动柄上，写在柄的悬停提示和页头 ⓘ 里。额度页每个池那一行的停用开关留在行里，不收进「⋯」。额度页每个渠道的组头右边放整渠道的「全部暂停 / 全部放开」（混合状态是「暂停其余 / 放开已停」，#2900）：`xs` 描边按钮，点开后在组头下面展开和池开关同款的原因表单（先预览会动哪几个池），一次只开一张表单。
- 行用 `RowFrame`（或 `ListRow`）：行高、内边距取 `h-row`（两行的行用 `tall`，取 `row-tall`：标准 48、紧凑 40）、`p-section`，带 `group/row` 给悬停露出用；拖动柄浮在行左边的留白里，不占一列。
- 行下面展开的明细、表单、提示用 `RowDetail`：左边按 `p-section` 加 `--spacing-row-indent`（3rem：展开箭头加序号的宽）缩进，和行里的名字对齐。行首没有箭头、序号，名字就贴着行的左内边距时（设置页的仓库行，#1917）传 `indent={false}`，只留 `px-section`。
- 行和行之间只有一根 `divide-border` 细线，不画框；悬停 `bg-accent`、选中 `bg-selected` 加左边竖线。关着、被跳过的行只把名字那块降对比度（`opacity-60`），不整行换灰底。
- 同一件事一行里只写一遍：状态已经写了的（「池暂停」），不再另贴小标签；长的附注（「满了，等空位，不算故障」）收成一个小图标，话在悬停和读屏里。
- 一页最该看的那一句（路由页：这个用途现在实际派给谁）做成区块上面的标题块：名字单独一行 `text-subtitle`，下面隔 12 是结论短话 `text-heading font-normal` 加结论的 `StatusBadge`，再下面一行 `text-meta` 灰字细节；标题块和下面的区块隔 24。结论只写短话（「首选 Opus 5.5」「实际派 GPT 5.6 luna」），走哪条路、为什么不是首选放灰字行，整句在悬停里。
- **一行不折**（创始人 2026-10-11 看 390 宽「变成 2 行了」，#1914 第 5 轮）：标题块三行、行的小字、卡头说明、筛选条，在 320 到 1568 任何宽度都只占一行。行里的名字（模型名、路由名）是认东西的那一样，不截断：真长到放不下宁可换行。做法：容器 `whitespace-nowrap`，会变长的那段 `min-w-0 truncate` 并把整句放 `title`，状态标签、开关这类不让位的 `shrink-0`；手机上放不下的说明换短说法（`md:hidden` / `max-md:hidden` 两份），不靠换行。只有成段的说明文字（表单说明、原因分组的标题）可以折。e2e `11-mobile-overflow` 量标题块三行的高度。
- 同一类的几组次级筛选用 `FilterTabGroups`：组间一道细竖线，后一组前面写组头小标题；只读的说明项（「对题」）用 `FilterTabNote`，说明在悬停里，不另占一行。任何宽度都是一行，lg 以下放不下就整排横向滑动，不折成第二行。
- 一个配置项按「模型 × 路由」配的（思考档位），配在路由上：路由展开后的明细里就地改，配过的在行的小字里写一句；要横着比所有路的，放同一页的一个页签（路由页「思考档位」），不另开一页（#1914 第 5 轮并进路由页）。
- 定高的两行行（模型目录、渠道这种按行高开窗只画看得见几行的长列表，思考档位页签的路由行）例外：名字也截断、整名放 `title`，因为行高是算死的，换行会压住下一行（#1916）。第一行＝名字加一个状态（`data-row-name-line`），第二行＝灰字小字（`data-row-meta`），各占一行；e2e `11-mobile-overflow` 在 320、390 量这两行。
- 同一模型有几条路分不出来时（两条 Claude 订阅），小字直接写「渠道 · 池号 · 跑在哪」，池号看得见，不只放悬停（#1916）。
- 路由行在手机上状态只画点，字放悬停和读屏，不让状态标签把名字挤成两行；「顺位第一条活的」这类标签放小字行的开头，不放末尾（末尾会被截掉）。
- 模型名字旁有强弱档的画一个 `Tag`（强档用 `brand`、标准档和快档 `neutral`，`components/model-strength-badge.tsx`），用途页的模型先后和模型目录两处同一个；没标档位的不画。档位只读目录（`models.strength`），驾驶舱不改（#2691）。用途页「动手战绩」表里的「派工档」（主力 / 中档 / 快档，单子的难易）是另一回事，表头写全称，不和强弱档混。

### StatusBadge 与 Tag 的分工（#1910）

- `StatusBadge`：有状态色的（在跑、卡住、失败、已完成、已关……），点或图标加字，意思靠字传。
- `Tag`：分类、来源、套餐、提交号这类没有状态色的；`tone` 只是着色，不表示进度或好坏。

### 会发写请求的按钮（#2009）

创始人 2026-10-13「现在驾驶舱缺少确定按钮 loading，所有页面都判断下」：点了「确认发布」「叫停」这类按钮看不出点没点上、还能连点。做法照 Primer 按钮无障碍规范（加载中不用原生 `disabled`、配 aria-live 播报、失败把焦点送到错误）和 TanStack Query（`isPending` 驱动界面）。

- **普通按钮**：`<Button loading={m.isPending} onClick={() => m.mutate(…)}>`。忙时 `aria-busy` + `aria-disabled`（不用原生 `disabled`，键盘焦点留得住），点击被拦，同一帧里的第二下由按钮里的 ref 再挡一道（状态还没提交到 DOM 时只靠 `loading` 挡不住）；`onClick` 返回 Promise 时，落地前也挡。传了 `loading`（哪怕是 `false`）按钮旁边就始终有一个 `aria-live="polite"` 的隐藏播报区，忙时读「正在<按钮上的字>…」，`loadingLabel` 改这句。不写 `role="status"`：页面自己的结果提示才是那个 status。
- **转圈**：`LoaderCircle` 加 `animate-spin`，宽度不跳——有前置图标就替掉图标（同一尺寸类）；没图标就字留着占位、看不见，转圈盖在正中；传 `loadingText` 就是「转圈 + 那几个字」，两份字叠在同一格，按钮宽取宽的那份。颜色不另起：底色、字色照按钮的 variant，鼠标是 `cursor-progress`。`asChild` 不支持 `loading`（类型上二选一）。
- **确认框的确定键**：传 `onConfirm={async () => …}`，不再写 `onClick={(e) => { e.preventDefault(); confirm(); }}`。等的时候确定键转圈、别的键标 `aria-disabled`；Esc、「先不」都关不掉；成功才关；失败留在原处：页脚上面一行 `role="alert"` 的「没成功：<原因>」（`st-fail` 淡底、`ink-fail` 字），焦点送过去，确定键恢复能再点。`onConfirm` 里照旧自己弹成功、失败的 toast；失败要把错误抛出来，框才知道没成。只传 `onClick` 的老写法照旧点了就关（不发请求的确认）。
- **保存**：`SaveButton` 的 `pending` 就是忙态：转圈 + `aria-busy`，底色照旧是「不能存」的灰（#1904）。
- **任务那排按钮**（暂停、继续、叫停、重做）：`TaskActionsProvider` 记着哪张单的哪个操作在发，任务页、看板侧边详情的 `ActionButtons` 对应那颗转圈；暂停、叫停、重做在确认框里等。
- **检查 R12**（检查规则表里那一行）：`<Button>`、`<AlertDialogAction>` 的 `onClick`（顺着同一文件里的函数名最多追三层，含 `useCallback` 包的）调了 `mutate` / `mutateAsync`，或 `<form onSubmit>` 调了、它里面 `type="submit"` 的 `<Button>` 和 `<SaveButton>`，必须带 `loading=`、`onConfirm=`、`SaveButton` 的 `pending=`，或 `disabled=` / `aria-disabled=` 里写着 pending。用 `@babel/parser` 解析 JSX（本仓 TypeScript 是 7，没有进程内的编译器 API），解析不了的文件报出来。认不出跨文件的（处理函数从 props、context 传进来的），这类靠评审。
- **例外**：按钮开标签里或它上一行写一行注释 `loading-ok: <理由>`（`{/* loading-ok: … */}` 或 `// loading-ok: …`），理由不能空。第一期留下的四处 `loading-ok: TODO #2012` 和第二期其余只置灰的写请求按钮（加进驾驶舱、整理确认、移出用途、登记/撤掉模型串、提醒「处理」、发版预检、「全部立即探测」、清理工作树、暂停池）都已在 #2012 改成 `loading=` / `onConfirm=`；现在只有跨文件、R12 认不出且确实不要忙态的地方才写这条例外。

### 页头（`Page`，#1897）

- 标题行：标题在左（后面跟 ⓘ），操作和刷新在右，同一行垂直居中；刷新是标题行右侧的固定槽位（`refresh` 属性），页面不自己摆 `RefreshBar`。

### 画布（`/board`，原来的主页）的排版和机器资源（#1973）

- **按顶栏的当前项目**：只画这一仓的单，别的仓的卡片不画；这一仓没有在跑的单，整块换成「现在没有在跑的单」。右侧「要你拍的」「做完的」同一条界：别的仓的不列，不挂仓的整机决定照列，按钮上的件数跟着变。切项目后把新的卡片收进视野。机器两格和顶上的引擎健康不跟项目走。在这一页切项目不跳走。

### 任务页（`/tasks/:taskId`）的概览和过程（#3140）

## 六、对比度闸

`packages/web/src/lib/contrast.test.ts` 把 16 套主题逐套算一遍（WCAG 2.2 AA）：

- 状态墨色 `ink-{tone}` 在各种底和同色淡底上 ≥4.5:1；
- `muted-foreground` 在 background、card、popover、muted、panel 上 ≥4.5:1；
- `input` 对 card、`ring` 对 background ≥3:1；
- `destructive-foreground` 对 `destructive` ≥4.5:1。

每组都有一条故意造红的用例。校准值不手写：由生成脚本算（见下一节），测试读的是生成文件。

### 怎么加一套主题

主题只写种子，校准值由脚本算（学 Ant Design 的「种子 + 算法派生」，依据见 `specs/1844-驾驶舱设计规范/方案.md` 第十三节）。

1. 在 `packages/web/src/theme/palettes.ts` 的 `PALETTE_SEEDS` 里加两条（深、浅各一条）：`{ id, mode, seeds }`。`seeds` 只写 13 个 `#rrggbb` 基色：`bg`、`panel`、`surface`、`elev`、`fg`、`brand`，加七个状态色 `run`、`wait`、`human`、`stall`、`fail`、`done`、`stop`。这里不写任何百分比。
2. 在 `src/lib/theme.ts` 的 `PaletteId` 和 `PALETTES` 里登记 id、名字和一句话介绍。
3. 跑 `pnpm --dir packages/web gen:palettes`。脚本对每个校准量用二分法找「最少要混多少前景色」，在要求的所有底色上过线（文字 4.5:1，控件边框和聚焦圈 3:1），再多留 0.1 对比度的余量，写进 `src/theme/palettes.generated.css`。`--brand-foreground`、`--destructive-foreground` 在本套的页面底和主要文字色里取对比度高的。
4. 提交种子表和生成文件。不要手改生成文件：`src/theme/palettes.test.ts` 在内存里重新生成一遍，和提交的文件有一个字不同就红。
5. 脚本报「过不了线，换种子」，说明这套的前景色和底色本身对不上，改种子，不要去降门槛。

## 七、截图怎么交

改界面的 PR 带改前（主线）、改后两组截图。用 `packages/web/scripts/shots.ts`，它会起 `dev:mock`（假数据，不连后端）：

```
node packages/web/scripts/shots.ts before                      13 页 × 1920/1366/390 × 亮暗
node packages/web/scripts/shots.ts after --widths 1366 --pages home,tasks --modes light
```

图存到仓根 `_tmp/shots/<标签>/<页>-<宽>-<亮暗>.png`。
全局改动（令牌、`ui/`、外壳）要贴全部 13 页的改前改后图，至少 1366 宽亮暗各一张。
不做像素对比闸：迁移期每片本来就要变样子。

### 截图怎么挂进 PR

图不进代码分支（会把二进制带进主线历史），推到远端 `shots/<单号>` 分支，PR 正文引用它的 raw 链接。分支只放图片，用不带父提交的孤儿提交。在仓根（代码分支的工作树里）照抄，`<标签>`、`<单号>` 换成实际的：

```
cd _tmp/shots/<标签>
export GIT_INDEX_FILE=$PWD/../<标签>.idx          # 临时暂存区，不动代码分支的暂存区
git --work-tree=. add -f .                          # _tmp 被忽略，要 -f；图在分支根目录
c=$(git commit-tree "$(git write-tree)" -m "截图 #<单号>")
unset GIT_INDEX_FILE && rm -f ../<标签>.idx
cd ../../..
git push origin $c:refs/heads/shots/<单号>
```

- 同一单要补图再推：把这单要的图全放进目录重做一遍，推送加 `--force`（孤儿提交没有父提交，不加会被拒；分支上只有图片，覆盖不丢别的东西）。
- PR 正文用 `![说明](https://raw.githubusercontent.com/thoerwink8/fleet-dao/shots/<单号>/<文件名>)`。
- 分支留着：删了 PR 里的图就裂。
- 引擎收树前会核对（#2983，`packages/engine/src/real/shots.ts`）：只看 `_tmp/shots/<标签>/` 下一层的 PNG/JPEG/WebP（看文件头）和树里没推的孤儿图片提交，链接、子目录、别的文件拒收不碰；单棵树最多 200 张、单张 10 MiB、合计 100 MiB。远端 `shots/<单号>` 上按 blob 号全读到才算交付；读不到就存进引擎的受限归档 `<状态目录>/archive/<任务>/shots/<代码头>/`（图按 sha256 起名，`manifest.json` 记代码头、清单、hash、结局；所有任务合计 2 GiB、留 30 天），存不成就不删树。别的删树路（每小时对账的工作树清扫和一键清理、建树前删同一位置的旧树、没带代码头的收树）走同一道 `keepShotsBeforeRemove`：清扫不看远端，同一个头记过已交付才认，否则有图就存进归档，存不成不删、记没查成写明原因、下一轮再试；建树撞上存不成的旧树停下报 `SHOTS_KEPT`。合并后 PR 说明的「还欠什么」写明待交付或失败，不写「无」。引擎不替你推图片分支：存进归档的图仍要人或下一张单补推。
- 这种只含图片（png、jpg、jpeg、webp、gif）的推送，pre-push 钩子认出后跳过格式和类型检查（卫生检查照跑），不用 `--no-verify`。钩子看的是这次推上去的提交改了什么，不是当前检出的代码分支，所以推截图时代码分支没写完也不受影响；混进一个非图片文件就照常全查。只删远端分支（这次的 ref 行非空、本地 sha 全是 0）同样跳过这两样：没有新内容可查。和推新内容混在同一次里时，删的那几行不算，仍按推上去的内容判。
