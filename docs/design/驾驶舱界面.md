# 驾驶舱界面规范

母单 #1844，方案 `specs/1844-驾驶舱设计规范/方案.md`。这份是定稿：改驾驶舱界面（`packages/web`）先读它。
令牌在 `packages/web/src/app.css`，检查是 `packages/web/scripts/lint-design.ts`，由 `src/test/lint-design.test.ts` 守着（CI 必过）。
令牌改了，同一个 PR 改这份文档。

## 一、视觉基调

照字节 Arco Design / Arco Pro 的 B 端控制台（#3509）。样子拿不准的，一律照 Arco 的做法（创始人 10-22「字节是怎么做的，我们就怎么做吧」）。设计稿是本机临时资料，不随仓提供；仓内令牌以 `packages/web/src/app.css` 为准，页面实现见 `packages/web/src/routes/`。

1. **主题只有一套**，分亮、暗两种，暗色跟随系统（`prefers-color-scheme`），没有切换开关。主色只有 `#165DFF`，密度也只有一套。为什么：一件事只有一种样子，页面只验亮暗两种。
2. **根字号不放大**：按 Arco 原样，1rem = 16px，浏览器 100% 下正文 14px、顶栏 60、左菜单 220，手机桌面一样。理由：创始人 10-22 拍「字节怎么做我们就怎么做」。
3. **做减法**：一件事只写一处、一行一个状态、低频操作收进「更多」。
4. **颜色只给异常**：带底色的标签只有灰、橙、红三种；分类标签只用灰；指标卡不带图标。正常、计数、分类不上色。
5. **蓝字只用 `text-brand-ink`**：`brand`、`success`、`warn`、`fail` 只给填充（底、边、圆点、进度条），字色一律用对应的 `*-ink`。
6. **卡片没有阴影**：浅灰页面底（`page`）上放白卡片（`card`）分层；阴影只给浮起的东西（下拉、气泡、对话框、抽屉）。
7. 数字用无衬线加等宽数字（tabular-nums）。只有编号、提交号、路由号、模型 id、代码用 `font-mono`。
8. 样式由机器守：类名只用下面的令牌（lint-design），颜色和对比度由 `src/theme/contrast.test.ts` 算，动效档位由 `src/theme/motion.test.ts` 核。

## 二、令牌

| 层 | 是什么 | 谁能用 |
|---|---|---|
| 色值 | 两块令牌：亮色写在 `:root`，暗色写在 `@media (prefers-color-scheme: dark)` 里的 `:root`，具体值以 `packages/web/src/app.css` 的对应令牌为准。阴影、遮罩的 rgba 也在这两块里 | 只有 `app.css` |
| 语义令牌 | 本节下面的颜色、字号、圆角、阴影、动效、组件令牌（`app.css` 第一个 `@theme`） | 页面和组件 |
| 版式常量 | 某一页要的专用尺寸（`app.css` 第二个 `@theme`「版式常量」，如 `h-topbar` 60、`w-sidebar` 220、`max-w-cockpit`、只给任务页用的 `max-w-task-table`、只给提需求页用的 `max-w-chat`） | 只在写明的那一页用 |

- `@theme` 里有 `--color-*: initial`：Tailwind 默认色板（`red-500`、`white`、`black`……）整个不生成，写了也不生效。
- **两块令牌以外不许出现色值**（`#hex`、`rgb()`、`hsl()`），也不许把填充色当字色（`color: var(--brand|--success|--warn|--fail)`，图标例外）；都由 `src/theme/contrast.test.ts` 守。
- 暗色跟随系统：`:root` 写 `color-scheme: light dark`，`dark:` 变体是 `@custom-variant dark (@media (prefers-color-scheme: dark))`。

### 2.2 字号

**根字号不放大：按 Arco 原样，1rem = 16px。** 理由：创始人 10-22 拍「字节怎么做我们就怎么做」。手机桌面同一套字号；JS 里按像素算的尺寸（窗口化列表的定高行和窗口高、画布节点、任务页过程面板宽）直接用设计值。尺寸照旧写 rem（用户在浏览器调大默认字号时整站一起变），写 px 的只有边框、聚焦圈、竖线（1–3px）。

字号五档加等宽一档，手机桌面一样（Arco）：

| 类名 | 字号 / 行高（px） | 字重 | 用途 |
|---|---|---|---|
| `text-meta` | 12 / 20 | 400，可 500 | 时间戳、表头、计数、标签里的字、辅助说明（中文最小 12） |
| `text-body` | 14 / 22 | 400，可 500 | 默认：列表行、表格、正文、按钮、输入、菜单 |
| `text-heading` | 16 / 24 | 500 | 卡片、抽屉、对话框标题 |
| `text-title` | 20 / 28 | 600 | 页面标题；一页最多一处的主标题块（原来的 `text-subtitle` 并进来了） |
| `text-display` | 24 / 32 | 600 | 只给指标数字（配 tabular-nums） |
| `text-mono` | 13 / 20 | 400 | 等宽的编号、提交号、代码 |
| `text-canvas` | 11 / 14 | 400 / 500 | 画布（`/board`）已删（#3533），令牌留着，新代码不用 |

行高、字重绑在字号上，不另写 `leading-数字`。字重只用 `font-normal`、`font-medium`、`font-semibold`。
字体：正文 Inter（`@fontsource-variable/inter`）加苹方 / 思源黑体 / 微软雅黑，等宽 JetBrains Mono（`@fontsource-variable/jetbrains-mono`）。
旧名 `text-micro`、`caption`、`sub`、`label`、`strong`、`stat-num`、`stat`、`subtitle` 都已从 `app.css` 删除。

### 2.3 间距

内外边距、`gap`、`space` 只用这些档：`0`、`px`、`0.5`、`1`、`1.5`、`2`、`2.5`、`3`、`4`、`5`、`6`、`8`、`10`、`12`、`16`。
宽高（`h-*`、`w-*`、`size-*`）不限档，但不许写任意值。

### 2.4 圆角

| 类名 | 值 | 用途 |
|---|---|---|
| `rounded-sm` | 2px | 按钮、输入、下拉、标签（`StatusBadge`、`Tag`）、菜单项、格子 |
| `rounded-md` | 4px | 卡片、浮层、对话框 |
| `rounded-lg` | 8px | 少用 |
| `rounded-full` | — | 圆点、头像、计数角标（不画文字标签） |

### 2.5 阴影

卡片没有阴影，靠浅灰页面底上的白卡片分层。阴影只有两种，值在令牌块里（`--pop`、`--pop-side`）：

| 类名 | 用途 |
|---|---|
| `shadow-pop` | 下拉、气泡、菜单、对话框 |
| `shadow-pop-side` | 抽屉 |
| `shadow-row-selected`、`shadow-brand-ring`、`shadow-done-pop` | 特效：选中行竖线、额度热、完成一闪 |

旧名是别名：`shadow-card`、`shadow-xs` → 无阴影；`shadow-overlay`、`shadow-modal` → `shadow-pop`。

### 2.6 动效

照 Arco：时长三档 `duration-100`（悬停变色）、`duration-200`（展开收起、浮层）、`duration-300`（抽屉进出、进度条）；缓动只有一条 `ease-arco` = `cubic-bezier(0.34, 0.69, 0.1, 1)`（旧名 `ease-out`、`ease-in-out` 指到同一条）。不写时长的 `transition-colors` 默认 100、`ease-arco`。
`motion/react` 里的过渡从 `src/theme/motion.ts` 取数，不在组件里另写；`app.css` 写的是同一组数，`src/theme/motion.test.ts` 核两边一致。
系统设置或设置页打开「减少动效」时，全部停下（时长归零、在跑的呼吸和扫光停，状态照样切）。

### 2.7 组件令牌

只有一套，用 Arco 的数值。值写 rem，表里是像素（1rem = 16px）。

| 类名 | 是什么 | 值 | 用在 |
|---|---|---|---|
| `h-control`（`size-control`、`min-h-control`） | 控件高（默认档） | 32 | 按钮、输入、下拉、开关组、筛选标签；另有 24 / 28 / 36（xs / sm / 大）三档写在组件里 |
| `h-row`（`min-h-row`、`size-row`） | 行高 | 40 | 列表行、菜单项、大号按钮 |
| `min-h-row-tall` | 两行的行高（名字一行加一行小字） | 48 | `RowFrame tall`（路由页的模型行、路由行，#1914）、`ListRow tall`（任务列表，#1919） |
| `p-section`（`px-`、`py-`、`mb-`） | 卡片内边距 | 20 | 卡片的页头和正文、空状态、展开明细 |
| `gap-section-gap` | 区块间距 | 16 | 页头和内容之间、卡片之间 |
| `gap-stack`（`py-stack`、`px-stack`） | 区块内间距 | 12 | 页头、卡片页头、行内元素之间、横幅左右 |

- 只许 `components/layout/`、`components/ui/` 用（lint-design R10）。页面要尺寸就用版式组件，不自己写这六个类。
- 标签、图标、徽标、小号按钮 `xs` 不起令牌：小号按钮最矮 24px，是可点区的下限。手机上可点区至少 40（#1820）。
- 两个比例：列表行上下内边距 = (`h-row` − 一行正文 22px) / 2，键值行 = `h-row` / 5，筛选标签和 `sm` 号控件比 `h-control` 少 4px。都写成 `calc(var(--spacing-…) …)`，只在 layout、ui 里。

## 三、版式组件

方案 B（#3509）：底下留 Radix（`components/ui/`，只给组件层用），上面自建业务组件层 `packages/web/src/components/layout/`，参数名照 antd。外壳（顶栏、左菜单、底部导航）在 `components/shell/`。

**页面只拼组件**：

1. 页面（`routes/`）和业务组件（`components/` 下除了 `layout/`、`ui/`、`shell/`）不写样式。`className` 只许位置类（`min-w-0`、`flex-1`、`shrink-0`、`col-span-*`、`sr-only`、`hidden`、对齐和截断这类），颜色、字号、边框、圆角、阴影、内外边距、间距一律交给组件（R13）。排版用 `Stack`、`Grid`，字用 `Text`。
2. 不 import `components/ui/*`、`radix-ui`、`motion`（R14），不写 `style={{}}`（R15），不用原生 `button`、`table`、`h1`–`h4`、`dl`、`progress`、`hr`（R17）。
3. 新件（`Stack`、`Grid`、`Text`、`Table`、`Progress`、`Steps`、`Descriptions`、`ProbeCells`、`Timeline`、`PickList`、`Anchor`、`Collapse`、`Form`/`FormItem`、`ConfirmDialog`、`Drawer`、`InfoTip`、`AuthCard`、`Chat`/`Message`/`Composer`）不收 `className` 和 `style`。旧件（`Section`、`List`、`KeyValue` 等）迁移期还收 `className`，迁完一页收一页。
4. 状态只走状态字典（`src/theme/status-dict.ts`，9 个域）：`<StatusBadge status="task:running" />`，中文和颜色等级都从字典取，页面不传 `tone`、`label`（R20）。后端来的原始值先过 `toStatus(domain, raw)`，认不出返回 `unknown`、写原值在悬停里，不猜。旧的 `tone`/`label` 写法标了 `@deprecated`，只给没迁的老页面。
5. 读 query 的数据不写默认值（`data ?? []`、`?? 0`），用 `LoadState` 那一族（`LoadingRows`、`LoadError`、`LoadStale`、`LoadPartial`，空用 `EmptyState`）或 `Read<T>`（`lib/read.ts`）把「在读、没读成、旧了、缺一块、空」五种分开画（R19）。
6. 最多两层容器（页面底上一层 `Section` 卡片，卡片里是行和格子），展开区不再套框（R18）。一个文件一个主按钮，列表行里不放主按钮（R20）。

状态类组件渲染 `data-tone` / `data-level` / `data-status`；单测断言这些属性，不断言类名。所有件逐个摆在陈列页 `/_design` 里标题叫「组件」的那块（`routes/design-components.tsx`），有出错、空、缺一块的样子。

| 组件 | 是什么 |
|---|---|
| `Page` | 页头：面包屑、标题左、操作右，刷新在固定槽位（见下面「页头」）；内容区边距上 16、左右 20、下 32 |
| `Section`、`SectionGrid` | Arco Card：白底、4 圆角、无阴影无描边，内边距 20 |
| `Button` | 按钮（页面唯一能拿按钮的地方，包 `ui/button`，#3509 工作台补上）：`variant` primary/secondary/outline/text/danger、`size` xs/sm/md；`href` 是链接（`external` 开新窗口）；`disabledReason` 置灰并在悬停写原因；写请求传 `loading` |
| `Stack`、`Grid` | 竖排、横排的间距（`sm`/`md`/`lg`/`xl`），栅格列数和 `main`/`split` 两种主次栏 |
| `Text` | 字：`size`（meta/body/heading）、`tone`（default/secondary/muted/warning/danger）、`strong`、`mono`、`truncate` |
| `Table` | 表格：`columns`、`rows`、`rowKey`、`expandable`、`selectedKey`、`onRowClick`；`load` 传出错时整张换成红条加「重试」，读失败不画成空表 |
| `List`、`ListRow`、`RowFrame`、`RowDetail` | 列表行（40 高，两行 48），悬停 `fill-1`、选中 `brand-1` 底；拖动排序的列表自己管 `li` 时用 `RowFrame`；行尾放按钮的行传 `wrapTrailing`（手机上行尾落到文字下面、标题换行） |
| `KeyValue`、`Descriptions` | 键值对（Arco Descriptions） |
| `Stat`、`StatGrid` | 指标：标签加数字（可带单位），不带图标；一行、指标之间一道竖线 |
| `StatusBadge`、`LevelDot` | 状态：正常、进行中、常态画圆点加字；warning、error 画橙、红底标签；表格里 `variant="dot"` |

### 行：一个主信息、一个状态，次要操作收进「⋯」（#1914，路由页样板）

参照 macOS 系统设置、Linear 列表行、Vercel 设置页：每行只有一个主信息和一个状态，层级靠字重和灰度，不靠边框和色块。

- 一行从左到右：（拖动柄）序号或状态点、名字加一行灰字小字、一个状态、开关、行尾「⋯」。别的都不进行里。
- 状态只放一个：有状态色的用 `StatusBadge`（行里挤的时候 `variant="dot"`，点加字、没有底），没有状态色的用 `Tag`。
- 偶尔才动的操作（挪位置、档位、移出……）收进 `RowMenu`。鼠标设备上「⋯」平时在原位极淡（`opacity-40`，右边不空一块），拖动柄平时整个藏着；悬停这一行、键盘焦点进到这一行、菜单开着时变实；触屏一直实着。菜单项手机上至少 40 高。键盘快捷键（Alt+方向键挪位置）照旧挂在拖动柄上，写在柄的悬停提示和页头 ⓘ 里。额度页每个池那一行的停用开关留在行里，不收进「⋯」。额度页每个渠道的组头右边放整渠道的「全部暂停 / 全部放开」（混合状态是「暂停其余 / 放开已停」，#2900）：`xs` 描边按钮，点开后在组头下面展开和池开关同款的原因表单（先预览会动哪几个池），一次只开一张表单。
- 行用 `RowFrame`（或 `ListRow`）：行高、内边距取 `h-row`（两行的行用 `tall`，取 `row-tall`：48）、`p-section`，带 `group/row` 给悬停露出用；拖动柄浮在行左边的留白里，不占一列。
- 行下面展开的明细、表单、提示用 `RowDetail`：左边按 `p-section` 加 `--spacing-row-indent`（3rem：展开箭头加序号的宽）缩进，和行里的名字对齐。行首没有箭头、序号，名字就贴着行的左内边距时（资源页的仓库行，#1917）传 `indent={false}`，只留 `px-section`。
- 行和行之间只有一根 `line` 细线，不画框；悬停 `fill-1`、选中只换 `brand-1` 底（不再画左边竖线）。关着、被跳过的行只把名字那块降对比度（`opacity-60`），不整行换灰底。
- 同一件事一行里只写一遍：状态已经写了的（「池暂停」），不再另贴小标签；长的附注（「满了，等空位，不算故障」）收成一个小图标，话在悬停和读屏里。
- 一页最该看的那一句（路由页：这个用途现在实际派给谁）做成区块上面的标题块：名字单独一行 `text-title`，下面隔 12 是结论短话 `text-heading font-normal` 加结论的 `StatusBadge`，再下面一行 `text-meta` 灰字细节；标题块和下面的区块隔 24。结论只写短话（「首选 Opus 5.5」「实际派 GPT 5.6 luna」），走哪条路、为什么不是首选放灰字行，整句在悬停里。
- **一行不折**（创始人 2026-10-11 看 390 宽「变成 2 行了」，#1914 第 5 轮）：标题块三行、行的小字、卡头说明、筛选条，在 320 到 1568 任何宽度都只占一行。行里的名字（模型名、路由名）是认东西的那一样，不截断：真长到放不下宁可换行。做法：容器 `whitespace-nowrap`，会变长的那段 `min-w-0 truncate` 并把整句放 `title`，状态标签、开关这类不让位的 `shrink-0`；手机上放不下的说明换短说法（`md:hidden` / `max-md:hidden` 两份），不靠换行。只有成段的说明文字（表单说明、原因分组的标题）可以折。e2e `11-mobile-overflow` 量标题块三行的高度。
- 同一类的几组次级筛选用 `FilterTabGroups`：组间一道细竖线，后一组前面写组头小标题；只读的说明项（「对题」）用 `FilterTabNote`，说明在悬停里，不另占一行。任何宽度都是一行，lg 以下放不下就整排横向滑动，不折成第二行。
- 一个配置项按「模型 × 路由」配的（思考档位），配在路由上：路由展开后的明细里就地改，配过的在行的小字里写一句；要横着比所有路的，放同一页的一个页签（路由页「思考档位」），不另开一页（#1914 第 5 轮并进路由页）。
- 定高的两行行（模型目录、渠道这种按行高开窗只画看得见几行的长列表，思考档位页签的路由行）例外：名字也截断、整名放 `title`，因为行高是算死的，换行会压住下一行（#1916）。第一行＝名字加一个状态（`data-row-name-line`），第二行＝灰字小字（`data-row-meta`），各占一行；e2e `11-mobile-overflow` 在 320、390 量这两行。
- 同一模型有几条路分不出来时（两条 Claude 订阅），小字直接写「渠道 · 池号 · 跑在哪」，池号看得见，不只放悬停（#1916）。
- 路由行在手机上状态只画点，字放悬停和读屏，不让状态标签把名字挤成两行；「顺位第一条活的」这类标签放小字行的开头，不放末尾（末尾会被截掉）。
- 模型名字旁有强弱档的画一个 `Tag`（强档用 `brand`、标准档和快档 `neutral`，`components/model-strength-badge.tsx`），用途页的模型先后和模型目录两处同一个；没标档位的不画。档位只读目录（`models.strength`），驾驶舱不改（#2691）。用途页「动手战绩」表里的「派工档」（主力 / 中档 / 快档，单子的难易）是另一回事，表头写全称，不和强弱档混。
- 用途页、模型目录、渠道页默认只列开着的路由（`routing_catalog.enabled`）。关着的、渠道页里没配进用途的，点「显示全部」才出来；只显示一部分时不能调先后。用途里的模型先后不因这个开关改。已关模型点开展开后，里面的路由照旧都列出来。
- 长列表的筛选条分两层：上层搜索框加右边的计数，下层是开关和下拉，窄屏整排横滑；「清除筛选」只在筛着的时候出现。

### StatusBadge 与 Tag 的分工（#1910、#3509）

- `StatusBadge`：状态（在跑、卡住、失败、已完成、已关……），从状态字典取字和等级。正常、进行中、常态画圆点加字；只有 warning、error 画橙、红底标签。意思靠字传，颜色只是辅助。
- `Tag`：分类、来源、套餐、提交号这类非状态的，只有灰（default）、橙（warning）、红（error）三种底；分类一律灰。旧的 `tone` 里 `stall`、`doubt` 落到橙，`fail` 落到红，其余（含 `brand`、`run`、`done`）都回灰。
- 带底色的标签外形同一套：`components/layout/tone.ts` 的 `badgeShape`（`h-6`、`px-2`、`text-meta font-medium`、`rounded-sm`），`Tag` 和 `StatusBadge` 的橙、红标签都用它，改一处两边一起变。不再有全圆胶囊文字标签；页里不手写 `rounded-full` 加字的小块。
- 一屏里圆角就两档：按钮、输入、标签和状态 `rounded-sm`（2px）；卡片、浮层 `rounded-md`（4px）。

### 筛选条和保存钮（#1904）

- 筛选一律用 `FilterTabs`：同一页的主筛选用默认（Arco 下划线页签，计数是小圆角块），同一页再有一组次级筛选用 `variant="secondary"`（选中是 `fill-2` 底加 `brand-ink` 字），两组不用同一个样子。
- 窄屏横向滑动，还有内容没滑出来的那一端渐隐；页签模式支持左右方向键、Home、End，`idPrefix` 给页签起 id。
- 分组说明（「不是流程里的一段」这类）写在组头上，不当选项放进筛选条。
- 保存按钮用 `SaveButton`：能存是 `brand` 实色，不能存（没改动、正在存）是灰底灰字的禁用样子。
- 状态字（在跑、关着、开着、已关）经 `StatusBadge`（字典键），非状态的标签才用 `Tag`；lint-design R11 拦裸文字。
- 通知卡正文默认两行，点一下展开；主操作带字，手机上也不退成无字图标。

### 会发写请求的按钮（#2009）

创始人 2026-10-13「现在驾驶舱缺少确定按钮 loading，所有页面都判断下」：点了「确认发布」「叫停」这类按钮看不出点没点上、还能连点。做法照 Primer 按钮无障碍规范（加载中不用原生 `disabled`、配 aria-live 播报、失败把焦点送到错误）和 TanStack Query（`isPending` 驱动界面）。

- **普通按钮**：`<Button loading={m.isPending} onClick={() => m.mutate(…)}>`。忙时 `aria-busy` + `aria-disabled`（不用原生 `disabled`，键盘焦点留得住），点击被拦，同一帧里的第二下由按钮里的 ref 再挡一道（状态还没提交到 DOM 时只靠 `loading` 挡不住）；`onClick` 返回 Promise 时，落地前也挡。传了 `loading`（哪怕是 `false`）按钮旁边就始终有一个 `aria-live="polite"` 的隐藏播报区，忙时读「正在<按钮上的字>…」，`loadingLabel` 改这句。不写 `role="status"`：页面自己的结果提示才是那个 status。
- **转圈**：`LoaderCircle` 加 `animate-spin`，宽度不跳——有前置图标就替掉图标（同一尺寸类）；没图标就字留着占位、看不见，转圈盖在正中；传 `loadingText` 就是「转圈 + 那几个字」，两份字叠在同一格，按钮宽取宽的那份。颜色不另起：底色、字色照按钮的 variant，鼠标是 `cursor-progress`。`asChild` 不支持 `loading`（类型上二选一）。
- **确认框的确定键**：传 `onConfirm={async () => …}`，不再写 `onClick={(e) => { e.preventDefault(); confirm(); }}`。等的时候确定键转圈、别的键标 `aria-disabled`；Esc、「先不」都关不掉；成功才关；失败留在原处：页脚上面一行 `role="alert"` 的「没成功：<原因>」（`st-fail` 淡底、`ink-fail` 字），焦点送过去，确定键恢复能再点。`onConfirm` 里照旧自己弹成功、失败的 toast；失败要把错误抛出来，框才知道没成。只传 `onClick` 的老写法照旧点了就关（不发请求的确认）。
- **保存**：`SaveButton` 的 `pending` 就是忙态：转圈 + `aria-busy`，底色照旧是「不能存」的灰（#1904）。
- **任务那排按钮**（暂停、继续、叫停、重做）：`TaskActionsProvider` 记着哪张单的哪个操作在发，任务页、看板侧边详情的 `ActionButtons` 对应那颗转圈；暂停、叫停、重做在确认框里等。
- **检查 R12**（检查规则表里那一行）：`<Button>`、`<AlertDialogAction>` 的 `onClick`（顺着同一文件里的函数名最多追三层，含 `useCallback` 包的）调了 `mutate` / `mutateAsync`，或 `<form onSubmit>` 调了、它里面 `type="submit"` 的 `<Button>` 和 `<SaveButton>`，必须带 `loading=`、`onConfirm=`、`SaveButton` 的 `pending=`，或 `disabled=` / `aria-disabled=` 里写着 pending。用 `@babel/parser` 解析 JSX（本仓 TypeScript 是 7，没有进程内的编译器 API），解析不了的文件报出来。认不出跨文件的（处理函数从 props、context 传进来的），这类靠评审。
- **例外**：按钮开标签里或它上一行写一行注释 `loading-ok: <理由>`（`{/* loading-ok: … */}` 或 `// loading-ok: …`），理由不能空。第一期留下的四处 `loading-ok: TODO #2012` 和第二期其余只置灰的写请求按钮（加进驾驶舱、整理确认、移出用途、登记/撤掉模型串、提醒「处理」、发版预检、「全部立即探测」、清理工作树、暂停池）都已在 #2012 改成 `loading=` / `onConfirm=`；现在只有跨文件、R12 认不出且确实不要忙态的地方才写这条例外。

### 页头（`Page`，#1897）

- 标题行：标题在左（后面跟 ⓘ），操作和刷新在右，同一行垂直居中；刷新是标题行右侧的固定槽位（`refresh` 属性），页面不自己摆 `RefreshBar`。
- 说明（`description`）最多一行，写在标题行下面；字符串超过 50 个字自动收进 ⓘ。长说明用 `detail` 传，任何宽度都在 ⓘ 里。手机上说明也收进 ⓘ，`keepDescription` 才例外（任务页的状态行这种关键信息）。
- 一页只有一个说明位：说明写这页管什么，不写「怎么用」「点这里」这种占位。
- 所有页同一最大宽（`max-w-cockpit`），页面不自己限宽、不再有窄栏。
- 手机上刷新是不带框的图标按钮（`ghost`），比标题弱；桌面是带字的描边按钮。
- 页头右边已经放了一句汇总的页（主页、路由页）刷新用 `refresh.variant = 'dot'`：只一个图标钮，最后更新时间在悬停和读屏里，数据旧了才写「数据有点旧 / 数据已过期」。
- 页头右边的汇总只写一句（「4 个派得出去 · 1 个不知道」），不排一串状态胶囊；坏的、不知道的数是 0 就不写，不画红。

### 工作台（原「主页三块」，`/`，决定 0093；#3509 样板页）

- **过程**（`components/task-process.tsx`）：**回合 → 笔 → 步骤 → 调用**，样子照设计稿（#3228）。块头说明写「N 个回合 · M 笔 · 用时 X」。顶上一条时间条，每一笔一段、宽度按用时比例，失败红、在跑蓝、其余灰；下面一行起止（最早一笔起跑，到最后收场或「现在 时:分」）；点一段展开那一笔所在的回合再滚过去。回合头一行可点收起：第几回合、返工、起止 · 用时 · 几笔 · 档位 · PR 新增行数，结局放右边，词在状态字典 `task:round:*`（做成了、验收没过、CI 红了、超时、进行中、结局没记……，引擎多出来的新收场名不在字典里，原样写成橙标签、不猜）；前面收场了的回合默认收起，最后一回合和有笔在跑的展开，人点过就听人的。返工回合头下面一个淡红框「为什么返工」（上一回合的结局加它记的返工意见）；还没收场的写「进行中」；进行中的单最后一回合末尾一行「接下来 自测 → … → 合并」（这一回合还没走的几步；返工、下一回合还没开跑的写「第 N 回合：动手 → … → 合并」）；笔上没记回合号的（旧引擎跑的，#3190）按回合收场时刻归：第 N 回合管上一回合收场之后到它收场为止（记了开始时刻的从开始时刻算），落在所有已收场回合之后的归还没收场的那个，回合头写「其中 N 笔是旧引擎跑的、没记回合号，按回合收场时刻归进来」；哪个回合都归不进的（库里没有回合记录的老单）单列「更早的几笔」并写明不猜；对题不进回合，单列「回合之前」。笔一行（#3533 照 Arco 只拼 `layout/disclosure.tsx` 的展开行，开合由页面管；行首不再画图标，结局一处写在第二行）：第一行「第 N 笔 · 段 · 为什么起」（第几笔按整张单起跑先后一起数，三段不分开），**为什么起**（出方案 / 主写 / 补提交 / 自测红了再改 / 各种返工 / 原路重试 / 换路由重派 / 切号重跑 / 暂停后继续 / 现在就换模型 / 人点了继续；动手的老记录没记写「老记录没记起因」；对题和验收本来不记），后面灰字**新会话还是接上一笔的会话**（没记就不写）；第二行模型 · 起止（时:分）· 用时 · 结局（`StatusBadge` 点加字，词在状态字典 `task:segment:*`：完成、超时、被停掉……，在跑、结局没读到另有词；颜色只给异常）；再下面起因摘要、小计（命令、失败、在跑、结果未知、改几次 +/-）。右边展开箭头和「看会话」。验收那一笔写结论（过没过、没过的问题、转给人的）。笔之间引擎在会话外连着做的几件事（建工作树、自测、推分支、开 PR、等 CI、验收、挂自动合并、等合并）串成一行浅底「引擎 自测 → 推分支 → 开 PR → 等 CI 没成」，右边是加起来的用时，每件的起始时刻和用时在悬停里；没成的红字；连着的同一种等待折成「等内存 N 次，共 X」放进这串里，等的是下一回合的笔就归下一回合。步骤行：行首状态图标、标题（Agent 那句话；先调工具的是「动词 对象」；有失败的红字）、右边展开箭头；第二行起止时刻（时:分:秒）、用时、小计，在跑的这行蓝字；有失败的和在跑的自动展开，人点过一次就听人的；展开一笔才去读它的步骤（`GET /tasks/:taskId/runs/:runId/steps`，后端从 `run_transcript` 的轻量行现算，切法在 shared 的 `task-process.ts`），展开一步才读那一步的序号区间（`useStepCalls`）。单个调用一行：灰色动词（已运行 / 已读取 / 已编辑 / 创建 / 已搜索，失败是「运行失败」红字）加对象，改文件带 +/-，点开是工具回的结果；没有退出码的命令（Mirasim）写「结果未知」，不写成功也不写失败。

### 截图怎么挂进 PR

图不进代码分支（会把二进制带进主线历史），推到远端 `shots/<单号>` 分支，PR 正文引用它的 raw 链接。分支只放图片，用不带父提交的孤儿提交。在仓根（代码分支的工作树里）照抄，`<标签>`、`<单号>` 换成实际的：

```
cd _tmp/shots/<标签>
export GIT_INDEX_FILE=$PWD/../<标签>.idx          # 临时暂存区，不动代码分支的暂存区
git --work-tree=. add -f .                          # _tmp 被忽略，要 -f；图在分支根目录
c=$(git commit-tree "$(git write-tree)" -m "截图 #<单号>")
unset GIT_INDEX_FILE && rm -f ../<标签>.idx
cd ../../..
git push origin $c:refs/heads/shots/<单号>
```

- 同一单要补图再推：把这单要的图全放进目录重做一遍，推送加 `--force`（孤儿提交没有父提交，不加会被拒；分支上只有图片，覆盖不丢别的东西）。

- 引擎收树前会核对（#2983，`packages/engine/src/real/shots.ts`）：只看 `_tmp/shots/<标签>/` 下一层的 PNG/JPEG/WebP（看文件头）和树里没推的孤儿图片提交，链接、子目录、别的文件拒收不碰；单棵树最多 200 张、单张 10 MiB、合计 100 MiB。远端 `shots/<单号>` 上按 blob 号全读到才算交付；读不到就存进引擎的受限归档 `<状态目录>/archive/<任务>/shots/<代码头>/`（图按 sha256 起名，`manifest.json` 记代码头、清单、hash、结局；所有任务合计 2 GiB、留 30 天），存不成就不删树。别的删树路（每小时对账的工作树清扫和一键清理、建树前删同一位置的旧树、没带代码头的收树）走同一道 `keepShotsBeforeRemove`：清扫不看远端，同一个头记过已交付才认，否则有图就存进归档，存不成不删、记没查成写明原因、下一轮再试；建树撞上存不成的旧树停下报 `SHOTS_KEPT`。合并后 PR 说明的「还欠什么」写明待交付或失败，不写「无」。引擎不替你推图片分支：存进归档的图仍要人或下一张单补推。
- 这种只含图片（png、jpg、jpeg、webp、gif）的推送，pre-push 钩子认出后跳过格式和类型检查（卫生检查照跑），不用 `--no-verify`。钩子看的是这次推上去的提交改了什么，不是当前检出的代码分支，所以推截图时代码分支没写完也不受影响；混进一个非图片文件就照常全查。只删远端分支（这次的 ref 行非空、本地 sha 全是 0）同样跳过这两样：没有新内容可查。和推新内容混在同一次里时，删的那几行不算，仍按推上去的内容判。
