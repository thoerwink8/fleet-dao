## 原话

```
2026-10-12 18:11，创始人在对话里

可以都按照你的推荐来，但是这样的话，怎么才能让其他仓库同步呢？也不是说一模一样的同步，至少我fleet-dao仓库多了新机制，也能享受到对吗
```

「你的推荐」是上一问的第 2 条：#1952 先合；下一张单再把流程钩子收成仓库插件，全局只留说话规矩。

## 决定

1. 机制的原件只在 fleet-dao。`pnpm agents:sync` 把钩子脚本装到这台的 `~/.fleet-dao/hooks/`。别的仓不拷 `agents/hooks/`，也不拷整份通用段。
2. fleet-dao 里有一份插件目录。过程组是开会话、主对话、收尾、落盘。目录里的命令指向 `~/.fleet-dao/hooks/` 里那份，不指向别的仓的 `agents/hooks/`（那条路径只有 fleet-dao 有）。
3. 别的仓要享受过程组，就在仓里放一个订阅标记，写上跟哪一组。没标记的仓不登记流程钩子。公司仓继续这样。
4. 用户级只加一个不长大的加载器：当前仓有订阅标记，就按目录重写这个仓的项目级流程钩子；没有标记就什么都不写。0083 删掉的是「每个仓都跑流程钩子」，不是这个加载器。引擎无头会话（`FLEET_HEADLESS=1`）加载器也不写。
5. 已订阅的仓，原件改了脚本：下次同步之后，钩子跑的就是新脚本，那个仓不用再提交。目录里新加一条钩子：下次在该仓开会话或跑同步，项目设置里会出现这一条。没订阅的不会出现。
6. 说话规矩（含 0084 的进度表）仍由同步写进各家全局说明，不靠订阅。这是第二条通道，和流程钩子分开。

## 没做的

- 合并并同步之前，这台用户级还没有加载器。只放 `.fleet-plugins.json` 还不会登记过程钩子。
- fleet-dao 自己的项目设置仍指向本仓 `agents/hooks/`。加载器把这条路径当成已经登记，不重复写一条。
- 桌面筛选脚本只负责放、取消标记，不自动给机器上的仓订阅。
