## 为什么回头

0026（2026-10-06 17:25）把无人值守改成「起脱离会话的工人、这一轮结束」。实际用下来：创始人说了进入无人值守，会话起完工人就收尾了，没人再盯工人、收他的引导、汇报进度，他看到的是「无人值守的会话轮次结束了」。0026 删挡收尾的理由是「收尾钩子把这一轮按住，下一轮不来，引导补账等死」；他现在要的就是这一轮不结束，那一层代价他接受。

## 决定

1. **只有这个会话自己跑了 `unattended.mjs on`（创始人说了「进入无人值守」「过夜」「我在睡觉」）才挡收尾。** 收尾钩子（`agents/hooks/stop.mjs`）对这个会话输出 `decision: block`，理由写具体：继续盯工人（`worker.mjs watch --wait 55`，法国的活用 `france.mjs`）；每次工人有进展（PR 开了、做完、卡住）就 `pnpm progress:note` 并给他一行汇报；没有新结果别空转、别重复上一句；怎么合法放行（`done` / `needs-you` / `off`）。没开的会话、别的机器、工人和反方（机器派的会话，`on` 直接拒）都不受影响。
2. **起子代理、监视、后台命令不自动开。**（0026 第 2 条保留。）`pretool.mjs` 只在已经开着时记一笔「这个会话调了工具」，不写新状态；旧版自动开留下的状态文件（`auto: true`）不认。
3. **工人那一层保留。** 活仍由脱离会话的工人（`worker.mjs start --detached`）干，每做完一件提交、推送、记进度、发他一次；会话负责盯着（`watch --wait 55`）、收他的引导、汇报。
4. **这些情况自动放行，防别的会话被永远挡住：**

   | 情况 | 怎么放行 |
   |---|---|
   | 创始人说停、退出无人值守 | `unattended.mjs off` |
   | 工人都收口、队列空了 / 要他拍板 | `done "做了什么"` / `needs-you "要他拍什么"` |
   | 开着满 12 小时（`--hours` 最多 12） | 过期，删状态，说一声 |
   | 还有工人在跑，被挡回去后连着 20 次没调工具 | 转暂停，写明原因 |
   | 所有工人都做完或掉线（pid 不在、已 clean），被挡回去后连着 3 次没调工具 | 转暂停（没有什么可盯的） |
   | 总共挡了 200 次 | 转暂停 |
   | 状态文件读不了、写不了、认不出 | 放行并明说是故障 |

   「没调工具」靠 PreToolUse 钩子每次调工具记一笔判；`watch --wait 55` 每圈都是一次工具调用，所以盯着工人不会被当成空转。
5. **单次前台等待不超过 60 秒保留**（`pretool.mjs`，不分无人值守与否）。

## 已知局限

- **创始人新发的消息会掐掉正在跑的工具调用**（Mirasim 客户端行为，本仓管不到）。挡住的会话被他打断后，这一轮可能落空，下一轮要靠开会话钩子（`founder-inbox.mjs`）补上他发了没收到的话；补账那一环在这一轮没结束时仍然等不到，这是 0026 当时指出的代价，这次接受。
- 「还有没有工人在跑」只看本机 `~/.fleet-dao/workers/*/meta.json` 的 pid；法国引擎的活不在里面，盯法国靠 `france.mjs`，钩子不知道。所以只在法国干活时，会话被挡的上限是「连着 3 次没调工具」或 12 小时。
- 真会话里挡不挡得住、被挡后模型怎么表现，只能在真会话里看；仓里测的是钩子的输入输出和状态文件。
