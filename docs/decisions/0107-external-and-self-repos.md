## 原话

```
一、两个名词（用名词，别写成「给别人看」这种动作）
- 对外仓：同事、领导、客户会读到的仓。第一个是公司的〔一个公司仓〕。
- 自用仓：只有创始人和 AI 读的仓，fleet-dao、他的私人仓都算。现有的「私人仓」标记并进自用仓，不再分三类，也不叫「公司仓 / 项目仓」。
- 仓以外写给别人看的东西叫「对外内容」：MR / PR 描述、单子评论、发给同事的文档和消息、对外页面。

二、对外仓和对外内容怎么写
- 写给读的人：只写项目本身的事；写结论（谁、哪天、定了什么、为什么），不贴原话；不写 AI 工具的事（额度、模型、代理怎么派、谁复核谁）和 AI 署名行；不写创始人个人的机器、账号、私人项目。

- 对外仓必须自己就完整：机器上没装 fleet-dao 时，AI 只读仓里的规矩也能把活干对；fleet-dao 只做加法，不往对外仓里加它的骨架、检查、标记文件。对应地，仓合同和 repo:init 对对外仓不提醒、不补。

五、顺带两件（只改 fleet-dao 自己）
1. CHANGELOG 两处写……只留一处：推荐每周收口时由 github-audit 自动生成这一版的一节……里程碑说明只链过去；清掉 [Unreleased] 里过时的条目。
```

## 定了什么

1. **两类仓、一类内容**：对外仓（同事、领导、客户会读到的，公司仓都是）、自用仓（只有创始人和 AI 读的：fleet-dao 和他的私人仓）；仓以外写给别人看的叫对外内容。不再有「项目仓 / 私人仓 / 公司仓」三分法。
2. **对外仓和对外内容怎么写**替换通用段「项目仓记什么」：只写项目本身的事、写结论不贴原话、不写 AI 工具的事和 AI 署名、不写创始人个人的机器账号私人项目；对外仓里照仓自己的规矩走，冲突以仓里为准。fleet-dao 只给四条底线：只为掏新钱、删了找不回这两件事停下问；凭证、密钥不进仓；没验证不说完成；生产只读（没得到明确许可不写生产库、不改生产配置）。
3. **仓是哪一种**（`agents/hooks/repo-kind.mjs`）：自用仓在仓根 AGENTS.md 有一行 `<!-- repo-kind: 自用仓 -->`（旧的 `<!-- repo-kind: 私人仓 -->` 照认），提交进仓、跟着仓走；fleet-dao 本身认两份文件，不靠标记；其余一律对外仓，不凭远端猜。没有私有登记、不写 `.git/config`、进仓不问。唯一的提醒：没标记、远端又全在创始人自己 GitHub 账号下的仓，开会话提醒一句「像是自用仓，要加标记吗」，每仓每天一次，他说加才加（`pnpm repo:init <仓路径> --self`，或手加那一行）。
4. **对外仓必须自己就完整**：仓合同（`agents/repo-contract.json`）只管自用仓——开会话不提醒、`repo:check` 说一句不管、`repo:init` 拒绝且一个字不写；`repo:init --self` 先打标记再补，补出的 AGENTS.md 模板自带标记。对外仓的 AI 署名兜底（0106 第 5 条）照旧，判法换成第 3 条。
5. **原话**：和对外仓项目有关的原话只进私有处（驾驶舱库为主，断网先存本机、联网补传），不进对外仓、对外内容，也不进公开仓 fleet-dao；fleet-dao 的引导文件里只写意思。fleet-dao 自己的、关于 AI 怎么干活的引导和决定照旧贴原话（不带公司项目的业务、人名、内网地址）。工具改造在 #3109。
6. **CHANGELOG 只留一处**（#3110）、**agents-sync 同步完核对各家读到的指令文件**（#3111）。

## 没采纳的

- 最终版第三节原先的做法：类型记在本机 `.git/config` 加一份按远端地址的跨机器私有登记、进仓先问一次。同日改定为标记跟着仓走：自用仓只有创始人和 AI 读，标记进仓不泄露什么；对外仓什么都不打，同事看不到，没装 fleet-dao 也不影响；也省掉每台机器登记、换机器补登记。
- 凭远端在谁的账号下自动判自用仓：一个仓可能有公司 GitLab 和个人 GitHub 两个远端，判错就是把公司仓当自用仓；只做提醒、不自动标。

## 读法

第 5 条「原话一律进私有处」按第四节的标题（「不进对外仓」）和它点名的范围（「和对外仓项目有关的」）读：只管和对外仓项目有关的原话；fleet-dao 自己关于 AI 怎么干活的原话不在此列。要是创始人的意思是 fleet-dao 里所有原话都不留，另立一条决定替代这一条。
