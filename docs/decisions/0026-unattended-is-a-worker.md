## 原话

```
按照你推荐，顺便吞掉我的引导是不是也是收尾这个原因？
```

上一轮推荐（他回的「按照你推荐」指的就是这一条）：普通对话该结束就结束；只有说了无人值守才起脱离进程的工人，一直干到完。收尾钩子只提醒，不挡。

## 决定

1. **收尾钩子不再 `decision: block`。** 不管有没有旧的无人值守状态、有没有后台活。仓根临时文件照旧只提醒。
2. **起子代理、监视、后台命令不再自动开无人值守。** `armForBackground` 不写状态。
3. **「进入无人值守」起 `worker.mjs start --detached "创始人说了进入无人值守"`，这一轮结束。** 工人做一件就提交、推送、记进度、通知一次，直到做完、要创始人拍、或他说停。不在聊天里循环 watch 把这一轮按住。
4. **`unattended.mjs on` 不再写状态。** 只打印去起工人。旧状态文件留着也不挡收尾，开会话不再塞「这一轮不要结束」。

## 引导为什么算同一条链

Mirasim 的「引导」先攒着，等这一轮下一次调模型才塞进 Claude。这一轮在那之前结束、被打断或进程挂了，界面仍显示「已引导」，Claude 没见过。下一轮开会话钩子用 `founder-inbox.mjs` 对账补上。收尾钩子把这一轮按住，下一轮不来，补账也不发生；模型看到的是「先别结束这一轮」。挡收尾不是删字的那一行，是让补账等死的那一环。删掉挡收尾之后，没塞进来的引导靠下一轮开头补上。实时塞进当前这一轮仍是 Mirasim 的事，本仓改不了那个时机。
