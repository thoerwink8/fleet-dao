## 决定

1. **两件事分开叫。** 「页面点验」＝把做出来的功能页面真打开点一遍、看效果，是交活的一部分；「e2e」只指 CI 里那个自动回归 job。文档和交代里不再混用。
2. **回归网挂在时间上，不挂在每个 PR 上。** 每夜在主线跑一轮全量（含全部 e2e spec），#1003 已落地；非 `pull_request` 事件一律全跑。
3. **PR 的 e2e 只点改动页。** 按改到的页面文件映射到对应的 spec，只跑那几个；只改后端、映射不到页面的 PR 不跑；改到 e2e 夹具、CI 工作流、映射表本身的全跑。落地在 #1186。目标：只改一页的 PR，e2e 墙钟从约 364 秒降到 90 秒以内。
4. **页面点验分三档**（创始人「要我拍的都按照你推荐」）：不碰界面＝不要；界面重构＝一眼截图；改了看得见的行为＝真点一遍加截图。e2e 跑过的页面以它存的截图为准，不用再手工起环境截。

## 为什么是这个

五步法过了一遍：「碰 web/api/db/shared 就跑全量」这条要求没人署名，是 AI 自己定的（质疑需求）；db、shared、根配置不再单独触发 e2e（删除，#1002）；回归网一天跑一次就够，不用每个 PR 付 300 多秒（简化）；PR 上只剩改动页，才谈并行提速（加速）；每夜那一轮自动跑（自动化，最后才做）。
