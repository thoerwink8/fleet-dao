# 0123 GitHub 单和 PR 减量：存量不动，记录类不再走 PR

- 索引状态：生效
- 日期：2026-10-31（北京时间）
- 谁拍的：创始人 2026-10-31 凌晨在讨论稿 #3760 上「按推荐拍」，没等别家挑错（同 0122）。
- 状态：采纳。分三批：#3763、#3764、#3765。
- 关联：`specs/3760-github-volume/讨论稿.md`；决定 0097（引导记进仓）、0111、0117、0122。

## 背景

编号到 3760 是单 1,514 张加 PR 2,246 个共用的号，开着的只有 66 条。每周新开在 10-12 那周最多（单 661、PR 592），10-26 那周降到 27、39。单和 PR 基本一对一；还在持续产生的噪音是两类不挂单的 PR：每记一条创始人引导一个（60 个）、每天刷新测试耗时表一个（20 个）。10-30 GitHub 核心额度被用光过一次（#3758 的检查因此红）。

## 决定

1. **存量不删、不迁**：删了找不回，换新仓会断掉所有链接和写死的单号。日常只看开着的单和 PR，驾驶舱只列开着的，历史靠搜索和按版本的里程碑。
2. **创始人引导不再一条一个 PR**：记进驾驶舱库（经账本写口），仓里只留按周汇总的意思、不带原话。部分取代决定 0097「引导记进仓里 `docs/directives/`」；`docs/directives/` 已有文件留作档案。（#3764）
3. **测试耗时表每周刷新一次**，不再每天开 PR。（#3763）
4. **查清额度用光的来源再定修法**。（#3765）
5. 「一张单一个 PR」照旧：它是每次改动的验收记录，不砍。自动观测和 AI 读 GitHub 的减量已在 0122（#3741、#3757）里做，不重复。

## 实测数字

落地后一周回填：不挂单的 PR 每周个数（目标 ≤ 2）、核心额度是否再用光。
