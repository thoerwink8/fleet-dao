## 起因

公司项目仓（内网 GitLab，同事会看）的文档和提交说明里写满了 AI 工具的事（额度、云会话、用哪个模型、子代理还是主会话、让哪家挑错）、创始人对 AI 怎么干活的偏好、他的原话原封引用，提交带 AI 署名行。源头在 fleet-dao 推出去的规矩：

1. 通用段让「别的仓」把引导记进 `docs/PROGRESS.md`「## 创始人引导（待处理）」（模板就是「时间「原话」」），把额度这类临时调整记进同一文件的「## 生效中的临时调整」。
2. 仓合同 `progress` 项要求每个仓都有这两节，`repo:init` 会替公司仓补上；`agents-md` 模板写「进度、创始人引导、临时调整记在 docs/PROGRESS.md」「通用规矩以 fleet-dao 为准」。
3. 通用段「日期、原话、来龙去脉只进决定记录和方案」没分仓，项目仓的决定记录也照贴原话。
4. 各家 CLI 默认往提交和 PR 里加署名，规矩没说项目仓不要。

## 定了什么

1. **仓分三类**：fleet-dao；私人仓（只创始人自己用、仓根 AGENTS.md 有一行 `<!-- repo-kind: 私人仓 -->`）；项目仓（其余，公司仓都算）。不按远端在谁的账号下猜：一个仓可能有几个远端、镜像、fork，判错把公司仓当私人仓就是泄露（GPT 挑错第 5、6 条）。
2. **项目仓记什么**写进通用段一节：进项目本身的事（需求方确认、业务和技术决定、现场情况、怎么验的和结果）；不进 AI 工具的事、对 AI 怎么干活的取舍、个人机器账号和私人项目；原话写成结论（谁、哪天、定了什么、为什么）；文档、注释、单、提交、PR/MR 都照这条，不加 AI 署名行。fleet-dao 和私人仓不受这节限。
3. **引导记到哪按内容分**：AI 怎么干活的进 fleet-dao `pnpm progress directive`（只关一个项目的进本机 AI 记忆）；AI 运营的临时调整进 fleet-dao `docs/PROGRESS.md` 那一张表；项目的拍板记进项目仓写成结论。fleet-dao 是公开仓，记进去的不带公司项目的业务、人名、内网地址。
4. **仓合同**删掉 `progress` 项，`agents-md` 模板改成「需求方的确认、业务和技术决定记在 docs/decisions.md」，不提 AI、fleet-dao。新项目脚手架（`project.ts`）的 AGENTS.md 模板同改。
5. **钩子**：删掉开会话读别的仓「## 创始人引导（待处理）」清单、〔范围〕标记那一整套（`checkDirectives`、`scopeNote`，以及从没接上收尾钩子的 `stopScopeCheck`）。调工具前钩子加一道兜底（`ai-attribution.mjs`）：项目仓里 `git commit`、`gh pr create|edit`、`glab mr create|update` 的文字带 AI 署名就拦；`git push` 时查要推、还不在远端上的提交的**最终说明**，带署名就拦（GPT 挑错第 2、3 条：只看命令文本盖不住编辑器、`-F` 文件、amend）。git 跑不起来放行并说没查成。
6. 工人子代理说明：项目仓照那个仓自己的分支和提交规矩，不用 fleet-dao 的 `local/<单号>-` 分支名。指挥官技能「拍了板当场记」分仓写。
