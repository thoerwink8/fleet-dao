## 断链

- 事：巡检「记账」读不到引擎记下的 token，演练红了。
- 当时的修法（#1936）：把判据放宽成「四样 token 读到任意一样」，演练过了。
- 根子：引擎读用量的地方和时机不对（经 Mirasim 起的会话要按中转计量补记），#1946 才修。
- 为什么会这样修：通用段只说读不到要报明确的失败，没说接下来先修哪一环；放宽读方的判据是最近的一条路，检查绿了就没人再追。创始人认为那是逃避。

## 决定

1. 通用段「底线」紧跟「不拿空、0 或 ok 冒充没事」那条，补一句原话：「读不到先追数据源；要放宽判据，PR 里贴上游真的不给的证据。」
2. 落在动作必经的地方：检查红了、读回的结果和预期不符时读的是 `chain-first`，它的「硬规矩」跟着写一条，指回第 2 步的写方、存放处，并照通用段这条。
3. 钉住：`agents/test/rules/read-source-first.rules.test.ts` 查这句在同步脚本认的那对标记之间、在「底线」里、不在本仓段，同步目标清单盖住登记的每一家 AI，`chain-first` 跟着写；每样都有一条故意造出的失败。

## 没做的

- 不拿关键词拦「放宽判据却没贴证据」的 PR：判不了，这是写死判断（`judge-or-code`）。
