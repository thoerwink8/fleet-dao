## 原话

```
我都同意。

我希望你替我拍板全部的流程，因为你比我现在更熟悉整套流程。我现在其实稍微有点不熟悉，只能大概把握，只要是有益处的，或者能让我整个流程更顺畅的，你都可以改。

我希望你仔细思考，改完之后不断地复验，或者结合整套机制看看有没有其他还能改的，顺便去验证一下，再次协助我探索。谢谢。
```

「都同意」指的四项：理想的一天按「说一句话，中位 30–45 分钟在法国上线，只为四类人闸打扰」设计；删 canary，换看门狗加「N 小时没合 PR」报警；E2E 移出 PR 闸；指挥官侧钩子三处改法。

## 为什么（法国库近 14 天、CI 150 次、本机会话 107 个）

- 开单到法国上线中位 157 分钟、p90 513 分钟；其中合并后等发版中位 91 分钟（58%），动手只占中位 18.6 分钟。
- 总开关被关 81 次，全是发版脚本或指挥官暂停引擎，关着累计 22.5 小时，19 次要人手工开。
- 卡住 114 次、205 小时：轮数用完停下等人 57 次（36 次人只是点继续）、跑满 60 分钟被杀 6 次（隔夜）、验收做不出来 25 次（多为认不出作者族的误报）；真要人看的只有约 8 次。
- 只有 46% 的单一次做成；返工轮花掉动手 token 的 47%，每轮冷启动重读仓库；纯解冲突也花首轮同等 token。
- 冷验收拒单抽 15 条：7 条代码真错、5 条验收条在 diff 里看不出、3 条误判（没给 PR 正文、建议也拒）。
- E2E 只占 2.5% 的 job、19% 的 runner 分钟，把 PR 墙钟从 2.3 拉到 7.2 分钟；52 次红 20 次，约 16 次是测试时序竞态。
- 本机：无人值守收尾钩子空转 410 次，密钥形状误拦 119 次，前台超时拦 51 次。

## 决定

1. **发版不停整台引擎。** 只在切版本重启那段停接新活；在跑任务发前暂停、发完按会话号续上（0088 第 2、3 条保留）；去掉 10 分钟排空；发版验证只看这次新版相关项；发版驱动中途死了法国自己恢复开关。命令行改开关的审计记成运维脚本。
2. **主线头 CI 全绿、没有发版在走就发**，取消「至少隔 1 小时」。
3. **返工续原会话。** CI 红、验收拒、合并冲突的下一轮，同路由同会话用户同工作树就续上一轮会话，只补返工意见；连续两轮续会话没过才开新会话。合并冲突引擎先自己 rebase，解不开才派模型。引擎在会话结束后自己跑改到的测试和 tsc，红了续进同一会话再改一次。单任务设 token 预算，超了停下等人。
4. **卡住先自动处理一次再停下等人。** 轮数用完换路由自动继续一次（沿用重置次数上限）；验收做不出来自动兜底（补全作者族、同族兜底、换路由重试、读不到的文件跳过注明）；跑满时限被杀的自动重派一次；CI 结果没查成自动重查。卫生检查拦下、缺权限这类真问题照旧停下等人。
5. **冷验收保留**（换家、独立），材料加 PR 正文和测试输出，只判「怎么算做完」，建议不挡；要 diff 外证据的验收条判「不归验收」，转给指挥官，不回炉动手。
6. **E2E 挡发版、不挡 PR。** PR 必过集只放 lint、受影响单测、打包；E2E 在主线推送上跑，发版只认主线头 CI 全绿。E2E 并行；首跑红重试过的标偶发，达阈值移进不挡的隔离集并自动开单限期修。本机 `pnpm check` 默认只跑改到的，全量加 `--all`。
7. **删 canary**，看门狗加「主线 N 小时没合 PR 且有可接的单」报警；canary_runs 表保留停写。
8. **merge-gate 判改标准**：改到标准路径而没有创始人同意记录的不放行（补人闸缺口）。
9. **指挥官侧钩子**：无人值守收尾钩子在后台还有东西在跑时放行；密钥钩子只拦真读密钥和高风险操作，提到路径名不拦；前台超 60 秒的命令自动改成后台跑，不拦。

## GPT 反方意见（gpt-6-luna，有异议 3 条）怎么处理

- 「每次合并就发 = 对外发布，要人拍」：不收。发版目标是法国自家引擎，自动发版 0088 已拍；对外发布（npm 等）仍人拍。
- 「E2E 移到合并后，坏前端会发上去」：收，改成 E2E 挡发版（第 6 条）。
- 「钩子只打码挡不住读密钥外传」：收，高风险操作照拦（第 9 条）。
- 「自动继续不能无界接力」「偶发隔离要阈值和复核」：收（第 4、6 条）。

## 不动

- 四类人闸；主线锁住必走 PR；只发主线 CI 全绿的提交、健康不过自动回滚；推前扫密钥；订阅路由不新增账单；cgroup 内存总闸。

resume（#2037 及返工续会话）、release（#2038 及取消 1 小时间隔）、verify、ci、hooks、canary 六包，各自 PR 引用本决定。

## 修订（2026-10-15，#2674）：碰到风险路径的 PR 照样跑 e2e

第 6 条「E2E 挡发版、不挡 PR」补一个例外：PR 改动碰到表结构（`packages/db/src/schema/`）、迁移（`packages/db/migrations/`）、e2e 备库和样例数据（`packages/store/src/testing/`、`packages/api/test/e2e/`）、e2e 用例和夹具（`packages/web/e2e/`）、`deploy/catalog.json` 时，PR 的 CI 跑 e2e 全套（和主线推送同一个 job、同样分片），合并闸把它当必过项（跑了才算，没跑算过）；其余 PR 照旧不跑。

为什么：#2399（删 session_runs）改了表结构和测试样例数据的读法，PR 上单元测试全绿就合了，主线 e2e 备库那一步对每个 worker 都失败，主线连红两轮、自动发版停了约 3 小时，偶发统计还开了两波共 168 张假单。e2e 出事的口子很集中，别的 PR 跑 e2e 多半白跑，所以只把减多了的这一小块按风险加回来。

路径清单只写在 `packages/conventions/src/ci-plan.ts` 的 `E2E_PR_RISK_PATHS` 一处，`ci.yml` 只读 changes 的 e2e 输出。命中时输出 `all`（全套）而不是按 spec 映射：这些路径是整个备库、样例库的地基，说不准会碰到哪一页。

## 修订（2026-10-18，#3037；2026-10-22 起按决定 0113 改写成现行做法）：「不归验收」的条，派单前挡下，漏网的代码照合、单子留着

第 5 条的「不归验收、转给指挥官」原意不变：这些验收条不算没过、不回炉、不挡合并闸。现行做法（决定 0113 取代了 10-18 那版的持久验收责任账）：

- 要 diff 外证据的验收条（截图、现场、线上、读库、读回，以及「核实原场景卡在哪」「定位某次超时的真实阶段」这类诊断型）在开单和拉单时就挡下（`packages/conventions/src/off-diff-acceptance.ts`，开单、整理单、拉单共用一份判据）：交给引擎的单拒开或不拉，这类单只能本机或指挥官做，单子开着，直到有人贴上证据再关。不在库里另起「待验」状态，也不拿「已合」冒充「已验」。
- 冷验收仍判出「不归我验」的漏网条：留言转人，代码照合；工作流自己记着这几条，合并前把需求引用改 `Refs`（分片）、原验收项留在「还欠什么」，收尾不关单。
- 引擎不再往 `acceptance_duties` 写新行；10-18 到 10-22 记下的旧行不动，只读，照旧经管理 CLI 结清（下一片收掉）。

## 修订（2026-10-22，#3604，决定 0115）：第 5 条里「什么算不过」收窄

第 5 条「只判怎么算做完，建议不挡；要 diff 外证据的判不归验收」不变，口径补严：只有「某条验收条在 diff 或测试输出里看得到没做到」才算不过；弄坏原有功能、安全、边界之类验收条以外的意见一律进建议（通过时留言到单上）、不挡合并；看不到证据而判不了的转人，不判不过。族顺序（决定 0006）不动。依据与回退见 0115。
