## 起因

0002 定了 Fusion 的大方向。具体怎么走（叫法、分几步、换模型、讨论、驾驶舱、代码放哪）在 #169 逐题讨论了七题、六轮插题，再从进单到发布串成一条链检查：找出 33 处不闭合，和 GPT 收敛 25 处，其余 7 件、定稿 19 条交创始人拍。

## 决定

**计划怎么组织**

1. **层级**：项目（一个仓）→ 版本（里程碑，标题 `v<N> 一句目标`，没挂＝未排期）→ 母单或单独的小单 → 子单（GitHub 子议题，别人开的具体问题）→ 块（Lead 拆的活，不开单）。计划以 GitHub 为准，`docs/plan.md` 是每个版本开始和结束时生成的快照（#138）。驾驶舱首页画布按这套层级分层，其余模块以它为骨架。
2. **版本**：创始人要的照开，AI 挑的等他点（意向到下一次版本规划失效、到时重提）；创始人开的单默认进当前版本，受预算约束。预算＝并发槽位 × Lead 额度预测，留两成给急修和插队；做完没发布的版本攒到 2 个就不开新版本。开始后 AI 不往进行中的版本加非紧急的，创始人随时能加、能插队。收尾：发布说明（做了、没做、挪去哪）→ 创始人拍发布 → 里程碑关；没拍发布，下个版本照常开工、每天提醒一次。
3. **母单**：能一起验收的才归成一张（不是「起因一样」）。谁开：创始人、开单第 0 步、版本规划提案、Lead（小单做大了升成母单；熔断后把剩下的开成后续母单）；副手不开单。怎么关照 #169「插题（再续）」十条：按目标关（验证达成就关，不要求子单全关）、开工后范围冻结、上限和熔断（具体数等 v1 实测定；2026-09-27 创始人改：额度只跟踪、不作上限，#257）、结束写去向、等人不卡死、未排期不自动关、要改同一批文件的不同时跑。
4. **插队**：四档先后——急修（主线红、生产坏、数据、泄露、安全，只认看得见的证据）> 插队（只有创始人能点）> 本版 > 未排期；满了就让最不急的那张在下一个存档点让位，最多等 10 分钟，同一张最多被让 2 次。

**一张单怎么走（Fusion 模式，默认）**

5. **0–7 步**：0 创单并讨论 → 1 收单（引擎，不用模型；引擎自己开的单正文写全了需求、没有需求文档的照收，Lead 照正文写需求文档随 PR 进仓，#295）→ 2 规划·拆块（Lead 写方案和任务简报，更新母单正文；说不清的问创始人：2026-09-27 创始人改、放进 v1，一律带选项和推荐、按推荐先走不停下等，超出这张单范围的另开单，碰人闸的只挡合并那一步，他之后改了在下个存档点生效、已经合了的开后续单，#259、design 第五节「没人拍板」）→ 3 方案评审（别家 1–2 家、1 分钟内；和讨论结论一致或小单就跳过）→ 4 执行（副手按简报干；拆得开时最多 3 个同时，先定接口和谁改哪些文件，各在自己的工作副本；Lead 逐个合进来、每合一个跑一遍测试，验收时收下、打回最多 2 次或自己接手）→ 5 验证（别家的验证模型对照「怎么算做完」逐条答做到 / 没做到 / 看不出，带证据；只有三种能挡：没做到验收条、有证据弄坏原有功能、安全或丢数据；默认 1 轮、最多 2 轮）→ 6 开 PR·过 CI（红了回 Lead 派副手改，最多 3 轮）→ 7 合并、关单（碰人闸的等创始人拍）。母单按块循环 4–7，所有块做完再做一次母单级验证。合并后不再补审。
6. **存档点和换模型**：每步结束 Lead 存一个存档点（一个 git 提交加写明白的进度）。换模型在存档点换，中途也能换（引擎先临时提交、自动写存档点、记「中途切换」）；新模型先读存档点，再按需翻上一个会话的完整记录；关键想法必须写出来。Lead 的座位长开，在存档点按上下文用量换新会话；只有存档点由 Lead 写，简报和母单正文下半从它生成。
7. **单模型模式**：额度不够时切（创始人手动，或引擎按剩余额度自动切，记一笔）；第 2、4 步同一个模型，第 3 步关，第 5 步只对高风险的开。副手渠道没额度时 Claude 单干；Claude 没额度时，简单的单由一个便宜模型单干，难的等。
8. **不许机器给自己派活**：只有带证据的急修能自动开单（创始人自己的回答另开的不算机器给自己派活：他合并后才改选的后续单、超出范围等他拍的单由引擎对账自动开，#259、design 第五节「没人拍板」）；验证提的建议每张母单最多并成 1 张后续单；空位时只做本版能并行的块、下个版本候选母单的只读准备、第二意见和考新模型，不碰未排期。

**配置与骨架**

9. **流程配置**：每个仓一份 JSON，可以有几套（每一步的模型顺序，讨论、评审、验证几家几轮，测试命令，会话内存，高风险路径，哪些路径算页面代码，各类别默认用哪套）。fleet-dao 放全组织默认，项目只写不同的；禁令（GPT 不做界面、不用 Fable）写在全组织默认里、项目改不掉，改它算改标准。驾驶舱派单页是它的编辑器，改了开 PR 自动合；读不到、认不出就这个项目停派、报红，不拿默认顶；带格式版本号，引擎认当前和上一版。文件名和位置在 #191 定。**「界面」「本机」两个标签去掉**：派活按要改的文件过滤（碰页面代码不给 GPT）；本机还是法国在派单时选、记在单上。
10. **照 k8s 的骨架**：每个对象分「想要的」（人和 Lead 写）和「实际的」（系统写），一组对账程序把实际的拉向想要的，事件来了马上对、漏了定时补；读写只走法国一个接口；规矩只放两个必经口——写进接口时的准入检查、派活时的调度（先过滤：禁令、额度、文件冲突；再打分：配置顺序、战绩）。标签只分类和显示，不驱动流程。驾驶舱里的东西分四类、各存一处：规则（仓里的 JSON）、指令（法国库，马上生效：开关 AI、暂停、换模型、先后）、计划（GitHub）、状态（系统写，人只看）。
11. **盘面同步**：法国一处为准，各处订阅变化，断线回来按同步号补漏或重取；本机会话靠钩子注入「等你拍的、当前版本、最近的决定」；快照过期的会话不许推 PR（急修除外）；两台机器都挂时 GitHub 当收件箱，恢复后对账补。
12. **core 包**：所有判断（对象和格式、状态机、写入检查、派活、对账决策、禁令 / 人闸 / 上限）放进一个新包，纯判断、不碰网络和库；引擎、后端、网页、`fleet` 命令、钩子都是外壳，调它判、自己去做。讨论出的每张边界表变成它的测试；规则搬进来的同一个 PR 删掉外壳那份，规则编号两边对账。

**记录、讨论、插话、帅位**

13. **讨论记录**：每张单一份简报加全文。两边都放：写进公开的单（GitHub 那份当备份），法国库存一份给驾驶舱快查；两边不一致以法国库为准；超过单条上限的全文分成多条评论。往公开单写之前过卫生检查，拦下的那段只留法国库，单上写「这段只在驾驶舱」；飞书群告知在记录，只收挂了单的讨论群和 @机器人的消息。全文按时间存原话、留版本、分清更正和撤回；简报一屏六栏（一句话现状、方向、已定、待定、分歧、下一步），逐层往上汇总；「已定」只认拍板记录；全文缺了标「缺」不编，AI 补的简报标「待确认」。
14. **讨论能接着聊**：同一场讨论各方保留自己的会话，随时拉起接着聊；停在收敛、分歧定型或到上限；重新拉起要写明能改变结论的新证据。
15. **插话**：单内的事找这张单的 Lead（副手从不直接收人的话），跨单的事（先后、版本、规矩）找帅位；插的话在两步之间处理，「停」立刻打断；页面显示已送达 / 已生效。
16. **帅位**（和创始人对话的总指挥会话；09-27 晚创始人改回全局只一个，前提四条见 `specs/169-Fusion形态/需求.md`「帅位改回只一个」，机制 #299；替掉 09-27 凌晨定稿时的「不设独占座位，每台机器、每个项目都可以有」）：全局只一个、管所有项目，创始人指定谁当，新的接班、旧的下一次现查就退役；受保护动作（认领、派工人、改派、交单、记决定）前现查任期；派工先在库里认领，别人拿着的不碰，改派要创始人说；记决定前读主线上已有的，冲突就问（技能 `agents/skills/commander-seat`）。design 第十二节里服务器上定时起的「AI 帅位」是另一回事。

**人闸与发布**

17. **谁的话算数**：项目主人拍人闸、插队、改目标，可以给别人限时、限项的代理授权（放驾驶舱「成员与权限」页，写明管哪几项、到哪天，进操作记录）；其他成员的话当输入。
18. **发布**：发主线上的某个提交，按版本确认，即「合并≠上线」（标准加这一条，人闸第四类）；root 侧自己核「提交在主线上、有同意状态」再跑发布脚本；出问题回退预先授权。半截功能先「最后才接入口」，做不到才用配置里的开关；打开给用户用的开关算发布。（2026-09-27 早补的指针，本条意思不变：本条管给用户用的产品和开关；fleet-dao 自己的法国引擎、驾驶舱随主线自动发布，见 design 第三节第 42 条、ops 第九节「自动发布」。）
19. **通用规矩跟着改**（人闸第四类，改标准的 PR 创始人看过再合）：讨论从一问一答改成能接着聊；「挂了阶段的单」改成「挂了版本或未排期」；「谁发现谁当场修」改成急修（主线红、生产坏、数据、泄露、安全）照旧当场修，其余开小单、按版本修；discuss skill 的轮数上限和默认几家跟着改。
