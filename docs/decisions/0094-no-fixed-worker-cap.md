## 原话

```
工人名额 3 个是规定吗？我觉得不合理，你自主调整。不要刻舟求剑……要有空杯心态；完全可以不拘泥本仓库的约定，重塑一个新的完整机制。
```

## 依据

旧的「4 个、工人 3 个」在 0034 里没有写依据，只是起步值。真正会出问题的只有两件：本机资源被顶满（宿主崩过，见 `agents/skills/discuss/scripts/ask.mjs` 注释），和两个工人改同一批文件互相覆盖。个数卡不住这两件：3 个轻活不会压垮机器，2 个重测试可能会；3 个范围不重叠的工人没问题，2 个改同一文件就有问题。所以直接按这两件判。

## 新规则

1. **不设固定个数。**
2. **本机负载**：派新工人前看空闲内存和 CPU。空闲内存 < 4G，或 1 分钟负载 > 核数×0.8，就先不派，等一个收口再派。跑重测试（整套 vitest、构建、e2e）的工人错开，不同时起。
3. **范围不重叠**：同时在跑的工人不改同一批文件。撞了就排队，或交给同一个工人连着做。
4. **监控（巡检）不占工人名额**；它是脚本为主、只读，不计入上面两条的“工人”。
