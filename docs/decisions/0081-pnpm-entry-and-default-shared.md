## 断链

- 事实：创始人只记 `pnpm xxx` 这类命令，不记软件、路径、双击哪个文件；他用 Mirasim，没有「桌面上点图标」这条路。
- 写方：他在某个仓的会话里说出来，只到达那个会话的 AI。
- 存放处：通用段没有「仓要给一条命令起最新版」；就算写进去也只是文字——Claude Code 官方明说 `AGENTS.md`、`CLAUDE.md` 是上下文、不是强制（https://code.claude.com/docs/en/memory ），确定会发生的只有钩子（https://code.claude.com/docs/en/hooks ）。
- 读方：新仓的 AI 读不到，先给了 `start.cmd` 加路径加环境变量。
- 报警方：没有任何东西查「一个仓（含以后新开的）合不合规」；开会话钩子在任何仓都跑、已经在读各仓 `docs/PROGRESS.md` 的「创始人引导」一节，但没人让它查合规。「自上而下」的提醒也断了：第一版挂在 `pnpm progress:directive` 上，而别的仓记引导是 AI 手写进 `docs/PROGRESS.md`，那条命令只在 fleet-dao 里有，碰不到出事的场景。
- 为什么这么久没人知道：「项目特有还是各仓通用」默认落在项目一侧、全靠会话里当场醒悟；同一条「不要让我记东西」几小时里说了两次，两次都只记进了一个仓。

## 决定

1. **合同写成数据**：`agents/repo-contract.json`，每项 `id`、`说明`（事实陈述）、`检查`（`file` 文件在；`scripts` 这些脚本在、不空、不带占位记号；`lines` 文件里有某几行）、`补法`。首批四项：`entry`（仓根 `package.json` 有 `dev`、`start`、`stop`、`check`，占位不算）、`agents-md`、`progress`（`docs/PROGRESS.md` 有「## 创始人引导（待处理）」「## 生效中的临时调整」两节，和开会话钩子现读的同一个标题）、`gitignore-tmp`。以后加要求就是加一项，所有仓都自动被查。合同进改标准路径。
2. **一份逻辑，钩子和命令共用**：`agents/hooks/repo-contract.mjs`，只用 node 自带模块，随钩子整份拷进 `~/.fleet-dao/hooks/`；装到机器上之后从同步专用检出 `~/.fleet-dao/origin-main` 读合同，合同一合进主线，各台机器下次开会话就按新的查。读不到、认不出明确失败。
3. **两条命令**：`pnpm repo:check [仓路径]`（全过 0、有缺 1、读不了或认不出 2）；`pnpm repo:init [仓路径] [--dry-run]`（只补缺的、绝不覆盖；入口放占位，一跑就报 TODO、退出 1，占位不算 entry 通过；认不出的那项不动）。别的机器、别的仓里用 `node ~/.fleet-dao/hooks/repo-contract.mjs check|init`。
4. **豁免看得见**：仓根 `AGENTS.md` 写一行 `<!-- repo-contract:skip <id> <理由> -->`；没写理由不算数，照查并说出来；豁免和理由在 `repo:check` 的输出里列出来。fleet-dao 自己豁免了 `entry`（本机不起引擎和驾驶舱）和 `progress`（引导记在进度单 #1055）。
5. **开会话钩子在任何仓里都查**：有缺项往开场上下文里加一段事实（缺什么、怎么补、怎么豁免），每个仓每天（北京时间）最多一次，记号在 `~/.fleet-dao/repo-contract/<仓的 git 公共目录指纹>`；全过一个字不说；合同读不到、钩子自己出错说一句没查成。工人会话（`FLEET_WORKER=1`）不查。
6. **「自下而上」的触发点**：创始人引导条目带 `〔范围：通用〕` 或 `〔范围：只此仓〕`，通用的上推后写成 `〔范围：通用→fleet-dao#<PR号>〕`。开会话的 `checkDirectives` 对待处理、归本会话或无主的条目，没标范围的、标了通用还没上推的，在原来那一行后面各补一句；已处理的不追溯。收尾的 Stop 钩子比 `HEAD` 新记的条目没标范围，用 `systemMessage` 提醒，同一会话同一条一次，绝不拦。
7. **撤掉第一版挂在 `progress:directive` 上的提示**：它只在 fleet-dao 里有，碰不到出事的场景；范围标记由上面两个钩子在每个仓里提醒。fleet-dao 自己的引导在进度单 #1055 上，不带范围标记，这一处没覆盖（它本身就是改标准的仓）。
8. **通用段只留一条短的**：指到合同、只记 pnpm 命令、默认各仓通用、引导标范围；细则在合同和钩子里。

## 没做的

- 提交、推送前拦（方案 C）：先观察一周，还漏再升。
- 指挥官技能「验收」加「创始人怎么打开它」。
- 别的仓不批量改：由开会话钩子在各仓下次开会话时提醒、`repo:init` 补。

## 依据

业界的多仓规范检查、脚手架方案要 CI、付费套餐或常驻服务，和「单人、私有仓不配 CI、不新造常驻进程」冲突；只借「规则清单写成数据 + 本机一条命令 + 退出码」这个形状。「说出原则时提醒上推」没有现成先例，自己做。
