# 0081 仓根要有 pnpm 命令入口；创始人说的原则、偏好默认各仓通用

- 日期：2026-10-12（北京时间）
- 谁拍的：创始人在带货工作台仓的 Mirasim 会话里选定「要作为通用规矩」（原话见下）；具体写法由那个会话派的子代理按断链图起草，改标准，等创始人看过 PR 再合。
- 状态：待创始人同意（改标准）。
- 关联：`agents/shared-rules.md`「在任何仓里干活」第 1 条（加「默认各仓通用」）和新加的「pnpm 入口」一条；`packages/conventions/src/directive-scope.ts` 的 `DIRECTIVE_SCOPE_HINT`、`packages/conventions/src/bin/progress.ts` 的 `directive` 分支；钉它的测试 `agents/test/rules/repo-entry.rules.test.ts`；字数账 `agents/rules-budget.json`。`docs/design.md` 第十五节第 12 条（自下而上）。
- 取代：无。通用段第 1 条「各仓都用得上的规矩给 fleet-dao 开 PR」照旧，这次给它加了默认和触发点。

## 原话

```
2026-10-12 约 04:00（北京时间），带货工作台仓的 Mirasim 会话

不，我希望类似 pnpm xxx 方式，可以命令启动；我在 mirasim 是很难记住对应的软件的

这个非常重要，我甚至认为是需要自下而上的，所以 fleet-dao 应该也接收到，作为一个规则；但是显然没有这个意识，说明存在断链，判断下哪里断链
```

同一个仓更早一次同类话（2026-10-12 03:50）：「密钥在项目里要有类似历史保存和随时更换的能力，不要让人记」——当时只记进了那个仓的 AGENTS.md 和记忆，没往上推。

## 断链

- 事实：创始人只记 `pnpm xxx` 这类命令，不记软件、路径、双击哪个文件；他用 Mirasim，没有「桌面上点图标」这条路。
- 写方：他在某个仓的会话里说出来，只到达那个会话的 AI。
- 存放处：通用段「在任何仓里干活」没有一条讲「仓要给一条命令起最新版」；fleet-dao 自己的 `pnpm plan`、`pnpm pr:open`、`pnpm progress:*` 只是本仓习惯，没写成对别的仓的要求。
- 读方：新仓的 AI 开工读通用段和仓 AGENTS.md，读不到这件事，先给了 `start.cmd` 加路径加环境变量。
- 报警方：没有。也没有任何东西在他说出原则那一刻问「别的仓也适用吗」。
- 为什么这么久没人知道：「项目特有还是各仓通用」默认落在项目一侧、全靠会话里当场醒悟；第 1 条「各仓都用得上的给 fleet-dao 开 PR」没有触发点。同一条「不要让我记东西」几小时里说了两次，两次都只记进了一个仓。

## 决定

1. **问题：入口。** 通用段加一条：能跑起来的仓，根 `package.json` 给 `pnpm dev`（起最新版）、`start`、`stop`、`check`（交活前检查），写进 README 第一屏；没 Node 的仓也放一个只有 `scripts` 的（不装依赖）。依据：npm、pnpm 的 `scripts`（`start`、`dev`、`test`）本来就是生态里「一条命令起项目」的通行入口；带货工作台仓（daihuo-workbench）已经这样做了：它的仓根 package.json 只有 `scripts`，四条命令各调它 server/scripts 下的一个 PowerShell 脚本。
2. **机制：把默认翻过来（改读方，不加报警）。** 第 1 条加：创始人说的原则、偏好默认各仓通用，当场给 fleet-dao 开 PR；当成只此仓有效的，要他明说过，或在仓里记决定的地方写明为什么。
3. **机制：写点自己提醒。** `pnpm progress:directive` 记完引导多打一行「这条是各仓通用吗？……」（`DIRECTIVE_SCOPE_HINT`）。只在 fleet-dao 里有这条命令；别的仓靠第 2 条的读方。
4. **不新造巡检。** 不加「查各仓有没有 `pnpm dev`」的定时任务；以后标准体检（`docs/design.md` 第十五节第 8 条「仓」那一类）落地时再把它列进体检项。
5. **别的仓这次不去改。** 由各仓下次进去干活的 AI 按新规矩补（扫过的现状写在 PR 里）。
