## 起因

0116 把讨论稿放进 `docs/`，文件名 `YYYY-MM-DD-<短名>-survey.md`；方案则一直放 `specs/<单号>-<短名>/`，带 `- 状态：在做 | 做完 | 被取代 | 未复核`。一件事要写两份：先在 docs 里出讨论稿，定了再到 specs 里写方案，两份各有一套状态、一套检查，讨论稿「已定」以后就没人再管；方案又是照着讨论稿重写一遍。需求方要的是流程更高效、更规范：同一件事一份文件、一条状态线。

## 决定

1. **fleet-dao 的讨论稿起在 `specs/<单号>-<短名>/讨论稿.md`**，同一份从「讨论中」接着改到「已定」「在做」「做完」，方案正文就写在稿里（模板的五、六、八节），不另起 `方案.md`。太长的落地记录放同目录不带状态行的 md（照 `specs/3587-建议筛子/第一片落地.md`），第八节链过去。决定只写条目，起因分析链回讨论稿（只写在文档里，不加检查）。
2. **通用脚本加布局开关**（#3671）：`package.json` 的 `discussionDraft` 新增 `layout`（`dated` 默认＝0116 的行为，`topic`＝按主题放）和 `file`（topic 下稿的文件名，默认 `讨论稿.md`）；fleet-dao 在仓根声明 `{"layout":"topic","dir":"specs"}`。topic 下 `new` 必须带 `--issue <单号>`（没带退出 2、先开单），同单号已有目录就报出来、不新建（退出 1），短名第一段不许纯数字（防 `555-2-x` 被当成子编号）。没配新键的仓（含对外仓）路径、参数、退出码都不变。
3. **状态一条线**：讨论中 → 已定 → 在做 → 做完；岔路 搁置、被取代；「未复核」只留存量旧方案。讨论稿脚本在 topic 下：讨论中查八节标题、超期提醒取 H1 里第一个日期（没有就不提醒）；已定 / 在做 / 做完查结论节有决定链接和单号；搁置 / 被取代不查正文；未复核报错。
4. **方案索引同一套状态**：`specs-index.ts` 的主文件挑法改成 `讨论稿.md` > `需求.md` > `方案.md` > 按文件名第一份；状态值先去 `<!-- -->` 和两头空白、再按开头认词（七个词没有互为前缀，`已定（日期，见 [决定](…)）` 认成已定）；白名单七个词，讨论中 / 已定 / 搁置只许写在 `讨论稿.md`，写在别的主文件报红。「还在管事」＝讨论中、已定、在做、未复核；做完、搁置、被取代进「历史」。两边认词规则一致，`agents/test` 和 `conventions` 各有测试钉着。
5. **CI 选测**：`ci-plan.ts` 在 `specs/` 整体不跑测试那条之前加一条，`specs/*/讨论稿.md` 改动选到 agents 和 conventions 的测试（讨论稿检查和索引核对）。
6. **存量不迁移**：180 个 specs 目录里没有一个 `讨论稿.md`，docs 下也没有讨论稿；旧方案的四个状态照认，`specs/README.md` 只有说明文字和新状态的表头变化。0116 的正文不改，头部加 `被取代：0118`：被取代的只是「fleet-dao 的稿放 docs、日期文件名」这一部分（第 3、6 条），八节模板、叫法、五步、推前检查、`discussionDraft` 声明差异都照旧。`docs/…-survey.md` 的那条 `ci-plan` 规则留着，`dated` 布局的仓仍可用。
7. **护栏登记不新增**：`command:discuss:check`（0116 登记）的命中来源补上新的稿路径，不新登记。

## 不做

- 不强制所有方案都走讨论稿：小事、旧方案照旧直接写 `方案.md`。
- 脚本不查单存不存在、不从分支名推单号（单号由人带）；不查同目录两份带状态行的 md；不改稿的 H1「讨论稿」字样。
- 手动在已有旧方案的目录里放讨论稿，旧 `需求.md` / `方案.md` 的状态行就不再被索引核对：不查，`docs/workflow.md` 写了一句。

## 没讨论成（照实记）

这是改标准的活，按 `discuss` 技能本该先让别家挑错。本机没装 `cursor-agent`，`ask.mjs` 退出 2（没问成），所以没有讨论成，也没有别家的意见可记。没等的理由：方案不迁移（存量一份不动）、两个 PR 都可单独回退（回退通用脚本的开关就回到 0116 的行为，把 `package.json` 里的 `discussionDraft` 声明去掉即可），不算难回退的重大决定；设计由一个只读的设计代理出方案、本机会话核过现状冲突再落地。这一条的风险是少了一道外部挑错，要是以后发现 topic 布局有漏，补讨论再改。

## 实测

- 改之前：fleet-dao 的讨论稿放 `docs/`、方案放 `specs/`，两份文件两套状态；`pnpm discuss:new` 不认 `--issue`。
- 改之后（2026-10-23，本机）：`agents/test/discussion-draft.test.ts`、`packages/conventions/test/specs-index.test.ts`、`ci-plan.test.ts`、`decisions-index.test.ts` 共 180 条全过。实跑起稿 `pnpm discuss:new -- demo --issue 9999 --ask "试"` 生成 `specs/9999-demo/讨论稿.md`（状态讨论中）；`pnpm discuss:check` 报「讨论稿检查过了：1 份」；起稿后没重生成索引时 `pnpm specs:index --check` 报不一致、退出 1，`pnpm specs:index` 重生成后过（索引里这一行状态「讨论中」，在「还在管事」）。试稿和索引改动已删，没提交。
- 顺带发现：模板的 H1 带日期和「讨论稿」字样（`# 标题（日期，讨论稿）`），索引的标题列会显示成「demo（2026-10-23，讨论稿）」；这一版不改 H1（超期提醒要靠 H1 里的日期）。
