## 依据（都是查过的数字；没查实的单独列在最后）

- 引擎源码 28,823 行、测试 36,321 行；任务工作流 `workflows/task*.ts` 共 1,281 行。
- 「纯 Temporal 层」（工作流、活动选项、worker、Schedule、演练、判断重放层、看门狗、叫醒）合计 3,665 行。**去掉 Temporal 本身对引擎源码的净影响只有约 0–1.2k 行**（拿掉 3,665、再新增约 2.5–3.5k 行：状态机、租约、看守、幂等、故障演练），所以不能拿「引擎降到一万行」当去 Temporal 的理由；那一万行要靠砍功能范围，是产品决定，不是编排决定。
- Temporal 真正独有的是**一张单的长流程**（记住走到哪、崩了重放接着走、信号、查询、取消）；它**不续会话**（引擎被杀，会话管道断了接不上，由孤儿收割后同一棵树同一分支重跑这一段）、**不管切号的判断**（普通函数）、**不记账**（写 `runs` 表）；排空（671 行）也不是它引起的（会话是引擎进程的子进程）。去 Temporal 后这几件的粒度都不变。
- 外围里**因为用了它才长出来**的：8 个 Schedule 加 8 个工作流外壳（引擎重启后暂停的 Schedule 要人手 `--unpause`，是个真陷阱）、每个测试一个测试服务端（`specs/353`：CI 偶发卡 60 秒，同一个坑踩了两次）、重放夹具与判断重放层、`mirror()` 把状态再抄一份进库。**不是它引起的**：失败规则引擎（2,443 行，模型不可靠引起；509 §九本来就写「删重试策略」）、三个对账（对的是 GitHub 和库）、排空、内存门。
- 现在换底座最便宜（法国引擎当时关着、没有在途单），但这只说明「换便宜」，不说明「一定要换」；最强的反对理由是引擎的问题是**写码会话成功率 38%、3 天半只做完 12 张单——瓶颈在模型会话和流程，不在编排**，花 2–3 周换底座对「引擎能不能开」没有直接贡献，还把 #452 演练往后推；换底座还会和没在真环境跑通的新三段流程叠成两个未知。

## 别家模型挑错（gpt-6-luna，两轮共 8 条，全认）

第一轮 3 条：①「先问事实、再动手、再记账」不能保证恰好一次，起会话、开 PR 都会撞竞态（→ 加副作用表、起会话先写 starting 行加部分唯一索引）；②租约只靠到期，旧执行者被暂停后醒来会和接手者重复动手（→ 围栏号 fence）；③「引擎关着」不等于没有在途工作流（→ B4 前要查清运行中工作流、Schedule、信号、孤儿会话）。
第二轮 5 条：①「Temporal 历史是第二份状态」说不准，活动本身也是至少一次（→ 措辞改成「三份减到两份、无镜像漂移」）；②起会话查询与启动之间有竞态（同第一轮第 1 条）；③事件流水不能当副作用已完成的证据（→ 一律以下一轮现读的事实为准）；④进程内定时器改变了停机补跑、跳过重叠、失败后的语义（→ 写明等价做法并补故障用例；本轮 #1078 就按这个做）；⑤「切回 Temporal 秒级」不成立（→ 要先有接管栅栏）；⑥新增行数漏算了幂等、补偿、观测、迁移、演练（→ 上调到 2,500–3,500 行、工期 2–3 周）；⑦选项 1 不该放行 B0–B6（→ 本份的第 2 条就是收窄后的放行范围）。
没有没认的；没有再追第三轮。
