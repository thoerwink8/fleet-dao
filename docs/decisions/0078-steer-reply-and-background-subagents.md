## 决定

1. **调工具前先回引导。** 他中途插进来的话（引导）一送到，下一次调工具之前先回他一句（收到了、打算怎么办），再接着干。
2. **派 Agent 子代理一律后台跑，主对话留在这一轮。** 不写 `run_in_background: false`。派了子代理这一轮不结束，留着等完成通知；等的时候单次前台等待不超过 60 秒，要等更久用 Monitor 或 `run_in_background` 的命令。不分无人值守与否。
3. **引导涉及子代理用 `SendMessage` 转。** 他的引导关系到某个在跑的子代理的活，就用 `SendMessage` 把原话转给那个子代理，不等它跑完、也不另起一个。

## 为什么

- 他的话只在两次工具调用之间送到主会话（Mirasim 的「引导」先攒着，等下一次调模型才塞进去，见 0026「引导为什么算同一条链」）。不先回一句，他不知道收到没有。（这条只对命令行里中途打的字成立；Mirasim 的「引导」要等这一轮结束、后台子代理都跑完才读进来，见文末修订。）
- 前台子代理一跑几分钟，主会话这期间没有工具调用的间隙，他的引导送不进来。后台跑的子代理不占主会话，间隙照常有。
- 主对话派完子代理就结束这一轮，没人收完成通知、没人收他的引导；以前这条只写在无人值守里，平时一样会出这个洞。
- 引导是给某个子代理的活的，主会话自己改不了它手上的东西；等它跑完再说就白跑一遍，另起一个就是两份活撞车。

## 修订：Mirasim 的引导由钩子取原文先转（#1743）

- 状态：创始人 2026-10-11 让指挥官测、没问题就合（改标准，PR #1797 正文「还欠什么」写「人闸：改标准」，指挥官实测通过后挂自动合并）。原话见下。

- 被替代的第一版：#1797 第一版做的是「钩子见到引导在等就拒调用、叫这一轮马上结束，无人值守的收尾钩子放行」。10-11 实测这样没用：这一轮结束了，引导照样等后台子代理（晚 2 分 05 秒）。第一版连同「派了这一轮不结束（有引导在等时除外）」的例外一起删掉，没合进过主线。

### 依据（#1743）

- 2026-10-10 17:25 实测（临时 Haiku 5.5 会话 a1138385，做 6 次各 15 秒的 `sleep`，没有子代理）：引导 09:25:23.876Z 发出，之后它又调了 4 次工具都没收到；这一轮 09:26:46Z 结束，0.4 秒后引导才作为新的一轮送进来。
- 无人值守让一轮几小时不结束，引导就卡几小时：10-10 11:47 发给会话 802f14bb 的，15:01 那一轮结束才进来；17:10 发给主帅 a8378600 的，到 17:37 还没进来，这期间调了 33 次工具。
- 2026-10-11 03:05–03:58 指挥官实测（四轮真 Mirasim 会话，脚本在本机主检出的 _tmp/steer-1797 下，不进仓）：
  - 第一版（叫这一轮结束）：Mirasim 自己记的 `steers[].at` 是 03:37:01，当场写进了 Claude Code；这一轮结束了，03:39:39 后台子代理收场后才进会话，比这一轮结束晚 2 分 05 秒。所以等的是子代理，不是这一轮。
  - 后台子代理一轮结束不会被杀，照常交回；进程重开（插队、重启）才会断。
  - 新做法（调工具前钩子转原文）：引导后 20 秒模型回了，子代理照跑。
  - 新做法（收尾钩子转原文，引导在它写最后一段话时到）：23 秒回了。
  - 稍后 Claude Code 把同一条正式送进来，模型说了一句「这条前面已回」。
  - 取原文：`ui-cli raw` 订阅这个会话、等 snapshot，约 0.6 秒；`ui-cli watch` 不带 steers，不能用。
  - 顺带找到的 bug：判「引导送到没有」时，后台任务完成通知（`<task-notification>` 开头）开的新一轮、Stop 钩子挡回来的「Stop hook feedback:」被当成了创始人的话，钩子就不拦了。
- 「插队」（打断当前这一轮）送得快，但会重启会话进程，在跑的那次工具调用结果丢了、后台子代理和监控被断，不拿它当解法。

### 决定（补第 1、2 条）

1. **引导在等就由钩子取原文转给模型。** 主对话每次调工具前，`agents/hooks/main-thread.mjs` 读 `~/.mirasim/diag/` 当前和上一小时的 `ev-<UTC 年月日时>.ndjson`，找 sessionId 等于本会话号的 `turn.steer`。会话记录里那之后没收到他的话（任务通知、Stop 钩子反馈开的一轮都不算），且晚于上次转过的，就起 `node ~/.mirasim/app/<最新版本>/server.cjs ui-cli --port 4970 raw '{"type":"subscribe","sessionKey":"claude:<会话号>"}' --await snapshot --seconds 4`，取 snapshot 帧的 `steers`（`[{ text, at }]`），拒这次调用、理由带北京时刻和原文：先用一句话回它，再接着干活，不用结束这一轮；稍后同一条正式送进来时说一句「这条前面已回」。
2. **同一条只转一次。** 转过的记进 `~/.fleet-dao/steer-shown/<会话号>.json`（最后转过的 `at`）；记不下就不转（不然每次调工具都拦），明说没查成。
3. **收尾时也转。** `agents/hooks/stop.mjs` 收尾时有还没转过的（写最后一段话时到的，调工具前钩子没机会拦）就 `decision: block`，reason 带原文；先于无人值守判，转过一次就不再挡。第一版「有引导在等就放行收尾」删掉；第 2 条「派了这一轮不结束」没有例外。
4. **取不到原文不拦。** ui-cli 起不来、回的认不出、这一轮里没有它：用 systemMessage 写「引导检查没查成：…读不到原文（原因）」，不当成没有。diag 读不了同样明说没查成；整个 `~/.mirasim` 都不在（这台机器没装 Mirasim）不说话。
5. **子代理的调用不管**（输入带 `agent_id`）。
6. **前台派子代理照旧拒**（第 2 条不变），只改理由里不实的那半句：一轮结束不会杀掉后台子代理（2026-10-11 实测），进程重开（插队、重启）会；拒的理由是前台等子代理时主对话不调工具，引导转不进来。
