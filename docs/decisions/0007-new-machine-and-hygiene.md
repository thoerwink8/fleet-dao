「都按照你说的拍」指的是指挥官上一条消息里三个问题的推荐项，即下面第 2、3、5 条。

## 决定

1. **目标**：C 盘没了或换一台新电脑，`git clone fleet-dao` 后一条命令把这台配好；私有的东西从 `fleet-dao-vault` 拉回（README「密钥和本机配置在哪」已经指向它）。怎么做按 `best-practice-first` 走：业务说明、业界对照、别家挑错，方案交创始人拍（#509 之外另开单）。
2. **总钥匙只靠 GitHub 账号**：新电脑登上 gh 就能拉回私有仓里的全部配置；电脑上要用的东西明文放 `fleet-dao-vault`，延续 2026-09-30「电脑上的东西明文放私有仓，电脑没了还找得回」。代价是 GitHub 账号成了总钥匙，必须开两步验证。
3. **保险箱的解密钥匙按「已经丢了」处理**：C 盘事故后这台的 `~/.fleet-dao/` 里已经没有它，保险箱只有这一把锁。换一把新钥匙，把法国、香港的副本重新加密一遍；新私钥按第 2 条明文放进保险箱的 `workstation/`。
4. **卫生检查不卡流程**：已知敏感值名单整套删掉（#481，子单 #532），卫生检查不再靠任何本机上会丢的东西；CI 那一遍只报不挡。推之前查出真密钥拦不拦：创始人说「都不想拦」，理由是 `fleet-dao-vault` 是私密库；但卫生检查管的是往公开仓 `fleet-dao` 推东西，保险箱私密护不住这里。这条前提和创始人对清之前，#481 照它现在的做法（推之前查出真密钥照拦），对清之后按他的意思改。
5. **auto 模式的「日常动作」说明进仓**：写进 `agents/config/claude-permissions.json`，由同步工具装到每台机器的 `~/.claude/settings.json`；只写「和工作仓同一个 GitHub 主人的仓是自己的」「改自己仓里单子和 PR 的标题、正文、标签、评论、子单关系是日常」，推送、删除、发布都不写进去。
6. **改了规矩、技能、钩子、权限，合进主线后每台机器自动同步，不靠人提醒**：先修「主检出不在 main 上，开会话时就整轮跳过同步」这个断点（2026-10-01 这台就因此落后主线 6 个提交）；同步只认 origin/main 上的内容，永远不拿功能分支去同步。
