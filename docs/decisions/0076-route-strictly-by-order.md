# 0076 选路只按顺序，冷验收验不了由冷验收兜

- 日期：2026-10-10
- 谁拍的：创始人
- 状态：采纳
- 出处：创始人 2026-10-10 12:35 对话；相关单：#1626、#1667、#1681。改了 0047 的「约 10% 试探」。

## 内容

创始人原话：「我觉得不对，正确的改法应该是 就按照优先级顺序，除非额度用完/我关闭了该模型/中断报错；其余情况就应该用顺序排到的模型，至于为什么冷验证失败，是要处理优化冷验证」

1. 每个用途都按创始人在驾驶舱排的模型顺序派。只在三种情况往后挑：额度用完（含留量线）；创始人关掉了这个模型或钉住了别的；会话中断报错（含派前探测不通、熔断）。
2. 同一个模型的几个渠道之间，照旧按额度微调先后（0047）。模型之间不微调。不试探（0047 那「约 10% 试探」不再用）。
3. 不为了让冷验收好验，在选路那头加限制。#1626「写码不派 cursor-auto」、#1667「返工优先已有作者族」都撤掉（撤的单等 #1681 合了再开）。
4. 冷验收挑不出别家时自己兜（#1681）：作者族认不出（如 Cursor Auto），或别家一家都派不出，就从两个不同的族各挑一个模型各验一遍，两家都过才算过。连两个不同的族都凑不齐，才停下等人。
