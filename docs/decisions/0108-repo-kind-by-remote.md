## 原话

```
我现在认为判断标准很简单：
1. 判断 GitHub 这个仓库到底是私有的还是公开的。
2. 假设 GitHub 不存在该仓库，就一律视为自用仓。
3. 很明显，GitHub web 的项目就是公司仓。
```

```
我觉得那怎么办呢？这些项目说明我们的规范还不好嘛。所以，你认为应该怎么走？其实很简单，你前面猜其实都是猜对的。那你有没有什么很好的建议呢？
```

```
没问题，就按照这个标准。对外仓随时可以顺口说一句，变成自有仓，你觉得这样是不是合适的？也做成机制?就相当于对外仓每一次都额外问一次，然后做一个标记文件。还有其他需要补充的吗？或者我说的对吗？
```

## 起因

0107 第 3 条要求自用仓在 AGENTS.md 打标记、没标记一律对外仓。拿本机 41 个检出一对：现有的自用仓都得补标记；而按远端猜（公司 GitLab、内网 → 对外，全在创始人 GitHub → 自用）一个都没猜错。创始人提的「按 GitHub 私有 / 公开判」对不上：fleet-dao 是公开的自用仓；公司工具箱仓同时挂内网 GitLab 和他 GitHub 的私有镜像；还要联网、要登录才判得出。

## 定了什么

1. **按远端自动判、不问**（先认到的算数）：本机 `.git/config` 的 `fleet.repoKind`（self / external）→ fleet-dao 本身、仓根 AGENTS.md 有自用仓标记的是自用仓 → 有任何一个远端不在创始人自己的 GitHub 账号下（公司 GitLab、内网地址、别人的 GitHub）就是对外仓，全在他账号下就是自用仓 → 没有远端的判不出来，照对外仓办。git 跑不起来也照对外仓办。
2. **一句话改类型**：创始人随口说「这个仓是自用仓／对外仓」，AI 就跑 `pnpm repo:kind self|external [仓路径]`，记进本机 `.git/config`，不往仓里加文件（有公司远端的仓，同事拉代码看得见仓里的文件）。有不在他 GitHub 下的远端、却记成自用仓的，命令提醒一句后果（往后的提交说明、文档会照 fleet-dao 的写法记，能拉代码的人都看得到），照记。两个方向都能改。
3. **不每次都问**：只有没远端、判不出来的仓，开会话提醒 AI 动手前问创始人一次（每仓每天最多一次），答了用第 2 条记下，以后不再问。0107 里「没标记但远端在他 GitHub 下就提醒要不要加标记」那句去掉。
4. **标记只管例外**：AGENTS.md 的自用仓标记照认（`repo:init --self` 照打），用在没远端又想跨机器带着走的自用仓；对外仓里什么都不加。
5. 换机器：本机记的不跟着走，那台按远端重判，判不出来的再问一次——偏严的一边，可以接受。

## 没采纳的

- 按 GitHub 仓私有 / 公开判：公开的 fleet-dao 是自用仓；挂了他 GitHub 私有镜像的公司仓会被判成自用仓；要联网、要 gh 登录，断网换机器判不出来。
- 对外仓每次开会话都问一次、答了做标记文件：几十个公司仓每次都问太吵；标记文件进对外仓违背 0107「对外仓里什么都不加」。
