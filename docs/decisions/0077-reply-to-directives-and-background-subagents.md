# 0077 引导先回、子代理一律后台跑（创始人 2026-10-10 13:02 选定）

- 日期：2026-10-10（北京时间 13:02）
- 谁拍的：创始人。指挥官给了三条方案（改标准），问他「你回一句『同意』我就开 PR」，他回「都按你的推荐来。」
- 状态：采纳
- 关联：补充 0024（派活默认用子代理）、0025（子代理走自己的一道）、0030（无人值守也用子代理）；0028 的「单次前台等待不超过 60 秒」照旧，通用段里挪到子代理那句，并成一处。「一轮结束时兜底」那一版（收尾钩子拦）没做，0026 的「没开无人值守时收尾不拦」不动。

## 原话

```
都按你的推荐来。
```

## 为什么

- 创始人在 Mirasim 里一轮跑着的时候打的字叫「引导」。Claude Code 把它写成 transcript 里的一行 `{"type":"attachment","attachment":{"type":"queued_command","commandMode":"prompt","prompt":…}}`，附在下一次工具结果后面送进主对话。
- 只有主对话两次工具调用之间才送得进去。主对话前台等子代理时，整段卡住；子代理自己收不到。
- 本机 178 条送到的引导，AI 的第一反应：直接再调工具 107 条（60%），先写话 45 条（25%），本轮随即结束 26 条（15%）。收到了不回是常态，创始人觉得「石沉大海」。
- Mirasim 一轮结束会杀掉还在跑的后台子代理（记录里写着「didn't finish before the previous session ended」）。后台子代理只在派它的那一轮里，界面上显示每一步。

## 决定

1. **调工具前查引导。** 新钩子 `agents/hooks/main-thread.mjs` 挂在 PreToolUse 上、不写 matcher，每次工具调用都过。它只查主对话：输入带 `agent_id` 的是子代理，不查。它从 transcript 尾部往回读：最后一条创始人引导之后，主对话还没写过一段非空文字，就拒这次调用。理由是「你刚收到创始人的引导『前 200 字』：先用一句话回它（问题就答，指令就说改成什么；涉及在跑的子代理就用 SendMessage 转给它并说已转），再接着调工具」。写了话就放行。
   - 后台任务的完成通知、子代理交回的报告也走 queued_command，不算引导。创始人开了新的一轮，之前没回的引导就不再拿来拦。
   - 读不了 transcript（没给路径、文件不在、读出错），不拦，用 systemMessage 明说「引导检查没查成：原因」。
2. **子代理一律后台跑。** 主对话调 Agent、Task 而 `run_in_background` 不是 true，同一个钩子拒，理由说明为什么。子代理里再派子代理不管。
3. **通用段补三句**（`agents/shared-rules.md`「怎么跟我说话」）：中途收到引导，下一句先回它；涉及在跑的子代理，用 `SendMessage` 转给它，并告诉他已转。子代理一律后台跑；主对话留在这一轮，单次前台等待不超过 60 秒，等它跑完再收尾。commander 技能「派活」同步改，删掉「它活在聊天这一轮里，轮次结束就跟着死」的旧说法。

## 落在哪

- 钩子：`agents/hooks/main-thread.mjs`；登记：`packages/agents-sync/src/targets.ts`（Claude 那份设置）。
- 钉住的测试：`agents/test/rules/main-thread.rules.test.ts`、`agents/test/rules/mid-turn-answer.rules.test.ts`。
- 通用段字数上限从 2000 放到 2080（`agents/test/agents-md-budget.test.ts` 写了为什么）：Codex、Gemini 这些家没有这个钩子，只能照文字做。

## 没验证完的

- 同一条回复里先写文字、再调工具时，PreToolUse 触发那一刻文字那行是不是已经落盘，没有直接测到。查到的：本机 165 份 transcript 里，同一个 message.id 的文字行和工具行共 2231 对，文字行一律排在前面；本会话里两次实测，工具真跑起来时，文字行和工具行都已在盘上。判法本来就是「引导之后有一段文字就算回了」，同一条回复里的文字只要落了盘就算；风险只在落盘晚于钩子触发。钩子见到「没回」时先等 300 毫秒再读一遍，才拒。真碰上误拦，再加长等待或改判法。
