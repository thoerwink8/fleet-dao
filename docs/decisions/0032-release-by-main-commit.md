- 状态：采纳，分片落地（母单见本文末尾）
- 关联：替代 0011 第 3、4 条里「按版本标记（`v<N>` tag）发」的那一半；保留 0011 第 4 条原话的流程（暂停派活、手头活干完、部署、接着派活）。补 `AGENTS.md`「引擎怎么接活」里「每次发版后总开关和接活开关自动置关」一句（#1050、#1086）。

## 原话

```
我想了一下，其实里程碑发版完全没必要？只需要main new commit发版就行了，按照这个思路看看怎么处理优化驾驶舱 /grill-ai  全程你拍板，我要睡觉
```

## 为什么

- 今晚一次发版要先把发布 PR 合进去、打 tag、等 CI 空下来、排空、部署、手工开引擎；中间卡过一次 21 分钟（等「主线头 CI 空下来」，自动合并连着进来永远等不到）。
- 「按版本发」是 2026-10-02 为了「别让每个 PR 合并就上线」定的（0011）。现在有了驾驶舱「发布到法国」按钮（#1232）：创始人点一下才发，同样不是合并就上线；版本标记这一层只剩手续，没有再挡住什么。
- 引擎只拉「挂了当前版本里程碑」的单，这是计划的事（拉哪些单），和「哪个提交上线」是两回事，不必绑在一起。

## 决定

1. **发版单位＝主线上的一个提交。** 要发的是主线头（或点名的主线提交），条件只有一个：这个提交自己的 CI 是绿的（发版车已经这么看了，#1252）。不再要求有 `v<N>` 标记、发布 PR、CHANGELOG 里的版本号。
2. **入口只有一个：驾驶舱「发布到法国」按钮**（法国页发版卡，#1217 合页后在合并后的那一页）；命令行 `release-train.mjs` 是同一趟流程的备用入口。
3. **里程碑只管计划**：「里程碑＝版本」仍用来分组、排先后、决定引擎拉哪些单；它不再触发任何发布动作，也不再有「发布 v<N>」。
4. **发版前后引擎状态**：发版照 0011 第 4 条原话的样子走——暂停派活、等手头活收完、部署、**恢复到发版前的样子**（发版前开着的，发完自动开回；发版前就关着的，保持关）。取代「每次发完一律置关、等人去点」（#1050、#1086）：提交一级发版会很频繁，每次都要人去点，引擎就白停。恢复动作写进操作记录。创始人 2026-10-05 那句「每次更上去处于关闭状态，点击开启」说的是当时按版本的发法，这里按他今晚的方向覆盖；他要改回，说一句即可。
5. **删掉整层**：`v<N>` tag、发布 PR（`publish:pr`）、`release.yml` 打标记、CHANGELOG 版本节的自动生成、`/api/release/version` 和更新日志页的「发布 v<N>」、自动发布按 tag 找要发的版本（法国的自动发布单元只留读数：落后几个提交），都按下面几片依次删；删之前每片先确认没有别处读它。

## 不动

- 里程碑本身（计划分组、引擎拉单看当前版本）；
- 发版车的暂停、等收尾、验证流程；
- 发版是对外发布这一条人闸：创始人点按钮就是同意，指挥官代跑要带他的原话。
