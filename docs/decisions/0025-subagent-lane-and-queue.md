## 查到的根因

- #1118 的子代理 143 次调用、25 分钟、31 万 token（Mirasim 面板实测）。看它的调用清单：大半是「cd 工作树 && 命令」「后台起测试、每 55 秒醒一次 tail 日志」「timeout 50 bash -c 'until grep …'」。这不是模型笨，是本仓调工具前钩子把**主会话**的三条规矩套在了子代理身上：前台等待不许超 60 秒（创始人 10-04「选 1」）、欠账催送、起后台活自动开无人值守。这三条的目的只有一个：创始人的话只在两次工具调用之间送到主会话，不能让一条长等待把话卡住。子代理不和他对话，套上只剩代价。
- 读代码靠 grep 加 Read 来回翻，一个函数的调用链要五六次调用。仓里一直配着 codegraph 的 MCP，但从没给 fleet-dao 建过索引。
- 指挥官派出子代理后坐等全部完成（收尾钩子要求后台活收口了才能结束这一轮，等的方式却是一轮轮短等），队列里别的活没人派。

## 决定

1. **子代理走自己的一道**：调工具前钩子见到带 `agent_id` 的调用（Claude Code 只在子代理里的钩子调用带它），不套前台等待上限、不催欠账、不自动开无人值守；密钥护栏、危险命令、`git reset --hard` 这些照旧管。空的、不是字符串的 `agent_id` 不算子代理，宁可多拦。
2. **给仓建代码索引**：`codegraph init -y`（`.codegraph/` 在 .gitignore 里，不进仓，每台机器自己建）。子代理交代第一条：读代码先用 `codegraph_explore`。
3. **子代理的交代瘦身**：只要一次汇报；测试前台跑到完；不要求逐步记进度、不要求两段式汇报；仍要写清要改什么、怎么算做完、跑哪些测试、别碰什么、PR 怎么开。
4. **指挥官按队列派**：当前版本的先后就是队列，每收到一个完成通知就派下一件，并发不超过 4，等通知时做自己能做的，队列空了、在跑的为 0 才收尾。Workflow 工具能自动接续，但要创始人明说「用 workflow」。
5. **法国那一半**另见母单 #1121：AI 当时自加的保守关卡（发布后置关失败连坐整版、没成不再试、人手切版按住不过期、装机脚本整体要人重跑、陈旧提醒不消、发版火车等本机工人和 PR）改掉；创始人拍过的三条不动（按版本标记发 0011、发完开关回关要他点开、健康检查不过自动退回）。

## 没做的

- 没有让子代理在会话被打断时活下来：Mirasim 一来新消息就重开进程，子代理跟着死。能做的是子代理早提交、早推分支，指挥官下一轮按工作树接着派。
- 没有把钩子的 60 秒上限整体放宽：主会话那条仍然成立，创始人的话还是要靠两次调用之间的间隙送到。
