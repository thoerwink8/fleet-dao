## 起因

那个对外仓 2026-10-23 的一份排查讨论稿，第一版只有六节（提出的问题、另外查出的、根因归拢、要拍板的、顺序、没核实的），缺定了以后要动哪些旧规矩、每批怎么算做完和风险、拍板结果和交接；证据是看到的、读代码推的还是猜的也没统一标。要交给别人接着做时，这些缺口会让接手的人重新问一遍。需求方当天定了八节模板和五步流程，写进了那个仓自己的规范。

## 决定

1. **叫法进通用段**（一句，把原来的「我说「先讨论」就只讨论」并进同一句，没有净加句子）：话以「讨论：」「出讨论稿：」开头，先出讨论稿、不改代码；没这么开头但一次提了好几点、或要创始人拍板的，先问一句要不要出。通用段只写这一句，细则进技能（通用段只放模型猜不到的事）。
2. **新技能 `discussion-draft`**：`SKILL.md` 写叫法、五步、证据三级和命令；`template.md` 是八节模板的上游原件（提出的问题、另外查出来的、根因归拢、要改的已有规矩、要拍板的、顺序验收和风险、没核实的、结论），第一节带「怎么想」清单（复现找证据 → 追根因 → 横向找同一根因的其他现象 → 需求方方案和备选比 → 定最小改法 → 写清不做什么）；`scripts/draft.mjs` 一个零依赖文件，`new` 起稿、`check` 推前查。技能由 `packages/agents-sync` 装到每台机器每家 AI，所以叫法和流程不用各仓再写一遍。
3. **起稿**：`new <短名> --ask "…"` 按模板生成 `YYYY-MM-DD-<短名>-survey.md`（默认放 docs 目录），去掉模板开头的说明注释，状态「讨论中」，`{{标题}}` `{{日期}}` `{{起因}}` `{{代码版本}}` 自动填（代码版本＝短提交号加 package.json 的 version，git 读不到照实写「没读到」）。同短名已有稿不论哪天都只报出来、不新建（退出 1）：一个主题一份稿。
4. **推前查**：「讨论中」的稿模板的 `## ` 标题要齐（按模板现读，不在脚本里写死八节，各仓改了措辞照样对得上）；「已定」的结论节（模板最后一节）要有指得到文件的决定链接和匹配任务编号格式的编号；状态认不出也算不合规。不合规退出 1，推前钩子拒推；「讨论中」超过 7 天只提醒。读不到配置、模板、目录退出 2，不算过。
5. **各仓差异写在仓根 package.json 的 `discussionDraft`**：稿的目录、后缀、模板位置、决定放哪（目录或单文件）、任务编号正则、从哪天起查（用模板之前的旧稿跳过）、提醒天数，不写全用默认（docs、`-survey.md`、技能自带模板、`docs/decisions` 或 `docs/decisions.md`、GitHub 单号、全查、7 天）。认不出的键报错，不悄悄按默认查。不另加标记文件：package.json 是仓自己的，对外仓也能用。
6. **fleet-dao 自己**：`pnpm discuss:new`、`pnpm discuss:check`；推前查落在 CI——`agents/test/discussion-draft.test.ts` 拿仓里的稿跑同一个检查，每个 PR 全套跑；`ci-plan.ts` 加一条，只改稿时本机推前也选到这个测试。没有改 `.githooks/pre-push`：那份钩子常从主检出跑在别的工作树里，不能引用只在新分支上才有的脚本。
7. **对外仓怎么接**：对外仓要自己就完整、fleet-dao 不往里加骨架和检查（通用段「对外仓和对外内容怎么写」），所以同步分两半——技能和叫法由同步工具自动装到机器上；模板、脚本、推前钩子由那个仓自己接：`draft.mjs` 原样拷进仓、模板留在仓里并保留八节标题、状态行和四个占位、`discussionDraft` 声明差异、仓自己的推前钩子调 `check`。上游改了脚本或模板，下游照同一个办法再拷一次。

## 为什么这样放

- 叫法是「创始人怎么说话」，必须每次会话都在上下文里，所以进通用段；五步、模板、怎么想是「怎么做」，用到时才读，进技能，不付每轮的 token。
- 一个技能目录装下说明、模板、脚本，同步工具已经会整个目录拷过去，不用新开同步通道。
- 检查按模板现读标题、按配置认目录和编号，差异是数据，不是分支代码；下游拷过去的是同一个文件，上游修了 bug 再拷一次就一致。
- 不进仓合同（`agents/repo-contract.json`）：讨论稿不是每个仓都会有，合同只放每个自用仓都该满足的几项。
