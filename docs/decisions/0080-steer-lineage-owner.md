## 出了什么事

创始人 2026-10-11 截图，两条串的路（prompt-log 对得上）：

1. 他 17:49 在一个 fleet-dao 会话里问的话，被另一个项目的会话（cwd 是用户目录）当成自己的活答了。原因：开会话钩子 `recentPrompts` 末尾一行「创始人最近 60 分钟落盘的话」，把**所有别的会话**收到的话（不分项目、不分会话）列给每个会话。Mirasim 每一轮都 `--resume` 起进程，开会话钩子每轮都跑，于是每个会话每一轮都看见别的会话最近一小时的全部话。
2. 他 18:15 发给指挥官会话的引导，另一个 fleet-dao 会话也接着办了，开出重复 PR #1884。原因：开会话时「创始人引导还有 N 条没处理（进度单 #1055）……先接着办」叫**每个**会话办全部待处理引导；同一个仓开着几个指挥官会话就撞车。

## 决定

1. **血缘。** 一个 Mirasim 会话（`~/.mirasim/sessions/claude/<目录>/`）会换好几个 Claude 原生会话号（/compact、换模型）。`founder-inbox.mjs` 的 `lineageOf` 给当前原生会话号，按目录名、`record.json` 的 `nativeSessionId`、`turns.jsonl` 各轮的 `sessionId` 找出它所属的目录和这个目录用过的全部原生号。找不到（不是 Mirasim 起的、这台没装、没给会话号）返回「无血缘」，不猜；读不了、一个号出现在两个目录里返回「没查成」，不当成无血缘。
2. **他的话只给同一家。** 删掉「别的会话收到的话」那一行的全局版本；改成只列同一血缘里、别的原生会话号最近 60 分钟收到的话（原意「上一个会话没来得及处理的」就是同一个 Mirasim 会话换了原生号）。「发了没收到」的对账只读本血缘那个目录，比对从「同一个原生号」放宽到「同一条血缘」，换号前丢的引导也补回本会话、换号后重发收到了就不再报。无血缘的会话两行都不出，不拿别的会话的话顶。
3. **引导认主。** `pnpm progress:directive` 在评论第二行写 `〔主：<Mirasim 会话目录名>〕`，取不到写「无主」。开会话时本血缘的待处理引导列全文、叫它办；别的会话的只说一句「别的会话还有 N 条引导在办，不归你，别动」，不列原文；无主的（旧的、在 Mirasim 外记的）照列开头，写明先认领。`pnpm progress:claim <评论号>` 把主人改成本血缘：无主的直接改，已有别的主人的拒绝，除非 `--force --why "<为什么>"`（原会话已经没了），改主那一笔记进评论。别的仓的「## 创始人引导（待处理）」清单同样认条目里的 `〔主：<目录名>〕`：有主且不是本血缘的只计数不列。
4. **规矩一句。** 通用段「进度当场记下来」那条加：只办归本会话的，别的会话的不动，无主的先 `pnpm progress:claim <评论号>` 认领。「这一轮没进到你这里的，下一轮开头会补上」不改：补上的就是本血缘的，和新做法不冲突。

## 不动的

- `main-thread.mjs` 转 Mirasim 引导按会话号取（#1743），本来就不串。
- 「发了没收到」只列本会话的（#1733）：这次只是把「本会话」从一个原生号放宽到整条血缘。

## 为什么这样做

- 认主的单位选「Mirasim 会话」而不是原生会话号：原生号会因 /compact、换模型变掉，按原生号认主，换号后自己的引导就成了「别人的」；Mirasim 会话目录是创始人眼里的「一个会话」，跨换号不变。
- 不靠「cwd 是不是同一个仓」划界：同一个仓开几个指挥官会话正是第二条路撞车的场景，按仓划界堵不住。
- 删掉全局广播那一层，而不是在提示里加「别的会话的别办」：模型看见了原文就会办，最好的拦法是不给原文。
