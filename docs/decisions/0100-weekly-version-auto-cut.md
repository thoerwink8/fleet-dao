## 为什么

- 没人关版本：10-08 决定 0032 删 `release.yml` 时（#1280），唯一会关里程碑、会把开着的单搬到下一版的 `milestone-close` 一起删了。之后 v4 只进不出：开 7、关 747（其中 273 个是 PR），没有截止日，「这一版做了什么」看不出来。
- PR 又挂回了里程碑（`pr-open.ts`，#1058），违反 0015，进度数是虚的。
- `github-actions[bot]` 开的报警单被当成人开的挂进当前版本（10-05 起 112 张），违反「AI 发现的进未排期」。
- 对账里「版本里开着却没排进先后」这条永远报，github-audit 定时那一轮 10-04 到 10-15 连红 12 天、没人看；拉单和发版车本来就把没排进先后的单排后面照样拉。
- 先后清理按全仓开着的单清：单挪到别的版本还开着，`readPlan` 报错整个失败，清理也跟着不跑。
- 驾驶舱提需求开的单落未排期，可能被闲置清理关掉；点名派单还在用版本闸，和 0031 不一致；引擎「里程碑关了才挪单」那段只在有人关了之后才触发。

照 Linear Cycles：周期固定、到期自动结束、没做完的自动滚进下一个周期，周期本身就是「这段时间做了什么」的记录。

## 决定

1. **版本＝一周的时间盒**：永远只开一个 `v<N>` 里程碑，带到期日；标题 `v<N> MM-DD～MM-DD`，后面可以接一句目标。没挂里程碑仍是未排期。
2. **到期自动收口**（`.github/workflows/github-audit.yml` 的 version-cut 任务，每天一次、能手动触发）：北京时间过了到期日 → 开 `v<N+1>`（到期日 +7 天）→ 开着的单逐张留一句再挪过去 → 旧版先后段整段接到新版最前 → 旧版说明末尾写收口段（关了几张、完成/不做/重复各几、滚过去的单号、收口时主线头）→ 关旧版 → 回读核对。挪单失败不关旧版、退出码非 0；同一天重跑不出重复；没过期什么都不做。手工关了还挂着开着单的版本，同一份代码兜底挪走。
3. **每版做了什么看里程碑收口段**：`CHANGELOG.md` 不再是唯一来源（自动收节随 0032 删了，10-08 后 587 个提交它只改过 2 次）。
4. **只有一处写**：版本交接只归收口任务；引擎单子打标里「里程碑关了才挪单」那段删了；点名派单不再看版本（和 0031 一致）。
5. **单进哪一版**：创始人开的（含驾驶舱提需求）进当前版本；机器人账号开的（GitHub 上类型是 Bot 的都算）进未排期；`pnpm issue:new --milestone 当前` 解析成开着的那个 `v<N>`，写死已关的 `v<N>` 报错并提示用「当前」。PR 不挂里程碑（重申 0015）。
6. **对账红了有人接**：GitHub 对账没过就开（或更新）同一张「GitHub 对账没过」单（挂当前版本、贴「缺陷」「本机做」），绿了自动关。对账加兜底：开着的 `v<N>` 不是恰好一个、当前版本没有到期日、过期一天多还没收口、已关的版本还挂着开着的单、开着的 PR 挂了里程碑；删「版本里开着却没排进先后」那条。
