## 为什么

- 四类人闸是给「不可信的自动写码模型」设计的。交互会话里的高级模型有人在旁、会读规矩、不会把敏感信息往外送，对外发布要他点头只是多一次打断。
- 「花钱」他观察下来六成以上是换模型、换档这类在已买订阅里的事，并不多花钱；真会让账单多一笔的只有新开订阅、充值、开按量计费。
- 「删数据」他大多直接同意；真要他看的是删了就回不来的那几样。能恢复的、有备份的、AI 自己产生的东西删了也没损失。
- 改标准他已经交给指挥官拍。

## 决定

1. **交互会话**（指挥官、本机子代理、各家 CLI 会话）只为两件事停下来问创始人：
   1. 要掏新钱：新开订阅、充值、开按量计费的账单。用已买的订阅、换模型、换档、多开会话都不问。
   2. 删了找不回又没备份的：删 GitHub 仓、删没备份的生产库数据、删创始人自己的文件。能恢复的、有备份的、AI 自己产生的（分支、工作树、临时文件、通知、确认没有读者的废表）直接删。
2. **对外发布**（推代码、发版、发到 VPS、开 PR 和单）和**改标准**：自己判断，事后一行报结果和理由，不问。
3. **法国 VPS 上引擎自动派的写码模型照旧**受引擎护栏约束：卫生检查、合并闸、冷验收、`standard-paths.json`、整理会话贴「要人拍」等，代码和语义都不动。
4. 合并闸对碰了改标准路径的 PR 仍要正文有「创始人原话」那一行（它挡的是引擎模型）。交互会话开这类 PR，贴他这次说的原话；没有就贴他授权指挥官拍板的那句（引导 20261015054500）。发版车 `release-train.mjs --founder-ok` 同理。
5. 重大且难回退的方案拍板前仍用 `discuss` 让别家挑错——这是找人挑错，不是问创始人。
