# 本仓怎么协作（细则）

仓根 `AGENTS.md` 只当目录，这里是它指过来的细则：进度和单、PR、改标准、发版和底线。通用规矩在 `agents/shared-rules.md`；目标看 `docs/goals.md`。

词义固定：单＝GitHub issue；主线＝origin/main；法国＝法国 VPS 上的引擎；本机＝创始人的电脑；创始人＝仓的主人；项目＝驾驶舱的顶层（一个项目一个仓）。

## 进度和单

- 创始人讲的 AI 做法（以后都管的）当场 `pnpm progress directive --kind ai` 记下（先分拣，其余类的去处和判法在 `pnpm progress directive` 的输出里，决定 0117），接手先 `pnpm progress read`；每条引导挂一张单、单关了就算办完（没有认领、标已处理）；记法、进度流水的全套见 `docs/directives/README.md`。
- 计划以 GitHub 为准，`pnpm plan` 现读。版本是一周一版的时间盒：永远只开一个 `v<N>`、带到期日，到期由 `github-audit.yml` 的收口任务自动开下一版、把开着的单滚过去、关旧版（决定 0100）。创始人开的单（含驾驶舱提需求）进当前版本，开单写 `--milestone 当前`，别写死 `v<N>`；AI 和机器人账号发现的不急的开小单进未排期，告诉他排第几。PR 不挂里程碑。
- 每版做了什么只看 `CHANGELOG.md`（决定 0107 第 6 条）。引擎每天 06:30（北京时间）把 v4 起已收口但主线缺少的版本一次补齐，机器人开一个 `changelog/v<N>` PR，按 CI 自动 squash 合并；里程碑只保留对应节的链接、滚单和收口主线头。`schedule_runs.scanned` 计实际读全并逐条核过适用性的已关闭里程碑数，`found` 计待补日志的版本数；没有待补版本仍按真实扫描数记成功，已关闭里程碑列表为空则记 unscanned 和原因。源数据没查成不开 PR，记失败；法国发布历史缺失不写成「没有发布」。
- 需求写在单上，四节：场景、原话、已知的模块、怎么算做完；用 `pnpm issue:new` 开（参数见它报错里的用法；必带 `--domain engine|api|mirasim` 和 `--nature bug|perf|process`，每轴恰好一个，查询轴见 design 第七节「标签与里程碑」；本机做的再加 `--local`）。一个队列（GitHub 单）、一本账、两种执行者，默认开单给法国，开完顺手戳法国立刻接；只有讨论中的、急修、要本机资源的、改标准的这几种才贴 `--local` 留本机（决定 0096）。本机做活一律先开单（`pnpm issue:new --local`，开完自动领）或 `pnpm work claim <号>`，分支用 `local/<单号>-<短名>`（引擎用 `fleet/<单号>-`）。有 PR 合并且单已关，租约自动收，不用手动；无 PR 的运维成功，凭真实验证先 `pnpm issue:close <号> --note "验证结果"`，再 `pnpm work done <号>` 收租约账。未完成验收责任仍保留开放，done 不代替验收结清或关单检查；没做成或放手用 `pnpm work done <号> --failed|--release "原因"`。本机队列看 `pnpm work queue`（领者、心跳、开着的 PR、挂着的引导、能不能接）；有先后依赖的单在正文里单起一行写 `前置：#N`（可写几个，后面可跟说明）或 `前置：2026-11-12 复查日`（北京时间到那天之前不做），前置单没关、日期没到，`pnpm work queue` 不算可接、法国引擎拉单也不拉，不用再贴「本机做」压着（解析只有一份，`packages/conventions/src/prerequisites.ts`，#2783）；要扛过会话重启和网关断的写码活用 `pnpm work run <单号>` 派脱离聊天进程的无头工人（`pnpm work runs` 看，`packages/conventions/src/work-run.ts` 开头有全貌）；`pnpm pr:open` 在 `local/<单号>-`、`fleet/<单号>-` 分支上需求栏没挂单就自动补 `Closes #<单号>`，且不收 `--no-issue`、挂的单和分支单号对不上也拒开。这是本机 CLI 的行为（在 `fleet/` 分支调用也一样）；引擎通过自己的 `openPr` 活动生成正文，不经这个 CLI，关单语义见下面「PR」。要写方案才写，放 `specs/<编号>-<短名>/`（编号别和已有目录撞）；方案正文写下就不改，头部的状态行可以改：新方案主文件在 `# 标题` 下面带 `- 状态：在做 | 做完 | 被取代 | 未复核`，被后来的方案推翻时改成「被取代」并加 `- 被取代：specs/<目录>`，改完跑 `pnpm specs:index` 重新生成 `specs/README.md`（还在管事 / 历史两节，`pnpm check` 核对，主文件怎么挑见 `packages/conventions/src/specs-index.ts` 开头）。
- 决定或方案落地后回填实测：把「改之前多少、改之后多少」的数字补进那份决定（或方案），写明哪天、怎么量的；量不了的写「没量成」和原因，不留空。决定只增不改，回填在文末另起一节追加，不改原有条文。
- 提议删功能、删关卡、删检查时，理由里写它的用量和成本：用了几次，多花多少次请求 / 读行数 / 时间；拿不到数的写明拿不到和原因，不凭感觉删。
- 流程标签「全程」「三段」（决定 0105；标签名以 `packages/conventions` 里的常量为准）：只给法国引擎的单用，本机做的单不贴。贴「全程」＝这张单指定走全程（同一个写码会话从动手带到合并），贴「三段」＝指定走三步单；都不贴＝按开关 `engine.flowMode` 和单号哈希分组，不用你管。两个都贴、贴了又碰迁移、合并闸、凭据、权限、任务工作流、发布脚本、改标准路径的，引擎一律退回三段并在分组记录里写原因。贴了标签的单仍进每日简报的对照，但是人挑的、不是随机的，只当参考；贴错了在引擎派单前改，分组一次定下就不再改。开关用 `fleet-api flow-mode status | set`（ops 第五节）。
- 引擎自己挑单、自己关单，不直写主线；单要写成什么样它才接，见 `packages/engine/AGENTS.md`。

## PR

- `pnpm pr:open` 开 PR，当场挂自动合并（改标准见下）；只看 CI，红了才回来修。谁开谁负责到合并。开的时候必带和开单同一套 `--domain`、`--nature`，贴上才能按域、按性质筛。
- CI 一律全套（决定 0101）：每个 PR 都跑全部单元测试、web 打包、e2e 全套（两种屏宽）、deploy 全套，和主线推送一样；合并闸等全套绿。同一 PR 重推时输入没变的测试台复用上一轮的结果，合并后主线同一棵树复用 PR 的结果。不用自己判这个 PR 要不要跑 e2e。
- 关单分执行者：本机最后一个 PR 的「需求」栏下另起一行写 `Closes #号`，由 GitHub 在合并时关闭。引擎 PR 正文和实际 squash 消息都去掉自动关单词，保留需求关联，工作流在合并收尾时关单。冷验收判出「不归我验」的条时写 `Refs #号` 并留单（贴「本机做」），有人贴上证据再关。验收核对需求关联，不要求引擎正文有自动关单词。任务工作流将验过的头传给自动合并口，先核头没变、再绑定该头并显式提交安全 squash 标题和非空正文，核 GitHub 回执一致后才算挂好；REST 直接合并和回退同样显式传消息。GitHub merge queue 会忽略自定义消息，不能沿这条消息确认机制宣称安全；回执缺失或不一致先撤挂并核撤挂回执，再保留原失败；撤挂也读不清则明确结果未知。没有 PR 的用 `pnpm issue:close`；完整约定见 design 第七节「关单要有证据」。合并不等于验完（决定 0113）：要 diff 外证据的验收条在开单、拉单时就挡下，这类单留给本机或指挥官做，单子开着直到有人贴上证据再关；冷验收仍判出「不归我验」的漏网条，代码照合，引擎收尾不关单、PR「需求」栏在合并前改 `Refs`（分片）。#3591 起不再往 `acceptance_duties` 写新行；#3630 删了结清、拍板卡、管理 CLI 和关单闸对它的检查，还开着的旧行由 `fleet-api acceptance-handback-once` 一次性交回原单（见决定 0113 补充段）。
- 推之前本机只跑改到的测试文件（`npx vitest run <文件>`）加格式和类型检查，其余交给 CI。后端 Node 22 直接跑 TypeScript，相对导入带 `.ts`。
- 改了哪个包的入口、命令、坑，顺手改那个包的 `AGENTS.md`。全部 pnpm 命令见 `README.md`。

## 改标准

- 交互会话只为掏新钱、删了找不回又没备份的两件事问创始人（`agents/shared-rules.md`）；对外发布和改标准自己拍，事后一行报结果和理由。
- 改标准＝改到 `packages/conventions/standard-paths.json` 列的路径；技能脚本、同步工具的代码修 bug 不算。合并闸对碰了这些路径的 PR 仍要正文有「创始人原话」那一行——这是挡法国引擎自动模型改规矩的护栏，引擎开的 PR 没有原话、合不进。交互会话开这类 PR：`pnpm pr:open --founder-quote "<原话>" --at "<时间>"`，他这次说过就贴这次的，没说就贴他授权你拍板的那句（引导 20261015054500），直接挂自动合并。不认 GitHub 账号的批准（本机 gh 登的是创始人账号）。为什么这样分见 design 第五节讲改标准的那一条。
- `agents/config/claude-permissions.json` 的 `autoMode` 两个数组都要带 `"$defaults"`，少了内置安全规则整段被换掉。

## 发版和底线

- 主线绿了法国自动发版。先改仓库、合进主线，再落到法国，不在机器上手改。本机只做断链急修、要本机资源的、指挥官本职，其余给法国。
- 已上线的真问题先回退再修；主线必过检查红了立刻修，修复 PR 写清是哪次合并弄坏的。CI 里的检查必须确定、只看检出来的文件，看外部状态的放定时任务、只留言不挡 PR。
- 公开仓：卫生检查只拦真密钥（pre-push 挡）。
